# 1단계 — 전환 목록과 등가성 디프 하니스

`COMMON_RULES_DELTA.md` B를 적용한다. 이 단계는 **조사와 하니스**다 — 전환
자체는 하지 않는다.

## 목표

현행 원장 유입 경로 전부를 mapper 세계로 옮기는 **전환표**와, 옮겼을 때 같은
원자가 나오는지 증명하는 **디프 하니스** 하나.

## 흐름

1. 유입 경로 전수 목록: `sources` 선언(관측 2·이송·랏이벤트·선언형) ×
   실제 데이터 유무 × 현재 mapper 지원 여부(`ledger_lot_event_mapper`는 있음).
2. 경로별로: 대응하는 Pack claim(2단계에서 확정될 이름을 가칭으로) ·
   현 config의 어떤 블록이 Profile의 어떤 binding이 되는가 · 자동 변환
   가능한 부분과 사람 결정이 남는 부분.
3. **디프 하니스**: 소스명 하나를 받아 같은 행 N개를 legacy 번역기와 mapper
   양쪽에 태우고 원자 봉투를 정렬·대조해 「동일 / 차이 목록」을 내는 도구.
   차이는 필드 단위로(id·시각 생성값 등 «당연한 차이»는 정규화 후 제외하되
   제외 목록을 출력에 명시).
4. 실측 1회: `lot_event`를 하니스에 태워 현 mapper의 등가성을 잰다 — 이 숫자가
   1단계의 완료 증거다.

## 제약

- legacy 번역기 코드 동결(읽기만). mapper 쪽 결함이 나오면 고치지 말고 차이
  목록에 적어 보고.
- 하니스는 R-J 비례 규칙의 «위험 자리»(쓰기 게이트·경계 계약)에 해당하므로
  정당하다 — 단 이 하니스 하나로 끝내고 증식 금지.

## 테스트

- 하니스 자기 테스트: 같은 번역기를 양쪽에 넣으면 차이 0.
- `lot_event` 등가성 실측 결과(차이 0 또는 설명된 차이 목록).

## 보고

전환표(경로 × Pack 후보 × 자동/수동 구분) · 등가성 실측 숫자 · mapper 쪽 발견
결함 목록 · 2단계 Pack 목록에 대한 제안.

## 추가 (2026-08-17): 처리 단위 분류 — 전환표의 필수 열

원칙: 처리 단위는 행이 아니라 **분자(한 사건의 온전한 서술)**다. 1행=1분자는
특수례. 전환표는 소스마다 아래 부류를 판정해 적는다:

| 부류 | 정의 | 실물 | 처리 소관 |
|---|---|---|---|
| A 행내 전개 | 1행 → N원자 | 스플릿 행의 리스트 짝짓기(has_wafer×19) | 단순 전개=Pack, 리스트 짝짓기=mapper |
| B1 짝 문법 | N행 = 1사건 | 스플릿·머지 2행(겹침=슬롯 사상) | mapper (묶음 키+문법 코드) |
| B2 EAV 피벗 | 속성 행 N → payload 1 | name/value 행 표 | mapper |
| B3 스냅샷 디프 | 연속 행 차이 = 사건 | 재고·상태 표 | mapper |
| C 표 간 참조 | 1행 + 이웃 표 | 관측→run_uid→검사 이력 | Pack 전제 선언 |
| D 집계 | N행 → 요약 1 | — | **금지** — 집계는 질의 시점에 (저장은 문장, 계산은 읽기) |

인터뷰 판별 질문(04 연동): 「한 사건이 몇 행에 걸쳐 있습니까?」 — 감지 보조:
같은 키 행 반복·부모/자식 컬럼 상보성·name/value 쌍. B 판정 시 마법사는 초안을
만들지 않고 「구조 변환 mapper 필요」로 멈춘다.
