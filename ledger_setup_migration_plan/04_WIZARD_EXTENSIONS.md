# 4단계 — 마법사 확장: 인터뷰 정문과 문장 판정

v2 04(`SETUP_WIZARD`)가 기반이다 — 그 계약(role form 메타데이터 생성·샘플
문장·드라이런·predicate 숨김)을 바꾸지 않고 **앞뒤에 한 층씩** 붙인다.

## 목표

관리자의 첫 화면이 폼이 아니라 **인터뷰**이고, 마지막 화면이 JSON이 아니라
**문장 판정**이 되게 한다. (근본 원칙: 시스템이 초안, 사람이 판정)

## 흐름

### 앞 — 인터뷰 (Pack 선택을 대신한다)
1. 테이블 지목 → 시스템이 컬럼·타입·distinct 예시·NULL율을 읽는다.
2. 원장 용어 0개의 질문 4~5개 (답 후보는 실물에서 추려 제시):
   - 「한 행은 **무엇 하나**에 대한 말입니까?」 (wafer_id 발견 → "웨이퍼?" 제안)
   - 「일어난 **사건**입니까, 정해 둔 **규칙/대장**입니까?」
   - (사건이면) 「무슨 일입니까?」 — claim 견본 문장들로 제시
   - 「언제인지는 어느 컬럼입니까?」 「같은 행이 다시 오면 뭘로 알아봅니까?」
3. 답 → Pack·claim·binding **초안 전체**를 시스템이 생성. 초안 값마다
   근거와 «추정» 표지(COMMON_RULES_DELTA A-4).
4. 인터뷰를 건너뛰고 v2 04의 원래 흐름(Pack 직접 선택)으로 가는 뒷문 유지.

### 뒤 — 문장 판정 (승인 표면)
5. 드라이런 원자를 **한국어 문장으로** 렌더(육하 렌더러 재사용):
   「CL-2601-006-A1은 CL-2601-006에서 갈라져 나왔다」 ×N + 원자 수 요약.
6. **틀린 문장을 클릭하면 그 문장을 만든 binding이 열린다** — 수정은 문장에서
   출발한다. JSON은 고급 상세.
7. 승인 → 기존 3단 저장(검증·드라이런 토큰·저장+리로드+「먹었는가」) 그대로.

## 제약

- 인터뷰 질문·후보 추림 규칙을 프론트에 하드코딩하지 않는다 — 질문은 Pack
  메타데이터(전제·claim 견본)에서 계산.
- 알 수 없는 의미를 자동 확정하지 않는다(v2 04 계약). 인터뷰가 못 좁히면
  「모르겠음 — 후보 N개」로 정직하게 남기고 사람에게 넘긴다.
- 문장 렌더에 내부 어휘 금지(COMMON_RULES_DELTA C).

## 테스트

- 인터뷰 4답 → 초안 생성 → 문장 N개 → 승인 → 저장까지 **문서 없이** 완주
  (P-01~03 재현 시나리오의 종결 검증).
- 틀린 답을 주면 초안이 «추정» 표지와 함께 다르게 나오고, 문장 클릭 → binding
  수정 → 문장 갱신 왕복.
- 드라이런 DB 쓰기 0 · 기존 admin 회귀 · production build.
