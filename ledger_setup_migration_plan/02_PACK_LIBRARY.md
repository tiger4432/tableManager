# 2단계 — 현행 세계를 덮는 Pack 라이브러리

v2 02(`CLAIM_MAPPING_PROFILE`)의 Profile/Pack 계약과 1단계 전환표를 적용한다.
Pack은 **엔진에 도메인을 넣지 않기 위한 선언**이다(v2 규칙 3) — 여기서 만드는
것은 선언 파일이지 코드 분기가 아니다.

## 목표

현행 원장이 이미 말하는 것 + 판정으로 예약된 것을 덮는 Pack 집합. 각 Pack은
마법사가 그대로 렌더할 수 있는 **한국어 메타데이터 완비**여야 한다(3단계 사전의
원천이 이 파일들이다).

## Pack 목록 (가칭 — 1단계 보고로 조정)

| Pack | claim | 덮는 현행 | 비고 |
|---|---|---|---|
| `observation@1` | 발견(finding) | void_obs·delam_obs | run/method 요구를 **claim 메타데이터로** 명시 — 「분모가 서려면 검사 이력 표가 필요하다」를 마법사가 미리 말하게 |
| `transfer@1` | 이동(movement) | dt_log | from/to/qty/container |
| `lineage@1` | 갈라짐·합침·등록 | lot_event | 두 줄 문법·리스트 짝짓기는 mapper 구현에 캡슐화(선언화 금지 — 검토서 §7-⑤) |
| `process@1` | 공정 통과 | (신규 — process_event 류) | recipe {id,rev} 중첩을 role 둘로 받아 Pack이 접는다 |
| `measurement@1` | 계측 | (신규 — MI 표) | 4상태 계약을 **NULL 패턴→상태 규칙**으로 선언(예: value NULL이면 state 후보 제시) |
| `registry@1` | 배정·규칙표 | bonding_map 류 대장 | R-N: 맵을 주어로·전개 금지·계획≠실행. 승인 시각 없으면 「행 생성 시각임」 표지 강제 |
| `derivation@1` | 규칙 파생(태그·스킴) | R-M ⑤ | 조건은 원장에서·3류·evidence 필수 |

## 각 Pack이 반드시 갖출 것

- claim별: 한국어 이름·한 줄 뜻·**이 claim이 만드는 문장의 견본**("〈웨이퍼〉가
  〈공정〉을 지났다") · role 목록(각 role: 한국어 라벨·필수 여부·기대 타입·
  좋은 예/나쁜 예 값).
- **전제 선언**: 이 claim이 화면에서 «보이려면» 추가로 필요한 것(run 표·축 선언·
  바인딩)을 Pack 메타데이터에 적는다 — 5단계 현황판이 이걸 읽어 결핍을 계산한다.
- 대응 predicate/서명으로의 컴파일 규칙(고급 상세에만 노출).

## 제약

- Pack에 특정 테이블·컬럼명 금지(스키마 독립성 — v2 규칙 1).
- 새 술어가 필요하면 R-M 절차(ontology 층 등재)로 — Pack이 어휘를 몰래 늘리지
  않는다.
- 주어 타입·불량 종류가 코드에 막히는 지점은 **구현하지 말고 판정 요청 목록으로**.

## 테스트

- Pack 스키마 validator(필수 메타데이터 완비 검사 — 한국어 라벨 빠지면 실패).
- 같은 `transfer@1`을 서로 다른 소스 둘에 바인딩해 서로 다른 원자가 나오는 것.
- 1단계 하니스로: Pack 경유 결과 = legacy 결과 (소스별).

## 보고

Pack 파일 목록 · claim/role 표 · 판정 요청 목록(주어 타입·종류 등) ·
전제 선언이 5단계에 주는 인터페이스.

## 개정 (소유자, 2026-08-17): Pack은 설계물이 아니라 «추출물»이다

소유자 판정: 「Pack 부실한 상태에서 (마법사를) 하면 독이 된다 — 초기에는 Pack
설계도 동시에 해야 한다.」 책상 설계 Pack 위에 세운 마법사는 틀린 추상으로
사용자를 자신 있게 안내하는 기계가 된다.

**Pack 성숙 규율 (이 단계의 작동 방식을 바꾼다):**

1. **Pack 초안은 실제 착지에서 추출한다.** 위 7종 표는 «목표 목록»이지 선작성
   대상이 아니다. 소유자가 러너북(as-is)으로 실제 소스 하나를 세팅할 때마다,
   그 과정에서 나온 바인딩·전제·문장을 Pack 후보로 **추출**한다.
2. **v1 승격 기준: 서로 다른 소스 «둘»이 같은 Pack으로 착지.** 소스 하나만
   지나간 Pack은 그 소스의 사진이지 추상이 아니다 — draft 표지를 달고 남는다.
   둘째 소스에서 안 맞는 부분이 드러나는 지점이 Pack의 진짜 경계다.
3. **따라서 초기 정문은 마법사가 아니라 «원시 모드»다** — Profile 손편집 +
   드라이런 + 문장 미리보기. 마법사(04)는 v1 Pack이 둘 이상 실증된 영역에만
   인터뷰를 열고, 미실증 모양엔 「아직 이 모양의 Pack 없음 — 원시 모드로」를
   정직하게 안내한다. (04 제약에 반영)
4. **소유자의 현재 재구축 작업이 곧 Pack 설계 세션이다.** 소스 하나 착지 →
   짧은 추출 회의(무엇이 일반화되는가, 무엇이 이 소스 고유인가) → Pack 후보
   갱신. 이 루프가 1~2단계의 실제 실행 형태다.
