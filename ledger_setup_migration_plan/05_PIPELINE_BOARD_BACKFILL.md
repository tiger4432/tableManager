# 5단계 — 파이프라인 현황판과 백필 라우트

P-04의 종결 단계. 2단계 Pack의 **전제 선언**이 입력이다.

## 목표

기능 하나(소스 하나·불량 종류 하나) 기준으로 「필요한 것 N개 중 M개 충족 —
다음: ○○」을 계산해 주는 라우트와, 그 자리에서 실행하는 백필.

## 흐름

1. `GET /admin/ledger/pipeline` — 소스/기능 단위 사슬 상태:
   ```
   표 선언 ✓ → Profile ✓ → 드라이런 ✓ → 원자 0 ← 「백필 미실행」 [실행]
   → 축·기하 ✗ 「siblings_axes에 이 소스의 축 없음」 → 온톨로지 ✗ 「바인딩 0」
   ```
   각 단계: 충족/결핍/무관 + **결핍의 이름** + 다음 행동(버튼 또는 파일·블록
   링크). 계산 근거는 Pack 전제 선언 + 실측(원자 수·선언 존재).
2. `POST /admin/ledger/backfill` — 소스 지정, mapper 경로로 실행, 결과는
   분자/원자/거절 수. strict 토큰. 실행 후 현황판 갱신.
3. 구조 뷰 선언 패널과 상호 링크(행 ↔ 현황판 항목).
4. 「원장 셋업」 탭의 머리에 현황판을 앉힌다 — 셋업의 첫 화면이 «지금 어디까지
   됐나»가 되게.

## 제약

- 현황판이 «추측»하지 않는다 — 충족/결핍은 전부 실측(선언 존재·원자 수·
  관계 존재)이고, 판단 불가면 「판단 불가 — 이유」로.
- 백필은 게이트 경유 그대로(전량 거절도 결과로 보고 — 숨기지 않는다).

## 테스트

- 새 소스를 단계별로 채워 가며 현황판이 결핍을 정확히 갱신.
- 백필 라우트: 쓰기 결과 수치 = CLI 백필과 동일, 거절 사유 노출.
- 결핍 0이면 대조 API에 실제로 후보가 뜨는 것까지(끝까지 이어짐 검증).

## 보고

라우트 스키마 · 화면 경로 · 「저장했는데 왜 비었지」 재현 시나리오가 현황판
문장으로 해소되는 기록.

## 추가 (MAPPER_STANDARD 연동)

현황판의 결핍 계산 입력은 Pack **전제 선언 + mapper `REQUIRES`**다(표준 §2).
둘은 같은 어휘(관계 이름·선언 파일·블록)를 쓰며, 결핍 문구는 그 어휘를 그대로
인용한다 — 현황판이 자기 문구를 발명하지 않는다.
