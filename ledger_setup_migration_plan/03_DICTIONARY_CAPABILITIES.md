# 3단계 — 사전 API와 「답할 수 있는 질문」

P-01·02·03의 종결 단계. 2단계 Pack 메타데이터가 원천이다.

## 목표

닫힌 목록 전부를 한국어 뜻·실물 예시와 함께 내려주는 라우트 하나, 그리고
온톨로지를 낱말이 아니라 **능력(답할 수 있는 질문)**으로 렌더하는 화면 하나.

## 흐름

1. `GET /admin/ledger/dictionary` — 응답에:
   - Pack·claim·role (2단계 메타데이터 그대로 — 한국어 라벨·뜻·견본 문장·필수)
   - 열거형 전부: object_kind·traversable·direction·상태값·불량 종류·method
   - 술어(고급 상세용): 서명 + origin(code/config) + **라이브 예시 원자 1개**
     (원장에서 실물 인용, 없으면 「아직 원자 0」) + 사용량
2. **능력 렌더**: 「지금 이 원장이 답할 수 있는 질문」 — claim 단위로,
   실제 원자 수와 함께. ("이 웨이퍼는 어디서 왔나 — 1,083건이 말하고 있음")
   소스를 하나 이으면 **능력의 증분**("새로 답할 수 있게 되는 것")을 미리 보여줌.
3. 기존 셋업 화면(원장 셋업 탭)의 모든 자유 기입 열거 자리를 이 API 드롭다운으로
   교체. 자유 기입은 컬럼명·리터럴에만 남는다.

## 제약

- 사전의 «내용»을 프론트에 하드코딩하지 않는다 — 전부 서버가 Pack·어휘에서
  계산. Pack에 한국어가 빠져 있으면 사전이 빈칸을 «빈칸으로» 보여준다(지어내기
  금지).
- 예시 원자는 실물 인용만 — 견본을 합성하지 않는다.

## 테스트

- 사전 응답 완비성: 등재된 Pack/claim/열거형이 전부 응답에 있고 한국어 라벨
  누락이 검출된다.
- 예시 원자가 실제 원장 행과 일치.
- 셋업 화면에서 자유 기입 열거형 0 (DOM 검사).

## 추가 (원고·개념 틀)

- 사전 화면의 산문 원고는 **`PRIMER.md`가 정본**이다(한 행의 여행 §1 표·
  vocabulary §2·읽기측 §5). 화면은 이 원고를 렌더하지 재작성하지 않는다.
- 능력 렌더의 개념 틀은 **「읽기 = 서브그래프 추출」**(PRIMER §5-2-bis) —
  「답할 수 있는 질문」 목록은 다섯 해석기의 추출 기준을 사람 말로 옮긴 것이다.
