# 7단계 — legacy 번역기 은퇴

`COMMON_RULES_DELTA.md` B-6을 적용한다. 이 단계 전까지 legacy는 동결 병행.

## 목표

소스 전부가 mapper 경로로 등가 증명을 마친 뒤, legacy 번역기 경로를 한꺼번에
은퇴시킨다. 「기존 번역기 문법」이 신규 사용자의 눈에 띄지 않는 상태가 완료다.

## 전제 (전부 충족돼야 착수)

- 1단계 하니스 기준 소스별 등가: 차이 0 또는 소유자가 승인한 «설명된 차이».
- 5단계 현황판·백필이 mapper 경로만으로 전 소스를 서빙.
- 실데이터 유입(자동 갱신·체인)이 mapper 경로로 전환 확인.

## 흐름

1. 은퇴 대상 목록 확정: `lot_event_translator.py`·`observation_translator.py`·
   `transfer_translator.py`·`declared_translator.py`와 그 전용 config 블록.
2. 구 그래프 은퇴의 전례를 따른다: 진입점 차단 먼저(백필·워커가 legacy를 못
   집게), 사체 정리는 대충·나중에 일괄(코드 삭제는 별도 커밋).
3. config에서 legacy 전용 문법 블록을 Profile로 이관 완료 표시 후 보관
   (`retired/` 이동 — 삭제 아님).
4. 문서 갱신: 가이드가 legacy 문법을 가르치지 않게. 은퇴 표지는 6단계 검사기의
   은퇴 유산 목록에 등재.

## 제약

- 원자 재백필 금지 — 은퇴는 «쓰는 길»의 교체지 이미 쓴 원자와 무관하다
  (source_who가 legacy 이름인 원자는 역사로 남는다 — 정상).
- 되돌림 경로 문서화: 은퇴 커밋 해시와 재활성 절차 한 단락.

## 테스트

- 전 소스 백필이 mapper 경로만으로 초록.
- legacy 진입점 호출 시 명확한 거절문(「은퇴됨 — Profile로」).
- 기존 원자 읽기 경로 무손상(trace·대조·여정 회귀).
