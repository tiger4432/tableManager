# 📊 Status Report (상황 보고 표준)

총괄 PM(및 모든 에이전트)이 프로젝트 상황을 보고할 때 따르는 표준 절차. **기억이 아니라 파일 근거로 보고한다** — 컨텍스트 압축·세션 교체 후에도 이 절차만 따르면 동일 품질의 보고가 나온다.

## 1. 근거 수집 (보고 전 필수 — 추측 금지)

| 순서 | 소스 | 얻는 것 |
|---|---|---|
| 1 | `docs/process/PROJECT_STATUS.md` | 현재 초점 · 열린 문제 · 최근 완료 (단일 상태 보드) |
| 2 | `git log --oneline -15` + `git status --short` | 실제 커밋된 것 vs 미커밋 작업물 |
| 3 | `git worktree list` + `git branch -vv` | 병렬 작업 중인 브랜치·병합 대기물 |
| 4 | 백그라운드 에이전트/별도 세션 유무 | 진행 중(미완) 위임 작업 |
| 5 | (필요시) `docs/overview/SYSTEM_OVERVIEW.md` §1 | 핵심 가치 — 각 작업이 어느 가치에 복무하는지 매핑용 |

## 2. 보고 구조 (3축 고정)

### ✅ 해결한 것 (Done)
- 커밋 해시가 있는 것만. **"무엇을"이 아니라 "어떤 문제가 사라졌는지"**로 서술 (예: "커밋 N개" ❌ → "교정이 화면에 영영 안 뜨는 경로 제거" ✅).
- 정량 성과가 있으면 실측 수치로 (예: 10s → 31ms).
- 각 항목을 **핵심 가치(SSOT §1의 5대 가치)에 매핑** — 왜 중요했는지가 드러나게.

### 🔄 하고 있는 것 (Doing)
- 진행 중인 위임(에이전트/세션/worktree)과 각각의 범위·예상 산출물.
- 검수·병합·커밋 대기물 (누구 승인이 필요한지 명시).

### ⏭️ 할 것 (Next)
- **즉시 다음 단계** (현재 작업 완료 시 이어질 것) → **단기 백로그** (보드 열린 문제 중 우선순위) → **로드맵** (핵심 가치 기준 장기 방향) 3단 구분.
- 사용자 결정이 필요한 분기점은 ⚠️로 표시.

## 3. 서술 규율

- **독자는 자리를 비웠다 돌아온 팀장**이다: 세션 중 만든 코드네임(F1, C-2 등)은 첫 등장 시 한 줄 설명을 붙인다.
- 표는 열거용, 서사는 문장으로. 화살표 축약(`A→B→실패`) 금지.
- 완료를 과장하지 않는다: 테스트 실패·미검증·리스크 수용은 그대로 표기.
- 보고가 길어지면 **맨 앞에 3줄 TL;DR**.

## 4. 보고 후 (docs-as-code)

- 보고 중 보드와 실제 상태의 불일치를 발견하면 **즉시 `PROJECT_STATUS.md`를 고친다** (보고서가 아니라 보드가 SSOT).
- 정기 보고가 아닌 마일스톤 보고(큰 단계 완료)면 `docs/history/`에 이력 스냅샷을 남길지 판단한다.
