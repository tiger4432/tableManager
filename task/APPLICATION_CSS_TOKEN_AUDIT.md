# 목업 ↔ 라이브 «계측» 차이 — 눈으로는 안 잡히는 것만

> 소유자 01:2x 「할거 없으면 css라도 빡세게 만져」
> 도착지 판정 ①「목업 2a 를 옆에 놓고 부품마다 비교했을 때 «같아 보인다»」
> ⚠️ **파일은 안 건드렸습니다.** `board.css` 는 클라 레인이 «최근 90분에 네 번» 커밋 중입니다.
>    아래는 붙여 넣을 수 있게 값까지 뽑은 목록입니다.

측정: 목업 `localhost:8123` · 라이브 `localhost:8080/rnd-board.html`, 둘 다 1280px.

---

## 🔴 1. 한글 폰트가 «빠져 있습니다» — 이게 제일 큽니다

```
목업    Outfit, "Noto Sans KR", -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif
라이브  Outfit, system-ui, sans-serif                        board.css:20
```
`Outfit` 에는 한글이 없어 **한글은 전부 다음 폰트로 떨어집니다.** 그게 서로 다릅니다.

**실측 — 같은 한글 문자열 20px 폭:**
```
목업   223.2px   (-> Noto Sans KR)
라이브 240.8px   (-> system-ui)
차이   +17.6px = «7.9% 더 넓다»
```
🔴 **이 화면은 글자가 대부분 한글입니다.** 폭이 8% 다르면 줄바꿈·칸 폭·잘림이 전부 달라져
「부품마다 비교했을 때 같아 보인다」가 **처음부터 불가능**합니다.

📎 **이 박스에 `Noto Sans KR` 이 있습니다** (`document.fonts.check` = true, 목업·라이브 «양쪽»에서).
선언만 고치면 됩니다. **한 줄입니다.**

---

## 2. 패널 모서리 — 라이브가 «직각»입니다

```
목업    .패널  border-radius: 8px   (66개) · 안쪽 카드 10px
라이브  .rb-panel border-radius: 0px  -> 8px 인 요소 «0개»
```

## 3. 알약(pill)이 통째로 없습니다

```
목업    radius 20px 요소 33개 · 연한 색면 위에 얹힘
라이브  radius 20px 요소 «0개».  50% 원 12개(①② 표식)만 있음
```

**목업의 알약 토큰 — 그대로 씁니다:**
```
중립      radius 20px · bg #FFFFFF            · fg rgb(31,39,51)   · 12.5px · padding 2px 8px
파랑      radius 20px · bg rgb(232,240,252)   · fg rgb(26,102,208) · 12px   · padding 2px 8px
보라      radius 20px · bg rgb(240,233,251)   · fg rgb(109,40,217) · 11px   · padding 2px 7px
테두리형   radius 20px · bg transparent        · fg rgb(71,83,107)  · 11px   · padding 2px 7px
```

## 4. 강조 위계가 «평평합니다»

```
weight    목업 700 : 110개 · 600 : 190 · 500 : 30
          라이브 700 :  «3개» · 600 :  42 · 500 : «0개»
```
500 축이 없어서 「보통 / 굵게」 둘뿐입니다. 목업은 셋입니다.

## 5. 본문이 «한 단» 작습니다

```
최빈 크기   목업   12.5px (606) · 16px (369) · 11.5px (349) · 12px (295)
            라이브 11.5px (163) · 11px (161) · 16px (85) · 12.5px (41)
```
🔴 라이브의 **최빈이 11.5/11px** 입니다 — 목업의 본문 단(12.5px)이 라이브에선 소수(41개)입니다.
상설 「작은 글씨는 없느니만 못하다 · 가독성 = 기능」에 걸립니다.

## 6. 색면이 없습니다

```
목업    rgb(232,240,252) 27 · rgb(227,243,247) 10 · rgb(240,233,251) 8 · rgb(194,47,47) 13
라이브  전부 «0».  강조색은 rgb(26,102,208) «1개»뿐
```
목업의 「빨강 강조」(194,47,47)가 라이브엔 **하나도 없습니다.**

## ✅ 통과한 것 — 여기는 손대지 마십시오

```
타입 하한   11px 미만 텍스트 «0개»          (상설 통과)
대비        WCAG AA 미달 «0개»              (전 요소 계산)
가로 넘침   없음 (doc 1280 = win 1280)
인라인 오염 11개인데 «전부» grid-area·min-width — 조립식 규칙대로 «배치는 부품 밖»
```

## 순서 — 효과 대비 비용

```
1  폰트 한 줄        board.css:20 에 "Noto Sans KR" 을 Outfit 뒤에    ← 제일 크고 제일 싸다
2  패널 8px          .rb-panel border-radius
3  본문 12.5px        11.5 -> 12.5 한 단 올리기
4  알약 토큰 넷        위 값 그대로
5  weight 500 축
6  색면 · 빨강 강조
```

## 안 잰 것

```
1  부품별 «위치·크기» 대조     스크린샷 경로가 막혀 못 봤다 (브라우저 창 미표시)
2  상호작용(클릭·Ctrl·감쇠)     이번 계측은 «정지 화면»만이다
3  목업의 JetBrains Mono 로딩   목업에서 loaded 1 · unloaded 다수 — 라이브와 대조 안 했다
```
