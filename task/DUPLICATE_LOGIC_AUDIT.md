## 🔴 S1. 복합 업무키 조립 — «넷» (서버)  ← 가장 위험

행의 «정체성»을 만드는 코드가 넷이고, 재료도 빈 값 정책도 다릅니다.

```
① crud.py:2297  assemble_composite_business_key
                재료: payload 의 `updates`
                빈 값: `_unfilled_composite_parts` -> «is_blank_value»
                (이 함수의 주석이 「그 둘은 같은 질문이어야 한다」고 이미 경고합니다)
② crud.py:2914  행 동기화 — 소스 컬럼이 «바뀌었을 때»
                재료: «행 객체» getattr
                빈 값: `all(v != "")`  «손으로» · 비면 «폴백»
③ crud.py:4439  셀 «하나» 바뀌었을 때
                재료: «행 객체» getattr
                빈 값: `all(v != "")`  «손으로» · 비면 «None»
④ enrichment_mapper.py:158  파생 표 키
                재료: config 를 «자기가» 읽음
```

**왜 위험한가**
```
구분자·컬럼 목록이 바뀌는 날 «넷 중 몇»만 따라갑니다 -> 같은 행이 두 키를 갖습니다
오류 «안 납니다». 행도 들어갑니다. 나중에 «중복»으로만 보입니다
2026-09-02 소유자가 dt_log 에서 겪은 것이 이 부류입니다
```
⚠️ **총괄이 그날 「조합은 assemble_composite_business_key 가 정본」이라고 안내했는데,
   정본은 «쓰기 경로 하나»에 대해서만 정본입니다.** 그 안내를 여기서 정정합니다.

**해체 방향(제안, 미승인)**: 「재료를 받아 키를 낸다」를 «한 함수»로. 재료 셋(updates / row / config)은
호출자가 dict 로 맞춰 넘기고, 빈 값 판정은 `is_blank_value` «하나».

## 🔴 S2. 빈 값 판정 — 정본 «10» · 손으로 «25» (서버)

```
is_blank_value(...) 호출        10
strip() == "" 류를 손으로        25   ← raw grep. «그중 몇이 같은 질문인지는 아직 안 갈랐습니다»
```
⚠️ 25 는 «수»일 뿐 판정이 아닙니다. 파싱처럼 정당하게 다른 것이 섞여 있습니다.
다음 라운드에서 «부류로» 갈라야 합니다 — 아래 셋으로:
```
ⓐ 같은 질문인데 손으로 쓴 것        -> 정본으로 바꾼다
ⓑ 다른 질문 (예: 파서의 입력 검증)   -> 그대로 둔다
ⓒ 판단 불가                       -> 그 자리를 이름으로 남긴다
```

## 🟡 C1. 절단 판정 — «세 철자» (클라, 한 파일 안)

`map_editor.js` 안에서 「응답이 잘렸나」를 세 가지로 씁니다.
```
:4210  typeof result.total === 'number' && result.total > result.data.length   -> «던짐»
:5339  같은 식                                                                 -> «경고»
:10066 Number(result && result.total)                                          -> 「N개 중 M개」
```
🔴 그리고 이 셋이 `defer_total` 을 «못 붙이는» 이유였습니다 (2026-09-02 클라 판정).
   `typeof null === 'number'` 는 거짓, `Number(null)` 은 0 이라 «조용히» 꺼집니다.
**해체하면 그 셋이 한 번에 `defer_total` 을 받을 수 있게 됩니다.**
