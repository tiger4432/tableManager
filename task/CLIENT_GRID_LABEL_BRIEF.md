# 그리드에 «선언된 것이 보이게» — 라벨 셋과 「선택한 행 다시 번역」

총괄 -> 클라. 2026-08-31. 설계 정본은 `task/GRID_RESCOPE_BRIEF.md` (소유자 판정 둘로 모양 확정).
이 문서는 «클라 몫»만 떼어 낸 것입니다.

## 🔴 시작 조건 — 서버 칸 «하나»를 기다립니다. 그 전엔 착수하지 마십시오
```
필요   GET /api/ledger/declaration 의 응답에 sources 절
       [ { source, relation, emits[술어], scope_columns[선언된 입력 컬럼] } ]
지금   { state, entities(9), predicates(14) }  <- sources 가 «없습니다»
발주   구현자 큐의 «맨 앞»에 넣었습니다 (2026-08-31 02:0x). 곧 옵니다
```
```bash
curl -s localhost:8080/api/ledger/declaration | python -c "import sys,json;print('sources' in json.load(sys.stdin))"
```
⚠️ **없는 칸에 맞춰 «먼저» 짓지 마십시오.** 화면이 픽셀 0 이 되고 하니스는 초록입니다 —
   이 저장소에 이미 한 번 난 사고입니다. 감시로 기다렸다가 «생긴 뒤» 붙이십시오.

## 도착지
```
운영자가 그리드에서 «선언된 소스 표»를 열면 그것이 소스임을 «보고»,
행을 골라 「다시 번역」을 누르면 그 범위만 다시 돕니다.
선언 안 된 표에서는 그 메뉴가 «없고», 없다는 것도 «보입니다».
```

## 1. 자리 — 새 화면 «없습니다»
```
메인 그리드   client2/src/main.js (컨텍스트 메뉴가 이미 있습니다) · grid.js
새 창·새 탭·새 라우트·모달   ⛔ 전부 없습니다
```

## 2. 라벨 — «머리에 한 줄». 그리고 «셋»으로 말합니다
```
「원장 소스 — dt_transfer · 만드는 것: transfer@1」   선언에 «있습니다»
「원장에 안 들어갑니다」                           선언에 «없습니다» — 이것도 말해야 합니다
「선언을 못 읽었습니다」                           라우트 실패 — 위 둘과 «구별»되어야 합니다
```
🔴 셋을 「라벨 없음」 하나로 합치지 마십시오. 합치면 「소스가 아님」과 「못 읽음」이 같아지고,
그건 이 프로젝트가 반복해서 잡아 온 병입니다(상설 ⑥ 「부재는 셋으로 말한다」).

## 3. 메뉴 — 선택이 있을 때만 «한 줄»
```
[ 선택한 N행 다시 번역 ]
누르면   🔴 «드라이런 먼저». 「거둘 N · 다시 만들 M」을 보여주고 «그다음» 실행 여부를 묻습니다
범위     선택한 행을 scope_columns 중 «하나»로 묶습니다
         -> 고를 수 있는 컬럼은 서버가 준 그 목록«뿐»입니다. 화면이 딴 컬럼을 제안하면 서버가 거절합니다
```
⛔ 전체 선택을 «막지» 마십시오. 대신 드라이런 수를 보여주고 사람이 정하게 하십시오 (소유자 판정).

### 🔴 「0」을 문장으로 «짓지» 마십시오 — 값이 정해져 있습니다
드라이런이 0을 낼 때 그것이 무슨 뜻인지는 `task/APPLICATION_RUN_WORDS.md` 가 «확정»했습니다.
```
아직 · 전수가 아님 · 가리킬 수 없음 · 정말 없음 · 이미 빠져 있음 · 해당 없음
```
서버가 «어느 것인지»를 값으로 줍니다. 클라는 그 값으로 문구를 그리고, **문장을 짓지 않습니다.**
(이건 `retroactive_view.js` 가 `count_kind` 를 다루는 방식과 «같습니다» — 그 규율 그대로.)

```

    (「못 읽음」은 라우트를 죽여서 만드십시오)

G4  드라이런이 «먼저» 뜨고, 그 전에는 아무것도 안 써지는가
```
