# 「접힘」 셋 — 펼치면 무엇이 나오나

총괄 큐 1번(`de46a838`). 총괄이 「접힘」이라 이름 붙인 셋의 «펼친 모양»입니다.
**적는 것은 셋뿐입니다** — ① 접히기 전에 무엇이 있었나 · ② 무엇이 반드시 살아야 하나(왜) ·
③ 그것이 어디에 있어야 하나.

```
잰 방법   커밋된 HEAD 를 «읽어» 접는 자리를 열었습니다. 화면은 안 열었습니다
         값이 아니라 «사실의 이름»으로 적었습니다
⛔ 스키마 없음 · UI 설계 없음 · 어느 것이 쉬운지 «안 골랐습니다»
```

# ① Ⅱ-2 — 봉투 거절

## ① 접히기 «전»에 있던 것
```
위반은 «여럿»일 수 있고, 하나하나가 셋을 듭니다:  «코드» · «자리» · «문장»
그리고 그 위반이 «어느 원자»의 것인지도 붙습니다
```

## ② 반드시 살아야 하는 것 — **«자리»입니다. 그리고 «몇 개 중 몇 개»**
```
지금 나가는 것   «사유 이름» 하나 (닫힌 목록 열둘 중)
                🔴 그것도 «첫 위반»의 것입니다 — 둘째부터는 사유에 안 실립니다
🔴 왜 자리인가   자리가 없으면 운영자가 이 둘을 «못 가릅니다»:
                「내 선언이 틀렸다」  ↔  「내 소스의 «어떤 행»이 비었다」
                둘은 «반대 행동»입니다 — 하나는 선언을 고치고, 하나는 원천을 고칩니다
🔵 이미 그 판별을 «하는» 화면이 옆에 있습니다  선언 초안 쪽은 「몇 개 중 몇 개 · 어느 칸」을 같이 냅니다
```
🔵 **그리고 서버가 이미 «들고» 있습니다** — 게이트가 코드·자리를 «버리지 않고» 보고에 담습니다.
   쓰는 곳 «둘», 읽는 곳 «0». 나가는 길이 없을 뿐입니다.

## ③ 어디에 있어야 하나 — **«응답의 칸»입니다. 행의 칸이 될 수 없습니다**
```
행의 칸   이미 있습니다 — 소스마다 «사유별 누계»(수 · 마지막 시각)
         🔴 여기에 «자리»를 넣을 수 없습니다. 그 칸은 「합이 거절 수와 같다」가 «불변식»이라,
            원자마다 다른 자리를 넣으면 그 등식이 깨집니다
응답의 칸  자리는 «원자마다» 다르므로 «표본»의 성질입니다
         🔵 게이트에 표본 상한이 «이미» 있습니다 — 같은 규율에 실으면 됩니다
```

# ② Ⅱ-4 — 소급 실행의 자리표

## ① 접히기 «전»에 있던 것
```
실행이 든 것   «무엇을 하는 실행인가»(연산) · «인자» · «실행 id» · «요청자»
그리고 사실 하나   🔴 「이 사건은 «표가 하나가 아니다»」
```

## ② 반드시 살아야 하는 것 — **「표가 없다」는 «사실» 자체**
```
지금 나가는 것   «표 이름 하나». 그런데 그런 표는 «없습니다» — 자리표입니다
🔴 왜 살아야 하나  실패 목록이 «걸린 표»로 줄을 세웁니다. 운영자는 거기서 본 이름을
                표 등록에서 찾습니다 — 그리고 «못 찾습니다». 없는 표를 찾게 됩니다
                「표가 없는 사건」과 「이름이 그런 표」가 «같은 픽셀»입니다
🔵 대신 있어야 할 답 «연산»입니다. 실행이 «무엇을 하는지»는 이미 실행에 붙어 있습니다
```
🔴 **이건 부재를 «값»으로 쓴 것입니다** — 제 부재 어휘가 다루는 바로 그 병의 한 층 아래입니다.
   「해당 없음」을 적을 자리가 없어서 «이름»을 지어냈습니다.

## ③ 어디에 있어야 하나 — **«행의 칸»입니다. 그리고 그 행이 «이미» 답을 듭니다**
```
사건 행이 이미 «연산»과 «인자»를 자기 안에 들고 있습니다
🔴 없는 것은 사실이 아니라 «읽는 쪽의 규칙»입니다 — 읽는 쪽이 「이 사건의 정체 = 표 이름」으로
   보고 있어서, 표가 없는 사건에 이름을 지어 줘야 했습니다
```

# ③ Ⅳ-3 — 맵퍼 재적재

## ① 접히기 «전»에 있던 것
```
「다시 읽었다」는 «시각»입니다. 워커가 그 시각을 «들고» 있습니다
그리고 그것과 짝인 상태 하나   「«한 번도» 안 읽었다」
```

## ② 반드시 살아야 하는 것 — **«마지막 재적재 시각»과 「한 번도 없음」**
```
지금 나가는 것   «로그 한 문장» 안의 조각. 그리고 그 문장은 «조용할 때는» 안 나옵니다
🔴 왜 살아야 하나  운영자가 이 고장을 부르는 말이 「재기동하면 없어진다」입니다.
                «마지막 재적재로부터 얼마»가 그 말을 «수»로 바꾸는 유일한 값입니다
                그게 없으면 「내가 고친 것이 도는가」에 답할 방법이 «없습니다»
                -> 그래서 운영자는 «고쳤는데도» 재기동합니다. 그게 이 항목의 비용입니다
⚠️ 「한 번도 없음」은 «0초 전»이 아닙니다. 둘이 같은 픽셀이 되면 이 값은 쓸모가 없습니다
```

## ③ 어디에 있어야 하나 — **«응답의 칸». 어느 행에도 안 붙습니다**
```
이건 «행»의 성질이 아니라 «프로세스»의 성질입니다 — 어느 규칙의 것도 어느 맵퍼의 것도 아닙니다
🔵 그리고 프로세스의 성질을 이미 «내는» 자리가 있습니다 (심박이 그 모양입니다)
   -> 새 종류가 아니라 «그 옆»입니다
```

# 🔴 셋은 «같은 모양»인가 — **둘은 같고, 하나는 «반대»입니다**

```
Ⅱ-2 · Ⅳ-3   사실이 «있는데» 나가는 길이 없습니다        -> 접힘이 «출구»에서 일어납니다
             (하나는 아무도 안 읽는 보고에, 하나는 로그 문장에)
             할 일은 «들고 있는 것을 내보내는» 것입니다

Ⅱ-4        사실이 없는 게 아니라 «빈 자리를 못 만들어서» 값을 지어냈습니다
             -> 접힘이 «입구»에서 일어납니다
             할 일은 내보내는 것이 아니라 «읽는 쪽이 무엇을 정체로 보나»를 바꾸는 것입니다
```
🔴 **그래서 구현자의 갈림은 「둘 + 하나」입니다.** 앞의 둘은 «같은 일»을 두 번 하는 것이고,
셋째는 그것과 성질이 다릅니다 — 앞의 둘을 먼저 묶어도 셋째는 따라오지 «않습니다».
