## ③ 🔴 맵 — 틀렸습니다. 그리고 총괄이 「제일 나쁘다」고 한 바로 그 종류입니다

```
                 화면/API      원장·소스 직접      판정
141칸              141            141            ✓
검사               29             «30»           ✗  한 자리가 사라진다
발견               13             «14»           ✗  사라진 그 자리에 «보이드가 있다»
```

**원인 — 맵의 분모가 `bonding_log` 입니다.**
```sql
FROM bonding_log b  LEFT JOIN found f …  LEFT JOIN scanned s …
```
검사는 됐는데 `bonding_log` 에 그 자리가 «없으면» 조인에서 **통째로 탈락**합니다.
슬롯 07 에서 탈락하는 자리는 **(0,0)** 이고, 실측:
```
inspection_run  (0,0)  1건 있음
void_obs        (0,0)  1건 있음        <- «발견된 결함이 지도에 안 그려진다»
bonding_log     bx=0,by=0  «0건»       (bx=0 인 행은 3개, by=0 인 행은 1개뿐)
```

**기간 창이 원인이 아닙니다 — 배제했습니다:**
```
window  30d -> 검사 30 · 발견 14      180d -> 30 · 14      365d -> 30 · 14
```

**한 슬롯 문제가 아닙니다 — 전수로 쟀습니다:**
```
SYN-VOID-001 의 슬롯 25개 «전부» 에서 자리가 떨어집니다
slot 01   소스 30 -> 조인 27   «3 자리»
slot 02~25 각 1 자리
```

🔴 **그리고 화면에 「떨어졌다」는 표시가 없습니다.**
`검사 29` 는 「검사된 수」가 아니라 **「검사 ∩ 본딩된 수」**입니다. 라벨이 그렇게 안 말합니다.

📎 **같은 부류를 다른 API 는 «세고 있습니다»** — `/siblings` 응답에
`scanned_outside_universe: 277` 이 «이름 붙어» 들어 있습니다. 맵만 조용히 버립니다.

⚠️ **제가 못 가른 것:** (0,0) 이 «진짜 다이 자리인데 본딩 로그가 빠뜨린 것»인지,
«픽스처가 없는 자리에 검사를 만든 것»인지는 못 정했습니다. `valid_die_ref` 는 product/type 축이라
웨이퍼별로 못 물어봅니다. **어느 쪽이든 화면이 말없이 버리는 것은 그대로 결함입니다.**

### 덤 — 격자가 선언보다 작습니다 (총괄이 이미 아는 건 확인만)
```
bond 축   선언 grid 15×15 = 225칸   응답 141칸   x[0..13] y[0..13] -> «14×14»
core 축   선언 23×23 = 529칸        응답 110칸

```
그리고 **세 투영이 셀 수는 다른데 「발견 13 · 검사 29」는 셋 다 같은 값**을 답니다.
dt 축은 셀이 11개뿐인데 라벨은 검사 29 라고 말합니다 — **18자리가 어디 갔는지 화면이 안 말합니다.**
