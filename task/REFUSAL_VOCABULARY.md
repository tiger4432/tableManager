# 거절의 «어휘» — 명세

총괄 지시(`task/MARKING_CONTRACT.md` 「다음 = A-2」)에 대한 응용 산출물.
페이즈 `task/PHASE_ONTOLOGY_REVIVAL.md` 걸음 ②(「왜 거절됐는지」가 읽힌다)의 «깊은 판».

**근거는 커밋된 코드뿐입니다.** 라이브 선언 값도 이 박스의 행 수도 인용하지 않았습니다.

# 🔴 결론 먼저 — 문제는 「두 어휘가 갈렸다」가 «아닙니다»

지시서가 인용한 주석(`ledger/config_explorer_service.py`, 2026-08-21)은 이렇게 적혀 있습니다.
```
런타임 «85» · 화면 «57» · 공유하는 코드 이름 «0»
```
총괄 경고대로 「주석은 «의도»의 증거이지 «동작»의 증거가 아니다」를 지키고 **다시 셌습니다.**
셋 다 오늘은 다릅니다. 그리고 **다른 방향으로 다릅니다.**

```
🔴 공유가 «0» 이 아닙니다             같은 이름 «6»
🔴 「같은 것을 다르게 부르는 것」은 «둘»뿐   binding · predicate
=> 두 집합은 «경쟁하는 두 방언»이 아닙니다. «서로 다른 것»을 재고 있습니다
   (총괄이 「0 이면 다른 것을 재는 것」이라 적어 두신 그 경우가 «거의» 맞았습니다)
```

## 그러면 진짜 문제는 무엇인가 — 재 보니 «둘»입니다
```
🔴 ① 주소가 «버려지는 경계»가 하나 있습니다
     코드와 경로를 가진 거절들이 그 경계에서 «문장 하나»가 되고, «셋만» 살아남습니다
🔴 ② 거절 «여섯»은 애초에 코드도 경로도 없습니다 — 문장뿐입니다
     문장은 화면의 «어느 칸»에도 붙일 수 없습니다
```

# ① 세었습니다 — 방법과 수

## 방법 (재현 가능하게 적습니다)
```
센 것    코드를 «첫 인자»로 받는 생성자의 문자열 리터럴, 파일별 «중복 없이»
        LedgerSetupValidationError( "code", path, message )
        RoleFrameError( "code", path, message )
        SourcePreparationError( "code", path, message )
        LedgerFrameError · ProfileValidationError · problems.add( "code", ... )
안 센 것  변수로 넘기는 코드 · 시험 파일 · 스크립트
```

## 층이 «둘»이 아니라 «셋»입니다 — 그게 첫 정정입니다
누가 «언제» 부르는지로 갈랐습니다. 파일로 가르면 아무 말도 안 됩니다.
```
L1  저장 시점        setup_bundle.validate_bundle_errors        «41»
    구조·이름·카탈로그. 초안 미리보기가 «맨 먼저» 부릅니다
L2  컴파일 시점      setup_registry.snapshot_compile_errors      «5»
    초안 미리보기가 L1 «다음»에 부릅니다 — 화면에서도 «돕니다»
L3  실행 시점        roleframe · source_preparation · ledger_frame · source_profile  «77»
    행이 있어야 압니다. 화면은 test_run 으로 «같은 것»을 돌립니다
```
🔴 **주석이 「화면 57 vs 런타임 85」로 세운 대립은 L1 대 L3 였고, L2 가 «양쪽»에 있습니다.**
그리고 화면은 이미 L3 를 «돌립니다» — 같은 준비기·같은 맵퍼·같은 컴파일러, 쓰기 없이
(`config_explorer_service.test_run`, 그 주석이 스스로 「이건 두 번째 검증기가 아니다」라고 적어 둠).

## 교집합
```
L1 ∩ L3   «6»   invalid_entity_ref · invalid_predicate · missing_required_role
                unknown_entity_type · unknown_predicate · unknown_role
L1 ∩ L2   «0»
L2 ∩ L3   «1»   unverified_join
```

# ② 대조 — 「같은 것을 다른 이름으로」는 «둘»입니다

이름을 «접두 + 주어»로 갈라 «주어»로 맞췄습니다 (invalid_ · unknown_ · missing_ ·
unsupported_ · ambiguous_ · duplicate_ …를 떼고 남는 것). 기계적이라 다시 셀 수 있습니다.

```
같은 주어      «6»
그중 이름이 갈린 것  «2»
   binding     L1 invalid_binding      <->  L3 unsupported_binding
   predicate   L1 invalid/unknown      <->  L3 invalid/unknown + unsupported_predicate
그중 이름이 같은 것  «4»  (entity_ref · entity_type · required_role · role)
```

## 나머지는 «겹치면 안 되는» 것들이었습니다 — 그래서 겹치지 않습니다
```
L1 에만 «30»   파일 · 카탈로그 · 버전 · 타임존 · id 형식 · 미지 컬럼 · 미지 릴레이션 …
              -> 실행 시점엔 «이미 통과»한 것들입니다. 거기 없는 게 «맞습니다»
L3 에만 «58»   바인딩 값이 비었나 · 한 단위에 값이 둘인가 · 시각이 타임존을 가졌나 ·
              맵퍼가 던졌나 · 준비 산출이 모자라나 …
              -> 행을 봐야 압니다. 폼이 «알 수 없는 게» 맞습니다
```
🔴 **그래서 「두 어휘를 합치자」는 틀린 처방입니다.** 합칠 것이 «둘»뿐이고, 나머지는 각자
다른 시점의 사실입니다. 주석이 스스로 적어 둔 결론과 같습니다 — 「85 를 폼에 이식하면
세 번째 어휘가 생긴다」.

# ③ 그러면 «정본»은 무엇인가 — 코드 이름이 아니라 «주소»입니다

## 근거: 코드를 가진 거절은 «전부» 주소를 함께 가집니다
```
RoleFrameError            (code, path, message)   자기 docstring: "path-addressed"
SourcePreparationError    (code, path, message)   자기 docstring: "path-addressed"
LedgerSetupValidationError(code, path, message)   .to_mapping() 이 셋을 그대로 냅니다
```
🔴 세 층이 이름을 공유하지 않아도 «주소»는 공유합니다 — 셋 다 «선언 문서 안의 한 자리»를
가리킵니다. 화면이 필요한 것은 「같은 이름」이 아니라 **「어느 칸이냐」**입니다.
=> **정본은 «경로»입니다.** 이름은 층마다 달라도 됩니다. 실제로 다른 것을 재고 있으니까요.

## 그런데 그 주소가 «버려지는 자리»가 있습니다 — 이게 A-2 의 실체입니다
```
자리   ledger/config.py `_validate_for_version`
동작   setup_version >= 5 이면 v5 검증기를 부릅니다 (코드 + 경로를 가진 것들)
       그리고 그 결과를 «문장 하나»로 감쌉니다 — LedgerConfigError
       🔴 그 문장에 «앞의 셋»만 넣습니다 (errors[:3])
결과   코드 «없음» · 경로 «없음» · 나머지 거절은 «사라짐»
```
그리고 이 경계는 운영자의 길 위에 «있습니다» — 어드민 화면이 `ledger_config.load()` 로
선언을 읽고, `load` 가 이 함수를 지납니다.

## 코드도 경로도 «처음부터 없는» 것 — 여섯
```
ledger/envelope.py `check_envelope`   violations 를 «문장»으로 모읍니다 — «6»
                                     세계 시각 · 출처 · 번역기 판 · 원문 경로 · 페이로드 둘
```
🔴 이 여섯은 «원자마다» 걸리는 것이고, 운영자가 가장 자주 만나는 부류입니다.
그런데 화면의 어느 칸도 가리키지 못합니다.

⚠️ **세지 «않은» 것 하나를 밝힙니다.** `ledger/config.py` 에는 문장뿐인 `raise` 가 77 개
더 있습니다. 그런데 그건 setup_version 5 «미만»의 문법을 검사하는 자리라, v5 선언에는
안 걸립니다. **부재의 증거로 쓰지 않았습니다** — 「걸릴 수 있나」는 판정이 필요한 별건입니다.

# ④ 그래서 «두 줄»

```
① 「거절은 «무엇이 틀렸나»와 «선언의 어느 칸이냐»를 «항상 함께» 냅니다」
② 「운영자는 그 칸을 열어 고치고, 다시 시험합니다」
```

## 이 두 줄이 서려면 «셋»이 필요합니다 — 코드는 지시서로 넘깁니다
```
1 🔴 주소를 «버리지» 않는다        문장으로 감싸는 자리에서 코드·경로 목록을 «그대로» 올린다
                                그리고 «셋만» 남기지 않는다 — 자른다면 「몇 개 중 몇 개」를 말한다
2 🔴 봉투 거절 여섯에 코드·경로를   원자 단위 거절이 화면에서 «자리»를 갖게 됩니다
3 ⚠️ 화면이 test_run 을 «권한다»    L3 는 이미 화면에서 돕니다. 문제는 «돌려 보라고 말해 주지 않는» 것
                                (걸음 ①과 같은 자리라 그 라운드에 얹으면 됩니다)
```

## 하지 말 것 — 재 보니 «셋 다» 나쁜 처방입니다
```
⛔ L3 의 코드를 폼에 «이식»       주석이 이미 답했습니다 — 세 번째 어휘가 생깁니다
⛔ 이름을 «통일»                 합칠 것이 둘뿐이고, 나머지는 다른 시점의 «다른 사실»입니다
⛔ 거절문을 «길게»               소유자 상설(2026-09-04): 화면은 보여 준다, 설명하지 않는다.
                               길어지는 것은 «자리»가 없어서입니다 — 자리를 주면 문장이 짧아집니다
```

```
⛔ 코드를 쓰지 않았습니다 — 위 셋은 지시서로 넘어갑니다
⛔ 도메인 낱말 없음 · 이 박스의 행 수 없음 · 라이브 선언 값 없음
⛔ 실행해 보지 않았습니다. 위 수는 «커밋된 소스»를 센 것이고, 방법을 적어 두었으니
   다시 셀 수 있습니다
📌 세지 않은 것 하나(v5 미만 문법의 문장 77개)를 «부재의 증거로 쓰지 않고» 밝혀 둡니다
```
