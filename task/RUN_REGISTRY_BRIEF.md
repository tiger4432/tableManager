# 실행 행과 취소 — 원장만이 아니라 «등록부 연산 전부»

총괄 지시서. 2026-08-31. 소유자 지적으로 범위가 «넓어진 것이 아니라 제자리로» 왔습니다.

> 「지금 원장만 생각하는데 범용적으로 고려해라? 체인, 파일 등등」

## 왜 이 지시서가 «원장 것»이 아닌가 — 실측
```
등록부(server/retroactive.py)에 «이미» 있는 것
   chain_replay · enrichment_backfill · enrichment_confirm · withdraw
   넷 다 restartable 선언 · 자기 드라이런 · deletes 명시
🔴 원장이 «없습니다». 등록부는 처음부터 범용이었고, 빠져 있던 게 원장입니다
```
```
인제션은 «이미» 진행 행을 갖고 있습니다
   file_ingestion_checkpoints 13,972행  table_name·filename·total_rows·processed_rows·chunk_index
   file_ingestion_logs        22,352행  status·error_message·retry_count
=> 「무엇을·어디까지·전체 얼마」가 파일마다 이미 있습니다
```
**즉 없는 것은 「원장의 실행 기록」이 아니라 «요청형 연산의 실행 기록»입니다.**

## 🔴 그래서 «둘»로 갈립니다 — 억지로 한 표에 넣지 마십시오
```
① 요청형   등록부의 연산들 (+ 원장 재번역)
          사람이 «걸어야» 돌고, 끝이 있습니다
          -> 실행 행이 «없습니다». 이 지시서의 신설은 여기 «하나»
② 상시형   파일 인제션
          계속 돕니다. 파일마다 체크포인트가 «이미» 있습니다
          -> 신설 «없음». 화면이 그 표를 그대로 읽습니다
```
⛔ ②를 ①의 표에 «옮기지» 마십시오. 이미 있는 것을 옮기는 것은 이득이 없고 위험만 있습니다.

## 만들 것 — 표 «하나» + 규약 «하나»

### 실행 행 (요청형 전용)
```
run_id · op · params(범위 포함) · 시작 시각 · 마지막 진행 시각
처리한 수 · 전체 수(알면. 모르면 «없음» — 0 아님)
상태  도는 중 / 끝 / 취소 요청 / 취소됨 / 실패
```
🔴 **연산마다 표를 만들지 마십시오.** 등록부가 이미 연산을 «값»으로 다루므로 표도 하나입니다.

### 취소 규약 (모든 요청형 연산이 «같은 방식»)
```
취소 = 실행 행에 «취소 요청»을 세우는 것
연산 = 배치 «사이»에서 그 값을 보고 스스로 멈춘다.  프로세스를 죽이지 «않습니다»
```
```
왜 안전한가   원장 백필 · 체인 리플레이 · 범위 재번역 — 전부 «페이지마다 커밋»이고 restartable
             중간에 멈춰도 안 깨지고, 이어서 하면 됩니다
소유자 사유   「백필 돌리다 서버 렉먹는데 백필만 못꺼서 서버 재기동 사례 많음」
             -> 프로세스 kill 이 지금의 문제입니다. 이 규약이 그걸 없앱니다
```

## 멈춤 조건
```
S1  어떤 연산이 «배치 경계»를 안 갖는다 (한 번에 다 하고 끝난다)
    -> 그 연산은 협조적 취소가 «불가능»합니다. STOP 하고 어느 것인지 보고하십시오.
       억지로 중간에 끊으면 그게 지금의 프로세스 kill 과 같아집니다
S2  실행 행을 쓰려면 연산 코드를 «크게» 고쳐야 한다
    -> 등록부가 감싸는 자리에서 쓰는 것이 맞습니다. 연산 안까지 파고들어야 하면 STOP
S3  진행 수(처리한 수)를 «못 내는» 연산이 있다
    -> 0 으로 채우지 «마십시오». 「모름」으로 두고 보고하십시오
```

## 검증
```
G1  취소가 프로세스를 «안 죽이는가»   취소 후 그 프로세스가 «계속 살아» 다른 일을 하는가
G2  취소 후 «이어서» 되는가          같은 연산을 다시 걸면 멈춘 자리부터인가
G3  전체 수를 모르는 연산이 «0» 이 아니라 «모름»으로 나오는가
G4  🔴 상시형(인제션)이 이 표에 «안 들어가는가» — 옮기지 않았는지 확인
G5  실행 행이 «연산마다» 생기는가 — 등록부 넷 + 원장 재번역이 같은 표에 뜨는가
```

## 하지 않는 것
```
⛔ 연산별 실행 표 — 하나입니다
⛔ 인제션 체크포인트를 옮기기 — 이미 있습니다
⛔ 프로세스를 죽이는 취소
⛔ 가짜 전체 수 · 가짜 퍼센트
```

## ⚠️ 아직 «일반화 못 하는» 것 — 알고 두십시오
```
그리드의 「선택한 행 다시」   선언이 relation -> source 를 주는 것은 «원장»뿐입니다
                          체인은 규칙이, 인제션은 파서가 그 매핑을 압니다 — 셋이 다른 데 삽니다
                          -> 원장으로 «먼저» 내고, 둘째가 생기면 그때 템플릿으로 올립니다
                             (상설: 「지금 이미 둘」일 때 만든다)
```
