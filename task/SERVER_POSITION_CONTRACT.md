**그래서 적어 둡니다. 이유는 dt_map 이 아닙니다 — «같은 점이 여러 자리에 산다»가 원래 참입니다.**

```
void 점 «하나»
  placements: [ { space: "die:base", x: 13,       y: 5        },
                { space: "inchip",   x: 14041.75, y: 9879.75, extent: {…} } ]

웨이퍼 맵     die:base 자리를 씁니다        -> 칸 하나
칩 확대       inchip  자리를 씁니다        -> 실제 위치·실제 크기
composite     inchip 자리를 «여러 다이»에서 모읍니다 -> 한 점 = 진짜 디펙 하나
🔴 셋 다 «같은 노드 · 같은 walk». 두 번 묻지 않습니다
```
⛔ **「확대용 좌표」라는 «두 번째 층»을 만들지 마십시오.** 자리 목록 하나면 셋 다 섭니다.

```
낼 것   { space: "inchip", x, y, extent: { x, y, unit } }     extent 는 «선택»
        🔴 unit 을 «같이» 내십시오. 지금 값이 한 종류라고 숫자만 내면,
           두 번째 단위가 들어오는 날 «조용히» 틀립니다
⛔ 금지  die:base 자리에 크기를 넣기 — 다이 칸에 반경은 뜻이 없습니다
⛔ 금지  extent 가 없을 때 0 이나 1 로 채우기 (§3 과 같은 규칙)
```

## 15. 맵 부품에게 — 「없다」가 «두 가지»입니다. 한 문장으로 말하지 마십시오

```
소스가 내 space 를 «선언 안 함»        -> 인스턴스가 «안 섭니다».  「이 맵은 해당 없음」
선언은 했는데 이 점에 그 자리가 없음   -> 그 점만 «안 그립니다». 맵은 «섭니다»
                                        그리고 그 수를 «맵 밖»에 셉니다 (§8 ⑤)
🔴 예시   dt_map 은 die:core 를 «선언»합니다 -> core 맵이 «섭니다»
          그런데 5,619행에 core 자리가 «없습니다» -> 점이 적고, 5,619가 «맵 밖»입니다
          «빈 맵»이 아니라 «점이 적은 맵»입니다
```

## 16. 낱말 대조 — 총괄 명세(77603751)와 맞춰야 합니다
```

이 계약      space: die:base | die:core | die:dt | inchip
판정         총괄이 「당신 것이 맞습니다 — 제 명세를 당신 낱말로 고치겠습니다」
🔴 이유      die 하나로 두면 dt_map 이 «두 die 자리»를 갖는 것을 못 씁니다.
             die:dt 와 die:core 는 «다른 격자»입니다 (같은 표 안에서 컬럼이 다릅니다)
```

# 18. 🔴🔴 «필드가 아직 없는 것»과 «이 점에 자리가 없는 것»은 다릅니다 — 제 계약의 구멍

> 09:3x 화면이 비었습니다. 원인이 이 구멍입니다. **제가 안 적어서 생긴 일입니다.**

```
실측   GET /lot_map · GET /composition  ->  응답에 "placements" 가 «0회» 등장
       (서버는 §7 을 아직 구현하지 않았습니다 — 계약은 «요구»이지 «현황»이 아닙니다)
클라   placementOf(p, space) 가 placements 가 배열이 아니면 null 을 냅니다
       -> if (!at) { offSpace += 1; continue }  ->  «모든 점»이 자리 없음으로 세어짐
결과   칠해진 픽셀 «0». 그런데 숫자·배지·페이저는 전부 «맞습니다»
```

**§15 가 「이 점에 자리가 없으면 그 점만 안 그린다」라고만 적혀 있고,
「필드가 «아직 없으면»」을 안 적었습니다.** 클라는 §15 를 정확히 따랐습니다.

## 규칙 — 상태가 «셋»입니다. 둘로 접지 마십시오
```
placements 키가 «없다»       계약 미착지.  -> 🔴 «옛 경로로 그립니다» (cells 의 x·y)
                             그리고 화면이 그 사실을 말합니다 — 「좌표 계약 대기」
placements: []               이 점은 «어느 자리에도» 없음  -> 안 그리고 «맵 밖»에 셉니다
placements: [ … ]            그 자리에 그립니다
```
🔴 **이건 제가 `APPLICATION_EMPTY_REASON_BRIEF` 에 쓴 것과 «같은 구분»입니다** —
「없다」와 「아직 안 왔다」를 가르는 것. **제 계약에 제가 그걸 안 썼습니다.**

## 착지 순서 — 이번에 배운 것
```
🔴 새 필드를 요구하는 계약은  «읽는 쪽»이 먼저 가면 화면이 꺼집니다
   순서   서버가 필드를 낸다  ->  클라가 그 필드로 갈아탄다  ->  옛 경로를 뺀다
   지금   클라가 «먼저» 갔습니다. 계약이 그 순서를 «안 적어서»입니다
계약은 이제 적습니다:  «옛 경로는 새 필드가 실제로 올 때까지 살아 있습니다» (§2 lot_map 조항과 같은 규칙)
```
