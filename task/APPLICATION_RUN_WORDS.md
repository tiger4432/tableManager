# 진행 화면의 «부재 어휘» — 명세 (응용 → 총괄, 2026-08-31)

요청: `task/APPLICATION_RUN_WORDS_BRIEF.md`. 셋(① 이름 ② 행동 ③ 위험)에 답합니다.
**화면 안 그림 · 새 상태 축 없음 · 술어/선언 제안 없음 · 이 박스의 «수»를 근거로 쓴 곳 없음.**

---

## 0. 결론 먼저 — 여덟이 «다섯 + 밖 하나»가 됩니다. 넷째 축은 안 만들었습니다

```
여덟   ① 전체 수 모름  ② 처리 0(시작 전)  ③ withdraw 0·remake N  ④ 행 있음·remake 0
      ⑤ 도는 작업 없음  ⑥ 취소 요청·아직 안 멈춤  ⑦ 표본/상한  ⑧ 질문이 성립 안 함
접힘   ②⑥ -> 「아직」        운영자 행동이 «같습니다» (기다린다)
      ①⑦ -> 「전수가 아님」  운영자 행동이 «같습니다» (이 수로 완료를 판단하지 않는다)
      ⑧   -> 어휘 «밖». 0 이 아니라 «수를 내지 않는 자리»입니다
남는 다섯   아직 · 전수가 아님 · 가리킬 수 없음 · 정말 없음 · 이미 빠져 있음
```
🔴 **여덟 중 «둘»만 정반대로 읽힙니다**(§3). 나머지 셋은 글자로 충분합니다.

## 0-bis. 기존 「부재는 «셋»으로 말한다」 아래로 접었습니다 — 낱말 그대로

상설 ⑥의 셋은 walk 의 낱말이고, 운영 화면에서는 같은 셋이 이렇게 읽힙니다:
```
「아직 안 골랐다」    -> 아직 «안 일어났다»          아직
「서버가 못 답한다」  -> 기계가 «그 수를 못 낸다»     전수가 아님 · 가리킬 수 없음
「걸었는데 없다」    -> 돌려 봤고 «정말 없다»        정말 없음 · 이미 빠져 있음
```
**넷째를 만들지 않았습니다.** ⑧이 셋에 안 들어가는데, 그건 넷째가 아니라 **부재가 아니기 때문**입니다
(§2-밖). 제 결측 명세가 이미 「0 이 아니라 «질문이 성립 안 함»」으로 판정한 자리와 같은 것입니다.

---

## 1. ①② 이름과 행동 — 다섯

| 경우 | 언제 | 화면 문구 (사람 말) | 운영자가 할 일 |
|---|---|---|---|
| **아직** | 시작 전 · 취소 요청은 갔고 아직 안 멈춤 | 「아직 시작 안 함」 · 「멈추는 중」 | **기다립니다.** 다시 걸지 않습니다 |
| **전수가 아님** | 전체 수를 못 냄 · `count_kind` 가 `exact` 가 아님 | 「모름」 · 「표본 N」 | 이 수로 **완료를 판단하지 않습니다** |
| **가리킬 수 없음** 🔴 | 재료 행은 있는데 낡은 것을 짚지 못함 | 「가리킬 수 없음 — 선언을 봐야 합니다」 | **올립니다.** 태워도 안 고쳐집니다 |
| **정말 없음** | 돌려 봤고 대상이 없음 | 「없음」 | **없습니다.** 이것도 정보입니다 |
| **이미 빠져 있음** 🔴 | 거둘 것이 없는데 다시 만들 것은 있음 | 「이미 빠져 있음 — 복구입니다」 | **태웁니다.** 같은 범위를 다시 돌립니다 |

**밖 — 「해당 없음」**: 그 연산에 그 수가 «성립하지 않는» 자리.
`0` 을 쓰지 «않고» 수를 내지 않습니다. 화면은 빈칸이 아니라 「해당 없음」으로 씁니다.

⚠️ 문구 규율(이 채널에 이미 판정된 것) 그대로 지켰습니다 —
**⛔ 「데이터 없음」·「0」으로 적지 않습니다.** 「세어 봤더니 0」과 구별이 안 됩니다.

---

## 2. ③ 위험 — **정반대로 읽히는 것은 «둘»이고, 둘이 같은 모양입니다**

```
이미 빠져 있음    읽힘 「거둘 게 없네 = 할 일 없음」   진실 「이미 빠져 있다 = 복구해야 한다」
가리킬 수 없음    읽힘 「만들 게 없네 = 끝났음」       진실 「못 짚는다 = 선언을 고쳐야 한다」
```
🔴 **둘 다 「0인데 일감이 «있다»」입니다.** 그래서 화면 규칙은 «하나»면 됩니다:
```
「0 인데 일감이 있는 경우」만 «다르게» 생긴다. 나머지 셋은 글자로 충분하다
```
이러면 `OPS_PROGRESS_PAGE_CONCEPT` 의 상한을 안 넘습니다 — **칸을 늘리지 않고**
「진행」 칸 안에서 갈리며, 색은 상태 하나에만 남습니다.
📌 3초 판별식(「끊을지 말지」)도 안 깨집니다 — 이 둘은 «끊는» 판단이 아니라 «따로 손대야 하는» 표시입니다.

⚠️ **「전수가 아님」은 셋째 위험이었는데 이미 막혀 있습니다** — `RUN_REGISTRY_BRIEF` S3 이
「0 으로 채우지 마십시오」로 못 박았고, 게이트 G3 이 그걸 잽니다. 여기서 더 만들지 않습니다.

---

## 3. 🔴 두 줄 시험 — 연산은 «문장을 쓰지» 않고 «고릅니다»

```
연산이 하는 것   자기가 내는 «수마다» 위 다섯 + 밖 중 «하나»를 고른다
화면이 하는 것   고른 값으로 문구를 «만든다». 연산의 저자는 문구를 안 씁니다
```
그래서 새 연산이 아홉째를 만들지 않습니다 — **목록이 닫혀 있고 연산은 그 안을 가리킵니다.**
📎 고르는 칸의 «이름»은 등록부 소관이라 제가 정하지 않습니다. 정하실 것은 **값의 목록**뿐이고,
   그게 위 여섯입니다.

### ⚠️ 다만 «고르는 단위»가 수 하나가 아닌 연산이 있습니다 — 멈추지는 않습니다
```
ledger_rescope   「거둔 수」 하나만으로는 «정말 없음»과 «이미 빠져 있음»이 구별되지 «않습니다»
                 갈리는 것은 «짝»입니다:  (거둠 0, 다시 만듦 N) -> 이미 빠져 있음
                                        (거둠 0, 다시 만듦 0) -> 가리킬 수 없음 또는 정말 없음
=> 그 연산은 「나는 «짝»으로 말한다」를 «미리» 고를 수 있습니다. 값만 실행 시점입니다
   -> S3(실행해 봐야만 안다)에 «안 걸립니다». 등록부가 짝을 받을 수 있는지만 확인해 주십시오
```
🔴 그리고 이건 제 결측 명세의 발견과 **같은 모양**입니다 — 거기서도 뜻을 정한 것은
한 수가 아니라 **두 술어의 차이**였습니다. 운영 쪽에서도 「수 하나로는 안 갈린다」가 반복됩니다.

## 4. 멈춤 조건 점검 (지시서 S1~S3)

```
S1  둘이 행동이 같다 -> 합쳐라        ✅ 두 번 합쳤습니다 (②⑥ · ①⑦). 여덟 -> 다섯
S2  셋으로 안 접히는 것이 남는다     ✅ ⑧ 하나가 안 접혔습니다. 넷째를 «안 만들고»
                                    「부재가 아니다」로 어휘 «밖»에 두었습니다 (근거: 제 결측 명세)
                                    이것을 「남은 것」으로 볼지 판정해 주십시오 — 저는 밖이 맞다고 봅니다
S3  연산이 스스로 못 고른다          ✅ 없습니다. ledger_rescope 의 짝도 «미리» 고를 수 있습니다
                                    (등록부가 짝을 받는지만 확인 필요 — 위 §3)
```

## 5. 이 문서가 «안» 한 것
```
⛔ 화면을 그리지 않았습니다 — 문구와 «갈리는 규칙 하나»까지입니다
⛔ 상태 축을 안 만들었습니다 — 실행 상태 다섯은 RUN_REGISTRY 것이고, 여기는 «그 옆의 수»입니다
⛔ 술어·선언을 제안하지 않았습니다
⛔ 이 박스의 수를 근거로 쓰지 않았습니다 — 인용은 커밋된 문서(`RUN_REGISTRY_BRIEF` S3·G3 ·
   `OPS_PROGRESS_PAGE_CONCEPT` §3·§5-bis · `scoped_redo_report` §3 · `APPLICATION_GAP_SPEC`)뿐입니다
```
