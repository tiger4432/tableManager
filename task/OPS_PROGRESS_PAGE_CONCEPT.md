# 실행 중인 작업 — 목록과 «끊기». 컨셉 문서 (목업용, 2차)

> 🔴 **1차는 버립니다.** 상태 분류·거절 사유·큐 통계를 잔뜩 그렸는데, 소유자가 원한 것은
> 그게 아니었습니다:
>
> ```
> 「지금 돌고있는 프로세스나 스레드 리스트 딱딱 나와서 너무 오래걸리면 끊거나 현황을 보고 싶을 뿐이야」
> 「운영에서 실제로 백필같은거 돌리다가 서버 렉먹는데 백필만 못꺼서 서버 재기동 사례 많음」
> ```
> 이 화면의 목표는 «감시»가 아니라 **「하나만 끊기」** 입니다.

---

## 1. 푸는 문제 — 한 줄

**백필이 서버를 무겁게 만드는데, 백필만 못 꺼서 서버를 통째로 내린다.**

```
지금   긴 작업이 프로세스 «안»에서 돕니다
      -> 끊으려면 프로세스를 죽여야 하고, 그러면 그 프로세스의 «다른 일»도 같이 죽습니다
      -> 그래서 실제로는 서버를 재기동합니다. 운영에서 «자주» 있는 일입니다
필요   그 작업 «하나»만 멈추기. 서버는 그대로.
```

---

## 2. 화면 — 이것뿐입니다

```
지금 도는 작업 목록
   무엇       원장 백필(어느 소스) · 체인 리플레이(어느 규칙) · 범위 재번역 · 인제션
   언제 시작   그리고 «경과»   「17분째」 — 이게 끊을지 말지의 판단 근거입니다
   어디까지    처리한 수 / 전체(알면). 모르면 «처리한 수»만. 가짜 퍼센트 금지
   [ 취소 ]   ← 이 버튼이 이 화면의 전부입니다
```
끝난 것은 최근 몇 개만 아래에. 목록이 길어지면 이 화면의 목적이 흐려집니다.

⛔ 상태 분류·거절 사유별 집계·큐 통계는 **넣지 마십시오.** 1차의 실수입니다.
   그건 나중에 «진단» 화면이 필요해지면 그때입니다.

---

## 3. 🔴 「취소」는 프로세스를 죽이는 것이 아닙니다

```
❌ 프로세스 kill    지금 하고 있는 그것입니다. 다른 일이 같이 죽습니다
✅ 협조적 취소      작업이 «배치 사이»에서 스스로 멈춥니다. 프로세스는 그대로 삽니다
```

**가능한 이유 — 이미 그렇게 지어져 있습니다:**
```
원장 백필      «페이지마다» 커밋. 중단해도 커서가 남아 이어서 됩니다
체인 리플레이   «페이지마다» 커밋. restartable
범위 재번역     같은 성질 (지금 만드는 중)
=> 중간에 멈춰도 «안 깨집니다». 그래서 취소가 안전하고 재개가 공짜입니다
```

```
동작   취소 -> 그 작업의 «행»에 취소 표시 -> 작업이 다음 배치 «전»에 보고 스스로 멈춤
표시   「취소 요청됨 — 이번 배치 끝나면 멈춥니다」
      🔴 즉시 목록에서 지우지 «마십시오». 언제 «실제로» 멈췄는지가 보여야 합니다
```

---

## 4. ⚠️ 서버에 «없는» 조각 하나 — 목업은 있는 것처럼 그리십시오

```
없음   실행 «행»(run) 을 적어 두는 표
      /admin/retroactive/{op}/run 이 run_id 를 «돌려주는데» 그걸 기록하는 데가 없습니다
      백필·리플레이도 「지금 돌고 있다」를 아무 데도 «안 적습니다»
=> 지금은 «목록 자체»를 만들 수 없습니다. 서버 라운드에서 이 표를 먼저 만듭니다
```
```
그 표가 들 것   run_id · 무엇(연산 · 소스/규칙) · 시작 시각 · 마지막 진행 시각
              처리한 수 · 상태(도는 중 / 끝 / 취소 요청 / 취소됨 / 실패)
              -> 「경과」와 「취소」가 전부 여기서 나옵니다
```

## 4-bis. ⚠️ `supervisor_status.json` 을 «쓰지 마십시오»
```
실측 2026-08-30 밤: 그 파일은 «10일 전»에 멈춰 있고 자식 넷이 전부 stopped 입니다.
그런데 서버는 «돌고 있습니다» (heartbeat 200) — 감독자를 안 거치고 뜬 프로세스이기 때문입니다
=> 그 파일은 「감독자가 띄운 것」만 압니다. 「지금 도는 것」의 정본이 «아닙니다»
```

---

## 5. 하지 «말아야» 할 것

```
⛔ 프로세스를 죽이는 버튼 — 그게 지금의 문제입니다
⛔ 가짜 진행률 — 전체를 모르면 «처리한 수»만
⛔ 취소를 누르자마자 목록에서 지우기 — 실제로 멈춘 시각이 보여야 합니다
⛔ 1차의 상태 분류표 — 이 화면의 일이 아닙니다
```

## 5-bis. 🔴 UI 제약 — «절대 지저분하지 않게» (소유자 상설)

앞선 목업이 지저분하다는 판정을 받았습니다. 그래서 이번엔 «상한»을 못 박습니다.

```
화면       «한 목록». 탭 없음 · 패널 나눔 없음 · 차트 없음
행 하나     [무엇]  [경과]  [진행]  [ 취소 ]      -> 칸 «넷». 다섯째를 만들지 마십시오
색         상태 하나에만. 나머지는 «글자»로 충분합니다
끝난 것     최근 몇 개만, 흐리게, 아래에
빈 화면     「도는 작업 없음」 한 줄. 그것도 «정보»입니다
```
```
⛔ 배지·아이콘·진행 막대 여러 개 ·통계 숫자 ·접었다 펴는 층
⛔ 「나중에 쓸지 모르니」 넣어 두는 칸 — 그게 지저분해지는 방식입니다
```
🔴 판별식: **이 화면을 열어 「끊을지 말지」를 3초 안에 정할 수 있나.**
   그 결정에 안 쓰이는 것은 넣지 «않습니다».

## 6. 요약

```
목록 + 경과 + 취소.  그게 전부입니다.
그리고 취소는 «프로세스를 죽이는 것»이 아니라 작업이 «스스로» 멈추는 것입니다 —
페이지마다 커밋하는 구조라 이미 안전하게 그렇게 할 수 있습니다.
```
