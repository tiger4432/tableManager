🔴 **의존을 따지면 하나가 뒤집힌다: ①(JSON 편집기 제거)은 첫째가 아니라 «마지막»이다.**
구조화된 경로가 생성·편집·삭제를 «다» 할 수 있기 전에 편집기를 빼면 **할 수 없는 일이 생긴다.**

**③ 접기 — 승인된 규칙 (2026-08-19).** 내가 준 「유도된 칸은 접고 사람이 정하는 칸은 편다」가

🔴 **강제됨과 «같이» 취급하면 안 된다** — 강제됨은 «스키마»가 정한 것이라 내일도 하나지만,
후보 1개는 «지금 데이터»가 하나일 뿐이라 팩이 하나 더 생기면 둘이 된다. 같이 접으면

**우선순위(위가 이긴다): 남음 → 펼침 · 문제 → 펼침 · 유도/강제 → 접힘 · 후보 1 → 접힘 · 그 외 → 펼침**
「남음」이 무조건 이기는 이유: 「3개 남음」이라면서 그중 하나를 접으면 **두 숫자를 다 못 믿게 된다.**

**⑥ 맨바닥 부팅 — 소유자가 «쓰다가» 찾았다.** 회사에서 config를 손으로 비우고 첫 선언을

일곱 절의 «키»를 요구한다(값은 비어도 됨. 실측: 뼈대만으로 오류 0). 로드가 안 되면 스냅샷이
안 서고, 화면은 「선언 없음」만 내고, **새로고침해도 같은 자리**다.
즉 **화면으로 맨바닥에서 시작할 수가 없다.** 그건 「JSON 편집기 없이 선언한다」가 «0단계»에서

## 0-a. 🔴 소유자 지시 — 화면의 «모양» (2026-08-19)

인수 기준이 「얼마나 안 불편한가」라면, 이건 **무엇을 만들 것인가**다. 소유자가 직접 쓰다
내린 것이라 협상 대상이 아니다. 메시지로만 존재하면 압축과 함께 사라지므로 여기 옮긴다.

**① JSON 편집기를 뺀다.**
「더 나은 JSON 편집기」가 아니라 **없앤다.** 쓰기 경로에 JSON 텍스트 입력이 없다.
못 치는 칸은 잘못 칠 수 없다 — 사다리의 최강 수단을 작성 표면 전체에 적용한 것.
저장될 내용을 **읽기 전용으로** 접어서 보여 주는 것은 편집기가 아니므로 남겨도 된다.

**② 뭐를 어떻게 넣는지를 UI로 만든다.**
값의 후보 집합을 알 수 있는 자리에 **자유 입력은 결함이다.** 컬럼은 물리 카탈로그에서 뽑은
피커 + 후보마다 실측 값 보유율(§2·§8). 자유 입력을 남기려면 **왜 그 집합을 셀 수 없는지**를
말할 수 있어야 한다.

**③ 선언을 체계적으로 — 여섯 층이 뼈대다.**
낱말 → 엔터티 → 팩 → 프로필 → 매퍼 → 소스. 이미 소유자의 머릿속 순서이고 가이드의 순서다.
층마다 **「정할 것 n개 남음」**을 보인다 — 「체계적」이 느낌이 아니라 **보이는 것**이 되게.

**④ 확장 UI로 길어지지 않게 — 🔴 길이가 아니라 «자유도»로 접는다.**
길다고 접으면 **§0의 「사람의 판단 다섯」이 같이 숨는다.** 판별자는 이미 코드에 있다:
`config_authoring.py`가 칸마다 `state="derived"`와 등급(`TIER_STRUCTURAL`/`TIER_DERIVATION`)을
찍는다.

| 칸 | 기본 |
|---|---|
| 사람이 정함 | **펼침** + 제약 컨트롤 |
| 유도됨·강제됨 | **접힘** — 한 줄로 값 + 근거 |

문제가 있는 칸은 등급과 무관하게 **스스로 펼친다.** 펼치면 `ground`가 보여야 한다(§3).

**⑤ 다른 영역의 목록을 참조하는 값은 드롭박스.**
> 「채울값이 다른 영역의 리스트를 참조하는건 드롭박스로」

규칙으로 읽는다: **다른 절의 id를 값으로 갖는 칸은 그 절에 대한 드롭박스다. 예외 없이.**
팩이 부르는 술어·엔터티, 프로필이 부르는 팩, 소스가 부르는 매퍼·프로필·전처리기, 롤 참조 —
전부 **같은 파일 안에** 이미 있는 것을 옮겨 적는 일이다. 그게 두 시간의 대부분이었다.
- id만 나열하지 말고 **그게 무엇인지** 함께 (술어면 목적어 종류, 매퍼면 구현).
- 🔴 **대상 절이 비었으면 빈 드롭박스가 아니라 그렇게 말한다** — `팩 없음 — 먼저 팩 선언`.
  층이 순서대로라 먼저 도착하는 건 정상이고, 빈 드롭박스는 「고장」으로 읽힌다.
- `@1` 같은 버전은 id의 일부다. 고르는 것이지 치는 것이 아니다.

**⑥ 목록은 살아 있어야 한다.**
> 「각 선언 별로 지정한 리스트들이 다른 드롭박스에 리스트 업데이트 잘되게」

한 절에 선언하면 그것을 참조하는 **모든 드롭박스가 즉시** 반영한다. 저장·새로고침 왕복 없이.
층이 서로 먹이므로 실제 고리는 「팩 선언 → 프로필에서 묶기」다. 목록이 로드 시점 스냅샷이면
**첫 사용에서 고리가 끊긴다.** 낡은 드롭박스는 자유 입력보다 나쁘다 — 틀린 닫힌 집합을
조용히 내밀고, 사람은 **쳐서 빠져나올 수도 없다.**
절 목록의 **단일 출처**를 정하고 피커가 전부 거기서 읽는다. 피커가 자기 사본을 캐시하지 않는다.
지운 선언은 드롭박스에서도 사라지고, 그걸 가리키던 것은 **보이는 문제**가 된다.
이건 위젯 요구가 아니라 **상태 관리 요구**다 — 피커를 열 개 만든 «뒤에» 반응성을 끼워 넣는
것이 가장 비싼 순서다.

## 0. 통과 조건은 하나다

**거절 40건 중 «사람이 판단해야 했던 다섯»만 남는다.** 나머지 35건은 화면에서 **일어날 수
없어야** 한다 — 「거절문이 친절해졌다」는 통과가 아니다. 그건 ④(가장 약한 수단)이고
친절한 거절도 왕복이다.

두 숫자로만 채점한다.

| | 어젯밤 | 통과선 |
|---|---|---|
| 거절당한 저장 | 40 | **≤ 5** |
| 사람의 실제 판단 | ~5 | **~5 (줄면 안 된다)** |

두 번째가 중요하다. 판단까지 사라졌으면 화면이 **대신 골라 준** 것이고, 그건 어젯밤
`basis`가 12건을 만든 것과 **같은 기제**다 — 엔진이 말없이 골랐고 그 침묵이 데이터가 됐다.

## 1. 검수 방법 — 코드 리뷰가 아니다

**내가 화면으로 `dt_log`를 처음부터 다시 선언한다.** 어젯밤 소유자가 걸은 그 여정을,
같은 순서로, 빈 상태에서.

읽기만 하는 검수는 「불편한지」를 못 잰다. 불편은 **왕복 횟수**로만 드러난다.

측정 규약:
- 저장 시도 1회 = 1왕복. 거절되면 사유를 그대로 적는다.
- 「어젯밤에도 났던 거절인가 / 새 거절인가」를 나눈다. **새 거절은 회귀다.**
- 각 층(낱말→엔터티→팩→프로필→매퍼→소스)에서 **손으로 친 문자 수**를 센다.
  타이핑이 남아 있는 자리가 다음 오타의 자리다.

## 2. 항목별 — 무엇을 «반증»할 것인가

각 항목은 「있다」가 아니라 **「틀릴 수 없다」**로 잰다. 존재는 확정이 아니다.
그래서 통과 판정마다 **내가 고의로 틀리게 해 본다.**

| 항목 | 수단 | 통과 = 이게 안 돼야 한다 |
|---|---|---|
| §1 `__occurred_at` | ① 구조 | 매퍼가 시각 컬럼 «이름»을 물을 자리 자체가 없다. `source_plan.driver.occurred_at`을 읽는 매퍼가 0개 (grep으로 센다) |
| §2 컬럼 드롭다운 | ③ 제약 | **없는 컬럼 이름을 타이핑해 저장할 수 없다.** 자유 입력이 남아 있으면 실패 — 드롭다운이 «있는» 것과 자유 입력이 «없는» 것은 다르다 |
| §2 값 개수 표시 | ③ 계측 | 값이 0%인 컬럼을 «모르고» 고를 수 없다. 후보 옆 숫자가 라이브 실측인지 확인 — 하드코딩·캐시면 실패 |
| §8 유일성 실측 | ③ 계측 | 유일하지 않은 조합을 business_key로 골랐을 때 백필 «전에» 안다 |
| §3 유도 | ② 유도 | 다른 선언에서 계산되는 칸이 사람에게 안 물린다. **단, 유도값은 근거와 함께 보인다**(§3 아래) |
| §9 전수 보고 | ④ 진단 | 작성 경로에서 문제 3개를 심으면 **3개가 다 나온다**(첫 개에서 안 멈춘다) |

## 3. 🔴 유도한 것은 «값과 근거»를 같이 보인다

②(유도)는 강한 수단이지만 **①과 달리 위험이 있다.** 칸을 없애는 게 아니라 **말없이
채우는** 것이라서다.

어젯밤의 결함이 정확히 이 모양이었다: `basis`가 그룹에서 무엇을 뜻하는지 아무도 안 정했고,
**엔진이 조용히 골랐고**, 그 침묵이 원장에 12건으로 앉았다. 화면이 유도한 값을 근거 없이
보여 주면 **같은 결함을 UI 규모로** 재생산한다.

**규칙: 파생된 칸은 «값»과 «어디서 왔는지»를 같이 렌더한다.** 그리고 사람이 그걸
**덮어쓸 수 있어야** 한다 — 덮어쓸 수 없으면 그건 유도가 아니라 강제이고, 강제라면
파일에서 빼야 한다(①).

## 4. 검수 결과가 나올 형식

라운드마다 이 표만 낸다. 산문 없이.

```
층        왕복  타이핑  새 거절
낱말        n     n자      -
엔터티      n     n자      -
팩          n     n자      -
프로필      n     n자      -
매퍼        n     n자      -
소스        n     n자      -
─────────────────────────
합계        n     n자      n건
```

**합계 왕복 ≤ 5, 새 거절 0이면 통과.** 아니면 그 자리를 §2 표의 수단 등급으로 되돌린다.

## 4-b. 🔴 조작자의 «자리»를 잃지 않는다 (소유자 실측 2026-08-19)

소유자가 화면을 직접 쓰다 보고했다:

> 막 리스트 갱신한다고 새로고침 했더니 다시 페이지 맨위로 올라가있고 이럼 안됨

한 문장에 결함이 **둘** 있고 눈에 보이는 쪽이 더 작다.

**큰 것: 애초에 새로고침을 해야 했다.** 목록이 살아서 안 갱신되니 다시 불렀다. 스크롤만
고치면 «망가진 고리를 편안하게» 만드는 것이라 방향이 틀렸다.

**작은 것: 다시 그릴 때 조작자가 움직였다.** 정당한 재렌더는 앞으로도 있으니 따로 성립해야 한다.
**한 곳이 바뀌었다고 패널을 통째로 다시 그리지 않는다.** 스크롤은 넷 중 하나일 뿐이다:

| 지켜야 할 것 | 잃으면 |
|---|---|
| 스크롤 위치 | 소유자가 보고한 것 |
| 포커스 | 입력 중 커서가 사라져 다음 타자가 허공에 간다 |
| 접힘/펼침 상태 | 같은 절을 매번 다시 편다 |
| 입력 중이던 값 | 쳤는데 아직 확정 안 한 글자가 날아간다 |

🔴 **세 번째가 이 문서의 §2 접기와 정면으로 충돌한다.** 통째로 다시 그리는 패널 위에 접기를
얹으면 **무엇이 바뀔 때마다 스스로 접히는 화면**이 된다. 접기보다 먼저 해결한다.

「스크롤 위치를 저장했다 복원」은 답이 아니다 — 넷 중 하나만 되살리고, 레이아웃과 경합하며,
포커스와 입력 중인 글자는 그대로 날아간다. **DOM을 유지하고 바뀐 것만 바꾼다.**

**검수:** 긴 절 맨 아래로 스크롤 → 다른 절 드롭박스에 먹이는 선언을 하나 만든다 →
**새로고침 없이** 그 드롭박스가 갱신되고, 자리·포커스·펼침이 그대로인지 본다.

## 5. 비범위

- 시각 디자인·색·간격 — `ui-designer` 소관. 여기서 재는 것은 **마찰**이지 미감이 아니다
- 삭제·이름변경 경로 — 판정 5건이 아직 열려 있다(보드 구현자 레인 절)
- 성능 — 왕복이 5회면 1초가 늦어도 어젯밤보다 낫다
