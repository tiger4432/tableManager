# ① 지금 몇 걸음인가 — **「0 걸음」입니다. 그런데 그게 문제가 아닙니다**

```
화면을 열면(어드민 개요)  CHAIN 묶음에 «실패 트랜잭션» 칸이 «이미» 있습니다   -> 0 클릭
그 옆의 「탭 열기 →」      Chain 탭. 「CHAIN 실패 (OUTBOX TRANSACTIONS)」 표   -> 1 클릭
```
🔴 **닿는 길은 «막혀 있지 않습니다».** 실패는 첫 화면에 «수»로, 한 번 눌러 «행»으로 있습니다.

## 🔴 그런데 «반대로 읽히는 칸»이 옆에 있습니다 — 이게 이 문서의 답입니다
같은 Chain 탭에 큐가 있고, 둘이 «다른 것»을 셉니다.
```
실패 표   status 가 FAILED 인 것을 셉니다
큐       processed_chain 이 false 인 것을 셉니다
사실     실패한 행은 processed_chain 이 true 입니다  (총괄이 준 재료)
=> 실패한 행은 «큐에서 빠집니다». 큐는 「대기 0」이 됩니다
```
🔴 **「대기 0」은 「밀린 것 없음 = 잘 돌고 있다」로 읽힙니다.** 실제로는 «실패해서 나간» 것입니다.
   두 칸이 각각 맞는데, 나란히 놓으면 «정반대»를 말합니다.
📎 제 부재 어휘 명세의 그 부류입니다 — 「0 인데 일감이 있는 경우」.

# ③ 한 걸음이 되려면 «무엇이» 있어야 하나

⛔ 화면을 설계하지 않습니다. **어떤 «사실»이 어느 화면에 있어야 하나**까지입니다.
그리고 그 사실이 **서버에 이미 있나 없나**를 갈랐습니다.

## 필요한 사실 «셋»

```
① 「이 큐의 0 은 «비어서»가 아니라 «실패로 빠져서»다」
   서버에  ✅ 있습니다. 두 수(실패 · 대기)가 이미 각각 있습니다
   없는 것  그 둘을 «잇는 문장». 지금은 사람이 두 칸을 보고 이어야 합니다
   => «화면 일»입니다

② 「실패한 것이 언제부터 실패였나」
   서버에  ✅ 있습니다. 실패 표가 실패 «시각»과 재시도 «수»를 이미 냅니다
   => «화면 일». 개요의 그 칸이 수만 내고 «언제부터»를 안 냅니다

③ 「이 실패가 «무엇을» 막고 있나」
   서버에  ❌ 없습니다. 실패 행은 «걸린 표»를 말하지만,
          그 표가 원장의 어느 소스로 가는지는 잇는 데가 없습니다
   => «서버 일»입니다
```

```
⛔ 토큰을 입력해 보지 않았습니다
```

# 기록이 어디로 가나

**①** 「방금 그 체인이 어디까지 갔나」를 보려면 여는 파일이 **둘 중 하나**입니다 — 체인 루프가
서버와 «같은 프로세스»면 서버 로그, «단독 워커»면 워커 로그. 그리고 그 둘은 «고정»이 아니었습니다:
로거를 만드는 자리가 루트 핸들러를 «전부 떼고» 자기 것을 달았고, 서버 쪽이 «먼저» 부르고 체인 쪽이
«나중»에 불려서 나중이 이겼습니다 — 그래서 서버 로그가 기동 몇 초 뒤 «끊겼고», 그 뒤 줄들이
워커 로그로 «통째로» 넘어갔습니다. 지금은 「먼저 부른 쪽이 이긴다」로 바뀌어 파일이 «프로세스를
따라갑니다». 🔴 **그런데 그건 «어느 파일인지»를 정한 것이지 «누가 그걸 아는지»는 아닙니다.**

🔵 **이 문단은 «낡았습니다» (2026-09-05 00:43 재측정).** 서버가 «지금 쓰는 로그 파일 이름»을
내고 큐 패널이 그립니다 — 못 받으면 «모름»으로 그립니다. 아래는 «그때» 잰 것으로 남깁니다.

**②** 화면이 그 파일 이름을 내는 자리는 **없습니다**. 클라에서 워커 로그 이름은 «0» 건이고,
서버 로그 이름은 소스 «둘»뿐인데 그것도 «주석»이며 출하 번들에는 «0» 입니다. 그래서 운영자는
로그 줄에 붙은 «어느 로그인지» 태그를 보려면 «이미 맞는 파일을 열고 있어야» 합니다 — 태그는
연 사람에게만 보이고, 열 파일을 고르는 데는 못 씁니다. 계측기 셋을 만들어도 «파일을 못 고르면»
셋 다 안 보입니다.

**③** 그런데 그 옆에 «비슷한 말을 하는 자리»는 이미 있습니다 — 대기열·규칙 편집기가 못 읽었을 때
「이 서버 «프로세스»에 그 라우트가 없습니다(404) — 재기동이 필요합니다」라고 «프로세스»를 이름으로
말합니다. 즉 「어느 프로세스인가」를 말하는 어휘는 서 있고, 「그래서 «어느 파일»인가」만 비어
있습니다. 그러니 이건 새 자리가 아니라 **그 옆 칸**입니다. ⛔ 어떻게 그릴지는 적지 않습니다 —
지시서 자리입니다.

## ① 지금 — 누른 «직후»부터 «끝날 때»까지

누르는 자리는 소급 패널의 연산 카드입니다. (표 화면의 되돌리기 배너는 «인자를 넘겨» 이리 보낼
뿐, 거기서 도는 것이 아닙니다.)

```
누르기 «전»     세는 중… -> 셈 + 「몇 건 지웁니다」 -> 확인 질문 «하나»
누른 «직후»     버튼 자리가 requesting…                                         ✅
응답 «즉시»     토스트 「queued — run id ⟨…⟩」 + «걸린 인자»가 서버 echo 로       ✅
               🔵 그 줄은 «레코드에 남아» 재렌더를 견딥니다 — 토스트가 사라져도 남습니다
그 «즉시»       실행 목록을 «다시 읽습니다». 다음 박자를 안 기다립니다
               🔵 「안 걸린 줄 알고 또 누르는 것」을 막으려고 «일부러» 있는 자리입니다
큐에 앉은 동안   실행 목록에 줄이 «있습니다». 막대가 «안 흐릅니다». 진행 칸은 「N분째」
               그 N 은 «큐 시각»부터 잰 것이라 「기다린 시간」이 «수로는» 있습니다
개요           Running «수» · 부제 「oldest Nm」 (0 이면 idle · 못 읽은 출처는 «이름 대어»)
끝나면          줄이 아래로 내려가고 시계가 «멈춥니다»(걸린 시간). 최근 몇 개만 남습니다
```
🔴 **「도는 동안」의 토스트는 «없습니다».** 진행 카드 «부품»은 있는데 소비자가 «하나»입니다
(파일 인제션). 커밋된 HEAD 기준으로 셌습니다.

## ② 구멍 — 셋이 구별되나

```
「곧 돕니다」       ⚠️ 반쪽. 「아직 안 돈다」는 «보입니다» (막대가 안 흐릅니다)
                  «언제쯤»이 없습니다 — 순번·몇 번째·예상: 화면 자리 «0» (총괄 실측)
                  🔴 제 실측 하나 더: 실행 목록이 «최신 것부터»이고 «잘립니다».
                     큐 순서와 «반대»라, 줄을 세어도 순번이 안 나옵니다
「늦어집니다」      ⚠️ 반쪽. 「N분째」는 있고, 그 N 이 «늦은지»를 말하는 자리가 없습니다
                  🔴 이건 화면이 빠뜨린 게 아닙니다 — 체인 큐 패널이 자기 규율에
                     「임의 임계 금지: 60초가 늦다는 근거가 이 저장소에 없다」고 «적어 뒀습니다»
                  => «무엇이 늦은 것인가»가 아직 «아무 데도» 안 정해져 있습니다
「안 돌고 있습니다」 🔴 «구별 안 됩니다». 그리고 «반대로» 말합니다
```

### 🔴 셋째가 이 절의 답입니다
```
개요의 Running 수는 «도는 것»과 «기다리는 것»을 «같이» 셉니다 (끝난 것만 뺍니다)
큐를 집어가는 것은 «스케줄러 한 프로세스»입니다 (큐 행과 아웃박스 행이 «한 커밋»으로 나갑니다)
=> 그 프로세스가 안 떠 있으면 줄은 queued 로 앉아 있고,
   화면은 「Running 3 · oldest 12m」이라고 «돌고 있다»고 말합니다
```
소유자의 「대기열에 들어가놓고 막 안 돌고」가 «정확히» 이 자리이고, 화면은 하필 그때
«가장 확신에 찬 문장»을 냅니다.
📎 이 문서 ①의 「대기 0」과 «같은 부류의 반대편»입니다 — 거기선 0 이 거짓말을 했고,
   여기선 «0 이 아닌 수»가 거짓말을 합니다.

⚠️ 그리고 「기다림」이 «글자»로 안 나갑니다. 상태 낱말은 뷰모델까지 «와 있는데»
   화면이 그것을 «클래스»로만 씁니다 — 색과 안 흐르는 막대뿐이라 «읽을 낱말»이 없습니다.

## ③ 무엇이 있어야 하나 — 그 사실이 «서버에 이미 있나»

⛔ 화면을 설계하지 않습니다. 「어떤 «사실»이 어디에」까지입니다.

```
① 「이 줄은 아직 «안 시작»했다」
   서버 ✅ 실행 목록이 상태 낱말을 «행마다» 냅니다 — 뷰모델까지 와 있습니다
   화면 ❌ 안 그립니다 (클래스로만)
   => «화면 일». 새 라우트 «0»

② 「내 앞에 몇 개인가」 (순번)
   서버 ⚠️ «재료만». 큐에 앉은 행도, 큐 시각도 있는데 «순번»이라는 수는 없습니다
        🔴 목록이 «최신 것부터»이고 «잘립니다». 화면이 뒤집어 세면
           「보이는 것 안에서의 순번」이 되어 «틀린 수»가 나옵니다
   => «서버 일» — 세는 자리가 서버여야 잘림에 안 걸립니다

③ 「언제쯤 도나」 (예상)
   서버 ⚠️ 재료는 있습니다 — 실행 행이 «시작»과 «끝» 시각을 둘 다 듭니다
        🔴 그런데 총괄 실측으로 표본 «3건»에 편차 «100배»입니다.
           그 위에서 만든 수는 «감»이 아니라 «지어낸 수»가 됩니다
   => 🔴 판정 자리입니다: 「예상 시각」을 낼 것인가, 아니면 ①②④ 로 «감»을 대신할 것인가

④ 「아무도 안 집어가고 있다」   ← 소유자가 두려워하시는 그것
   서버 ✅ «이미 있습니다». 스케줄러가 «틱마다» 심박을 찍고, 상태 라우트가 그것을
        «오래됨 기준»과 «함께» 냅니다.
        🔵 그리고 소급 실행은 «틱 스레드 밖»에서 돕니다 — 그래서 심박이 오래됐다는 것은
           「긴 작업 중」이 아니라 «틱이 안 돈다»입니다. 그 모호함은 어제 닫혔습니다
   화면 ❌ 어드민이 그 라우트를 읽는 자리가 «0» 입니다 (클라 전체에서 «0건»)
   => 🔵 「이미 되는데 아무도 안 쓴다」 부류입니다. «새로 만들 사실이 없습니다»
```

🔴 **그래서 셋 중 가장 무서운 것이 가장 «싼» 것입니다** — ④ 는 서버에 이미 있고,
②는 «세는 일»이며, ③만 판정이 필요합니다.
