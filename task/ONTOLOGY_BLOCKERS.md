# 🔴 운영에서 온톨로지가 «한 달째» 안 도는 이유 — 현재까지 정리 (2026-09-04, 총괄)

> 소유자: 「지금 한달째 운영에서 온톨로지 안돌아감」 · 「현재까지 문제들 다 정리해」

⚠️ **읽는 법.** 아래를 «두 갈래»로 갈랐습니다.
- **A. 운영 온톨로지를 막는 것** — 이게 한 달의 이유입니다. 대부분 «아직 안 고쳐졌습니다»
- **B. 오늘 잡은 운영 사고** — 오늘 하루 나온 것이고 «대부분 고쳐졌습니다». A 와 원인이 다릅니다

🔴 그리고 **A 의 항목은 총괄이 «운영을 본 것이 아닙니다».** 코드에서 읽은 것과 소유자 관측을
합친 것입니다. 「운영이 그렇다」로 확정된 것은 «소유자가 말씀하신 것»뿐이고 그렇게 표시했습니다.

# A. 운영 온톨로지를 막는 것

## A-1 🔴 원장 표가 «없을» 수 있습니다 — 그러면 나머지는 전부 무의미합니다
```
코드   ledger/schema.py:52   LEDGER_TABLE = "ledger_events"
      schema.py:79          CREATE TABLE IF NOT EXISTS ledger_events (...)
🔴 부팅이 이 DDL 을 «안 돌립니다» — main.py 어디서도 안 부릅니다
세우는 자리  ledger/setup.py:160 setup_from_document(...)
           <- config_explorer_service.py:136 이 «선언 활성화» 경로에서 부릅니다
소유자 관측  「운영에 ledger events 릴레이션이 없다」
```
**확인** `SELECT to_regclass('public.ledger_events');` -> NULL 이면 없습니다
**푸는 법** 온톨로지 탐색기에서 선언을 «활성화»하면 그 경로가 표·인덱스를 만듭니다.
`IF NOT EXISTS` 라 이미 있으면 아무 일도 안 일어납니다.

## A-2 🔴 화면이 통과시킨 선언이 «실행에서» 죽습니다 — 어휘가 «안 겹칩니다»
코드가 자기 주석에 이미 적어 뒀습니다 (`config_explorer_service.py:540-546`):
```
런타임이 거절하는 방법   «85가지»
화면이 거절하는 방법     «57가지»
두 집합이 공유하는 코드 이름   «0»
그래서 선언이 폼을 통과하고 백필에서 죽습니다
실측 예: `lot_event` 가 «하루에 다섯 번» — dead cursor · business key mismatch ·
        string time · missing registration_probe … «전부 화면에서는 초록»
```
🔴 **이것이 「한 달」의 가장 그럴듯한 구조적 이유입니다.** 고치는 시도가 화면에서는 성공으로
보이고 실행에서만 실패하면, 무엇을 고쳐야 할지 «알 수가 없습니다».

## A-3 🔴 시험 실행이 «머리 200행»을 봅니다 — 표본이 아닙니다
```
config_explorer_service.test_run -> backfill.preview_first_batch(fetch_rows=PREVIEW_FETCH_ROWS=200)
docstring: 「THE FIRST PAGE, NEVER THE CURSOR」 (이유는 타당합니다 —
           새 소스는 커서가 없고, 기존 소스는 커서 뒤가 비어 보이니까)
```
🔴 **그런데 「첫 200행」은 «대표»가 아닙니다.** 소유자 지적 그대로입니다 —
「어떻게 실무 소스에 모든 행값이 다 채워짐」.
```
소유자 관측  「시간 컬럼 비어있다고 안 되는데 실제로는 채워져 있음」
=> 머리 200행 «안»에 빈 값이 있으면 선언 전체가 거절될 수 있습니다
=> 총괄이 «못 확인한 것»: 한 행의 실패가 «배치 전체»를 죽이는지, 그 행만 거절되는지
   -> 이것이 A 갈래에서 «가장 먼저 재야 할» 한 가지입니다
```

## A-4 🔴 맵퍼 파일을 고쳐도 «옛 코드»가 돕니다
```
소유자 실측  「맵퍼 함수 안에 print(1) 넣었는데 서버 로그에 안 뜨고 «돌았다»고 함」
기제        reload_worker_process_cache() 가 mappers.* 를 sys.modules 에서 비우고 재import 합니다
           -> 그런데 그건 «SYSTEM_RELOAD 이벤트»가 왔을 때만 돕니다
           -> 🔴 «파일을 고치는 것»은 그 이벤트를 «안 만듭니다»
=> 워커는 부팅 때 import 한 모듈을 계속 돌립니다. 그 옛 함수가 «성공»하니 「돌았다」도 참입니다
```
**우회** 어드민의 「Reload Configs」(POST /admin/reload-configs) -> 그 뒤 print 가 «찍혀야» 합니다
🔴 안 찍히면 그때가 진짜 결함입니다 (이벤트 미생성 / 워커가 못 봄 / 비우고도 옛 것 사용)

## A-5 선언된 릴레이션 «열»이 표가 아니라 «뷰»입니다
```
프레임워크는 선언된 것을 «전부 표로» 보고 매 부팅 ADD COLUMN 을 던집니다 -> 28번 실패
그 실패가 «맨 print» 였습니다 -> 아무도 몰랐습니다
✅ 오늘 고침: 릴레이션당 «한 줄»로 「표로 선언됐는데 뷰」 (부팅 로그 28 -> 10)
🔴 아직 판정 안 남: 뷰를 «선언 가능»하게 할지(ⓐ) · 불가로 할지(ⓑ) · 말만 할지(ⓒ)
⚠️ dt_log_transferable 이 그 열 중 하나입니다 — 소유자가 «지금 선언 중인» 계열입니다
```
📌 CLAUDE.md 완성 판정이 「뷰는 두 줄로 안 말해진다 · 그게 설계의 빚」이라고 «이미» 적어 뒀습니다.

## A-6 키를 «두 컬럼으로 조립»할 수 없습니다
```
키 부분의 kind 는 셋뿐  column · constant · declared_lookup — «전부 값 하나»
문법이 「closed, execution-free」로 «일부러» 그렇게 돼 있습니다
=> mat_id 가 lot+slot 조합이면 «선언으로는 못 합니다». 표에 컬럼을 하나 두는 것이 이 시스템의 답
🔴 미해결: dt_log 의 한 행이 die 인가 lot_slot 인가 — 도메인 사실이라 총괄이 못 정함
   die@1 키가 «넷»(mat_id·x·y·mat_type) · lot_slot@1 이 «둘»(lot·slot)
```

## A-7 walk 이 「키 부분이 같은 다른 노드」를 표현 못 합니다
```
은퇴한 /api/ledger/siblings 가 scope=<axis>:<value> 로 답하던 것 = «있다가 없어진» 능력
맵 페이저(목업 「‹ 3/25 ›」)와 옛 fetch 넷 삭제가 «둘 다» 여기 걸려 있습니다
🔴 소유자 판정 대기
```
