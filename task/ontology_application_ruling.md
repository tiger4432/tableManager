## ✅ C — 사내 화면 텍스트가 서버로 나가는 것: **소유자 승인**

> **소유자 (2026-08-21 16:2x): 「C는 사내 서버라 괜찮음」**

**진행하십시오.** 다만 당신이 스스로 건 가드는 **그대로 둡니다** —
```
✔  클릭한 «선택 영역 하나»만 보낸다
✔  화면 «전체 스캔» 금지 (지시서에 못 박은 그대로)
```
승인은 「사내 서버」라는 전제 위에 있다. **그 전제가 바뀌면(외부 노출·로그 반출) 다시 올릴 것.**

🔴 **올린 것 자체가 옳았다.** 당신이 「최소이지만 판단은 제 것이 아니다」로 멈춘 것이 맞는
처신이다. 데이터가 세션 밖으로 나가는 결정은 소유자 몫이다.

## 🟡 A — 지시서 둘의 착수 승인: **접수. 다만 «지금은 레인이 없다»**

```
1  APPLICATION_PROPAGATION_BRIEF     전파 + walk
2  APPLICATION_ANYWHERE_SEED_BRIEF   클릭한 글자가 씨앗
```
**지시서는 받았고 잃지 않는다.** 다만 오늘 두 레인이 다 차 있다:
```
구현자   packs·claims 제거 + binding 템플릿 (하위 에이전트로 도는 중)
총괄     lot_event 를 흐르게 (카탈로그 벽에서 판정 대기 중)
```
**「2 가 1 을 안 기다린다」는 판단은 맞다** — `resolve` 가 `walk` 없이 `explore_entity` 로
쓸모가 있다는 것도 맞게 봤다. 레인이 비는 대로 **2 부터** 연다.

⚠️ **착수 순서는 총괄이 정한다. 당신은 지시서를 더 다듬지 말고 «대기»하라** —
아직 안 도는 것을 계속 정교하게 만드는 것이 오늘 이 프로젝트가 지운 것들의 유래다.

## ✅ B — 클라 확장은 어느 레인인가: **client-pm 소관. 지금은 열지 않는다**

브라우저 확장(클릭 잡기 + 패널)은 표현 계층이라 `client-pm` 이 맞다.
**다만 지금 그 레인을 열지 않는다** — A 와 같은 이유다.
2번 지시서에서 «서버 쪽»(`ledger_trace_router`·`ledger_catalog`)과 «클라 확장»을
**분리해 두면** 서버 절반을 먼저 착지시킬 수 있다. 그렇게 나뉘어 있는지만 확인해 두라.

## 참고 — 당신 응용이 기다리는 `lot_event` 의 «현재 벽»

응용 ①③④⑥ 이 이 재료를 기다리므로 상태를 공유한다.
```
커서 삭제·재실행까지 갔다가  cursor_value: cursor number must be finite 로 거절
원인   table_config 가 lot_event.business_key = "txn_seq" 로 선언
       실측 txn_seq 는 142행 중 «62행 NULL» · (event_time,txn_seq) distinct 113/142
       → 선언된 키를 데이터가 뒷받침하지 않는다
검증기 커서는 «카탈로그가 선언한 유일 키»를 덮어야 한다 (setup_bundle.py:1438)  ← 규칙은 옳다
후보   row_id  NULL 0 · (event_time,row_id) 142/142 · UUIDv7 이라 단조
그런데 카탈로그가 그 유일 인덱스를 «모른다» — 26표 «전부» PRIMARY KEY(row_id) 인데
       indexes 를 선언한 표가 «0개»였다. 로더에 그 갈래는 있는데 한 번도 안 쓰였다
현재   총괄이 「표마다 선언」이 아니라 「로더가 안다」로 고칠지 소유자 판정 대기
```
**즉 막힌 것은 원장도 매퍼도 아니고 «카탈로그의 주장»이다.**
