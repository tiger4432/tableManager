# 운영자의 여정 — 「표가 있다」에서 「원자가 들어갔다」까지

총괄 지시(`task/MARKING_CONTRACT.md` 「다음 = 운영자의 여정을 «끝까지» 걸어 보십시오」)에 대한
응용 산출물. 정본 DoD 는 `task/PHASE_ONTOLOGY_REVIVAL.md` 입니다.

```
시작   운영자에게 «데이터가 든 표»가 있다
끝     원장에 원자가 있고, 화면이 「들어갔다」고 말한다
```

**잰 기준:** 커밋된 HEAD 뿐입니다. 걸음마다 「**서버가 아나**」와 「**화면이 말하나**」를 «따로»
적었습니다 — 오늘 이 둘이 계속 갈렸습니다.

⚠️ **재는 중에 트리가 움직였습니다.** 표 등록 라우트를 처음 쟀을 때는 작업 트리에만 있었고
(HEAD 에 «0»), 몇 분 뒤 `e627d6e5` 로 커밋됐습니다. **미커밋을 「있다」로 적지 않았고**, 아래는
전부 그 커밋 «이후»의 HEAD 기준입니다.

---

# 🔴 맨 앞 — 막히는 자리 «다섯»

## ① 🔴 표 등록 — 라우트는 «오늘» 섰는데, 읽는 화면이 «0»
```
서버   `/admin/tables/config/raw` GET · POST     («있습니다», e627d6e5)
화면   그 경로를 읽는 곳  소스 «0» · 번들 «0»
```
=> 여정의 첫 걸음이 여전히 «앱 밖»입니다. 클라가 걸어 보고 찾은 그 구멍이 «절반» 메워졌습니다 —
서버 쪽 절반입니다.

## ② 🔴 「왜 안 들어갔나」 — «수»는 있고 «이유»가 없습니다
```
서버   소스별로 냅니다: 상태 · 원자 수 · 분자 수 · «거절된 분자 수» · 갱신 시각
       🔴 그런데 «거절 이유»는 커서 뷰에서 «의도적으로 빠져» 있습니다
          (`_CURSOR_FIELDS` 옆에 그 이유가 적혀 있습니다 — NULL 과 빈 객체의 뜻이 달라서)
화면   거절 «수»를 읽는 곳 «1» · 거절 «이유»를 읽는 곳 «0»
```
=> 운영자는 「몇 개가 거절됐다」까지 갑니다. **「무엇을 고쳐야 하나」에서 멈춥니다.**
🔴 **이것이 DoD 의 후반부(「왜 안 들어갔나를 화면에서」)가 «아직 안 선» 자리입니다.**

## ③ 🔴 선언 거절의 «주소» — 서버가 싣기 시작했는데 읽는 쪽이 «0»
```
서버   선언 거절이 (코드 · 경로 · 문장)을 «전부» 나릅니다. 자르면 「몇 개 중 몇 개」를 말합니다
       (A-2 명세 ①이 지목한 경계가 닫혔습니다)
화면   그 목록을 읽는 곳 «0»
       옆에서 «다른» 거절 하나는 이미 경로를 그리고 있습니다 — 그릴 자리는 «있습니다»
```
=> 배선만 남았습니다. 그리는 방법을 새로 발명할 필요가 없다는 뜻이기도 합니다.

## ④ ⚠️ 원자 쌓기 — 화면이 소스 이름을 «타이핑»으로 받습니다
```
서버   전진 번역이 소급 연산으로 «있습니다». 취소 가능 · 재시작 가능 · 페이지마다 커밋
화면   연산 목록은 서버가 준 대로 그립니다 ✅
       🔴 그런데 인자는 «운영자가 친 것»을 받습니다. 고를 목록을 «안 채웁니다»
          그 인자의 도움말이 «다른 라우트를 직접 부르라»고 말합니다
```
=> 운영자가 자기 소스의 «id 를 이미 알고» 있어야 합니다. 방금 선언한 사람이 그걸 알 이유가 없습니다.

## ⑤ ⚠️ 「시험」과 「적재」의 거절이 «다른 자리»에 있습니다
```
시험   화면이 «진짜 것»을 한 번 돌립니다 — 같은 준비기·맵퍼·컴파일러, 쓰기 «없이»
       거절이 «그 자리»에서 그대로 나옵니다 ✅
적재   같은 거절이 실제로 나면 «수»로만 남습니다 (위 ②)
```
=> 같은 실패가 시험에서는 «읽히고» 적재에서는 «안 읽힙니다». 운영자는 그 둘이 같은 것인지 모릅니다.

# 걸음 여덟 — 각각 네 칸

## 1. 「내 표를 도구가 알게 한다」
```
② 어디서   서버 라우트 «있음». 전용 화면 «없음»
③ 무엇이 막나  화면이 없으므로 라우트를 «직접» 불러야 합니다
④ 다음이 보이나  🔴 아니오 — 시작점이 화면에 없으니 「그다음」도 화면에 없습니다
서버가 아나   ✅ 예 (오늘)          화면이 말하나   ❌ 아니오
```

## 2. 「무엇이 있고 무엇이 무엇을 말하는지 적는다」 (엔티티 · 술어)
```
② 어디서   온톨로지 탐색기의 초안. 폼의 «모양»이 선언 스켈레톤에서 생성됩니다
③ 무엇이 막나  이름·형식·미지 참조 — 저장 시점에 코드와 «경로»로 거절됩니다
④ 다음이 보이나  ✅ 예 — 경로가 «어느 칸»인지 가리킵니다
서버가 아나   ✅ 예                화면이 말하나   ✅ 예
```

## 3. 「내 표를 소스로 선언한다」 (읽기 · 준비 · 매핑 · 바인딩)
```
② 어디서   같은 화면, 같은 초안
③ 무엇이 막나  구조 -> 컴파일 순으로 걸립니다. 둘 다 코드와 경로를 냅니다
④ 다음이 보이나  ✅ 예
서버가 아나   ✅ 예                화면이 말하나   ✅ 예
⚠️ 다만 여기서 «형태»가 틀리면 원자가 안 섭니다 — 그 형태는 `task/ATOM_ROW_SHAPE.md` 가 정본입니다
```

## 4. 「돌려 보기 전에 시험해 본다」
```
② 어디서   화면에 «있습니다». 진짜 준비기·맵퍼·컴파일러를 «쓰기 없이» 한 번
③ 무엇이 막나  여기서 나오는 것이 «답»입니다. 거절이 자기 말로 그 자리에서 나옵니다
④ 다음이 보이나  ✅ 예 — 「이 결과가 활성화를 막나」가 «값»으로 오고, 화면이 그 값을 읽습니다
서버가 아나   ✅ 예                화면이 말하나   ✅ 예 (번들에도 있습니다)
```

## 5. 「활성화한다」
```
② 어디서   같은 화면
③ 무엇이 막나  활성화를 막는 것이 «이름»으로 옵니다. 빨간 시험 결과는 «막지 않습니다»
④ 다음이 보이나  ✅ 예
서버가 아나   ✅ 예                화면이 말하나   ✅ 예
```

## 6. 「원자를 쌓는다」
```
② 어디서   소급 연산 화면. 목록은 서버가 준 대로 그립니다
③ 무엇이 막나  🔴 «자기 소스 이름»입니다. 화면이 고를 목록을 안 채우고 도움말이 다른 라우트를 가리킵니다
④ 다음이 보이나  ⚠️ 절반 — 「무엇을 하라」는 있는데 「무엇에 대고」가 없습니다
서버가 아나   ✅ 예                화면이 말하나   ⚠️ 목록만. 인자는 «타이핑»
```

## 7. 「들어갔는지 본다」
```
② 어디서   소스 현황 화면. 상태 넷을 «접지 않고» 그립니다. 읽기 전용입니다
③ 무엇이 막나  없음 — 여기까지는 갑니다
④ 다음이 보이나  ⚠️ 「안 들어갔다」까지는 보이고, 「왜」는 다음 걸음입니다
서버가 아나   ✅ 예                화면이 말하나   ✅ 예
⚠️ 이 화면은 «원장을 읽지 않습니다» — 번역기가 기록한 것을 읽습니다. 그 차이가 답과 함께 나옵니다
```

## 8. 「왜 안 들어갔는지 본다」
```
② 어디서   🔴 «없습니다». 거절의 «수»가 있는 자리는 있고, «이유»가 있는 자리는 없습니다
③ 무엇이 막나  이유가 커서 뷰에서 의도적으로 빠져 있고, 화면도 읽지 않습니다
              선언 거절은 서버가 코드·경로를 «싣기 시작했는데» 읽는 쪽이 없습니다
④ 다음이 보이나  🔴 아니오 — 여정이 «여기서» 끝나지 못합니다
서버가 아나   ⚠️ 절반 (선언 거절은 예 · 적재 거절 이유는 아니오)   화면이 말하나   ❌ 아니오
```

# 그래서 여정은 «어디까지» 갑니까

```
1 표 등록      🔴 화면 밖
2 어휘 선언     ✅
3 소스 선언     ✅
4 시험         ✅
5 활성화        ✅
6 쌓기         ⚠️ 이름을 알아야 함
7 들어갔나      ✅
8 왜 안 들어갔나 🔴 없음
```
🔴 **가운데 넷(2~5)은 이어집니다.** 끊기는 곳은 «양 끝»입니다 — 들어가는 문(1)과 나오는 답(8).
그리고 그 둘은 같은 성질입니다: **서버는 알고 화면이 말하지 않습니다.**

## 판정으로 올리는 것 «둘»
```
1  ②·③ 이 «같은 라운드»인지 — 둘 다 「거절을 화면에 세운다」이고, 그릴 자리도 이미 있습니다
   따로 하면 거절이 두 모양이 됩니다 (A-2 가 경고한 「세 번째 어휘」와 같은 부류)
2  ⑥ 의 인자 목록을 채우는 것이 «소급 화면»의 일인지 «선언 화면»의 일인지
   소스 목록을 아는 쪽은 선언 화면입니다
```

## 이 문서가 «하지 않은» 것
```
⛔ 코드 없음 · 도메인 낱말 없음 · 이 박스의 행 수 없음 · 라이브 선언 값 없음
⛔ 오늘 착지한 것을 「됩니다」로 «접지» 않았습니다 — 걸음마다 서버·화면을 따로 적었습니다
⛔ 미커밋을 「있다」로 쓰지 않았습니다. 재는 중에 커밋된 것 하나를 그 사실과 함께 적었습니다
⛔ 실제로 클릭해 보지 «않았습니다» — 이건 코드에서 잰 여정입니다.
   브라우저로 걷는 것은 «다른 종류»의 증거이고, 총괄이나 클라 몫입니다
```
