# 원자의 `predicate` — 이름인가 «불변 id» 인가 (총괄 회신, 2026-08-21 14:4x)

> 응용 기획 세션이 판정을 올렸다. **총괄 회신이 메시지로 두 번 유실돼 이 파일이 정본이다.**
> 응용 세션 원문 근거: `task/ontology_arbitrary_question.md` · `task/ontology_application_algorithm.md`

---

## 올라온 제안

소유자 발화(2026-08-20): 「**원장에 has_wafer 이런 도메인 어휘 안 들어가고** 어떻게 할 수 있을지」

```
지금    원자에  predicate = "register"        도메인 이름이 그대로 저장된다
제안    원자에  predicate = <불변 id>          뜻은 선언이 답한다
```
얻는 것: 개명이 원자를 안 건드림 · 공장·팀마다 다른 이름이 한 id 를 공유 · 읽는 쪽이 다르게 해석.

---

## 🔴 총괄 정정 ① — 「재백필이 어차피 대기 중이라 비용 0」은 «절반만» 맞다

응용 세션 전제: 원장이 안 흐르고 재백필이 대기 중 → 지금 바꾸면 추가 비용 0.

**총괄 실측 (2026-08-21 14:2x, 라이브 DB):**
```
원장 전체            221,563
ledger-v2 원자           792   (0.36%)
커서 12개 중 v2           1개
   dt_job     ledger-v2:925655da…      ← «막혀 있지 않다». 오늘 재스탬프 끝나 재개 가능
   lot_event  lot_event/1/rules:…      ← v1 모양. 막힌 건 «이쪽»뿐
```
**커서 전역 지문 문제는 오늘 해소됐다**(`b100fb2a`, 소스별 지문). 그래서 「원장이 안 흐른다」는
이제 `lot_event` 에만 참이다.

**그러면 비용이 0이 아니다:**
```
이미 쌓인 792행이 «옛 모양»으로 남는다       소유자 원칙: 원장은 append, 갈아치우지 않는다
지우고 다시 넣으면                          = 갈아치우기. 소유자가 오늘 명시적으로 거절
그냥 다시 읽으면                            predicate 가 바뀌어 uq_ledger_atom 키가 달라짐
                                            → 같은 사실이 «중복 792행»
```
792는 작지만 부류가 같다. **「지금이 나중보다 싸다」는 여전히 성립한다. 「0」만 틀렸다.**

## 🔴 총괄이 더 무겁게 보는 대가 — 응용 세션 목록에 «없던» 것

```
④ 원장이 «자기 완결성»을 잃는다
      지금   원자 하나만 보면 predicate = "register" — 뜻이 그 «안»에 있다
      뒤엔   원자는 id 만 들고, 뜻은 «지금 살아 있는 설정 파일»에 있다
      → 선언이 바뀌거나 지워지면 «과거 원자가 안 읽힌다»
```
**뷰로 해소되지 않는다 — 뷰도 «지금» 설정을 보기 때문이다.**
원장은 핵심가치 ⑤(변경 이력 추적)의 근거인데, 그 근거가 «가변 파일»에 기대게 된다.
하려면 **「선언은 은퇴만 되고 삭제되지 않는다」**가 같은 라운드에 서야 한다.

⚠️ 응용 세션이 붙인 조건(**id 는 생성되면 불변** · `register@1` 은 이름을 포함하므로 조건 미달)은
옳다. 다만 그 조건만으로는 위 ④가 해결되지 않는다 — 불변 id 라도 «선언이 사라지면» 뜻이 사라진다.

---

## 판정

**총괄 소관이 아니다. 소유자 판정으로 올린다.**

이유: 오늘 하루 지운 것들(절 넷·선언 다섯)은 **저작 층**이라 되돌릴 수 있다.
이것은 **원장에 영구히 들어가는 모양**이고 쌓인 원자는 되돌릴 수 없다.
응용 세션이 「제가 판단하지 않는다」고 한 것은 **옳은 처신이다.**

---

## 순서 — 겹치지 않고 «도움이 된다»

소유자가 `packs`·`claims` 절 통째 삭제를 승인했다(`task/ledger_drop_packs_claims_brief.md`).
```
지금    claim.emit.predicate  +  mappings.use     ← 술어를 «두 곳»이 부른다
그 뒤   mappings.<sentence>.predicate             ← «한 곳»
```
**id 라운드를 하게 되면 그 뒤가 더 쉽다.** 고칠 자리가 하나로 줄어든다.
현재 순서(packs 먼저)를 바꿀 이유가 없다.

---

## 응용 세션 질문에 대한 답

**「무한 케이스 감사를 나머지 문서 둘에도 반영할까」 → 하십시오.**
그건 그 레인 «안»의 일이고 총괄 승인이 필요한 종류가 아니다.
총괄에 올려야 할 것은 **저장 모양 · 원장 스키마 · 설정 형식**처럼 다른 레인과 부딪히는 것뿐이다.

⚠️ **메시지가 새고 있다.** 총괄 회신이 오늘 두 번 도달하지 않았다(수신 기록 0건).
**급한 판정은 파일에도 같이 적을 것 — 파일이 정본이다.**

# 🔴 총괄 의견 — 소유자 요청 (2026-08-21 15:0x 「predicate 를 불변 id 로 할지 의견 어때」)

## 결론: **찬성. 다만 제안된 모양 그대로는 아니다.**

### ① 문제가 `predicate` «하나»가 아니다 — 부류로 봐야 한다

```
DEDUPE_COLUMNS = occurred_at · predicate · subject_type · subject_keys ·
                 object_payload · source_translator_ver · source_raw_ref
                              ↑            ↑
                          둘 다 «이름»이다
```
`subject_type` 도 `Lot@1` → `Lot` 로 이름이 들어가고 **똑같이 dedupe 키다.**
엔터티를 개명해도 같은 일이 난다. **`predicate` 만 고치면 옆에 같은 게 하나 남는다**
([[rule-the-class-not-the-instance]]).

### ② 처방 — id 로 바꾸되 «이름을 같이 저장한다»

```
predicate         불변 id       ← dedupe 키에 «들어간다»
predicate_label   쓸 때의 이름   ← dedupe 키에 «안 들어간다». 사람이 읽는 용
subject_type      같은 처방
```
**이러면 위 §「원장이 자기 완결성을 잃는다」가 해소된다:**
```
개명해도 원자 0건        id 가 안 바뀌니 dedupe 그대로
원장이 여전히 읽힌다      원자 하나만 봐도 이름이 «그 안»에 있다
선언이 지워져도 안전      뜻이 «가변 설정 파일»에 의존하지 않는다
```
🔴 **그리고 쓸 때의 이름을 남기는 것이 지금보다 «더» 정직하다.** 지금은 이름이 바뀌면
과거 원자가 «새 이름»으로 읽히는데, 그것은 그때 그렇게 부르지 않았다는 사실을 지운다.

### ③ 이 제안이 오늘 배운 것을 어기지 않는지 자기검사했다

오늘 박은 질문: **「이 칸이 서로 다른 두 값을 가질 수 있나. 하나만 나오면 사본이다.」**
([[if-code-cannot-reach-it-neither-should-the-declaration]])
```
predicate_label   개명 전/후로 다른 값. 공장마다 다를 수도 있다   → 사본 아님 ✅
predicate(id)     label 과 갈라질 수 있다                        → 사본 아님 ✅
```
오늘 지운 선언 다섯은 전부 이 질문에 「하나」로 답했다. **이건 「둘」로 답한다.**

### ④ 정직하게 — 이득의 절반은 «미래»다
```
지금 확실   개명이 자유로워진다        화면에서 소유자가 만드니 개명은 실제로 일어난다
아직 미래   공장·팀마다 다른 이름 통합   지금은 이름이 하나뿐이다
```

### ⑤ 순서 — 따로 하지 말고 «붙인다»
```
packs·claims 제거    지문 이동 + 재스탬프 1회
predicate → id       지문 이동 + 재스탬프 1회 + 원장 스키마 변경
문자열 시각          지문 이동 + 재스탬프 1회
```
**따로 하면 재스탬프 3회, 붙이면 1회.** 그리고 원장이 **792행**인 지금이 가장 싸다.

### ⑥ 🔴 창이 닫히는 시점 — 이것이 순서를 정한다
**지금은 안 해도 되돌릴 수 있다** — 792행이면 지우고 다시 쌓는 것이 현실적이다.
**`lot_event` 를 흐르게 하는 순간 그 창이 닫힌다.**
그래서 **「lot_event 를 흐르게 할지」 판정보다 이것이 «먼저»여야 한다.**
