# 결측을 «사람 말»로 — 명세 요청

총괄 -> 응용. 2026-08-30 밤. 선행 조건 «없습니다» — 지금 시작할 수 있습니다.

## 먼저 — §5 를 제가 오늘 밤 «다시» 발견했습니다

마킹 계약 §5 에 이렇게 적혀 있습니다:

> 본딩축 rotation «180» · DT축 0 · 코어축 0
> 「본딩 (3,4) 와 코어 (3,4) 는 «다른 물리 자리»입니다」
> 「어느 기준계로 만든 노드인지를 노드 id 가 «스스로 지녀야» 합니다」

오늘 밤 저는 같은 문제를 서버 쪽에서 처음부터 다시 유도했고, 설계가 두 번 뒤집힌 뒤에
**같은 결론에 도착했습니다.** 그리고 두 결론이 «같은 규칙의 다른 경계»입니다:

```
소스(번역)       -> 표준 좌표로 «기록»            오늘 소유자 판정
화면(사람 클릭)   -> 표준 좌표로 «노드 id 생성»     §5 가 이미 적어 둔 것
=> 규칙은 하나입니다: 「원장에 들어가는 모든 문에서 표준으로」. 문이 둘일 뿐입니다
```
§5 에 그 문장을 한 줄 얹어 주십시오 — 다음 사람이 한쪽만 보고 반쪽으로 고치지 않게.

## 본 요청 — 결측의 «말»을 정해 주십시오

### 기작은 이미 확인됐습니다. 도메인 낱말이 «하나도» 안 들어갑니다
```
어휘를 순회한다. 술어 P · 주어타입 S · 목적타입 O 를 «선언에서» 읽고
   결측(주어쪽) = S 노드 중 P 로 나가는 것이 «없는» 것
   결측(목적쪽) = O 노드 중 P 로 들어오는 것이 «없는» 것
```
실측(개발 박스, 모양만): `of_kind@1` 로 관측된 결함 종류 «1»(void), `leads_to@1` 로
모델이 닿는 종류 «2»(void·delam) -> 한쪽 방향으로 «1» 이 남습니다.

### 🔴 그런데 «부재가 곧 결측은 아닙니다» — 여기가 명세의 핵심입니다
```
어휘는 「무엇이 «있을 수» 있나」를 말합니다. 「무엇이 «있어야» 하나」는 «안» 말합니다
=> 모든 빈자리를 결측이라 부르면 화면이 빈자리로 가득 차고, 진짜는 그 속에 묻힙니다
```
그래서 **술어마다 「이 부재가 일감인가」를 누군가 말해야** 하고, 그게 이 명세입니다.

### 정해 주셔야 하는 것 넷

```
① 이름       각 결측을 «사람 말»로 뭐라 부르나
② 두 방향     🔴 섞이면 안 됩니다. 뜻이 다르고 «할 일»이 다릅니다
             관측O · 모델X   「봤는데 왜 그런지 못 댄다」   = 설명 결측
             모델O · 관측X   「그렇다고 했는데 아직 못 봤다」 = 검증 결측
             화면에서 이 둘을 어떻게 «다르게 말할» 것인가
③ 행동       각 결측이 사람에게 «무엇을 하라»고 하나
             (이게 없으면 목록일 뿐이고, 목록은 안 읽힙니다)
④ 🔴 제외    어떤 부재는 «결측이 아니다» — 그걸 술어별로 갈라 주십시오
             예: 「아직 계측 안 한 웨이퍼」는 일감이 아닐 수 있습니다
                 「종류가 안 붙은 결함」은 일감입니다
             이 판단이 이 문서의 «값어치»입니다. 나머지는 기계가 합니다
```

### 기존 원칙 위에 서 주십시오 — 새로 만들지 마시고
```
보드 설계 원칙 ⑥   「부재는 «셋»으로 말한다」
                 이미 있는 그 구분과 «같은 낱말»을 쓰십시오. 넷째를 만들지 마십시오
CLAUDE.md        「액션은 놀라움을 줄이는 장치」 — 정당한 감쇠는 «설명»이나 «학습»이고
                 유일한 위조는 «안 보이게 매끄럽게 만드는 것»
                 -> 결측을 조용히 두는 것이 그 위조입니다. 이 명세가 그걸 뒤집습니다
```

## 이 명세가 «어디로» 가나 — 둘이 여기 매달려 있습니다
```
진행 관리 화면    task/OPS_PROGRESS_PAGE_CONCEPT.md 의 「상태」 칸이 이 말을 씁니다
액션 발급         보류 중이고 판정 하나가 남아 있습니다 (C-2 — 「채웠다 치고」의 정의)
                 -> 결측의 «수»를 보고 나서 액션 형태를 정하는 것이 순서라고 총괄이 적었습니다
```
그래서 이 명세가 먼저입니다. 그리고 이건 «코드가 아니라 말»이라 응용 자리입니다.

## 하지 마실 것
```
⛔ 결측 검출을 «구현»하지 마십시오 — 명세만. 코드는 지시서로 나갑니다
⛔ 술어를 새로 «제안»하지 마십시오 — 지금 어휘 14 개로 무엇이 결측인지만 정하면 됩니다
⛔ 이 박스의 «수»를 근거로 쓰지 마십시오 — 씨앗이라 운영과 다릅니다
   (모양은 봐도 됩니다. 「이 박스에서는」을 붙이면 됩니다 — CLAUDE.md 의 그 관문)
```

## 그리고 판정이 필요하면 올려 주십시오
④(무엇이 결측이 아닌가)는 도메인 판단이 섞일 수 있습니다. 총괄이 못 정하는 것이면
소유자께 올립니다 — 오늘 밤 제가 스키마로 도메인을 «추론»하다 네 번 틀렸고,
네 번 다 소유자가 한 줄로 잡았습니다.

## 승인합니다. 그리고 «제 지시서를 고친 것»이 이 문서의 값어치입니다
```
제가 쓴 것   「두 방향 = 한 술어의 주어쪽·목적쪽」
당신 정정     한 술어의 두 쪽이 «아니라», 같은 타입에 들어오는 «두 술어»의 집합 차이
            그리고 그런 타입이 «넷»입니다 (defect_kind · quantity · wafer · die)
=> 제가 든 예시 자체가 제 규칙과 안 맞았습니다. 한 쌍만 보고 적어서 나머지 둘이 이름 없이 남을 뻔했습니다
```
그리고 제외가 «대부분 구조»라는 것도 제 예상을 뒤집었습니다 — 저는 ④가 도메인 판단 덩어리일
줄 알았는데, 실제로는 셋이 기계로 갈리고 «하나»만 남았습니다. 그게 제대로 재 본 결과입니다.

「목록에 Ⅰ 이 뜨면 검출기의 결함이다」     명세가 «자기 검사»를 들고 있습니다

## ⏭ §4 판정 — **셋 다 «분류하지 말고 나이를 함께 보이십시오»**

「시간이 지나면 채워지나」를 제가 답하면 오늘 밤 네 번 틀린 그 방식이 됩니다. 그래서 **답 대신
질문을 없애는 쪽**으로 판정합니다.

```
문제   「아직」이냐 「없다」냐는 «술어의 성질»이 아닙니다 — 같은 웨이퍼가 5분 뒤엔 「아직」이고
      한 달 뒤엔 「없다」입니다. 술어마다 하나로 못 정합니다
판정   검출기가 «분류하지 않습니다». 부재를 «나이와 함께» 냅니다
      「계측 없음 — 첫 등장 후 34일」
      -> 사람이 봅니다. 임계값도, 도메인 입력도, 새 축도 «없습니다»
근거   원자에 occurred_at 이 «이미» 있습니다. 새로 만들 것이 없습니다
```
```
✅ 그러면 당신이 그은 경계가 «그대로» 섭니다
   진행 관리 화면   시간이 채우는 것 — 「아직」
   결측 목록        시간이 안 채우는 것 — 「없다」
   차이는 «나이»이고, 그건 데이터가 답합니다
⏭ 나중에 「N일 넘으면 결측」이 필요해지면 그때 «선언 한 줄»입니다. 지금 만들지 마십시오
```
⚠️ 소유자께 이 판정을 올립니다. 공정 순서에 「이건 반드시 며칠 안에 채워진다」 같은 사실이
   있으면 그때 임계값이 생기고, 그건 소유자 것입니다.
