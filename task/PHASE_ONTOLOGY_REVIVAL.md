# 📌 페이즈 — 「**운영에서 선언 하나가 원장까지 도달한다**」 (2026-09-04 개시)

> 소유자: 「문제 리스트 정리해서 다 해결해. 알아서 진행 내 컨펌 없이. 보고만해」
> 「하나의 페이즈로 정해서 중기적으로 이어지게 해」
> 사실: **운영에 `ledger_events` 가 없습니다.** 온톨로지가 **한 달째** 안 돕니다.

---

## 🔴 완성의 정의 — «두 줄». 운영자의 여정으로
```
운영자가 소스를 «선언»하고 «활성화»하면, 원자가 원장에 쌓인다.
그리고 「들어갔나 · 왜 안 들어갔나」를 «화면에서» 알 수 있다.
```
⚠️ 이 박스에서 되는 것은 완성이 아닙니다. **운영자가 그 두 줄을 할 수 있어야** 완성입니다.

## 이 페이즈가 «아닌» 것 — 밖으로 뺍니다
실재하는 결함이지만 위 여정을 «막지 않습니다». 페이즈에 넣으면 페이즈가 아니게 됩니다.
```
⏸ 뷰를 선언 가능하게 (ⓐ 판정함)      ⏸ 감사 로그 대형 리플레이 (ⓑ 판정함)
⏸ walk 의 키 부분 공유               ⏸ schema.py 색인
⏸ SQLite 사각지대                    ⏸ 아웃박스 지연 감사 · 실행 로직 정비
⏸ /dashboard/summary 게이트          ⏸ map_editor NaN (추출 라운드)
```
📌 판정은 이미 내려 뒀습니다(`task/IMPLEMENTER_ORDERS.md`). **페이즈가 끝나면 그 순서로 갑니다.**

## 여정의 다섯 걸음 — 이 순서가 곧 작업 순서입니다

### ① 「활성화하면 원장이 선다」를 «믿을 수 있게»
```
사실   activate 는 시험 실행 통과를 «요구하지 않습니다».
      거절 조건은 스냅샷 해시 compare-and-swap «하나»뿐 (config_drafts.py:592)
      그 경로(setup_from_document)가 ledger_events 와 인덱스를 만듭니다 (IF NOT EXISTS)
문제   화면이 그렇게 «안 읽힙니다». 빨간 시험 결과 옆에서 활성화를 누를 사람은 없습니다
할 일   test_run 응답에 「이 결과는 활성화를 막지 않는다」를 «값»으로
       activate 사전조회에 「무엇이 막나」를 «이름»으로 (지금은 스냅샷 해시 하나)
```
🔴 **이 한 걸음이 「한 달」을 설명할 수 있습니다.**

### ② 「왜 거절됐는지」가 읽힌다
```
소유자 관측  「시간 컬럼 비었다는데 실제로는 채워져 있음」 · 「어떻게 실무 소스에 모든 행이 다 채워짐」
할 일   거절문이 «N행 중 M행»과 «컬럼 이름»을 말한다
       한 행이 배치 전체를 죽이면 «그것도 고친다» — 부분 실패는 «부분»으로 보고한다
근거   완전한 소스를 요구하는 것은 이 도구의 역할과 어긋납니다
```

### ③ 「고친 것이 반영된다」
```
소유자 실측  맵퍼에 print(1) 을 넣었는데 로그에 «안 뜨고» 「돌았다」고 함
기제        파일 수정은 SYSTEM_RELOAD 를 «안 만듭니다» -> 워커가 부팅 때 모듈을 계속 씁니다
할 일       「Reload Configs」 뒤에 «반영되는지» 재고, 안 되면 고칩니다
```

### ④ 「도는 것이 보인다」
```
맵퍼가 «본문에 들어간» 순간의 로그 (시작·끝·던짐 «셋을 따로»)
진행 상황은 파일 인제션과 «같은 모양»(레지스트리 + 조회). ⛔ DB 컬럼 추가 없음
대기열의 __retroactive__ 등 «내부 토큰»을 사람이 읽는 값으로 (소유자: 「이딴 표기 절대금지」)
```

### ⑤ 「들어갔는지 확인된다」
```
/admin/ledger/sources 의 ingestion 네 상태 — 라우트는 «살아 있고 읽는 쪽이 0» 입니다
할 일   그 화면을 만듭니다. 원장이 서면 «즉시» 필요해집니다
```

## 🔴 진행 규칙 — 중기적으로 이어지게
```
① 걸음이 착지할 때마다 «멈추지 않고» 다음으로. 총괄이 재기동하고 보고합니다
② 소유자 컨펌 «없이» 진행. 다만 «되돌릴 수 없는 것»에 닿으면 그때만 멈추고 올립니다
   (스키마 변경 · 데이터 삭제 · 감사 «단위» 변경 · 인증 표면 변경)
③ 각 걸음의 끝에 «운영자가 무엇을 할 수 있게 됐나»를 한 줄로 적습니다
   -> 코드 변경 목록이 아니라 «여정의 어디까지 왔나»
④ 이 문서가 페이즈의 정본입니다. 걸음이 끝나면 여기에 «착지 표시»를 합니다
```
