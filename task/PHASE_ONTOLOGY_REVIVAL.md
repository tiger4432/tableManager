## 🔴🔴 전략 (소유자 2026-09-04 19:2x) — **체인이 «원장의 준비 층»입니다**

> 「체인은 순위 올려. 원장 선언 쉽게하기 위해 «체인으로 테이블 변화»해서
>  «한 행 = 원자 하나» 맵핑되게 다 맞출거야」

```
어려운 선언을 «지저분한 원천 표»에 맞추는 것이 아니라
   체인이 표를 «한 행 = 원자 하나»로 «만들어» 두고, 원장은 그걸 «그대로» 읽는다
```
🔴 **이것이 `CLAUDE.md` 완성 판정의 «완성형»입니다:**
```
「임의의 스키마에서 «두 줄»로 선언법을 말할 수 있어야 개발한 것」
   -> 한 행 = 원자 하나면, 선언이 «정말로» 두 줄이 됩니다
상설 「표에 원천 데이터 넣고, 그걸로 원장」
   -> 그 「표」를 «체인이 만든다»는 것이 이 전략입니다
```

### 그래서 «녹아 없어지는» 문제들
```
키 조립 불가 (A-6)      mat_id = lot+slot -> «체인이 그 컬럼을 만들어» 둡니다
                      (오늘 아침 총괄 답 「표에 컬럼을 하나 두십시오」가 이 전략의 한 조각이었습니다)
시간 컬럼 거절 (A-3)    체인이 채운 표는 그 컬럼이 «있습니다»
선언이 길어짐           원천의 지저분함을 선언이 «흡수하지 않습니다»
```

### 🔴 그래서 «순위가 바뀝니다»
```
전   체인 결함 = 운영 사고 (온톨로지와 «별개»)
후   체인 결함 = «온톨로지 결함» — 준비 층이 안 돌면 원장에 넣을 표가 «안 만들어집니다»
=> 체인의 신뢰성·가시성이 이 페이즈의 «안»으로 들어옵니다
```


⚠️ 이 박스에서 되는 것은 완성이 아닙니다. **운영자가 그 두 줄을 할 수 있어야** 완성입니다.
