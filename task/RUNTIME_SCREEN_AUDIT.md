## 2. 🔴 발견 ① — 같은 401 에 탭 일곱이 «네 가지»로 답합니다

토큰 없이 어드민을 열면 `/admin/**` 이 «전부» 401 입니다(네트워크 실측). 그 «한 조건»에 대해:

| 탭 | 401 을 이름 대나 | 화면이 실제로 말하는 것 |
|---|---|---|
| Overview | ✅ | 「대기열 조회 실패 (HTTP 401). **수를 그리지 않습니다.**」 ← 사유 + 세 상태 규율 |
| Tables | ✅ | 「표 등록 조회 실패 (HTTP 401).」 |
| Ontology Explorer | ✅ | 「요청 실패 (401)」 ×2 **그리고** 「선언 · 0개 / 표시할 정의가 없습니다.」 |
| Chain | 🔴 **거짓** | **「No active chained ingestion rules found」** — `/admin/chain/rules → 401` 인데 「규칙이 «없다»」고 말합니다 |
| File Ingestion | ❌ | 표 머리글만. 사유 «없음» |
| Auto Update | ❌ | 머리글만 + 「없음」류. 사유 «없음» |
| Enrichment | — | **수가 나옵니다**(규칙 4 · 결손 1,952,799) |

```
근거   GET /admin/chain/rules      -> 401   (그런데 화면은 「규칙 없음」)
      GET /admin/auto-update/status -> 401  (화면은 머리글만)
      GET /enrichment/rules        -> 200   ← 🔵 «토큰이 필요 없습니다»
      GET /tables/<t>/data          -> 200   ← 같음
      GET /api/ledger/declaration   -> 200   ← 같음
```
🔴 **부류 ㉰ 「화면이 거짓을 말한다」의 실물입니다** — Chain 탭에서 「없어서 0」과 「못 읽어서 0」이 «같은 그림»이 됩니다.
📎 상설 「같아 보이는 다섯 개의 0」 · 「거절의 사유와 다음 행동은 남는다」.
🔵 그리고 **한 화면에 «토큰 뒤» 라우트와 «열린» 라우트가 섞여 있는데 화면은 그 차이를 말하지 않습니다** — 운영자는 Enrichment 만 「된다」고 읽고 나머지를 「고장」으로 읽습니다.

**한 줄 재현:** 토큰 없이 `admin.html` 을 열고 Chain 탭 -> 화면 문구와
`performance.getEntriesByType('resource').filter(r=>/chain\/rules/.test(r.name))` 의 상태를 나란히 보십시오.

## 3. 🔴 발견 ② — 「왜 꺼졌나」를 말하는 방식이 «넷»입니다

| 화면 | 꺼진 컨트롤 | 사유를 어디서 말하나 |
|---|---|---|
| `admin.html` · Ontology Explorer | `←` `→` | ❌ `title` 없음 (이력 네비게이션이라 «자명»할 수는 있습니다) |
| `map_editor2.html` | `me2-table-select` · `me2-col-x` · `me2-col-y` · `확정` (5 중 4는 title 없음) | ✅ **옆 문구**로 — 「규칙 선택 필요 · alignment 선언 3건 · 1건만 자동 채택」 · 「컬럼 선택 필요」 |
| `walk.html` | `날리기` | ⚠️ **간접** — 드롭다운이 「— 고르십시오 —」라고만. 버튼은 말 없음 |
| `rnd-board.html` | `걷기` | ⚠️ **간접** — 옆 패널의 「마킹 1 · 0 marked」 |

| `index.html` 나머지 셋 | `➕Row`·`🗑Row`·`📁업로드` | ✅ `title` 「뷰 — 읽기 전용」 |

같은 질문(「왜 못 누르나」)에 답하는 자리가 `title` · 옆 문구 · 다른 패널 · 없음 넷이고, 정본이 «없습니다».
🔵 정본 후보는 이미 있습니다: `index.html` 의 세 버튼이 쓰는 `title` — C-107 의 `write_guard` 가 그 «한 좌석»입니다.
