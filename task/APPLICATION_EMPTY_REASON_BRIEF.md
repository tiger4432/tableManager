# 지시서 — 빈 화면의 «사유»는 이미 API 에 있습니다. 짓지 마십시오

> 총괄 판정 `ontology_application_ruling.md` 01:1x:
> 「우리가 스팟파이어보다 «더» 주는 것 하나 — 빈 화면의 이유가 셋이라 «어느 것인지» 말해야 합니다:
>  아직 안 골랐다 / 골랐는데 그 종류가 없다 / 대조를 안 했다」
> **읽는 쪽(클라)이 오늘 밤 쓸 것입니다. 서버는 «이미 다 주고 있습니다».**

---

> 🔴 **정정 (같은 날 01:0x, 클라 배선을 열어 본 뒤).** 위 표의 첫 줄이 틀렸습니다.
> 「아직 안 골랐다」는 **서버가 답하는 것이 아니라 «클라가 스스로 아는 것»**입니다.
> ```
> 실측  client2/src/rnd_board/api.js  fetchSubgraph 가 collect 를 «항상» 보낸다
>       query.set('collect', collect || 'quantity')      -> state=not_requested 는 «안 나온다»
>       그리고 씨앗이 없으면 control_bar_panel 이 요청을 «아예 안 한다» (Promise.resolve(null))
> ```
> **그러므로 서버가 사유를 답하는 것은 «둘»(그 종류가 없다 · 대조 안 함) + 예산이고,
> 「아직 안 골랐다」는 마킹 저장소가 비었는지로 클라가 «혼자» 판정합니다.**
> `not_requested` 를 화면 상태로 배선하면 «영원히 안 오는 값»을 기다리게 됩니다.

## 세 사유 → 실제 필드 — 전부 «불러서» 확인했습니다

응답의 `propagation` 블록에 있습니다. 새로 만들 것 없습니다.

```
사유                      state              contrast      실측
────────────────────────────────────────────────────────────────────────────
아직 안 골랐다             not_requested      unexamined    collect 안 넘김
골랐는데 그 종류가 없다     empty              unexamined    collect="action" → 닿는 게 0
대조를 안 했다             ranked             unexamined    양수 씨앗만
답이 있다 (대조까지)        ranked             contrasted    음수 씨앗 넘김 → ranked 90
```

🔴 **`state` 와 `contrast` 는 «다른 축»입니다.** `ranked` 인데 `unexamined` 인 것이 정상 상태이고,
그게 곧 「대조를 안 했다」입니다. 하나로 합치지 마십시오.

📎 **`empty` 는 사유 문장을 «이미 한국어로» 들고 옵니다** — 지어내지 말고 그대로 쓰십시오:
```
message: "이 걷기가 action 노드에 닿지 않았습니다"
```

## 🔴 사유는 셋이 아니라 «넷»입니다 — 예산

```
complete: false   걷기가 «예산에 잘려서» 멈춤 → 「없다」가 아니라 «미검사»
```
서버 주석이 그렇게 못 박아 두었습니다: 「예산이 걷기를 잘라 못 본 후보는 ABSENT 가 아니라 UNEXAMINED」.

## ⚠️ 그런데 `complete` «만» 보면 틀립니다 — 실측

```
씨앗                 hops   노드   complete   truncated.reason
──────────────────────────────────────────────────────────────
BW-001 (3노드짜리)     2      3     false      depth      ← 더 볼 게 «없는데» false
BW-001                12     3     true       (없음)
WaferLeg              2     12     false      depth
WaferLeg              12    34     true       (없음)     ← 홉 6에서 포화, 12에서 완주
CW-HBM-B-03           12   400     false      nodes      ← 이게 «진짜» 미검사
```

🔴 **`reason: "depth"` 는 「홉을 적게 줬다」는 뜻이지 「더 있다」가 아닙니다.**
`complete=false` 를 그대로 「미검사」로 그리면 **낮은 홉에서 항상 미검사**가 됩니다.

```
읽는 규칙   complete=true            → 다 봤다
            reason="nodes"/"edges"   → 🔴 «미검사». 「없다」로 그리지 말 것
            reason="depth"           → 홉을 늘리면 더 나올 수 있다.  「홉 N 까지」로 표기
```

## 화면 문구 — 짧게. 전체 문장 금지

```
아직 안 골랐다        「선택 없음」
그 종류가 없다        「이 걷기에 <종류> 없음」        (message 그대로 써도 됨)
대조를 안 했다        「대조 없음」                    ← 0 이 아니라 «미검사»라는 뜻
예산에 잘렸다         「미검사 — 노드 상한」
홉이 짧다            「홉 N 까지」
답이 있음            「N marked」
```

---

## ⛔ 하지 말 것

```
✗ 사유를 «지어내기»              전부 응답에 있다. state · contrast · complete · truncated.reason
✗ 넷을 하나로 합치기              「빈 화면」 한 문구로 접으면 이 라운드의 요구가 사라진다
✗ complete=false 를 미검사로       reason 을 봐야 한다.  depth 는 미검사가 아니다
✗ 0 이나 「없음」으로 채우기        판정에 이미 있음 — 이 화면이 금지하는 «유일한» 것
✗ 회색으로 지우기                  보이되 못 고르고, 옆에 사유 (기존 상설)
```

## 안 잰 것

```
1  hops 기본값이 화면에서 몇인지    클라 쪽이라 안 봤다. 「홉 N 까지」의 N 이 그 값이다
2  edges/claims/actions 상한 절단   reason 에 그 값들이 있는 건 봤지만 «띄워 보진» 않았다
```
