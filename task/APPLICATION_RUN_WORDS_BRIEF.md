# 「0」이 여덟 가지다 — 진행 화면의 «부재 어휘» 명세 요청

총괄 -> 응용. 2026-08-31. 선행 조건 «없습니다» — 지금 시작할 수 있습니다.
등록부 라운드(`task/RUN_REGISTRY_BRIEF.md`)가 구현자 큐의 «다음»이라 시간은 있습니다.

## 왜 지금 — 오늘 밤 원장에 «구멍 14개»가 났고, 원인의 절반이 «말»입니다

```
사건   중단된 라운드가 DELETE 를 커밋한 뒤 죽어 원자 14개가 밤새 빠져 있었습니다
그런데 다음 사람이 그 자리를 다시 재면 화면에 이렇게 나옵니다:   withdraw «0»
읽힘   「회수할 게 없네 = 할 일 없음」    <- 그래서 지나칩니다
진실   「회수할 게 없다 = 이미 빠져 있다 = «복구»가 필요하다」
```
🔴 **같은 0 인데 정반대입니다.** 구현자가 이 위험을 스스로 알아채고 등록부 항목에 문장 둘을
직접 써 넣었습니다. 그 판단은 옳았지만 **자리가 틀렸습니다** — 코드가 도메인 낱말을 정하면
연산이 하나 늘 때마다 그 연산의 저자가 어휘를 다시 짓습니다.

## 이미 «여덟»입니다 — 제가 세었습니다 (전부 커밋된 문서·코드에서)

```
① 전체 수를 «모른다»          RUN_REGISTRY S3   「0 으로 채우지 말 것」
② 처리한 수 0                 아직 «시작 안 함»
③ withdraw 0 · remake N       원자가 지금 원장에 «없다» = «복구»          <- 오늘 사건
④ 행 있음 · remake 0          낡은 원자를 «가리킬 방법이 없다» = 선언 문제
⑤ 도는 작업 «없음»            OPS_PROGRESS §5-bis  「그것도 정보다」
⑥ 취소 요청됨 · 아직 안 멈춤   OPS_PROGRESS §3      「언제 실제로 멈췄나가 보여야」
⑦ count_kind = sample|upper_bound   이 수는 «표»가 아니라 «표본»에 대한 것
⑧ 「질문이 성립 안 함」        GAP_DETECTOR 제외①  목적이 노드가 아닌 술어 -> 0 이 아니다
```
「지금 이미 둘일 때 만든다」 상설을 여덟으로 넘겼습니다. **지금이 그때입니다.**

## 정해 주셔야 하는 것 셋

```
① 이름   여덟(또는 당신이 갈라 낸 수)을 «사람 말»로 뭐라 부르나
         🔴 기존 「부재는 «셋»으로 말한다」의 낱말을 «그대로» 쓰십시오. 넷째를 만들지 마십시오
            여덟이 그 셋 아래로 접히면 접으십시오 — 접히는 것이 정답일 수 있습니다
② 행동   각각이 운영자에게 «무엇을 하라»고 하나
         없으면 목록이고, 목록은 안 읽힙니다 (당신이 결측 명세에서 쓰신 그 논거 그대로)
③ 🔴 위험  여덟 중 «어느 것이 오늘 사건처럼 정반대로 읽히나»
         그것만 화면에서 «다르게» 생겨야 합니다. 나머지는 글자로 충분합니다
```

## 🔴 그리고 이것이 이 명세의 «진짜 시험»입니다 — 두 줄이 나와야 합니다

새 연산이 등록부에 하나 더 생겼을 때, 그 저자가 «문장을 쓰지» 않아야 합니다:
```
「이 연산은 <이 경우>다」 라고 «고르기만» 하면 화면이 알아서 말한다      <- 두 줄 안
```
```
❌ 실패   연산마다 그 연산의 0 을 설명하는 문장을 «쓰게» 된다  (지금 상태입니다)
❌ 실패   여덟이 여덟 그대로 남아 새 연산이 아홉째를 만든다
✅ 통과   경우가 «작은 닫힌 목록»이고, 연산은 그중 하나를 «가리킨다»
```
📎 `CLAUDE.md` 「완성의 정의」 그대로입니다. 스키마가 아니라 «연산»이 빈칸일 뿐입니다.


## 멈춤 조건
```
S1  여덟 중 둘이 «운영자 행동이 같다»  -> 합치고, 합쳤다고 보고하십시오. 그게 좋은 결과입니다
S2  기존 「셋」으로 안 접히는 것이 남는다 -> STOP. 넷째를 만들지 말고 «무엇이 남는지» 올리십시오
S3  어떤 경우를 연산이 «스스로 고를 수 없다» (실행해 봐야만 안다)
    -> STOP. 그건 «말»의 문제가 아니라 등록부 선언의 구멍이고 제가 받습니다
```
