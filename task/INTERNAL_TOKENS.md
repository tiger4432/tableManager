# 내부 토큰 -> 사람이 읽는 것 — 대응표

총괄 지시(`task/MARKING_CONTRACT.md` 「다음 = 「이게 왜 도는지」의 명세」)에 대한 응용 산출물.
소유자: 「retroactive 문구는 «반드시» 제거. 이게 대체 왜 도는지 알 수 있게. «어느 소스»에서
«무슨 트리거» 땜에 도는지 명시」 · 「`__retroacitve__` 이딴 표기 절대금지」

**근거는 커밋된 HEAD 뿐입니다.** 「표면」은 CLAUDE.md 정의를 씁니다 — 사람이 «고르고 찍는
자리»이지 응답의 배관 칸이 아닙니다.

---

# 🔴 대응표

## ① `__retroactive__` — 실행 «하나»가 자기가 무엇에 대한 것인지 못 말합니다
```
지금    소급 실행을 큐에 넣을 때, 큐 행의 «표 이름» 칸에 이 글자가 들어갑니다
왜      그 큐 행은 표 하나에 대한 것이 아닙니다. 그 칸이 비면 안 되니까 놓은 «자리표»입니다
문제    자리표인데 «표 이름처럼» 읽힙니다. 그리고 실행이 무엇에 걸렸는지는 «다른 칸»에 있습니다
```
```
바꿀 것   «표시»입니다. 상수가 아닙니다
         🔴 그 상수는 «판정하는 자리»가 있습니다 — 큐를 읽는 쪽이 이 값으로 「데이터가 아니다」를
            가릅니다. 지우면 제어 이벤트가 데이터로 읽힙니다. ⛔ 지우자고 하지 않습니다
사람이 읽을 것  그 자리에 «실행이 무엇에 걸렸는지»를 놓습니다 — 아래 ③의 형식
```

## ② `admin` — 사람 이름 자리에 «기본값»이 들어갑니다
```
지금    실행을 걸 때 요청자를 안 주면 이 글자가 «기록»됩니다 (큐 payload 와 실행 행 «양쪽»)
문제    사람 이름처럼 읽히는데 사람이 아닙니다. 「누가 걸었나」에 답한 척합니다
사람이 읽을 것  🔴 «누가 걸었는지 모른다»를 그렇게 말합니다.
              값을 지어내지 않는 것이 이 도구의 규율입니다 (「없음」은 답입니다)
```

## ③ 「왜 도는지」 — 재료가 «표에는 있고 창구에서 빠집니다»
🔴 **이게 이 명세의 핵심이고, 지어낼 것이 «하나도» 없습니다.**
```
표에 있는 것   실행 id · 연산 · «인자» · «요청자» · 상태 · «큐에 들어간 시각» ·
              시작·마지막진행·끝난 시각 · 처리 행수 · 전체 행수 · 결과 · 오류
화면에 가는 것  실행 id · 연산 · 상태 · 움직임 · 무진행 초 · 멈춤판정 초 ·
              처리 행수 · 전체 행수 · 취소가 닿는 시점 · 복구 문장
🔴 빠진 것     «인자» · «요청자» · «큐에 들어간 시각»  <- 「왜 도는지」의 재료가 정확히 이 셋입니다
```

### 형식 — 예시가 아니라 «형식»입니다
```
「<요청자> 가 <큐에 들어간 시각> 에 <연산 이름> 을 <인자> 에 걸었습니다」
```
```
<요청자>        실행 행의 요청자. 없으면 「모름」 (위 ②)
<큐 시각>       실행 행의 큐 시각
<연산 이름>     연산 등록부가 «이미» 사람 말로 들고 있습니다 — 화면이 목록에서 쓰는 그 이름
              ⛔ 연산의 «코드 이름»을 쓰지 마십시오. 그건 경로 조각입니다
<인자>          아래 ④의 규칙
```

## ④ 인자를 «그대로» 보여 주는 규칙 — 연산마다 다르기 때문입니다
```
① 키는 «선언된 그대로». 연산 등록부가 인자마다 키와 «도움말»을 이미 들고 있습니다
② 순서도 «선언 순서». 연산이 정한 순서가 그 연산의 문법입니다
③ 🔴 값이 운영 데이터를 담을 수 있으면 «키와 값의 «이름»만». 값 자체를 늘어놓지 않습니다
   -> 「<키>: <n>개」처럼 «세어서» 말합니다. 무엇이 걸렸는지는 알 수 있고 내용은 안 나갑니다
④ 인자가 없으면 «없다»고 씁니다. 빈칸으로 두지 않습니다
```
⚠️ 문구를 «길게» 만들지 않습니다 — 오늘 상설대로 화면은 보여 주고 설명하지 않습니다.
위 형식은 «한 줄»이고, 인자는 그 옆의 «값»입니다.

## ⑤ 자동으로 거는 자리 — **«없습니다». 재서 적습니다**
```
잰 것    실행을 큐에 넣는 함수의 «호출자 수»
결과    «하나» — 사람이 누르는 라우트뿐입니다
=> 「사람이 눌렀다」가 «완전한 답»입니다. 트리거를 «지어낼» 필요가 없습니다
⚠️ 큐를 «읽어서 돌리는» 쪽은 따로 있습니다. 그건 「누가 걸었나」가 아니라 「누가 실행했나」이고
   지금 물음은 앞의 것입니다
```

# 근거 — 어떻게 쟀나

## 「표면에 닿는 토큰」을 전수로 찾은 방법
```
① 서버 전체에서 «밑줄 두 개로 감싼» 문자열 상수를 훑고, 언어 자체의 것을 뺐습니다
② 각각이 «응답으로 나가나»를 봤습니다 — 라우트가 도는 파일에 그 글자가 있나
③ 그리고 «값으로» 나가는 것을 따로 봤습니다.
   🔴 여기가 중요합니다: 토큰은 «코드»가 아니라 «데이터»로 화면에 갑니다.
      화면 소스에서 그 글자를 찾으면 «영원히 0» 입니다 — 실행 때 값으로 도착하니까요
```

## 그렇게 갈린 넷
```
🔴 표면에 닿는다 (출력)   `__retroactive__` — 큐 행의 표 이름 칸
                        `admin`          — 요청자의 기본값
✅ 표면이지만 «입력»       파일 이름에 적는 강제 재적재 토큰.
                        운영자가 «직접 쓰는» 것이고 안내 문구가 이미 붙어 있습니다
                        -> 바꾸는 대상이 «아닙니다»
✅ 표면에 안 닿는다        도우미 안에서만 소비되는 자리표 · 선언 출처를 담는 내부 칸 ·
                        물리 카탈로그 자리표. 응답으로 나가는 것을 «못 찾았습니다»
                        ⚠️ 「없다」가 아니라 「이 방법으로 못 찾았다」입니다
```

## 앞서 「내부 토큰 넷」이라 적힌 것 — 다시 세었습니다
주석이 아니라 코드로 셌고, **바꿀 것은 «둘»입니다**(위 ①②). 나머지는 입력이거나 표면 밖입니다.
🔴 그리고 그 둘보다 큰 것이 **③ — 재료가 창구에서 빠지는 것**이었습니다. 토큰을 고쳐도
「왜 도는지」는 안 나옵니다. 셋을 실어야 나옵니다.

# 그래서 지시서로 넘어갈 것 — 셋
```
1  실행 목록이 «인자 · 요청자 · 큐 시각»을 함께 냅니다      -> 서버
2  큐 행의 표 이름 자리에 놓인 자리표를 «표시»에서 지웁니다   -> 화면. ⛔ 상수는 그대로
3  요청자가 없으면 «모름»으로. 이름을 지어내지 않습니다       -> 서버
```
⛔ 코드는 쓰지 않았습니다 · 도메인 낱말 없음 · 이 박스의 행 수 없음 · 라이브 선언 값 없음
📌 ⑤의 「없다」는 «세어서» 낸 답입니다 — 호출자 하나.
