# 응용 기획 — «지금 유효한 것만» (2026-08-21)

> 🔴 **이 한 장이 최신이다.** 이 세션의 문서 여섯 개에는 오늘 **열두 번의 정정**이
> 얽혀 있다. 옛 문장을 인용하지 않으려면 여기부터 읽는다.
> 근거가 필요할 때만 §9 의 안내를 따라 원문으로 간다.

---

## 1. 도착지 — 한 문장

**사람이 표시한 것에서 출발해, 원인 candidate 와 «다음에 할 일» 이 나오고,
사람은 승인만 한다.** 해석하는 단계가 없다.

## 2. 소유자가 세운 가치 넷 (정본)

    ①  스키마 제약 없는 데이터베이스
    ②  다양한 사람이 «편하게» 지식을 쌓고 그것을 통합
    ③  기존 엣지 관계가 읽는 응용에 따라 «다른 의미»로 해석
    ④  마이그레이션 free

**전제:** 「세상을 표현하는 완벽한 어휘 집합은 없다 → 계속 확장 가능해야」

## 3. 상설 규칙 둘

    무한 케이스        설계 안의 «유한한 목록» 이 실패 지점이다
    기본 원리          무한 케이스에 규칙을 다 지정할 수 없다. «생성기» 로 바꾼다

🔴 **구별법 (값을 치르고 배움):** 무한 케이스 규칙은 **「지금 이미 여럿인 것」** 이
코드에 열거돼 있을 때 건다. **「나중에 여럿이 될 것」** 에 층을 미리 만들면 그것은
무한 케이스 대응이 아니라 «미래에 대한 베팅» 이고, 소비자 0 인 축이 된다.

## 5. 알고리즘 — 현재 유효한 형태

**질문은 씨앗, 답은 전파, 액션은 전파가 닿은 노드.**

    노드    개체 · 물리량 · 액션 · 결측 · 선언
    간선    `object_kind = entity_ref` 인 원자  +  기전 엣지  +  바인딩
    씨앗    부호 있음.  + 관측됨 / − «봤는데 안 났다» / 없음 = 미검사
    방향    씨앗을 «관측» 으로 두면 occurred_at 이 기준선이 되어 자동
    산출    최상위 집합 (지배당하지 않는 것 전부) + 근거 경로 + 미계측 표시

**관문 셋은 «판정» 이 아니라 «배선» 이다** — 상류는 전도 방향, 기전은 연결의 유무,
관측 편향은 «다른 노드». 사람이 읽을 것이 없다.

### 반환(대수)이 질문을 정한다

    (ℝ, +, ×)           질량       구조적 근접도 · 기전 추적 · 액션 도달
    (2^S, ∪, ·)         이진 도달   공유 «분율»
    ([0,1], max, min)   퍼지 도달   «등급이 실린» 공유 분율
    (ℕ, +, ×)           계수       경로 «가짓수» — DAG(기전 그래프) 전용

⚠️ 이 넷은 «열거» 가 아니라 예시다. 구현은 반환을 «인자로 받는다».

## 6. 실측으로 확정된 것

    대조 = 전파의 k=1 절단      부호 정규화 씨앗 1홉 = 케이스-컨트롤 비율 차, 오차 1e-12
                              단 씨앗 쪽 첫 홉은 «차수로 나누지 않는다»
                              (나누면 차이 0 인 요인이 −0.06 이 된다)
    대조가 못 보던 넷 = k≥2     혈통 공통점 · 경로 요인 · 기전 연결 · 미계측
                              «기능 넷» 이 아니라 «고차항 하나»
    감쇠 상수는 필요 없다        활성은 «분기» 에서만 나뉜다. 홉 거리는 무관
    편차는 «비대칭» 에서만       대칭적으로 기전을 늘리면 편차가 안 는다
    슈퍼노드에서 둘이 «반대로»    질량은 거짓 신호(잔차 = m·(1/p_C − 1/p_N), 위로 전달)
                              도달은 정확히 0 (경로 구조 무관)
    순환 수렴 조건              바깥이 «멱등» 이고 안쪽이 «누적하지 않아야» 한다
                              (max,+) 는 바깥이 멱등인데도 발산한다
    경로 요인                   대수로는 불가. 방문 기록을 든 «탐색». 대부분은 원자 집계로 족함
    선언 진단이 «오늘 돈다»      원장 없이. kind 하드코딩 없이 void·delam 둘 다

## 7. 🔴 죽은 주장 — 인용하지 말 것

오늘 정정된 것들이다. 원문 문서에는 정정 표시와 함께 남아 있다.

    ✗ 「개체 타입은 config 로 못 늘린다」          v3 `entities` 에 있다
    ✗ 「개체 타입 선언 검증기가 없다」              `setup_bundle._validate_entities`
    ✗ 「세 요구가 같은 천장 하나에 막혔다」          근거 소실 (위 둘이 죽으면서)
    ✗ 「기전을 원장에 이으려면 Model 개체 타입」     구조뷰의 요구지 «전파» 의 요구가 아니다
    ✗ 「저장 단에 도메인 낱말 0건」                 1건 — 인덱스의 `lot` 키
    ✗ 「k≥2 가 넷을 다 잡는다」                    둘은 «도달», 둘은 «질량». 섞으면 순위가 틀린다
    ✗ 「멱등이면 순환에 안전」                      바깥·안쪽 «둘 다» 조건이 있다
    ✗ 「지금 바꾸면 비용 0」                       792행이 이미 쌓였다. 「나중보다 싸다」만 참
    ✗ 「관장 엣지 선언이 필요하다」                 기존 bindings 키 확장으로 족하고, 필요 미실증
    ✗ 「⑤ 죽은 선언은 별도 응용」                  ① 의 «부산물». 같은 전파가 활성 0 으로 잡는다
    ✗ 「유사도는 코사인」                          코사인은 간격을 쓴다 → «순위 상관»
    ✗ 「결측 = 기대(선언) − 실재」                  기대는 «모집단» 이 정한다. 선언하면 하드코딩
