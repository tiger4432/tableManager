# 우측 패널을 «현재 항목의 지도»로, 그리고 같은 사실을 세 번 읽지 않는다
## (소유자 판정 2026-08-21 13:1x)

> 소유자: 「우측 패널은 현재 트리구조를 다 펼쳐두고 **일종의 현재 항목의 지도?로 전환**할 수
> 있을까 어차피 후보 경로는 안 쓰는데 **그거 지우고**」
> 「**편집창도 트리 상단 에러는 없애도 될 것 같아 좌측 패널에 에러가 떠 있어서.
> 항목 열면 트리가 위에 나오게** 해 줘」
> 총괄이 「가(지도만) / 나(지도+거절 표시)」로 물음 → 소유자: **「ㅇㅇ 나 안으로 해,
> 편집창 내 에러 로그 지우고」**

---

## 🔴 도착지

```
어디가 «남았는지» 한눈에 보고, 눌러서 바로 간다.
그리고 같은 거절을 세 번 읽지 않는다
```
소유자가 앞 라운드에서 이유를 말했다 — **「충돌 해소 결과를 바로바로 보면서 셋업하고 싶음」.**
가운데 패널은 길어서 스크롤해야 보이는데, **우측 330px 안에는 전부 들어온다.**

---

## 재 놓은 사실 (총괄 실측 2026-08-21 13:0x, 라이브 화면)

### 우측 패널 `.oe-side` (330px) 가 지금 담고 있는 것
```
Reference Flow
   「현재 경로」 · SOURCE_PLAN · lot_event         ← 소스면 «항상» 한 홉. 정보량 0
Integrity
   이 정의를 사용하는 곳 · 0
   참조 검사 ✓ 직접 참조 4건 · 미해소 0건
           ✓ relation·cursor·preparer·mapper 계약이 compile됨
```
✅ **「경로 후보」는 이미 없다** — 어젯밤 지웠다. 소유자가 말한 것은 **「현재 경로」**다.

### 편집창에서 트리 «위»에 있는 것 — 203px
```
123px  .oe-editor-context   초안 상태 editing · Revision 0 · 기준 snapshot <64자 해시>
 36px  .oe-note             「자유도 0인데 문법이 요구하는 칸 10개 · 화면이 채우고 근거로 보낸다」
  +    거절이 있으면 그 목록이 여기에도 뜬다
```
**거절이 화면에 «세 번» 렌더된다** — 총괄이 `pm_walk` 를 만들며 쟀다:
고유 거절 21건이 본문 텍스트에 **62줄**로 나왔다(≈3벌).

## 무엇을 한다

```
지운다   Reference Flow(현재 경로)          한 홉짜리
지운다   편집창의 «거절 목록(로그)»          좌측 인덱스가 이미 보여 준다
남긴다   Integrity(참조 검사·미해소 건수)    진짜 정보다. 건드리지 않는다
새로     우측 = 현재 선언의 «지도»
             다 펼친 목차 · 지금 보는 행 표시 · 눌러서 그 행으로 이동
             🔴 그리고 «거절이 있는 가지에 표시»  ← 소유자가 고른 「나」
결과     항목을 열면 «트리가 맨 위»에 온다
```

### 🔴 지우는 것과 남기는 것의 «경계» — 여기서 틀리기 쉽다
```
지운다   편집창 위쪽의 «모아 놓은» 거절 목록      = 소유자가 말한 「에러 로그」
남긴다   각 «행»에 붙은 거절 표시                 = 어느 칸이 문제인지 아는 유일한 수단
```
⚠️ **행에 붙은 표시까지 지우면 폼을 못 채운다.** 오늘 아침 총괄이 소스를 만들 때 그 표시로
어느 칸이 남았는지 알았다. **모아 놓은 것만 지운다.**

⚠️ `.oe-editor-context` 의 «기준 snapshot 64자 해시»가 123px 을 쓴다. **지우라는 말은 없었다** —
줄여서 트리를 위로 올리는 선에서 처리하고, 지워야 할 것 같으면 «묻고» 지운다.

## 지도가 답해야 하는 질문 — 이것이 합격 기준이다

```
1  이 선언이 통째로 어떻게 생겼나          다 펼친 목차
2  나는 지금 어디에 있나                   현재 행 표시
3  «어디가 남았나»                         거절 있는 가지에 표시
4  거기로 어떻게 가나                      눌러서 이동
```

---

## ⛔ 멈춤 조건 — «하나»다

> **330px 안에 다 펼친 목차가 안 들어가면 → 멈추고 보고.**

`lot_event` 는 행이 38개가 넘는다. 접어서 넣는 순간 **지도가 아니라 두 번째 트리**가 되고,
그러면 이 라운드는 뜻이 없다. 폭이 문제면 그 사실을 보고할 것 — 접는 것으로 «도망가지» 말 것.

나머지는 진행하면서 재고, 숫자는 나오는 대로 한 줄씩.

## 🔴 받아들이는 시험

```
1  거절이 «있는» 새 소스를 만들고 지도를 본다
      남은 자리가 지도에 표시되는가 · 눌러서 그 행으로 가는가
2  거절 텍스트가 화면에 «몇 벌» 렌더되는가
      지금 3벌 → 좌측 인덱스 + 행에 붙은 표시. «모아 놓은 목록»은 편집창에서 사라진다
3  항목을 열면 트리가 «맨 위»에 오는가        지금은 203px 아래다
4  Integrity 가 여전히 미해소 건수를 답하는가  ← 지우지 않았다는 확인
5  거절 0 · active 까지 여전히 간다 · 편 횟수 0 유지
6  라이브 설정 회귀 없음: 거절 0 · missing 0 · 「4 layers · complete」
```
⚠️ **4번을 빼지 말 것.** 「우측을 지도로 바꾼다」를 「우측을 갈아엎는다」로 읽으면
Integrity 가 같이 사라지고, 그건 소유자가 지우라 한 것이 아니다.
