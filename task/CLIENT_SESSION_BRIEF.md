## 4. 🔴 공유 트리 규칙 — 오늘까지 이걸로 사고가 «여섯 번» 났습니다

세션 여럿이 **하나의 working tree**를 공유합니다.

```
✔  git add <경로>            경로를 «하나씩» 적는다
✔  git commit ... -- <경로>  🔴 commit 에도 경로를 붙인다
                             안 붙이면 «인덱스 전체»가 간다 — 실제 사고 있었음
✔  커밋 전 git diff --cached --name-only 로 «담길 것»을 눈으로 센다
✔  커밋 메시지에 백틱이 있으면 `-F` 파일로 (셸이 백틱을 «실행»한다)

✖  git add -a / -A / 디렉터리째
✖  git stash · git checkout -- · git reset --hard · git clean
      🔴 이것들은 «트리 전체»를 건드린다. 남의 미착지 작업이 사라진다
      빨강의 주인을 가릴 땐 git diff -- <파일> 로 «읽는다». 아무것도 안 건드린다
```

## 6. 채널 — **세션 간 메시지는 쓰지 않습니다. 파일과 커밋입니다**

> 소유자 지시: 「세션 간 메시지가 에러를 유발하는 것 같다. **지시문 커밋 기반으로** 통신 돌려」

```
총괄 → 당신    task/CLIENT_ORDERS.md            «지금 할 것»만 담긴다
당신 → 총괄    task/client_session_report.md     보고 · 질문 · 판정 요청
공통           일 시작 전 git pull → 쓴 뒤 commit + push
               🔴 커밋이 «초인종»이다. 총괄이 커밋을 감시한다
```
- **착수 전·보고 전에 `CLIENT_ORDERS.md` 를 다시 읽습니다.** 순서가 바뀌었을 수 있습니다.
- 판정 요청은 보고 파일 **맨 위**에 「🔴 판정 요청」으로 적습니다.
- ⚠️ 아직 두 파일이 없으면 **당신이 보고 파일을 만들면서 시작**하십시오.
