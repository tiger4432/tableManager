# 프로필이 소스 «안»으로 들어간다 — 소유자 판정 2026-08-20 20:2x

> 소유자: 「**근데 그럼 프로필도 소스랑 묶여야 하는거 아니야?**」 → 「**ㅇㅇ 진행**」

**오늘 준비기·매퍼가 지나온 길(`ledger_source_plan_merge_brief.md`)의 두 번째 걸음이다.
그릇은 같다 — 소스플랜.**

---

## 🔴 왜 되는가 — 코드가 이미 그렇게 말하고 있다

```
프로필 필수 셋       source · packs · mappings              setup_bundle.py:1074
profile.source       그 소스의 이름과 «같아야» 한다            setup_bundle.py:1432
                     → 한 프로필은 «정확히 한» 소스의 것이다. 공유가 «불가능»하다
컴파일 시점          source_plan 이 profiles[profile_id] 를    setup_registry.py:892
                     자기 안으로 해소한다
```

**1:1이 검증기로 강제돼 있고, 컴파일러는 이미 프로필을 소스 안에 넣어 쓴다.** 별개 절로 두는 것이
사는 것은 없다. 아침에 소유자가 프로필을 뺀 이유는 「**그릇이 될 수 없다**」였지(그릇은 `relation`을
가진 소스여야 했다) 「밖에 있어야 한다」가 아니었다. 그 이유는 흡수를 막지 않는다.

## 왜 «지금»인가 — 커서를 두 번 물지 않으려고

설정 모양이 바뀌면 `snapshot_sha256`이 움직이고 커서가 무효화된다. **커서는 이미 무효화된 상태로
소유자 판정을 기다리고 있다.** 지금 같이 하면 리셋 한 번이 둘을 덮는다. 나중에 하면 두 번 문다.

---

## 바뀌는 모양 — 새 자리를 «만들지 않는다»

```
전                                          후
sources.<id>.profile_id: "dt-job@1"             sources.<id>.profile: { packs, mappings }
profiles: { "dt-job@1": {source,packs,mappings} }   ← 절이 사라진다
                                                `source` 필드도 사라진다 —
                                                자기를 «든» 소스가 곧 그것이다
```

🔴 **프로필의 «내용»은 한 글자도 바꾸지 않는다.** `packs`·`mappings[]`(`mapping_id`·`use`·`bind`·
`sentence`)는 그대로다. 바뀌는 것은 **어디에 사는가**뿐이다.

---

## 딸려 오는 것 — 전부 «강제되는» 것이지 덤이 아니다

```
① 척추가 다섯 → 넷        「프로필」 층이 비어 없어진다
② authorable_kinds        profile 이 빠진다 → 좌측 인덱스 그룹 하나가 사라진다 (선언 16 → 14)
③ @버전                   profile@ 이 versioned 종류에서 빠진다
                          🔴 V1 설계의 «두 번째» 시험이다 — 코드 0줄이어야 한다.
                             고쳐야 하면 그 자리가 결함이니 보고할 것
④ 라이브 설정 이관         소스 2 · 프로필 2. 샘플도 같이
⑤ 스켈레톤                 profiles 절을 지우고 그 본문을 소스 아래 `profile` 로
⑥ 검증기                  _validate_profiles · unknown_profile · invalid_profile ·
                          _cross_profile_contract · _profile_binding_columns ·
                          setup_registry 의 프로필 레지스트리와 profiles[item["profile_id"]]
⑦ 삭제 로직               소스↔프로필 «상호참조»가 사라진다. 그 고리 때문에 넣어 둔
                          주석·가드가 있으면(참조 수가 0이 안 되던 자리) 같이 정리
```

### ⚠️ 착수 전에 반드시 재고 시작할 것 두 가지

```
A  프로필을 «id로» 참조하는 곳이 소스 말고 또 있는가
   grep 이 아니라 «소비자»를 세어라. 하나라도 있으면 흡수가 그것을 끊는다
B  프로필 id 의 @버전을 «읽는» 곳이 있는가
   흡수하면 버전이 사라진다. 원자에는 안 실리는 것으로 보이지만(source_translator_ver 는
   스냅샷 해시다) «보이는 것»으로 판정하지 말고 재서 확인할 것
```
**둘 중 하나라도 소비자가 있으면 멈추고 보고할 것.** 그때는 설계가 달라진다.

## 🔴 통째로 착지한다 — 조각으로 나누지 말 것

절을 지우는 변경이 반만 들어가면 라이브 설정이 어느 쪽으로도 안 읽힌다. 스켈레톤·검증기·이관·
화면·테스트가 **한 커밋**이다. 오늘 이미 한 번 이 규율로 착지했다.

**착지 전 확인 (화면으로):**
```
1. dt_job 을 열면 프로필 본문이 «그 안에» 트리로 뜬다 (packs · mappings)
2. 좌측 인덱스에 Profiles 그룹이 «없다» · 선언 14개
3. 척추가 네 층이고 라벨이 맞다
4. versioned 에서 profile@ 이 코드 0줄로 빠진다
5. 🔴 소스 하나를 «폼만으로» 새로 만들어 저장 → 거절 0        ← 이번 라운드의 «목표»
6. lot_event 배치 프리뷰의 원자 수가 흡수 «전»과 같다 (696 · incomplete 0 · DB 쓰기 0)
7. 소스 하나를 지울 때 삭제 미리보기가 여전히 옳게 답한다
```

🔴 **5번이 이 라운드의 목표다.** 오늘 6번이 못 넘어간 이유가 정확히 이것이었다 — 새 소스가
자기를 가리키는 프로필을 «따로» 만들어야 했고, 남은 거절 둘이 `profile_id`였다.
**흡수하면 소스를 만드는 것이 한 번의 행위가 된다.** 5번이 안 되면 이 라운드는 목표에 못 닿은 것이다.

⚠️ **6번을 빼지 말 것.** 프로필은 매퍼가 낸 역할이 «어느 주장의 어느 자리»로 가는지를 정한다.
자리를 옮기다 그 결선이 끊기면 원자 수가 조용히 달라진다. 숫자로 못 박는다.

## 🔴 소유자 추가 지시 — 「컨피그 모양도 바꾸고 마이그레이션 코드를 주는 게 어때」 (2026-08-20 21:1x)

**같이 간다. 이 라운드 안이다.**

### 왜 — 버전만 올리면 「거절」로 끝난다

`setup_version`은 코드 주석이 **「문법 세대를 말하는 필드」**라고 적어 둔 자리다. 오늘 문법이
두 번 바뀌었는데 숫자는 3에 서 있다. 그래서 지금은 옛 파일이 이렇게 거절된다:

```
나오는 것       bundle.source_preparers: field is not allowed
나와야 할 것    unsupported_setup_version
```

**틀린 자리를 가리키는 거절문이다.** 운영에서 옛 백업을 되돌린 사람은 여기서 한참 헤맨다.
그리고 버전만 올리면 **거절이 정확해질 뿐 길이 생기지는 않는다.** 소유자가 요구한 것은 길이다.

### 무엇을 만드나 — 스크립트 하나

```
server/scripts/migrate_ledger_config.py     (경로는 기존 관례를 따른다)

입력   ledger_config.json  (setup_version 3, 절 구성이 «어떤 세대든»)
출력   같은 자리에 새 모양으로 쓴다. 쓰기 «전»에 backup/ 에 사본 — 삭제 경로가 이미 쓰는 관례 그대로
```

**하는 일은 셋뿐이다:**
```
① source_preparers · mappers 가 있으면  → 참조하는 소스의 driver.preparation · driver.mapper 로 본문을 옮기고 절을 지운다
② profiles 가 있으면                    → 참조하는 소스의 profile 로 옮기고, profile.source 필드를 버린다
③ setup_version 을 4 로 올린다
```

🔴 **세대별로 «독립»이어야 한다.** 소유자 라이브 설정은 ①이 이미 손으로 끝나 있고 ②만 남았다.
①이 없으면 건너뛰고 ②만 한다. **이미 새 모양인 파일에 돌리면 「할 것 없음」이라 말하고 끝난다(멱등).**

🔴 **애매하면 «추측하지 말고 멈춘다».** 어떤 준비기·매퍼·프로필을 가리키는 소스가 **0개거나 2개 이상**이면
그 이름을 대고 거절한다. 1:1이 아니면 흡수의 전제가 깨진 것이고, 그건 사람이 볼 일이다.

### 🔴 받아들이는 시험 — 손으로 한 이관과 «같은 것»을 내야 한다

```
git show <병합 전 커밋>:server/config/sample/ontology/transfer_explorer/ledger_config.json
  → 임시 파일로 꺼내 스크립트를 돌린다
  → 지금 트리의 «손으로 이관된» 샘플과 diff 가 «0» 이어야 한다   (setup_version 줄 제외)
```
**diff 가 0이 아니면 둘 중 하나가 틀린 것이다.** 어느 쪽인지 대고 보고할 것 —
스크립트를 손 이관에 맞추는 것도, 손 이관을 스크립트에 맞추는 것도 «판정»이지 정리가 아니다.
