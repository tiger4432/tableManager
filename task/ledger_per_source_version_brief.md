# 커서 지문을 «소스별»로 — 소유자 판정 2026-08-20 22:3x

> 총괄이 두 길을 올림(① 재스탬프 · ② 소스별 지문) → 소유자: 「**2번**」

---

## 🔴 왜 — 지금은 남의 선언이 내 커서를 막는다 (실측)

```
① snapshot_sha256 은 «하나»고 전역이다 — registries 가 모든 절을 덮고 bundle_sha256 까지 재료
② 모든 소스가 «같은» 그 값을 커서에 넣고 대조한다   backfill.py: ledger-v2:<전역해시>
③ 관측: 탐침 소스 추가·저장 dbe731ba → cbaef075 · 삭제 cbaef075 → dbe731ba
        «정확히 되돌아왔다» — 동시 편집이었다면 원래 값으로 복귀하지 않는다
```

**그래서 `lot_event` 의 프로필을 고치면 `dt_job` 의 커서까지 막힌다.** 그리고 운영 원장은
**수백만 행**이라 리플레이는 답이 아니다 — 같은 사실이 새 지문을 달고 수백만 행 더 쌓인다.

**코드가 스스로 적어 둔 원칙이 이미 답이다** (`setup_registry.py:617`):
「해시는 **원자를 바꿀 수 있는 것만** 덮는다」. 지금 지문은 **남의 선언까지** 덮는다.
이 라운드는 그 원칙을 «소스 단위»에서 지키게 하는 것이다.

---

## 도착지

```
커서가 비교하는 값 = 그 소스에 «실제로 닿는 재료»의 지문
→ 남의 선언을 고쳐도 내 커서가 «안» 막힌다
→ 그리고 사람이 「영향 없음」을 판단할 일이 없어진다 — 시스템이 안다
```

### 🔴 「닿는 재료」의 «전이 폐포» — 이게 설계의 전부다

```
그 소스의 source_plan 전체        relation · driver(read·preparation·mapper) · profile
그 profile 이 참조하는 packs
그 packs 의 claims 가 참조하는     predicates (vocabulary)
그 claims·binds 가 참조하는        entities
+ compiler_contract_version · setup_version      문법 세대가 바뀌면 모두 바뀌는 게 맞다
```
**`bundle_sha256` 은 재료에서 «빠진다».** 그것이 전역성의 정체다.

⚠️ **폐포를 «자기 것»으로 좁히지 말 것.** 공유 술어(`register@1`은 오늘 두 팩이 쓴다)를 고치면
**그것을 쓰는 소스가 «전부» 움직여야 맞다.** 좁히면 조용히 안 막히고, 그게 더 나쁘다.

✅ **오늘의 흡수가 이걸 쉽게 만들었다.** 준비기·매퍼·프로필이 소스 «안»에 있으므로
그 본문이 자동으로 폐포에 들어온다. 구현자가 잡았던 「`preparer_id`가 `source_event_id`로
샌다」는 함정도 **같이 사라진다** — 그 준비기가 이제 그 소스의 재료이기 때문이다.

## 옮기는 장치 — «읽지 않는다»가 안전의 핵심

```
저장된 커서    옛 전역 지문 → 새 소스별 지문으로 «한 번 재스탬프». 재읽기 «없음»
이미 쌓인 원자  건드리지 «않는다». 과거는 과거의 지문으로 남는다
               (소유자 원칙: 원장은 append 다. 갈아치우지 않는다)
```

🔴 **재읽기를 안 하는 것이 중복을 막는다.** `source_translator_ver` 가 `uq_ledger_atom` 의
재료라(`schema.py:60`) 새 지문으로 «다시 읽으면» 옛 원자와 중복 판정이 안 되어 수백만 행이
겹쳐 쌓인다. **커서 위치는 그대로 두고 지문만 바꾼다.**

⚠️ **원자의 `setup_snapshot_hash` 는 그대로 둔다.** 그건 「어느 «전체» 셋업이 이걸 만들었나」라는
출처이고 커서 비교와 다른 질문이다. **이 라운드에서 바뀌는 것은 「커서가 비교하는 값」 하나다.**

## 🔴 받아들이는 시험 — 판별식 셋을 «다» 봐야 한다

```
1  lot_event 의 프로필을 고친다  →  dt_job 의 지문이 «안» 움직인다      ← 이 라운드의 목표
2  dt_job  의 프로필을 고친다   →  dt_job 의 지문이 «움직인다»          ← 1만 보면 「다 안 움직임」과 구별 안 된다
3  공유 술어 register@1 을 고친다 → 그걸 쓰는 소스가 «전부» 움직인다     ← 폐포가 좁아졌는지 여기서 드러난다
4  재스탬프 후 backfill --source lot_event --max-batches 1 이 «거절 없이» 돈다
5  lot_event 배치 프리뷰 원자 696 · incomplete 0 · DB 쓰기 0            ← 뜻이 안 변했다는 숫자
```

⚠️ **1번만 초록인 것은 아무것도 증명하지 않는다.** 「모든 것이 안 움직인다」도 1번을 통과한다.
**2와 3이 판별식이다.** 오늘 이 프로젝트에서 「두 규칙이 같은 답을 내는 표본으로 쟀다」가
이미 한 번 있었다.

⚠️ **1·2·3은 라이브 설정이 아니라 «사본»으로 잰다.** 소유자 설정을 흔들지 말 것.
