# 🔨 공사7 — **마킹 «교집합» 구독자**. 저장소 옆, 부품은 안 건드립니다 (총괄 23:0x)

> 소유자: 「즉 후보 map 의 마킹 활성은 (마킹 1과 2의 교집합)」

## 왜 «부품 밖»인가
`MarkingStore` 가 이미 이름별로 들고 있고 `entries(name)` · `subscribe(name, …)` 가 있습니다.
그러니 교집합은 **저장소 위의 한 겹**이지 어느 부품의 일이 아닙니다.
```
만들 것   이름 둘을 구독해서 «교집합»을 셋째 이름에 쓰는 것 하나
          marking:1 ∩ marking:2  ->  marking:3
부품      «안 건드립니다». 후보 맵은 layout 에서 reads 를 'marking:3' 으로 바꾸면 끝
부호      🔴 부호(+/−)가 다르면 «교집합이 아닙니다». 같은 노드에 한쪽이 +, 한쪽이 −면
          그건 「같이 가리켰다」가 아니라 «모순»입니다. 어떻게 다룰지 정해서 «명시»하십시오
          (제 판단: 부호까지 같아야 교집합. 다르면 «따로» 셀 수 있게 남길 것)
```
🔴 **이름을 «박지» 마십시오** — (읽을 이름 둘, 쓸 이름 하나)를 «받는» 것이어야 합니다.
   마킹이 넷·다섯이 되는 날 코드가 안 바뀌어야 합니다. 그게 이 저장소의 규칙입니다.

📎 이 연산이 «두 곳에서 같은 것»입니다 — 걷기의 「여러 씨앗이 동시에 닿은 것」도 교집합입니다
   (`∩ parents[씨앗]`). 지금 만드는 것이 나중에 그쪽 모양의 본보기가 됩니다.

수락: 이름 «셋째»를 추가하는 데 코드 0줄 · 부품 파일 0줄 · 변이로 깨울 것
      (교집합을 합집합으로 바꾸면 빨강 · 부호 무시하면 빨강)

**더 «구체적인» 규칙이 이깁니다** — 그게 이 화면이 하려는 일(사람이 값을 고른다)에 더 가깝고,
