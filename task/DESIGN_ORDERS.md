## 🔴 그런데 lot_map 은 «질의»만이 아니었습니다 — 같이 사라지는 것 «여섯»
버리는 건 결정됐고, 이 여섯이 walk 으로 «안 옮겨지면» 맵은 빈 채로 남습니다.
**하나씩 «어디로 가는지» 정하고 버립니다. 조용히 사라지면 안 됩니다.**
```
① 프레임        frame.grid = { grid_cols · grid_rows · grid_start_x/y · grid_y_invert
                              · rotation · side · phys_chip_x/y · phys_offset_x/y

② 유효 다이     valid_die_ref { table, map_id }  — 「이 자리가 애초에 칩이 있는 자리인가」
③ 칸의 상태     cell.state = found | scanned | unscanned
                🔴 «unscanned» 가 제일 중요합니다. 0 이 아니라 «안 봤다»입니다
④ 분모          scanned / found 수  — 트렌드 y 의 분모가 여기서 나옵니다
⑤ 맵 밖         unplaced { state, scanned, found, reason, message }
                🔴 검사됐는데 좌표가 없는 자리. 지어내지 않고 «수로만» 말하는 그 자리입니다
⑥ 겹침 표시     superposed · available_slots · frames_matched / frames_considered
```
🔴 **①③⑤ 는 「없음」을 «세 갈래»로 구분하는 장치입니다** — 이 제품이 다른 대시보드와
다른 이유가 그것입니다. walk 이 이걸 못 실으면 「버렸다」가 아니라 «퇴보»입니다.

⚠️ **1 을 건너뛰고 2 를 하면 맵 셋이 빕니다.** 지금 walk 이 닿는 좌표 노드는

## 🔴 이 그림이 «말하고 있는 것» 셋 — 이걸 놓치면 그려도 틀립니다

### ⓐ 맵과 트렌드는 «같은 collect» 입니다. 시작점만 다릅니다
```
① 기본 트렌드   Start each groupby     · Collect trend Y value
⑤ 맵           Start specific groupby · Collect trend Y value   <- «똑같습니다»
```
**맵은 다른 데이터가 아니라 «한 그룹으로 좁힌 같은 데이터»입니다.**
그래서 부품마다 데이터를 다르게 가져오면 안 됩니다 — 🔴 **walk 함수는 «한 벌»입니다.**
소유자 상설 ①(근원 템플릿 + 데이터 갈아끼우기)이 여기 그대로 적용됩니다:
```
템플릿   walk 호출 «하나»            walk({ start, collect })
선언     부품마다 { start, collect } «값»만 다름
시험     같은 화면에 트렌드와 맵을 «서로 다른 선언»으로 앉혀 간섭 없음
```

### ⓑ 마킹이 «둘» 이고 각자 다음 walk의 «시작점»입니다
```
마킹 1   기본 트렌드에서 찍음  ->  ③④⑤ 의 start
마킹 2   후보에서 찍음        ->  ⑦   의 start
```
이미 만드신 marking_store 의 「이름 붙은 마킹 여럿」이 «이걸 위한» 구조입니다. 그대로 씁니다.

### ⓒ 「일단 wafer 로 고정」 — 🔴 groupby 를 «설정 축»으로 만들지 마십시오
소유자가 「일단」이라 쓰셨습니다. **지금은 wafer 하나입니다.**
나중에 여럿일 «것 같아서» 축을 만드는 건 이 지시가 아닙니다 (관문 ②③).
값 하나를 그냥 `'wafer'` 로 두고, 바꿀 일이 생기면 그때 «둘»이 됩니다.

## 할 것 — 순서대로
```
1  walk 함수 «한 벌»을 세우십시오. 입력은 { start, collect } 둘뿐입니다
2  기존 부품들의 데이터 취득을 그 함수 «호출 하나»로 바꾸십시오
   -> 지금 api.js 는 fetchLotMap · fetchComposition · fetchSubgraph · fetchTrends · fetchSiblings
      «다섯 갈래»입니다. 도식에는 그런 갈래가 «없습니다»
3  부품마다 { start, collect } 선언을 «레이아웃 항목 옆»에 두십시오 (지금 reads/writes 옆)
4  ⑦ 이 «둘»(후보 트렌드 · 후보 맵)을 먹입니다 — 같은 walk 결과를 «두 부품»이 씁니다.
   두 번 부르지 마십시오
```

## 🔴 지우지 마십시오 — 앞선 판정 그대로입니다
```
lot_map 경로는 «살아 있어야» 합니다. collect 가 그림을 «낼 때» 옛 경로를 뺍니다
지금 원장에 좌표를 «주어로» 가진 원자는 die transfer «1,405개»뿐입니다
보이드·본딩은 총괄이 «v5 선언»으로 여는 중입니다 — 열리면 알리겠습니다
```
즉 **당신은 배선을 먼저 깔고, 재료는 제가 넣습니다.** 재료가 없다고 배선을 미루지 마십시오 —
walk 이 «빈 결과»를 주면 부품은 「없음」을 정직하게 그리면 됩니다. 그게 이미 있는 계약입니다.

## 완료의 정의
```
· api.js 에서 부품이 부르는 함수가 «하나»입니다
· 트렌드와 맵이 «같은 collect 선언»으로 서고, 시작점만 다릅니다
· 마킹 1 을 바꾸면 ③④⑤ 가 «같이» 바뀝니다
· 마킹 2 를 바꾸면 후보 트렌드·후보 맵이 «같이» 바뀝니다
```

```

```
🔴 **이름을 «박지» 마십시오** — (읽을 이름 둘, 쓸 이름 하나)를 «받는» 것이어야 합니다.

   (`∩ parents[씨앗]`). 지금 만드는 것이 나중에 그쪽 모양의 본보기가 됩니다.

수락: 이름 «셋째»를 추가하는 데 코드 0줄 · 부품 파일 0줄 · 변이로 깨울 것
