# 결측의 «말» — 명세 (응용 → 총괄, 2026-08-30 밤)

요청: `task/APPLICATION_GAP_SPEC_BRIEF.md`. 넷(① 이름 ② 두 방향 ③ 행동 ④ 제외)에 답합니다.
**구현 없음 · 새 술어 제안 없음.** 인용한 선언은 저장소의 `.sample`(모양의 증거)입니다.

## 0. 🔴 먼저 — 「두 방향」의 자리를 정정합니다. 한 술어의 두 «쪽»이 아닙니다

지시서의 기작은 술어마다 «주어쪽·목적쪽»을 냅니다. 그런데 지시서가 든 예시는 그 두 쪽이 아닙니다:

```
관측된 종류   of_kind@1  의 «목적»   -> defect_kind@1
모델된 종류   leads_to@1 의 «목적»   -> defect_kind@1
차이 «1»     한 술어의 두 쪽이 아니라, «같은 타입에 들어오는 두 술어»의 집합 차이입니다
```

**그래서 일반형은 이렇습니다 — 축을 더하지 않고, 도메인 낱말도 안 씁니다:**
```
한 타입 T 에 들어오는 술어가 «둘 이상»이면
   각 술어가 T 에서 «닿은 노드 집합»을 만들고, 그 집합들의 «차이»가 결측이다
   방향의 이름 = 「어느 술어가 그것을 가졌나」
```
선언에서 그 타입이 «넷»입니다:
```
defect_kind@1   of_kind · leads_to
quantity@1      measures · leads_to
wafer@1         has_wafer · in_container
die@1           inspected · transfer · bonded_from
```
🔴 **이것이 이 명세의 첫 산출입니다.** 「관측/모델」은 그 넷 중 «둘»(defect_kind · quantity)에서
나오는 특수형이고, 나머지 둘은 같은 기계인데 «다른 이름»이 붙습니다(아래 §2-B).
한 쌍만 보고 규칙을 적으면 나머지 둘이 이름 없이 남습니다.

## 0-bis. 결측은 상설 ⑥의 «셋» 중 하나 «안»에 삽니다 — 넷째를 만들지 않았습니다
```
아직 안 골랐다     화면 상태. 결측이 아니다
서버가 못 답한다    화면 상태. 결측이 아니다
걸었는데 없다      🔴 결측은 «전부» 여기 안에 있다
```
그리고 총괄이 이 채널에 이미 판정한 문구 규율을 그대로 씁니다:
**⛔ 「데이터 없음」·「0」으로 적지 않습니다** — 「세어 봤더니 0」과 구별이 안 됩니다.

## 1. ④ 제외가 먼저입니다 — 셋은 «기계»가 가릅니다. 도메인 판단이 필요 없습니다

지시서가 「④가 이 문서의 값어치」라 했는데, 재 보니 **제외의 대부분이 도메인이 아니라 구조**입니다.
도메인 판단이 필요한 것은 «한 부류»뿐이고 그것만 올립니다(§4).

### 제외 ① — 목적이 «노드가 아니면» 목적쪽 결측이 «정의되지 않는다»
```
has_netdie@1   목적 kind=value
register@1     목적 kind=none
=> 없어질 «노드»가 없습니다. 목적쪽은 세지 «않습니다» (0 이 아니라 «질문이 성립 안 함»)
```

### 제외 ② — 🔴 «자기 고리»의 양 끝은 결측이 아니라 «사슬의 끝»이다
```
transfer@1      die       -> die
bonded_from@1   die       -> die
derived_from@1  lot       -> lot
slot_map@1      lot_slot  -> lot_slot
leads_to@1      quantity  -> quantity (목적에 defect_kind 도 있어 «절반»만 자기 고리)
```
사슬은 «머리와 꼬리»가 항상 한쪽을 안 갖습니다. 그걸 세면 **모든 사슬이 결측 둘을 냅니다** —
화면이 그것으로 찹니다. 지시서가 경고한 「빈자리로 가득 차고 진짜가 묻힌다」가 정확히 이 자리입니다.
```
✅ 세는 것   사슬 «가운데»가 끊긴 것 (양쪽이 다 있어야 할 자리에 한쪽이 없음)
❌ 안 세는 것 사슬의 머리(출처 없음) · 꼬리(다음 없음)
```
🔴 **그리고 이 제외는 «단일 술어»에만 걸립니다 — §2-B 와 어긋나지 않습니다** (총괄 지적, 명시):
```
안 센다   한 술어 «하나»만 보고 그 끝이 비었을 때        「transfer 가 없다」 = 사슬의 꼬리
센다     같은 타입에 «다른 술어»가 그 노드를 이미 들 때   「검사는 있는데 계보가 없다」
근거     검사가 있다는 것은 그 자리의 «존재가 확인됐다»는 뜻이고,
        그러면 「그럼 어디서 왔나」를 물을 «근거»가 생깁니다. 아무도 안 든 노드에는 그 근거가 없습니다
```
그래서 §2-B 의 「출신이 끊긴 자리」는 사슬의 머리가 «아니라» 두 술어의 «차이»입니다.

⚠️ 다만 **머리·꼬리를 «세지 않는다»와 «안 보인다»는 다릅니다.** 소유자가 오늘 시킨
「웨이퍼 id 없는 종점 캐리어」가 바로 꼬리 쪽이고, 그건 §2-B3 에서 «다른 이름»으로 잡힙니다 —
결측이 아니라 «끝인데 정체를 모르는 것»입니다.

### 제외 ③ — 「없는 것이 정상인 자리」는 술어의 «뜻»이 이미 말한다
```
observed@1 주어쪽   결함이 «없는» 다이 = 양품. 이게 결측이면 좋은 웨이퍼가 통째로 일감이 됩니다
```
🔴 판별식(도메인 없이): **그 부재가 «좋은 소식»이면 결측이 아니다.**
선언에서 이 성질을 가진 것은 `observed@1` 하나입니다 — 나머지 열셋은 부재가 좋은 소식이 아닙니다.

## 2. ①② 이름과 방향 — 남은 것에만 붙입니다

### A. 「관측 ↔ 모델」 — 지시서가 든 두 방향. 타입 «둘»에서 나옵니다

| 타입 | 방향 | 이름 (사람 말) | 뜻 |
|---|---|---|---|
| `defect_kind@1` | 관측O·모델X | **기전 없는 결함 종류** | 봤는데 왜 그런지 못 댑니다 |
| `defect_kind@1` | 모델O·관측X | **아직 안 나타난 예측 종류** | 그렇다고 했는데 아직 못 봤습니다 |
| `quantity@1` | 관측O·모델X | **어디에도 안 쓰이는 계측 항목** | 재고 있는데 아무 기전에도 안 들어갑니다 |
| `quantity@1` | 모델O·관측X | **모델이 부르는데 안 재는 항목** | 기전이 이름을 대는데 계측이 없습니다 |

🔴 **넷을 한 낱말로 합치면 안 됩니다.** 할 일이 정반대입니다 —
왼쪽 둘은 «모델을 늘리는» 일이고, 오른쪽 둘은 «측정을 늘리는» 일입니다.

### B. 같은 기계, 다른 이름 — 타입 «둘»이 더 있습니다 (§0 의 산출)

| 타입 | 방향 | 이름 (사람 말) | 뜻 |
|---|---|---|---|
| `wafer@1` | 자리O·다이X | **속을 모르는 웨이퍼** | 어느 자리에 있는지는 아는데 무엇이 담겼는지 모릅니다 |
| `wafer@1` | 다이O·자리X | **어디 있는지 모르는 웨이퍼** | 무엇이 담겼는지는 아는데 어느 자리인지 모릅니다 |
| `die@1` | 계보O·검사X | **검사 기록이 없는 자리** | 어디서 왔는지는 아는데 본 적이 없습니다 |
| `die@1` | 검사O·계보X | **출신이 끊긴 자리** | 봤는데 어디서 왔는지 모릅니다 |

📌 「웨이퍼 id 없는 종점 캐리어」(소유자 지시)는 **「어디 있는지 모르는 웨이퍼」의 캐리어 쪽 짝**입니다.
   같은 끊김을 자리에서 보면 그 이름이고, 웨이퍼에서 보면 이 이름입니다.

### C. 단일 술어의 주어쪽 — 제외를 통과한 것 «셋»

| 술어 | 이름 (사람 말) | 뜻 |
|---|---|---|
| `of_kind@1` | **종류가 안 붙은 결함** | 봤다고 적혔는데 무엇인지 안 적혔습니다 |
| `processed_with@1` | **공정 이력이 없는 웨이퍼** | 무엇을 거쳤는지 안 적혔습니다 |
| `in_container@1` | **담긴 데 없는 자리** | 자리는 있는데 어느 웨이퍼의 자리인지 모릅니다 |

## 3. ③ 행동 — 「무엇을 하라」. 상설의 «답이 어디 있나» 축을 그대로 씁니다

목록만 있으면 안 읽힌다는 지시서 지적에 따라, **이름마다 «누가 무엇을»**을 답니다.
새 축을 만들지 않고 CLAUDE.md 의 Ⅰ~Ⅳ 를 씁니다.

```
기전 없는 결함 종류        Ⅳ 어휘/모델   그 종류의 기전을 «모델에 한 줄» 넣는다        엔지니어
아직 안 나타난 예측 종류    Ⅲ 세상        그 종류를 «찾는 검사»를 건다                  계측
어디에도 안 쓰이는 계측 항목  Ⅳ 어휘/모델   이 항목이 무엇에 이르는지 «모델에» 적는다 —
                                     또는 «안 재도 된다»고 판정한다                 엔지니어
모델이 부르는데 안 재는 항목  Ⅲ 세상        그 항목을 «계측 대상»에 넣는다                계측
속을 모르는 웨이퍼          Ⅱ 원천        그 자리의 «구성 기록»을 원천에서 가져온다      운영
어디 있는지 모르는 웨이퍼    Ⅱ 원천        그 웨이퍼의 «자리 기록»을 원천에서 가져온다    운영
검사 기록이 없는 자리       Ⅲ 세상        아직 «안 본» 것이라면 검사를 건다             계측
출신이 끊긴 자리           Ⅱ 원천        계보 기록을 원천에서 가져온다                 운영
종류가 안 붙은 결함        Ⅱ 원천        분류 결과를 원천에서 가져온다                 운영
공정 이력이 없는 웨이퍼     Ⅱ 원천        공정 기록을 원천에서 가져온다                 운영
담긴 데 없는 자리          Ⅱ 원천        컨테이너 기록을 원천에서 가져온다             운영
```
🔴 **Ⅰ(원장 안에 이미 있다)이 이 표에 «없습니다».** 결측은 정의상 「걸었는데 없다」이므로
Ⅰ 이면 애초에 결측이 아니라 «못 걷고 있는 것»입니다 — 그건 결측 목록이 아니라 walk 의 문제입니다.
📌 그래서 **결측 목록에 Ⅰ 이 뜨면 그건 결측이 아니라 «검출기의 결함»입니다.** 판별식으로 씁니다.

## 4. ✅ 판정 «도착» — 분류하지 않고 «나이»를 함께 냅니다 (총괄 2026-08-31 00:4x)

제가 「시간이 지나면 채워지는 부재」를 결측/진행 중으로 갈라 달라고 올렸고, 총괄이
**답 대신 질문을 없애는 쪽**으로 판정했습니다.

```
문제   「아직」이냐 「없다」냐는 «술어의 성질»이 아닙니다 —
      같은 웨이퍼가 5분 뒤엔 「아직」이고 한 달 뒤엔 「없다」입니다. 술어마다 하나로 못 정합니다
판정   검출기가 «분류하지 않습니다». 부재를 «나이와 함께» 냅니다
      예: 「계측 없음 — 첫 등장 후 34일」
      -> 사람이 봅니다. 임계값도 · 도메인 입력도 · 새 축도 «없습니다»
근거   원자에 occurred_at 이 «이미» 있습니다. 새로 만들 것이 «0»
```
✅ 그러면 아래 경계가 «그대로» 섭니다 — 차이는 «나이»이고, 그건 데이터가 답합니다:
```
진행 관리 화면   시간이 «채우는» 것 — 「아직」
결측 목록       시간이 «안 채우는» 것 — 「없다」
```
⏭ 나중에 「N일 넘으면 결측」이 필요해지면 그때 «선언 한 줄»입니다. **지금 만들지 않습니다.**
⚠️ 총괄이 이 판정을 소유자께 올렸습니다 — 공정 순서에 「반드시 며칠 안에 채워진다」는 사실이
   있으면 그때 임계값이 생기고, 그건 소유자 것입니다.

🔴 그래서 §2·§3 의 이름·행동에서 **「아직」과 「없다」를 낱말로 가르지 않습니다.**
   같은 이름에 «나이»가 붙습니다 — 그 셋(계측 없음 · 검사 없음 · 검사 기록 없는 자리)도 그렇습니다.

## 5. 이 문서가 «안» 한 것 (지시서의 ⛔ 그대로)
```
⛔ 검출을 구현하지 않았습니다 — 명세만
⛔ 술어를 새로 제안하지 않았습니다 — 선언의 열넷 위에서만 정했습니다
⛔ 이 박스의 «수»를 근거로 쓰지 않았습니다 — 인용은 `.sample` 의 «모양»뿐이고
   §0 의 「타입 넷」·§1 의 「자기 고리 다섯」은 선언 구조이지 행 수가 아닙니다
```
