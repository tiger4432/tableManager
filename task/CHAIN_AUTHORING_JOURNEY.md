# 체인 규칙 작성 여정 — 「지저분한 표」에서 「한 행 = 원자 하나」까지

총괄 지시(`task/MARKING_CONTRACT.md` 「전략의 «증명»이 아직 없습니다」)에 대한 응용 산출물.
전략 정본은 `task/PHASE_ONTOLOGY_REVIVAL.md`, 표의 «모양»은 `task/ATOM_ROW_SHAPE.md` 입니다.

```
시작   운영자에게 «지저분한 원천 표»가 있다
끝     「한 행 = 원자 하나」인 표가 «있고», 그것이 갱신되며 돈다
```

**커밋된 HEAD 로만 쟀습니다.** 걸음마다 「서버가 아나」와 「화면이 말하나」를 «따로» 적었습니다.

# 🔴 맨 앞 — 막히는 자리 «다섯»

## ① 🔴 «비대칭» — 변환은 앱에서 쓸 수 있고, 그걸 «거는 규칙»은 못 씁니다
```
변환 코드   목록 · 읽기 · «쓰기» 라우트가 «있습니다». 없는 파일도 만듭니다
           쓰기가 허용된 자리는 «둘»로 좁혀져 있습니다 — 변환 폴더와 작업 폴더
           화면도 «있습니다» (소스 «1» · 번들 «1»)
규칙       🔴 «읽기»뿐입니다. 쓰기 라우트가 «없습니다»
           화면은 목록을 읽습니다 (소스 «2» · 번들 «2») — 고치는 자리는 아닙니다
```
=> **코드는 앱 안에서 쓰는데, 그 코드를 표에 «거는» 한 줄은 앱 «밖»입니다.**
전략(「체인이 표를 만든다」)의 마지막 한 걸음이 정확히 거기서 끊깁니다.

## ② 🔴 대상 표가 «먼저» 있어야 하는데, 그걸 말해 줄 자리가 없습니다
```
사실   변환의 결과를 표에 쓸 때 «그 표의 선언»에서 키를 읽습니다.
      선언이 없으면 식별자 없이 들어가고 «조용합니다» (ATOM_ROW_SHAPE 맨 앞 ③)
오늘   표를 등록하는 라우트가 «섰습니다». 화면은 클라가 짓는 중입니다
🔴    그런데 규칙을 «쓰는 자리»가 없으니, 「그 표가 아직 없습니다」를 «말해 줄 자리»도 없습니다
```
=> ①이 열리기 전에는 ②를 고칠 자리가 «생기지 않습니다». 순서가 있습니다.

## ③ ⚠️ 변환 파일은 «그 서버에서만» 삽니다
```
사실(커밋된 주석)  변환 폴더는 저장소에서 «빠져» 있고 견본과 특정 접두어만 다시 실립니다
뜻              앱에서 쓴 변환은 «쓴 그 서버»에 있습니다. 다른 환경으로 «따라가지 않습니다»
```
⚠️ 이건 결함이 아니라 «성질»입니다 — 운영자의 코드니까요. 다만 **여정의 사실이라 적습니다**:
「내 환경에서 됐다」가 다른 환경의 답이 아닙니다.

## ④ 🔴 「이 표가 원자 행 표인가」를 «만들 때» 확인할 자리가 없습니다
```
확인이 필요한 것  바인딩할 컬럼이 «모든 행»에서 안 비었나 · 조립 키가 컬럼으로 «있나» ·
                시각이 시각으로 «읽히나»                        (ATOM_ROW_SHAPE ②)
지금            그걸 재 주는 자리는 «선언 쪽»입니다 — 소스로 «잡은 뒤에» 시험을 돌려야 압니다
=> 표를 만드는 사람은 «나중에» 압니다. 만들 때가 아니라
```

## ⑤ ⚠️ 「고친 것이 반영되나」 — 재는 것은 구현자 큐입니다
```
라우트   설정 다시 읽기 라우트가 «있습니다». 화면도 «있습니다»
🔴 그런데  「변환 파일을 고치면 실제로 «새 코드»가 도나」는 «별개»이고, 소유자가 반증을 보셨습니다
        그 측정은 구현자 큐에 있습니다 — 여기서는 «화면과 경로»만 적고 결과는 그쪽을 인용합니다
```

# 걸음 일곱 — 각각 네 칸

## 1. 「원천 표가 도구 안에 있다」
```
② 어디서   표 등록 라우트 «있음»(오늘). 전용 화면은 클라가 «짓는 중»
③ 무엇이 막나  화면이 아직이면 라우트를 직접 불러야 합니다
④ 다음이 보이나  ⚠️ 화면이 서면 보입니다
서버 ✅   화면 ⏳ (짓는 중 — 미커밋을 「있다」로 적지 않습니다)
```

## 2. 「대상 표를 «먼저» 등록한다」
```
② 어디서   같은 라우트
③ 무엇이 막나  🔴 «순서를 모릅니다». 먼저 해야 한다는 것을 말해 주는 자리가 없습니다
④ 다음이 보이나  🔴 아니오 — 안 하고 지나가면 «조용히» 식별자 없는 쓰기가 됩니다
서버 ✅   화면 ❌
```

## 3. 「변환을 쓴다」 (조립 키 컬럼 · 값 채우기 · 행 거르기)
```
② 어디서   ✅ «앱 안»입니다. 변환 폴더를 목록·읽기·쓰기 할 수 있고, 없는 파일도 만듭니다
③ 무엇이 막나  없음 — 여기는 «됩니다»
④ 다음이 보이나  ⚠️ 절반 — 쓴 다음 «어디에 거나»가 안 보입니다 (걸음 4)
서버 ✅   화면 ✅
🔴 「이미 되는데 아무도 안 쓴다」가 여기입니다 — 전략 문서 어디에도 이 자리가 안 적혀 있었습니다
```

## 4. 「규칙을 만들어 그 변환을 표에 건다」
```
② 어디서   🔴 «앱 밖». 읽기 라우트만 있고 쓰기가 없습니다
③ 무엇이 막나  규칙 파일을 서버에서 직접 고쳐야 합니다
④ 다음이 보이나  🔴 아니오 — 여정이 여기서 앱을 나갑니다
서버 ❌   화면 ❌ (목록은 보이고, 고치는 자리가 없습니다)
```

## 5. 「고친 것을 반영시킨다」
```
② 어디서   설정 다시 읽기 라우트 «있음» · 화면 «있음»
③ 무엇이 막나  ⚠️ 변환 «파일» 수정이 실제로 반영되나 — 구현자 측정 대기 (위 ⑤)
④ 다음이 보이나  ⚠️ 버튼은 보입니다. 「반영됐다」가 보이는지는 그 측정의 답입니다
서버 ✅   화면 ✅ (「반영됐나」는 별개)
```

## 6. 「돌려서 표를 채운다」
```
② 어디서   새 행은 체인이 «스스로» 집습니다. 이미 있는 행은 소급 적용으로 «다시» 겁니다
          큐 현황 화면 «있음» · 소급 화면 «있음»
③ 무엇이 막나  ⚠️ 소급을 걸 때 인자를 «타이핑»으로 받습니다 (여정 명세 걸음 6과 같은 자리)
④ 다음이 보이나  ✅ 예 — 큐와 실행 목록이 있습니다
서버 ✅   화면 ✅
```

## 7. 「이 표가 «원자 행 표»인지 확인한다」
```
② 어디서   🔴 «없습니다». 표를 보고 그 조건을 재 주는 자리가 없습니다
③ 무엇이 막나  선언 쪽에 «붙인 뒤» 시험을 돌려야 압니다
④ 다음이 보이나  🔴 아니오 — 만든 사람이 «나중에» 압니다
서버 ❌   화면 ❌
```

# 그래서 이 여정은 «어디서» 끊깁니까

```
1 원천 표 등록    ⏳ 화면 짓는 중
2 대상 표 «먼저»  🔴 순서를 말해 주는 자리 없음
3 변환 쓰기       ✅ «앱 안에서 됩니다»
4 규칙 걸기       🔴 앱 «밖»
5 반영           ⚠️ 버튼 있음 · 반영 여부는 측정 대기
6 돌리기         ✅
7 모양 확인       🔴 없음
```
🔴 **전략의 끊긴 곳은 «변환»이 아니라 «규칙»입니다.** 변환은 앱 안에서 씁니다. 그것을 표에
«거는» 한 줄이 앱 밖이라, 전략이 「명세」에서 「되는 것」으로 못 넘어갑니다.

## 판정으로 올리는 것 «둘»
```
1  규칙 쓰기가 «이 페이즈»인가
   전략이 「체인이 표를 만든다」이므로 걸음 4 가 막히면 전략 전체가 안 섭니다.
   다만 규칙 쓰기는 «실행되는 것을 고르는» 자리라 반경이 다릅니다 — 총괄 판정입니다
2  걸음 7(모양 확인)을 «표 쪽»에 둘지 «선언 쪽»에 둘지
   지금은 선언 쪽에만 있고, 그래서 표를 만드는 사람이 늦게 압니다.
   ⚠️ 다만 조건 자체는 «선언이 정합니다»(어느 컬럼을 바인딩하나) — 표만 봐서는 못 잽니다.
      그래서 「표 쪽에도 둔다」는 곧 «선언을 먼저 고르게 한다»는 뜻입니다. 순서 문제입니다
```

## 이 문서가 «하지 않은» 것
```
⛔ 「체인을 이렇게 바꾸자」를 «먼저» 제안하지 않았습니다 — 걷고, 막히는 자리를 적었습니다
⛔ 코드 없음 · 도메인 낱말 없음 · 이 박스의 행 수 없음 · 라이브 선언 값 없음
⛔ 미커밋을 「있다」로 적지 않았습니다 (걸음 1의 화면을 ⏳ 로 뒀습니다)
⛔ 반영 여부는 «인용»만 했습니다 — 재는 것은 구현자 큐입니다
📌 실제로 클릭해 보지 않았습니다. 코드에서 잰 여정입니다
```
