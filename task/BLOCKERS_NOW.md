총괄 지시(「하나의 목록으로」 · 「네 갈래를 구조로」 · 「모든 줄을 «셋»으로 표시하십시오」).
**새 조사 없이**, 여섯에 있던 것을 모으고 겹친 것을 합치고 HEAD 에 대고 다시 쟀습니다.

## 🔴 상태는 «셋»뿐입니다 (총괄 판정 `5d553192`)
```
🔴 막힘   서버 ❌ 또는 둘 다 ❌
⚠️ 반쪽   서버 ✅ · 화면 ❌      -> 목록에 «남습니다». 지우지 않습니다
✅ 닫힘   서버 ✅ · 화면 ✅      -> 지웁니다
근거   DoD 가 「«화면에서» 안다」입니다. 라우트는 운영자가 «못 봅니다»
```
🔵 이 표시는 화면이 «움직이는 중»에도 안 틀립니다 — 그래서 지금 하기 좋은 일입니다.

```
모은 곳   ATOM_ROW_SHAPE · REFUSAL_VOCABULARY · OPERATOR_JOURNEY
         INTERNAL_TOKENS · CHAIN_AUTHORING_JOURNEY · UNDO_JOURNEY
구조     심각도가 아니라 «무엇을 막나» — 도착 검사가 갈라 낸 네 갈래
```
> DoD: 「소스를 «선언»하고 «활성화»하면 원자가 쌓인다 **·** 「들어갔나 · 왜 안 들어갔나」를
> «화면에서» 안다」 / 완성 판정: 「«어떻게 선언하면 되는지» 2줄 이내로」

## 🔴 산술 — 26 이 어디로 갔는지 «전부» 답니다
```
모은 것                                      26
− 합친 것 «세 쌍»                            -3   → 23
− 성질·조건이라 뺀 것 «둘»                   -2   → 21
− 판단으로 뺀 것 «하나»                      -1   → 20
+ 도착 검사가 찾은 것 «하나» (Ⅴ-1)           +1   → 21
− ✅ 닫힘으로 지운 것 «넷»                   -4   → «17»  ✅ 아래 목록과 일치
                                                  (막힘 «9» · 반쪽 «7» · 맥락 «1»)
```
⚠️ 지난 판에 «일곱»을 지웠는데, 그중 «셋»은 라우트만 보고 지운 것이라 **되살렸습니다** —
   규칙 편집기 · 실행이 왜 도는지 · 선언 거절의 주소. 셋 다 «반쪽»입니다.

# Ⅰ. 완성 판정(«두 줄»)을 막는 것

## Ⅰ-1 🔴 막힘 — 대상 표가 «먼저» 등록돼야 하는데 아무도 안 알려 줍니다
```
출처   원자 행 명세 ③ · 체인 여정 ②      서버 ⚠️ (조용히 식별자 없는 쓰기)  화면 ❌
세는 법 규칙 저장 경로가 「그 표가 없다」를 말하는지 봅니다 — 지금은 «말하지 않습니다»
🔵 규칙 편집기 라우트가 생겨서 이걸 말해 줄 «자리»는 이제 있습니다
```

## Ⅰ-2 ⚠️ 반쪽 — 규칙 편집기에 «화면»이 없습니다 (되살림)
```
출처   체인 여정 ①                      서버 ✅ `5dd8b2e4` (쓰기 라우트)   화면 ❌
세는 법 그 경로를 읽는 클라 — 소스 «0» · 번들 «0»
⚠️ 지난 판에서 «라우트만» 보고 지웠던 것입니다. 판정대로 되살립니다
```

# Ⅱ. DoD «후반부»를 막는 것 — 「왜 안 들어갔나를 화면에서」

## Ⅱ-1 ⚠️ 반쪽 — 선언 거절의 «주소»를 읽는 쪽이 없습니다
```
출처   거절 어휘 ① · 여정 ③             서버 ✅ `a1814dc6`   화면 ❌
세는 법 그 값을 소비하는 자리를 셉니다 — «0»
✅ 옆에서 «다른» 거절 하나가 이미 경로를 그립니다 — 그릴 자리는 «있습니다»
```

## Ⅱ-2 ⚠️ 반쪽 — 봉투 거절 «여섯» (서버가 오늘 닫혔습니다)
```
출처   거절 어휘 ②                      서버 ✅ `1936c356` (코드·주소가 붙었습니다)  화면 ❌
세는 법 그 검사가 내는 것에 코드·경로가 있는지 봅니다 — 이제 «있습니다»
⚠️ 화면 쪽은 «안 쟀습니다». 서버가 방금 섰으므로 다음 갱신에서 잽니다
```

## Ⅱ-3 🔴 막힘 — 같은 실패가 «시험»에서는 읽히고 «적재»에서는 안 읽힙니다
```
출처   여정 ⑤                           시험 ✅ · 적재 ⚠️
🔴 크기를 «아직 안 쟀습니다» — 거절 이유가 화면에 선 뒤로 이 줄이 얼마나 남았는지 모릅니다.
   「안 쟀다」를 「없다」로 적지 않습니다. 다음 갱신의 «첫 줄»입니다
```

## Ⅱ-4 ⚠️ 반쪽 — 자리표가 «표 이름»처럼 읽힙니다
```
출처   내부 토큰 ①②                     요청자 기본값 ✅ 「모름」   자리표 ❌ 그대로
세는 법 그 자리표가 «값으로» 도착하는 화면이 있는지 봅니다
      ⚠️ 코드에서 그 글자를 찾으면 «0» 입니다 — 토큰은 코드가 아니라 «데이터»로 갑니다
📌 상수는 «판정하는 자리»가 있어 그대로 둡니다. 바꾸는 것은 «표시»입니다
```

## Ⅱ-5 ⚠️ 반쪽 — 실행이 «왜 도는지» (되살림)
```
출처   내부 토큰 ③                      서버 ✅ (인자·요청자·큐 시각 셋 다 실렸습니다)
세는 법 화면이 그 셋을 읽는지 셉니다 — 큐 시각 «소스 1 · 번들 1» · 요청자 «0» · 인자 «미측정»
=> 🔴 셋 중 «하나»만 읽습니다. 지난 판에서 서버만 보고 지웠던 것이라 되살립니다
```

# Ⅲ. 「시도할 수 있나」를 막는 것 — 되돌리기

## Ⅲ-1 🔴 막힘 — 복원이 «앱 밖»입니다 (선언 · 표 등록 둘 다)
```
출처   되돌리기 ①                       서버 ⚠️ (백업은 만듦 · 복원 함수 «0»)   화면 ❌
세는 법 그 모듈의 함수를 셉니다 — 뜨기·목록·최근·주기검사·정기실행. 복원 «0»
🔵 이제 앱 안에서 «쓸 수» 있는 것이 셋입니다(표·규칙·변환). 되돌릴 수 있는 것은 «0» 입니다
```

## Ⅲ-2 🔴 막힘 — 원장에서 지운 것이 «감사»에 안 남습니다
```
출처   되돌리기 ③   표(셀) 회수 ✅ 남음 · 원장 행 삭제 🔴 쓰는 자리를 «못 찾았습니다»
⚠️ 「없다」가 아니라 「이 방법으로 못 찾았다」입니다
```

## Ⅲ-3 🔴 막힘 — 회수가 «둘»인데 층이 다릅니다
```
출처   되돌리기 ④   하나는 «표의 셀» · 하나는 «원장의 행». 이름이 비슷합니다
막는 것 첫째를 걸고 「원자가 안 사라진다」고 읽을 자리입니다
```

## Ⅲ-4 ⚠️ 반쪽 — 백필 재실행은 «안전한데» 화면이 안 말합니다
```
출처   되돌리기 ⑤   서버 ✅ (한 커밋 · 유일 색인 «둘»)   화면 ❌ (하나도 안 말합니다)
✅ 「이미 되는데 아무도 안 쓴다」 부류
```

# Ⅳ. 원자가 «맞게» 쌓이나 — 두 줄이 나온 «다음»의 문제

## Ⅳ-1 🔴 막힘 — 「이 표가 원자 행 표인가」를 «만들 때» 확인할 자리가 없습니다
```
출처   체인 여정 ④   서버 ❌   화면 ❌
막는 것 만든 사람이 «나중에» — 선언에 붙여 시험을 돌린 뒤에 압니다
```

## Ⅳ-2 🔴 막힘 — 시각 컬럼의 «타입»이 준비 경계까지 사는지 «미검증»
```
출처   원자 행 명세 ④   실행이 필요합니다. 제가 «안 쟀습니다»
📌 구현자 큐. 결과를 «인용»할 자리입니다
```

## Ⅳ-3 🔴 막힘 — 「고친 것이 반영되나」
```
출처   체인 여정 ⑤   라우트 ✅ · 화면 ✅ · 「변환 파일 수정이 반영되나」는 «별개»
📌 구현자 큐(맵퍼 리로드)
```

## Ⅳ-4 ⚠️ 반쪽 — 소급 실행이 인자를 «타이핑»으로 받습니다
```
출처   여정 ④ · 체인 여정 6   서버 ⚠️   화면 ⚠️
🔵 닫힌 목록을 주는 기제가 «이미 있습니다» — 인자 선언에 그 칸이 있고 «한 인자가 씁니다».
   🔴 그런데 소스 인자는 «안 씁니다». 도움말이 다른 라우트를 가리킵니다
=> 「없다」가 아니라 «있는데 그 인자가 안 쓴다»입니다
```

## Ⅳ-5 🔴 막힘 — 바인딩된 컬럼이 «한 행»만 비어도 그 행이 거절됩니다
```
출처   원자 행 명세 ②
세는 법 선언의 읽기 칸을 셉니다 — 여섯, 행을 «거르는» 것 «0»
📌 판정 대기 — 「이 행은 문장이 아니다」를 말할 자리
```

# Ⅴ. 맥락 — 사실이지만 «완성 판정을 막지는» 않습니다 (총괄 판정 `4c431b7f`)

## Ⅴ-1 「한 문장으로 만드는 일」이 «코드 쓰기»입니다
```
사실   행을 그 모양으로 만드는 유일한 길이 변환을 «쓰는» 것입니다 (쓰는 자리는 앱 안에 ✅)
판정   두 줄이 답해야 하는 것은 «선언법»이지 «표를 준비하는 법»이 아닙니다.
      변환을 쓰는 것은 「도메인을 아는 유저가 «자유롭게 세팅»한다」의 «세팅»에 들어갑니다
🔴 다만  소유자 문장의 «해석»이라 소유자께 올라가 있습니다. 뒤집히면 다시 «막는 것»이 됩니다
⛔ 그 전에 그 방향으로 아무것도 만들지 않습니다
```

# 목록에서 «뺀» 것 — 막는 것이 아니라서
```
변환 파일이 «그 서버에서만» 산다   성질입니다(운영자의 코드). 여정의 사실로 명세에 남깁니다
한 행 = 한 원자의 선언 조건 셋     조건이지 막는 것이 아닙니다
화면이 시험을 «권하지» 않는다      버튼은 «있습니다». 「권하는가」는 코드로 못 재고,
                              상설이 「화면은 보여 준다, 설명하지 않는다」입니다 — 판단으로 뺐습니다
```

# 이 목록을 «다시» 재는 법
```
각 줄의 「세는 법」이 그것입니다 — 커밋 번호가 아니라 «세는 방법»입니다
🔴 그리고 지우기 «전»에 두 칸을 «둘 다» 보십시오. 서버만 보고 지우면 이번처럼 «셋»이 되살아납니다
⚠️ 이 방법으로 «못 가르는» 것 셋: 번들이 청크로 갈릴 때 · 화면이 움직이는 중일 때 ·
   토큰이 «값으로» 도착할 때(소스에서 영원히 0)
⛔ 제안 없음 · 코드 없음 · 도메인 낱말 없음 · 새 조사 없음
```

# 🔴 도착 검사 — 「이 목록을 닫으면 «두 줄»이 나오나」

```
① 「<이 표>의 한 행이 «한 문장»이 되게, 주어 식별키 · 시각 · 목적어 · 수식어를
    «각각 한 칸»으로 채우십시오」
② 「선언에서 <그 표>를 소스로 잡고, 술어 하나를 골라 그 칸들을 역할에 «짝지으면» 됩니다」
```
```
「<이 표>」를 도구가 안다   Ⅰ-1 · Ⅰ-2
「됩니다」를 확인한다       Ⅱ 다섯
🔵 안 기대는 조각          소스로 잡기 · 술어 고르기 · 역할 짝짓기 · 조립 키 컬럼 만들기
                        -> **둘째 줄은 오늘 써집니다**
실패 넷                  「이 박스에서는」 ❌ · 컬럼 이름 ❌ · 손으로 맞춤 ❌ ·
                        «절차»가 되나 -> Ⅴ-1 (맥락으로 판정됨)
```
📌 **목록을 다 치우는 것과 완성 판정에 «도착»하는 것은 같은 일이 아닙니다.**
