총괄 지시(`task/MARKING_CONTRACT.md` 「막히는 자리를 «하나의 목록»으로. 그리고 «지금» 상태로」).
**새 조사 없이**, 여섯에 있던 것을 모으고 겹친 것을 합치고 **오늘 HEAD 에 대고 다시 쟀습니다.**

```
모은 곳   ATOM_ROW_SHAPE · REFUSAL_VOCABULARY · OPERATOR_JOURNEY
         INTERNAL_TOKENS · CHAIN_AUTHORING_JOURNEY · UNDO_JOURNEY
정렬     심각도가 아니라 «DoD 의 어느 절반을 막나»
```

## 🔴 산술 — 26 이 어디로 갔는지 «전부» 답니다 (정정 2026-09-04)
첫 판에 「합쳐서 18 -> 남은 것 14」라 적었는데 **목록에는 18 이 있었습니다.** 세지 않고 쓴 수였고,
그 사이 항목 하나가 «조용히» 빠졌습니다. 세어서 맞춥니다.
```
모은 것                                             26
− 합친 것 «세 쌍»                                   -3   → 23
   선언 거절의 주소(거절 어휘 ① + 여정 ③)
   대상 표가 먼저(원자 행 ③ + 체인 여정 ②)
   자리표와 기본값(내부 토큰 ① + ②)
− 성질·조건이라 뺀 것 «둘»                          -2   → 21
− 재서 지운 것 «둘»                                 -2   → 19
− 판단으로 뺀 것 «하나»                             -1   → 18   ✅ 목록과 일치
+ 도착 검사가 찾은 것 «하나» (A-9)                  +1   → «19»
```
🔴 마지막 하나가 첫 판에서 «말없이» 빠졌던 것입니다 — 아래 「뺀 것」에 이유와 함께 되살렸습니다.

# 🔴 A. DoD «전반부»를 막는 것 — 「선언하고 활성화하면 원자가 쌓인다」

## A-1 표 등록에 «화면»이 없습니다
```
출처   운영자 여정 ① · 체인 여정 1
지금   서버 ✅ (라우트 있음)    화면 ❌ (소스 «0» · 번들 «0»)
확인   그 경로를 읽는 클라 파일 수를 셌습니다
막는 것 여정의 «첫 걸음»이 앱 밖입니다
```

## A-2 🔴 규칙을 «앱 안에서 못 씁니다» — 전략의 마지막 걸음
```
출처   체인 여정 ①
지금   서버 ❌ (읽기 라우트만, 쓰기 «없음»)    화면 ❌ (목록만)
확인   규칙 경로의 라우트를 셌습니다 — GET 하나
막는 것 「체인이 표를 만든다」가 «명세»에서 «되는 것»으로 못 넘어갑니다
📌 소유자 판정 나왔고 구현자 큐에 있습니다
```

## A-3 대상 표가 «먼저» 등록돼야 하는데 아무도 안 알려 줍니다
```
출처   원자 행 명세 맨 앞 ③ · 체인 여정 ②
지금   서버 ⚠️ (표가 없으면 «조용히» 식별자 없는 쓰기)    화면 ❌
막는 것 순서를 모르고 지나가면 «조용히» 틀립니다
📌 A-2 가 열리기 전에는 이걸 «말해 줄 자리»가 안 생깁니다. 순서가 있습니다
```

## A-4 「이 표가 원자 행 표인가」를 «만들 때» 확인할 자리가 없습니다
```
출처   체인 여정 ④
지금   서버 ❌    화면 ❌
막는 것 만든 사람이 «나중에» — 선언에 붙여 시험을 돌린 뒤에 압니다
```

## A-5 시각 컬럼의 «타입»이 준비 경계까지 사는지 «미검증»
```
출처   원자 행 명세 맨 앞 ④
지금   실행이 필요합니다. 제가 «안 쟀습니다»
📌 구현자 큐에 있습니다. 결과를 «인용»할 자리입니다
```

## A-6 「고친 것이 반영되나」 — 구현자 측정 대기
```
출처   체인 여정 ⑤
지금   설정 다시 읽기 라우트 ✅ · 화면 ✅ · 「변환 파일 수정이 반영되나」는 «별개»
📌 구현자 큐(맵퍼 리로드). 화면·경로만 적고 결과는 인용합니다
```

## A-7 소급 실행이 인자를 «타이핑»으로 받습니다
```
출처   운영자 여정 ④ · 체인 여정 6
지금   서버 ✅ (연산 목록)    화면 ⚠️ (목록은 그리고, 인자는 운영자가 «칩니다»)
확인   그 인자의 도움말이 «다른 라우트를 직접 부르라»고 말합니다
막는 것 방금 선언한 사람이 자기 소스 이름을 «이미 알고» 있어야 합니다
📌 클라 큐
```

## A-8 바인딩된 컬럼이 «한 행»만 비어도 그 행이 거절됩니다 — 거를 자리가 없습니다
```
출처   원자 행 명세 맨 앞 ②
지금   선언의 읽기 칸 «여섯» 중 행을 거르는 것이 «없습니다»
확인   그 여섯을 셌습니다
막는 것 무효가 된 행이 표에 남아 «매번» 거절됩니다
📌 판정 대기 — 「이 행은 문장이 아니다」를 말할 자리
```

## B-3 봉투 거절 «여섯»에 코드도 경로도 없습니다

## B-4 같은 실패가 «시험»에서는 읽히고 «적재»에서는 안 읽힙니다

```
지금   시험 ✅ · 적재 ⚠️ (수로만)
막는 것 운영자가 그 둘이 «같은 것인지» 모릅니다
📌 B-1 이 서면 절반이 같이 닫힙니다 — 따로 세지 않도록 여기 답니다
```

## B-5 실행이 «왜 도는지» 못 말합니다 — 재료가 창구에서 빠집니다
```
출처   내부 토큰 명세 ③
지금   표에 «인자 · 요청자 · 큐 시각»이 있고, 화면에 가는 줄에서 «셋 다» 빠집니다
확인   화면으로 가는 줄의 칸을 세어 표의 칸과 맞췄습니다 — 오늘도 그대로입니다
```

```
출처   내부 토큰 명세 ①②
지금   큐 행의 표 이름 칸에 자리표 · 요청자 자리에 기본값
📌 상수는 «판정하는 자리»가 있어 그대로 둡니다. 바꾸는 것은 «표시»입니다
```

```
출처   되돌리기 여정 ①
```

# 목록에서 «뺀» 것 — 막는 것이 아니라서

```
변환 파일이 «그 서버에서만» 산다   성질입니다(운영자의 코드). 여정의 사실로 명세에 남깁니다
한 행 = 한 원자의 선언 조건 셋     조건이지 막는 것이 아닙니다. 원자 행 명세가 정본입니다
🔴 화면이 시험을 «권하지» 않는다   버튼은 «있습니다»(화면이 그 경로를 부릅니다).
                              「권하는가」는 코드로 못 재고, 오늘 선 상설이
                              「화면은 보여 준다, 설명하지 않는다」입니다.
                              => 제가 «판단으로» 뺐습니다. 첫 판에서 말없이 빠졌던 그 하나입니다
```

# 🔴 도착 검사 — 「열여덟을 닫으면 «두 줄»이 나오나」 (그리고 그 답이 A-9 를 «열아홉째»로 만들었습니다)

총괄 지시(「목록은 «할 일»이지 «도착지»가 아닙니다」)에 따라, **두 줄을 실제로 써 보고**
완성 판정에 대 봤습니다. 「닫히면 될 것 같다」로 적지 않았습니다.

## ① 두 줄 — 열여덟이 다 닫혔다고 «가정»하고 씁니다
```
① 「<이 표>의 한 행이 «한 문장»이 되게, 주어 식별키 · 시각 · 목적어 · 수식어를
    «각각 한 칸»으로 채우십시오」
② 「선언에서 <그 표>를 소스로 잡고, 술어 하나를 골라 그 칸들을 역할에 «짝지으면» 됩니다」
```

## ② 조각이 «무엇에» 기대나 — 그리고 «안 기대는» 것
```
조각                          기대는 것
「<이 표>」를 도구가 안다        A-1 (등록 화면) · A-3 (순서를 알려 줌)
「채우십시오」                  A-2 (규칙을 앱 안에서 쓴다)  🔴 그리고 그 «너머»가 있습니다 — ④
「됩니다」를 확인한다            B 여섯 전부

🔵 아무것에도 «안 기대는» 조각 — 즉 «지금 이미» 되는 것
「선언에서 <그 표>를 소스로 잡고」   ✅  선언 화면이 있고 경로로 거절합니다
「술어 하나를 골라」                ✅  어휘 선언이 같은 화면에 있습니다
「그 칸들을 역할에 짝지으면」        ✅  바인딩 폼이 선언 스켈레톤에서 생성됩니다
「각각 한 칸」을 «만드는» 것        ✅  조립 키 컬럼은 변환이 만들 수 있습니다
```
🔴 **둘째 줄은 «오늘» 써집니다.** 열여덟 중 어느 것에도 안 기댑니다.
=> 완성 판정을 막는 것은 «첫째 줄»이고, 그중에서도 A-1·A-2·A-3 입니다.

## ③ 완성 판정의 «실패 넷»에 대 봤습니다
```
❌ 「이 박스에서는 이렇게」로만 말해지나     아니오 — 이 박스의 이름이 한 낱말도 없습니다
❌ 이 박스의 «컬럼 이름»이 들어가나         아니오 — 전부 «자리»의 이름입니다
❌ 손으로 맞춰서 돌게 만들었나              해당 없음 — 돌려 본 것이 아니라 «쓴» 것입니다
🔴 두 줄이 안 되고 «절차»가 되나            «걸립니다». 아래 ④
```

## ④ 🔴 걸린 자리 — 「채우십시오」가 «세 걸음»을 덮고 있습니다
```
두 줄이 말하는 것    「표에 채우십시오」 — 한 번의 «적기»처럼 들립니다
실제로 필요한 것     ① 대상 표를 등록하고  ② 변환을 «쓰고»  ③ 규칙으로 그것을 «걸고»
                  그다음에 선언합니다
=> 열여덟을 다 닫아도 ②가 남습니다. A-2 는 「규칙을 앱 안에서 쓴다」이지
   「채우는 일이 «적기»가 된다」가 아닙니다
```
🔴 **그래서 열여덟에 «없던» 것이 하나 나왔습니다.** 아래 A-9 로 목록에 넣습니다.
⚠️ 이건 「코드를 없애자」가 아닙니다 — 제안은 하지 않습니다. **완성 판정이 두 줄을 요구하는데
   그 한 낱말이 코드 쓰기를 덮고 있다**는 사실을 적는 것까지입니다.

## ⑤ 그래서 알게 된 것 하나 더 — 열여덟이 «한 가지»를 재는 게 아닙니다
```
완성 판정(두 줄)에 걸리는 것     A-1 · A-2 · A-3 · A-9   «넷»
DoD 후반부에 걸리는 것          B 여섯
「시도할 수 있나」에 걸리는 것     C 넷
어느 쪽도 아닌 것               A-4 · A-5 · A-6 · A-7 · A-8
                             (원자가 «맞게» 쌓이는지에 걸립니다 — 두 줄이 나온 «다음»의 문제)
```
📌 목록을 다 치우는 것과 «완성 판정에 도착»하는 것은 같은 일이 아닙니다. 넷이 먼저입니다.

## A-9 「한 문장으로 만드는 일」이 «코드 쓰기»입니다 (출처: 완성 판정 대조)
```
지금   행을 그 모양으로 만드는 유일한 길이 변환을 «쓰는» 것입니다
      쓰는 자리는 앱 안에 «있습니다» ✅ — 그런데 그것은 «적기»가 아니라 «작성»입니다
막는 것 완성 판정의 두 줄에서 「채우십시오」 한 낱말이 그 작성을 덮습니다
      -> 두 줄이 «절차»가 됩니다 (실패 넷 중 둘째)
서버 —   화면 —   (라우트·화면의 문제가 아닙니다. «두 줄로 말해지나»의 문제입니다)
📌 제안 없음. 판정은 총괄·소유자 자리입니다
```

# 이 목록을 «다시» 재는 법
```
각 줄의 「확인」이 세는 방법입니다. 커밋 번호가 아니라 «세는 법»으로 적었습니다 —
그래야 다음 사람이 「고쳐졌다고 들었다」가 아니라 «재서» 지울 수 있습니다
⛔ 제안은 넣지 않았습니다 · 코드 없음 · 도메인 낱말 없음 · 새 조사 없음
```
