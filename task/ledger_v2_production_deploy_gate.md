# [Gate] 오늘 작업을 운영에 올리기 전에 — 무엇이 멈추는가

> **상태:** 소유자 확인 필요 (배포 전)
> **작성:** 2026-08-18, 원장 단순화 1라운드 착지 시점
> **이유:** 오늘 legacy 실행 경로를 지웠다. 운영이 그 경로로 돌고 있으면 배포가 곧 정지다.

## 오늘 지운 것

- legacy 번역기 5개 (`lot_event`·`observation`·`transfer`·`declared`·`translator_pattern`)
- legacy 문법 드라이버 4개와 `--legacy` 진입점
- `ledger/config.py`(v1 선언 문법) — 제거 진행 중
- 5파일 manifest 셋업 → **단일 파일**. 옛 모양은 로더가 `unlisted_config_file`로 거절한다

## 운영이 어느 상태인지에 따라 결과가 갈린다

이 박스에서는 확인할 수 없다. **운영은 여기가 아니다.**

### 경우 A — 운영이 v1(legacy) 원장으로 돌고 있다

`server/config/ledger_config.json`(v1 선언)과 번역기로 백필이 돌고 있다면,
**배포하는 순간 원장 적재가 멈춘다.** 지운 모듈을 부르는 진입점이 없어졌기 때문이다.
조용히 멈추지 않고 거절로 멈추지만, 멈추는 것은 같다.

→ 배포 전에 **v2 셋업을 운영에 먼저 세우고** 등가를 확인해야 한다.

### 경우 B — 운영이 v2 5파일 manifest로 돌고 있다

`server/config/ontology/`에 `manifest.json`·`catalog/`·`dataflows/`가 있다면,
**배포하는 순간 config 로드가 거절된다.** 단일 파일 규칙이 루트 하위의 다른 `.json`을
전부 거절하기 때문이다.

→ 배포와 **같은 시점에** 변환기를 돌려야 한다:
`python scripts/convert_ontology_to_single_file.py --root <운영 root> --out <새 파일>`
변환기는 원본을 지우지 않는다. 새 파일을 만든 뒤 옛 4파일+manifest를 **루트 밖으로** 옮긴다
(루트 안에 두면 그 자체가 거절 사유다 — 이 박스에서 실제로 밟았다).

### 경우 C — 운영에 v2 셋업이 아예 없다

`server/config/ontology/`가 없다면 원장 v2는 운영에서 한 번도 안 돌았다는 뜻이다.
배포해도 **멈출 것이 없다.** 대신 소유자가 셋업을 처음부터 세우게 된다 — 오늘 준비한
경로가 그것이다.

## 커서 — 어느 경우든 걸린다

이 박스의 `lot_event` 커서는 **v1 모양**(`lot_event/1/rules:34311f15`, 원자 1,195)이다.
운영도 같은 모양이면 v2 백필이 `legacy_cursor_reset_required`로 거절한다. **의도된
안전장치**이고, 옛 규칙 원자와 새 규칙 원자가 섞이지 않게 막는다.

지금 CLI에는 커서를 옮길 승인된 문이 없다(`--reset-cursor`는 조건 없이 거절).
전환하려면 셋 중 하나를 소유자가 정해야 한다:

1. 커서만 지우고 재번역 — 원자는 `source_translator_ver`로 구분되므로 섞이지 않는다
2. 기존 원자까지 지우고 재번역 — 깨끗하지만 그 소스 몫이 사라진다
3. **새 소스 이름으로 붙인다** — 같은 표를 다른 `source_id`로 선언하면 커서가 없어 바로 돈다.
   시연·검증에는 이게 가장 깨끗하다

## 배포 전 확인 목록

- [ ] 운영이 A·B·C 중 어느 상태인가
- [ ] (A) v2 셋업을 먼저 세우고 등가를 확인했는가
- [ ] (B) 변환기를 배포와 같은 시점에 돌릴 준비가 됐는가. 옛 파일을 **루트 밖**으로 옮기는가
- [ ] 운영 `file_ingestion_checkpoints`에 `file_mtime`·`file_size`가 있는가
      (없으면 파일 인제션이 매 스윕마다 전량 재적재 중이다 — 이건 원장과 무관하게 지금 급하다)
- [ ] 커서 전환을 어떻게 할지 정했는가

## 이 문서의 한계

전부 **이 박스 실측에 근거한 추론**이다. 운영의 config·커서·DB 상태는 여기서 볼 수 없고,
봤다고 말해서도 안 된다. 위 세 경우 중 어느 것인지는 소유자만 답할 수 있다.
