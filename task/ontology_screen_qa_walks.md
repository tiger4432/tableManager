# 작성 화면 — 총괄이 브라우저에서 «직접» 거는 검수 걸음

총괄(포크)이 소유자 브라우저에서 실행한다. 구현자 보고를 «대조»하는 용도이지 대체하는 게 아니다.

**왜 필요해졌나.** 2026-08-19 하루의 실패가 거의 전부 **한 층 아래에서 재고 통과시킨 것**이었다 —
스위트 초록, 서버 200, 커밋 범위 깨끗함. 전부 맞는 측정인데 **소유자가 서 있는 층이 아니었다.**
아래 걸음은 전부 **화면이 무엇이라고 «쓰는가»**를 본다. 응답 코드가 아니라.

---

## 매번, 재기 «전에»

1. **번들 확인** — 살아 있는 페이지의 `script[src]`가 `dist/admin.html`이 가리키는 것과 같은가.
   다르면 캐시 무시 재적재. **이걸 건너뛰면 수리 전 화면을 재게 된다**(2026-08-19에 두 번).
2. **어느 상태에서 거는지 적는다** — 「새로 만든 초안」/「안 읽히는 선언」/「활성 선언」.
   이 셋이 오늘만 세 번 갈라졌다.

## 매번, 잰 «뒤에»

3. **파일을 확인한다** — 화면이 「저장됐다」고 하면 `ledger_config.json`에 실제로 그 값이 있는가.
   화면 표시는 대리 지표다.
4. **소유자 설정을 건드렸으면 되돌린다.** 저장을 누를 걸음은 임시 선언으로만.

---

## W1 · 빈 설정에서 선언 «둘» — 원래의 걸음

**왜.** 하루 종일 여기서 막혔다. 실패는 언제나 **두 번째** 동작에서 났다.

부팅 → 엔터티 만들기 → 키 → 저장 → **두 번째** 엔터티 → 키 → 저장.

**실패 판정:** 두 번째가 무반응 · 409 · 첫 번째 화면으로 되돌아감 · 파일에 하나만 들어감.

## W2 · 화면이 «자기 이름»을 말하는가 — 일곱 종 전부

**왜.** 오늘 두 번 났다. `wafer@1`을 만들었는데 화면이 `lot@1`을, 나중엔 무엇을 만들든
`sources.dt_job`을 그렸다. 편집기가 «떴는지»만 재고 «무엇이라고 쓰는지»를 안 물어서 통과했다.

엔터티 · 낱말 · 팩 · 매퍼 · 프로필 · 준비기 · 소스를 **각각** 새로 만든다.

**셀 것:** 화면에 **그 이름이 몇 번**, **다른 선언 이름이 몇 번**. 작업 영역 안에서.
**실패 판정:** 내 이름 0 · 남의 이름 1 이상.

## W3 · 새 선언에 «시작점»이 있는가 ← 지금 열려 있는 결함

**왜.** 팩을 새로 만들면 「None defined」 네 줄과 `{}`뿐이다. 무엇을 만들어야 하는지 화면이
한 마디도 안 한다. 소유자가 JSON을 빼라는 이유가 **「구조를 못 외우겠다」**인데 여기서 정확히
외워야 한다.

팩을 새로 만든다 → **원본 JSON을 쓰지 않고** 첫 주장을 시작할 수 있는가.

**실패 판정:** 채울 수 있는 칸이 0개. 「없음」을 여러 방식으로 반복.

## W4 · 미완성 선언을 «마저» 쓰기 — 소유자의 주된 길

**왜.** 「일단 와꾸 짜놓고 나중에 살 채우는」. 살을 채우는 대상이 **안 읽히는 선언**이라,
제안이 가장 필요한 자리다.

없는 술어를 참조하는 팩을 저장 → 목록에 `invalid`로 뜨는가 → **눌러서 열리는가** →
안에 **이유가 보이는가** → 고쳐서 저장 → **살아나는가**.

**실패 판정:** 목록에서 사라짐 · 눌러도 안 열림 · 열렸는데 이유가 없음 · 고쳐도 안 살아남.

## W5 · 저장하고 «계속» 편집

**왜.** 저장할 때마다 목록으로 튕기면 「살 채우기」가 성립하지 않는다.

저장 → 편집기가 그대로인가 → **바로 이어서 고치고 또 저장** → **세 번째까지** 되는가.
`invalid`인 선언에서도 같은가.

**실패 판정:** 두 번째·세 번째 저장 실패 · 자리를 잃음 · 저장 뒤 텍스트가 «바뀜».

## W6 · 쓰던 게 «안 사라진다»

**왜.** 검색창에 타이핑하면 저장 안 한 초안이 조용히 지워졌다. 경고도, 이탈 경고도 없었다.

키를 치고 **저장하지 않은 채** → 검색창에 타이핑 → **그대로인가** → 탭 전환·새로고침 →
**그대로인가**.

**실패 판정:** 비워짐. **조용히** 비워지면 더 나쁘다.

## W7 · 삭제 — 거절이 «안» 떠야 한다

**왜.** 남이 참조하는 걸 지우면 예전엔 설정이 통째로 안 읽혀서 미리 막아야 했다. 부분 적재
이후로는 아니다. 지금 막으면 관문을 되살린 것이다.

아무도 안 쓰는 것 삭제 → 사라지는가 · **남이 참조하는 것 삭제** → **거절 없이** 사라지고
참조하던 것들이 `invalid`가 되는가 · 확인 문구가 **무엇이 안 읽히게 되는지 맞게** 말하는가 ·
다시 선언하면 살아나는가 · **`@1` 없는 것 같은 안 읽히는 선언도 지워지는가**.

**실패 판정:** 거절 · 「영향 없음」이라 해 놓고 남이 죽음 · 안 읽히는 것에 삭제 버튼 없음.

## W8 · 제안 — 열린 것과 닫힌 것

**왜.** 오타 하나가 원장 안에서 **같은 뜻을 영원히 둘로 가른다**(`register@1` vs `regsiter@1`).
거절로 못 막고 고를 수 있게 해서 막는다.

이름 칸에 몇 글자 → **제안이 뜨는가** · **없는 이름을 새로 쳐도 안 막히는가**(datalist인 이유) ·
닫힌 목록 칸이 **드롭박스**인가 · **현재 값이 항상 선택지에 있는가**(모르는 값이어도) ·
**설정이 안 맞는 상태에서도 제안이 뜨는가**.

**실패 판정:** 새 이름이 거절됨 · 드롭박스가 모르는 값을 첫 옵션으로 **갈아 끼움**(그리는 것만으로
파일이 바뀐다) · 깨진 설정에서 목록이 빔.

## W9 · 깨진 설정에서도 화면이 «열리는가»

**왜.** 저장이 안 막히게 된 순간, 저장 한 번으로 화면을 못 열게 만들 수 있다.

안 맞는 설정을 저장 → **새로고침** → 열리는가 → **서버 재시작** → 나머지 선언이 여전히 사는가.

**실패 판정:** 500 · 빈 화면 · 멀쩡한 선언까지 사라짐.

## W10 · 거절문이 «맞는 곳»을 가리키는가

**왜.** 계산하느라 잠깐 빼놓은 선언을 「선언되지 않았다」고 말하면, 화면에 멀쩡히 있는 것을
찾아 헤매게 된다.

`invalid`인 선언들의 이유 문장을 읽는다.

**실패 판정:** 화면에 있는 것을 「없다」고 말함 · 이유가 남의 칸을 가리킴 · 이유가 비어 있음.

---

## 그리고 매번 보는 것 — 오늘의 병

**「없는 것」을 무엇인가로 그리고 있지 않은가.**

- 빈 통을 여러 개 그리지 않는가 (「None defined」 × 4)
- 균일한 상태를 반복하지 않는가 (`Complete` × 6, `active · valid` × 6)
- 같은 것을 두 번 그리지 않는가 (정의 탭의 JSON + 원본 JSON 탭)
- 값이 없을 때 「불러오는 중」이라 하지 않는가

오늘 실패 열한 개가 **전부 이 한 가지**였다.
