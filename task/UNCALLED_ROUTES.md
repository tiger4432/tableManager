# 서버가 «내는데» 화면이 «안 부르는» 것 — 전수

총괄 지시(`6297b9e0`). 오늘 이 부류가 «네 번» 우연히 나와서 전수로 갑니다.
지시대로 **서버에서 시작**했습니다 — 화면에서 시작하면 넷 다 「없음」으로 읽힙니다.

```
잰 방법   ① 도는 서버의 openapi 로 «경로»를 셌습니다 (라우트는 커밋된 코드가 정합니다)
         ② 클라 소스 전체에서 그 경로를 부르는지 셌습니다
         ③ 차집합마다 한 줄: 「이게 화면에 있으면 운영자가 «무엇을 할 수» 있나」
먼저 본 것  상설대로 CODE_MAP §1(라우트 계수) · §5-H-bis. 🔵 ③의 답 «하나»가 거기 이미 있었습니다
```

## 🔴 셈을 «두 번» 고쳤습니다 — 첫 수가 틀렸습니다
```
1차   «24» 안 부름   -> ❌ 틀렸습니다
      틀린 이유: 탐색기가 «변수 경로 헬퍼» 하나를 지나갑니다. 리터럴로는 그 호출이 «안 보입니다»
      그래서 실제로 «부르고 있는» 탐색기 라우트 여섯을 「안 부름」으로 셌습니다
2차   헬퍼에 넘어가는 인자를 모아 다시 셌습니다 -> 경로 108 · 부름 91 · «안 부름 17»
3차   ③으로 거르니 «후보 다섯»
```
🔴 **지시의 「심볼로 세라」가 이 자리를 정확히 겨눴습니다.** 리터럴은 «이름만 같은 것»에 속고,
   그 반대로 «변수로 지은 호출»을 못 봅니다. 둘 다 틀리는 방향입니다.

# ✅ 후보 «다섯» — ③에 답이 있는 것

| 라우트 | ③ 화면에 있으면 운영자가 무엇을 하나 |
|---|---|
| 심박 | 「지금 이 큐를 «집어가는 프로세스»가 살아 있나」 — 리플레이가 안 도는 이유의 답 |
| 컬럼 통계 | 「이 조합이 «유일한가»」 · 「순서로 쓸 수 있는 후보」 · 「그 컬럼에 값이 실제로 있는 행 수」 |
| 결측 | 「내 선언에서 «무엇이 빠졌나»」 — 이름표까지 붙여서 |
| 계획 시험(쓰기 없음) | 「내 선언이 «왜» 거절되나, 그리고 무엇을 고치면 되나」 |
| 가상 조인 검증 | 「내가 쓴 조인이 «실제로 맞나»」 |

## 🔵 그중 «셋»은 오늘 이미 나온 것이고, «둘»이 새 것입니다
```
알던 것   심박(리플레이 절) · 컬럼 통계(두 줄 시험 마디 3)
새것 ①   결측 — 🔴 그 이름표의 «정본»이 제 명세입니다. 거절문이 사람을 그 문서로 보내는데,
         정작 «결측을 보여 주는 화면»이 없습니다. 문서를 읽고 «무엇이 빠졌는지»는 못 봅니다
새것 ②   계획 시험 — 🔵 ③의 답을 **CODE_MAP 이 이미 적어 뒀습니다**:
         옆 라우트는 역할마다 「연결됨 / 없음」 «한 낱말»을 내고, 그 낱말로는 선언을 못 고칩니다.
         이 라우트는 «이름 붙은 거절 사유 · 해석된 실제 컬럼명 · 그 값이 선언에서 왔나 유도에서 왔나
         · 틀린 선언을 지우면 무엇이 유도되나»를 같이 냅니다
         🔴 그리고 화면은 «한 낱말 쪽»을 부르고 있습니다
새것 ③   가상 조인 검증 — 두 줄 시험 «마디 2»의 파생 칸과 같은 주제입니다
         (선언이 「이 준비기가 검증된 조인을 받나」를 적는데, 검증 자체를 부르는 화면이 없습니다)
```

# ❌ 후보가 «아닌» 것 — ③에 답이 없어서

```
내부 사건 넷    서버끼리 부르는 자리입니다. 화면이 부르면 «안 됩니다» — 없는 게 맞습니다
페이지 셋      fetch 가 아니라 «이동»으로 열립니다. 제 셈법이 못 보는 것이지 «안 쓰는» 게 아닙니다
다운로드 하나   클라가 «다른» 다운로드 경로를 씁니다. 둘 중 하나는 중복이고,
              이으면 운영자가 얻는 것이 «없습니다» (그건 지우자는 얘기이고 이 항목이 아닙니다)
선언 시험 하나  🔵 코드가 자기 주석에 「이 라우트를 부르는 클라 «0» 」이라고 «이미 적어 뒀고»,
              새 작성 경로(초안 -> 검토 -> 활성화)가 그 자리를 대신합니다. 소스 미리보기는
              그 라우트를 «서버 안에서» 지납니다 -> 이으면 «두 번째 문»이 됩니다
```

# ⚠️ ③을 제가 «못 답하는» 것 «셋» — 추측하지 않습니다

```
표기 미리보기 · 코어 요약 · 오버레이
=> 지도·표기 도메인입니다. 「화면에 있으면 무엇을 할 수 있나」를 답하려면 그 도메인을 알아야 하고,
   저는 모릅니다. «후보»로도 «후보 아님»으로도 적지 않고 «못 답함»으로 둡니다
📌 그 도메인 레인이 ③ 한 줄씩만 답하면 이 표가 닫힙니다
```

# 🔴 이 전수가 말하는 것 한 줄

**후보 다섯 중 «넷»이 「왜 안 되는지 / 무엇을 고치면 되는지」를 내는 라우트입니다.**
화면은 그 옆의 «한 낱말짜리» 답을 부르고 있습니다 — 연결됨/없음 · 0/N · 도는 중.
그래서 이 부류는 「기능이 없다」가 아니라 **「진단이 있는데 화면이 요약만 읽는다」**입니다.

## 안 훑은 것
```
⚠️ «응답의 칸» 단위로는 안 훑었습니다 — 이번 것은 «라우트» 단위입니다.
   부르는 라우트 91 중에 「받아 놓고 안 그리는 칸」이 있을 수 있고, 그건 다음 라운드 크기입니다
⛔ 고치지 않았습니다 · UI 설계 없음 · 이 박스의 행 수 없음
```
