# 서버가 «내는데» 화면이 «안 부르는» 것 — 전수

총괄 지시(`6297b9e0`). 오늘 이 부류가 «네 번» 우연히 나와서 전수로 갑니다.
지시대로 **서버에서 시작**했습니다 — 화면에서 시작하면 넷 다 「없음」으로 읽힙니다.

```
잰 방법   ① 도는 서버의 openapi 로 «경로»를 셌습니다 (라우트는 커밋된 코드가 정합니다)
         ② 클라 소스 전체에서 그 경로를 부르는지 셌습니다
         ③ 차집합마다 한 줄: 「이게 화면에 있으면 운영자가 «무엇을 할 수» 있나」
먼저 본 것  상설대로 CODE_MAP §1(라우트 계수) · §5-H-bis. 🔵 ③의 답 «하나»가 거기 이미 있었습니다
```

## 🔴 셈을 «두 번» 고쳤습니다 — 첫 수가 틀렸습니다
```
1차   «24» 안 부름   -> ❌ 틀렸습니다
      틀린 이유: 탐색기가 «변수 경로 헬퍼» 하나를 지나갑니다. 리터럴로는 그 호출이 «안 보입니다»
      그래서 실제로 «부르고 있는» 탐색기 라우트 여섯을 「안 부름」으로 셌습니다
2차   헬퍼에 넘어가는 인자를 모아 다시 셌습니다 -> 경로 108 · 부름 91 · «안 부름 17»
3차   ③으로 거르니 «후보 다섯»
```
🔴 **지시의 「심볼로 세라」가 이 자리를 정확히 겨눴습니다.** 리터럴은 «이름만 같은 것»에 속고,
   그 반대로 «변수로 지은 호출»을 못 봅니다. 둘 다 틀리는 방향입니다.

```

              그 라우트를 «서버 안에서» 지납니다 -> 이으면 «두 번째 문»이 됩니다
```

# 🔴 이 전수가 말하는 것 한 줄

**후보 다섯 중 «넷»이 「왜 안 되는지 / 무엇을 고치면 되는지」를 내는 라우트입니다.**
화면은 그 옆의 «한 낱말짜리» 답을 부르고 있습니다 — 연결됨/없음 · 0/N · 도는 중.
그래서 이 부류는 「기능이 없다」가 아니라 **「진단이 있는데 화면이 요약만 읽는다」**입니다.

```

# 🔵 격차 탐지기의 «화면» — 어떤 사실이 어디에 (총괄 큐 2번)

거절문이 사람을 «제 레인의 명세»로 보내는데, 그 명세는 「이름이 무슨 뜻인가」를 답하지
「지금 무엇이 비었나」를 답하지 않습니다. 그 간극만 적습니다.

## ① 탐지기가 «이미 아는» 사실 — 넷
```
어느 «갈래»인가      한 쌍이 어긋난 것 / 주어 쪽이 빈 것 / 목적어 쪽이 빈 것
무엇이 «있고 없나»    있는 쪽과 «없는 쪽»을 각각 이름으로 듭니다
그 격차의 «이름»과 «뜻» 또는 «다음 행동»   -> 이름표는 제 명세가 정본이고 표가 기계 판형입니다
🔴 «공허한가»        선언상 «애초에 생길 수 없는» 것인지를 따로 냅니다
```

## ② 그중 «화면에 있어야» 하는 것 — 셋. 그리고 셋째가 핵심입니다
```
✅ 이름 + 다음 행동   거절문이 이미 사람을 이름표로 보냅니다. 이름만 있고 «목록»이 없어서
                  운영자는 「무슨 뜻인지」는 알고 「내 것 중 무엇이 그건지」는 모릅니다
✅ 없는 «쪽»         주어 쪽이 빈 것과 목적어 쪽이 빈 것은 «반대 행동»입니다
🔴 «공허함»          「선언상 있을 수 없다」와 「있을 수 있는데 없다」가 갈려야 합니다
                  안 갈리면 운영자가 «선언이 금지한 것»을 채우려고 데이터를 찾습니다
                  📎 이 레인이 하루 종일 적은 부재 부류의 그 자리입니다 — 0 이 두 뜻인 자리
```
⛔ 어떻게 그릴지는 안 적습니다.

## ③ 어디에 — **«둘 다»입니다. 그리고 서로 다른 것을 답합니다**
```
거절이 나는 자리   지금 거절은 「이 격차에 «이름이 없다»」일 때 납니다.
                그 거절이 «어느 갈래·어느 타입·어느 술어»인지를 같이 들면,
                이름을 «어디에 적어야 하는지»가 그 자리에서 답해집니다
                -> 지금은 사람이 명세를 열고 «어느 줄을 더할지» 스스로 찾아야 합니다
목록            「지금 열려 있는 격차」는 거절이 아니라 «상태»입니다.
                이름 · 없는 쪽 · 공허함을 «한 줄에» 두는 목록이 그 자리입니다
🔴 그래서 하나로 합치면 안 됩니다 — 거절은 «작성자»의 물음(이름을 어디 적나)이고,
   목록은 «운영자»의 물음(무엇이 비었나)입니다
```

## 이 절이 «안 한» 것
```
⛔ UI 없음 · 코드 없음 · 값 없음 (무엇이 실제로 비었는지는 «안 쟀습니다» — 화면 얘기입니다)
🔴 ①은 탐지기 코드에서 읽었습니다. 명세(제 문서)가 아니라 «코드»가 무엇을 내는지를 봤습니다
```

# 🔵 「진단을 «누가» 쥐나」 — 남은 것을 갈랐습니다 (총괄 큐 2번)

⛔ 「안 불린다」를 「이어야 한다」로 읽지 않습니다. 그 함정이 오늘 나왔습니다(오버레이).

```
심박        🔵 «서버»가 쥡니다 — 프로세스가 사는지는 화면이 «계산할 수 없습니다»
           => 이으면 «새 사실»이 화면에 옵니다.  이어야 합니다

🔴 **그래서 「안 불리는 라우트」의 답이 둘로 갈립니다** — 서버가 진단을 쥔 것은 «이을 것»이고,

# ✅ 판정 (총괄) — **심박은 목록에서 «나갑니다». 잔량계 «하나»**

```
제 물음   심박의 «명부» 절반이 «운영자» 화면감인가, «총괄·배포»의 것인가
판정      «청중»이 답입니다:
         운영자   「내 일이 «움직이나»」   -> 큐의 첫 줄이 이제 답합니다
         배포·총괄 「선언된 프로세스 중 «무엇이 안 떠» 있나」 -> 심박의 넷 상태가 그 답입니다
=> 운영자는 «프로세스 이름»이 필요 없습니다. 그래서 이 목록에서 나가고 «배포 관심사»로 남습니다
```
🔴 **잔량계: «하나» — 계획 시험(쓰기 없는 진단)뿐입니다.**
아침에 다섯이었고, 셋은 «이어져서», 하나는 «다른 길로 답해져서», 하나는 «청중이 달라서» 나갔습니다.
