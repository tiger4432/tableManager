# 재대조 — `unplaced` 수리가 «맞는지»

> 총괄 라운드 `ontology_application_ruling.md` 04:4x · **읽기 전용, 코드 0줄**
> 앞 라운드: `task/APPLICATION_SCREEN_TRUTH_CHECK.md`

```
✅ ①  합계        맵 + unplaced = 소스.  웨이퍼 14장 전수 «14/14 정확»
✅ ②  헛울림      0 이어야 하는 자리에서 0.  reason 도 null
🔴 ③  「모른다」   «잴 수 있는데 포기했습니다». 그리고 화면이 쓰는 축이 바로 그 축입니다
✅ ④  화면↔서버   화면 글자가 서버 값과 «같습니다». 라벨도 정정됐습니다
```

---

## ✅ ① 합계 — 웨이퍼 14장 전수, 하나도 안 틀립니다

`by=wafer` 로 라우트를 부르고 소스(`inspection_run` · `void_obs`)에 각각 물었습니다.

```
wafer              소스검사 소스발견 | 맵검사 맵발견  미배치검사 미배치발견   합계
SYN-BW-001-01        30      21    |   27    20        3        1        OK
SYN-BW-001-02        30      21    |   29    20        1        1        OK
SYN-BW-001-07        30      14    |   29    13        1        1        OK
… (14장)                                                                  OK
                                                        합계 불일치 «0 / 14»
```
🔴 **앞 라운드에서 제가 「slot 01 은 3자리」라고 한 것까지 그대로 맞습니다** — 27+3=30.

## ✅ ② 헛울림 없음

```
SYN-BW-101-07   unplaced state=measured · scanned 0 · found 0 · reason «null»
```
0 이어야 하는 자리에서 0 이고, **0 일 때 사유 문구를 안 답니다.** 맞습니다.

## ✅ ④ 화면이 서버와 «같은 말»을 합니다

```
화면   「141칸 · 발견 13 · 검사 29 · bonding_log ∩ inspection_run 기준」
       「맵 밖 · 귀속 불가 — 이 행 축(bond_lot)으로는 … 0 이 아니라 «모른다»이다.」
서버    projections[bond] found 13 · scanned 29  /  unplaced.state "unknown" · 같은 message
```
📎 **앞 라운드에서 제가 지적한 라벨이 고쳐졌습니다** — 「검사 29」가 이제
「**bonding_log ∩ inspection_run 기준**」이라고 «스스로 말합니다».

---

## 🔴 ③ 「모른다」가 진짜가 아닙니다

### 가드
```python
if not (subject_column and identity_column and axis.column == identity_column):
    return {"state": "unknown", "reason": "row_axis_is_not_the_unit_subject", …}
```
행 축이 «웨이퍼 자신»일 때만 셉니다. `bond_lot ≠ base_id` 라 **항상 unknown** 입니다.

### 근거로 적힌 전제가 «거짓»입니다
독스트링: 「그 자리는 랏·설비·슬롯을 갖고 있지 않다」.
**orphan 은 `base_wafer_id` 를 갖고 있습니다.** 없는 것은 «공정 행»이지 웨이퍼가 아닙니다.

### 실측 — 셋 다 셀 수 있습니다
```
(a) 슬롯 지정 (= 화면이 부르는 방식)
    bond_lot=SYN-VOID-001 · slot=07  ->  웨이퍼가 «1개»로 정해진다 (SYN-BW-001-07)
    그 웨이퍼의 orphan = «1»                        -> 셀 수 있다

(b) 슬롯 없음 (랏 전체)
    랏의 웨이퍼 25장 · orphan 합계 = «27»            -> 셀 수 있다

(c) 진짜 귀속 불가는 무엇인가
    bonding_log 에 «행이 하나도 없는» 웨이퍼 = «0개»  (검사된 웨이퍼 2,630 전부 행이 있다)
    -> 「어느 랏인지 모르는」 자리는 지금 «하나도 없다»
```

### 🔴 그래서 이 화면에서는 unplaced 가 «영원히» 모른다입니다
```
화면이 부르는 것   /api/ledger/lot_map?row=SYN-VOID-001&slot=07&kind=void   (by 없음)
by 없음 -> 기본 축 = bond_lot -> 가드에 걸림 -> «항상 unknown»
```
**구현자가 찾은 2,525 void 중 이 화면이 셀 수 있는 것은 «0개»입니다.**
수리는 `by=wafer` 에서만 살아 있고, 화면은 그 축을 안 씁니다.

### 그리고 화면이 이미 웨이퍼 이름을 찍고 있습니다
```
같은 패널 안:  「07 / 25 · SYN-BW-001-07」
바로 아래:     「이 행 축(bond_lot)으로는 … 귀속시킬 수 없다」
```
**웨이퍼를 화면에 쓰면서 웨이퍼를 모른다고 말합니다.**

## 판정 요청 — 둘 중 하나입니다

```
A  가드를 «슬롯이 지정되면» 웨이퍼 축과 같게 본다
   슬롯이 웨이퍼를 하나로 정하므로 (a) 가 그대로 성립. 제일 작은 수정
B  unknown 을 유지하되 화면이 «by=wafer 로 한 번 더» 물어 옆에 붙인다
   서버 계약을 안 건드림. 대신 요청이 하나 는다
```
⛔ 어느 쪽이든 **제가 고를 것이 아닙니다.** 다만 **지금 상태는 「모른다」가 아니라
「안 물어봤다」**이고, 그 둘을 가르자는 것이 이 필드가 생긴 이유였습니다.
