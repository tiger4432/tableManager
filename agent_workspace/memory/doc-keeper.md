## 공통 (전 에이전트)

> **착수 규율 (사용자 지시 2026-07-27): 만들기 전에 이미 있는지 먼저 본다.**
> 문제를 만나면 **"이 시스템이 이미 이걸 하는 곳이 있나 · 이건 무엇과 구조적으로 같은가"**를 먼저 확인한다.
> 1차 참조는 `docs/architecture/PRIMITIVES.md`(기능→구현 카탈로그), 2차는 `docs/architecture/CODE_MAP.md`.
> 새로 만들 때는 **왜 기존 프리미티브를 재사용할 수 없는지 보고서에 명시**한다. 유사한 것이 있으면 **같은 이름·같은 형태**로 만든다.
> 실제 사례 — DOE 삭제 미반영은 `replace_map`(맵 Push가 쓰는 기존 연산)으로 해결되는데 클라에 차집합 계산 기계장치를 얹고 있었다.

> **언어 규약 (사용자 지시 2026-07-26): 에이전트가 산출하는 텍스트는 모두 영어로 쓴다.**

> ③ 서브에이전트에게 내리는 지시서·메시지 ④ 커밋 메시지.
> 대상 아님 — 사용자에게 직접 보이는 UI 문자열·토스트·에러 문구(한국어 유지), `docs/**` 프로젝트 문서, 기존 주석의 일괄 번역(건드리는 줄만 영어로).

- **함정**: 시스템 python으로 실행하면 psycopg2 부재 등으로 거짓 실패한다.
  **올바른 방법**: 모든 Python 실행은 conda `assy_manager` 필수 — `conda run -n assy_manager python <파일>` (예: `docs/history/gen_index.py`).
- **함정**: Windows 콘솔은 cp949라 한글/유니코드 출력에서 인코딩 에러가 난다.
  **올바른 방법**: `PYTHONIOENCODING=utf-8`을 앞에 붙여 실행.
- **함정**: `conda run`은 멀티라인 `python -c` 인라인 코드를 처리하지 못한다.
  **올바른 방법**: 코드를 스크립트 파일로 저장 후 파일 실행.
- **함정**: `/tmp`는 Windows python에서 보이지 않는다.
  **올바른 방법**: 세션 스크래치패드 디렉터리를 사용.

## doc-keeper 전용

- **함정**: 코드맵 라인 앵커를 diff 삽입 줄수로 산술 이동하면 틀린다(리팩터·삭제가 섞이면 오프셋이 어긋남).
  **올바른 방법**: 앵커는 항상 Grep 실측으로 갱신.
- **함정**: 구현 보고서가 "X 문서에 반영하라"고 지목해도 그 문서에 해당 서술 섹션이 없을 수 있다 — 엉뚱한 곳에 문장을 심게 된다.
  **올바른 방법**: 지목 문서에 해당 흐름 서술이 실존하는지 먼저 확인하고, 실제 서술된 문서에 반영.
- **함정**: 병행 에이전트의 미커밋 변경이 있는 상태에서 working tree를 읽으면 미병합 시프트가 섞여 들어간다. 착수 시점 `git status`가 clean이어도 **사이클 도중** 오염이 유입될 수 있다. 🔴 **오염되는 것은 앵커만이 아니다 — 서술(사실)도 같이 오염된다.** 2026-08-11 실제 사례 둘, 같은 라운드에서:
  ① `server/chain_replay.py`를 working tree로 읽었으면 **「R2도 이미 고쳐졌다」**라고 적었을 것이다. 그때 트리는 **틀린 것이 아니라 빨랐다**(그 변경은 20여 분 뒤 `53f9187`로 착지했다) — 그리고 **빠른 것과 틀린 것은 나중에 그 문서를 읽는 사람에게 구별되지 않는다.**
  ② 지시서가 준 앵커 `crud.py:3025`를 working tree로 검증해 **「안 맞는다」고 총괄에게 보고했고, 총괄이 그 책임을 받았다.** 앵커는 커밋(`d8bad66`·`53f9187`) 기준으로 **정확했고**, 내가 읽은 것은 다른 레인의 미커밋 파일이었다(그 레인은 `94954cb`로 착지해 앵커를 3195로 밀었다). **남의 잘못이라고 보고하기 전에 특히 이 기준을 지켜라.**
  **올바른 방법**: 커밋 대상 배치의 사실은 **앵커든 서술이든** 처음부터 `git show <커밋>:<file>` 기준으로 읽는다. **커밋 메시지와 트리가 충돌하면 커밋이 이긴다.** working tree 실측을 썼다면 종료 전 `git status`·`git log` 재확인 후 오염 파일만 재검증하고, 미커밋 상태를 근거로 쓴 문장에는 **어느 리비전 기준인지**를 문장 안에 남긴다.
- **함정**: 사이클 지시서의 "대상 배치" 목록과 실제 커밋 트리거 수가 어긋날 수 있다(병행 커밋이 목록에서 빠짐) — 목록만 따라가면 커밋이 문서화 누락된다.
  **올바른 방법**: 착수 시 `git log`에서 직전 정비 이후의 feat/fix 커밋을 전수 대조해 목록 밖 커밋을 식별하고 보고서에 명시한다.
- **함정**: 구현/조사 보고서가 "A와 B의 정책이 다르다"는 **대비 주장**을 하면 그대로 문서에 옮기기 쉬운데, 한쪽만 조사되어 실제로는 양쪽 동일한 경우가 있다(M1도 M2와 동일하게 `align_unavailable`을 처리하는데 M2 전용처럼 기술된 사례).
  **올바른 방법**: 차이·대비를 단정하는 서술은 **양쪽 모두를 직접 Grep으로 재확인**한 뒤 문서화한다. 한쪽만의 근거로 차이를 주장하지 않는다.

- ⭐ **함정**: 정정문을 «절 머리»에 쓰고 그 절이 접혔다고 여긴다. 독자는 위에서부터 읽지 않고 **검색으로 도착한다.** 실측(2026-08-23) — `ONTOLOGY_LEDGER_SETUP.md` 가 `:990` 에서 게이트를 「거짓이 됐다」고 부정하면서 `:1553`·`:1846`·`:1868` 에서 현재형으로 단언하고 있었다. 그중 `:1868` 은 **막힌 사람이 읽는 「흔한 실패와 해결」 표의 행**이라, 없는 필드를 점검하라고 보냈다.
  **올바른 방법**: 정정을 쓰기 «전에» 그 **술어를 파일 전체에 grep 하고 «건수»를 센다.** 1보다 크면 노트는 수리가 아니다. 이 라운드에서 지시받은 7건 밖에 «6건»이 더 있었고, 그중 넷은 같은 오류의 사본이었다.

- 🔴 **함정**: 「둘 -> 셋」처럼 **하나 늘려서** 개수를 고친다. 측정처럼 읽히지만 산술이다. 실측(2026-08-23) — 소비자 수를 증분했더니 **틀린 값이 나왔고, 원래 값도 같은 방식으로 틀려 있었다**: `ledger_journey.py` 는 「둘」일 때도 안 세어져 있었다. 실제는 모듈 넷·사이트 다섯이고, 그중 하나(`ledger_structure.py`)는 로더를 «안 부르고» 파일명으로 읽는다.
  **올바른 방법**: **델타가 아니라 집합을 다시 유도한다.** `grep -c` 로 호출을 세고, 「로더를 부르는 것」과 「선언을 읽는 것」이 같은 집합인지도 본다.

- ⭐ **함정**: 정정문 «안»에 심볼 이름을 기억으로 적는다. 거기가 독자의 경계가 가장 낮은 자리다. 실측(2026-08-23) — 내가 쓴 정정 노트가 `source_profile._RETIRED_PROFILE_FIELDS` 를 인용했는데 **그 심볼은 없다.** 그럴듯했던 이유는 «비슷한 게 둘 있어서»다: `setup_bundle._RETIRED_BINDING_FIELDS`(밑줄 有)와 `source_profile.RETIRED_BINDING_FIELDS`(밑줄 無)가 **서로 다르게 동작한다.**
  **올바른 방법**: 앵커는 **`grep` 출력에서 붙여넣는다.** 그리고 비슷한 심볼이 둘이면 **둘 다 이름 대고 동작 차이를 적는다** — 안 그러면 다음 독자가 다시 합친다.

- **함정**: 문서를 파이썬 스크립트로 쓴다. 실측(2026-08-23) — 배지 문자열의 `"🔴"` 는 파이썬 소스에서 짝 없는 서로게이트 둘이라 인코딩이 불가능한데, **열기는 쓰기 모드로 열려서** 441줄 파일이 4줄로 잘린 뒤 죽었다(git 인덱스에서 복구).
  **올바른 방법**: 문서 수정은 `Edit` 로 한다. 스크립트가 꼭 필요하면 **임시 경로에 쓰고 «성공하면» 옮긴다.**
