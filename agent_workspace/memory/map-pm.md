> **착수 규율 (사용자 지시 2026-07-27): 만들기 전에 이미 있는지 먼저 본다.**
> 문제를 만나면 **"이 시스템이 이미 이걸 하는 곳이 있나 · 이건 무엇과 구조적으로 같은가"**를 먼저 확인한다.
> 1차 참조는 `docs/architecture/PRIMITIVES.md`(기능→구현 카탈로그), 2차는 `docs/architecture/CODE_MAP.md`.
> 새로 만들 때는 **왜 기존 프리미티브를 재사용할 수 없는지 보고서에 명시**한다. 유사한 것이 있으면 **같은 이름·같은 형태**로 만든다.
> 실제 사례 — DOE 삭제 미반영은 `replace_map`(맵 Push가 쓰는 기존 연산)으로 해결되는데 클라에 차집합 계산 기계장치를 얹고 있었다.

> **언어 규약 (사용자 지시 2026-07-26): 에이전트가 산출하는 텍스트는 모두 영어로 쓴다.**
> 대상 — ① `agent_workspace/reports/**` 보고서 ② 코드에 새로 쓰거나 수정하는 **주석**
> ③ 서브에이전트에게 내리는 지시서·메시지 ④ 커밋 메시지.
> 대상 아님 — 사용자에게 직접 보이는 UI 문자열·토스트·에러 문구(한국어 유지), `docs/**` 프로젝트 문서, 기존 주석의 일괄 번역(건드리는 줄만 영어로).

- **함정**: 시스템 python으로 실행하면 psycopg2 부재 등으로 거짓 실패한다.
  **올바른 방법**: 모든 Python 실행은 conda `assy_manager` 필수 — `conda run -n assy_manager python <파일>` (예: `docs/history/gen_index.py`).
- **함정**: Windows 콘솔은 cp949라 한글/유니코드 출력에서 인코딩 에러가 난다.
  **올바른 방법**: `PYTHONIOENCODING=utf-8`을 앞에 붙여 실행.
- **함정**: `conda run`은 멀티라인 `python -c` 인라인 코드를 처리하지 못한다.
  **올바른 방법**: 코드를 스크립트 파일로 저장 후 파일 실행.
- **함정**: `/tmp`는 Windows python에서 보이지 않는다.
  **올바른 방법**: 세션 스크래치패드 디렉터리를 사용.

## map-pm 전용

- **함정**: 좌표 검증에서 **단사·범위·왕복 항등만** 보면 균일 오프셋을 절대 못 잡는다 — 셋 다 같은 함수의 자기 대조라 결함이 있는 `f`와 그 역함수가 모두 통과한다.
  **올바른 방법**: **독립 오라클과 키→값 단위로** 대조하고, "틀린 프레임으로 해석하면 몇 셀이 달라지는가"를 함께 낸다. 그 수가 0이면 픽스처가 아무것도 검증하지 못한 것이다.
- **함정**: 픽스처가 결함 축을 죽인다. `chip_x == chip_y`면 회전 시 피치 스왑 결함이, `minC == 0`이면 bbox 항 결함이 **원리적으로** 안 나타난다.
  **올바른 방법**: 이방성 칩 · rot 90/270 · back · `bbox != 0`을 **동시에** 만족하는 실맵을 쓴다.
- **함정**: 실패 주입 횟수를 세지 않는다. 1회 실패 후 회복 분기를 시험하려는데 조회를 2회 모두 막아 **그 분기를 한 번도 실행하지 않고** "해소"를 선언했다.
  **올바른 방법**: 주입 횟수를 명시적으로 세고, **결함 버전을 되돌려 넣어** 검증이 실제로 실패하는지 확인한다.
- **함정**: 서버가 provenance 토큰을 늘렸을 때 클라의 **어휘 목록만** 맞추면 끝난 것처럼 보인다. 실제로는 그 토큰을 **생산하는 표지 분기**가 따로 있다. `confirmed`(2026-08-06)는 표지가 `wafer_map_metadata`에 **저장되므로** 클라가 그 모양을 DB에서 직접 읽는데, `geometryDeclaration`에 분기가 없어 여섯 실측값을 그대로 읽고 **`declared`**를 냈다 — 토큰 누락은 정보를 잃지만 이쪽은 **정보를 지어낸다**(I4 사칭). 지시서가 목록 둘만 지목했고 그것이 더 작은 쪽이었다.
  **올바른 방법**: 토큰을 넣기 전에 **"이 토큰을 만드는 표지가 저장되는가"**를 먼저 묻는다. 저장되면 포트의 분기를 **같은 라운드에** 넣는다. 그리고 축이 여럿이면 축마다 확인한다 — 전체 메타 판정(`geometry_declaration`)과 축별 판정(`orientation_declaration`)은 **다른 함수·다른 표지**이고, 한쪽만 닫으면 나머지 절반이 닫힌 것처럼 보인다.
- **함정**: 어휘를 **개수**로 고정한 핀은 정당한 추가를 클라 결함으로 읽는다. 2026-08-06 기준 어휘가 **다섯 곳**에 열거돼 있었고 그중 둘이 개수 핀이었다. 한 파일은 자기 주석에 *"개수가 아니라 이름·위치로 고정한다"*고 적어 놓고 **두 줄 아래에서 다시 개수를 박았고**, 같은 자리가 세 번째로 터졌다. 규칙을 아는 것과 지키는 것은 다르다.
  **올바른 방법**: **구성원을 고정하고 개수는 고정하지 않는다.** 다만 핀을 지울 때 **무엇이 함께 사라지는지 변이로 재라** — 이번에 위치 핀만 남기자 없는 토큰 `'provisional'`을 끝에 붙인 변이가 **초록으로 통과했다**(4079/0). 경계는 계약(`contracts/*/client_harness.mjs`)의 **집합 비교**가 소유하게 두고, 파일마다 어휘를 다시 적지 않는다.
