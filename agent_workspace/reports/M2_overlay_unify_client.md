## 1. 설계 요약

```
소스 원본 (x,y) ─[소스 자신의 메타 프레임]─▶ 물리 좌표 ─[타깃의 현재 화면 컨트롤]─▶ 셀
```

핵심은 **`gridData`가 이미 물리 키(`${px}_${py}`)로 저장된다**는 사실이다. 렌더는 매 프레임
`(c,r) → getPhysicalCoords → coordKey`로 되짚어 그린다. 따라서 오버레이 셀도 **같은 물리 키**로
들고 있으면, 사용자가 화면 컨트롤을 어떻게 돌리든 **렌더 단계에서 메인 맵과 똑같은 규칙으로
같이 움직인다**. 물리 키는 소스 메타만으로 결정되므로 화면 조작에 불변이고, 화면 조작은 양쪽에
동일하게 적용된다. 메인 로드는 "소스 메타 == 현재 컨트롤"인 특수 케이스가 된다.

### 오버레이 전용 변환 코드는 없다 — 프레임 창(frame window)

변환 함수들은 규격을 DOM에서 읽는다. 오버레이 전용 식을 새로 쓰는 대신 **읽기 지점만 잠깐
갈아끼운다**:

- `physFrameOverride` (모듈 변수) + `physNum(key, domEl, dflt)` / `gridDimNum(...)` / `withPhysFrame(frame, fn)`
- 주입 지점은 **두 곳뿐**: `getTransformedPhysicalConfig`, `getWaferBoundingBox`
- `withPhysFrame`은 **동기 전용**(내부 await 금지 — 주석 명시)
- 기존 `parseFloat(v) || dflt` 규약(0 → 기본값) 그대로 보존

### 재사용한 함수 (신규 기하 코드 0줄)

| 함수 | 역할 | 비고 |
|---|---|---|
| `getCellFromVisualCoords` | 저장 (x,y) → 프레임 셀 (c,r) | bbox·start·invertY 포함 |
| `getPhysicalCoords` | (c,r) → 물리 (px,py) | screen shift 포함 |
| `getWaferBoundingBox` | bbox(minC/maxR) | `physNum`/`gridDimNum` 경유로 프레임화 |
| `getTransformedPhysicalConfig` | 회전별 칩 피치 스왑·back offset 부호 | `physNum` 경유로 프레임화 |
| `isCellInsideWaferFast` / `getScreenShift` | 위 함수들이 내부 호출 | 무수정 |
| `fetchGridMetaFor(table, mapId)` | `(target_table, map_id)` 쌍 메타 조회 | 메인 로드와 동일 경로 |

`projectCellsToPhys(cells, frame)`는 `loadExistingMap` 셀 루프(`:2683-2688`)와 **같은 두 줄,
같은 인자 순서**를 소스 프레임을 씌운 채 실행할 뿐이다.

### 신규/변경 함수

- `frameFromMeta(meta)` — grid_metadata → 프레임 기술자. **없는 물리 항목은 undefined로 남긴다**(현재 화면 값 폴백).
- `currentFrame()` / `resolveFrame(frame)` / `frameAxesKey(rf)` — 축 전부(회전·면·y반전·START·치수·물리 6종) 비교의 단일 근거.
- `projectCellsToPhys(cells, frame)` — 구 `overlayCellsToPhysMap` 대체.
- `deriveMapBinding(schema)` / `buildKeyFilters(keyColumns, mapKey)` — 서버 `derive_table_binding`·`build_key_filters`와 같은 규약을 `/tables/{t}/schema`에서 유도.
- `probeAlignDeclaration(...)` — **Phase 2 관문**(§5).
- `currentGeomSignature()` — **물리 파라미터 6종 추가(QA-B C7)**. §4-C에 실측 근거.

### 데이터 흐름 (addOverlayLayer)

① align 선언 probe(`limit=1`) → ② 소스 스키마→바인딩 유도 → ③ `/tables/{src}/data`(원본 좌표)
+ ④ 소스/타깃 메타 병렬 조회 → ⑤ 프레임 확정 → ⑥ 격자 규격 호환성 검사 → ⑦ align 요약 →
레이어(`rawCells`=소스 원본, `frame`=소스 메타, `cells`=물리 키 Map).

## 4. 증거 (라이브 브라우저 · 실 DB **읽기 전용**)

### 측정 방법 (오라클을 공유하지 않는 관측)

- **D(오버레이 셀)** = 오버레이 **표시/숨김 두 캔버스의 픽셀 차분**(셀 우상단 마커 영역). 색 가정 없음.
- **M(메인 맵 셀)** = 셀 좌하단 픽셀이 legend 색인 셀(값 텍스트·마커·워터마크 회피).
- 두 집합을 화면 상태의 **물리 키로 환산**해 비교. 환산식은 별도 재구현 오라클이며,
  **"M의 물리 집합이 모든 상태에서 불변"으로 자기검증**됨(§4-D).
- 이 창은 비표시라 `requestAnimationFrame`이 멈춰 캔버스가 얼어붙는다 → 탭 fronting + 측정 전
  명시적 강제 렌더(`grid-cols` change) 후 캡처. **이 함정을 못 잡았으면 "마커 0개"를 결함으로 오판할 뻔했다.**
- 안전판: `fetch` 셰임으로 **GET 외 전 요청 차단**. 세션 종료 시 `__blocked = []`
  (=비-GET 요청 **시도 자체가 0건**), `bonding_map/4B13` `updated_at` 불변(2026-07-24) 확인.

### D. 오라클 자기검증 + 서버 대조

독립 재구현 오라클(bbox·shift·물리식 재작성)로 **DB 원본 셀**에서 직접 계산:

| 대조 | 결과 |
|---|---|
| `aa223` 원본 139셀 → 타깃 프레임 → 물리 vs **앱이 그린 메인 맵** | **139/139 완전 일치, 차 0** |
| `AAA` 원본 90셀 → **AAA 자신의 프레임** → 물리 vs **앱이 그린 오버레이** | **90/90 완전 일치, 차 0** |

**서버 `/api/maps/overlay` 대조** (서버 응답의 타깃 프레임 (x,y)를 타깃 메타로 물리 환산):

| 조합 | 서버 | 클라 | onlyServer | onlyClient |
|---|---|---|---|---|
| `AAA`(270/back) → `aa223`(0/front) | 90, `origin: derived`, rot 270 flip x | 90 | **0** | **0** |
| `4B12`(270/front) → `4B13`(0/back, offset 0.1) | 177, `origin: derived`, rot 270 flip x | 177 | **0** | **0** |

**결론**: 두 구현이 결함 축이 살아있는 조합(rot270 · back · `chip_x≠chip_y` · `offset_x≠0` ·
`minC≠0`)에서 **완전히 일치**한다. 즉 (a) 현재 라이브 서버는 A1 수정이 반영된 코드로 돌고 있고,
(b) 클라 단일 구현이 서버의 정답을 재현한다. 어느 쪽이 옳은지 다툴 불일치가 **발생하지 않았다** —
서버를 옳다고 전제하지 않고 DB 원본에서 독립 계산한 오라클도 같은 값을 낸다(위 표).

## 5. Phase 2 이관 (조용히 빠뜨리지 않음)

1. **계측 보정(`align_overrides`)** — 메타로 유도 불가능한 데이터. 서버 소유 유지.
   Phase 1은 **적용하지 않으며**, 선언이 있으면 `align_override_declared`로 **명시 실패**(§4-E).
   라이브 config의 유일한 항목은 `__example_eds_fail_map`(주석 키)이라 현재 실선언 0건 → Phase 1 착지 가능.
2. **`dt_log` / `bonding_log` 오버레이** — 좌표 컬럼이 관례 밖(`tx/ty`, `bx/by`)이고 그 선언이
   `map_overlay_config.table_bindings`(서버 전용)에만 있다. 클라는 `/tables/{t}/schema`로 유도할 수
   없어 `binding_unavailable`로 **명시 실패**한다. **Phase 1 한계 = 이 두 테이블은 겹칠 수 없다.**
   (§6-①의 계약 제안으로 해소.)
3. **`align_applied.offset` 실값 표기** — Phase 1 클라 요약은 항상 `(0,0)`. 순수 평행이동 케이스의
   실수치 표기는 보정 계약 확정 후.
4. **프레임 스택(`openMapFrame`/`popMapFrame`) 라이브 회귀** — 구조상 정합(§3)이나 이번 라운드에
   실행하지 못함. 다음 라운드 필수 항목.

## 6. 서버 계약 제안 (구현하지 않음 — 총괄 판단용)

① **맵 바인딩 노출**: `GET /tables/{t}/schema` 응답에 `map_binding: {x, y, val, key_columns}` 추가
(또는 `GET /api/maps/bindings?table=`). 서버 `resolve_binding`이 이미 계산하는 값이며, 이것만
있으면 위 Phase 2-② 한계가 사라지고 클라 유도 로직(`deriveMapBinding`)이 **선언 소비로 축소**된다.

② **보정값 계약 (Phase 2 본체)**: 정렬된 좌표가 아니라 보정값만.
`GET /api/maps/align?target_table=&target_key=&source_table=&source_key=&eqp=`
→ `{ origin: "declared"|"default"|"none", dx, dy, rotation, flip, note }`
클라는 이 값을 **물리 좌표에서** 적용한다. 근거를 계산할 수 없으면 `align_unavailable`.
현재 클라는 이 정보를 얻으려고 `/api/maps/overlay?limit=1`을 probe로 쓰고 있다 —
셀 1건을 낭비하는 임시 수단이며, ②가 생기면 즉시 대체한다.

③ **삭제 금지 확인**: `/api/maps/overlay`는 유지했다(`bonding_plan.py` 가용량 산출이 같은 정렬
모듈을 쓴다). 서버 측 A2(선언 경로의 bbox 누락)는 여전히 유효한 서버 백로그다.

## 7. 남은 판단거리 (총괄 결정 요청)

**소스 메타에 물리 규격이 없을 때 프레임을 "얼릴지 띄울지".**
현재는 **띄운다**(미등록 항목은 매 렌더 현재 화면 값으로 재해석). 칩 툴팁이 문자 그대로
"현재 화면 규격으로 해석"이라 의미가 일치하고, C7 시그니처가 **실제로 일하는** 유일한 경로다(§4-C).
대안은 추가 시점의 화면 값을 스냅샷해 **얼리는** 것 — 그러면 오버레이가 메인 맵처럼 영구 고정되지만
`syncOverlayGeometry`의 재투영이 항상 항등이 되어 시그니처가 사실상 죽는다.
**소스 메타가 완전한 정상 경로에서는 어느 쪽이든 동작이 같다**(라이브 4맵 전부 물리 6종 등록 완료).

## 8. 교훈 제안 (client-pm 교훈 파일용 — 직접 추가하지 않음)

- **함정**: 비표시(비컴포지팅) 브라우저 창에서는 `requestAnimationFrame`이 발화하지 않아
  `scheduleRenderGridCanvas`의 `isRenderScheduled` 플래그가 **영구 true로 고착**된다. 캔버스가
  얼어붙은 채 모든 후속 렌더가 조용히 사라지고, 검증자는 이를 **구현 결함으로 오판**한다.
  **올바른 방법**: 캔버스 검증 전 탭을 fronting 하고, 측정 직전 동기 렌더 경로를 명시적으로 태운다
  (`inputsToRedraw` 소속 입력에 `change` 디스패치). "마커 0개"는 렌더 정지부터 의심할 것.
- **함정**: `phys-*` 입력은 `inputsToRedraw` 목록에 **없어** 값만 바꾸면 재렌더가 예약되지 않는다.
  이 상태로 캔버스를 캡처하면 낡은 화면을 새 상태로 착각해 측정이 오염된다(실제로 1회 오염됨 —
  같은 상태 2회 측정이 불일치해서 발견).
  **올바른 방법**: 물리 파라미터 변경 후에는 반드시 명시적 렌더를 유발한 뒤 관측한다.
- **함정**: 캔버스 픽셀로 셀 상태를 읽을 때 값 텍스트·FRONT/BACK 워터마크·웨이퍼 원·원점
  하이라이트가 중앙/중앙부 픽셀을 오염시킨다.
  **올바른 방법**: 색 판정은 셀 **좌하단**에서, 오버레이 마커는 **표시/숨김 차분**으로 — 색 가정을
  아예 없애면 legend 색과 오버레이 팔레트가 충돌해도 무관해진다.
- **함정**: 좌표 검증 픽스처를 `40x40 · chip 7/7 · rot0`(등방 · `minC=0`)으로 고르면 피치 스왑 항도
  bbox 항도 **원리적으로 0**이라 어떤 결함도 드러나지 않는다.
  **올바른 방법**: `chip_x≠chip_y` · rot 90/270 · back · `offset≠0` · `minC≠0`을 **동시에** 만족하는
  실맵(29x25 chip11/13, 27x21 chip12/16)을 쓴다. bbox의 `minC`를 실제로 출력해 0이 아님을 확인할 것.
