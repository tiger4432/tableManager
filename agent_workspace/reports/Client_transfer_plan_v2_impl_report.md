## 6-b. 2차 배치 (추가 지시 ①~⑨)

### 6-b-1. DOE STACK — **다중 구간 지원** (서버 계약 §0-2-bis 배선)

| 요구 | 구현 |
|---|---|
| ① 한 칸에 다중 구간 (같은 자재) | STACK 입력은 **자유 텍스트 그대로**. `1, 2-15, 16`을 파싱하지 않고 `stack_band`에 원문 저장 |
| ② 행을 나눠 다른 자재 | DOE 펼침 안 **`[+ 구간]` 버튼 하나**. 구간마다 자재·소요·knob가 따로 |

- **DOE 행의 단위 = `(값, STACK 구간)`**. `S.doe: Map<value, Band[]>`, `Band = {seq, stack, need, materials[], knobs[]}`.
- **`band_seq`는 `max+1`, 삭제해도 재번호하지 않는다** — 재번호하면 자식 `map_doe_source`가 고아가 된다. 실증: `[1,2]` → seq1 삭제 → `[2]` → 추가 → `[2,3]`.
- **`stack_band`는 비키 자유 텍스트** — 라벨을 고쳐도 자재가 그대로 붙어 있다.
- 접힌 행은 구간이 여러 개면 접어 요약: `구간 2개 [1, 2-15, 16 / 17-20] · 자재 2매 · 43 / 290`.
- 자재 목록 그룹 단위도 **(값, 구간)**.
- **UI 추가량은 버튼 1개**(`[+ 구간]`).

**🎉 스톱갭 제거**: 서버가 `map_doe`/`map_doe_source`를 확정·적용해 `knobs.__stack`/`__materials` 동반 보관과 `DOE_CODEC`을 **전부 삭제**했다. 폐기된 `transfer_plan` 헤더 테이블 업서트도 제거.
**키 조립 지점은 2개 함수뿐**: `doeRowKey(value, seq)` · `doeSourceRowKey(value, seq, lot, slot)`.

### 6-b-2. 오버레이 → 실맵 가져오기 (신규)

| 장치 | 내용 |
|---|---|
| `S.doeServerLoaded` | 서버 상태를 **성공적으로 읽었는가**. 거짓이면 prune 자체를 실행하지 않는다 (요구 ⓐ) |
| `S.serverKeys.{doe,source}` | 로드 성공으로 채워지고 업서트 성공으로 늘고 삭제 성공으로 준다. **삭제 후보 = `serverKeys − keep`** |
| 교집합 가드 | 후보 ∩ 실제 서버 행만 삭제. `keep`이 비어도 `serverKeys`가 비면 **대상 0** — 공집합은 "전부 지워라"가 아니라 **"모른다"** |
| 응답 절단 검사 | 조회가 절단되면 "안다"고 주장하지 않고 **로드 실패로 강등** |
| 빈 catch 제거 | prune 실패는 예외를 던지고 호출부가 **경고 토스트**로 표면화 |

**ⓑ 실패를 상태로 보존**: `S.doeServerLoaded=false` 유지 + 헤더 `⚠ 서버 상태 미확인` + 경고 토스트.
**ⓒ 초안이 있어도 서버 로드 건너뛰지 않기**: `if (!hadDraft …)` 제거. **항상** 서버를 읽고, 서버에 행이 있으면 **공유 테이블이 정본**(다른 세션 저장분 보호). 초안이 달랐으면 조용히 버리지 않고 고지.

**🆕 검증 중 발견한 형제 결함(같이 고침)**: 삭제만 막았더니 **쓰기가 남의 행을 덮어썼다.** 로드 실패 후 편집하면 `band_seq`가 1부터 다시 매겨져 서버의 `…|F|1`을 업서트로 덮어 `stack_band`·`qty_total`이 날아갔다(1차 주입 테스트 실측). → **`doeServerLoaded`가 거짓이면 쓰기도 보류**(1회 재로드로 자동 회복 시도) + 고지.

## 12. 교훈 제안 (client-pm 메모리 — 총괄 승인 후 반영)

- **함정**: 여러 맵이 공유하는 메타 테이블을 **식별자 일부**로만 조회하면 남의 행을 집어온다. `limit=1`이 붙어 있으면 중복 사실조차 드러나지 않는다.
  **올바른 방법**: 메타 조회는 **식별자 전체 쌍**으로 걸고, `limit`을 기대치+1로 두어 **중복이면 경고**한다.
- **함정**: 목적이 다른 두 기능이 **같은 입력 위젯을 재사용**하면, UI를 갈라 놓아도 내부에서 같은 경로를 타 한쪽이 다른 쪽 상태를 파괴한다. 모드 토글로 의미를 바꾸는 방식은 **숨은 상태**를 만들어 문제를 키운다.
  **올바른 방법**: **DOM부터 분리**하고 경로도 분리한다. 보조 기능은 자기 선택기를 갖고 주 상태를 **읽기만** 한다. "어느 버튼을 눌렀는지가 곧 의도"인 구조는 확인창도 모드도 필요 없다.
- **함정**: 리팩터링으로 블록을 통째로 교체할 때 그 안의 **작은 공용 헬퍼**가 같이 사라져도 `try/catch`가 삼키면 기능이 **조용히 죽는다**. 화면은 정상으로 보이고 저장만 안 된다.
  **올바른 방법**: 블록 교체 후 **삭제된 심볼을 grep으로 확인**한다. 1차 저장소의 `catch`는 `console.warn`에서 멈추지 말고 **사용자에게 보이는 신호**까지 올린다.
- **함정**: 브라우저는 **백그라운드 탭의 `setTimeout`을 throttle**한다. 알림·자동 해제의 수명을 타이머에만 맡기면 복귀 시 무한 누적된다.
  **올바른 방법**: 수명은 **만료 시각을 정본**으로 두고 `Date.now()` 비교로 판정한다. `visibilitychange` 훅으로 복귀 즉시 정리하고, 반복 이벤트는 집계, 상한을 둔다. 검증은 `setTimeout`을 무력화해 재현한다.
- **함정**: "현재 화면에 없는 것 = 서버의 잔재"로 단정하고 삭제하면, **조회 실패 한 번이 전량 삭제로 증폭**된다. 공집합이 "전부 지워라"처럼 동작한다.
  **올바른 방법**: 삭제는 **"있다고 직접 확인한 것"** 에만 한다 — 로드 성공을 상태로 보존하고, 그때 얻은 키 집합과의 차집합만 지운다. 조회가 절단됐으면 "안다"고 주장하지 않는다. **그리고 상태를 모를 땐 삭제뿐 아니라 쓰기도 멈춘다** — 블라인드 업서트가 남의 행을 덮어쓴다.
- **함정**: 자기 산출물을 자기 함수로 되읽어 대조하는 테스트(왕복·개수·범위)는 **균일 오프셋·일괄 변환 오류를 원리적으로 못 잡는다** — 같은 변환의 자기 대조라 전부 참이 된다.
  **올바른 방법**: **앱 밖의 독립 오라클**(별도 클라이언트로 읽은 원천 데이터)과 **직접 손으로 계산한 기대값**을 쓰고, 개수가 아니라 **좌표·키 같은 식별 값 단위로 대조**한다.
- **함정**: 파일을 `open(path,'w')`로 연 뒤 쓰기에서 예외가 나면 **원본이 0바이트로 잘린다**(열림 시점에 truncate). 인코딩 오류처럼 늦게 터지는 실패에서 특히 위험하다.
  **올바른 방법**: 문자열을 **먼저 인코딩해 검증**하거나 임시 파일에 쓴 뒤 **원자적 교체**한다. 되돌릴 수 없는 산출물은 편집 전 사본을 둔다.
