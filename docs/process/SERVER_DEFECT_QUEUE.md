🔴 **낱개로 고치지 말 것.** §3 의 부류를 먼저 보고, 그 부류의 정본을 고친다 (소유자 상설
   「부류에서 판정한다」). 같은 줄이 등급표와 부류표에 «둘 다» 나오는 것은 그래서다.

### 🔴🔴 0-bis. **줄마다 「잰 것」인지 「인용한 것」인지 적는다** (2026-09-06 신설)

이 대기열의 줄은 «주장»이다. 그리고 실측 문서에서 옮겨 적는 순간 **그 주장의 근거가 여기 없다.**

```
✅ 잰 것    큐에 넣기 «전»에 그 술어를 코드에 대고 확인했다        -> 착수 가능
⚠️ 인용     실측 문서의 문장을 «그대로» 옮겼다                    -> 착수 «전»에 확인 한 걸음
```

#### 🔴 오늘 이것이 «통제된 비교»로 나왔다 — 같은 문서 · 같은 시간 · 같은 손
```
L-4  내가 «직접 재고» 넣었다   -> purge 블록에 create_audit_log 없음을 확인. 전제가 «섰다»
L-3  «인용만 하고» 넣었다      -> 재 봤더니 두 경로 «다» 감사 로그를 쓴다. 전제가 «거짓»
L-5  «인용만 하고» 넣었다      -> 아직 안 쟀다. 같은 위험
```
**다른 변수가 하나도 없다.** 「재고 넣었나」 하나다.

#### 왜 이것이 «비싼가» — 인용은 라운드를 태운다
```
레인은 큐의 줄을 «전제»로 읽고 짓기 시작한다. 전제가 거짓이면
   ① 없는 결함에 라운드가 간다
   ② 그리고 레인이 「지시대로 했는데 안 됩니다」가 아니라 «전제가 다릅니다»로 답해야 겨우 잡힌다
      -> 그 문화가 없으면 «안 잡힌다»
```
🔵 이 저장소는 그 문화가 «있다». 오늘 레인 셋이 내 전제를 넷 잡았다. 그러나 그건
   **에너지를 쓰는 안전망이지 규율의 대체물이 아니다.**

#### 그래서
```
① 줄을 큐에 «넣을 때» 「잰 것」/「인용」을 표시한다
② 「인용」인 줄의 착수 첫 걸음은 «수리»가 아니라 «확인»이다
③ 확인이 전제를 깨면 -> 줄을 «지우지» 말고 «갈래»를 적는다 (L-3 이 그 예다)
   틀린 것은 대개 «문장»이지 «항목»이 아니다
```

```
③ 철회 후보가 얼마나 «쌓이는가»        리플레이가 보고만 하고 방치한다.
                                     🔴 물음은 수가 아니라 «세는 계기가 있나»이고, 없으면 그게 결함이다
④ 아웃박스 다섯 역할을 «가를 것인가»    C-5. 큰 건이라 재고 올린다 — 아직 판정 안 했다
⑤ 매퍼 «모집단»                       추적되는 것 11(샘플 9 + 실물 2). 운영은 자기 매퍼를 쓴다.
                                     즉 계약을 어길 수 있는 인구가 저장소에서 «안 보인다»
```
⚠️ **①③⑤ 는 「없다」로 읽히면 안 된다.** 안 센 것과 없는 것은 다르다.
