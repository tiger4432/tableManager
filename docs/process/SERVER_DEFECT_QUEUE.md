## 0. 읽는 법 — 등급이 순서를 정한다

```
등급 0  «사라진다»      데이터·기록이 없어진다. 화면을 만들어도 안 고쳐진다   -> 제일 먼저
등급 1  «거짓을 말한다»  화면이 참이 아닌 문장을 낸다. 운영자가 틀린 판단을 한다
등급 2  «안 들린다»      값은 만들어지는데 볼 자리가 없다. 마지막 홉이 없다
등급 3  «인자가 안 간다»  화면이 고른 것이 전선을 못 건너 서버 기본값이 항상 이긴다
등급 4  «구조»          위 넷을 «다시 만들어 내는» 자리. 낱개를 고쳐도 또 생긴다
```
🔴 **이 등급은 제가 정한 것이 아니라 실측 넷이 각자 «따로» 도달한 것이다** — D·E·F·W1 의
   우선순위 절이 전부 「멈춤 > 거짓 > 안 들림」으로 끝났다. 그 위에 «소실»을 얹었다.

🔴 **낱개로 고치지 말 것.** §3 의 부류를 먼저 보고, 그 부류의 정본을 고친다 (소유자 상설
   「부류에서 판정한다」). 같은 줄이 등급표와 부류표에 «둘 다» 나오는 것은 그래서다.

## 6. ⚰️ 도달 불가 — **살아 있는 결함으로 세지 않는다**

grep 에는 살아 보이고 실행에는 없는 것들. 지울 것을 셀 때만 본다.
```
운영 기동의 asyncio.to_thread 재시도 경로 · refreshHealthStrip 계열 카드 둘
HTML 그래프 팔(공개 API 넷 + TableEdge) · _default_is_header 매트릭스 · is_header_fn 축
GeneralUpdateBatch.silent(인제션 경로) · 진행 페이로드 status 칸 · directory_watcher debug 10줄
VERDICT_PORT_CONFLICT(5자식 중 1) · 라우트 열거의 WS·mount 사각(실물 0)
terminal_finding_point_projection(decode_node_id 가 그 가지에 못 감)
```
🔴 **`logger.debug` 열 줄은 «화면 안건이 아니다»** — 응용 레인 판정: 운영자의 답은 화면에 있고
   로그는 «고치는 사람»의 재료다. 로그 위생 안건이고 별건이다.
⚠️ 다만 그중 **하나는 화면에 닿는다**: 옮기기 실패가 «원본 경로로 폴백»해서 기록의 경로가
   «없는 파일»을 가리킨다 (F-17 과 같은 자리). 로그를 켜도 안 고쳐진다.
