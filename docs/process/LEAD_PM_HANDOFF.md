## 1. 내 역할

**기획부장.** 직접 코딩하지 않는다(병합 검수 중 소규모 통합 수정은 허용). 하는 일은 넷이다:

1. **지시서를 쓴다** — 요청을 분해해 도메인 PM에게 위임
2. **주장을 내가 직접 검증한다** — 에이전트가 낸 수를 옮기지 않고 **다시 잰다**
3. **적대적 QA를 붙인다** — 등급을 착수 **전에** 선언
4. **검수 후 커밋한다**

📌 **에이전트가 내 지시를 거절하면 대개 에이전트가 옳았다.** 2026-07-31 하루에만 다섯 번 그랬고 전부 에이전트가 맞았다. 거절을 설득하지 말고 **근거를 읽어라.**

## 3. 핵심 가치 — ⭐ 모든 판정의 축

> **정본은 [`SYSTEM_OVERVIEW §1`](../overview/SYSTEM_OVERVIEW.md)이다.** 아래는 요약이고, 상충하면 SSOT가 이긴다.

### 3-1. 이 시스템이 무엇을 위해 있나

AssyManager는 **전산 인프라가 취약한 R&D 현장**을 위한 데이터 관리 플랫폼이다. 궁극 목적은

> **불완전한 현장 데이터를 사람이 최소 공수로 교정하여, 신뢰할 수 있는 온톨로지/지식 그래프로 축적하는 것.**

🔴 **그리드·테이블은 최종 산출물이 아니라 「교정 표면(Correction Surface)」이다.** 표를 예쁘게 만드는 일이 목적이 아니라, **사람이 진실을 넣는 자리**를 좋게 만드는 일이 목적이다. 기능 판정이 갈릴 때 이 문장으로 돌아온다.

```
다양한 로그 → 파서(정규화) → 체인(파생·연결) → 레이어드 저장(자동값)
  → 사람의 최소공수 교정(우선순위로 승리) → 실시간 신뢰 전파
  → 온톨로지 반영 → 객체 중심 추적(불량 WF 선택 → 연관 공정 이력 전부 소환)
```

### 3-2. 5대 핵심 가치 (우선순위순)

| # | 가치 | 무엇이고 왜 그 순위인가 |
|---|---|---|
| **1** | **최소 공수 교정** | 불완전 데이터를 사람이 **가장 적은 손으로** 진실로 바꾼다. Human-in-the-loop이 설계의 중심이다 |
| **2** | **온톨로지/지식 그래프** | **최종 목적지.** 교정된 진실이 그래프에 반영되어 객체 중심 추적이 된다 |
| **3** | **실시간 신뢰 전파** | 1→2를 잇는 **척추**. 반영이 안 믿기면 **교정이 멈추고 온톨로지가 틀린 채 굳는다** |
| **4** | **다중 소스 레이어링** | 1·2를 떠받치는 **메커니즘**. 한 셀에 여러 출처를 겹쳐 보관하고 **수동 값이 자동 값을 이긴다** |
| **5** | **변경 이력 추적** | 모든 교정의 **계보**이자 그래프 신뢰의 근거 |

**계기(정본, 사용자 2026-07-29 교체): 완료까지의 상호작용 점수** — 마지막 성공 저장 이후 누적된 **키입력 1 · 마우스 3 · 화면이동 5**의 합. 「최소 공수」를 에두르지 않고 직접 재는 유일한 값이라 **낮을수록 좋다.**
⚠️ **소급 산출이 불가능하다**(과거 세션에 클릭 로그가 없다) — **교정 표면을 고치기 전 기간이 유일한 "before"다.** 비율은 반드시 커버리지(`measured_ratio`)와 함께 읽는다. **미계측은 0이 아니다.**
⚠️ 무변경 저장은 `effort_recorded:false`를 돌려주고 그 공수는 **다음 성공 저장에 합산**된다 — 이 게이트가 없으면 **두 번 시도한 교정이 가장 낮은 점수**를 받아 계기가 목적과 정반대로 작동한다(QA 실측).
보조 계기 **재교정률**은 2026-07-29에 강등됐다(대량 트랜잭션 포함 여부로 2.01%↔13.13%, **6.5배 희석**).

**두 축의 특수성** — 현장 로그 형태가 매우 다양해 **파서 관리**가 시스템 수명을 좌우하고, 데이터 종류가 방대해 **체인 관리**의 정합성이 온톨로지 품질을 좌우한다.

### 3-3. 오늘의 일이 어디에 붙는가

가치 4(레이어링)가 **오늘만 세 번** 나왔다 — enrichment 자동확정 · 가상 조인 충돌 해소 · M3 맵 메타 자동. 셋 다 **낮은 우선순위로 써서 사람이 항상 이긴다**는 같은 문장 위에 서 있고, 그래서 셋 다 특별 분기가 없다. **새 자동 쓰기를 만들 때 이 자리를 먼저 본다.**

가치 3(실시간 신뢰 전파)이 오늘의 「조용한 실패」들이 왜 중대한지를 설명한다 — 초록 버튼에 행 0이면 **반영을 못 믿게 되고, 그러면 교정이 멈춘다.**

### 3-4. 표현 계층의 가치

**가독성은 기능이다** — 작은 글씨는 없느니만 못하다.
**UI는 절대 복잡하면 안 된다** — 교정 표면이 어려우면 가치 1이 무너진다.

## 3-A. 맵 도메인 규칙 (핵심 가치가 아니라 **맵 기준**이다)

> 사용자 확정 2026-07-31, 보드 `a64f98e` — 구 좌표 규약보다 위. **§3의 5대 가치와 다른 층이다.**

1. **유효 다이 영역은 항상 물리 WF 내 상대 위치를 보존한다** — 유효 다이는 맵 기하 메타(WF 직경·셀 크기·offset)와 **한 몸**. 회전 중심은 유효 다이와 무관하고 기하 메타에만 의존. 유효 다이를 불러올 때 **기존 기하 메타를 유효 다이의 것으로 갈아끼운다**
2. 회전·반전은 **물리 WF 중심** 기준
3. `START X,Y`는 현재 표기된 셀에 좌표를 매길 **기준**이고, 유효 다이 영역의 최소 X,Y에서 시작한다
4. **유효 영역 및 맵 기하를 바꾸는 행위는 기존 셀 좌표를 변경하지 않는다**
5. **회전·반전·Y축 반전은 셀 좌표를 변경한다**
6. 서로 다른 메타의 맵 오버레이는 각자의 회전·반전·셀 크기를 고려한 **WF 내 물리 좌표**로

🔴 **4와 5는 정반대 연산이다.** 기하 변경은 **DB 좌표를 붙잡고 캔버스 위치를 옮기고**, 방향 변경은 **다이를 붙잡고 번호를 옮긴다.** 이 짝이 일주일 내내 빠져 있어서 「기준 선언이 좌표를 바꾸는가」가 반복 재론됐다.

**닫은 문장(사용자):** 「유효 다이가 없으면 유효 다이 영역이 곧 웨이퍼 원이다」 — 선언된 기준이 없으면 영역이 곧 원이므로, 기하 변경과 지정이 **같은 연산**이다.

### 3-A-2. 좌표 공간 이름 (2026-07-31 개명 — 둘은 정반대 뜻이었다)

| 구 | 신 | 무엇 |
|---|---|---|
| `getVisualCoords` | **`getDbCoords`** | **저장되는** 좌표 |
| `getCellFromVisualCoords` | `getCanvasCellFromDb` | |
| `getPhysicalCoords` | **`getDieIndex`** | mm가 아니라 **셀 인덱스** |
| `getCellFromPhysicalCoords` | `getCanvasCellFromDieIndex` | |
| `xv`/`yv` | `dbX`/`dbY` | |

**`mm`은 일부러 비워 뒀다** — 규칙 6과 defect 표기가 진짜 밀리미터 공간을 요구하는데 **클라에는 그 공간이 없다**(원 판정조차 700×700 픽셀). 서버 `PhysicalWaferEngine`만 mm로 일한다.
⚠️ **개명 개수는 인용 금지** — 46 vs 67, 둘 다 재현 안 됨.

### 3-A-3. 장기 — defect 데이터 모양 (사용자)

**셀 좌표 + 맵 메타 + in-chip 상대 좌표(0 ~ cell size).** in-chip은 **절대 길이라 피치 의존**이다 — 7mm 칩의 3mm ≠ 15mm 칩의 3mm. 그래서 in-chip 좌표는 피치 경계를 못 넘고 **절대 WF mm를 거쳐 다시 나눠야** 한다. **몫이 셀, 나머지가 in-chip.** 오늘 나머지를 버리면 그 경로를 통째로 다시 연다.

**② 「빈칸일 때만 채운다」가 셋** — enrichment 자동확정 · 가상 조인 충돌 해소 · M3 맵 메타 자동. 셋 다 **낮은 우선순위로 써서 사람이 항상 이긴다**.

**③ 「못 봤다」가 「없다」로 읽히는 것** — F9 전체가 이것 때문에 존재한다. 조회 실패를 빈 목록으로 뭉개지 말 것.

**④ 조용한 실패가 시끄러운 실패보다 나쁘다** — 오늘 실증: 소급 트리거가 **200 「queued」를 내고** 스케줄러 스레드에서 죽었다. 초록 버튼, 행 0, 오류 표면 없음.

### 6-2. 🔴 측정 규율 (내가 제일 많이 틀린 자리)

- **커밋 메시지의 수를 옮기지 마라.** 트리 기준이라 미커밋 파일을 포함한다(「1739」는 미커밋 32건 포함, 실제 1707)
- **하네스는 자기 점수를 스스로 찍는다.** `grep -c "✗"`는 **요약줄까지 세서 +1** 한다(41을 42로 "정정"해 커밋에 박았다)
- **내 정정도 측정이다** — 같은 문턱을 넘어야 한다
- **한 박스에서 잰 값으로 다른 박스를 설명하지 마라** — 이 컴퓨터는 시뮬레이션, 운영은 다른 기계다
- **표시값은 「썼는가」의 증인이 아니다 — 층만 증인이다.** 우선순위 4가 2 아래에 쓰면 화면은 안 변한다
- **주석의 플랜 서술은 데이터가 아니다** — `EXPLAIN (ANALYZE, BUFFERS)`로 직접 재라
- **문서 지시서엔 사이트 목록 말고 틀린 문장을 줘라.** 3곳 지시 → 실제 5곳. 그리고 **누락은 grep에 안 걸린다**(옛 범위를 그대로 적은 색인 줄)
- **`FEATURE_CHECKLIST §1`에 행이 없으면** 그 기능은 회귀 검사에서 **구조적으로 빠진다** — 어떤 grep으로도 안 나온다

### 6-3. 🔴 하네스·테스트 함정

- **픽스처가 상쇄 구간에 앉으면 수리 전에 이미 초록**이다. 보존을 채점하기 **전에** 「이 입력이 결함을 재현하는가」를 단언하라
- **자기 무력함을 단언하는 테스트는 영원히 통과한다**(`assert already_derived == 0`)
- **빈 문자열 픽스처는 저장 경로를 지나면 비어 있지 않다**(`cast_value_by_type`이 `""`를 NULL로)
- **공유 인터프리터에서 「import 되는가」는 테스트 가능한 속성이 아니다** — 다른 테스트 파일의 `sys.path` 삽입이 보인다. 자식 프로세스로 확인하라
- **`server/scripts/`는 일방통행 문** — 스크립트는 `server/`를 부트스트랩하지만 그 반대는 없다. 런타임이 쓰는 로직은 `server/`에, `scripts/`엔 얇은 CLI만
- **대조 변이(consistent rename / comment-only)를 돌려라** — 탈출해야 정상. 안 탈출하면 탐지기가 소스 텍스트에 얹혀 있다

### 6-4. ❓ 열린 것 / 미검증

- **운영 서버가 `f3fd785` 이전 프로세스다** — 재기동 필요(후순위, 사용자 지시). F9 화면과 소급 진단 둘 다 그것에 걸려 있다
- **가상 조인이 운영에서 도는 걸 아무도 못 봤다** — 시뮬에서만 확인. 운영엔 선언이 따로 있다
- **`line_model_owner_attribution`은 못 켠다** — 타깃이 `owner`인데 뷰가 `owner`를 SELECT 안 한다. 뷰 쿼리 수정 선행 (사용자: 「나중에」)
- **CSV 내보내기가 가상 컬럼을 빠뜨린다** · **미상 행을 찾을 필터가 없다**(서버측 수리라야 함) — 대기열 26
- **`?cols=<가상컬럼>` 검색이 테이블 전체를 돌려준다** — 그 컬럼을 검색했다고 말하면서 (선행 결함)
- **`cell_overwrites`가 커지면 소급 건수가 느려진다** — 인덱스는 `manual_priority_source`가 아니라 **부분 복합**이라야(`WHERE ... IS NOT NULL`). 1,000만 overwrite에서 ~1.5s 추정, 미착수
- **`cell_sources`에 죽은 인덱스 2개, 약 2.0GB** — 보고만 됨, 손대지 않음
