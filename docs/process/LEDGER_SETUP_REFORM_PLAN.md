# 셋업 개혁안 — 소스→원장→온톨로지를 한 화면에서 (2026-08-15)

> 근거: 소유자 구술 P-01~04(`SETUP_PAIN_LOG.md`) + 전 시나리오 검토
> (`LEDGER_SETUP_SCENARIO_REVIEW.md`). 판정 정본 R-2026-08-15-M/N/O.
> 소비 화면(UI)은 Spotfire로 간다는 전략과 무관 — **이 계획은 «셋업» 화면이다.**

## 1. 진단 — 네 증상, 세 뿌리

| 뿌리 | 소유자 증상 | 검토서 |
|---|---|---|
| **A. 열거형을 자유 기입으로 시킨다** | P-01(술어 뭘 넣나) · P-02(어휘 안 보임, 드롭박스) · P-03(봉투 전 자리) | §7-④(b) |
| **B. 실물이 화면에 없다** | P-03(원자 컬럼을 뭘로 채우나) | §7-④(a)(c) |

## 2. 개혁 4라운드

### R1 — 사전(Dictionary) API + 전 폼의 드롭다운화  ← P-01·02·03의 즉효약
서버: `GET /admin/ledger/dictionary` 하나. 응답은 «닫힌 목록 전부»:
- **술어**: 이름·label_ko·한 줄 뜻·layer·origin(code/config)·status·
  **서명**(subject 허용 타입, object.kind, required 필드와 각 필드의 뜻)·
  **라이브 예시 원자 1개**(원장에서 실물 인용, 없으면 「아직 원자 0」)·사용량.
- **주어 타입**: 이름·keys·class·한 줄 뜻·사용량.
- **object_kind / traversable / direction / kind(observation·transfer·lot_event·
  derivation)** 등 모든 열거형과 각 값의 뜻.
- **불량 종류·검사 method** 목록(현행 코드 선언을 읽어서라도).
클라: 셋업 폼의 모든 열거 자리를 이 API가 채우는 **드롭다운**으로. 선택지에
마우스를 올리면 뜻+예시. 자유 기입은 «값»(컬럼명·리터럴)에만 남는다.

### R2 — 3열 매핑 워크벤치  ← P-03의 본체
한 화면 세 열, 전부 실물:
```
[왼쪽] 소스 실제 행           [가운데] 매핑                [오른쪽] 나올 원자
 테이블 선택 → 상위 20행       kind/술어 선택(드롭다운)      편집할 때마다 드라이런
 컬럼 목록(타입·NULL율·        → 서명이 «슬롯»으로 펼쳐짐    (기존 dry_run 모듈 재사용,
 distinct 예시 5개)            각 슬롯: 뜻 + 필수 여부       쓰기 0) 원자 봉투 그대로
                               컬럼 클릭→슬롯 배정           + 게이트 거절 사유 그대로
```
- **distinct 예시**가 붙으면 P-03의 「event_type에 뭐가 오는지」류가 해소된다
  (시나리오 C-2의 열거 문제).
- 중첩 payload(recipe:{id,rev})는 슬롯 트리로 렌더 — 접는 문법을 외울 필요가
  없어진다(시나리오 B-2).
- 저장은 기존 3단(검증→드라이런 토큰→저장+리로드+「먹었는가」) 그대로.

### R3 — 파이프라인 현황판 + 그 자리 실행  ← P-04의 본체
서버: `GET /admin/ledger/pipeline` — **기능 단위**(불량 종류 하나·소스 하나)로
사슬 상태를 계산해 답한다:
```
표 선언 ✓ → 소스 선언 ✓ → 어휘 ✓ → 원자 0 ← 「백필 미실행」 → 축·기하 ✗ → 온톨로지 ✗
                                    [백필 실행]                [siblings_axes에 추가 필요]
```
- 각 단계: 충족/결핍/무관 + **결핍의 이름** + 다음 행동(버튼 또는 「이 파일의
  이 블록」 링크).
- **백필 라우트화 포함**(`POST /admin/ledger/backfill`, 소스 지정·건수 보고) —
  「저장했는데 원자가 안 생긴다」의 종결.
- 구조 뷰와 상호 링크(선언 행 ↔ 현황판 항목).

### R4 — 합의 검사기  ← «영원히 조용»의 종결
`GET /admin/ledger/agreement` — 다섯 파일을 가로질러:
- 철자 대조: sources.columns ↔ table_config ↔ siblings_axes(geometry/join).
- **bindings·labels 점경로를 라이브 원자 잎과 실측 대조** — 「이 바인딩에 걸리는
  원자 0개」「이 라벨이 가리키는 잎 없음」을 문장으로. (틀린 경로가 오류가 아니라
  영원한 unknown이 되는 유일한 자리라, 실측 대조 외엔 방법이 없다.)
- 은퇴 유산 경고: `ontology_mapping.json`(구 그래프)을 열면 「죽은 파일」 표시.

## 3. 판정 대기 (계획 밖, 별도 라운드 — 「admin만으로」의 남은 구멍)
1. **불량 종류의 선언화** (`finding_kinds.py` → config) — R-M의 어휘 전례를 따름.
2. **주어 타입의 선언화** (`ENTITY_TYPES` → config, 뿌리 키 선언 필수 — R-O 연계).
3. 리스트 짝짓기류 구조 변환 번역기(스플릿 두 줄 문법) — 전용 번역기 유지가
   현답, 선언화는 무리하지 않는다.

## 4. 검수 기준 (포크)
- **소유자 여정**: 새 테이블 하나를 **문서를 한 번도 열지 않고** 워크벤치만으로
  원장까지 잇고, 현황판이 「축 미선언」을 알려줘서 그것까지 채우면 트렌드/대조
  API에 후보로 등장. 막히는 곳에서 만난 자유 기입 열거형 0회, 거절문에 다음
  행동 없음 0회.
- R1만으로도 「드롭박스 있어야 함」(P-02)이 닫혀야 하고, R2에서 P-03, R3에서
  P-04가 닫힌다. 라운드마다 해당 P를 재현 시나리오로 검수.

## 5. 순서와 크기
R1(사전+드롭다운)은 반나절감 — 즉시. R2(워크벤치)가 본체. R3·R4는 각각 독립
착지 가능. 콘솔(ledger.html) 투자 금지·API 응답 모양 변경 금지 경계는 유지
(사전·현황판·합의는 전부 **신설 admin 라우트**라 기존 계약을 안 건드린다).
