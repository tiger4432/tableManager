### 1. 무엇이 문제였나 — 기제 (재현: in-process, 시험으로 고정)

```
6f45a004 (09-11 13:52)  _maybe_explain_slow_prefetch 착지
                        224줄 신규 · 🔴 시험 파일 «0» (그 커밋의 파일 목록이 둘 다 소스다)
```

인제션 청크 루프의 모양(`directory_watcher.py`):

```
L3134  db = SessionLocal()            청크(1,000행) 세션
L3167  results = crud.apply_batch_updates(...)   내부에서 commit -> 반환 객체가 «전부 만료»
L3170  db.commit()
L3197  finally: db.close()            -> 그 객체들이 «분리»됨
L3190+ _maybe_explain_slow_prefetch(db, …, results, …)      ← 만료+분리된 객체를 «읽는다»
:452     rid = getattr(row, "row_id", None)
```

`expire_on_commit` 은 SQLAlchemy 기본값이고 이 저장소는 그것을 «끈 적이 없다»(`database.py`). 커밋은 만진 객체를 «만료»시키고, 만료된 속성은 세션이 있어야 다시 읽을 수 있는데 그 세션은 세 줄 위에서 «닫혔다». 그래서 그 한 줄이 던진다 — **`DetachedInstanceError: Instance <…> is not bound to a Session`**. 소유자가 사흘 동안 본 그 문장이다.

그리고 그 호출은 **감싸여 있지 않았다.** 예외는 청크 루프를 뚫고 바깥 핸들러까지 올라가 **파일을 통째로** 데려갔다.

#### 🔴 관문 하나가 증상 셋을 «전부» 설명한다

```
if already: return                     파일당 한 번
if prefetch <= threshold: return       그 청크의 선인출이 «느릴 때만» (기본 1.0 s)
```

| 소유자가 본 것 | 왜 그런가 |
|---|---|
| 산출물이 **하나만** 안 들어감 | 다른 산출물은 문턱을 «안 넘어» 그 줄에 도달조차 안 한다 |
| **어제까지는** 됐다 | 그 표의 선인출이 문턱을 «넘어선 날»부터 시작된다 |
| `__force__` **도 안 됨** | 강제는 같은 파일을 다시 «느리게» 돌린다 → 같은 자리에서 또 던진다 |

🔴 **박스는 이 자리에 «도달할 수 없다».** 그 함수의 자기 주석이 그렇게 적고 있다 — 운영 선인출 10 s, 이 박스 0.03 s. 즉 **박스에서 아무리 돌려도 한 번도 안 도는 코드였다.**

#### 수리 (`d00ac580`)

```
① _row_id_without_a_refresh   객체가 «이미 들고 있는» 식별키를 읽는다. 왕복 «0»
                              row_id 가 동적 표의 PK(models.py:988)라 식별키가 곧 답이고,
                              그 키는 만료와 분리를 «둘 다» 견딘다
② 호출 자리를 감싼다           진단기가 터지면 «계획 줄만» 건너뛰고 청크는 그대로 간다
```
시험 `test_a_diagnostic_may_not_kill_what_it_diagnoses.py` 셋: **결함 자체가 재현되고**(분리된 행의 `row_id` 가 `DetachedInstanceError`), 고친 함수는 세 id 를 내며 `record_statements` 가 «빔», 그리고 900 s 선인출 + 분리된 행에도 던지지 않는다. 워처 모집단 108 passed / 0 skipped · PG 88 passed.

### 2. 왜 사흘을 끌었나 — 여섯

#### ⓐ 증상 문장을 «자리»로 읽었다
「not bound to a Session」은 **기제**(SQLAlchemy 세션 수명)를 말하지 **좌석**을 말하지 않는다. 나는 그것을 위치로 읽고 «세션을 여는 곳»들을 뒤졌다. 정답은 «세션을 여는 곳»이 아니라 **세션을 닫은 뒤에 읽는 곳**이었다.

#### ⓑ 「진단기는 인쇄만 한다」고 믿었다
그 자리를 나는 «코드»로 안 셌다. 진단기·계측기는 «관찰»이라는 느낌이 있고, 그 느낌이 224줄을 시험 «0» 으로 착지시켰고, 사흘 동안 내 용의선상에서 그 파일을 빼 두었다.

#### ⓒ 반증이 subsystem 밖을 두 번 가리켰는데 두 번 다 안 나갔다
```
내 가설 ①  uq_vjoin_* 유일 인덱스     -> 소유자 「조인 원래 없었다고」        (반증)
내 가설 ②  중복 파일 서명 idx_fic_identity -> 소유자 「force 해도 안됨」      (반증)
```
반증 «둘 다» 「그 표의 데이터/선언 문제가 아니다」를 말하고 있었다. 나는 둘 다 그 안에서 다음 가설을 세웠다.
📌 이 부류는 **이미 기억에 있었다** — `a-refutation-that-points-outside-the-subsystem-must-move-me-out-of-it` (2026-09-14, 이틀 전). **기억만으로는 안 막혔다.**

#### ⓓ 전수 census 를 «사흘째»에 시켰다
오늘 아침 응용 레인에 지시(`319def58`, 10:25)한 「그 예외가 나려면 무엇이 참이어야 하나」 전수 세기는 **후보 7 → 6 소거 → 1** 로 끝났고, 걸린 시간은 «분» 단위였다. 그 지시는 첫날 나갈 수 있었다.

#### ⓔ `__force__` 가 결정적 단서였는데 거꾸로 읽었다
「강제인데도 안 된다」는 **「실패가 결정적이다 = 코드 경로에 있다」**는 뜻이다. 나는 그것을 「인제션 «전»에 거절되고 있다」로 읽고 중복/스킵 판정 쪽을 팠다.

#### ⓕ 운영자가 읽을 줄이 «파일도 좌석도» 안 댔다
바깥 핸들러가 찍은 것은 세션 문장 하나뿐이었다. 내가 이미 써 둔 상설(「운영 로그는 못 붙인다 — 줄 자체가 조치를 실어야 한다」)을 **그 줄이 어기고 있었다.** 그래서 소유자가 사흘 동안 나를 «증상»으로만 부를 수 있었고, 좌석은 결국 **소유자가** 찾아 주셨다(「maybe explain slow detch 여기서 에러 로그 있네」 · 「prefetch」).

### 3. 개발 방식에서 바뀌는 것 — 셋 (전부 «판별식»이고 덕목이 아니다)

#### ① 「진단기는 자기가 진단하는 것을 죽일 수 없다」
```
관찰용 코드(계측·EXPLAIN·샘플러·census)는
  · 자기가 «소유하지 않은» 상태를 읽지 않는다 (남의 세션·남의 커서·남의 파일 핸들)
  · 감싸여 있다 — 터지면 «자기만» 침묵하고, 감싸는 자리에 «무엇이 조용해졌는지»를 찍는다
판별식: 「이 줄이 터지면 무엇이 안 되나」. 답이 «관찰 말고 다른 것»이면 그 자리가 틀린 것이다
```

#### ② 「박스가 도달 못 하는 조건에서만 도는 코드는 시험이 «0» 이다」
`prefetch > 1.0 s` 는 이 박스가 «구조적으로» 못 만드는 조건이다. 그런 코드는 스위트를 아무리 돌려도 «한 줄도» 안 밟힌다 — 초록이 그 코드에 대해 아무 말도 안 한다.
```
착지 조건: 그 조건을 «강제로» 만들어 한 번 돌리는 시험이 «같은 커밋»에 있을 것
          (문턱을 픽스처가 넘기거나, 상태를 손으로 만들어 그 함수를 직접 부르거나)
📌 기억 「가드는 도달 가능해지는 날 틀린다」의 «계측기» 판. 이 자리는 09-11 에 생겼고
   09-13 쯤 «도달 가능해진 날» 처음 틀렸다
```

#### ③ 「가설이 «두 번» 반증되면 가설을 그만 세우고 전수 census 를 시킨다」
```
트리거   내 가설이 소유자/레인에게 «두 번째»로 반증된 순간          <- 셀 수 있다
행동     그 자리에서 가설을 멈추고, 「그 증상이 나려면 무엇이 참이어야 하나」로
        모집단을 «전수» 세는 지시를 낸다 (grep 문자열이 아니라 «조건»으로)
왜      반증 하나는 그 가설이 틀렸다는 뜻이지만, 반증 «둘»은 대개
        「내가 보고 있는 subsystem 이 아니다」는 뜻이다
```
⚠️ ③ 은 ⓒ 의 기억을 «트리거가 있는 규칙»으로 바꾼 것이다. 기억은 「밖을 가리키면 나가라」였고 그것은 «내가 알아채야» 발동한다. 이 규칙은 «세면» 발동한다.

### 4. 디버깅 방식에서 바뀌는 것 — 둘

```
① 증상 문장이 «기제»를 말하면, 그 기제를 낼 수 있는 좌석을 «전수» 먼저 센다
   — 그 세기의 단위는 «조건»이다: 「이 예외가 나려면 무엇이 참이어야 하나」.
     문자열 grep 은 그 조건이 «다른 낱말»로 쓰인 자리를 못 센다(오늘 census 가 그렇게 셌다)
② 「하나만 안 된다」는 «데이터 문제»로 들리지만 «관문 문제»일 수 있다
   — 코드에 「~일 때만 돈다」가 있으면 그 관문이 곧 「하나만」의 설명이다.
     그 표의 선언을 열기 «전»에, 그 경로의 «관문»부터 읽는다
```
