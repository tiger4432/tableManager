## 0. 왜 이 슬라이스인가 — 전략 전환의 실행분

기반(테이블) 영역이 한 달째 스키마 결합에 막혀 있다. 이번 주 `dt_map` 키 이주가
기각된 사유가 그 층의 성질을 보여준다: 충돌 7,159건 · 미끼 컬럼(100% 빈 값, 타입
불일치) · **「파생」 테이블 안의 사람 손수정 16,555행**. `create_all`은 기존 테이블에
손대지 않고, 컬럼 하나가 config·맵퍼·enrichment·참조뷰·그리드로 연쇄한다.

**「기반 완성 → 응용」 순서를 버린다.** 테이블 층에는 「완성」이라는 상태가 없다.

> **새 전략: 기반은 동결하고, 응용 화면 하나가 원장에서 필요한 것만 끌어간다.**

가능한 근거는 하나다 — **원장 스키마(7필드)는 안 바뀐다.** 도메인이 자라면 어휘가
자라는데 어휘는 DDL이 아니라 데이터다. 응용은 스키마 변경을 기다릴 이유가 없는 땅에
선다.

### 동결 선언 (기반 층)

- 버그픽스만. **새 스키마 진화·새 파생 테이블·새 enrichment 체인 금지** — 응용이
  명시적으로 요구할 때만 예외
- 새 데이터 요구의 기본 답이 바뀐다: ~~컬럼/테이블 추가~~ → **어휘 항목 + 번역기 한 장**

## 1. 이 슬라이스의 정의 — 「끝」의 모양

**한 주 뒤 이것이 되면 끝이다:**

> 화면에 `(lot, slot)`을 넣으면 **혈통 사슬이 홉별 상태와 함께** 뜬다. 읽기 전용.
> 참조뷰로 같은 질문을 던지는 링크가 옆에 있다.

되지 않아도 되는 것: 보이드 5홉 완주 · 프레임 확정 편입 · 잔량 · 액션 · 물질화 ·
SEMI 앵커 확정 · 기존 테이블 이주.

🔴 **다만 이 화면은 «위치 상세»로 설계한다 — 2주차에 버리지 않기 위해서.**
제품 소유자 확인(2026-08-12): **한 패키지에 칩이 10개 넘게 본딩된다.** 그래서
최종 화면은 2단이다 — 패키지 뷰(12칸 격자 + 형제 공유 요인) → **위치 상세**.
이 슬라이스가 만드는 것이 그 «상세»이므로, 단독 페이지가 아니라 **상위 뷰 밑에
들어갈 컴포넌트**로 만든다(§10 참조). 목록→상세는 기존 관례이므로 새 모드·모달이
아니다.

## 3. 작업 — 셋

### 3-1. `ledger_events` + lot_event 번역기 (백필)

**설계 §3의 봉투 7필드 그대로.** 필드를 줄이거나 늘리지 않는다 — 각 필드에 붙은
사고 근거는 설계 문서 §3 표에 있다.

- **신규 테이블**, 첫날부터 **시간 파티션**(나중에 붙이면 스키마 재작성이라는 것이
  본 세션에서 실측됨)
- `lot_event` 백필 = 일회성 번역 스크립트. **`lot_event`는 이미 이벤트 테이블**이라
  상태→이벤트 추론이 불필요하고 `event_time`이 `occurred_at`을 그대로 준다
- 번역 산출: SPLIT/MERGE 1건 → `derived_from` 1 + `slot_map` N(슬롯 쌍당 1) +
  `has_wafer` M(**채워진 wafer_id만** — 빈 값은 원자를 만들지 않는다) + 필요한
  `register`
- 🔴 **번역의 트랜잭션 단위 = 소스 이벤트 하나.** 분자(9원자)가 반쪽으로 착지하면
  안 된다. 상관 표지는 비의미 필드이므로 봉투가 보장하지 않는다 — 규칙으로 강제한다
- 🔴 **게이트**: 미선언 어휘·무신원·서명 위반은 **문 앞에서 거절하고 «센다»**.
  조용한 건너뛰기 금지
- `occurred_at`은 소스별 시각 컬럼을 config로 선언(`lot_event`→`event_time`).
  **도착 시각 대용 금지**

### 3-2. 추적 질의 (질의 시점 해결, 물질화 없음)

- 해결 서열은 설계 §6 그대로 — 계급 4 + 계급 내 3층 전순서. **해결기는 하나**
- Lot→Lot 재귀 CTE. 답은 **홉별 상태**를 실어 나른다:
  `resolved` / `candidate(rank,n)` / `unresolvable`
- **끊긴 자리가 이유와 함께 나와야 한다.** 빈 결과 금지 — 어느 홉에서 왜 끊겼는지가
  이 화면의 존재 이유다
- ⏸ 물질화는 **하지 않는다**. 필요 여부는 측정 레인(1000랏 증분 물질화)이 답한다

### 3-3. 화면 v0 (읽기 전용)

- 입력 `(lot, slot)` → 사슬 + 홉별 상태. **새 영역·모드·모달 금지**
- **「참조뷰로 보기」 링크 하나** — 정식 병행 캠페인 대신. 대조는 사후
- 클라 변경은 **빌드까지가 완료**다. dist 없으면 사용자에겐 없는 것

## 10. 목표 화면과 3주 로드맵 (예고, 착수 아님)

### 10.1 왜 2단인가 — 혈통은 나무가 아니라 «수렴»이다

제품 소유자 확인: **한 패키지에 칩 10개 이상.** 그러면 패키지 하나가 **서로 다른
랏·웨이퍼·시각의 혈통 사슬 10여 개가 수렴하는 지점**이다. 조사 질문 자체가 바뀐다 —
「이 다이의 코어 데이터」가 아니라 **「이 보이드가 어느 자리인가 · 그 자리의 사슬은
어디로 가나 · 형제들은 무엇을 공유하나」**.

```
┌ 패키지 뷰 ─────────────────────────────┐
│  Package P-1234   12칩                  │
│  ┌──┬──┬──┬──┐   ● 보이드 3            │
│  │ 1│ 2●│ 3│ 4│   칸=위치, 색=상태/공급원│
│  ├──┼──┼──┼──┤                          │
│  │ 5│ 6│ 7●│ 8│                          │
│  └──┴──┴──┴──┘                          │
│  🔴 형제 공유 요인                        │
│     보이드 3 → 전부 DtLot A · TapeLot T-88│
│     정상 9  → DtLot B·C 혼합              │
└─────────────────────────────────────────┘
        ↓ 위치 클릭
┌ 위치 상세 = 이 슬라이스가 만드는 것 ────┐
│ ① 보이드 ② 혈통 ③ 자재 ④ 계측 ⑤ 액션   │
└─────────────────────────────────────────┘
```

패키지 뷰는 새 층이 아니라 **위치 상세 12개의 집계**다.

### 10.2 이 구조에서만 가능해지는 질문 셋

1. **형제 상관** — 「보이드 3개가 공유하는 것은?」 같은 랏? 테입? 장비·시각대?
   근본원인 조사의 핵심 질문이고, 조인으로는 사슬 12개를 각각 펼쳐 교집합을 손으로 떠야 한다
2. **역방향 폭발 반경** — 「이 웨이퍼가 나쁘다. 어느 패키지들에 들어갔나?」
   `consumed`를 거꾸로 한 홉. **자재 격리 액션의 반경 계산이 곧 이 질의다**
3. **수율 귀속** — 패키지 불량을 공급원 12 중 어디로. 모르면 「후보 여럿」이 정직한 답

### 10.3 어휘 검증 — 골격 0, 개체 1 + 구성형 1

| 필요 | 판정 |
|---|---|
| **Package** | **발급형** — 재식별 검사 통과(패키지 id로 여러 관측에 걸쳐 다시 집는다) |
| **BondPosition** | **구성형** = Package × 위치 인덱스 — Die(Wafer × 그리드)와 같은 부류, register 불필요 |
| `consumed` | (Die, consumed, BondPosition) — 예약석 그대로, 목적어가 확정됨 |

**일곱 번째 스트레스 테스트 통과.** 구성형 개체가 두 번째 사례를 얻어 그 규칙이
우연이 아님이 확인됐다.

### 10.4 3주 로드맵 — 같은 화면이 «채워진다»

| | 화면에 늘어나는 것 | 어휘 |
|---|---|---|
| **1주 (이 지시서)** | 위치 상세: 혈통 사슬 + 홉별 상태 | v0 7개 (있음) |
| **2주** | **패키지 뷰 + 형제 공유 요인** · 보이드 · 계측 · 프레임 후보·핀 | `Package`·`BondPosition`·`consumed`·계측 attr |
| **3주** | 자재(TapeLot·Recipe) · **역방향 반경** · **액션 첫 하나** | `Recipe`·`TapeLot`·`action:hold` |

**화면을 새로 만드는 게 아니라 같은 화면이 채워진다** — 매주 클릭되는 물건이 나오고
이전 것을 안 버린다.

🔴 **형제 공유 요인을 2주차로 당긴 이유**: 「보이드 3개가 전부 같은 랏·같은 테입」
한 줄이 이 구조에서 원장이 조인을 이기는 것을 가장 극적으로 보이고, 조사자가 실제로
원하는 답에 가장 가깝다. 그 한 줄이 뜨면 화면의 가치 증명이 끝난다.

🔴 **액션은 첫 개 하나만, 되돌릴 수 있는 것으로** (hold·재검사 요청). 자재 격리처럼
되돌리기 비싼 것은 그다음이다. 액션 버튼에는 **근거(투영 세대·규칙 버전·최약 홉
상태)가 붙는다** — 멱등·감사에 더해, 나중에 프레임이 뒤집히면 **그 근거를 쓴 액션이
자동으로 의심 목록에 뜨게** 하기 위해서다. 「지난주 hold가 틀린 프레임 위에서
내려졌다」를 현행 시스템은 알 방법이 없다.
