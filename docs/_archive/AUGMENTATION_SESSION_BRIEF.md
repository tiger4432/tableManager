## 1. 권한과 규율

- **상설 사전 승인**(R-I): 건별 소유자 승인 대기 없음. 시드 가드 플래그
  (`--i-accept-writing-to-owner-database`)는 기록 목적으로 명령줄에 명시.
- DB 접속: `server/database/database.py`의 `DEFAULT_PG_URL`. conda env
  `assy_manager` + `PYTHONIOENCODING=utf-8` (bare python 금지 — 가짜 실패 남).
- **규율 셋 (위반 = 즉시 중단)**:
  1. 합성 분리 마커 의무 — 신규 개체는 `SYN-` 네임스페이스, 표별 술어는 보드
     상단 블록 준수.
  2. **실데이터 행 무접촉** — UPDATE/DELETE로 실행 건드리기 금지. 증강은 INSERT
     전용이 원칙.
  3. **측정은 「연결됐는지」 하나뿐** — 사전 전수조사·비용 실측·분포 분석 금지
     (소유자: 「재지 말고 연결만」). 신규 하니스 제작 금지(R-J).

## 2. 간극 체크리스트 (이 순서로, 축 하나씩)

각 축: **연결 → 확인 한 콜 → 한 줄 보고 → 다음.** 확인 콜에서 막히는 게 API
결함이면 고치지 말고 구현자에게 한 줄 통지 후 다음 축으로.

1. **유효 다이 레퍼런스** — 전 SYN 프레임(`wafer_map_metadata`)의
   `valid_die_ref`가 실제 유효 다이 맵을 가리키게(참조 대상 생성 포함). 마스크는
   현실적으로(예: 원형 경계 밖·가장자리 링 제외). 확인:
   `GET /api/ledger/lot_map` 응답의 프레임에 valid_die가 실리는지.
2. **DT·코어 축 잔여 미연결** — SYN 세계에서 아직 `no_frame`/`unreachable`인
   투영 축(특히 excursion 랏 3개와 마킹 데모 랏들부터). DT·코어 프레임 등록 +
   전이 사슬이 실어 나르는 좌표 연결. 확인: 같은 API에서 3축 모두 `ready`.
3. **base 신원 없는 웨이퍼 120장** — k=1 실데이터 제외, SYN 쪽 잔여가 있으면
   채움. 확인: 프레임의 `wafer` 신원 필드 부재 수 감소.
4. **본딩후 대기 수량** (`post_bond_queue_h`) — 관측 편향 모델(bindings)이
   기다리는 소스 필드. `processed_with` 원자의 params에 대기 시간을 실을 수 있게
   시드 확장(랏별 편차 포함 — excursion 랏 하나는 길게, 대조가 잡을 수 있도록).
   확인: 원자 payload에 필드 존재.
5. **MI measured 수량 1~2종** (예: 두께) — 수치 대조·주석 결측 데모용. 일부
   웨이퍼는 일부러 결측으로 남길 것(결측 부류가 뜨는 게 데모의 일부다). 확인:
   원자 존재 + 일부 부재.
6. **경로 특징 표본** — 재작업(같은 공정 2회) 랏 1~2개, 스킵 랏 1개. 확인:
   해당 랏의 원자 서열에 반영.
7. **랏 스플릿/머지 + 조건 갈림** (2026-08-14 소유자 추가 지시, 물리 온톨로지
   앵커판) — 신규 랏으로만, 기존 100랏·excursion 정답지 무접촉.
   ① SYN 본딩 랏 하나가 자식 랏 둘로 스플릿(소속 변경을 원장 문법 그대로 —
   route 선언 금지, 이벤트만). ② **갈림 조건은 M4가 이미 이름 붙인 물리량으로**:
   `params_actual.pressure_MPa`(→`bond_pressure` 바인딩 기존재). M4 선언 그대로
   재현할 것 — **자식 A = 저압 → 보이드 상향**(bond_pressure −→ interface_unfill
   +→ void), **자식 B = 고압 → 박리 상향**(bond_pressure +→ die_stress +→ delam).
   한 조건이 두 갈래에서 서로 다른 불량을 내는 비단조가 M4 delam_formation
   signatures에 문장으로 선언돼 있고, 이 축은 그 문장을 데이터로 실증한다.
   방향 부호가 생명: 저압 쪽에 보이드, 고압 쪽에 박리 — 반대로 심으면 기전
   관문이 방향 불일치로 걸러야 정상이므로 절대 뒤집지 말 것. 값은
   `processed_with` params에만, **선언 추가 0개**(대조가 걷기만으로 갈림을 찾고
   기전 관문이 M4로 설명하는 게 시험 목적). 배수는 기존 사다리(2.30/3.38/4.97×)와
   겹치지 않게. ③ 두 자식이 하류 한 랏으로 머지 — 합류 후 웨이퍼별 «어느 갈래를
   걸어왔는지»가 걷기로 복원 가능해야 함. ④ 부모·합류 공정은 깨끗하게 — 「심지
   않은 쪽은 안 뜬다」가 구성적으로 참이 되게. `post_bond_queue_h`는 두 갈래
   동일하게(편향 관문이 여기서 울리면 안 됨 — 그 데모는 축 4 랏이 담당).
   확인 콜 하나: 합류 랏 웨이퍼 하나를 lot_map/trace로 찍어 두 갈래 조건이
   각자의 웨이퍼에 붙는지. 포크 수락 확인: 머지 랏 마킹 대조에서 압력 갈림이
   선언 0개로 드러나고, 기전 열이 보이드·박리를 각자 갈래로 설명하는지.

## 3. 도구 — 기존 것 재사용 우선

새 스크립트를 짓기 전에 기존 시드 계열(`server/scripts/seed_syn_world.py`,

파일로(conda run -c는 개행 거부).

   범주 위주, 수치는 계측성 값에만. 스텝 수가 실제로 100 근처여야 한다 —
   걷기 골격(홉=신원 변경만)이 100스텝에서도 평평한지가 이 축의 구조 검증.
   ② **심기: M4의 «정직한 공백» 중 하나를 실재로** — 권장: 특정 CMP 챔버를
   지난 코어 웨이퍼들만 `core_cmp_nonuniform` 계열 조건 →그 코어들이 들어간
   본딩 웨이퍼의 보이드가 **코어 프레임 가장자리 링**으로 상향(M4 signatures
   문장 그대로: "core frame: edge ring"). 방향·서명 일치 필수, 실행 시점
   config 재독(축 7 방식).
   ③ **바인딩**: 새 필드가 실재하게 되면 포크가 bindings에 값→물리량 항목을
   건다(범주 노브 바인딩은 씨앗 6 — 모양이 미정이므로 **DM은 걸지 말고 필드만
   실재하게**, 한 줄로 포크에 알릴 것).
   ④ 확인 콜: 본딩 랏 하나 마킹 대조에서 전공정 챔버/노브 갈림이 선언 0개로
   후보에 뜨는지 + `/trace` 1건이 전공정 스텝들을 주석으로 싣고 걷기 시간이
   유지되는지(숫자 하나만).
   ⑤ 규율 동일: SYN 마커·INSERT 전용·기존 랏 실측치 무접촉·측정은 연결 확인
   한 콜.
