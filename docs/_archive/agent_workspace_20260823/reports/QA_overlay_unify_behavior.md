## 1. 판정 (당시)

# 🔴 NO-GO

이 변경의 존재 이유가 "조용한 오정렬 제거"인데, **조용히 틀린 그림을 성공으로 표시하는 경로 2종을 새로 만들었고 라이브에서 재현했다**. 세 결함 모두 국소 수정(각 3~10줄)이라 재설계가 아니라 "고치고 재검수" 사안. 프레임 스택·import·잠금·dist 등 나머지는 전부 실측 통과.

| | 정상 | 소스 메타 500 |
|---|---|---|
| 마커 셀 수 | 139 | **129** |
| 정상과 불일치 | — | **틀린 자리 76 / 사라진 자리 86** |

차단 사유: ⓐ 화면은 정상인데 값만 틀리다 ⓑ 사용자에게 **사실이 아닌 이유**를 알린다 ⓒ 칩 수(139)와 실제 그려진 수(129)가 어긋난다 ⓓ **이 변경이 만든 새 상태다** — 구 설계는 서버가 한 트랜잭션에서 메타를 읽어 "셀은 왔는데 메타만 못 읽음"이 성립하지 않았다.

결정적 근거: 같은 파일 `:84-91`이 **정확히 이 안티패턴을 결함으로 지목하고 고친 주석**을 달고 있다 — *"'선언이 없다'(404/405)와 '확인하지 못했다'(그 외 실패)를 구분한다"*.

### [높음] B2 — `align_override_declared` 관문이 fail-open · **신규**
`map_editor.js:4029-4041`(`probeAlignDeclaration`: `if (!res.ok) return null; … catch { return null; }`)

**진짜 선언으로** 재현. `align_overrides`에 실선언 투입(서버가 `origin:"default"` 반환 확인) →

| probe 상태 | 결과 |
|---|---|
| 정상 | `align_override_declared` 실패 행 · **그리지 않음** ✅ |

`!res.ok`(5xx/프록시 오류)도 동일 경로 → **안전장치가 있으나 마나**. 주석의 *"구버전 서버·네트워크 오류는 차단 사유가 아니다"* 전제 자체가 틀렸다.

### [중-높음] B3 — 관문이 `by_eqp` 전용 선언에 눈이 멂
`map_editor.js:4025-4028`(probe URL에 `eqp` 미전달) ↔ `server/map_overlay.py:352-360`

`align_overrides["sample_map"] = {"by_eqp": {"METRO-A": {...}}}`(default 없음) → 서버가 `origin: "identity"`로 답하고 클라는 관문 미발동 → **정상 성공 행으로 그림**. 구현 보고서 §5-1의 *"선언이 있으면 명시 실패"* 는 이 형태에서 **거짓**.

### [중] B4 — 오버레이 조회가 범용 데이터 엔드포인트로 이동, 요청 5배·지연 4.4배

4. 랏 이름에 `_`가 있고 키 컬럼이 2개인 맵.
5. 동시 추가 경합 — `addOverlayForSource`(패널 경로)는 버튼 disable 밖.

## 5. 문서 정합

- §5-1 *"선언이 있으면 `align_override_declared`로 명시 실패"* → **거짓**(`by_eqp`·probe 실패에서 통과). 문구를 좁혀야 한다.
- §3·§5-4 "실행취소·프레임 복원 라이브 미실행" → **본 검수에서 해소**(공격 1~3).
- §4-E `binding_unavailable`은 UI 도달 불가임을 밝혀야 한다.
- 성능 변화(HTTP 1→5회, 12ms→53ms)가 보고서에 없다.

## 6. 교훈 제안

- **함정**: 캔버스 픽셀 diff 검증에서 오버레이 행 표시/숨김이 **레이아웃 높이를 바꿔 캔버스를 리사이즈**시킨다(1047→332→982px 관측). 같은 상태 2회 측정이 28만 픽셀 어긋나 "결함"으로 오판하기 직전이었다.
  **올바른 방법**: 측정 전 캔버스 부모 height를 실측값으로 고정하고, A→토글→복귀 후 픽셀 diff 0을 먼저 확인(측정 신뢰성 자기검증)한 뒤 본 측정을 신뢰한다.
- **함정**: 쓰기 차단 셰임만 걸고 "쓰기 0건"을 주장하면 **무엇을 쓰려 했는지**를 못 본다.
  **올바른 방법**: 차단하되 **body를 기록**한다. Push 페이로드 204행을 확보한 덕에 "표시 오류 vs 데이터 오염" 판정의 결정적 증거가 나왔다.
- **함정**: fail-open 관문은 정상 경로 테스트로는 절대 드러나지 않는다 — 관문이 도는 것만 보고 통과시키게 된다.
  **올바른 방법**: 관문마다 **선언은 살려 두고 관문의 조회만 실패시키는** 시나리오를 별도로 돌린다. 같은 파일에 이미 고쳐진 fail-open 주석이 있으면 신규 코드가 그 규율을 지키는지 대조한다.
