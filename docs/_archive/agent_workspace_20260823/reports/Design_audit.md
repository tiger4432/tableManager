### 1.2 왜 "어두컴컴"하게 느껴지는가 — 수치 근거

핵심 발견: **WCAG 대비율 자체는 대부분 통과한다** (text-main 18.2:1, muted 7.8:1, 시안 14.1:1). 즉 문제는 "대비 부족"이 아니라 **절대 명도·위계·탁함**의 3중 조합이다.

1. **절대 명도가 사실상 0.** 지면 `#07090e`는 L* 2.5 — 완전한 검정(L* 0)과 지각적으로 거의 구분 불가. 주간 사무실(300~500lux)에서 이 명도의 화면은 **거울이 된다**(반사·비침). 눈의 순응 기준이 밝은 실내에 맞춰져 있으므로 화면 전체가 "꺼진 모니터에 글자만 떠 있는" 인상 = 어두컴컴함의 1차 원인. 사무환경용 다크 테마의 통상 지면은 L* 12~20(`#1a2030`대)이다.
2. **표면 위계가 소멸.** 지면(L* 2.5) → 패널(L* 6.7) → 헤더 사이 ΔL*가 2~4에 불과. 저명도 구간에서 이 차이는 식별 한계 이하 → **패널이 카드로 안 읽히고 검은 화면 한 장으로 뭉개진다.** enrichment 라이브 스크린샷에서 3개 패널 경계가 거의 보이지 않음을 확인.
3. **구조선이 안 보인다.** 보더가 8% 흰색(대 지면 ≈1.3:1) — 표·패널의 선이 사실상 투명. 텍스트만으로 구조를 읽어야 하므로 스캔 피로 가중.
4. **네온 시안 + 글로우 = 탁함과 눈부심.** `#00f0ff`는 채도 100% 시안 — 순검정 위에서 할레이션(빛 번짐)을 일으키고, 청색 계열 순색은 적색 계열과 초점거리가 달라(색수차) 장시간 응시 피로를 만든다. 여기에 `box-shadow: rgba(0,240,255,...)` 글로우가 도처에 깔려 **안개 낀 듯한 탁함**("어두컴컴"의 질감 부분)을 형성. 톤 자체가 게이밍/사이버펑크 — R&D 데이터 툴의 신뢰 톤과 어긋난다.
5. **반투명 유리 + 블러의 혼탁.** 표면 대부분이 rgba 알파 합성 + `backdrop-filter: blur` — 어두운 그라데이션 위에서 알파 합성된 회색들은 채도가 낮고 색상이 미묘하게 틀어져 **"깨끗한 솔리드 색이 한 군데도 없음"** → 물리적으로 murky.
6. **정작 데이터 영역이 가장 어둡다.** AG-Grid `--ag-background-color = var(--bg-app)`(최저 명도), 홀수행 스트라이프 1% 흰색(비지각), row hover 4% 시안(비지각). 사용자가 하루 종일 응시하는 그리드가 화면에서 제일 검다.

### 1.4 다크 유지 vs 라이트 전환 vs 듀얼 — R&D 데이터 툴 관점 트레이드오프

| | **A. 라이트 전환** | **B. 밝힌 다크** | **C. 듀얼 토글** |
|---|---|---|---|
| 주간 사무환경 적합 | ◎ 실내광과 순응 일치, 반사 문제 소멸 | ○ L* 13+로 끌어올리면 실용 수준 | ◎ |
| 소형 고밀도 텍스트 가독 | ◎ 양극성(밝은 배경+어두운 글자)은 동공 수축→피사계 심도 증가로 작은 글자에 유리 (Excel/JMP/BI 툴이 라이트 기본인 이유) | ○ | ◎ |
| 장시간 응시 피로 | ○ 밝은 화면 자체 피로는 존재(저채도 지면으로 완화) | ○ 할레이션 제거 시 양호 | ◎ 시간대·개인차 대응 |
| 마이그레이션 비용 | 중~대 (AG-Grid quartz-dark→quartz 전환 + 하드코딩 색 청산 필요) | **소** (토큰 값 교체가 80%) | 대 (A+B+토큰 SSOT 전제) |
| 사용자 피드백 부합 | ◎ "어두컴컴" 거부에 정면 대응 | △ 개선이지만 여전히 다크 | ◎ |
| 리스크 | 셀 상태색(overwrite/dirty-tx/flash) 전면 재설계 필요 | 최소 | C 단독 선행 시 과설계 위험 |

**디자이너 권고:** 사용자 피드백이 "다크 테마 자체에 대한 거부"로 읽히므로 **A(라이트)를 기본 자세로 권장**. 단, 마이그레이션 리스크를 관리하려면 **B를 1차 스텝(토큰 값 교체만으로 즉효)** 으로 넣고, A로 갈 때 C의 토큰 규율(시맨틱 토큰만 참조)을 지키며 작업하면 추후 듀얼이 "값 세트 추가"로 축소된다. **최종 선택은 사용자 몫** — 목업 3종으로 실물 느낌을 비교 요청.

## 2. 페이지별 진단

### 2.1 일관성 (4페이지 토큰 통일 여부) — **불통일 확인**

| 페이지 | 토큰 출처 | 팔레트 | 모노 폰트 |
|---|---|---|---|
| index | `src/style.css` | 시안/퍼플 네온 다크 | JetBrains Mono |
| map_editor | `src/style.css` 공유 | 동일 + **map_editor.js 캔버스 하드코딩 ~40곳** | JetBrains Mono |
| enrichment | **HTML 인라인 복제** (style.css와 값 동일하나 사본) | 동일 | JetBrains Mono |
| admin | **HTML 인라인 별도 팔레트** | **Catppuccin 계열 (전혀 다름)** | **Fira Code** |

추가 발견: `main.js`의 스마트 페이스트 모달(1526~1654행)이 **메인 페이지 안에서 admin의 Catppuccin 색**(`#cdd6f4/#7f849c/#f38ba8`)을 하드코딩 — 한 페이지 내부에서도 두 팔레트가 섞여 있다. 토스트 CSS는 style.css/enrichment.html/admin.html에 **3중 복제**.

→ 결론: 재테마 작업의 실질 장애물은 CSS 토큰이 아니라 **(a) admin 별도 팔레트, (b) map_editor 캔버스 하드코딩, (c) main.js 모달 하드코딩, (d) enrichment 토큰 사본**이다. 어떤 방향을 택하든 이 4곳의 토큰화가 선행 조건.

### 2.2 정보 위계 — 메인 그리드 헤더 과밀 **확인**

70px 헤더 한 줄에: perf 배지 + Tx pending 배지 + enrichment 배지 + Apply/Discard 버튼 + Table 셀렉트 + 버튼 3개 + Graph Sync(조건부) + Options 드롭다운 + Menu 드롭다운 + API/WS 상태 배지 2개 = **12개+ 요소**. 그중 5개가 `display:none` 조건부 → 상태 변화 때마다 헤더 중앙이 **팝인/리플로**되어 시선 앵커가 흔들린다. 배지·버튼 다수가 HTML `style=""` 인라인 오버라이드로 구현되어(예: index.html 29~33행) 유지보수·일관성 취약. 이모지 아이콘(🔄🗑️⚡🧩...)이 모든 버튼에 붙어 시각 노이즈 가중.

### 2.3 인터랙션 상태

- **hover**: 전반적으로 잘 설계됨 (lift/glow 계열, transform·opacity 위주 — 성능 규율 준수).
- **focus**: `.glass-input:focus`만 링 존재. **`.glass-btn`·`.glass-page-btn`·드롭다운 항목에 `:focus-visible` 스타일 부재** → 키보드 탐색 시 현재 위치가 보이지 않음. enrichment는 키보드 중심 UX(Enter/↑↓/Esc)인데 정작 포커스 링이 없는 것은 모순.
- **로딩/빈/오류**: enrichment(오늘 신설)는 3종 모두 설계됨(스피너·빈 상태·setup 오버레이) — 모범. admin도 빈 상태 보유. **index 메인 그리드는 로딩=텍스트 배지뿐, 빈 상태=AG-Grid 기본** — 프리미엄 표준(SOP §4) 미달.
- **`--transition-smooth: all 0.3s`가 광범위 적용** — `all` 트랜지션은 색상 외 레이아웃 속성 변화에도 걸려 의도치 않은 애니메이션과 합성 비용 유발. 개별 속성 명시로 좁힐 것(표현 계층 수정으로 가능).

### 2.4 접근성 기본기

- **대비**: §1.3 — `--text-dim` 3.83:1 FAIL이 유일한 수치 낙제.
- **클릭 타깃**: 푸터 `glass-page-btn`(padding 2px 10px ≈ 높이 20px), 페이지 입력(48px 폭·미세), 체크박스 14~15px — **24px 최소 타깃 미달** 다수.
- **시스템 컬럼 이탤릭+저명도**(`.cell-system-readonly`: dim + italic + 더 어두운 배경) — 읽기 전용 표시 의도는 좋으나 3중 감쇠는 과함.

### 2.5 데이터 밀도·스캔 속도

- AG-Grid 본문이 `--ag-font-family: var(--font-sans)`(Outfit) — **숫자·ID 데이터가 프로포셔널 폰트로 렌더**되어 자릿수 정렬이 흔들린다. 데이터 툴 원칙(모노 또는 `font-variant-numeric: tabular-nums`) 위반. enrichment 참조 테이블은 모노 사용 — 페이지 간 원칙도 불일치.
- 행 스트라이프 1%·보더 1.3:1로 **행 추적선이 소멸** — 넓은 그리드에서 좌우 시선 이동 시 행 이탈 위험.
- map_editor: 네온 그린 아웃라인(`#22c55e` inside-wafer) + 레드 원점 글로우 + 시안 hover가 동시 표시 — 셀 값 색상(범례)과 상태 색상이 경쟁하여 **수만 셀에서 시각 노이즈**. 상태 표시는 채도를 낮추고 범례 색이 주인공이 되도록 재배분 필요.
