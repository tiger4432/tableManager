## 2. 확인된 결함 (전부 비차단)

### [중] F1 — 소스/타깃 **물리 규격 불일치**를 관문이 막지 않는다 (잠복)
`map_editor.js:4135`(관문이 `cols/rows`만 비교) · `:4152-4156`(물리 규격 차이는 툴팁 문구로만)

물리 좌표는 **인덱스**이고, 그 인덱스가 어느 다이를 가리키는지는 `getScreenShift`의 `offset/chip` 비율이 정한다(`:1180-1204`). 소스와 타깃이 다른 `phys_offset_*`/`phys_chip_*`를 선언하면 같은 인덱스가 같은 다이가 아니다.

실측 (29x25, chipX=11 동일, 소스 `offset_x`만 변경):

| 소스 offset_x (타깃 0) | 어긋난 셀 |
|---|---|
| 0.1 | 0 / 425 |
| 2.0 | 0 / 424 |
| 5.4 (반 피치 직전) | 0 / 424 |
| **6.0 (반 피치 초과)** | **424 / 424 — 전 셀 1다이 이동** |

관문 PASS, 칩은 `정렬됨`. **조용한 1다이 오차**이며 임계값에서 불연속으로 튄다.

**라이브 도달성 0** — 등록 9개 bonding_map 중 29x25 계열 7개는 `chip 11/13 · off 0/0`, 27x21 계열 2개는 `chip 12/16 · off 0.1/0`, eds/core는 `chip 7/7 · off 0/0`. 그래서 차단이 아니다.

**권장**: 관문에 `chipX/chipY/offsetX/offsetY` 동일성 추가(불일치 시 `align_unavailable`), 최소한 칩 상태를 `정렬됨`과 분리.

### [중] F2 — 관문의 기준이 타깃 **메타 입력**인데 실제 렌더 프레임은 **DOM**이다
`:4059`(`targetKey = getCurrentMapKey()`) · `:4129` · `:4135`

`getCurrentMapKey()`는 로드된 맵이 아니라 **현재 메타 입력 필드**를 읽는다(`:2014-2024`). 로드 없이 입력만 바꾸면 관문이 엉뚱한 맵의 메타로 판정한다.

재현 경로: ① `bonding_map/4B13`(27x21) 로드 ② 메타 입력에 `aa223` 타이핑(로드 안 함) ③ 소스 `EXP1`(29x25) 오버레이 추가 → 관문 `29x25 vs 29x25` **PASS** ④ 오버레이는 29x25 격자 키, 화면은 27x21 → 약 (1,2)셀 어긋남, 칩은 정상.

관문 자체는 load-bearing임이 실측됐다 — 우회 시 소스 45x45 → 화면 29x25에서 **758/1273 키가 격자 밖**.

**권장**: 로드 시점에 확정된 맵 키/프레임(`loadExistingMap`의 `loadedMapKey`)을 쓰거나 `currentFrame()`의 DOM 치수도 함께 비교.

### [중] F3 — 무증거 identity 추정의 라이브 노출 규모 (**회귀 아님** — 구 경로 동일)
`:4128`(`frameFromMeta(sourceMeta) || currentFrame()`) · `:2463-2485`

- `bonding_map`의 distinct `base` **397,600개** vs `wafer_map_metadata` 등록 **9개**. 나머지는 전부 "규격 미등록 → 현재 화면 규격으로 해석".
- 그중 **169개 맵은 셀 레벨 `grid_metadata` 컬럼에 자기 규격을 갖고 있다**(rot 90/270/back 포함). 예: `HFZ123.12` = `29x25 · rot270 · front · start(2,2)`.
- 실측: `HFZ123.12 → aa223` — 474키 중 **107셀이 정답 프레임과 다른 자리**, **36키가 격자 밖**(y 25..28)으로 밀려 렌더 창 밖에서 소멸. 칩은 `무보정`.

**회귀 판정**: 라이브 서버도 `origin: "identity", note: "맵 메타 부재 → identity로 간주"`를 반환하고 구 클라는 그 좌표를 현재 화면 프레임에 배치했다 — **새 경로와 완전히 같은 결과**. `/tables/{t}/schema`의 `columns`에 `grid_metadata`가 어느 맵 테이블에서도 노출되지 않아 `loadExistingMap:2582-2591`의 셀 레벨 폴백도 라이브에선 사문이다. **차단 아님.**

**권장(값싼 개선)**: 오버레이는 이미 소스 행을 통째로 가져온다(`:4096`). `/tables/{t}/schema`에 `grid_metadata`를 노출하면 **추가 요청 0회로** 169개 맵을 정확히 해석할 수 있다. 그전까지는 `무보정`을 진짜 identity와 **다른 칩 상태**로 분리할 것 — 현재는 "근거 있는 항등"과 "근거 없는 추측"이 같은 라벨이다.

### [낮] F4 — 격자 밖 투영 셀이 조용히 사라지고 `count`가 과대보고
`:4123`(`count: cells.length`) vs `:3939-3954`(`Map` 키 충돌 시 덮어쓰기). F3 사례에서 "474칩"이라 표시하고 36셀이 화면 밖으로 사라진다. 라이브 정상 경로에서는 중복 0·격자밖 0이라 현재 무해.
**권장**: 투영 후 격자 밖 키를 세어 0이 아니면 사유에 노출, 또는 `count`를 `cells.size`로.

### [낮] F5 — 사문·구 계약 문구 잔재
- `:1752-1753` 렌더 루프 주석이 여전히 **"서버가 타깃 프레임으로 정렬해 준 좌표… 좌표 변환 금지"** — 새 설계와 정면 모순. 다음 사람이 읽는 첫 문장이다.
- `:970-976` `getPhysicalCoords` 내 미사용 지역변수 4개. **셀마다·프레임마다** 호출되는 핫패스라 `parseFloat` 4회가 매번 낭비된다(기존 잔재). 삭제가 정답.

## 4. 런타임 검증 필요 (코드만으로 단정 불가)

1. **브라우저 캔버스 실렌더** — 검수는 기하 함수를 **원문 그대로 추출**해 Node에서 구동했다(DOM만 스텁). 픽셀 단계(`drawOverlayMarkers` 마커 위치, `activeOverlayLayers` 갱신 타이밍)는 범위 밖.
2. `renderGridCanvas:1635`에서 `syncOverlayGeometry()`가 **렌더 도중** `o.cells`를 교체하는 구조. 정적으로는 안전하나 레이어×셀이 큰 상태의 프레임 드랍은 실측 필요.
3. 프레임 스택(`openMapFrame`/`popMapFrame`)·실행취소 회귀 — 구현자도 미실행. **B 담당이나 좌표 관점에서도 미검증**.
4. F2 시나리오의 실제 UI 조작 가능성.
