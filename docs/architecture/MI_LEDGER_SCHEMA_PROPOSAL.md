# MI 계측이력 — 원장 스키마 제안 v0

> **Status:** 🟡 제안 (소스 실물 미확인 — 확정은 실물 대조 후) | **Owner:** 온톨로지 포크
> 앵커 목표(브리프 §10.4-bis, 제품 소유자 2026-08-13)의 MI 축.
> [DEFECT_SCHEMA_PROPOSAL](DEFECT_SCHEMA_PROPOSAL.md)(void)과 같은 지위의 문서이고,
> 같은 골격을 재사용한다. 판정 근거는 [CANONICAL_LEDGER_DESIGN](CANONICAL_LEDGER_DESIGN.md).

## 0. 한 줄

**점(point)은 소스 테이블에, 주장(claim)은 원장에.** MI의 원시 계측점 수천 개를
원장에 붓지 않는다 — 원장은 주장의 기록이지 텔레메트리 저장소가 아니다(설계 §5
텔레메트리 경계). 보이드 해석이 필요로 하는 것은 "이 자재의 BLT가 얼마였나"이지
점 하나하나가 아니고, 점이 필요해지면 raw_ref로 소스에 내려간다.

## 1. 소스 계층 — void의 2테이블 골격을 «재사용»한다

- **분모 = 기존 `inspection_run` 재사용.** 그 테이블의 키가 이미
  `(method, base_wafer_id, base_x, base_y, stack_gate, observed_at)`로 **method를 키
  재료로** 갖고 있다 — MI는 새 분모 테이블이 아니라 `method='MI-<종류>'`인 행이다.
  "스캔이 있었다"와 "계측이 있었다"는 같은 문장이다. (분모 없이 관측만 있으면
  「측정 안 함」과 「정상이라 특이값 없음」이 같은 부재가 된다 — void와 같은 이유.)
- **관측 = `mi_obs` 신설** (실물 확인 후 컬럼 확정). 방향은 void_obs와 동일:
  한 행 = 한 run이 본 한 측정값. `(run_uid, metric, site)` 키.
  값·단위는 행에 실린다(단위가 조인 너머에만 있는 숫자는 그리드에서 단위 없이
  보인다 — void §3과 같은 규칙). **판정값(pass/fail)은 저장하지 않는다** — 임계는
  레시피 파라미터고, 저장된 판정은 재심 불가(void의 「등급 금지」와 동일).

## 2. 원장 어휘 — 웨이퍼 내 계측에 «본질적으로 존재하는 것»만 (제품 소유자 지시)

웨이퍼 안에서 무언가를 잴 때 세상에 실재하는 것은 여섯이다. 나머지(잡 id·파일명)는
방언이거나 출처다. (v0 초판은 넷이었다 — 제품 소유자가 「누가」와 「어떻게」의 누락을
차례로 지적했고, 검토 결과 하나는 산문에 묻혀 있었고 하나는 「누가」에 뭉쳐 있었다.)

| 본질 | 내용 | 봉투에서의 자리 |
|---|---|---|
| **① 누가 (행위자)** | **잰 주체 — 장비.** 출처가 아니라 세상의 사실이다: 보이드 해석에서 장비는 **후보 공통 요인**이고(「전부 MI-2로 측정」= 장비 편향, 형제 교집합의 입력), 산문에 묻으면 분석이 못 쓴다 | payload의 `eqp` — **질의 가능한 필드로** (§12의 장비 개체 승격 판정이 나면 `processed_with` 동반 주장으로 승격 경로) |
| **② 어떻게** | **방법·레시피·조건** — 같은 장비라도 레시피가 다르면 다른 측정이다. **재심 가능성이 여기 걸린다**: 임계·조건은 레시피의 파라미터라, 어떻게를 잃은 값은 재판정이 불가능해진다 (void의 「등급 금지」와 같은 뿌리) | payload의 `{method, recipe, conditions?}` — 역시 질의 가능하게. 레시피도 형제 교집합의 후보 요인 |
| **③ 어디** | **2계층이 기본이다 (제품 소유자): 어느 «칩»의, 칩 내부 `inchip_x, inchip_y`.** 칩(다이)은 웨이퍼 × 격자 좌표(frame 하)로 지정되고, 그 안의 위치가 inchip 좌표다 — `void_obs`의 (base_x, base_y) + (inchip_x, inchip_y)와 **같은 위치 문법**. 선택적으로 그 자리의 **구조**(bond_line·film·TSV…) | subject = Wafer, payload의 `{frame, die_x, die_y, inchip_x, inchip_y, structure?}` (§5-2: 프레임은 subject 금지 — 다이 지정이 payload에 있는 이유). **void와 문법이 같으므로 「같은 칩의 같은 자리」 조인이 공짜** |
| **④ 무엇을** | **물리량** — 두께·폭·면적·정렬오차·휨… 단위와 차원은 물리량의 시그니처에 속한다 (µm 없는 「두께」는 없다) | payload의 `quantity` — 어휘 등재 대상, 방언은 번역으로 소멸 |
| **⑤ 얼마** | 값 (+ 요약이면 stat·n) | payload의 `{value, unit, stat?, n?}` |
| **⑥ 언제** | 계측이 일어난 세상의 시각 | `occurred_at` (도착 시각 대입 금지) |

그리고 봉투에는 **⑦ 발화자 — 누가 이 주장을 «하는가»** 가 원래부터 있다:
`source{who, translator_ver, raw_ref=run_uid}`. 행위자(①)와 발화자(⑦)는 다른
질문이다 — MI 장비가 쟀고(행위자), MI 시스템의 내보내기 파일이 말하며(발화자),
둘이 갈리는 날(수기 입력·타 시스템 경유)이 반드시 온다.

```
(Wafer W, measured,
 {quantity, value, unit,
  frame, die_x, die_y, inchip_x, inchip_y, structure?,
  eqp, method, recipe, conditions?, stat?, n?},
 occurred_at, source{who, raw_ref: run_uid})
```

봉투 7필드가 이 여섯+발화자를 새 구조 없이 그대로 받는다 — **①②④⑤가 object,
③이 subject+위치 payload, ⑥이 occurred_at, ⑦이 source.**

물리량(②) 규율 둘: 단위는 물리량 시그니처의 일부라 단위 없는 값은 게이트가 거절
(void의 `DEFAULT_UNIT: None`과 같은 자세). 그리고 두 장비가 같은 이름을 쓴다고 같은
물리량이 아니다 — 프레임 검사(dt_x↔core_x 규율) 전 통일 금지.

## 3. 관측이냐 추론이냐 — R-A의 규칙을 그대로 적용

- **소스가 스스로 요약을 발화하면** (per-wafer summary 행이 있는 MI 시스템):
  그 요약은 **관측(2류)** — 소스가 말한 것이다.
- **원시점만 있어서 번역기가 집계하면** (mean/min/max 계산): 그것은 규칙 아래의
  결론 — **`#<derivation>` 접미 강제, 3류.** 예: `#mean_agg`. 어느 쪽인지는
  config에 **선언**하고, `test_every_declared_derivation_is_explicitly_classified`가
  분류를 강제한다 (R-D·상설 규칙의 적용례).

## 4. 번역기 선언 스케치 (`ledger_config.json`에 한 장)


## 5. 화면 소비 (보이드 해석에서의 자리)

- 추적/패키지 화면에서 자재 홉 옆에 계측 팩트 몇 줄: 「BLT 12.3µm (n=49, #mean_agg)」
  — basis 규율(R-C) 그대로: 가정/집계는 표시가 다르다.
- 형제 공유 요인(2주차)의 입력: 「보이드 난 3자재가 전부 BLT 하위 10%」류의 한 줄이
  이 어휘가 사는 목적이다.

## 5-bis. MI↔void 물리 모델이 서면 온톨로지에 어떻게 심는가 (제품 소유자 질문, 2026-08-13 밤)

물리 모델(예: BLT·휨·본딩 조건 → 보이드 형성)은 어휘도 원장도 아니고 **「선언되고
버전이 박힌 규칙」**이다 — `#slot_preserving`(관례)과 `#frame_from_eqp_product`
(유도 규칙)가 이미 놓은 그 자리의 세 번째 시민. 심는 방법은 다섯 문장이다:

1. **모델 = 선언 + 버전.** config에 등록: 모델 id·버전·**입력 시그니처(어느
   물리량들)**·출력(무슨 주장). 해시가 provenance에 박히므로 모델 v2와 v3의 주장이
   원장에서 나란히 구분된다 — append-only가 모델 버전 비교를 공짜로 만든다.
2. **입력 계약은 물리량 어휘가 이미 준비했다.** 6요소의 quantity(단위·차원 시그니처)가
   모델의 타입 시스템이다. 모델이 아직 없는 물리량을 요구하면 → 그 물리량의 어휘
   등재와 수집이 먼저다. **모델의 변수 목록이 곧 «무엇을 수집할지»의 우선순위표가
   된다** — 물리 모델링이 서는 순간 얻는 가장 큰 실익.
3. **점수는 투영에, 지속 주장만 원장에.** 모델의 위험도 점수는 재계산 가능한
   숫자라 투영(캐시)에서 접는다 — 「숫자는 쌓지 않는다」. 원장에 들어가는 것은
   둘뿐: 지속되어야 할 결론(예: 재검 필요)은 **3류 추론 원자 + `#<모델명_버전>`
   접미**로, 그리고 모델에 근거한 **액션**은 액션 스키마 그대로
   `(대상, action:*, 근거{모델 id·버전, 입력 원자들의 raw_ref, 투영 세대})`.
4. **관측이 항상 이긴다 — 그리고 빗나감이 관측으로 돌아온다.** 모델이 위험하다 한
   패키지가 깨끗이 스캔되면 관측(2류)이 예측(3류)을 자동으로 이기고, 그 빗나감
   자체가 기록 가능한 사실이 되어 모델 개선의 입력이 된다(OODA — 효과가 관측으로
   회귀). 모델 검증도 같은 구조: 예측 대 실제 보이드 발생을 원장 폴드로 대조 —
   가상 MI의 «정답지» 구조가 실모델 검증 하네스로 일반화된다.
5. **화면은 basis 확장 하나.** R-C의 구조화 basis가 `{kind: model, name, version}`을
   받으면 끝 — 모델 근거 팩트는 가정 계열(점선)로 렌더되고, 세 번째 시각 어휘는
   만들지 않는다.

## 6-bis. 디펙 · 보이드 · MI 원장 통일 검토 (제품 소유자 요청, 2026-08-13 밤)

**결론: 통일 가능하다. 골격은 이미 하나고, 갈라지는 것은 술어 둘뿐이다.**

셋을 나란히 놓으면:

| | 누가·어떻게·어디·언제·발화자 | 무엇을·얼마 (갈래) |
|---|---|---|
| MI 계측 | **동일** (6요소 골격) | 물리량의 «값» — 연속량 |
| 보이드 | **동일** — 위치 문법도 방금 통일됨 (칩 + inchip) | 발견의 «존재와 범위» — 기하 |
| 디펙 일반 (fab·dt·bonding) | **동일** | 발견의 «존재와 종류» (+기하) |

즉 차이는 object 하나에만 있다. 술어 둘로 갈래를 명명한다:

- **`measured`** — 물리량의 값: `{quantity, value, unit, …}` (MI)
- **`observed`** — 발견의 존재: `{finding_kind, geometry?, gate?, …}` (보이드 =
  `finding_kind: void`, fab 디펙 = 각자의 kind — **닫힌 값 집합, 추가 전용**)

이로써 §12에 걸려 있던 **`observed` 술어 필요성 판정이 닫힌다**: 1주차 투영은 필요
없었고(예상대로), 디펙 축이 서는 지금이 그 술어가 필요해지는 시점이다 — 어휘 v0로
등재한다. (「필요가 실증된 뒤 등재」 — 어휘 성장 규율 그대로.)

통일이 공짜로 사주는 것:
1. **번역기 패턴 하나** — 세 소스가 같은 골격의 선언을 쓴다 (분모 재사용 포함).
2. **화면 팩트 렌더러 하나** — 추적/패키지 화면에서 계측 팩트와 디펙 팩트가 같은
   문법으로 앉는다 (basis·발화자 배지 포함).
3. **형제 교집합이 세 축을 한 질의로** — 「보이드 난 자재들이 공유하는 것」을 셀 때
   eqp·recipe·lot·tape가 measured/observed 불문 같은 payload 필드라 요인 후보를
   같은 방식으로 센다.

통일하지 «않는» 것 (경계 명시):
- **소스 테이블은 각자 산다** — void_obs와 mi_obs의 컬럼이 다른 것은 방언의
  다양성이고, 통일은 원장(공통 언어)에서 한다. 소스 테이블을 하나로 합치는 것은
  방언을 어휘에 맞추는 역방향이라 기각.
- **run 간 재식별 안 함**은 셋 모두 동일 적용 (관측은 그것을 만든 스캔에 속한다).
- **판정값(pass/fail·grade) 저장 금지**도 셋 모두 동일 (임계는 레시피 파라미터).

## 6-quater. 불량의 class — 컬럼이 아니라 «주장» (제품 소유자, 2026-08-14: "정확히는 class에 대한 주장이지")

보이드·디펙류에는 분류(class)가 필요하다 — 계면/벌크/에지 보이드, 디펙의 유형 등.
소유자의 표현이 설계 그 자체다: **class는 저장된 속성이 아니라 주장이다.** 도구가
분류하고, 사람이 영상을 보고 뒤집고, 그 정정이 이 시스템의 핵심 워크플로(최소 공수
교정)다. 두 갈래로 받는다:

**① 소스가 스캔 시점에 분류를 발화하면 — 같은 발화의 일부.**
`observed` payload에 `class` 필드: `{finding_kind: void, class: interfacial, …}`.
같은 원자, 같은 발화자(도구). class 값 집합은 **finding_kind별 닫힌 집합**으로
어휘 시그니처에 선언(추가 전용, 로컬 선등재) — 두 장비가 같은 class 이름을 쓰면
프레임 검사 먼저(같은 물리 기준인가).

**② 사후 재분류 — 별도 주장, `classified_as`.**
```
(Wafer W, classified_as,
 {kind: event_ref → 원래 observed 원자 id, payload: {class, scheme?}},
 occurred_at, source{who: 사람 또는 다른 도구})
```
어느 관측을 재분류하는지는 **event_ref가 핀한다**(관측은 run 간 신원이 없으므로
위치 재조합이 아니라 원자 참조가 옳다). 해소는 레이어링 그대로: 사람의 재분류가
도구의 원래 class와 경합하면 등재 우선순위(수동>자동)로 이기고, 화면은 경합을
contested로 보인다. 도구 v2의 재분류도 같은 문법 — **분류 이력 전체가 남는다.**

**경계 유지**: class ≠ 판정. "무엇인가"(계면 보이드)는 주장으로 받지만
"합격인가"(pass/fail)는 여전히 저장 금지 — 임계는 레시피 파라미터라는 규칙 불변.

**콘솔 파급**: class가 현황판의 슬라이스 축이자 케이스-컨트롤의 대조 축이 된다
(「계면 보이드만 이 장비에 몰림」). 가상 소스 정답지에 class별로 다른 요인을 심으면
분류 축의 분석도 정답 대조로 검증된다.

## 6-ter. 비정량 인간 관측 — fab의 OM 등 (제품 소유자 지시, 설계 판단 위임분)

정규 계측이 아닌, 사람이 현미경(OM) 등으로 «본 것» — 「이물 있음」「긁힘」「들뜸
의심, 심함」 — 도 원장에 들어간다. 최적 설계 판단 넷:

**① 어휘는 새로 만들지 않는다 — `observed`가 이미 그 자리다.**
```
(Wafer W, observed,
 {finding_kind,          # 이물·scratch·변색·들뜸… — 닫힌 집합, 로컬 선등재로 성장
  severity_word?,        # 관찰자가 «말한» 낱말 그대로 (아래 ②)
  zone? | {frame, die_x, die_y, inchip…}?,   # 위치는 «가능한 만큼만» — 굵은 zone
                         #   (edge·center·사분면)도 정식 위치 어휘다
  note?,                 # 자유 텍스트 — 화면 표시·재발화용. 로직이 파싱 금지(R-C)
  method: "OM"},
 occurred_at, source{who: 관찰자, raw_ref: 행/사진})
```

**② `severity_word`가 「등급 저장 금지」에 안 걸리는 이유**: 금지된 것은 **계산된
판정**(임계 대비 pass/fail — 임계가 레시피 파라미터라 재심 불가)이고, 사람의 「심함」은
계산이 아니라 **그 사람이 발화한 관측 자체**다. 원장은 발화의 기록이므로 낱말 그대로
싣는다.

**③ 입구는 교정 표면이다 — 새 입력 장치를 만들지 않는다.** `fab_obs` 테이블을
선언하고 **기존 그리드에서 사람이 직접 행을 친다.** 공짜로 얻는 것: 편집 UI·
레이어링·이력·공수 계기 전부 기존 것이고, 원장은 여느 소스처럼 번역기 한 장으로
읽는다 — 사람 입력도 «소스»다, 발화자가 사람일 뿐. 유일한 신규 결정: **사람이 자기
행을 고치면 그것은 재발화다** — 번역기가 `updated_at` 워터마크로 수정 행을 재방문해
**supersedes 원자**를 낸다. 원장 규율과 사람의 수정 습관이 여기서 정확히 만난다.

**④ 분모의 정직**: 임의적 OM 관찰엔 체계적 분모가 없다 — 「봤는데 깨끗함」은 거의
기록되지 않는다. 그러므로 투영은 **OM 관측의 부재를 깨끗함의 증거로 절대 세지
않는다**(SAT와의 차이 — 거긴 run 분모가 있다). 현장이 「검사했음, 특이 없음」을
기록해 주면 `inspection_run(method='OM')` 행으로 환영하되, 요구하지 않는다.
