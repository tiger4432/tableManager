# 정준 원장 · 온톨로지 설계 — 착수 문서

> **Status:** 🔵 설계 확정 · **구현 0** | **작성:** 2026-08-12 (포크 세션 결산) | **소유:** 총괄 + ontology-pm
>
> 제품 소유자와 총괄이 포크 세션에서 확정한 설계의 결산이다. 스트레스 테스트 다섯 —
> 디펙·보이드·레시피·테입 / 수율·잔량·액션 / dt_frame / 전역 커버리지 / 현행 연결 —
> 을 통과했고 **골격 수정은 0**이었다. 바뀐 것은 어휘·규칙·경계 선언뿐이며, 그것이 이
> 골격이 맞다는 현재까지의 증거다. 구현은 본 세션의 확정 시스템 진도와 맞물려 착수한다.
>
> 🔴 이 문서는 **설계이지 현행 서술이 아니다.** 여기 적힌 것 중 코드에 존재하는 것은 없다.

## 0. 한 문장

> **언어는 다스리고, 원장은 쌓고, 투영은 접고, 액션은 근거를 남긴다 — 권위는 원장 한 곳에만 있다.**
>
> **숫자는 쌓지 않는다. 주장을 쌓고, 숫자는 접는다(fold).**

## 1. 전체 지도


**투영**(그래프 포함·캐시). 미군의 교리·CCO 어휘 / 보고 아카이브 / COP·MIDB 뷰와 같은 3분할.

## 2. 왜 — 조인의 벽

- 참조뷰의 config는 **O(질문)**으로 는다. 이 설계에서 번역기는 **O(소스)**, 술어는 **O(개념)** — 새 추적 질문의 config 비용이 0이 된다.
- 혈통(스플릿·병합 추적)은 **가변 깊이** 질문이라 조인이 원리적으로 못 한다(transitive closure). 경계 규칙: **홉 수가 데이터에 달려 있으면 그래프 몫, 스키마에 달려 있으면 조인 몫.**
- 결측 추정 = 「선언된 엣지를 따라 가장 가까운 확정값」 프리미티브 하나. 추정값은 낮은 우선순위 **주장**으로 얹혀 실제 배송이 오면 자동으로 진다 — 기존 레이어링 원리의 재사용.
- 확정의 책임 경감: **확정 = 핀 주장**(파괴 없음), **번복 = 핀 철회 → 차순위 후보 노출** — R2 인출 의미론 그대로. 다중 후보는 MHT(다중가설추적)의 40년 된 원형을 따른다.

## 3. 원자 스키마 — 7필드

**원자 = 홀로 남아도 참인 주장 하나.** 16컬럼 행은 원자 16개다(행은 분자).

```
event {
  id          uuid7                      # 단조 = 워터마크 + 기록시각 내장
  subject     { type, keys{col: val} }   # 구조화된 신원. 이어붙인 문자열 금지
  predicate   닫힌 어휘 (§4)
  object      { kind: 값|개체참조|이벤트참조, payload(타입 보존) }
  occurred_at                            # 세상의 시각 ≠ 기록 시각
  source      { who, translator_ver, raw_ref }
  supersedes? event_id                   # 정정·철회 = 새 원자
}
```

| 필드 | 근거가 된 실제 사고 (2026-08-11) |
|---|---|
| `id` 단조 | 감싸 도는 픽스처 키가 인덱스 측정을 오염시킨 실측. `recorded_at`은 uuid7에 내장돼 필드 절약 |
| `subject` 구조화 | 이어붙인 키가 빈 조각에서 `a_b`→`a`로 무너져 운영 17만 행 |
| `predicate` 닫힘 | `dt_job` vs `dt_job_id` — 자유 이름은 기계마다 철자가 다르다 |
| `object` 타입 보존 | 렌더 문자열 감사에서 정수 `0`=문자열 `"0"`, NULL=`비어있음` |
| `occurred_at` 분리 | 재적재가 순서를 바꾸면 안 된다 — 「newest는 재접촉이 아니라 새 주장」 |
| `source` 3요소 | 출처 의무(ICD 206) + 번역기 버전 + **원문 참조(재번역 유일 경로)** |
| `supersedes` | append-only의 정정 수단 |

**원자성 검사 넷** (게이트에 건다): ① 홀로 참인가 ② 반쪽 없이 착지하는가 ③ 결론이
아니라 발화를 적었는가 ④ `raw_ref`로 재발화 가능한가.

**일부러 뺀 것**: confidence(추론 주장의 object 안 — 봉투 아님) · priority(해결기
config) · processed/status 플래그(**가변 필드 0** — 소비자는 자기 커서) ·
batch/transaction 의미(상관 표지는 비의미 필드, 해석기가 읽으면 계약 위반).

## 4. 어휘 — 정준과 온톨로지의 분리

판별법: **object가 이벤트참조·∅면 정준(기록에 대한 말), 값·개체참조면 온톨로지(세계에
대한 말).**

### 4.1 정준 어휘 — 기록의 문법. **사실상 동결** (변경 = 마이그레이션급 사건)

- 봉투 7필드 (§3)
- 행위 술어: `register`(발급, object ∅) · `pin`(선택, object=이벤트참조)
- 예약: `same_as`(개체 동일성 재정) · `action:*`(발령 기록, object=근거)
- 🔴 도메인 개념(slot 등)이 이 층에 스며들면 골격 오염이다.

### 4.2 온톨로지 어휘 — 세계의 언어. **append-only로 성장**

**개체 타입** (v0):

| 타입 | 부류 | SEMI 앵커 |
|---|---|---|
| Lot · Wafer | 발급형 | E90 substrate |
| **Die** | **구성형** = Wafer × 제품 그리드 → **register 불필요** | E142 location |
| Product · Equipment | 발급형 | — / E10 |
| 예약: TapeLot · Defect · Recipe | 발급형 (재식별 판정 후) | — |

**관계 술어** (v0):

| 술어 | subject → object | 앵커 |
|---|---|---|
| `derived_from` | Lot → Lot | E90 genealogy |
| `slot_map` | Lot → Lot + {from, to} — 슬롯 쌍당 원자 1 | E90 |
| `has_wafer` | Lot → Wafer + {slot} | E90 |
| `frame_confirmed` | Wafer → 프레임값 (닫힌 8후보) | E142 좌표계 |
| 예약: `processed_with`(E40) · `state`(E10 6상태) · `consumed`·`reserved`(잔량 fold) | | |

**attr 개념**: lot · slot · wafer · product · equipment · bin · position{frame,x,y} ·
event_time. **단위 규율**: 수치 개념은 {value, unit} — 단위 없는 수치 등재 불가.

**투영 상태어** (`resolved`·`contested`·`candidate(rank,n)`·`unresolvable`·`pinned`)는
셋째 어휘로, **원장에 절대 기입되지 않는다** — 캐시가 자기 상태를 말하는 낱말이다.

### 4.3 성장 메커니즘

🔴 **어휘 자체도 append-only다.** 원자가 술어를 영원히 참조하므로 삭제·재정의 불가,
deprecate(신규 기입 금지)만 가능. 항목마다 **서명**을 선언한다:

```json
"derived_from": { "status": "active", "since": 1,
  "subject": ["Lot"], "object": {"kind": "entity", "types": ["Lot"]},
  "unit": null, "semi_ref": "E90 genealogy", "superseded_by": null }
```

등재는 **3문 검사**를 통과한 판정으로만: ① 기존 어휘로 정말 못 쓰나(재사용 검사)
② SEMI 대응이 있나(있으면 차용 + `semi_ref`, 없으면 `"local"` 명시) ③ 클래스별 검사
(개체 후보 → 재식별 검사 / 좌표류 → subject 금지 검사 / 값 → 단위 선언).

## 5. 규칙 모음 (판정 완료)

1. **subject는 등록 개체 타입만.** 자연 주어가 미등록이면 가장 가까운 등록 개체에
   붙이고 위치는 payload로 (ABI georeference-to-discover). 개체 날조 금지, 이벤트
   폐기도 금지(sequence neutrality — 답이 질문보다 먼저 올 수 있다).
2. 🔴 **번복 가능한 주장은 subject에 못 들어간다** (dt_frame 판정). 프레임 좌표는
   payload `{position{frame,x,y}}`로 적고 **다이 결합은 투영에서** 현재 우승 프레임
   확정으로 계산한다. 핀 철회 → 재투영으로 소속만 재계산, 원자는 하나도 안 틀린다.
3. **발급형/구성형 분리.** 존재가 우연적이면 register 이벤트(Lot·Wafer·Defect),
   정의적이면 구성(Die = Wafer × 제품 그리드 — 다이 1.6억 register 문제 소멸).
4. **재식별 검사** — 여러 관측에 걸쳐 「같은 것」이라 다시 집을 필요가 있으면 개체,
   아니면 attr 주장. (보이드 성장 추적 = 개체 / bin 값 = 주장)
5. 🔴 **텔레메트리 반입 금지.** 원장은 주장의 기록이지 텔레메트리 저장소가 아니다 —
   트레이스는 제 저장소에, 원장엔 파생 주장만 raw_ref를 달고.
6. **투영은 손대지 않는다.** 정정은 원장에 이벤트로 (「dt_map은 손으로 고치지
   않는다」의 일반화).
7. **액션 = 근거 명기 이벤트.** `(대상, action:*, 근거{투영 세대, 규칙 버전})` —
   같은 근거 재발령 금지(멱등), 정당화 데이터 영구 추적(감사), 효과는 관측으로
   복귀(폐루프). 고위험 액션은 사람 핀이 문턱.

## 6. 해결 서열

```
0 핀(사람) > 1 확정된 체인 주장 > 2 관측 > 3 추론
  같은 계급 안: 등재 우선순위 → occurred_at 내림차순 → 이벤트 id (전순서)
  2·3층은 계급을 넘지 못한다 — SSOT §4 「우선순위 결정」과 동일 규칙
```

해결기는 **하나**다(소비자마다 따로 해결하면 「같은 질문에 화면마다 다른 답」).
해결기 변경 = 새 투영 세대 강제 — 조용한 답 변경을 가시적 diff로 만든다.

## 7. 파생 수량과 액션

```
수율(Wafer) = fold { (Die, register…구성) + (Die, attr:bin, 값) }
잔량        = fold { register(+) · attr:usable · consumed(−) · reserved(−) }
```

성질 넷: **드리프트 불가**(저장 카운터가 없다 — 재접기가 곧 검산) · **정정이
흐른다**(supersedes·늦은 관측이 자동 재계산; 프레임 재확정 한 방에 다이급 수율
자동 재산) · **모든 숫자가 설명 가능**(드릴다운 → 원자들) · **신선도
명시**(워터마크). 규모에선 증분 물질화 + **전량 접기와의 대조 검산 패스**(전량이
정본, 증분이 캐시).

### 7-bis. 🔴 1000랏 실측이 이 절을 정정한다 (2026-08-12, 합성 프로브)

이 절이 「증분 + 검산」이라고 한 줄로 적은 것을 실제로 재 봤다
(`agent_workspace/reports/Incremental_materialization_1000lots.md`, **합성 모델 ·
이 박스 · 운영 증거 아님**). 세 가지가 이 절의 서술을 바꾼다.

**① 검산의 «주기»가 경제성 전부다 — 이 절은 그걸 안 적었다.** 검산 = 전량 접기
1회(43.0초) + 해시합 비교(0.92초). 그래서 **전량만 44.0초 대 증분+매배치검산
63.6초 — 캐시가 없느니만 못하다.** 손익분기 주기는 **2배치당 1회 이하**이고,
10배치당 1회면 45% 절약. **주기 없는 검산 선언은 설계가 아니다.**
비교는 해시합을 관문으로, `EXCEPT ALL`(10.3초)은 위치 특정에만.

**② 증분이 전량보다 단위당 34~52배 비싸고, 원인이 §5-2다.** 전량 38.8µs/슬롯 대
증분 2.02ms/접촉슬롯. 손익분기 **접촉 슬롯 2~3%**(1000랏에서 약 22,000~30,000).
기전은 플랜 사고가 아니라 구조다 — **§5-2가 프레임을 subject에서 금지**하므로
다이 슬롯 키가 **계산된 정준 좌표라 인덱싱이 불가**하고, 플랜이 263만 행을 조인
필터로 버려 9,987행을 낸다. 🔴 **§5-2는 옳은 규칙이고 이것이 그 규칙의 청구서다.**
그리고 선형성 5축 중 이 축만 깨졌다(+53.5%) — 웨이퍼당 원자 수가 늘면 더 나빠지므로
**34~52배는 천장이 아니라 바닥**이다.

**③ 질의 시점 해결은 5개 투영 클래스 중 3개에서 유효하고, 죽는 건 하나다.**
점 조회(0.60 대 0.39ms) · 웨이퍼 500다이 bin 맵(4.71 대 4.17ms — 물질화 이득 거의
없음) · 잔량 전량 fold(186ms)는 질의 시점으로 충분하다. **죽는 것: 슬롯 단위 혈통 —
인라인 452ms/건 대 물질화 0.58ms/건, 780배이고 20배 원장에 34.8배로 초선형.**
§10의 「초기엔 질의 시점 해결」은 **랏 단위 추적에만** 성립한다.

**부수 측정**: 늦은 도착으로 재해결됐는데 결과가 같은 슬롯이 **19.8%** — sequence
neutrality의 가격표(19.7초 중 3.9초). 「정정이 흐른다」는 **싸다**: 재결합 원자당
30~42µs, 다이 전면 커버(1,250만 원자) 환산 **≈376초 = 6분 배치**.

**바이트**: 힙 312.3B/원자(71.1%), 인덱스 몫 **28.9%** — `cell_sources`의 74.9%보다
건강하지만 **접근 경로가 둘뿐이라서**다. subject 키 인덱스를 하나 더 달면
+95B/원자(+21.7%). 투영은 435B/슬롯으로 **원장 자체의 89%**.

⚠️ **계측기 고장 둘을 잡고 보고했다**: 임시 테이블에 `ANALYZE`가 없어 플래너가
474MB 투영을 seq scan → P4에 **가짜 10.9배 스케일 비선형**이 떴다(통계 호출 하나
빠진 것). 그리고 프레임 폭풍 뒤 비교 비용 6배는 **부풀림**이었다(1,139ms →
`VACUUM FULL` 후 183ms) — 검산 수치는 전부 vacuum 후 정상 상태다.

## 8. SEMI 차용 — 어휘를 발명하지 않는다

언어가 3층이 된다: **골격**(우리, §4.1) / **SEMI 개념**(차용) / **소스 방언**(번역으로
소멸). 미군이 CCO를 중간층으로 쓰는 구조와 동일.

| SEMI | 다루는 것 | 우리 지도 |
|---|---|---|
| **E90** | 기판 추적·genealogy | 혈통 전장 그 자체 |
| **E142** | 기판 맵·좌표계(복수 인정)·bin | 맵·Die (2026 대개정 진행 중) |
| E10 | 장비 6상태 (PRD·SBY·ENG·SDT·UDT·NST) | `state` 닫힌 값 집합 |
| E40 | 공정 잡 | 구간 사건 모델 (판정 대기 §11) |
| E30/SECS-II | 장비 이벤트 | 장비 소스 번역기 원형 |

⚠️ SEMI 본문은 유료 — 공개 요약·스키마(E142.1 XML)로 1차 확인함. 실제 차용은 본문
확보·대조 레인(§12-1)이 선행.

**커버리지의 정직한 답**: v0 어휘는 혈통용이다. 전역 커버는 상태가 아니라 **과정**이며
(MIDB도 수십 년 큐레이션), 골격 스트레스 지점 넷 중 셋(구간 사건·단위·타입 수준
주장)은 수용 가능, 하나(텔레메트리)는 경계 선언으로 봉쇄(§5-5).

## 9. 참조 근거 (미군)

- **BFO/CCO** — 2024 DoD·IC가 상위/중위 온톨로지 기준선으로 채택. continuant/occurrent 분리, `is_about`/`designates`(관측은 개체를 가리키지 되지 않는다)
- **ICD 203** — 추정 확신도의 닫힌 어휘 (7단 + 수치 구간)
- **ICD 206** — 배포 산물의 출처 명기 의무 → source 필수·투영의 세대 인용
- **JP 2-0** — 원시↔완성 정보 분리, 정보 격차 → 수집 요구 (= contested 슬롯 → 워크리스트)
- **JP 3-0 COP** — 공유 그림은 산출물이지 권위가 아니다 (= 투영)
- **Reid 1979 MHT / Forty Years of MHT** — 다중 가설 유지·가지치기 (= 후보 스킴·축적 상한)
- **JDL 융합 모델** — Level 0→1 관측→개체 상관 (= 층 건넘의 키 변경)
- **BE 번호/MIDB** — 신원은 등록 행위 (= 발급형 개체) · **OBP** — 객체 = 수렴점 · **ABI 4기둥** — georeference to discover(= locator 정박) · data/sequence neutrality

(링크 전체는 포크 세션 대화에 있음 — irp.fas.org의 ICD·JP 원문 PDF, CCO GitHub, ISIF MHT 저널)

## 10. 현행 연결 전략

> **제1원칙: 원장은 기존 시스템의 «소비자»로 태어난다. 쓰기 경로는 한 줄도 안 바꾼다.**

`ledger_translator` = chain worker·graph_sync_worker의 **셋째 형제** (outbox 구독,
자기 커서). `ledger_events` 신규 테이블, **첫날부터 시간 파티션**.

| 단계 | 연결 | 비고 |
|---|---|---|
| 1 씨앗 | `lot_event` 백필 (일회성 번역) | 🎁 이미 이벤트 테이블 — `event_time`이 occurred_at을 그대로 줌 |
| 2 라이브 | outbox 중 lot_event분 구독 | 백필 워터마크 이후분부터 |
| 3 확정 편입 | `frame_confirmation` 쓰기 → `frame_confirmed`·`pin` 원자 | 확정 시스템의 원장 편입점 |
| 4 attr 최소 | bonding_log·dt_log의 **신원 컬럼만** (lot·slot·wafer_id) | 원자 수 통제 |
| 5 대조 운행 | 추적 질의를 참조뷰와 병행 N일 → diff 0 | 컷오버 조건 |
| 6 컷오버 | **질의 단위** 전환. 참조뷰는 대조군으로 존속 | |

**위험 통제 셋**: ① occurred_at — 번역기 config가 소스별 시각 컬럼을 선언, 없으면
거절 (도착 시각 대용 금지) ② outbox 7일 purge — 초기엔 테이블 백필이 복구 수단임을
명시 수용, purge 조건에 원장 커서 추가는 별도 판정 ③ 멱등성 — 커서 전진과 원자
append를 **한 트랜잭션에** (watcher P2-A 패턴 재사용).

**관측성 (탄생 조건)**: `note=` 박동에 거절 계수 + **뒤처짐 보고**(커서 vs outbox
헤드) — 그래프 워커가 못 하는 그것을 첫날부터.

**무변경 목록 (명시)**: `crud.py` · `apply_batch_updates` · cell_sources · 체인 워커 ·
기존 그래프 · 참조뷰 · 공식 맵 경로. **원장이 죽어도 현행 시스템은 무사하다** — 이
전략의 안전 증명.
