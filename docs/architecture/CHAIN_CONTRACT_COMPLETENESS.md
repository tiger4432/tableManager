## 0. 읽는 법 — 표 A 와 «같은» 네 표시

```
①   선언 칸이 있다            이름이 있고, 어긋나면 «이름 대어» 거절된다
②   기본값이 덮는다            칸은 없지만 «값이 적혀» 있고 한 자리에서만 정해진다
③   없다 = 결함              적을 자리도 덮는 값도 없다
③′  칸은 있는데 읽는 쪽이 0     선언이 약속하고 아무도 안 지킨다 (표 A 와 같은 뜻)
```
⚠️ **「맵퍼 «본문»이 무엇을 계산하나」는 이 표의 칸이 아닙니다** — 소유자 결정으로 체인은
파이썬이고(「둘째 도약(선언형 맵퍼)은 필요없어」), 그래서 본문은 «셀 수 없는 것»으로 §8 에 따로 적습니다.

## 4. 실패하면

| 칸 | 표시 | 근거 | 비고 |
|---|---|---|---|
| 예외 → 격리 | ② | 청크 단위 격리, 안 되면 «행 단위»로 좁힌다(워커 주석이 1,000 행 청크를 통째로 버리지 않는 이유를 적는다) | 값이 적혀 있고 칸은 없다 |
| 시도 상한 | ① | `max_group_attempts()` — 문서 최상단 키, 기본 «1» | 판정 245a24e8 |
| 연쇄 깊이 상한 | ① | `max_chain_depth` + `event_constants.max_chain_depth(document)` | 넘으면 「뒤 큐가 돈다」고 로그가 이름을 댄다 |
| **미룸 상한**(읽을 수 없는 행) | 🟡 **②** (09-11 신설) | `max_rows_not_visible_defers` — 문서 최상단 칸, 기본 `DEFAULT_MAX_ROWS_NOT_VISIBLE_DEFERS = 30`(스윕 ≤ 2 s 이므로 «약 1분»). 읽으면 `_RULES_DOCUMENT` 에서 «부를 때마다» 보므로 SYSTEM_RELOAD 로 반영된다 | 🔴 **미룸은 «시도»가 아니다** — `retry_count` 와 별도 카운터(`_ROWS_NOT_VISIBLE_DEFERS`)다. 시도로 세면 `max_group_attempts`(기본 1) 때문에 멀쩡한 청크가 첫 번에 격리되고, 격리는 청크를 «행 단위»로 다시 편다(실측 쓰기 여섯 → 사건 ≈1,700). ⚠️ 그래도 «유한»하다 — 상한에서 «이름 대어» 거절한다(S-160, 판정 267). 📎 **정본 서술**: `event_driven_backend.md` §2.4~2.5 — 「전부 없음 = 거절」 / 「아직 안 보임 = 미룸」의 가름과, 그 창의 «원인»(오염된 autocommit 커넥션이 행과 사건을 다른 커밋에 씀, S-167 09-11 13:37 닫힘) |
| **재시도가 «같은 입력»인가(멱등)** | 🔴 **③** | 규칙이 「이 맵퍼는 멱등이다」를 «말할 칸»이 없고, 재시도는 같은 그룹을 그대로 다시 먹인다 | 맵퍼 본문의 성질이라 §8 과 맞물린다 |

## 6. 🔴 그리고 «문법 자체»가 검증되지 않는다 — 이 표의 제일 큰 ③

| 칸 | 표시 | 근거 |
|---|---|---|
| **규칙 하나의 «모양»** | 🔴 **③** | `load_chain_rules()` 는 `json.load` 뒤 `data.get("rules", [])` 가 전부다. 필수 키 검사도, «모르는 키» 거절도 없다. 어드민 쓰기 경로(`ledger_admin`)의 주석이 «스스로 적어 둔다** — 「Nothing validates a single rule's shape - `chain_bindings` refuses at run time - and none was invented here」 |

🔵 **[09-11 총괄 정정] 「거절이 0」은 «아닙니다» — 오타의 «자리»에 따라 갈립니다:**
```
«키» 오타      조용히 통과.  `trigger_colums: [...]` 는 «모르는 키»라 무시되고 규칙은 표 단위로 돈다
«값» 오타      그 칸만 거절.  `trigger_columns: ["dt_jobb"]` 는 트리거 표가 «선언하지 않은 컬럼»이라
              `_report_unwatchable_trigger_columns` 가 로드 때 «이름을 댄다»(S-140 ④)
=> 즉 오늘 있는 것은 «칸 안의 값» 검증이고, 없는 것은 «칸 자체»의 검증이다.
   그래서 S-152 는 「값 검사를 더한다」가 아니라 「키 집합을 «닫는다»」이다
```

```
결과   오타 난 «키»는 «조용히 무시»된다. `trigger_colums` 로 적으면 표 단위로 굴러가고 아무도 안 알려 준다
대비   원장은 `setup_bundle` 이 `problems.exact(...)` 로 «모르는 키»를 이름 대어 거절한다
그래서 「선언을 고쳤는데 아무 일도 안 난다」가 체인 쪽에서는 «정상 동작»처럼 보인다
```
⚠️ 이것이 §2 의 `group_by`·그룹 «크기» ③ 과 «같은 뿌리»입니다 — 칸을 더해도 검증기가 없으면
그 칸은 오타 한 글자에 조용히 사라집니다. **순서는 「검증기 먼저, 칸은 그다음」입니다.**

## 8. 셀 수 «없는» 것 — 맵퍼 본문 (이름 대어 적는다)

```
무엇      맵퍼 파이썬이 «무엇을 계산하나»는 선언에 없다. 소유자 결정이고 이 표의 결함이 아니다
그래서    이 표가 답할 수 없는 물음 둘:
          ① 이 맵퍼는 «몇 번 돌려도 같은가»(멱등) — §4 의 ③ 과 같은 자리
          ② 이 맵퍼는 «어떤 행을 낼 수 있나» — 산출의 «모양»은 검증되지만(§3) «외연»은 아니다
보이는 것  `mapper_module` · `mapper_function` 이름과, 그룹 줄의 «초»와 `rows_in/rows_out`
          🔵 D-5 실측이 그 한계를 보여 준다: 정렬 맵퍼가 그룹당 «뷰 1,000»을 짓고 `rows_out` 은 0.
             「무엇을 하는지」는 표에 없고 「얼마가 드는지」만 있다 — 그것이 오늘의 가시성이다
```

## 9. 셈 — ③ «여섯» · ③′ «0»

```
③  여섯
  ㉠ 규칙 «모양» 검증 없음 (§6)          <- 나머지 다섯의 뿌리
  ㉡ 그룹 «키» 칸 없음 (§2)
  ㉢ 그룹 «크기» 손잡이 없음 (§2)        <- D-5: 이것만으로 s/1k 30%
  ㉣ 멱등을 말할 칸 없음 (§4)
  ㉤ 규칙 «사이»의 순서 (§5)
  ㉥ HOL 미룬 수 · 소급 전 비용 (§7, 관측 둘을 한 줄로 셈)
③′ 0    — 칸이 있는데 읽는 쪽이 0 인 자리는 «찾지 못했습니다»
        (체인 쪽은 반대로 「읽는 쪽이 있는데 칸이 없다」가 많습니다 — 위 여섯이 그 모양입니다)
```
🔴 **원장과 «대칭이 반대»입니다.** 원장은 「칸을 먼저 열고 읽는 쪽을 나중에」(그래서 ③′ 가 생겼고),
체인은 「기제를 먼저 짓고 칸은 안 만들었다」(그래서 ③ 이 전부 «칸 없음»입니다).
