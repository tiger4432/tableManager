## 0. 제품의 쓰임 — 모든 기저의 «주어»
```
문제가 난다(결함 · 수율 이탈)
 → 운영자가 대상을 «마킹»한다
 → 걸어서 닿는 하위 그래프(자재 · 공정 · 레시피 · 장비 · 검사)를 가져온다
 → «대조군»과 견줘 「무엇이 다른가」를 «순위»로 받는다
 → 필요하면 «행동»한다(홀드 · 이송 · 계획 · 확정)
그리고 이 전부가 «선언»으로 된다 — 임의 스키마에서 «두 줄»로 (완성의 정의, 2026-08-30)
```
지식 탐색과 운영은 «같은 기저»를 쓴다(소유자 문답 09-08 22:3x). 운영에서 느는 것은 «선언»이지 생성자가 아니다.

## 0-bis. 🆕 명제 — 「**행 하나는 사실 하나**」 (소유자 2026-09-15) · **정본은 여기다**

> 「결국 최종 목표는 하나야 — **행 하나는 사실 하나**」
> 「난 항상 단순한 설계를 지향해. 그래야 고장도 안 나고 빠르거든」

위 §0 이 «주어»라면 이 줄은 그 주어가 사는 «모양»이다. 통합도, 유일 키도, 실물화도 이 문장의 «따름정리»다.

```
행      «사실» 하나. 그 사실이 무엇인지 말하는 것이 «신원»(키)이다
칸      그 사실에 대한 «주장». 주장마다 «누가 말했나»(source layer)가 붙는다
원장    그 사실들을 원자로 번역한다 — 그러려면 사실이 «어딘가 행으로» 있어야 한다
```

### 0-bis-1. 그래서 따라오는 것 — 「**껍데기 셋, 체인 하나**」

```

`enrichment_rules.json` 과 `virtual_join_rules.json` 은 그것을 «적는 다른 문법»이지,

## 2-0. 번역이라는 «행위»의 기저 — 소스 → 원장 (09-09 17:51, 소유자 「소스 → 원장 기저 다 잰 거 맞아?」 → 「좀 수학적으로 재 봐」)
🔴 §2.3 의 D_Π(소스 인자 공간)는 이 절의 «구현»이다. 09:46 의 동결 검사는 「칸 → 인자」 한 방향만 참이었고 인자 목록이 «지어 놓은 것»에서 나와 하루에 축 둘(S-91 · S-99)을 놓쳤다. 여기서는 인자를 «행위»에서 뽑는다.

### 대상
```
관계 R      스키마 Σ(컬럼 이름·타입)를 가진 행의 유한 집합.  행 r ∈ R 은 함수 Σ → 값
원자 A      (주어 신원 s, 술어 p, 목적 o, 시각 t, 출처 π, 상태 σ)   — §2.1 의 fact 그대로
번역 T      T : P(R) → P(A).  «선언»이 정하는 함수.  선언 = T 를 고르는 인자
```
### 두 전제 — 이 절이 덮는 T 의 «범위». 밖은 다른 기저(체인)의 것이다
```
국소성     원자 하나는 «분자 하나»(행 하나 또는 group_by 로 묶인 행들)에서만 나온다.  a ∈ T(R) ⇒ ∃! m ⊆ R, a = f(m)
무계산     원자의 값·수식어는 분자의 컬럼 값 «그대로»이거나 상수다.  변환·집계·조인은 없다
=> 상설 「표에 원천 데이터를 넣고 그걸로 원장」이 이 전제다: 값을 «만드는» 것은 체인이 «표에» 쓰고, 원장 선언은 «표기»만 옮긴다.
   그래서 값 변환 · 그룹 집계 · 선언 조인은 이 기저의 구멍이 «아니라» 체인 기저(§4 의 write · mapper_sdk)의 항목이다  — 그쪽 완전성은 별도로 잰다
   🔵 **[09-11 D-4] 잤습니다** — [`CHAIN_CONTRACT_COMPLETENESS.md`](./CHAIN_CONTRACT_COMPLETENESS.md): 축 일곱 × 칸, ③ «여섯» · ③′ «0».
      원장과 대칭이 반대다 — 원장은 「칸 먼저, 읽는 쪽 나중」이라 ③′ 가 생겼고, 체인은 「기제 먼저, 칸 없음」이라 ③ 이 전부 «칸 없음»이다.
      제일 큰 ③ 은 «규칙 하나의 모양을 검증하는 자리가 없다»는 것이고, 나머지 다섯이 거기서 나온다
```
🔴 **[09-09 17:59 판정 196] 두 전제는 «규칙»이지 «관측»이 아니다.** 응용 D-6-2 실측: 출하 샘플 15 소스 중 «셋»이 범용 구현을 벗어나 파이썬으로 계산한다(`dt-job-role` 그룹 개수 · `lot-event-role` 분자 안 짝짓기/두 목록 위치/처음 본 주어 · `lot-event-live-frame`). 그 셋은 전제의 «반증»이 아니라 규칙의 **부채**다(S-100: 그 계산을 체인 규칙이 «표에» 쓰고 원장은 declarative-role 로 읽는다). 소유자 「모든 걸 커버할 수 없으면 설계 규칙을 정하든가」 — 규칙은 CLAUDE.md 설계 규칙 상설. 예외 «하나»는 각주로 남긴다: `register` 문장은 「원장이 이미 아는가」를 묻는다(비국소) — 그것은 선언된 `registration_probe` 가 답하는 «칸 있는» 비국소성이라 규칙의 «명시된 예외»다.

### 구조 정리 — 국소적·무계산 번역은 «전부» 다음 꼴로 «유일하게» 분해된다
```
T(R) = ⋃_{s ∈ S}  emit_s ( { m ∈ unit(filter(read(R))) : select_s(m) } )

read    : 관계 → 행 집합          어느 관계 · 어느 컬럼 · 어느 순서/페이지(커서)
filter  : 행 → {0,1}             「이 행이 이 소스의 행인가」                          ← S-91
unit    : 행 집합 → 분자 집합      분할: 행 하나 | group_by 키
select_s: 분자 → {0,1}           「이 분자가 문장 s 를 말하나」                        ← S-99
emit_s  : 분자 → 원자 «집합»      문장 s 의 각 원자 필드를 분자에서 «투영»한다:
            s(m)  = 신원 = 키 컬럼들의 조립(상수 포함)            o(m) = entity_ref(키 조립) | value(컬럼) + 수식어(컬럼들)
            t(m)  = 컬럼 | 적재 순간(basis)                        π(m) = 행/그룹의 엔진 참조(자동)
            σ     = 단언 (철회는 행의 «삭제»가 문으로 낸다 — 행이 아니라 사건)
            다중  = 한 셀의 목록(list_separator) → 원자 n 개

### 2.4 읽기 규칙 — 원장(집합)을 «해석»하는 법. 이것이 걷기(B)의 «시각·짐» 축과 맞닿는다
```

집합     같은 (n, p) 의 사실 «전부» — 복수값 속성은 «이 규칙»이지 새 칸이 아니다(단수 규칙으로 읽으니 «충돌»로 보인다)
as-of    τ ≤ τ₀ 인 사실만 — 유효 구간 · 이력 · 전/후 비교가 «전부» 이 규칙
세대     Π 의 리비전이 «활성»인 사실만 — 번역 세대(S-57)는 «읽기 규칙 + declare⁻¹»이지 원자 칸이 아니다
충돌     최신 규칙으로 읽는데 τ 가 같은 사실이 둘 — «수»로 낸다(동률은 답)
```

🔴 **[09-09 22:01 판정 210 — 소유자 「사실이 아니라 바꾼 거라 B」]** 위 「유효 구간 = fact(…, τ₁) 과 fact(…, retract, τ₂) 둘」과 「철회는 다른 사실」은 «오늘 코드가 아니고, 앞으로도 아니다». 갈래가 둘이다:
```

파생 표기     재번역이 «갈아 끼우는» 원자(프레임 변경 → dt_transfer 재번역 · 제외 · 행 삭제) — 옛 원자는 «사실»이 아니라 «옛 번역의 산출»이라 DELETE 가 맞다(색인으로 겨눔, S-101). 그 이력은 원장이 아니라 «소스 표»(감사 로그 · 셀 소스)가 든다

## 3-0. 질문이라는 «행위»의 기저 — 제품 낱말 «없이» (09-09 08:19, 소유자 「질문이란 행위에 대한 근본적인 기저를 적어 봐」)
🔴 §3 은 이 절의 «구현»이다. 여기 없는 것을 §3 이 들고 있으면 §3 이 «배관»을 축으로 만든 것이고, 여기 있는 것을 §3 이 못 들면 «구멍»이다.

### 대상
```
세계 W      사물들과, 그들 사이에 성립하는 사실들
주어 S      질문이 «무엇에 대한» 것인가 — 이름으로 «지칭»하거나 조건으로 «기술»한 W 의 부분집합
빈칸 H      묻는 사람이 «모르는 것». 질문 = 구멍 하나 뚫린 명제. 답은 그 구멍을 채운다
            구멍의 종류가 질문의 종류다: 어느 것(정체) · 얼마(값) · 참인가(진위) · 몇(수) · 언제(시각) · 무엇이 다른가(차이) · 왜(원인 = 의존의 사슬)
연결 P      주어에서 빈칸까지의 «길». 모르는 것은 대개 주어의 직접 성질이 아니라 관계를 «거쳐» 닿는다(이력 · 부분 · 공정). 어느 관계를 «따라가도 되는가»가 질문의 «뜻»이다
맥락 C      언제 기준인가(시각) · 누구와 견주나(모집단) · 무엇 단위로 세나(입도)
답의 모양 F  집합 · 표 · 참/거짓 · 순위 — 빈칸 종류와 묶음이 정한다
```
### 생성자 «넷»
```
지칭  refer   : 이름 | 조건 → S
연결  relate  : S × P → S′               따라가 닿는 것들
빈칸  ask     : S′ × H × C → 답 + 근거     구멍을 채우고, «무엇이 그 답을 받치는지»를 같이 낸다
맥락  frame   : 질문 × C → 질문           같은 질문을 다른 시각 · 모집단 · 입도에서
```
### 합성 «다섯» — 질문은 혼자 오지 않는다
```
좁힘   S ∩ 답             「그중에서」
넓힘   답을 묶어 세기        「종류별로 몇」
옮김   답을 새 주어로        「그것의 …는」— 탐색이 «이어지는» 이유
견줌   같은 빈칸을 두 주어에   「A 와 B 가 무엇이 다른가」— 판단의 형태
되돌림  전 질문으로           「아까 그것」
```
### 성질 — 답이 «답»이려면
```
전제 검사   질문이 «가정하는 것»(주어가 있다 · 그 길이 있다)이 거짓이면 답이 아니라 «거절», 무엇이 거짓인지 이름을 댄다
근거 동반   답에는 «어느 사실이 그것을 받쳤나»가 붙는다. 근거 없는 답은 결정을 못 받친다
불완전 표시  예산에 잘렸으면 «잘렸다»고 말한다. 잘린 답과 «없음»은 다른 답이다
멱등       같은 주어 · 같은 길 · 같은 맥락이면 같은 답 — 그래야 다시 물을 수 있다
```
### 닫힘
```
「왜」   = 연결된 것 중 견줌에서 «다른» 것        (새 생성자 아님)
「추세」 = 맥락의 시각을 옮겨 가며 같은 빈칸       (frame 의 반복)
「이상」 = 모집단과의 견줌에서 벗어난 것          (견줌)
=> 넷 + 다섯으로 못 만드는 질문이 나오면 그것이 이 절의 구멍이다
```
### §3 과의 대응 (검증 자리 — 정의가 아님)
```
refer → 씨앗 해소 · 마킹      relate → walk(follow · hops · 방향)      ask(H, C) → collect · group · aggregate · 시각      frame → D_walk 의 시각 · 모집단
좁힘 → 마킹 ∩ 결과            넓힘 → group · aggregate                 옮김 → 결과를 새 마킹으로(마킹 체인)              견줌 → diff(마킹₁, 마킹₂)      되돌림 → 마킹 저장소의 이름
성질  전제 검사 → 422 이름 대어   근거 동반 → 엣지 · 원자 참조(«오늘 답에 안 실림» — ③ 후보)   불완전 표시 → 절단 플래그 ①   멱등 → 시각 축 없어 «말해지지 않음»(B7 ③)
```
🔴 이 대응이 새로 드러낸 구멍 «하나»: **근거 동반** — 답(하위 그래프)이 «어느 사실(원자)이 그 엣지를 받쳤나»를 싣지 않는다. 대조의 순위가 «왜 그 순위인가»를 못 말한다. S-75 표 B 에 행 하나로.

## 3. 기저 B — 질의의 대수 (같은 날 재작성)
🔴 첫 판(축 열 목록)은 «오늘 라우트의 인자 재고»였다. 표 B 는 이 절의 검증이다.

### 3.1 대상
```
M   마킹     노드 집합 × 부호, 이름 붙음
G   하위 그래프  (노드 · 엣지 · 절단 표시)  — walk 의 값
S   표       (그룹 × 측정 × 집계 · n · 절단 여부) — 계산의 값
```
### 3.2 생성자 — 넷 + 마킹 대수
```
walk      : M × D_walk → G          «순수». D_walk = 길(follow · direction · hops · 인접 반전) × 짐(collect = 노드 타입) × 시각(as-of · 세대 = §2.4 읽기 규칙) × 예산(상한 · 절단 표시)
group     : G × key → S             key = 길 위의 노드 타입 또는 속성
aggregate : S × measure → S         measure = 수 · 비율 · 평균 · 분포 · «수식»(사용자가 적는 것 — 정의역이 «수식»을 받나가 §4.8 ②)
diff      : S × S → S               대조. 동률은 답
M 대수    ∪ · ∩ · ∖ · ¬(부호 반전)   대조군 = 전체 ∖ 사례 · 후보 = 마킹 ∩ 걷기 결과   (§4.8 ① — 오늘 «없음», C-46 실측)
```
### 3.3 합성
```
기본형   resolve ; walk ; group ; aggregate               (한 마킹의 그림)
대조     (walk(M₁) ∥ walk(M₂)) ; group ; aggregate ; diff   (두 모집단의 «차이»)
순위     diff 의 «정렬» — 생성자 아님(표현)
```
### 3.4 읽기 규칙과의 접점 · 항등
```
walk 의 시각 축 = §2.4 의 as-of · 세대     둘은 «같은 규칙»이다. 걷기에 시각이 없으면 원장의 이력이 «질문될 수 없다»
walk 는 멱등(같은 M · D_walk · 시각)      시각 없이는 «말해지지 않는다»
group · aggregate · diff 는 «순수»        서버든 클라든 «같은 답» — 다만 절단된 G 위의 S 는 «기울어진 답»이고 오류를 안 낸다 → 10^8 에선 서버여야 한다(자리의 문제, 생성자의 문제 아님)
```
### 3.5 표 B 의 ③ 을 기저에 대응시키면
```
생성자 정의역 구멍   시각(as-of · 세대)이 D_walk 에 없음                       -> «진짜 구멍» (§2.4 와 한 몸)
                   measure 가 «수식»을 받나                                  -> 정의역 검사(§4.8 ②)
생성자 «없음»        M 대수 (∪ ∩ ∖ ¬)                                        -> 지을지 판정(대조 서버화와 한 자리)
자리의 문제          group · aggregate · diff 가 클라에서 돈다                  -> 생성자는 «있다». 옮기는 일(예산 절단 때문에)
```
📎 제약(상설)은 그대로: 「마킹은 질의의 주어」 · 「사용자가 고르는 축은 노드 타입 하나, 술어는 follow 로만」 · 「부품은 거르지 않는다」 · 「라우트는 하나」 · 「배관 낱말은 축이 될 수 없다」.

## 4. 기저 C — 행동 (대수) — 2026-09-08 22:45 재작성 (소유자 「행동 집합이 아니라 제품 기능을 열거해 놓은 거 아니야?」→ 맞음)
🔴 기저는 «기능 목록»이 아니다. 기저 = 대상(타입) · 타입 있는 생성자 · 합성 규칙 · 항등/역 · 닫힘 · 최소성. 기능은 그 «인스턴스»이고 4.7 로 밀려난다.

### 4.1 대상(타입)
```

### 4.2 생성자 — «넷» (트리거는 생성자가 아니다 → 4.3)
