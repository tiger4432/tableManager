## 0. 제품의 쓰임 — 모든 기저의 «주어»
```
문제가 난다(결함 · 수율 이탈)
 → 운영자가 대상을 «마킹»한다
 → 걸어서 닿는 하위 그래프(자재 · 공정 · 레시피 · 장비 · 검사)를 가져온다
 → «대조군»과 견줘 「무엇이 다른가」를 «순위»로 받는다
 → 필요하면 «행동»한다(홀드 · 이송 · 계획 · 확정)
그리고 이 전부가 «선언»으로 된다 — 임의 스키마에서 «두 줄»로 (완성의 정의, 2026-08-30)
```
지식 탐색과 운영은 «같은 기저»를 쓴다(소유자 문답 09-08 22:3x). 운영에서 느는 것은 «선언»이지 생성자가 아니다.

## 1. 완전성의 정의 (소유자, 2026-09-08 밤)
```
완전한 집합   축을 «먼저» 열거한다. 축마다 칸의 상태는 셋 중 하나:
              ① 선언 칸 있음(이름 · 자리)   ② 기본값이 덮음(«무엇으로» 덮이는지 값을 적는다)   ③ 없음 = 결함(동결 전 채운다)
닫힘          새 경우는 «기존 칸에 대응»돼야 한다. 대응이 안 되면 축이 빠진 것이지 칸 하나를 «더하는» 것이 아니다
온전히 덮음    기능이 필요한 «정보»를 담는다 — 칸의 «값의 정의역»까지(「수식어에 숫자만」 같은 제약이 없게).
              정의역은 «일곱 층 어디에나» 숨는다: 문법(setup_bundle) · 발행(emit) · 걷기 · 폼 · 값 채움 · DB CHECK · 클라 투영 → 칸마다 일곱 층 «다» 본다
봉투          «출처» 축은 새로 정의하지 않는다 — 아웃박스 봉투 다섯 칸이 «완전한 덮개»다. 새는 곳은 «봉투 없는 쓰기 길»과 «원장이 안 읽는 봉투 사건» 둘뿐
동결 관문     S-75 표 셋의 ③ 이 0
```

## 3. 기저 B — 질의(걷기 스킴)
제약(상설): 「마킹은 질의의 주어」 · 「사용자가 고르는 축은 노드 타입 «하나», 술어는 follow 로만」 · 「부품은 거르지 않는다 — 거르는 것은 walk」 · 「라우트는 하나(`GET /api/ledger/subgraph`)」 · 「배관 낱말은 축이 될 수 없다」. 정본 소비자: `docs/architecture/WALK.md` · `task/CHART_DESIGN.md` §2-bis·§2-ter.

| 축 | 인자(칸 후보) | 오늘 |
|---|---|---|
| **B1 시작** | 마킹 = «이름 붙은» 노드 집합 × 부호, «여럿»(마킹1 · 마킹2 …) · 씨앗 해소(키 → 노드) · 정적 노드는 씨앗 아님(판정 08-29) | ① |

| **B3 짐** | `collect` = 노드 타입(도메인 낱말) | ③ — 09-06 축째 지워짐. 닿는 것 «전부»를 싣는다 |
| **B4 그룹** | `group_by` = 길 위의 노드 타입 또는 속성(레시피 · 장비 · 스텝) | ③ — 클라가 한다 |
| **B5 집계** | `measure`(값 · 수식어 · 개수) · `aggregate`(수 · 비율 · 평균 · 분포) · `n` | ③ — 클라 |

| **B10 거절** | 어떤 조합이 422 인가 — «이름 대어» | 부분 |

🔴 A2 의 카디널리티 ③ 은 B5 집계의 «중복 셈»을 구조적으로 못 막는다 — 표 둘은 «따로»가 아니다.

## 4. 기저 C — 행동 (대수) — 2026-09-08 22:45 재작성 (소유자 「행동 집합이 아니라 제품 기능을 열거해 놓은 거 아니야?」→ 맞음)
🔴 기저는 «기능 목록»이 아니다. 기저 = 대상(타입) · 타입 있는 생성자 · 합성 규칙 · 항등/역 · 닫힘 · 최소성. 기능은 그 «인스턴스»이고 4.7 로 밀려난다.

### 4.1 대상(타입)
```
K   키          문자열 · 셀 좌표 — 그래프 «밖»의 이름
M   마킹        노드 집합 × 부호, 이름 붙음 — 걷기의 주어
G   하위 그래프  (노드 · 엣지 · 집계 표 · 절단 표시) — 걷기의 값
R   행 집합     표 × 행 (셀 층 · 바깥 싱크 포함)
E   사건        봉투 다섯 칸 + 동사(C/E/D · 시스템 · 외부 응답) + R
D   선언        리비전 — 스키마 · 소스 · 템플릿 · 규칙 · 전이 표 · 가드 · 역할.  D_walk = 표 B 의 인자,  D_write = 표 스키마 · 전이 · 가드 · 싱크
A   원자 집합   원장
```

### 4.2 생성자 — «넷» (트리거는 생성자가 아니다 → 4.3)
```
해소   resolve   : K → M                        이름을 노드로. 그래프 밖에서 안으로 들어오는 «유일한» 문
걷기   walk      : M × D_walk → G                «순수»(부작용 0)
쓰기   write     : (G | 입력) × D_write → E       «부작용». 반드시 E(봉투)를 낸다 — 봉투 없는 쓰기는 이 대수 «밖»이다(D1 · S-74)
선언   declare   : D × ΔD → D'  (+ E: SYSTEM_RELOAD)  «인자 공간 자체»를 바꾼다 — 2차 연산. 이것이 메타 액션의 정의
파생   translate : E × D → A                     생성자가 «아니다» — write 에 따라 나오는 함자. 원장은 이 함자의 «상(image)»
```

### 4.3 합성 규칙 — 다섯
```
순차      f ; g                       타입이 맞으면 잇는다.  행동의 «기본형» = resolve ; walk ; write
조건(가드) walk ⊳ write                걷기 결과의 술어가 참일 때만 쓴다. 거짓이면 «이름 대어» 거절 — 조용히 안 쓰는 일은 없다
사건 연쇄  write ↦ E ↦ (walk ; write)  E 가 다음 합성을 «부른다». 🔴 이것이 «트리거»다 — 생성자가 아니라 규칙.
                                      체인 · enrichment · 알림 · 실시간 전파 · 승인 흐름은 전부 이 규칙의 인스턴스
병렬      walk(M₁) ∥ walk(M₂)          마킹 여럿을 같은 D_walk 로 — 대조(B6)의 재료
시각      tick 은 시스템 사건의 한 종류    일정 실행은 사건 연쇄의 인스턴스이지 별도 규칙이 아니다
```

### 4.4 항등 · 역
```
walk 는 멱등    같은 M · 같은 D · 같은 시각(B7) → 같은 G.  캐시와 재시도가 «안전»한 이유. 시각 축이 없으면(오늘) «같은 시각»을 못 적는다 → 멱등이 «말해지지 않는다»
write⁻¹ 존재    봉투 tx_id 로. 되돌리기는 기능이 아니라 «역원». 봉투 없는 쓰기(S-74 부류)는 역이 «없다» — 그것이 그 부류가 위험한 이유
declare⁻¹       세대 되돌림 — S-57 이 주는 것. 오늘은 없다
```

### 4.5 닫힘 — 왜 «생성»인가
```
행동 = (resolve ; walk ; write) 의 «인스턴스» = D 의 한 «점».   기능이 는다 = D 의 점이 는다.   생성자가 늘어야 한다 = 축이 «빠졌던» 것
체인       write ↦ E ↦ walk ; write                    별도 «규칙 언어»가 필요 없다(4.3 사건 연쇄) — 오늘 enrichment 규칙은 «이 꼴로 다시 적혀야» 한다
DOE        resolve ; write(D_template)                 걷기 0 홉
대조       (walk(M₁) ∥ walk(M₂)) ; diff                diff 는 G 위의 순수 함수(B6)
메타       declare ; translate 재실행                  «변경 비용 미리보기» = declare «앞»에 두는 walk(A5 · D4)
랏 홀드    resolve ; walk ⊳ write(D_transition)        가드 = 현재 상태 · 진행 중 이송
되돌리기   write⁻¹(tx)
알림       walk ⊳ write(D_sink)
```

### 4.6 최소성 · 완전성 판별식
```
최소성   넷 중 어느 것도 나머지로 안 만들어진다 —
         resolve 만 그래프 «밖»에서 들어온다 · walk 만 «읽기»다 · write 만 «부작용»이다 · declare 만 «인자 공간»을 바꾼다
완전성   (a) D_walk · D_write 의 «정의역»이 도메인이 필요한 점을 다 덮나 — 표 A · B 가 «그 검사»다
         (b) 4.3 다섯 밖의 «잇는 법»이 제품에 있나 — 있으면 규칙이 빠진 것
         (c) 오늘의 모든 라우트 · 손짓이 4.5 «꼴로 적히나» — 안 적히면 다섯째 생성자거나 결함
         (d) 봉투 없는 write 가 0 인가 (D1)
=> 「행동을 덮는다」= 기능 목록의 완비가 «아니라» ⟨D 의 정의역 완비 ∧ 합성 규칙 완비 ∧ 생성자 넷의 충분성⟩
```
🔴 그래서 S-75 표 ③(행동)의 «열»은 「이 행동이 어느 기능인가」가 아니라 「이 행동이 4.5 꼴로 «어떻게 적히나» · 봉투가 있나 · 안 적히면 «무엇이» 빠졌나(생성자/규칙/정의역)」다.

### 4.7 인스턴스 (검증용 — 기저가 «아니다». 위 표기로 적는다)
