## 2. 기저 A — 표기의 대수 (2026-09-09 05:57 재작성 — 소유자 「표 A·B 는 기능 리스트지 기저가 아니다」→ 맞음)
🔴 이 절의 첫 판(축 여덟 목록)은 «지금 문법의 칸 재고»였다. 재고로는 완전성이 «증명되지 않는다» — 기저에서 «유도»될 때만 닫힘이 나온다. 그래서 §4 와 같은 모양으로 다시 쓴다. 표 A(`LEDGER_SCHEMA_COMPLETENESS.md`)는 이 절의 «grep 검증»이지 정의가 아니다.

### 2.1 대상(타입)
```
T   노드 타입      선언된 이름 + 키 이름들
N   노드          T × K (키 값들) — 「술어가 아닌 것은 표면적으로 노드」(상설)
P   술어          이름 + 주어 타입들 + 목적어 종류
V   값            «타입 있는» 스칼라 (수 · 문자열 · 불 · 시각 · …)
Q   수식어        이름 → V 의 사전
τ   시각          순간 (occurred_at)
Π   출처          봉투 다섯 칸 + 번역기 리비전(sha) + 원천 행 참조
α   원자          «하나의 사실»
L   원장          원자의 집합 — append-only. 원장에는 «사실»만 있다
```

### 2.2 생성자 — «둘»
```
node : T × K → N                                            노드를 «부른다» (만들지 않는다 — 노드는 사실 속에서만 존재한다)
fact : N × P × (∅ | V | N) × Q × τ × Π → α                   원장의 «유일한» 내용 생성자
```
🔴 원장이 말할 수 있는 «모든» 것은 fact 의 상(image)이다. 존재 · 속성 · 은퇴 · 관계 · 측정이 «전부» fact 다:
```
존재      fact(n, register, ∅, Q, τ, π)                       Q = 그 시각의 속성 값들
속성 변경  같은 모양의 fact 하나 더                              «새 등록 원자»
은퇴      fact(n, retire, ∅, …)                                🔵 새 «칸»이 아니라 «술어» 하나 — 선언 한 줄
관계      fact(n₁, p, n₂, Q, τ, π)                              Q = 엣지 수식어
측정      fact(n, p, v, Q, τ, π)                                 v 의 «타입»이 V 의 정의역
유효 구간  fact(…, τ₁) 과 fact(…, retract, τ₂) «둘»              🔵 칸이 아니라 «두 사실 + 읽기 규칙(as-of)»
```

### 2.3 선언 = 생성자의 «인자 공간» D_A (문법이 «유도되는» 자리)
```
D_T   타입 선언      keys · attributes(이름 · «읽기 규칙» 단수/집합) · class · status
D_P   술어 선언      subjects · object.kind(∅|V|N) · V 의 «타입» · qualifiers(이름 · 타입) · «제약»(카디널리티 · 필수) · status
D_Π   출처 선언      소스 = 표/뷰 → fact 로 가는 «번역»(read · prepare · map · bind) · decision_key(판단 단위) · status
D_L   원장 선언      리비전(세대) · 파티션 · 지문
규칙  «모든 선언 항목은 status 를 가진다»(수명) — 술어에 있고 타입·소스에 없는 것은 «패턴 위반»이지 새 축이 아니다
```

### 2.4 읽기 규칙 — 원장(집합)을 «해석»하는 법. 이것이 걷기(B)의 «시각·짐» 축과 맞닿는다
```
최신     같은 (n, p) 의 사실 중 τ 최댓값 — 「지금 무엇인가」
집합     같은 (n, p) 의 사실 «전부» — 복수값 속성은 «이 규칙»이지 새 칸이 아니다(단수 규칙으로 읽으니 «충돌»로 보인다)
as-of    τ ≤ τ₀ 인 사실만 — 유효 구간 · 이력 · 전/후 비교가 «전부» 이 규칙
세대     Π 의 리비전이 «활성»인 사실만 — 번역 세대(S-57)는 «읽기 규칙 + declare⁻¹»이지 원자 칸이 아니다
충돌     최신 규칙으로 읽는데 τ 가 같은 사실이 둘 — «수»로 낸다(동률은 답)
```

### 2.5 역 · 닫힘 · 최소성
```
역        fact⁻¹ 은 «없다» — 원장은 append-only. 물림(withdraw)은 «다른 사실»이거나 Π 로 «겨눈 표시»다. 되돌리기는 C 의 write⁻¹(봉투)에서 온다
닫힘      선언 한 줄(D_T · D_P · D_Π)이 «새 사실 모양»을 만든다. 코드에 도메인 낱말이 «없어야» 하는 이유 — 낱말은 D 에만 산다
최소성    node 는 «부르기»(그래프 안 이름), fact 는 «내용». 둘 중 하나를 다른 하나로 못 만든다. 셋째는 필요 없다(속성·존재·관계가 전부 fact)
```

### 2.6 표 A 의 «열셋»을 기저에 «대응»시키면 — 성격이 갈린다 (응용이 표 A 를 이 열로 다시 적는다)
```
생성자 정의역 «구멍»   ① V 의 타입(값 목적어가 «수만»)                                   -> 문법 수리(D_P 에 값 타입)  «진짜 기저 구멍»
선언 «제약» 부재       ② 카디널리티(D_P 제약)                                             -> 문법 수리
선언 «수명» 패턴 위반   ③ 타입 status  ④ 소스 status                                        -> 문법 수리 «하나의 패턴»(술어 status 를 «일반화»)
선언 «판단 단위»       ⑤ decision_key(D_Π)                                                -> 문법 수리(판정 151·165)
읽기 규칙 (B 쪽)       ⑥ 복수값 속성 = «집합» 읽기  ⑦ 유효 구간 = «as-of» 읽기 + 사실 둘  ⑧ 세대 = «활성 세대» 읽기 + declare⁻¹   -> 원자 칸 «아님». 걷기 D_walk 의 시각·짐 축(B7·B3)과 declare⁻¹
사실로 «환원»          ⑨ 노드(인스턴스) 은퇴 = retire 술어 한 줄                            -> 선언 «한 줄», 문법 무변  ⚠️ 표 A 의 「엔티티 은퇴」는 ③ 타입 status 와 ⑨ 를 «섞었다»
                        🔴 오늘은 «거짓»(응용 D-0 ㉠): DB CHECK `ck_ledger_register_has_no_object` 가 'register' «리터럴»로 목적어 없는 술어를 하나로 못 박아 retire 를 «거절»한다 — 저장 층의 하드코딩. S-77(판정 169) 뒤에 참이 된다
사건·봉투 (C 쪽)       ⑩ 봉투 없는 쓰기  ⑪ 외부 응답 동사                                   -> C 의 write/E (D1 · A7)
도구                  ⑫ 변경 비용 미리보기                                                 -> declare «앞»의 walk (C §4.5 메타)
③′ 은퇴               ⑬ key_types · supersedes                                          -> 자유도 0 인 칸 삭제(판정 165)
=> 문법을 «고칠» 것은 ①②③④⑤ «다섯»(③④는 패턴 하나). 나머지는 읽기 규칙 셋 · 술어 하나 · 사건 둘 · 도구 하나 · 삭제 둘
```
🔴 동결 관문의 «바른 술어»: 「③ 이 0」이 아니라 **「문법의 모든 칸이 어느 생성자의 인자로 유도되고, 모든 생성자의 인자가 칸을 갖는다」**. 유도 안 되는 칸 = 하드코딩(③′) · 인자 없는 자리 = 구멍(①~⑤).

## 3-0. 질문이라는 «행위»의 기저 — 제품 낱말 «없이» (09-09 08:19, 소유자 「질문이란 행위에 대한 근본적인 기저를 적어 봐」)
🔴 §3 은 이 절의 «구현»이다. 여기 없는 것을 §3 이 들고 있으면 §3 이 «배관»을 축으로 만든 것이고, 여기 있는 것을 §3 이 못 들면 «구멍»이다.

### 대상
```
세계 W      사물들과, 그들 사이에 성립하는 사실들
주어 S      질문이 «무엇에 대한» 것인가 — 이름으로 «지칭»하거나 조건으로 «기술»한 W 의 부분집합
빈칸 H      묻는 사람이 «모르는 것». 질문 = 구멍 하나 뚫린 명제. 답은 그 구멍을 채운다
            구멍의 종류가 질문의 종류다: 어느 것(정체) · 얼마(값) · 참인가(진위) · 몇(수) · 언제(시각) · 무엇이 다른가(차이) · 왜(원인 = 의존의 사슬)
연결 P      주어에서 빈칸까지의 «길». 모르는 것은 대개 주어의 직접 성질이 아니라 관계를 «거쳐» 닿는다(이력 · 부분 · 공정). 어느 관계를 «따라가도 되는가»가 질문의 «뜻»이다
맥락 C      언제 기준인가(시각) · 누구와 견주나(모집단) · 무엇 단위로 세나(입도)
답의 모양 F  집합 · 표 · 참/거짓 · 순위 — 빈칸 종류와 묶음이 정한다
```
### 생성자 «넷»
```
지칭  refer   : 이름 | 조건 → S
연결  relate  : S × P → S′               따라가 닿는 것들
빈칸  ask     : S′ × H × C → 답 + 근거     구멍을 채우고, «무엇이 그 답을 받치는지»를 같이 낸다
맥락  frame   : 질문 × C → 질문           같은 질문을 다른 시각 · 모집단 · 입도에서
```
### 합성 «다섯» — 질문은 혼자 오지 않는다
```
좁힘   S ∩ 답             「그중에서」
넓힘   답을 묶어 세기        「종류별로 몇」
옮김   답을 새 주어로        「그것의 …는」— 탐색이 «이어지는» 이유
견줌   같은 빈칸을 두 주어에   「A 와 B 가 무엇이 다른가」— 판단의 형태
되돌림  전 질문으로           「아까 그것」
```
### 성질 — 답이 «답»이려면
```
전제 검사   질문이 «가정하는 것»(주어가 있다 · 그 길이 있다)이 거짓이면 답이 아니라 «거절», 무엇이 거짓인지 이름을 댄다
근거 동반   답에는 «어느 사실이 그것을 받쳤나»가 붙는다. 근거 없는 답은 결정을 못 받친다
불완전 표시  예산에 잘렸으면 «잘렸다»고 말한다. 잘린 답과 «없음»은 다른 답이다
멱등       같은 주어 · 같은 길 · 같은 맥락이면 같은 답 — 그래야 다시 물을 수 있다
```
### 닫힘
```
「왜」   = 연결된 것 중 견줌에서 «다른» 것        (새 생성자 아님)
「추세」 = 맥락의 시각을 옮겨 가며 같은 빈칸       (frame 의 반복)
「이상」 = 모집단과의 견줌에서 벗어난 것          (견줌)
=> 넷 + 다섯으로 못 만드는 질문이 나오면 그것이 이 절의 구멍이다
```
### §3 과의 대응 (검증 자리 — 정의가 아님)
```
refer → 씨앗 해소 · 마킹      relate → walk(follow · hops · 방향)      ask(H, C) → collect · group · aggregate · 시각      frame → D_walk 의 시각 · 모집단
좁힘 → 마킹 ∩ 결과            넓힘 → group · aggregate                 옮김 → 결과를 새 마킹으로(마킹 체인)              견줌 → diff(마킹₁, 마킹₂)      되돌림 → 마킹 저장소의 이름
성질  전제 검사 → 422 이름 대어   근거 동반 → 엣지 · 원자 참조(«오늘 답에 안 실림» — ③ 후보)   불완전 표시 → 절단 플래그 ①   멱등 → 시각 축 없어 «말해지지 않음»(B7 ③)
```
🔴 이 대응이 새로 드러낸 구멍 «하나»: **근거 동반** — 답(하위 그래프)이 «어느 사실(원자)이 그 엣지를 받쳤나»를 싣지 않는다. 대조의 순위가 «왜 그 순위인가»를 못 말한다. S-75 표 B 에 행 하나로.

## 3. 기저 B — 질의의 대수 (같은 날 재작성)
🔴 첫 판(축 열 목록)은 «오늘 라우트의 인자 재고»였다. 표 B 는 이 절의 검증이다.

### 3.1 대상
```
M   마킹     노드 집합 × 부호, 이름 붙음
G   하위 그래프  (노드 · 엣지 · 절단 표시)  — walk 의 값
S   표       (그룹 × 측정 × 집계 · n · 절단 여부) — 계산의 값
```
### 3.2 생성자 — 넷 + 마킹 대수
```
walk      : M × D_walk → G          «순수». D_walk = 길(follow · direction · hops · 인접 반전) × 짐(collect = 노드 타입) × 시각(as-of · 세대 = §2.4 읽기 규칙) × 예산(상한 · 절단 표시)
group     : G × key → S             key = 길 위의 노드 타입 또는 속성
aggregate : S × measure → S         measure = 수 · 비율 · 평균 · 분포 · «수식»(사용자가 적는 것 — 정의역이 «수식»을 받나가 §4.8 ②)
diff      : S × S → S               대조. 동률은 답
M 대수    ∪ · ∩ · ∖ · ¬(부호 반전)   대조군 = 전체 ∖ 사례 · 후보 = 마킹 ∩ 걷기 결과   (§4.8 ① — 오늘 «없음», C-46 실측)
```
### 3.3 합성
```
기본형   resolve ; walk ; group ; aggregate               (한 마킹의 그림)
대조     (walk(M₁) ∥ walk(M₂)) ; group ; aggregate ; diff   (두 모집단의 «차이»)
순위     diff 의 «정렬» — 생성자 아님(표현)
```
### 3.4 읽기 규칙과의 접점 · 항등
```
walk 의 시각 축 = §2.4 의 as-of · 세대     둘은 «같은 규칙»이다. 걷기에 시각이 없으면 원장의 이력이 «질문될 수 없다»
walk 는 멱등(같은 M · D_walk · 시각)      시각 없이는 «말해지지 않는다»
group · aggregate · diff 는 «순수»        서버든 클라든 «같은 답» — 다만 절단된 G 위의 S 는 «기울어진 답»이고 오류를 안 낸다 → 10^8 에선 서버여야 한다(자리의 문제, 생성자의 문제 아님)
```
### 3.5 표 B 의 ③ 을 기저에 대응시키면
```
생성자 정의역 구멍   시각(as-of · 세대)이 D_walk 에 없음                       -> «진짜 구멍» (§2.4 와 한 몸)
                   measure 가 «수식»을 받나                                  -> 정의역 검사(§4.8 ②)
생성자 «없음»        M 대수 (∪ ∩ ∖ ¬)                                        -> 지을지 판정(대조 서버화와 한 자리)
자리의 문제          group · aggregate · diff 가 클라에서 돈다                  -> 생성자는 «있다». 옮기는 일(예산 절단 때문에)
```
📎 제약(상설)은 그대로: 「마킹은 질의의 주어」 · 「사용자가 고르는 축은 노드 타입 하나, 술어는 follow 로만」 · 「부품은 거르지 않는다」 · 「라우트는 하나」 · 「배관 낱말은 축이 될 수 없다」.

## 4. 기저 C — 행동 (대수) — 2026-09-08 22:45 재작성 (소유자 「행동 집합이 아니라 제품 기능을 열거해 놓은 거 아니야?」→ 맞음)
🔴 기저는 «기능 목록»이 아니다. 기저 = 대상(타입) · 타입 있는 생성자 · 합성 규칙 · 항등/역 · 닫힘 · 최소성. 기능은 그 «인스턴스»이고 4.7 로 밀려난다.

### 4.1 대상(타입)
```
K   키          문자열 · 셀 좌표 — 그래프 «밖»의 이름
M   마킹        노드 집합 × 부호, 이름 붙음 — 걷기의 주어
G   하위 그래프  (노드 · 엣지 · 집계 표 · 절단 표시) — 걷기의 값
R   행 집합     표 × 행 (셀 층 · 바깥 싱크 포함)
E   사건        봉투 다섯 칸 + 동사(C/E/D · 시스템 · 외부 응답) + R
D   선언        리비전 — 스키마 · 소스 · 템플릿 · 규칙 · 전이 표 · 가드 · 역할.  D_walk = 표 B 의 인자,  D_write = 표 스키마 · 전이 · 가드 · 싱크
A   원자 집합   원장
```

### 4.2 생성자 — «넷» (트리거는 생성자가 아니다 → 4.3)
```
해소   resolve   : K → M                        이름을 노드로. 그래프 밖에서 안으로 들어오는 «유일한» 문
걷기   walk      : M × D_walk → G                «순수»(부작용 0)
쓰기   write     : (G | 입력) × D_write → E       «부작용». 반드시 E(봉투)를 낸다 — 봉투 없는 쓰기는 이 대수 «밖»이다(D1 · S-74)
선언   declare   : D × ΔD → D'  (+ E: SYSTEM_RELOAD)  «인자 공간 자체»를 바꾼다 — 2차 연산. 이것이 메타 액션의 정의
파생   translate : E × D → A                     생성자가 «아니다» — write 에 따라 나오는 함자. 원장은 이 함자의 «상(image)»
```

### 4.2-bis 생성자 «다섯째»와 생성자의 «성질» 셋 (09-09 06:01, 판정 168 — 표 C 의 검증이 연 것)
```
읽기   read : K × D_read → R        «표 행»을 읽는다. R 은 «사건의 접힘» — read(k) = fold(E)(k). D_read 는 «표 카탈로그»(이미 있는 선언), 지어내지 않는다
       왜 다섯째인가: R 은 G 가 아니다(그래프 ≠ 행). walk 로 못 만들고(원장에 없는 것을 읽는다), resolve 로도 못 만든다(K → M). 117 라우트 중 15 — «교정 표면»(핵심가치 ①) — 가 이것이다
성질   모든 생성자 f 에 «균일하게» 붙는 연산자 셋:
       dry(f)          효과 없이 결과만    — 미리보기.  dry(write) 는 있고(라우트 10 + apply=False) dry(declare) 가 «변경 비용 미리보기»(A5-2) 다: «짓기»가 아니라 «붙이기»
       f ⊳ expected(s) 기대 상태일 때만    — 조건부.   declare 에 있고(expected_revision) write 에 «없다»(C-2): 동시 사용자 10 에서 마지막 쓰기 승. 가드(walk ⊳ write)의 «원자성»이 이것
       f⁻¹             봉투로 되돌림       — 역.       write⁻¹ 은 봉투가 있어 «가능», 주어가 화면에 없다(C-6)
🔴 성질이 «한 생성자에만» 지어져 있으면 그것이 결함이다 — 판정 165 의 status 패턴과 같은 부류(「같은 성질은 같은 기제로」). 변경 비용(D8)을 «줄이는» 쪽이다: 기제 하나가 둘을 섬긴다
```

### 4.3 합성 규칙 — 다섯
```
순차      f ; g                       타입이 맞으면 잇는다.  행동의 «기본형» = resolve ; walk ; write
조건(가드) walk ⊳ write                걷기 결과의 술어가 참일 때만 쓴다. 거짓이면 «이름 대어» 거절 — 조용히 안 쓰는 일은 없다
사건 연쇄  write ↦ E ↦ (walk ; write)  E 가 다음 합성을 «부른다». 🔴 이것이 «트리거»다 — 생성자가 아니라 규칙.
                                      체인 · enrichment · 알림 · 실시간 전파 · 승인 흐름은 전부 이 규칙의 인스턴스
병렬      walk(M₁) ∥ walk(M₂)          마킹 여럿을 같은 D_walk 로 — 대조(B6)의 재료
시각      tick 은 시스템 사건의 한 종류    일정 실행은 사건 연쇄의 인스턴스이지 별도 규칙이 아니다
```

### 4.4 항등 · 역
```
walk 는 멱등    같은 M · 같은 D · 같은 시각(B7) → 같은 G.  캐시와 재시도가 «안전»한 이유. 시각 축이 없으면(오늘) «같은 시각»을 못 적는다 → 멱등이 «말해지지 않는다»
write⁻¹ 존재    봉투 tx_id 로. 되돌리기는 기능이 아니라 «역원». 봉투 없는 쓰기(S-74 부류)는 역이 «없다» — 그것이 그 부류가 위험한 이유
declare⁻¹       세대 되돌림 — S-57 이 주는 것. 오늘은 없다
```

### 4.5 닫힘 — 왜 «생성»인가
```
행동 = (resolve ; walk ; write) 의 «인스턴스» = D 의 한 «점».   기능이 는다 = D 의 점이 는다.   생성자가 늘어야 한다 = 축이 «빠졌던» 것
체인       write ↦ E ↦ walk ; write                    별도 «규칙 언어»가 필요 없다(4.3 사건 연쇄) — 오늘 enrichment 규칙은 «이 꼴로 다시 적혀야» 한다
DOE        resolve ; write(D_template)                 걷기 0 홉
대조       (walk(M₁) ∥ walk(M₂)) ; diff                diff 는 G 위의 순수 함수(B6)
메타       declare ; translate 재실행                  «변경 비용 미리보기» = declare «앞»에 두는 walk(A5 · D4)
랏 홀드    resolve ; walk ⊳ write(D_transition)        가드 = 현재 상태 · 진행 중 이송
되돌리기   write⁻¹(tx)
알림       walk ⊳ write(D_sink)
```

### 4.6 최소성 · 완전성 판별식
```
최소성   다섯 중 어느 것도 나머지로 안 만들어진다 — read 만 «원장 밖»(표 행)을 읽는다 ·
         resolve 만 그래프 «밖»에서 들어온다 · walk 만 «읽기»다 · write 만 «부작용»이다 · declare 만 «인자 공간»을 바꾼다
완전성   (a) D_walk · D_write 의 «정의역»이 도메인이 필요한 점을 다 덮나 — 표 A · B 가 «그 검사»다
         (b) 4.3 다섯 밖의 «잇는 법»이 제품에 있나 — 있으면 규칙이 빠진 것
         (c) 오늘의 모든 라우트 · 손짓이 4.5 «꼴로 적히나» — 안 적히면 다섯째 생성자거나 결함
         (d) 봉투 없는 write 가 0 인가 (D1)
=> 「행동을 덮는다」= 기능 목록의 완비가 «아니라» ⟨D 의 정의역 완비 ∧ 합성 규칙 완비 ∧ 생성자 넷의 충분성⟩
```
🔴 그래서 S-75 표 ③(행동)의 «열»은 「이 행동이 어느 기능인가」가 아니라 「이 행동이 4.5 꼴로 «어떻게 적히나» · 봉투가 있나 · 안 적히면 «무엇이» 빠졌나(생성자/규칙/정의역)」다.
