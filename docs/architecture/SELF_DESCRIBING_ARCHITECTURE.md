# 자기 서술 구조 — 판정과 근거 (2026-11-10)

> 이 문서는 «무엇을 왜 그렇게 정했나»의 기록이다. 결정마다 소유자의 문장(그대로)과 근거를 같이 둔다.
> 상태 낱말: **정함**(소유자 판정) · **총괄 정함**(소유자 문장에서 총괄이 내린 것) · **안**(컨펌 전) · **열림**(답 기다림).
> 설계의 세부(칸 · 문장 · 단계)는 `docs/design/CELL_SOURCE_OVERHAUL.md` 와 `docs/architecture/CHAIN_CLOSURE.md` 가 정본이다.

## 0. 한 문장

제품을 움직이는 모든 것(데이터 · 선언 · 실행 상태)이 **표의 행**이고, 그 표들은 원장 선언으로 **온톨로지 노드 · 엣지**가 되며,
AI 는 그 온톨로지를 **걸어서 이해하고 선언 행을 써서 제어**한다. 사람과 AI 가 같은 문으로 쓰고, 같은 이력이 남는다.

```
원천(파일 · 사람 · 외부)
  → 표(행)                     쓰는 쪽 — 쓰기 입구 하나
  → 체인(행 변경 → 맵퍼 → 표)   계산 · 조인 · 파생 · 판정 · 정합 검사는 체인이 표에 쓴다
  → 원장 선언(표 → 노드 · 엣지)  국소적 · 무계산 번역만
  → 걷기                        데이터에 답하는 유일한 길
  → 화면 · AI · 리포트            같은 걷기 답을 본다
```

**근거 — 표는 쓰는 쪽, 온톨로지는 읽는 쪽.** 원장 선언은 행 하나(또는 group_by 묶음)에서 나오는 것만 옮긴다(계산 없음).
여러 행을 걸어 세는 판정은 계산이므로 체인이 표에 쓰고, 원장이 그 표를 읽어 노드로 올린다. 걷기에서 판정을 바로 지어내면
원장에 «선언 없는 사실»이 생기고 이력 · 레이어 · 소급이 그 판정에 붙지 않는다. (소유자 «온톨로지 지어놓고 이렇게 표로 하는게 맞는지» 에 대한 답)

## 1. 두 층

```
위층  시스템 온톨로지   제품 자신 — 표 · 칸 · 규칙 · 원장 소스 · 리포트 · 수집기 · 실행 상태 · AI 메모리
아래층 도메인 온톨로지   운영자 데이터 — 선언된 엔티티 · 술어
```
- 둘 다 같은 걷기 엔진으로 걷는다. 시스템 세계는 제품이 출하하는 선언이라 빈칸을 제품이 메운다 → 걷기가 도메인보다 먼저 다 된다
  (소유자 «걷기가 시스템 세계에서 먼저 활성화되네 도메인보다» · «도메인도 얼른 끌어올려야지»). 가상 걷기의 빈칸 수리는 세계를 가리지 않으므로 도메인도 같이 오른다.
- 목적지(소유자 11-06, 11-10 재확인): 위층과 아래층을 결합하면 «완전 지능형 시스템» (소유자 «상위 층위 하위 층위 결합시키면»).

## 2. 메인 표가 곧 이력 — 셀소스 갈아엎기

| 판정 | 상태 | 소유자 문장 · 근거 |
|---|---|---|
| 메인 표 = 그 행의 이력. 쓰기 한 번 = 줄 하나, 지금 값 = 줄들을 순위로 합친 결과 | 정함 | 갈아엎기 목적지. 소유자 «처음부터 이렇게 할걸» · «셀 소스 관리는 … 로우 아이디 키로 모아서 구성하면 되잖아» |
| 물리 표 둘: `t__now`(행마다 지금 값) + `t__lines`(이력 줄). 분할(partition) 없음 | 정함 (앞의 ㄱ 분할을 뒤집음) | «근데 이러면 표 두개 하는거랑 뭐가 달라» · «그림자표랑 다를게 없는데» · «ㄴ이 낫지 직관적이고». 근거: 분할은 디스크에서 하는 일이 두 표와 같고, sqlite 에 분할이 없어 방언이 갈림. 두 표면 PG · sqlite 같은 DDL |
| 그림자 표와 다른 점 = 무엇이 원본인가. 여기서는 **줄이 원본**, 지금 값은 줄의 합 | 근거 | 지금 값 표가 망가져도 줄에서 다시 짓는다. 사람/체인 층 · 거두기 · 지우기 · 키 합치기가 전부 줄에서 판단된다 |
| 줄 삽입 + 지금 값 갱신 = 한 트랜잭션, 지금 줄을 먼저 잡는 순서 | 정함 | «지금 값과 이력줄 추가를 트랜잭션으로 하면 되잖아». 그래서 «줄로 다시 합친 값 = 지금 값» 점검 일(안전망)은 **짓지 않음** |
| 칸 추가 · 타입 · 지우기 · 이름 바꾸기 = 한 함수(`lines.alter_columns`)가 두 표에 같은 트랜잭션으로 | 총괄 정함 | 두 표의 칸이 갈라지지 않게 — 저자 하나 |
| 지우기 = «지워짐» 줄 + 지금 줄 내림 | 정함 | «지우기는 ㄱ» |
| 거두기 = 체인이 낸 몫만. 사람 몫(사람 줄 · 고정)은 행을 남긴다 | 정함 | «만약 거두기하면 체인층만 거둬야하고 사람 층은 남잖아» · «체인이 낸 행 부분만 없애면됨» |
| 출처 = 체인 규칙 + 입력 행 | 정함 | «체인 규칙 + 낸 행으로 해야하는거 아님?» |
| 키 겹침 → 줄 전부를 키 주인 row_id 로 이동(이기는 값은 오늘 병합 판단 그대로) | 정함 | «합쳐지면 rowid를 한쪽으로 몰아야하는거 아니야?» |
| 키 없는 행은 row_id 로만 | 정함 | «키 없는거는» |
| 옛 줄은 지우지 않는다(줄이 곧 층) | 정함 | «오래된 줄이 층 아니야? 그걸 왜 지워» |
| 옛 데이터 이주: row_id 순서로 넣음(흩어짐 줄이기) · 게이트 «이주한 지금 값 = 다시 합친 값 = 옛 값» · 되돌리기 `write_back` | 총괄 정함 | 노테이션 소급이 느렸던 원인이 «층이 디스크에 흩어짐»(HDD 무작위 읽기)이었다. 옛 이력이 착지 날 행끼리 모인다 |
| 사람 값의 신선도 «Below changed since edit» — 쓰기 5 단계가 won_by 옆에 적음 | 안 (총괄: 적는 자리는 쓰기 단계) | 읽을 때 세면 그리드가 이력 표를 읽게 되어 «그리드 읽기 영향 0»이 깨진다 |
| 집계 판정의 근거 행은 저장하지 않는다 — «규칙 + 키»를 들고, 근거는 원천 줄에서 그 시각으로 다시 짓는다 | 총괄 정함 | 근거 목록을 따로 쌓으면 선언과 갈라진다 |
| 몫마다 QA 판정 필수, 착지 전 교차 검수(쓰기 = D, 읽기 = A) | 정함 | «꼼꼼히 셀 쓰기 갈아엎는건 qa도 붙여» |
| 착지 당기기(관문은 그대로, 기다림만 줄임) | 정함 | «갈아엎기는 당길수 있으면 당겨봐» |

## 3. 감사 — 표 하나, 값 없음

| 판정 | 상태 | 소유자 문장 · 근거 |
|---|---|---|
| 감사 = 트랜잭션 · 표 · 누가 · 작업 종류 · 바뀐 행 수 · 행 이동(네비)만 | 정함 | «감사로그 그냥 트랜잭션, 테이블별, 누가 바꿨는지, 바뀐 행수, 바뀐 작업 타입 이것만» · «바뀐 행 네비 이거만 하라고» |
| 전 값(before value)은 없다 | 정함 | «전 값 한번도 본적 없어» · «감사로그에 값을 넣지마 그러면 또 표 커지잖아» · «줄일려고 하는데 왜 계속 키워» |
| 새 표 `audit_batches` 하나. `audit_logs` 는 착지 날 완전 은퇴, 데이터 아닌 기록도 같은 표 | 정함 | «데이터가 아닌 감사기록은 본적이 없는데». 오늘 audit_logs 는 칸 · 값마다 한 행이라 낟알이 달라 고쳐 쓰지 않고 새 표 |
| 바뀐 행 수 = 그 트랜잭션에서 줄을 쓴 서로 다른 row_id 수, 저장 안 하고 줄에서 셈 | 총괄 정함 | 소유자 낱말 «바뀐 행수»의 뜻 그대로 |
| 이력 봉투의 old_value 칸 제거 | 총괄 정함 | 소유자 «전 값 …» 문장. null 로 남기는 칸도 키우는 쪽 |
| 작업 종류 알약(OVERWRITE 등)은 작업 칸(edit · new · delete · withdraw · merge · mark · declare)을 읽는다 | 총괄 정함 | 소유자 다섯 칸의 «바뀐 작업 타입». 전 값 없이 알약이 산다 |
| 선언 저장 = `declare` 한 줄(누가 · 시각). 시스템 표를 다시 짓는 것은 감사 안 씀(잡음) | 정함 | «시스템 표에 감사로그 적용 못해? 표인데» |
| 다음: 선언의 원본도 시스템 표 행으로 — 같은 쓰기 입구 → 선언도 이력 · 되돌리기 · 전후 비교 | 정함(로드맵, 갈아엎기 · 트리거 찾기 다음) | 같은 문장, «ㄱ» · «완벽하다» |

## 4. 체인 — 한 개념, 위층 그래프로 깨운다

- 조인 · 파생행 · decide/derive 집계 · 칸 수식은 «종류»가 아니라 한 개념의 선언이다. 결과는 (규칙, 키)가 소유하고 키 묶음 단위로 다시 계산 · 거두기.
- 규칙 · 모순 감지(R001 «다이 본딩 배타성» 류)는 새 종류를 만들지 않고 체인 선언(걷기 + decide + 홀드 복사)으로 적는다
  — 소유자 «지금 홀드 카피 체인의 걷기 버전인듯». `check: die_bond_exclusive` 처럼 코드에 이름 붙은 검사는 운영자가 못 바꿔서 쓰지 않는다. (안)
- 재료 점검(행마다 키에 해당하는 데이터가 있나) = 재료 표마다 조인 `take {fn: count}` → `<재료>_rows` 칸. 선언만으로 된다.
  - 리포트 선언의 역할에서 이 조인들을 써 주는 «Create coverage joins» 버튼 — 정함(«1 ㄱ»). 숨은 자동 규칙은 쓰지 않는다(선언 목록에 없는 규칙이 돈다).
  - 알림(메일)은 소유자 몫 — «알림은 알아서 할게».

### 4.1 «먼 표가 바뀌어도 조용히 낡는 값» — 정합성 결함 (11-10 A 코드 읽기)
- 같은 표 · 조인 상대 표가 바뀌면 그 키만 다시 계산한다(있음).
- 조인 take 의 `fn: walk` 가 걸어 간 먼 표 · `take.ref` 표가 바뀌면 **규칙이 깨어나지 않는다** — 오류도 표시도 없이 낡는다.
- 앞 규칙이 그 먼 표 쓰기에 실패해도 순서 가드가 이 조인을 미루지 않는다.

### 4.2 트리거 찾기 = 위층 걷기 (다음 1순위)
- 소유자 «온톨로지랑 체인 결합해봐 트리거 찾기» · «체인 슈퍼 선언이랑 같이해야할듯» · «시스템 온톨로지를 잘 짜면 될거 같은데».
- 시스템 세계에 `chain_rule —reads_from(역할: trigger · right · ref · walk)→ table` 를 다 세우고(새 술어 없이 넓힘),
  선언이 바뀔 때 거꾸로 걸어 «표 → 깨울 규칙» 표를 짓고, 사건이 나면 아래층을 거꾸로 걸어 다시 계산할 행을 찾는다. (A 안 ㄱ, 추천)
- 같은 그래프 위의 걷기가 정적 검사기의 «순환 탐지» · «(표, 칸) 소유 충돌»과 «바꾸기 전 영향 범위»를 답한다.
- **열림**: ㄱ/ㄴ/ㄷ · ref 표가 바뀌면 규칙 전체를 다시 돌리나 · 소유 충돌을 거절하나(총괄 추천: 알리기만 — A official · B official 이 같은 마스터 칸을 층으로 쓰는 모양이 일부러 둔 설계).

### 4.3 Why not written (갈아엎기 뒤) — 정함(«ㄱ»)
- 오늘 «(규칙, 행) → 왜 안 썼나»에 답하는 곳이 0 이었다(화면 10 · 응답 10 · 로그 약 45 · 기록 4 중).
- (규칙, 행)을 넣으면 정본 판정을 차례로 **부르기만** 하며 어디서 멈췄는지 한 줄씩 답한다: 꺼짐 → 트리거 → 게이트 → 조인 짝 → 사람 값이 이김 → 대기 → «규칙보다 먼저 들어온 행 → 소급». 같은 자리에서 «무엇을 언제 썼나».
- AI · 리포트 규칙은 시험 실행(맵퍼)을 하지 않고 «not tried: costs a model call»(총괄 정함).
- 그 길에서 찾은 거짓 문장 둘(«마지막 결과» 배지가 상관없는 묶음에 덮임 · 그리드 큐의 «왜 안 도나»가 정본을 안 부르고 따로 가름)은 바로 고침(총괄 정함, 소유자 판정을 바꾸지 않음).

## 5. 걷기 — 가상 일괄

| 판정 | 상태 | 소유자 문장 · 근거 |
|---|---|---|
| 엔진을 안 적은 걷기는 전부 가상(표에서 바로 SQL), 원장(stored)으로 되돌리지 않는다 | 정함 | «다 가상걷기로 해» · «가상 읽든 말든 가상 일괄». 설정할 것 없음 |
| 못 읽은 선언은 답의 `engine.left_out` 에 이유와 함께 → 화면 «Not read: <선언> — <이유>» | 총괄 정함 | «안되는데 아무것도 안나옴» — 조용한 빈 답이 원인 추적을 막았다 |
| 빈칸 닫는 순서: 값 없는 목적어 → 노드 속성 1단(노드 · 선) → 2단(값까지) → 값 객체 | 진행 | 노드 속성 하나 때문에 그 소스의 문장 «전부»가 빠지던 것이 «아무것도 안 나옴»의 가장 유력한 꼴 |
| 운영자 뷰를 읽는 소스는 범위 밖 | 정함(이전) | f3bc02f6e «운영에서는 뷰 안 써». 갈아엎기 뒤 이름 t 는 «선언된 표의 보기»라 카탈로그가 t__now 의 종류를 싣는다(판정 함수는 그대로) |
| 클레임 노드: 이력 줄을 걷기에 노드로 — 한 칸에 지금 클레임 둘 이상 = 충돌. 오피셜은 그 위에 선언된 결정 | 안 | 외부 제안 «오피셜 충돌 방지 대신 클레임 노드». 오피셜은 없애지 않는다 — 운영자에게는 답 하나가 필요하다 |

## 6. AI — 걷고, 되묻고, 선언을 짓는다

### 6.1 AI 제어의 경계 (외부 검토 반영, 로드맵)
- **커널 층**: 시스템 표를 노드로 바꾸는 선언 · 쓰기 입구 · 멈춤 스위치는 AI 가 쓸 수 없다. 꼬였을 때 파일 기반 안전 모드.
- **되돌리기 범위** = 선언 복원 + 그 규칙이 소유한 몫 거두기 + 영향 행 재계산, 되돌리기 전에 영향 범위 미리보기.
- **자율 단계**: proposed → asserted → supported → predictive → intervened. 작업 종류마다 따로(`ai_action_kind.autonomy`), 장부 성적으로만 오르고 성적이 떨어지면 자동 강등.
  - 다시 오르는 길: 강등된 단계에서도 제안은 계속 장부에 채점된다(사람 승인 아래). 최근 창의 성적이 오름 기준을 다시 넘으면 한 단계씩 오른다. 창 크기 · 기준 값은 선언에 적는 자리(값은 운영자). 사람이 직접 올리는 것도 선언 한 줄 — 그것도 declare 감사가 남는다.
- **한도**: 한 번에 바꾸는 수(`step_cap`) + 시간당 · 하루 누적.
- **가지 세계**: 결과에 «본 세계와 다를 수 있는 이유»(데이터 양 · 가지 뒤 들어온 변경 수)를 같이.
- **오염 막기**: 메일 · 웹에서 온 사실은 낮은 순위 층 · 클레임 노드, 사람 확인 전엔 오피셜 아님. 메일은 보안 검토 먼저.

## 7. 식 엔진

- CASE WHEN(조건형 · 값형)은 10-13 부터 있다. 식 편집기가 한 줄이라 안 보였다 — 소유자 «식 편집기가 한줄이라 case when 상상도 못했네» → 여러 줄 편집 · CASE/If 뼈대 · 오류 위치 표시(클라B 안).
- `If(조건, then)` 허용, else 없으면 null — 정함(«ㄱ»). `SN(값, 대신)` 추가 — 소유자 «sn도 있지?».
- `Count([칸])` 은 빈 값(''·공백·NaN 포함)을 세지 않는다. `Count()` 는 행 수.
- 수식은 `=` 로 시작(조인 take · 칸 수식 · 집계 공통, 10i).

## 8. 리포트

- «last time» 류 칸을 최신 기준으로: 이미 있는 `keys.<칸>: ["latest"]` — 새 자리를 만들지 않는다(같은 «최신»에 선언 자리 둘 금지).
- 날짜 없는 웨이퍼는 비교 열에서 뺀다(10-24 판정 유지, 소유자 «ㄴ»).
- 그림 칸이 비면 사유 + 그림 표의 가장 가까운 키를 칸에 쓴다(조용한 빈칸 금지). 시각 철자 차이는 자동으로 접지 않는다(글자를 시각이라 추측해야 함) — 칸 타입을 datetime 으로 선언하는 자리가 있다.
- 신호등(안): 재료마다 있음 · 키 맞음 · 시각 맞음 · 소스끼리 맞음 · 운영자가 적은 관계식. 정합 판정은 체인 decide → 정합 표 → 원장 → 걷기(R001 · R002 와 같은 기제).
