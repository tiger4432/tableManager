# 헤더가 «한 줄 더» 쓴다 — `overflow: hidden` 이 flex 최소폭을 «0 으로» 풀고 있었다

> **커밋:** `b892e8e5` (20:33) — 디자인(클라) 레인 · C-118
> **일자:** 2026-09-16
> **레인 보고:** `task/DESIGN_ORDERS.md` · 총괄 검증 `7f5a351f` (20:38) · 병합 `9d2be58b`
> **측정 상자:** 이 워크스테이션. **운영이 아니다.**

## 배경

메인 그리드 상단 바에서 **폭 1280 일 때 컨트롤 아홉 중 여섯이 자기 클릭을 못 받고 있었다.**
그중 둘은 그날 실제로 쓰이는 버튼이었다. 계기는 `elementFromPoint(중심)` 이 그 버튼이 아니라
«다른 것»을 돌려주는 것이었다.

총괄이 지시서에 준 가설은 **「`min-width: 0` 부터 보십시오」**였다. 레인이 재서 **반대**를 찾았다.

## 무엇을 바꿨나

### ① 원인은 「빠진 `min-width: 0`」이 아니라 「있는 `overflow: hidden`」이었다

`.glass-btn-group` 은 모서리 반경 안으로 자식을 자르려고 `overflow: hidden` 을 쓴다.
flex 에서 overflow 가 `visible` 이 아닌 아이템은 `min-width: auto` 가 주는 **내용 기반 최소폭을
잃고 0 으로 풀린다.** 그래서 이 묶음이 자연 폭 550px 에서 **12px 로 접혔고**, 안의 버튼 여섯이
클립돼 사라졌다 — 자기 rect 는 그대로 보고하면서, 그려지지는 않고, 아무도 못 누르는 상태로.
그 픽셀을 차지한 형제(「Loaded N rows in …」 배지 · 표 선택 래퍼 · ⚙️ Options)가 대신 클릭을 받았다.

모서리 자르기는 남겨야 하므로 overflow 를 건드리지 않고 **「안 줄어듦」을 선언**했다:

```css
/* 🔴 C-118 — 「좁아지면 어떻게 되나」를 «여기 한 곳»이 말합니다. 두 줄입니다:
     줄어드는 것  필터 띠(자기 접기 단추가 있음) · 상태 문구(생략표로 줄어드는 `#performance-log`)
     안 줄어드는 것 컨트롤 전부. 모자라면 바가 «한 줄 더» 씁니다 */
.controls-area > .control-group,
.controls-area > .theme-toggle-btn,
.controls-area > .status-indicators {
  flex: 0 0 auto;
}
```

### ② 줄바꿈만으로는 «더 나빠졌다** — 헤더 자신이 눌리고 있었다

`.app-header` 는 `height: 52px` 였고, 동시에 «세로 flex 칼럼의 아이템»이라 `flex-shrink` 가 기본 1 이다.
줄바꿈을 켜자 상자는 70px 에 머무는데 내용은 168px 을 요구해 **내용이 그리드 위로 쏟아졌다.**
수치는 `blocked: 0` 인데 스샷에서는 워드마크가 1행에 앉아 있었다 — 수와 그림이 갈린 자리다.

```css
-  height: 52px;
+  flex: 0 0 auto;
+  min-height: 52px;
   ...
+  flex-wrap: wrap;
+  row-gap: 8px;
-  padding: 0 24px;
+  padding: 6px 24px;
```

### ③ 「Loaded N rows in …」 는 «읽는» 것이다

```css
.glass-log-badge {
  pointer-events: none;   /* 이 부품에 클릭 핸들러는 «하나도 없습니다»(실측) */
```

값이 길어지면 옆 버튼 위로 넘어가 그 버튼의 클릭을 먹던 자리다.

## 아키텍처 영향

- **넘침 전략이 한 곳에 선언됐다.** 전에는 「좁아지면 어떻게 되나」의 답이 아무 데도 없었고,
  그래서 `overflow: hidden` 의 부작용이 «정책처럼» 동작하고 있었다 — 컨트롤을 조용히 지우는 정책.
- 이 결함은 **오류를 하나도 안 냈다.** 버튼은 DOM 에 있고 rect 도 돌려주는데, 그려지지 않고
  hit-test 도 안 된다. 「깔끔 ①」(이 줄이 «참»인가)의 실물이다.
- 같은 커밋이 `replay_rules_harness.mjs` 바닥을 46 → 47 로 올렸다. S-270(`0c6a70c1`)이 단언 하나를
  더했고 게이트가 바닥이 따라오기를 요구했다.

## 🔴 그때 계기가 두 번 틀렸다 (총괄 기록)

```
① 첫 판   뷰포트가 0×0 인 채로 재서 「전부 가림」이 나왔다 (elementFromPoint 가 전부 null)
② 둘째 판  `top < 60` 으로 걸러 «아홉»만 봤는데, 바가 두 줄로 접히자 아래 줄이 창 밖으로 빠졌다
          -> «부분집합 위의 0» 이었다
③ elementFromPoint 가 null 이면 「가려짐」이 아니라 「화면 밖」이다 — 둘은 다른 수다
```
②는 총괄이 지시서에 준 한 줄짜리 게이트였고, 레인 판이 헤더 «전체»를 걷는 쪽으로 바꿨다.
