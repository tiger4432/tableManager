## 배경 — 반쪽만 있는 포맷은 포맷이 아니다

`📋 Copy to Excel`의 COPY HEADER MODE는 운영자 회사의 본딩맵 양식(상단 `TITLE` + 열 그룹 띠 +
우측 `VALUE | COUNT | STACK | DESC` 보조표)을 **쓸 수 있었다.** 읽을 수 있는 것은 **하나도
없었다.**

F1이 처음부터 ⓐ(내보내기)와 ⓑ(되붙이기)의 **한 쌍**으로 등록된 이유가 이것이다 — 내보내기만
만들면 "쓸 줄은 아는데 읽을 줄 모르는" 포맷이 생기고, 묶으면 **INV가 자명해진다: 복사한 것을
그대로 붙여넣으면 격자가 동일하다.** 한 줄로 양쪽이 동시에 채점된다.

```
INV-F1ⓑ-1: COPY HEADER MODE로 복사한 맵을 그대로 되붙이면 격자가 셀 하나까지 같다(빈 칸 포함).
```

아래의 모든 규칙은 **이 한 문장을 정직하게 만들기 위해** 있다.

---

## 결정 ① 읽는 쪽은 `text/html`이 아니라 **평문**이다

복사는 두 가지를 다 싣는다(`text/html` + `text/plain`). 읽는 쪽으로 평문을 고른 근거는 셋이고,
**대가도 소스에 명시했다.**

- **`parseTsv`가 이 저장소의 유일한 TSV 리더**이고, 엑셀의 인용 규칙(탭·줄바꿈을 품은 셀)을
  아는 것도 그것뿐이다. 그리드 화면과 DOE 패널이 이미 그것을 쓴다. 여기서 `split('\t')`을 손으로
  쓰면 **세 번째** 클립보드 파서가 생긴다.
- **사용자가 실제로 되붙이는 것은 엑셀을 거친 표**다. 엑셀이 내보내는 HTML은 mso 조건부 주석·
  중첩 표·rowspan이 섞인 넓은 표면이고, **우리가 쓴 colspan과 같다는 보장이 없다.** HTML을
  읽으려면 표 파서를 새로 써야 하는데 그게 곧 **두 번째 격자 파서**다(`compose_map_id`가 세
  개였을 때와 같은 형태).
- **대가는 숨기지 않는다.** 평문에는 병합이 없으므로 colspan 구조가 **「글자 뒤의 빈 칸」이라는
  관례로만** 남는다. 그래서 아래 INV-F1ⓑ-3은 부수 규칙이 아니라 **핵심 규칙**이다.

## 결정 ② 🔴 머리 띠의 빈 칸은 「빈 열」이 아니라 「왼쪽 칸의 연장」이다

보조표는 열마다 폭이 다르므로(`VALUE`가 3열, `COUNT`가 2열 …) 평문에서는
`VALUE ␣ ␣ COUNT ␣ STACK ␣ DESC ␣ ␣ ␣`처럼 도착하고, 데이터 줄도 **같은 자리**에 놓인다.
그래서 읽기는 **머리줄에서 배운 열 위치로만** 한다.

```js
// 🔴 **머리줄에서 배운 위치로** 읽는다. 비어 있지 않은 칸을 모으는(압축) 읽기는
//    STACK이 빈 줄에서 DESC를 STACK 자리로 밀어 넣는다 — INV-F1ⓑ-3.
const rec = aux.positions.map(p => pasteAt(lines[i], p).trim());
if (pasteBlank(rec[valueSlot])) break;   // 보조표가 끝났다(그 아래는 빈 칸 채움)
```

빈 칸을 걷어내고 압축하면 `['F','12','','FAIL']`이 `['F','12','FAIL']`이 되어 **DESC가 STACK
자리로 들어간다.** 화면은 멀쩡하고 값만 틀리는, 이 도메인의 그 결함이다. 압축 읽기는 하네스의
변이 목록에 **명시된 변이로 들어가 있다**(아래 검증).

## 결정 ③ 상단 그룹 띠는 **읽지 않는다** — 순환이라서 못 읽는다

읽을 수 있는데 안 읽는 게 아니다. 그룹 칸의 값은 **비어 있을 수 있고**(그 구역에 자재가 없는
맵), 평문에서 「빈 칸」과 「연장」은 **같은 문자**다. 폭을 복원하려면 글자를 알아야 하고 글자를
읽으려면 폭을 알아야 하는 순환이다. 그래서 정체 확인은 **항상 첫 열에 있는 `TITLE` 한 칸**으로
하고, 그룹 띠는 그리기로만 남긴다. **읽을 수 없는 것을 읽은 척하지 않는다.**

그 결정이 보조표 머리줄 판정에 조건 하나를 강제했다.

```js
// 🔴 `VALUE`가 없으면 보조표가 아니다. 이 조건이 없으면 **상단 그룹 띠**가 머리줄로 오인된다:
//    자재가 없는 맵에서는 그 줄의 마지막 비어 있지 않은 칸들이 라벨 `1H`·`MID`·`TOP`이고,
//    셋 다 `DOE_COLUMNS`의 헤더 단어라 `looksLikeHeader`를 그대로 통과한다. 그러면 격자 폭이
//    그룹 띠에서 계산돼 **표 전체가 어긋난다**.
if (ids.indexOf('value') < 0) return null;
```

머리줄 판정기는 새로 만들지 않았다 — `columnIdByHeader`(로스터 포함)와 `looksLikeHeader`는
DOE 패널 붙여넣기가 쓰는 그 함수들이고, `COUNT`를 `IGNORE`로 보내는 것도 그 로스터다. 훑는
방향만 다르다: **오른쪽에서 왼쪽으로** — 보조표는 줄의 꼬리에 있고, 왼쪽 격자 셀(`1`·`F` 같은
값)은 아는 열 이름이 아니라서 거기서 멈춘다.

## 산출물이 강제한 두 가지

### 🔴 노치 `D`는 데이터가 아니라 그림이다 — 되쓰면 그 맵의 Push가 영구 거절된다

복사는 웨이퍼 노치 방향을 빈 셀에 `D` 한 글자로 찍는다(`val === ''`일 때만). 그대로 되쓰면
원래 없던 셀 값이 하나 생기는데, 그 자리는 웨이퍼 bbox **밖**이라:

- `inside`가 거짓 → **화면에 색도 안 나오고**,
- `pushMapData`가 **직렬화하지도 않고**,
- 그런데도 **대비 관문의 분모에는 들어간다.**

= **붙여넣기 한 번이 그 맵의 Push를 영구 거절 상태로 만든다.** 옛 `Fill All`이 저지른 것과
같은 계급이다. 그래서 알아보고 **버린다** — `COUNT`와 같은 처리다.

```js
let v = parsed.rows[r][c];
if (n && r === n.r && c === n.c && v === 'D') { v = ''; stats.notchDropped++; }
```

**확인창의 수도 같이 고쳐야 했다.** 버릴 칸을 세면 "178칸"이라 말하고 177칸을 놓는다(실측
2026-07-30, 실맵 `4B12`). 작지만 확인창의 수를 못 믿게 만드는 종류이고, 「화면 34 · DB 33」과
같은 계급이라 `pastedCellCount`가 그 한 칸을 뺀다.

### 그런데 그 `D`가 이 포맷이 나르는 **유일한 프레임 지문**이다

노치 자리는 (회전, 면, bbox)의 함수다. 그래서 **치수가 같은 채로 프레임만 바뀐 경우**
(rot 0↔180, front↔back)를 잡는 유일한 신호다. 종전에는 이 계산이 `copyGridToExcel` 안에
인라인으로 있었고, 붙여넣기가 **같은 수**를 알아야 해서 `computeNotchCell`로 올라왔다 —
**두 방향이 같은 함수를 공유한다**(오버레이 규율과 같다: 두 번째 구현 금지).

```js
if (notchOnGrid && parsed.rows[n.r][n.c] !== 'D') {
  return { ok: false, reason: `복사할 때의 회전·면이 지금과 다릅니다 — 노치 표식(D)이 `
    + `${n.r + 1}행 ${n.c + 1}열에 있어야 하는데 「${parsed.rows[n.r][n.c] || '빈 칸'}」입니다.` };
}
```

격자 밖으로 나가는 규격에서는 `null`을 돌려준다 — **그때는 지문이 없는 것이지 0이 아니다.**
확인창이 *"노치 표식이 격자 밖이라 회전·면은 대조하지 못했습니다"*라고 말한다. 조용히
통과시키지 않는다.

## 거부한다, 최선 노력 배치를 하지 않는다

`checkPasteAgainstFrame`은 순수 함수이고 네 갈래로 거부한다 — **열 수 · 행 수 · 정체(TITLE) ·
프레임 지문(노치)**. 밀린 격자도 여전히 유효한 격자로 보이기 때문에, 여기서 통과시키면 아무도
못 잡는다.

정체는 **미상과 불일치를 구별한다.** TITLE이 없는 복사본(헤더 미포함)은 "다르다"가 아니라
**미상**이므로 통과시키되, 확인창이 그 사실을 말한다.

그리고 **격자 모양이 전혀 아닌 클립보드는 조용히 지나간다.** 다른 화면·다른 앱에서 긁은 표에
토스트를 띄우면 아무 붙여넣기에나 경고가 뜬다.

## 붙여넣기는 값을 **지우지 않는다**

```js
// 🔴 **지우지 않는다.** 복사본에 없는 값은 "삭제하라"가 아니라 "이 복사본이 말하지 않은 것"이다.
//    삭제는 DOE 패널의 삭제 버튼이 하고, 그것만이 Push에서 registry 행을 없앨 권한을 갖는다.
```

DOE 쪽 정체는 **VALUE**다. DOE 패널의 붙여넣기는 "포커스한 행부터 순서대로"라 VALUE가
개명이지만, 이 양식은 **값으로 주소를 매긴 표**라 VALUE가 키다. 그래서 개명은 하지 않는다.
패치 적용도 legend 변조 관문(`updateLegendRowForPanel`)을 지난다 — 이 파일에 legend를 직접
만지는 두 번째 경로를 만들지 않기 위해서다. `COLOR`는 이 양식에 없으므로 기존 값은 자기 색을
유지하고, 새 값만 공용 팔레트 경로가 배정한다.

**서버에는 아무것도 쓰지 않는다**(INV-F1ⓑ-4). 붙여넣기는 화면을 만들 뿐이고 저장은 `⚡ Push`
하나다. 그리고 저장되지 않을 셀은 **보고한다** — 분류기는 새로 만들지 않고 Push 관문이 쓰는
`classifyUnsavableCells`를 그대로 부른다(직전 커밋 `5a14e77`에서 들어온 그것).

## 가는 길에 닫힌 잠재 발산 둘

**① `HDR_GAP_COLS`.** 격자와 보조표 사이의 빈 칸을 **폭 계산만** 상수로 썼고, `auxCells`와
`auxTsv`는 각각 **리터럴 한 칸**을 찍고 있었다. 읽기 쪽이 격자 폭을 `VALUE의 열 위치 − 간격`으로
되찾으므로, 그 리터럴과 상수가 갈리는 순간 **붙여넣은 격자가 통째로 한 칸 밀린다.** 지역
상수 `GAP_W`가 모듈 상수로 올라왔고, 쓰기 쪽 세 자리가 전부 그것에서 나온다.

```js
gridWidth = aux.positions[0] - HDR_GAP_COLS;   // 읽기가 격자 폭을 되찾는 한 줄
```

이 발산은 하네스 변이 목록에 `writer emits a wider gap than the reader assumes`로 들어갔다.

**② `TITLE` 조립기.** 복사가 쓰고 붙여넣기가 대조하므로 두 곳에서 각자 조립하면 "정체가 같은데
글자가 다르다"로 거부된다. `copyTitleText()` 하나로 모았다.

## 새 컨트롤 0개 — 선택이 아니라 물리적 제약이다

운영은 평문 HTTP라 `navigator.clipboard`가 **`undefined`**이고 `execCommand('paste')`는 웹
콘텐츠에서 차단된다. **버튼에서는 클립보드를 읽을 수 없다.** 네이티브 `paste` 이벤트만 내용을
주므로 **Ctrl+V가 유일한 동선**이다. 확인창은 **하나**이고 급은 `🧹 Clear Grid`·`🎨 Fill All`과
같다.

양보 가드 둘: DOE 패널(`transfer_plan.onPlanPaste`)이 먼저 처리한 붙여넣기는 `defaultPrevented`로
비키고, 입력 칸(`INPUT`/`TEXTAREA`/`contenteditable`) 안의 붙여넣기는 그 칸의 것이다.

## 검증

- **하네스 52 단언 · 변이 13종 전부 사멸**(커밋 기록). 종료 조건은 `실패 0 && 놓친 변이 0`이다.
- 🔴 **채점 대상이 산출물이다.** 모든 붙여넣기 단언의 입력은 **같은 샌드박스에서
  `copyGridToExcel`이 클립보드에 넘긴 literal 문자열**이다. 기대 레이아웃을 다시 타이핑한
  테스트는 자기가 이미 믿는 레이아웃을 채점한다 — contract-keeper가 2026-07-29에 그 교훈을
  측정했고, 이 파일이 TSV를 손으로 쓰지 않는 이유다.
- **채점기가 원본 소스에서 침묵함을 먼저 단언한다**(`scorer is silent on the working tree`,
  두 변종). 이게 없으면 모든 변이가 **작업 트리가 이미 갖고 있는 결함**에 잡혀 "검출"된다.
- **변이는 프레임 가드도 겨눈다** — 자기 왕복은 깨끗한데 바뀐 프레임을 받아들이는 변이는
  빨개진다. 정체 교체·노치 교체·행 수 축소 세 조합으로 확인한다.
- **UI 실맵 왕복**: 복사 → `🧹 Clear Grid` → Ctrl+V → 다시 복사, **두 클립보드 형태 모두 바이트
  동일**(커밋 기록).
- **rot 270 → 90은 치수가 같은데도 거부된다** — 잡는 것은 노치다(커밋 기록).
- 이 라운드에 파이썬 스위트 수치는 없다. 변경이 전부 클라이언트이고, 클라 절반의 채점자는
  직전 커밋이 세운 빌드 게이트(`npm run build`)다.

⚠️ **하네스 파일 안의 서술 하나가 자기 코드와 어긋난다.** 머리 주석은 *"Ten source mutations
are applied"*라고 적었는데 `MUTATIONS` 배열에는 **13개**가 있다. 커밋 메시지의 "13 of 13"이
배열과 맞고, 주석이 늘어난 목록을 따라오지 못했다.

- **왕복하지 않는 것들**: 자재(1H·MID·TOP)는 상단 그룹 띠가 **의도적으로 읽히지 않으므로**
  복원되지 않고, `COLOR`는 양식에 없으므로 복원되지 않으며, `COUNT`는 알아보되 버려진다.
  결함이 아니라 **명시된 계약**이고, 이 커밋 시점의 사용자 문서(`DOE_GUIDE §4.2`)가 표로 그렇게
  적었다.
- **표②(자재 롤업)를 되붙이는 경로는 없다.** 로스터의 롤업 여덟 단어는 직전 커밋에서 예비로
  실린 것이고, `rollupToGrid`의 importer는 이 시점에도 0건이다.
- **`GET /api/maps/preset-routing`(F5 서버 절반, `50bddda`)의 클라 소비자는 이 커밋 시점에도
  없다** — 맵을 열 때의 규격 결정 동작은 아직 변하지 않았다.
- **문서 반영은 이 커밋에 없다.** 스펙·가이드·체크리스트는 다음 커밋(`3fcd72f`)에서 따라붙었다.
