## 배경 — 응용 단계의 첫 두 구성

게이트 ①이 닫히고 응용(application) 단계가 시작됐다. 은퇴 울타리를 다시 그은 뒤 **언 것을
하나도 안 건드리는 구성 ①과 ③**이 승인됐다.

## 구성 ① — 원자가 아니라 «선언»에서 노드를 만든다

증거 투영은 원자에서 event·claim·entity·value 를 짓고 있었다. 이제 **같은 방식으로 한 종류를
더** 짓는다 — 기계 모델 선언에서: **value 가 quantity 에 묶이고, quantity 가 선언이 말하는
방향으로 다른 quantity 를 몬다.**

**원장에서 읽는 것은 하나도 없고 낱말도 늘지 않는다** — quantity 는 **누군가 선언한 것에서
합성**되지 저장소에 앉아 있는 엔터티가 아니다.

🔴 **모델 이름이 노드 신원의 일부인 것은 «일부러»다.**

> 같은 물리량 이름이 **두 모델에 나타나고**, 공유 노드 하나로 두면 **모델러 둘의 단언을
> 어느 쪽도 하지 않은 제3의 것으로 이어 붙인다.**

id 는 왕복한다 — 웨이퍼 walk 에서 꺼낸 것을 그대로 seed 로 되돌려주면 resolve 되고 walk 된다.

**코드 0줄로 확장됨을 증명했다**: 선언 사본에 노드·엣지·바인딩을 하나씩 더하면 **정확히 그
노드와 그 엣지**가 나온다 — **노드 27 → 28, 엣지 27 → 29.** 관련된 payload 컬럼은 세 실행
모두에 있었고, **선언된 뒤에야** 엣지가 늘었다. **라이브 선언은 쓰이지 않았다.**

지시서가 이름 대지 않은 결과 하나를 스스로 적었다: **묶인 claim 하나가 기본 깊이에서
물리량 스물셋과 기계 엣지 스물하나를 끌어온다** — 여기서 도달 가능성은 **계약상 무방향**이기
때문이다. 데이터가 아니라 **선언이 경계**지만, collect 가 생겨 좁히기 전까지 **평범한 계보
뷰가 인과 구름으로 커진다.** 토글은 만들지 않았다 — **그 축은 다음 작업의 것.**

## 구성 ③ — 인자 하나로 갈리고, 분기하지 않는다

`subgraph()`가 **단일 seed** 또는 **부호 붙은 seed 집합**을 받고, 답을 노드 종류 하나로
좁히는 **선택적 `collect`**를 받는다. seed 빌더가 한 함수로 모여서 집합도 **멤버마다 같은
구성**을 돈다.

```
collect entity     -> 자기 웨이퍼들 위의 «선언된 공통 조상»
collect quantity   -> 순위 매긴 원인들
두 호출의 «노드 목록은 동일»
collect 는 네 자리에 나타나고 «어느 자리도 값으로 분기하지 않는다»
```

수용 조건이 그것이었다 — **거기서 분기가 났다면 모양이 틀렸다는 뜻**이기 때문이다.

**세 상태가 셋으로 남는다.** 대조 seed 가 없으면 답은 **「미검사」**라고 말한다 — 한 번도 안
본 것을 「보고 아무것도 못 찾음」으로 다루지 않는다. 양쪽 목록에 다 있는 id 는 **이름으로
거절**된다. 라이브 walk 는 **노드 상한에 닿으므로** 응답이 **전파가 끝났는지**도 말한다 —
예산이 못 미친 후보도 미검사다. 상위 집합은 관측 간 안정적이었고 **그 아래 순위는 아니었다.**

## 🔴 첫 홉 규칙에 «자기를 시험하지 않는 테스트»가 있었다

규칙을 변이시켜도 **열여섯이 전부 초록**이었다. **우세(dominance)가 부호를 가로질러 비교하지
않고, seed 별 재스케일은 양의 seed 둘이 차수가 다르지 않으면 순위를 못 움직인다.**
픽스처가 이제 그것을 하고, 변이가 **정확히 하나**를 빨갛게 만든다.

## 🔴 그리고 라이브 500 하나 — 쓰인 날부터 계속

수용 시험을 아예 못 돌리게 막고 있던 것:

```
요약을 찾는 SQL 이 «중괄호를 담은 JSON 경로»를 f-string 안에 지었다
-> 파이썬이 그것을 치환 필드로 읽었다
-> 모든 호출이 NameError
=> 서브그래프 엔드포인트는 «쓰인 이래로 모든 entity seed 에 대해 실패하고 있었다»
```

**살아남은 이유가 기록됐다** — 메모리 테스트는 전부 **순수 파이썬 쌍둥이**를 쓰고,
**PostgreSQL 테스트 하나는 서버가 없으면 skip** 된다. 이제 이스케이프됐고, **렌더된 SQL 이
그 리터럴 경로를 여전히 담는지 단언하는 테스트**가 붙었다.

## 아키텍처 영향

- 증거 투영이 **원장 밖의 선언(`server/config/mechanism_models.json`)에서 노드를 합성**한다.
  노드 신원에 **모델 이름이 들어간다** — 같은 이름의 물리량을 모델 간에 합치지 않기 위해.
- `subgraph()`가 **seed 집합 + `collect`** 를 받는다. 두 응용이 **인자 하나로만** 갈린다.

## 그때 남아 있던 것

- **인과 구름은 좁혀지지 않은 채**다. 묶인 claim 하나가 기본 깊이에서 물리량 23·기계 엣지 21을
  끌어오고, 토글은 만들지 않았다.
- 라이브 walk 는 **노드 상한에 닿는다.** 응답이 전파 완료 여부를 말하지만 상한 자체는 그대로다.
- 상위 집합 아래의 **순위는 관측 간 안정적이지 않았다.**
- 라이브 기계 모델 선언은 **쓰이지 않았다** — 확장 증명은 사본 위에서 했다.
