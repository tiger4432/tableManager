# Core usage map

## Change

- Added derived `core_usage_map` for fast spatial inspection of used core-die areas.
- The table is keyed by `core_wafer + core_x + core_y`, with `core_wafer` as its sole map scope. `used_count`, `used_dt_jobs`, and `core_lot_slots` are display/provenance fields.
- It never writes `core_wafer_map`; physical defect/bin data stays immutable from the usage projection's perspective.
- Two chain triggers rebuild only affected whole-wafer usage maps with `replace_map=true`:
  - `dt_inventory -> core_usage_map` after `core_frame` and core equations become available.
  - `dt_log -> core_usage_map` when ingest or enrichment changes `core_wafer`.
- Lot/slot-only raw rows deliberately produce no usage map. A mixed identity would create two map scopes for the same physical wafer before/after enrichment. Once operating enrichment supplies `core_wafer`, the corresponding wafer map is rebuilt from all available `dt_log` rows.

## Expected operational cost

- One additional dynamic table, schema-sync entry, admin/grid menu item, and websocket/outbox stream.
- A refresh reads all `dt_log` rows for one affected `core_wafer` and replaces only that derived map. It does not scan or rewrite unrelated wafers.
- Storage is one row per used physical core die, generally smaller than `dt_log`; `used_dt_jobs` grows with legitimate reuse and should be observed for unusually reused wafers.
