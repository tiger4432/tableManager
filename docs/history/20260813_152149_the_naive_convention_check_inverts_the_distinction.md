# The naive convention check inverts the distinction

**Date:** 2026-08-13 15:21 · **Domain:** Client (원장 추적 화면 / ledger slice 1 L3) · **Status:** 착지 — `d9b98ab`

> ⚠️ **검증은 «빌드된» dist에서, 레인 자체 포트로 받았다.** `:8081`은 돌고 있지 않았고
> 띄우지도 않았으며, 어느 것도 운영을 겨눈 적이 없다.

---

## 배경 — 세 번째 층은 화면이다

운영자가 lot을 입력하면(`LOT/02`나 `LOT 02`도) 웨이퍼의 계보가 hop 카드의 사슬로 나온다:
서버의 걷기가 «물은 질문», 답, 상태 배지, 그리고 서버의 `reason`을 **그대로**.

## 이 레인이 찾은 결함이 핵심이고, 그것은 «`candidate` hop을 만들어 봤기 때문»에만 드러났다

온톨로지 소유자가 판정한 관례/측정 구별은 **hop dict 어디에도 없다** — 사유 산문 «안»에 산다.
그리고 `server/ledger_trace.py::_with_basis`는 **이긴** 주장의 basis를 접미사로 붙이는데,
`candidate` 사유는 **진** 쪽의 basis를 문장 안에서 이름 댄다.

```
[candidate] class=2 observation 답 …-A6 · 하위 계급 반대 1종
  (…-ZZ(convention:slot_preserving)) · 1순위 … · basis=pair_field
```

그래서 `reason.includes('convention:')`은 구별을 **놓치는 것이 아니라 «뒤집는다»** —
**가정이 측정에 의해 «뒤집힌» 바로 그 hop을 「가정」이라고 이름 붙인다.** 프로브의
경합 hop 둘이 **둘 다** 여기에 걸렸다.

수리는 한 함수 안의 **앵커된 정규식 하나**다.

```js
const BASIS_SUFFIX = /\s·\s(convention:|basis=)([^\s·()]+)$/;
```

양방향이 못 박혔고, 그 핀이 실패할 수 있다는 것을 mutant가 증명한다.

## 🔴 덮지 않고 «올렸다»

hop에 구조화된 `basis: {kind, name}`이 있으면 **이 파싱이 통째로 사라진다.**
이것은 L2가 `predicate`를 추가할 때 이미 한 층 위에서 받아들인 것과 같은 논증이다 —
「클라이언트는 한국어 산문을 파싱하지 않고는 `has_wafer` hop과 `derived_from` hop을 구별할 수
없다」. **클라이언트가 한국어를 정규식으로 훑어야만 복원할 수 있는 판정은 리팩터 한 번이면
사라지는 판정이다.**

## 두 신호를 직교시켰다 — 색 = 상태, 무늬 = basis

관례 hop은 **점선** 레일·테두리와 점선 「가정 · slot_preserving」 칩을, 측정 hop은 **실선**
레일과 「근거 · pair_field」를 받는다. 운영자는 둘 중 어느 쪽인지를 **어느 것도 읽지 않고**
볼 수 있다.

## 복잡도 예산 — 앱 전체에서 폼 컨트롤 순증 +1

빌드된 페이지에서 라이브로 측정했다.

```js
ok('H13 the page carries exactly one input', controls === 1, `found ${controls}`);
```

기존 메뉴의 nav 앵커 하나 외에 **모달·모드·패널이 없다.** 단일 입력 상자가 Enter에서
확정되고 URL을 다시 쓴다 — **그래서 답이 링크다.** 둘째 입력도, 제출 버튼도, 히스토리
컨트롤도 없는 이유가 그것이다. 두 단언이 그것을 못 박아서, 미래의 필터 바는 빨갛게 되고
자기를 변호해야 한다.

**끊긴 사슬은 «내용»으로 렌더된다.** 모르는 lot은 빈 상태도 토스트도 아니라 **간극 hop
하나와 종료를 가진 추적**이다.

## 그때 남아 있던 것

- 13파일 +2,592/-8(빌드 산출물 포함). 하네스 674줄, 픽스처 둘.
- 세 상태 전부 **실제 서버 답**에서 렌더됐다: `resolved`, `candidate` ×2, `unresolvable`,
  그리고 `[root]`. `unresolvable` 케이스는 **버리는 스키마의 사본**에서 만들어졌다 —
  `public`은 한 번도 쓰이지 않았고 여전히 878 원자를 들고 있으며, 프로브 스키마와 롤은
  떨궈졌다.
- 가독성은 주장이 아니라 측정: 최소 글자 13px, 최악 WCAG 대비 라이트 4.50 / 다크 5.32,
  가로 오버플로 없음. 세션 가드는 **첫 응답을 두 번째보다 1500 ms 늦춰** 증명했다 — 순서가
  진짜로 뒤집혔으므로 그 측정은 실패할 수 있었다.
- 하네스 변이 시험 21/21, **이름 붙은** 단언이 잡았고 탈출 0, 대조군 2/2 탈출.
  하네스의 첫 실행은 세 번 빨갰고 그중 **두 번은 하네스가 자기 산문을 읽고 있었다** —
  `toLocaleString`/`innerHTML`을 **금지하는 주석 안의** 그 단어들에 매칭됐다.
- 게이트: `check:harnesses` exit 0(하네스 50개, 새것 171 단언 0 실패),
  `check:contracts` exit 0(계약 7종).
- 🔴 **지나가다 찾았고 안 고쳤다**: `database.py`가
  `connect_args={"options": "-c client_encoding=utf8"}`를 넘기는데, 이것이 `DATABASE_URL`의
  libpq `options`를 **조용히 덮어쓴다** — URL 수준의 `search_path`가 **에러 없이** 버려지고,
