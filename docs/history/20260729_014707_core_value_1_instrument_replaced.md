## 배경 — 계기가 이틀 만에 자기 한계를 증명했다

`ec75d4c`(2026-07-27)가 핵심가치 #1 "최소 공수 교정"에 처음으로 계기를 달았다.
**재교정률** — 사람이 같은 셀을 두 번 이상 고친 비율. 그 커밋은 출시와 동시에 자기 한계를
**실측으로** 기록해 두었다: 전체 2.01%, 200행 초과 트랜잭션을 제외하면 13.13%. 맵 에디터
push 같은 대량 트랜잭션이 손편집 신호를 **6.5배 희석**하고 있었다. 그때는 임계값 200이
"그럴듯해 보이는 틀린 숫자를 제조하는 자의적 노브"라는 이유로 필터를 넣지 않고, 선택을
사용자 결정으로 보드에 올려 두었다.

2026-07-29, 사용자는 그 미결을 **필터 선택이 아니라 계기 교체**로 닫았다.

## 결정 — 완료까지의 상호작용 횟수

새 정본 계기는 **한 데이터 단위가 채워질 때까지 사람이 쓴 클릭·화면 이동 수**다.
SSOT §1이 다음 상태로 바뀌었다:

```markdown
<!-- docs/overview/SYSTEM_OVERVIEW.md §1, 이 커밋 시점 -->
1. **최소 공수 교정** — 불완전 데이터를 사람이 가장 적은 손으로 진실로 바꾼다. ...
   - **계기(정본, 사용자 2026-07-29 교체): 완료까지의 상호작용 횟수** — 한 데이터 단위가
     **채워질 때까지 사람이 쓴 클릭·화면 이동 수**. "최소 공수"를 에두르지 않고 직접 재는
     유일한 값이므로 낮을수록 좋다. ⚠️ **미구현 — 계측 없이는 V1이 계기판 없이 굴러간다.**
     그리고 이 값은 **소급 산출이 불가능**하다(과거 세션에 클릭 로그가 없음). 따라서
     **교정 표면을 고치기 전에 계측을 먼저 붙여야** 개선 전/후를 비교할 수 있다.
   - **보조 계기: 재교정률**(`/dashboard/summary` → `recorrection`, 어드민 Overview 한 줄)
     — ... 첫 시도가 먹히지 않았다는 간접 증거다. 2026-07-29 정본에서 보조로 강등(원인이
     UI 공수인지 데이터 품질인지 분리되지 않고, 대량 트랜잭션 포함 여부로 2.01%↔13.13%
     **6.5배 희석**되어 단독 판단 근거가 못 된다). ...
```

사용자가 밝힌 이유 두 가지가 그대로 문서에 남았다.

1. **재교정률은 원인을 분리하지 못한다.** 같은 셀을 두 번 고쳤다는 사실은 UI 공수 탓일
   수도, 데이터 품질 탓일 수도 있다. "최소 공수"는 전자를 재려는 가치인데 지표는 둘을
   섞는다. 그래서 이 커밋에서 재교정률의 성격 서술이 "직접 증거"에서 **"간접 증거"**로
   바뀌었다 — 한 단어지만 지표의 지위 그 자체다.
2. **희석 계수가 정의에 달려 있다.** 2.01%↔13.13%는 같은 데이터에서 대량 트랜잭션 포함
   여부만으로 갈린 값이다. 6.5배 흔들리는 숫자는 단독 판단 근거가 될 수 없다.

상호작용 횟수는 "최소 공수"를 에두르지 않고 **직접** 잰다 — 대리 지표를 해석하는 단계가
사라진다.

## 아키텍처 영향

### 소급 불가능성이 순서를 강제한다

이것이 이 결정의 가장 무거운 구조적 결과다. 재교정률은 `audit_logs`에서 **파생**됐다 —
신규 로깅 코드 0줄로, 이미 쌓인 데이터에 질의만 하면 과거까지 계산됐다. 상호작용 횟수는
그렇지 않다. 과거 세션에 클릭 로그가 없으므로 **계측이 붙기 전 구간의 값은 영원히 존재하지
않는다.** 교정 표면(UI)을 먼저 고치면 개선 전 기준선이 사라지고, 개선했다는 주장을 검증할
방법이 남지 않는다. SSOT는 이 사실을 경고 표시와 함께 문서에 못 박았다.

이는 지표의 성질이 아키텍처 순서를 규정한 첫 사례다. 파생 지표(관측 데이터에서 뒤늦게
계산 가능)와 계측 지표(사건 발생 시점에 잡지 않으면 소실)의 차이가 **작업 순서의 제약**으로
번역됐다.

### 강등은 철거가 아니다

재교정률은 삭제되지 않았다. `/dashboard/summary → recorrection` 엔드포인트, 어드민
Overview 한 줄, `data_model §2.3`의 정의, `backend.md`의 계약이 전부 그대로다. 간접 증거도
증거이고, 분모와 함께 읽으면 여전히 읽을 수 있다 — "비율은 반드시 분모와 함께 읽는다"는
경고문도 보조 계기 줄에 그대로 따라 내려갔다. 계기 교체가 코드 철거를 동반하지 않은 것은
의도다.

## 검증

문서 전용 커밋이다(SSOT 1파일 + 보드 1파일, 순증 15줄). 스위트나 라이브 검증이 붙는
종류의 변경이 아니다. 검증에 해당하는 것은 **결정의 근거가 실측이었다**는 사실이다 —
2.01% / 13.13% / 6.5배는 이틀 전 `ec75d4c`가 라이브 데이터로 뽑아 히스토리에 남긴
숫자이고, 이번 결정은 그 숫자를 읽고 내려졌다. 계기가 자기를 강등시킬 근거를 스스로
생산한 셈이다.

## 그때 남아 있던 것

- **새 정본 계기는 미구현이었다.** 이 커밋은 문서 두 파일만 바꿨고, 클릭·화면 이동을 세는
  코드는 한 줄도 없었다. 즉 이 시점 핵심가치 #1의 정본 계기에는 **읽을 수 있는 값이
  없었다** — 보조로 내려간 재교정률만이 실제로 서빙되는 숫자였다.
- **재교정률의 대량 트랜잭션 희석은 그대로였다.** 지위가 보조로 내려갔을 뿐, 트랜잭션
  크기 필터는 여전히 들어가지 않은 상태였다.
- 같은 커밋이 보드에 사용자 결정 4건(계기 교체, `bonding_log` lot/slot = tape, 재교정
  인덱스 승인, 미선언 테이블 처분 승인)을 기록했다. 보드는 총괄 소관이므로 이 항목은
  기록됐다는 사실만 남긴다.
