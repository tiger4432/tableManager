## 배경 — 같은 실수를 두 번 했다

총괄이 DOE 삭제 버그를 잡겠다며 **클라이언트 쪽 차집합 계산**을 설계하고, 에이전트에게
"삭제가 어디서 새는가"에 대한 가설 4개를 브리핑했다. 사용자가 한 줄로 정리했다.

> DOE를 저장하는 것은 본딩 맵을 저장하는 것과 **구조적으로 같은 조작**이다. replace를 써라.

`replace_map`은 `crud.py`에 이미 있었고 맵 Push가 이미 쓰고 있었다.
DOE 테이블에 **범위를 잡을 `map_key_columns` 선언이 없었을 뿐**이다.
없던 것은 기능이 아니라 선언이었고, **총괄이 안 찾아본 것**이다.

같은 실수의 형제가 앞서 있었다 — 사용자의 수동 편집을 보호하겠다며 체인 소유권 탐지를 설계했는데,
시스템은 이미 모든 값에 source와 priority를 달고 있었고 USER가 체인보다 우선한다.

> **없는 선언은 없는 기능과 똑같이 생겼다.**

## 변경 내용

### 1) `docs/architecture/PRIMITIVES.md` — 기능 → 구현 카탈로그

의도적으로 **CODE_MAP이 아니다.** CODE_MAP은 *어디에 있는지*를, 이 문서는
**이 시스템이 이미 할 줄 아는 것**을 말한다.

수록 축(8절): 데이터 쓰기(맵 전량 교체·값 계층·미선언 컬럼 드롭) · 키와 정체 ·
설정에서 유도하기(제품 소유 vs 현장 소유) · 좌표와 맵(메타 델타 정렬·프레임 창) ·
인제션 · 프로세스 경계(Outbox+LISTEN/NOTIFY·경로 단일 교체점·격리 환경) ·
실패 규약("없다"와 "확인 못 했다"의 구분 · 절단 응답 강등 · warn-once).

각 항목은 **무엇 / 어디 / 언제 재사용 / 함정** 네 줄이고, 구현 세부는 코드에 남긴다 —
앵커가 낡는 것보다 **개념이 살아남는 것**이 중요하다.

수록 심사 기준이 한 줄로 정해져 있다:

> 다음 사람이 이 문제를 만났을 때, **존재하는 줄 몰라서 다시 만들 것인가?**

### 2) 착수 규율이 모든 에이전트 기억 파일의 공통 절 맨 위로

```
문제를 만나면 먼저 답한다 — "이건 무엇과 구조적으로 같은가."
답할 수 없으면 아직 설계할 준비가 안 된 것이다.
새로 만들 때는 왜 기존 프리미티브를 재사용할 수 없는지 보고서에 명시한다.
```

### 3) 문서 작업을 **입력 기준으로** 쪼갰다

한 에이전트가 입력이 전혀 다른 네 가지 일을 하고 있었고, 그래서 **엄격히 순차 실행**됐다 —
서로 의존하지도 않는 작업에 사이클당 20분 남짓.

| 에이전트 | 읽는 것 | 쓰는 것 |
|---|---|---|
| `doc-historian` | 커밋 diff | `docs/history/**` (추가 전용) |
| `code-mapper` | 소스 | `CODE_MAP.md` |
| `doc-keeper` | 변경의 **의미** | 리빙 문서 + `PRIMITIVES.md` |
| `doc-auditor` | 문서 vs 코드 | **아무것도 쓰지 않는다** |

**파일 집합이 서로 겹치지 않는 것**이 동시 실행을 안전하게 만드는 근거다.
`code-mapper`는 다른 에이전트가 동시에 편집하므로 워킹 트리가 아니라 `git show <hash>:`로 대조한다.

### 4) 검수를 저술에서 떼어냈다

`doc-keeper`가 문서를 **쓰면서 감사도** 하고 있었다 — `qa-reviewer`를 구현자와 분리한 것과 같은 이유로 잘못된 모양이다.
실제로 사이클 4에서 오버레이 스펙을 다시 쓰면서 같은 패스에 감사를 했는데,
**찾아낸 거짓 진술이 전부 이전 사이클의 저술에서 나왔다.** 방금 쓴 것은 심사 대상이 아니었다.

`doc-auditor`의 브리프에는 이 저장소에서 실제로 나온 실패 형태 3종이 박혀 있다 —
ⓐ 삭제된 파일이 살아 있는 것처럼 서술됨 ⓑ 구현 하루 전에 문서화된 동작
ⓒ 존재하지 않는 런처 파일. ⓑ가 미묘한데, **앵커는 실재하는 호출로 해석됐다 — 다만 서로 다른 함수였다.**
그래서 규칙이 "앵커는 일치하는 줄이 아니라 **그것을 감싸는 함수**로 해석한다"가 됐다.

읽기 트리거 등급도 이쪽 소관이다. 리빙 문서 49개 + 히스토리 211건이 있고 8개는 어떤 인덱스에도 없다.
**문서는 많아서 썩는 게 아니라 아무도 읽지 않아서 썩는다** — 트리거 없는 문서는 참으로 유지될 수 없으므로
등급 C는 갱신 백로그가 아니라 **아카이브 권고**다. 아카이브 결정 자체는 총괄이 한다.

### 5) 도메인 둘을 계층 분할에서 떼어냈다

- **`map-pm`** — 웨이퍼 맵 에디터 + DOE 패널. **"화면은 맞는데 숫자가 틀린"** 결함이 사는 곳이고,
  실제 리뷰 라운드를 치르고 세운 불변식 6개가 있다: 변환 구현은 하나 · 정렬의 근거는 메타뿐 ·
  서버 상태를 모르면 쓰지 않는다 · 불완전한 집합에 `replace_map`은 파괴적이다 ·
  정체는 라벨이 아니라 안정된 것에 · 같은 숫자를 두 번 계산하지 않는다.
- **`ontology-pm`** — 그래프를 서버·클라 **끝에서 끝까지** 한 도메인으로. 의미를 계층별로 쪼개는 것이
  좌표 코드에 서로 어긋나는 구현 둘을 만든 방식 그 자체다.
  미해결 문제를 그대로 상속한다 — Wafer 라벨이 조인 불가능한 정체 체계 둘을 들고 있고
  그중 하나는 실은 테이프 위치다. 두면 defect 역추적이 **다른 객체를 가리킨다.**
