# 매퍼 리터럴 계수기는 이름 집합을 라이브 config에서 읽는다 — 손으로 적은 목록은 드리프트한다

**날짜:** 2026-08-18 11:24 · **커밋:** `4360095` · **레인:** 서버(원장 단순화 2라운드 · 계기)
**측정 상자:** 이 워크스테이션. **운영이 아니다.**

---

## 배경

매퍼 재표준화 2라운드의 합격 조건은 「**매퍼가 선언을 알지 못한다**」이다. 그 문장은
**같은 방법으로 전후에 잰 수**가 없으면 검사할 수 없다 — 「깨끗해 보인다」는 판정이
아니다. 이 커밋은 그 수를 만드는 계기 하나를 `task/evidence/`에 놓는다. 운영 코드
변경은 없다.

## 이 파일이 하는 일

`task/evidence/ledger_mapper_literal_census.py`가 매퍼 파일을 **AST로** 훑어 모든 문자열
상수를 모으고, 그것을 **라이브 `ledger_config.json`에서 읽어 낸 네 이름 집합**에
대조해 분류한다.

| 부류 | 무엇 | 목표 |
|---|---|---|
| `mapping_id` | Profile mapping 식별자 | 0 (순수 배선) |
| `claim_ref` | claim 참조 | 0 (순수 배선) |
| `predicate` | 원장 어휘 낱말 | — |
| entity type | 개체 타입 철자 | 0 (순수 배선) |
| `qualifier` | 업무 어휘(`slot`·`from`·`to`·`wafer`) | **유지** |

🔴 **손으로 적은 목록을 쓰지 않는 것이 이 도구의 설계 결정이다.** 매퍼든 config든 한쪽이
바뀌는 순간 그 목록은 조용히 드리프트하고, 드리프트한 계기는 **낮게 읽는다** — 그리고
낮게 읽는 계기는 이미 깨끗한 매퍼와 **구별이 안 된다.**

## 합의에 두 번의 정정이 필요했고, 둘 다 계기를 낮게 읽게 만드는 종류였다

포크가 독립적으로 만든 착수 전 표(mapping_id 6 · claim_ref 0 · predicate 5 · entity type 11
· qualifier 7 · 합 29)를 **그대로 재현**하는 것이 이 도구의 검수 기준이었고, 거기 닿기까지
두 번 틀렸다.

- **술어는 `claim["predicate"]` 키가 아니다.** `claims[<이름>].emit.predicate`에 살고
  **버전이 붙어 있다**(`derived_from@1`). 매퍼는 `_base()`가 버전을 떼기 때문에 맨 철자를
  쓴다. 버전 있는 쪽과 맨 쪽을 비교하니 5가 아니라 **3**이 나왔다.
- **한정자는 `claim["qualifiers"]` 맵이 아니다.** claim의 `roles` 항목 중 `kind`가
  `attribute`인 것들이다. 엉뚱한 키를 보니 7이 아니라 **0**이 나왔다 — 브리핑이
  「**유지**」라고 못 박은 바로 그 부류에 대해 「이미 깨끗함」이라는 진단서가 발급된 것이다.

분류는 **첫 일치에서 멈춘다.** claim 이름이면서 술어 철자이기도 한 `slot_map`이 두 번
세어지지 않게 하기 위해서다.

## 검증

기록자가 인자 없이(기본 경로) 저장소 루트에서 다시 돌려 커밋의 표를 재현했다.

```bash
conda run -n assy_manager python task/evidence/ledger_mapper_literal_census.py
```

```
  mapping_id     6   :255 positional_row · :265 pair_field · :279 slot_preserving · …
  claim_ref      0
  predicate      5   :252 has_wafer · :263 derived_from · :276 slot_map · :294 slot_map · :319 register
  entity type   11   :238 Lot · :249 Wafer · :252 Lot · :253 Wafer · …
  qualifier      7   :254 slot · :278 from · :278 to · :278 wafer · :297 from · :297 to · :298 wafer

```

이 수들은 **오늘의 매퍼와 오늘의 config**에 속한다. 인용하려면 위 명령을 다시 돌린다 —
그것이 이 도구가 존재하는 이유다.

## 그때 남아 있던 것

- 운영 코드 변경 0. 커밋 본문의 원자 기준선 CASE DIFF 0 · 불변식 로케이터 10/10은
  기록자가 재실행하지 않았고 **커밋의 주장**으로 남긴다.
- 도구의 기본 매퍼·config 경로는 **이 상자의 절대 경로로 하드코딩**돼 있다(인자로
  덮어쓸 수 있다). 다른 상자에서 인자 없이 부르면 그 자리에서 죽는다 — 조용히 낮게
  읽지는 않는다.
- 2라운드 자체(매퍼에서 배선 리터럴 17개를 걷어내는 일)는 이 커밋 밖에 그대로 남아 있었다.
