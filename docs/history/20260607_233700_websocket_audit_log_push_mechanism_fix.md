# 변경 이력: 실시간 감사 로그(Audit Log) WebSocket 푸시 메커니즘 개선 및 디버그

- **작성일**: 2026년 6월 7일
- **작성자**: Antigravity
- **상태**: 완료

## 1. 개요 및 목적
- **현상**: 체인 인제션 및 일반 데이터 일괄 업데이트 시 일부 상황에서 실시간 감사 로그(Audit Log)가 클라이언트 화면(글로벌/셀/행 히스토리 탭)에 실시간으로 반영되지 않는 문제가 지속적으로 발생했습니다.
- **원인 분석**:
  1. **SQLAlchemy Autoflush 간섭**: `apply_batch_updates`에서 데이터 업데이트 시, 폴백 DB 조회 쿼리가 실행되면 자동 플러시(Autoflush)가 수행되어 `db.new`에 생성된 `AuditLog` 객체들이 세션에서 미리 비워집니다. 이로 인해 커밋 직전 `db.new`를 검사하는 로직이 빈 배열을 캡처하여 푸시 페이로드(`created_logs`)가 누락되었습니다.
  2. **지연 로딩 및 N+1 쿼리**: `db.commit()`을 호출한 이후 `created_log_objs`를 직렬화하면서 커밋 시점의 인스턴스 만료(Instance Expiry)로 인해 로그 속성을 읽을 때마다 매번 N+1 번의 개별 SELECT 쿼리가 실행되어 응답 속도 저하를 야기했습니다.
  3. **클라이언트 측 테이블 필터링**: 클라이언트(`main.js`)의 WebSocket 메시지 처리기(`handleWebSocketMessage`) 시작 부분에서 수신한 메시지의 테이블명이 현재 보고 있는 테이블명과 다르면 무조건 일찍 종료(`if (msg.table_name !== currentTable) return;`)되었습니다. 이로 인해 체인 업데이트(예: `production_plan` 수정으로 인해 백그라운드에서 `inventory_master`가 갱신되는 경우)가 일어나도 현재 보고 있는 테이블과 매치되지 않는 감사 로그는 클라이언트 단에서 그대로 무시되었습니다.
  4. **트랜잭션 ID 누락**: 체인 워커가 송신하는 WS 페이로드에 `transaction_id` 키가 누락되어 일부 클라이언트 사이드 캐시 병합 시 활용되지 못했습니다.

## 2. 세부 수정 사항

### 백엔드 수명 주기 관리 최적화 (`server/database/crud.py`)
- **Autoflush 방지**: 데이터 업데이트 루프 전체를 `with db.no_autoflush:` 컨텍스트로 감싸 쿼리 실행 중에 임시 생성된 `AuditLog` 객체가 `db.new`에서 강제로 밀려나지 않도록 격리했습니다.
- **선제적 flush 및 직렬화 타이밍 조절**: `db.commit()` 호출 전에 `db.flush()`를 명시적으로 실행하여 DB 할당 식별자(PK `id`)를 미리 확보했습니다.
- **메모리 내 직렬화**: 커밋 전에 직렬화를 수행함으로써 객체 만료로 인한 데이터베이스 재조회(N+1 쿼리)를 근본적으로 차단하고 캐시된 메모리 값으로 초고속 응답을 생성하도록 조정했습니다.

### 클라이언트 사이드 WebSocket 메시지 파싱 정합성 확보 (`client2/src/main.js`)
- **이력 파싱의 독립화**: `msg.table_name !== currentTable` 가드를 적용하기 **직전**에 메시지 최상위의 `created_logs`를 먼저 추출하도록 변경했습니다.
- **실시간 글로벌 이력 업데이트**: 활성화된 탭이 `'global'`인 경우에는 수정된 테이블의 종류와 무관하게 모든 실시간 감사 로그가 로컬 타임라인 캐시(`globalHistoryData`)에 축적되고 렌더링되도록 수정했습니다.
- **컨텍스트 매칭 보완**: 셀/행 탭인 경우 현재 보고 있는 테이블에 해당하는 로그만 매칭하도록 가드하여 크로스 테이블 감사 로그 스트리밍의 무결성을 확보했습니다.

### 체인 워커 WebSocket 페이로드 구조 대칭화 (`server/chain_ingestion_worker.py`)
- 체인 워커에서 브로드캐스트하는 메시지 페이로드에 `transaction_id` 필드를 정식으로 추가하여 REST API 엔드포인트의 브로드캐스트 페이로드 스펙과 일관되도록 구현했습니다.

## 3. 검증 결과
- **테스트 생략**: 사용자의 요청("서버 테스트하면 서버 굳음")에 따라 자동화 테스트 구동은 배제하고, 수동 소스 문법 및 런타임 정적 검사만 안전하게 마쳤습니다.
