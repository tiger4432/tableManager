## 배경 — 답은 «내내» 있었고 부르는 곳이 없었다

`/api/transfer-plan/stages` 는 역할마다 `connected` / `missing` 을 답한다.
**그 낱말로는 선언을 고칠 수 없다.** 「연결 안 됨」을 읽은 운영자가 다음에 갈 곳이 없다.

시운전(dry-run) 라우트는 **네 가지를 더** 답하고 있었고 **부르는 곳이 0** 이었다:

```
① 이름 붙은 사유          ② 사유 문장
③ 해석된 컬럼 + «그 표에 실제로 있는지»
④ 🔴 낱말이 결코 나를 수 없는 것 — 「틀린 선언을 지우면 무엇이 유도되나」
```

## 변경 내용

### ① 거절만 줄이 된다 (`b74ffa2d`)

```
승인된 역할에는 «줄이 없다»
이유: 통과 스물 + 거절 하나면, 이 블록이 답하려던 «그 거절»이 스무 줄 아래 묻힌다
```

### 🔴 그리고 이음매 계약이 나를 잡았다 — 이 라운드의 «기록할 값»이 여기다

레인이 **서버의 사유 이름을 클라에 적고** 한국어 라벨에 매핑했다.
`config_resolve_report` 의 **INV-F9-7 이 빌드를 거절했다.**

```
❌ 내가 한 것       서버가 정한 낱말을 «클라가 두 번째로» 적는다
                 -> 서버가 사유를 하나 더하는 날 화면이 «조용히» 그것을 모른다
✅ 고친 모양       상태는 «불리언만»으로 정한다
                 버킷 개수는 «이름을 부르지 않고 순회»한다
                 판정 낱말은 «서버의 것»을 그대로 그린다
증거             하니스가 «이 파일이 들어 본 적 없는» 버킷을 먹이고, 화면에 뜰 것을 요구한다
                 -> 순회로 바꿔서 산 것이 정확히 그것이다
```

🔴 **레인 자신이 그날 다른 모든 자리에 적용하던 규칙을 자기 코드에서 어겼고,
계약이 그것을 «구현 중»에 잡았다** — 사후 검수가 아니었다.

### ② 진단이 «어디 사는지»를 가리키는 줄 (`49289157`)

시운전을 admin 표면에 둔 것에는 그때 명시된 비용이 있었다 — **거절은 여기서 일어나고
진단은 저기 있다.** 가리키는 것이 없으면 운영자는 **진단이 존재한다는 사실 자체를 모른다.**

```
정적이다   아무것도 fetch 하지 않고 아무것도 받지 않는다
          -> 그래서 토큰이 필요 없다. 그리고 «토큰»이 애초에 진단이 이 화면에 못 산 이유다
조용하다   회색 · 작게. 이건 «주소»이지 «경고»가 아니다 —
          색을 넣으면 「여기 뭔가 잘못됐다」고 말하는 것이 된다
```

🔴 **거절 줄 «옆»에 안 붙였고, 그 이유가 실측이다.**

```
역할별 connected/missing 을 그리는 분류기   소유자 지시로 «끊겨 있는 절» 안에 산다
                                        살아 있는 호출자 «0»
살아 있는 경로                            stages 응답을 «범례에만» 쓴다
=> 안 도는 코드에 매단 안내는 «아무도 못 보는 안내»다. 그래서 패널이 «항상 그리는» 자리로
```

  서버의 것. 이 규율을 하니스가 «모르는 버킷»으로 강제한다.

  분류기가 끊긴 절에 있고 호출자가 0이라, 완화 안내가 붙을 자리가 «없다».
  `b74ffa2d` 는 그것을 **강제로 붙이지 않고 위로 올렸다.**
