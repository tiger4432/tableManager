### 🔴 이 줄기의 교훈은 「고쳤다」가 아니라 «실패가 어디로 옮겨갔나»다
```
전순서 좌석을 접었다      -> 라우트가 여전히 깨졌다. 「모델」이 없는 컬럼 넷을 «약속»하고 있어서,
                          실패가 ORDER BY 에서 «SELECT» 로 옮겨갔다
모델을 선언 컬럼만으로     -> 또 깨졌다. 뷰 행이 «평평»해져 그리드가 `data` 래퍼로 못 읽었고,
                          «선언된» row_id 가 PK 에서 밀렸다
```
📌 소스가 그 자리를 스스로 적는다: 「`kind` 를 읽는 자리가 이 앞에 «셋» 있었고 그중 «여기»는 없었다」.
**한 사실을 읽는 자리를 셋까지 세고도 넷째를 못 센 것**이고, 그것이 이 저장소가 반복해서 치르는 값이다.

### ⚠️ 그리고 「PK 가 필요하다」와 「신원이 있다」는 «다른 주장»이다
**출하 샘플** 실측(`table_config.json.sample`, 2026-09-12): `kind: view` **열하나** 중 **넷**이
`business_key` 를 아예 선언하지 않는다.
⚠️ **소스 주석은 「열」이라 적는다** — 그것은 «라이브 카탈로그»(gitignore)를 잰 수이고 저장소에 대해
아무 말도 하지 않는다. 위 열하나는 «추적되는 샘플»의 수다. 두 수는 «다른 모집단»이라 겹쳐 쓰면 안 된다.
SQLAlchemy 는 PK 없는 클래스를 매핑 못 하므로 컬럼 하나를 «지명»하지만, 그것은 신원의 주장이 아니다 —
그 넷은 읽기 경로에서 `total_order_key` 가 R7 로 **422** 를 낸다. 「이 관계는 페이징할 수 없다」를
말하는 자리는 «거기»이고, 모델의 지명이 그 답인 척하면 안 된다.

### 🔴 S-186-b — 「기억에서 카탈로그를 적었다」
출하 샘플의 `ledger_events` 항목이 컬럼 아홉을 선언했는데 그중 **넷이 없는 이름**이었다
(`recorded_at` · `subject_key` · `source` · `tx_id`). 물리 표는 «열넷»이다.
```

          `source_who` 를 `source` 로, 그리고 여기 어느 표의 것도 아닌 이름 둘
왜 안 잡혔나  «선언을 관계에 대고 읽는 것»이 아무 데도 없었다. 그래서 아무것도 실패하지 않았다

🔵 수리의 모양이 요점이다: 시험이 그 항목을 **`envelope.ROW_COLUMNS`** 에 대고 채점한다 —

## ③ 한 칸이 전선 위에서 무엇인가 (S-190 `46512d5b`)

소유자의 그리드가 `subject_keys` 와 `object_payload` 를 **「[object Object]」**로 그렸다.
```
사실      두 컬럼은 물리적으로 JSONB · psycopg2 가 `dict` 로 준다 · 라우트가 «그대로» 넘겼다
          · 그리드는 모든 칸을 «텍스트»로 받으므로 객체에 `String(...)` 을 불렀다
🔴 답      `utils/wire_format.wire_text(value)` — dict·list 면 JSON «텍스트», 그 밖은 «그대로»
```
🔴 **인자가 «값 하나»이고 타입 인자가 없는 것이 설계다** — 카탈로그의 타입 어휘는
number/datetime/string «셋»뿐이라 dict 는 «`string` 으로 선언된 칸»에만 도착할 수 있다.
값의 모양이 이미 답을 정하므로 둘째 인자는 「선언과 어긋날 두 번째 기회」가 된다.
🔴 **철자가 고정인 이유는 «두 독자가 이 문자열을 견주기» 때문이다** — `sort_keys`(dict 의 삽입 순서는
선언의 순서가 아니다) · `ensure_ascii=False`(한국어 키) · 좁은 구분자(그리드와 TSV 가 같은 바이트).
`str(value)` 는 파이썬 repr 이라 JSON 이 아니고 하류의 아무도 못 판다 — **행 TSV 가 그걸 하고 있었다.**
📐 부르는 자리 «여섯»(정의·import·시험 제외): `main.py` 넷 · `ledger_subgraph.py` 하나 · `dev_bench.py` 하나.

## ④ 돌려 보는 자리 (S-192 `803a709c`+`12985006`)

```
scripts/try_core.py  mapper <이름> <sample>  ·  parser <파일>  ·  folder <폴더>
```
🔴 **CLI 와 pytest 픽스처가 «같은 함수»를 지난다**(`run_sample_folder`) — 그래서 「명령줄에서는 된다」와
「시험은 통과한다」가 **다른 사실이 될 수 없다**.
🔴 **폴더 «하나»가 시험 «하나»다**(`input.csv` + `rule.json` + 매퍼 + `expected.tsv`). 등록할 목록이 없다.
🔴 **쓰지 «못한다»** — 커넥션을 서버가 읽기 전용으로 «강제»한다(판정 301). 「안 쓴다」와 「못 쓴다」는
다른 보장이다. ⚠️ DB 가 안 열리면 `db` 로 `None` 을 넘기고 그대로 돈다 — 매퍼 대부분은 `db` 를 안 만지고,
살아 있는 PostgreSQL 을 요구하면 벤치가 «제일 쓸모 있을 때» 못 쓰인다.
🔵 그리고 그 등록부를 «처음 쓴 것»이 이 벤치다 — 이름이 등록돼 있으면 «추측할 이름이 없다».
⚠️ **폴더 시험이 자기 공허함을 적어 뒀다**: `rows_to_tsv` 에서 `wire_text` 를 빼도 폴더 시험은 «초록»이었다.
두 규칙이 같은 답을 내는 표본은 판별식이 아니므로 그 자리를 «따로» 단언한다.

## ⑤ `/health` 가 «자기 자신과 모순»하고 있었다 (S-142 ②, `19735ed5`, 판정 297)

```

🔴 **결함은 「남은 파일」이 아니라 «한 응답이 자기와 모순»한 것이다.** 운영자는 workers 표를 읽고

⚠️ **그 변경이 둘째를 드러냈다**: `_roster.json` 이 일부러 심박 디렉터리 «안»에 살아서 `read_all` 이
