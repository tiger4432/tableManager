## 전제를 재봤다 (`bf77d7d`)

지시는 옳게 열렸다 — 기존 프리미티브 확인: 어드민의 config 프레임워크가 config 파일을
범용으로 나열·편집한다면 이 탭은 «등록»이지 새 에디터가 아니다. 재보니:

**편집 가능한 config 목록은 없다. 이 시스템의 어떤 config 파일도 UI에서 편집할 수
없었다.** 어드민의 유일한 파일 쓰기 경로는 `mappers/`·`ingestion_workspace/`에
allowlist된 Python «소스» 에디터였고, config를 쓰는 라우트는 0 —
`/admin/reload-configs`는 재읽기지 쓰기가 아니다.

그리고 그것은 배관 문제가 아니었다: `server/config/*`는 **설계상 gitignore**라
배포가 운영자 튜닝을 덮지 못한다. config를 쓰는 UI는 그것과 모순되지 않지만
**이 시스템 최초의 config 쓰기 경로**를 여는 것이고, 그 안전 표면은 구현 세부가
아니라 결정이다.

## 판정 R-G (`e64b2a1`, 보드 `54e414f`) — 읽기 전용 우선

탭은 view-first로 싣는다: 선언 렌더, `validate()`의 평결, **선언된 해시 대 커서가
마지막으로 돈 해시**의 대조와 어긋남 경고(탭의 하중 요소, 읽기 전용으로 완전 달성),
기존 reload 트리거 노출. UI 편집은 탭 기능으로 밀반입하지 않는다 — 소유자가 원하면
자기 라운드(validate·타임스탬프 백업이 undo·원자적 교체·reload·보고)로, 한 번 만들어
전 config에 범용으로.

논증이 남길 가치가 있는 부분이다: gitignore된 파일은 **역사가 아예 없다.** 쓰기를
쉽게 만드는 UI는 편당 위험을 올리는 게 아니라 **되돌릴 수 없는 편집의 빈도**를 올린다
— 「쓰기는 위험하다」와는 다른, 더 나은 논증.
