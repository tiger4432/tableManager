# The admin panel becomes the declaration editor

**Date:** 2026-08-14 15:20 / 15:25 · **Domain:** 프로세스(장기 방향 — admin·nocode) · **Status:** 기록만 — `81ee0da`, `9e92a4f`

## 진화 계획 (`81ee0da`) — 소유자 승인 「그렇게 해」, UI는 nocode 스타일

역할 재정의: 구조 뷰가 선언을 «읽는» 화면이라면 admin은 선언을 «쓰는» 화면이다
— 지표 정의·kind 등록·기전 엣지·측정 계획·프레임 확정. 축 둘이 설계를 통치한다:

- **선언 변경도 발화다** — admin의 모든 변경이 원장 이벤트로 남고(누가·언제·
  무엇을), undo = 이전 선언으로의 새 변경. config 무이력 문제의 해소이자
  「해석이 언제부터 달라졌나」 추적의 근거.
- **저장 게이트 내장** — 선언 신설 3문 + 스키마·로더 검증을 저장 버튼이 문다:
  미끼 선언이 UI에서 못 태어난다.

nocode 조사가 편집기 패턴을 선언 모양에 매핑했다: 목록형 선언은 표형 그리드 ·
조건부 기대는 문장형 규칙 빌더(문장이 그대로 config로 직렬화 — 사람이 읽는 것 =
기계가 읽는 것) · 기전 그래프는 모델당 소형 노드 캔버스(대형 캔버스의 난잡함은
모델 분할로 회피) · 공통 라이브 미리보기(구조 뷰가 생성형이라 공짜). 시점은 MI
묶음과 동행 — 지금 하는 것은 R6 쓰기 게이트에 「선언 변경 이벤트」 자리 확보
하나뿐. 위험 선언(어휘·번역)은 UI 편집 대상이 아니다 — 판정+고정 테스트 경로
유지.

## 확장 (`9e92a4f`) — 전 운영 config가 결국 nocode로, 나중에

소유자가 방향을 넓혔다: 체인 설정·파일 인제션·테이블 설정까지 같은 틀(그리드/
문장 빌더/저장 게이트/변경=발화/미리보기)로 간다 — 새 틀이 아니라 선언 편집기
패턴의 적용 범위 확대다. 순서까지 고정해 대기열에 등재됐다: 선언 편집기(MI
묶음)에서 검증 → config 중복 통폐합 라운드와 합류 → 체인·인제션 확대. 착수 지시
전 금지.

## 그때 남아 있던 것

- 둘 다 문서다 — 이 시점 admin 패널은 여전히 Monaco 기반 config 편집기이고,
  선언 편집기는 코드 0줄. 콘솔 R1~R7 임계 경로가 앞에 서 있었다.
