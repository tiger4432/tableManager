## 게이트를 «직접 돌려» 보니 빨간 것은 하나였다

```

check:harnesses    exit 0 · 지목된 하니스 57점 · 실패 0   -> 빨갛지 «않다»
```

판정: **클라 절반이 움직인다.** 라우트는 걷기이고 **걷기는 「선언된 격자」라는 개념을 모른다** —
문제의 줄 바로 위 두 줄이 정확히 그렇게 적고 있었다(「no server verdict here」).
사유를 이름 짓지 않는 라우트에 대해 클라가 «서버 모양의 사유 낱말»을 쓰면,
읽는 사람은 **서버가 그렇게 말했다고 배운다.**

서버가 이름 짓게 만드는 쪽은 **걷기 응답에 화면 개념을 심는 일**이라 기각됐다.

## 🔴🔴 둘째 빨강은 «내 계측기»였다 — 그리고 그 진단이 총괄의 실행 한 번을 태웠다

같은 커밋 본문이 스스로를 정정했다. `load_shows_loaded_map_harness` 는 **HEAD 에서 채점되고 통과한다** —

**남의 레인 빨강이라고 두 번 올렸고, 총괄의 검증 실행 한 번을 쓰게 했다.**

### ⚠️ 고치려던 시도도 기록됐다 — «되돌렸다»

워크트리를 LF 로 정규화하면 디프 중립일 것이라 «가정»하고 **129 파일을 변환했다.**
인덱스는 CRLF 를 들고 있으므로 **129 전부가 진짜 수정으로 떴다 — 바이너리 포함.**
즉시 되돌렸고, 자기 편집 둘은 따로 빼 두었다가 다시 얹었으며, 이후 `git status` 에 그 둘만 남았다.
**줄바꿈은 건드리지 않은 채로 뒀다.**

```
contracts 7/7 · rnd_board 170/0 · control_trend 59/0 · walk_box 48/0 · walk 32/0
composition 40/0 · intersection 24/0 · reach 63/0
```

번들은 다시 만들어졌고 그 위에서 쟀다. 이 워크트리에서는 `npm run build` 가 위의 CRLF 앵커에서
여전히 멈추므로 vite 를 직접 돌렸다 — 정상 경로는 총괄 트리에서 초록이다.

## 아키텍처 영향

- 클라가 **서버 모양의 사유 낱말을 짓지 않는다.** 계약 벡터 7/7.
- 선언 로더가 **주입 지점에서 하나**다 — 부품 둘은 서로를 여전히 모른다.
- 거절은 캐시되지 않는다. 「아직」이 「없음」으로 접히지 않는다.

## 그때 남아 있던 것

- **이 워크트리에서는 `npm run build` 가 여전히 멈춘다** — CRLF/LF 앵커 때문이고,
  같은 파일이 총괄 트리에서는 초록이다. 이 시점에 그 차이는 **줄바꿈뿐**임이 측정됐다.
- 히스토리 인덱스는 이 시점에 **744** 편이다.

  의도한 커밋이 아니라 **같이 스테이지된 것**이다.
