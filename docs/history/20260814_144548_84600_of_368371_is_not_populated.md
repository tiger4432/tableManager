# 84,600 of 368,371 is not "populated"

## 배경 — 라운드가 브리핑 넷을 정정했다, 전부 측정으로

세계 픽스처(`50a21c7`)의 리빙 문서 라운드. 총괄이 브리핑한 문장 넷이 실측에
반박됐고, 라운드는 브리핑대로 쓰기를 거부했다.

1. **「코어 컬럼이 이제 채워집니다」** — 전체 표처럼 읽힌다. 실제는 **368,371행
   중 84,600행, 108랏 중 24랏**이고, 라운드는 동사 대신 분수를 전 사이트에
   적었다. 화면의 모든 숫자에 적용하는 분모 규율이 산문에 도착한 것 — 「전부
   NULL → 이제 채워짐」이 복사돼 나갔으면 다음 진단은 108/108에서 출발했을
   것이다.
2. **「본딩→DT는 전부 25, 분산 없음」** — 표 전체로는 거짓: 차수 집합은
   {1, 25}이고 k=1은 코어 축이 아예 없는 실데이터 웨이퍼 120장이다. 결론은 더
   날카로운 이유로 살아남았다: **2~24 사이 표본 0** — 「many」 하드코딩 소비자는
   여전히 세는 소비자와 판별 불가.
3. **기하 19×19→23×23 전파** — 라운드가 확인하지 못해 **쓰지 않았다**:
   `core_wafer_map`의 표 전체 범위는 혼합 생산자 353장 위 25×25이고, 23×23은
   등록된 프레임의 속성이지 표의 속성이 아니다. 숫자 대신 단서가 들어갔다.
4. `dt_map.core_lot`은 전 사이트에 「선언 고정, 값 미도착」(5,619행, 채움 0)으로
   — 절대 「고정 완료」로 쓰지 않았다.

## 변경 내용

12파일 +150/−13. `apply_batch_updates` 결함의 기제는 추론이 필요 없었다 —
`crud.py`의 `unfilled_key_columns` docstring이 이미 서술하고 있었고, 「같은
비즈니스 키 두 번 푸시 = 같은 business_key_val을 든 두 행」 주석도 있었다.
유니크 인덱스가 조용한 중복을 시끄러운 거절로 바꿨을 뿐이라, 문서는 「인덱스
제거는 수리가 아니다」를 명시했다. 런북 §7의 자기모순(2026-08-14 개정 행이
「마이그레이션 파일 없다」 주장을 거짓이라 하면서 같은 절 마지막 행이 여전히 그
주장)은 옛 행을 삭제 대신 취소선 + 대체 행 포인터로 고쳤다.
