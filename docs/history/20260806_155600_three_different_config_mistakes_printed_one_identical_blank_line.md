# 서로 다른 config 실수 셋이 **똑같은 빈 줄 하나**를 찍고 있었다 — 진단이 결함이었다

> **커밋:** `17d8d00`(2026-08-06 15:56) | **일자:** 2026-08-06 낮
> **대상:** `server/map_alignment.py`(빌드 신원 · 사유 분리 · `index_col` 배선)
> **스위트:** **577 passed**

## 1. 모든 `align.log` 블록이 이제 **빌드 신원**으로 시작한다

```
build: commit <sha> | map_alignment.py modified <t> | process up since <t'>
       | features: canonical-walk,anchor,direction,confirmed-origin,...
```

**아무것도 기억할 필요가 없다.** sha는 호출 시점에 `.git`에서 읽고, 시각은 파일시스템과
시계에서 오며, **각 feature 토큰은 그것을 구현하는 심볼에서 유도된다** — 구현을 지우면 토큰이
**자동으로 사라진다.** 심볼을 하나씩 지워 보며 토큰이 떨어지는 것을 확인했다.
**한 항목도 잃지 않는 feature 목록은 정확히 이 저장소가 계속 값을 치르는 「울리지 않는 알람」**
이기 때문이다.

`.git`에 도달할 수 없으면 그 필드가 **그렇다고 말한다.** 추측하지 않는다 — **틀린 sha는 없느니만
못하다.**

이것이 존재하는 이유: 「저기서 그 코드가 돌고 있나」가 이 스레드에서 여러 라운드를 잡아먹었고,
증상으로 추론하려는 모든 시도가 틀렸다. 그리고 **같은 날 아침 두 레인이 자기 커밋보다 여섯 시간
낡은 서버를 출하 코드의 결함으로 읽었다.**

## 2. 🔴 조용한 갈래 셋이 이제 어느 것이 발화했는지 말한다

- 규칙의 소스 테이블 아래에 **바인딩이 없음**
- 바인딩이 **선언이 아니라 유도됨**
- 선언된 바인딩인데 **index 키가 없음**

**셋이 똑같은 빈 사유 하나를 찍고 있었다.** 서로 다른 config 실수 셋에 한 줄. 그래서 제안된
모든 원인이 그럴듯해 보였고 **로그에서 확인도 배제도 할 수 없었다.**

> **그것은 config가 결함인 게 아니라 진단이 결함인 것이다.**

내부 길이 가드도 더는 축을 조용히 끄지 않는다 — **서버 결함이고 config를 바꿔도 안 움직인다**고
말한다.

## 3. 도달한 적 없는 오버라이드

`index_col`이 `build_alignment_view`로 관통 배선됐다. 그 함수는 **다섯 파라미터 함수에 네
인자를 넘기고 있었고**, 그래서 **코드 자신의 주석이 존재를 가정하는 조작자 오버라이드는 한
번도 도달 가능한 적이 없었다.** 짝이 되는 query 파라미터는 `server/main.py` 소관이고 다른
레인이다.

## 4. 만들다 잡은 버그 하나 — **거짓 음성이 없는 결함을 사냥하게 만든다**

feature 탐침이 평탄 상수 스캔을 썼는데 **CPython이 dict 리터럴 키를 튜플로 폴딩**한다.
그래서 cell-index 토큰을 **가진** 빌드에서 그 토큰 **없이** 출력했다.
