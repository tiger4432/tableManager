## 배경 — 소유자가 폴더 인제션을 요구했다

`webkitdirectory`는 입력을 **폴더 전용**으로 만든다. 그래서 **입력 하나가 둘을 다 못 준다.**
`10b49623`이 입력을 **하나 더** 넣었고, N 개를 이미 처리하던 루프가 그대로 그것을 처리한다 —
새 기계를 안 만들었다.

🔴 **그리고 그 커밋이 자기 지시서의 전제를 정정했다:** 라우트가 이미 파일명을 유일하게 만들고
있으므로 **덮어쓰이는 것은 없었다. 잃던 것은 «경로»다.**

## 토스트가 파일마다 하나씩 떴다

`32c53c30`. 파일 100개면 토스트 100개. 루프 «밖»으로 옮겼다 — 5 파일 → 5 POST · 1 토스트,
20 파일 중 5 실패 → 토스트 2.

## 하위 폴더 이름이 서버에서 버려지고 있었다

`2c4027f3`. `voids_json_format`은 **경로 조각 «셋»**을 요구하는데 `voids` 폴더가 거절됐다.
가드를 **없애지 않고 넓혔다.** `6cdf421a`가 잎 이름을 지키게 해서 파서가 필요한 웨이퍼를
읽을 수 있게 했다.

## 아키텍처 영향

- 업로드가 **상대 경로를 나른다.** 폴더 구조가 인제션까지 살아 남고, 조각 셋을 요구하는
  파서가 폴더에서 온 파일을 읽는다.
- **입력 문이 둘이고 같은 문자열을 보낸다** — 브라우저와 데스크톱 래퍼가 같은 계약을 만족한다.
- 토스트가 **배치 단위**다.

## 그때 남아 있던 것

- 🔴 **`main.js:1250`의 드롭 핸들러가 루프의 «세 번째 사본»이고 아직 파일마다 토스트를 띄운다.**
  그리고 그것이 **실제로 동작하는 유일한 인제션 입구**다.
- **`ingest-file-btn`이 어느 HTML 에도 없다** — 그 파일 입력은 닿을 수 없다.
- 같은 나무를 두 번 올리면 **덮어쓴다.** 이 시점에 미정.
- `17fc0daa`가 **엔드투엔드는 검증 안 됐다**고 적었다 — 돌고 있는 서버 프로세스가
  라우트 변경보다 오래됐기 때문.
