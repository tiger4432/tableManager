## 배경 ― 「후보 목록에서 빼라」는 지시가 스펙에 있었다

11분 전 커밋된 스펙 §2가 **`grid_y_invert`를 후보 목록에서 빼라**고 적고 있었다.
그 문장은 재개발 착수 관문에 걸린 문서에 있었으므로, 틀렸다면 곧바로 열거기 설계에
들어간다. 그래서 `coordinate_transformer.py`를 다시 읽었다.

## 무엇이 관측됐나 ― 세 축이 같은 무대에서 놀지 않는다

**이 관측 자체는 맞다.** `rotation`과 `side`는 `cell_to_physical` 안에서 **격자 전체**를
축으로 미러하고:

```python
if self.side == "back":
    if self.is_rotated_90_or_270:
        r_m = (self.visual_rows - 1) - r
    else:
        c_m = (self.visual_cols - 1) - c
```

`grid_y_invert`는 `cell_to_visual` 안에서 **웨이퍼 바운딩박스**를 축으로 미러한다:

```python
if not self.invert_y:
    yv = r - min_r + self.start_y
else:
    yv = max_r - r + self.start_y
```

별칭이라던 두 튜플을 끝까지 합성하면 x는 완전히 같고 y만 상수만큼 어긋난다:

```
δ = (visual_rows − 1) − (min_r + max_r)
```

**δ = 0 ⟺ bbox가 격자 안에서 세로 중심.** 산술은 이 커밋 이후에도 유지됐다.

## 어디서 틀렸나

이 유도는 **「두 철자가 같은 bbox를 공유한다」**를 전제로 깔았다. 운영이 쓰는 경로에서는
**공유하지 않는다** ― `map_overlay._frame_phys_params`가 회전·면에 따라 오프셋 부호를
뒤집고, 그래서 두 철자의 bbox가 서로 미러된다. 전제가 참인 것은 **선언값을 엔진에
직결하는 raw 경로**뿐이었다.

**관측한 구간은 변환기 하나**였고, 답은 그 위의 다른 구간에 있었다. 라운드 1의 오류가
「선형부만 보고 합성을 말했다」였는데, 이 정정은 **다른 한 구간만 보고 파이프라인 전체를
말한** 같은 모양의 오류였다.

## 그래도 남은 것 ― I10 · I11, 그리고 「후보 목록에서 빼지 않는다」

이 커밋이 §7 불변식에 둘을 추가했다.

- **I10 ― 철자 동치는 좌표 동치가 아니다.**
- **I11 ― 군이 접힌다고 합성이 접히는 것은 아니다.** 자기 오류를 불변식으로 박은 것이다.

그리고 실무 결론 하나는 **반증 이후에도 살아남았다**: `frame_axes`가 `grid_y_invert`를
캐시 키에 넣고 `make_frame_transform`이 그것을 소비하므로, y반전으로 선언된 행을 후보
집합이 **자기 자신으로 재현하지 못하면** 정렬기가 그 맵의 `start_y`를 조용히 재작성한다.
정규화는 **읽기 쪽에서만** 한다 ― 쓰기까지 하면 그건 정렬이 아니라 데이터 변경이다.

## 아키텍처 영향

§2를 **삭제하지 않고 「반증 진행 중」으로 표시**하는 방식이 이 커밋에서 자리 잡았다.
같은 밤 `d3ed167`이 이 커밋의 결론까지 뒤집었을 때도 같은 규율이 적용돼, 두 오류가
모두 §2.2에 보존됐다.

## 그때 남아 있던 것

- 코드는 한 줄도 안 바뀌었다. 이 커밋이 반박한 것도, 이 커밋이 주장한 것도 **전부 문서 안**이다.
- δ 분포의 실측은 **배차만 됐고 돌아오지 않은** 상태였다. 그 실측이 35분 뒤에 이 커밋의
  전제를 무너뜨렸다.
- §2 본문은 취소선 처리된 옛 문장과 새 경고가 **함께 실린** 상태였다 ― 결론 한 줄만 옮겨
  적는 독자에게는 여전히 위험한 모양이었다.
