## 1. `34b4a93`이 **맞게** 고친 것 — 동어반복

사용자 문장이 결함을 정확히 진술했다: **「미리 앵커를 먹여놓으니 시프트 0이어도 만점이구만」**.

앵커가 미리 적용된 상태에서는 소스의 1번 다이가 기준의 첫 유효 다이 위로 **강제로 앉혀지고**,
그 다음에 겹침을 센다. 그러니 높은 겹침은 **프레임이 맞다는 증거가 아니라 앵커가 그렇게
앉혔다는 뜻**이다. 그리고 그것을 반박할 수 있는 유일한 수 — 시프트 — 는 **정의상 0**이었다.
**「이건 잘못 앉았다」가 나갈 수 있는 채널이 아예 없었다.**

그것이 그날 첫 신고 「화면 보면 어긋나 있는데 오버랩 266이래」의 설명이기도 하다.
**266은 앵커가 만든 수였다.** 여기에 index 축이 평행이동 불변이라 어떤 오프셋에서도 만점을
읽으므로, **지표 셋이 전부 「맞다」고 말하는 동안 틀린 것은 조작자가 눈으로 볼 수 있는 부분
하나뿐이었다.**

> **내 실수, 하루에 두 번:** `4947a65`가 동어반복을 정확히 진단하고도 **제거하는 대신** 잔차를
> 얹었고, `88ffc74`가 잔차를 되돌리면서 **동어반복만 남겼다.**

## 2. 그리고 그 수리가 배치를 `p = tf(x, y)`로 되돌렸다 — **거기가 회귀다**

`tf`는 `make_frame_transform`이다. **그 함수는 `start_x`/`start_y`와 `box.minC`/`minR`을
읽는다.** 반면 `reference_top_left`는 DB에서 **날것으로** 온다.

**피연산자 한쪽만 start를 지고 있었다.**

## 3. 사용자가 3점 측정으로 이름을 댔다

> 「유효다이영역 메타의 **start를 0으로 하면 잘됨**. 그런데 start를 점차 키우다가 **점점
> 틀어지다가** 극단적인 값으로 보내면 **아예 계산 안 됨** ... **앵커 계산 시 raw db좌표를
> 사용하지 않는 것 같음.**」

🔴 **파라미터에 비례하는 결함은 그 파라미터가 산술에 새는 것이다.** 그리고 극단값에서는
변환된 셀이 격자를 벗어나 **변환 자체가 거절**한다 — 그것이 사용자가 돌던 코드에서 읽은
`_placed = None`이기도 하다. 거절된 후보는 애초에 그 키를 못 받는다.

## 4. 수리 — 공간을 하나로, 그리고 차분에서 start가 소거되게

```
placed(cell) = anchor_src + L·(cell − anchor_src)      L = frame_linear_part
t            = anchor_ref − anchor_src                 둘 다 raw DB 좌표
seat         = anchor_ref + L·(cell − anchor_src)
```

차분이 start와 박스를 지운다:

```
c₂ − c₁ = (xv₂ − start + minC) − (xv₁ − start + minC) = xv₂ − xv₁
```

`frame_linear_part`는 **구조상 phys도 start도 한 글자 안 읽고**, 변환기의 선형부와 항등인
것은 **독립 오라클**이 지킨다 — `L`은 손으로 쓰이지 않는다. 세 값과 채점이 견주는
`ref_sorted`가 전부 저장 좌표에 산다. **탐색 폴백만 `make_frame_transform`을 타고**(절대
좌표가 필요한 갈래다) **그래서 start를 읽는 유일한 갈래로 남는다.**

## 8. 단언 둘이 바뀌었다 — 둘 다 **옛 `shift`의 뜻**을 인코딩하고 있었다

- `test_a_confirmed_origin_reproduces_the_alignment_it_was_derived_from`은 확정 후
  `shift == (0,0)`을 요구했다. **확정은 원점을 쓰고 저장된 셀은 하나도 안 옮긴다.** 그러니
  raw 앵커 차이가 0으로 돌아올 수 없고, **옛 단언은 이제 「확정이 데이터를 망가뜨릴 것」을
  요구하는 셈**이다. 좌석과 일치도로 대체, **48/48**.
- `test_no_per_map_origin_reaches_anything_the_scorer_reports`는 `shift.dx/dy`를 불변성
  튜플에 묶고 있었다. 기하는 25개 원점 쌍 중 **0개**에서 움직였고, 시프트는 **20/25**에서
  원점 델타만큼 움직였다 — 그 픽스처가 선언 원점과 함께 소스의 저장 셀도 옮기므로 **정직한
  raw 차이는 따라 움직여야 한다.** 튜플은 승자와 세 순위 축으로 바뀌었다.

**변이:** `4947a65` 모양의 **두 관문을 동시에** 지닌 사본 — 앵커를 배치에 다시 굽고 **그리고**
시프트를 `placed[i_min]` 위로 되돌린 것 — 이 세 파라미터 전부에서 (0,0)을 반환한다.
**관문 하나만으로는 빨개지지 않아서 둘 다 변이시켰다.**
