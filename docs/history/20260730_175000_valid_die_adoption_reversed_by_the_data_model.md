## 뒤집은 것은 사실이다

사용자 지시, 두 번:
- 참조 격자가 다르다고 지정을 막지 마라
- 「좌표는 db값 그대로 보존하고 **화면 표기 밀리게 그냥 보여주기**」

두 번째에서 사용자가 **불변식을 직접 진술했다.** 그리고 그 불변식은 데이터 모델의 사실이다 —

> **셀에 저장된 좌표라는 것은 없다.** `gridData`는 `물리 키 → 값`뿐이고, DB의 x/y는 **Push
> 시점에** `cellObj.x/.y`(= 렌더가 **현재 프레임으로** 유도한 좌표)에서 만들어진다.

그래서 「좌표를 보존한다」는 말의 **구현은 정확히 하나다 — 칸을 그대로 두는 것.** 격자 치수와
원점을 건드리지 않는 것이 곧 그것이다. 치수를 채택하면 **같은 칸이 다른 좌표를 낳는다.**
그리고 그 필연적 귀결이 F6이 재배치 기계장치를 만들어 막으려던 것이다 — 새 프레임이 표현하지
못하는 좌표 앞에서 재배치는 **셀을 버리거나(삭제) 번호를 다시 매기는(재좌표화)** 수밖에 없었다.
**둘 다 금지다.**

> 즉 **채택하는 설계는 어떤 것이든 잔여를 버리거나 다시 번호 매긴다.** 더 작은 수리로는
> 도달할 수 없고, 이것이 「제거가 답」인 이유다.

**총괄은 그 채택 설계를 직접 만들었고, 방어했고, 출하했다.** 사용자가 두 번 뒤집었다.

## 마스크는 애초에 채택을 필요로 하지 않았다

`projectCellsToPhys(cells, refFrame)`는 마스크 키를 **참조 자신의 프레임으로** 만든다 —
화면 컨트롤을 읽지 않는다. 채택이 하던 일은 **타깃의 인덱스 공간을 참조의 것과 맞춰서 마스크가
겹쳐 보이게 하는 것**뿐이었다. 맞추지 않으면 마스크는 밀려 보이고, **사용자가 요구한 화면이
정확히 그것이다.**

```js
// 종전:  const plan = storedCoordRepositionPlan(...); adoptFrameSpec(refFrame); ...
// 지금:  치수 차이는 **사실**이지 채택이 아니다. 화면은 그대로 두고 한 번 알린다.
dimsDiffer = { here: `${hereResolved.cols}x${hereResolved.rows}`,
               there: `${refResolved.cols}x${refResolved.rows}` };
```

순효과: **좌표 변경 0 · 행 유실 0 · 이 경로의 거절 0.** 치수 차이는 **info 토스트 1회**로만
말한다(확인창 없음, 새 컨트롤 없음) — 밀린 마스크는 **원인이 화면에 남지 않는 종류의 차이**라
(격자는 멀쩡해 보이고 마스크만 어긋난다) 조용하면 운영자가 데이터를 의심하기 때문이다.

## 재건: 무엇이 지워지고 무엇이 뒤집혔는지가 회계로 남았다

`94b9baa`의 diff가 그 재건이다 — **삭제 65 단언 · 반전 19 · 신규 몇 · 죽은 코드 414줄.**

**삭제**는 「행동이 사라졌고 대체하는 것이 없다」인 것들이다. 픽스처 D 전체(9)는 P0-1 가드가
**과도하지 않음**을 증명하려고 존재했는데 **과도할 가드가 남지 않았다.** G1 전체(9)는
`plan.moves.size`와 `plan.rekeyedWithValue`를 한 문장 안의 백 배 차이로 구별하려던 것인데
**문장이 없으면 차이도 없다.** G2 전체(9)는 `served` 항을 붙잡고 있었고 — **모집단이 아까워서**
그 인구(`deleteLegendRow`가 남기는, 값이 빈 서버 전송 행)는 버리지 않고 E로 옮겼다.

**반전**은 「행동이 사라졌고 그 **부재**가 이제 계약이다」인 것들이다.

- `clause4/screen-position-re-derived` → **`F8/screen-position-NOT-re-derived`.** F6은 모든 화면
  위치를 다시 유도하는 것을 성공이라 불렀고, **사용자의 말은 그 반대다**(「화면 표기 밀리게
  그냥 보여주기」). 그래서 0이 단언이다.
- `announcement-has-one-number-for-one-quantity` → **`notice-claims-no-cell-moved`.** 불변식 ⑥의
  더 강한 형태 — 한 수량에 한 수가 아니라 **셀 개수 자체가 없어야 한다.**
- `empty-*`의 채택 단언 전부. **빈 타깃이야말로 「아무것도 채택하지 않는다」를 논증하기 가장
  어렵고 그래서 가장 고정할 가치가 있는 자리**다 — 위험한 데이터가 없으니 채택이 공짜로 보인다.
  `phys-NOT-adopted`는 장식이 아니다: 칩 피치와 오프셋이 `getWaferBoundingBox`에 들어가므로
  **물리 규격만 채택해도 저장 좌표가 전부 움직인다.**
- ⚠️ `clause3/grid-opened-at-reference-size`는 **지시서가 삭제하라고 이름을 지목한 것인데
  반전으로 남겼다.** 그것을 통째로 지우면 **이 라운드를 나르는 픽스처 C가 그것을 나르는 단언을
  잃는다.** 「단언이 실제 결정을 표시하면 반전한다」는 규칙을 그대로 적용한 결과다.

**변이 회계: 16 선언 / 16 적용 / 16 전부 「이름 붙은 단언」이 검출 / 크래시 전용 0 / 미검출 0.**
21개는 **자기 단언과 함께 제거**했다 — 남겨 두면 `MUTATION DID NOT APPLY`나 `STILL GREEN`을
보고할 뿐이다.

### 재건이 자기에 대해 발견한 것 셋

1. **M5가 처음 쓴 대로는 STILL GREEN이었다.** 이 경로에 **낡음 가드가 둘 있고 서로
   중복이다** — 어느 하나만 지워도 실행이 조용하다. 어느 쪽도 독립적으로 채점되지 않았다.
   그리고 `frame-untouched`는 **조용히 장식이 돼 있었다** — 이제 아무것도 격자를 리사이즈하지
   않으므로 가드를 지워도 통과한다. `F6/stale/silent`가 이빨을 다시 넣었다.
2. **N2는 크래시로만 잡혔다.** 크래시는 실행을 중단시키므로 **그 뒤 단언이 전부 미채점**이 된다.
3. ⚠️ 신규로 `payload-key-set-unchanged`를 먼저 썼고 **세 픽스처에서 빨개졌다 — 옳게.**
   마스크를 적용하면 **어느 셀이 저장 가능한지가 바뀌는 것이 정상이고, 양방향으로 그렇다.**
   그래서 그 자리에 들어간 것은 마스크 독립인 `stored-coordinates-preserved-total`이다.

### 죽은 코드 414줄 — 닫힌 클러스터였다

`storedCoordRepositionPlan` · `applyStoredCoordReposition` · `repositionRefusalReason` ·
`adoptionCoordinateCost` · `adoptedFrameOf` · `dbCoordsByPhysKey` · `adoptFrameSpec` ·
`announceFrameAdoption`. 심볼마다 **남은 참조가 0인지 먼저 확인**한 뒤 지웠고,
**그중 어느 하나에 대한 코드 참조는 전부 그 여덟 중 다른 하나에서 왔다** — 닫힌 클러스터.

살아남은 것은 `frameDimError`·`frameDimBounds`이고, ⚠️ **`frameDimError`의 근거가 바뀌었으며
주석이 그렇게 말한다.** 옛 정당화는 "채택 1회가 격자 전수 순회 4회를 돈다"였는데 **채택이
없다.** 지금 그것을 지탱하는 것은 둘이다 — `projectCellsToPhys(cells, refFrame)`가 여전히
**참조의 치수로** 프레임 창을 열고 `getWaferBoundingBox`가 그 안을 스캔한다(1024x1024 메타 행
하나면 취소 불가능한 1,048,576칸 동기 루프다); 그리고 이제 더 무거운 쪽인 정합성 절반 —
0·음수·비정수를 기각한다. 그것이 없으면 `gridDimNum`/`parseInt`가 **참조가 선언한 것과 다른
프레임**으로 읽는다.

`reposition_regime_probe.mjs`는 `dbCoordsByPhysKey`를 슬라이스하고 있어 **시작 시점에 던졌을
것**이다. 질문 1·2가 그것을 건드리지 않으므로 **폐기가 아니라 재조준**했다.
