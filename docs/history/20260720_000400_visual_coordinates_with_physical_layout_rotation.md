# 2026-07-20 00:04:00 - 격자 맵 에디터 물리적 회전 렌더링 및 화면 기준 시각 좌표계 보정 일치화

## 1. 개요 및 동기
* **배경 및 요구사항**:
  * 회전(Rotation: 0, 90, 180, 270)이나 앞/뒷면(Side: FRONT, BACK) 전환 시, 웨이퍼의 물리적 형상과 그려진 칩의 배치(Layout)는 정상적으로 회전하고 뒤집혀야(Mirror) 합니다.
  * 그러나 이 상태에서 화면에 보여지는 격자 셀의 라벨 및 데이터베이스에 실제로 저장(Push)되는 `X`, `Y` 좌표값은 **눈에 보이는 스크린 상의 visual 좌표계(가로 X, 세로 Y - 화면 기준 좌표계)로 일정하게 매핑 및 일치**되어야 합니다.
  * 즉, 사용자가 맵을 90도 돌렸더라도, 화면 상의 좌상단(0,0)에 해당하는 칩을 데이터베이스에 적재할 때는 회전되지 않은 원래 물리적 좌표가 아닌, 눈에 보이는 좌상단 `(0, 0)` 좌표로 저장되어야 합니다.

---

## 2. 해결 방안 및 설계 구조

### A. 내부 물리 좌표와 외부 시각 좌표의 이원화 관리 (`client2/src/map_editor.js`)
* **물리 좌표 (`xp`, `yp`)**: 웨이퍼 기판의 절대 위치를 나타내며, `gridData` 딕셔너리의 내부 고유 키로 활용됩니다.
  * `getPhysicalCoords(c, r, cols, rows, rotation, side)` 함수를 복구 및 수학적 3차원 반전/회전식으로 정립하여, 화면 상의 시각적 셀 인덱스 `(c, r)`를 회전각과 앞/뒷면에 대응되는 기판 상의 고정 물리 위치 `(xp, yp)`로 매핑합니다.
  * 이를 통해 회전각 변경 시 칠해진 칩들이 눈으로 보기에 정확한 방향으로 3차원 회전 운동을 수행합니다.
* **시각 좌표 (`xv`, `yv`)**: 사용자가 화면에서 인지하는 픽셀 기준 좌표로, 셀 내부 라벨 텍스트, 호버 상태 가이드 및 데이터베이스에 적재되는 최종 값이 됩니다.
  * `getVisualCoords(c, r, cols, rows, rotation, side, invertY, startX, startY)` 함수를 신설하여, 회전 및 앞뒷면 상태에 구애받지 않고 항상 가로 방향을 `startX + c`, 세로 방향을 `startY + r` (Y반전 시 `startY + (visualRows - 1 - r)`)의 화면 뷰포트 기준 좌표로 변환하여 리턴합니다.

### B. 로드 및 최종 저장 로직 보정
* **적재 시 (`pushMapData`)**:
  * 루프 내에서 각 셀의 값을 가져올 때는 `getPhysicalCoords`로 구한 물리 키를 대조해 칩 데이터를 획득합니다.
  * 데이터베이스의 `x` 및 `y` 컬럼에는 `getVisualCoords`로 구한 화면 기준 시각 좌표를 최종 전달해 저장합니다.
* **불러올 시 (`loadExistingMap`)**:
  * 데이터베이스로부터 불러온 이진 좌표(눈에 보이는 visual 좌표)를 `grid_metadata`에 포함된 회전각/앞뒷면/Y축 반전 정보를 역이용(Inverse Mapping)하여 물리 좌표 `(xp, yp)`로 변환합니다.
  * 변환된 물리 키로 `gridData` 캐시를 채워 넣은 뒤 화면에 렌더링함으로써, 어떤 회전 상태로 저장되었든 상관없이 회전 상태와 맵이 완벽하게 결합되어 자동 복원됩니다.
