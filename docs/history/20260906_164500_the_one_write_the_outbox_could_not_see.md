## 무엇이 일어났나

이 시스템의 다른 모든 쓰기는 SQLAlchemy 의 `before_flush` 를 지나 `database.stage_event`
에 닿는다. 그 훅은 `session.deleted` 를 «걷는다».

```
그런데  대량 `.delete(synchronize_session=False)` 는 행을 «세션에 안 싣는다»
=> 그 목록이 «빈 채»이고, `replace_map` 퍼지는 «이벤트를 하나도 안 냈다»
=> 나중에 「무엇이 갔나」를 물을 것이 «없고», 그래프도 미전달 스윕도 «영영 모른다»
🔴 즉 아웃박스가 «볼 수 없는» 유일한 쓰기였다 — 기준 ④(한 능력에 길 둘)
```

## ⛔ 그리고 퍼지 «자리»가 하나가 아니라 «둘»이었다

판정이 요구해서 이번 라운드에 «세어» 나온 사실이다:

```
diff 갈래     `removed_row_ids`
비-diff 갈래   `purged_row_ids`
=> 둘이 «같은 대량 삭제 셋»을 «각자 손으로» 철자하고 있었다
🔴 «읽힌 쪽»만 고쳤으면 다른 쪽은 «안 보이는 채로» 남았을 것이다
=> 그래서 둘 다 `purge_map_rows` 를 «부른다». 그것이 이벤트를 한쪽에 더하고
   다른 쪽에서 «잊는 일»을 «불가능하게» 만든다
```
🔵 그리고 「`if batch.replace_map:` 자리 넷」 중 «나머지 둘»은 삭제가 «아니었다»
(하나는 퍼지 «범위»를 정하고, 하나는 채택된 행을 «센다») — 세어 보고 뺐다.
