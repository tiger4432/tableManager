> 「클로드.md에 박아 잘라쓰기 하네스 절대금지」

## 🔴 ① 금지의 사유는 「하니스가 약하다」가 «아니다» — 「다른 것을 재고 있다」이다

`640f0961` 이 실패 모양을 «양방향»으로 적었다:

```
import 를 하나 더하면      잘라낸 조각이 그 함수를 못 찾아 «던진다»
const 를 하나 더하면       vm 에서 const 는 컨텍스트의 «속성»이 안 된다 -> 밖에선 undefined
헬퍼를 부르게 바뀌면       그 헬퍼가 「뽑을 목록」에 없어 «던진다»
=> 전부 «코드가 맞는데» 빨개진다.  그리고 «반대도 참»이다 — 틀렸는데 초록일 수 있다
```

## 🔴 ② 그 문장이 «측정»으로 증명됐다 — 그리고 그 측정 자체가 자기를 한 번 정정했다

`bd572260`. 동작을 «전혀» 바꾸지 않는 리팩터 하나를 넣었다 — 모듈 상수 `HTML_ESCAPES`
를 `escapeHtmlAttr` 밖으로 뺐다. 같은 하니스를 전후로 돌렸다:

```

after  (import)     ASSERTIONS 21 0 · OK                            초록
```

🔴 **그런데 첫 프로브는 빨강을 «예측하고» 82/0 초록을 받았다.** 이유가 기록돼 있다 —
그 픽스처는 `&` `<` `>` `"` `'` 를 **한 번도 안 먹여서** 그 상수를 «참조하지 않는다».

```
빨강을 만드는 것은 «잘라쓰기»만이 아니라
   «잘라쓰기 + 경계값을 먹이는 픽스처»다
=> 두 규칙이 «같은 답»을 내는 표본은 판별식이 아니다
   그리고 그 말은, 남은 하니스들의 «전환 가치가 균일하지 않다»는 뜻이기도 하다
```

## 🔴 ④ 개정 하나 — 「덧붙이기는 잘라쓰기가 아니다」 (`d867cb9a`, 22:47)

`ab15f645` 가 하니스 전체를 다시 재고 나서 «금지가 그대로면 일이 안 된다»는 것이 드러났다.

```

그중 «모듈 수준 상태를 «심는» 것»   24 / 30

   모듈 최상단 가변값 47 중 «27개»의 합집합
```

**ESM 으로는 그것을 할 방법이 없다** — 네임스페이스 객체는 봉인돼 있고 `export let`
바인딩은 모듈 «밖»에서 읽기 전용이다. 그러니 「그냥 `export` 를 붙여라」는 앞선 판정은
**24개 하니스가 전보다 «덜 재게»** 만들었을 것이고, 점수 게이트에 걸렸을 것이다.

```
덧붙이기 = 대상을 «바이트 그대로» 복사 -> 마지막 줄 «뒤»에 프로브를 붙임
           -> 원본 옆에 둬서 상대 임포트가 그대로 풀림 -> import -> 삭제
🔴 잘라내는 양이 «0» 이라 금지의 사유가 «하나도 남지 않는다»
```

🔴 **퇴화 방지 장치가 «바이트 단언»이다** (`client2/tests/lib/probe.mjs`):

```
- 헬퍼 «하나». 24개가 각자 만들면 병이 이름만 바뀐 것이다
- assertAppendOnly 가 «바이트»를 비교한다 — 사본은 대상의 바이트로 «시작»해야 하고
  «정확히 그것 + 접미사»여야 한다.  누가 앞부분을 「조금만」 다듬는 것을 «기계적으로»
  알아채는 유일한 장치다
- 표식 __harness_probe__ 가 대상에 «없다»는 것을 매 로드마다 단언한다
- 소스를 «그대로» 돌려주는 mutate 콜백은 점수를 내지 않고 «던진다»
```

`d867cb9a` 가 `CLAUDE.md` 에 예외를 «박은» 이유도 적혀 있다 — 그게 없으면
**다음 세션이 오늘 밤 작업을 «위반»으로 보고 되돌린다.** 그리고 같은 문단이
**그것을 «다리»로, «도착지가 아님»으로** 명시했다.
