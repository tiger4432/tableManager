# 변경 이력: 대량 데이터 로드 시 실시간 진행률 및 다단계 상태 로그 피드백 구현

- **작성일**: 2026년 6월 1일
- **작성자**: Antigravity
- **상태**: 완료

## 1. 개요 및 목적
- 대량의 행(Row)을 로드할 때(특히 `Load All`), 데이터가 완전히 수신되어 그리드에 뿌려지기 전까지 상단 상태 바에 어떠한 실시간 진행 상황도 표시되지 않아 사용자가 화면이 멈춘(Freeze) 것으로 오인할 수 있었습니다.
- 사용자 경험(UX) 극대화를 위해 HTTP Response의 바이트 스트림을 직접 읽어와 **실시간 다운로드 백분율(%) 및 전송 누적량(MB)**을 표기하고, 데이터 다운로드 -> JSON 파싱 -> 그리드 렌더링 단계를 투명하게 시각화하도록 개선합니다.

## 2. 세부 구현 사항

### 프론트엔드 (`client2/src/main.js`)
- **ReadableStream을 활용한 다운로드율 계산**:
  - `loadAllBtn` 클릭 시 `fetch` 응답의 `res.body.getReader()`를 획득하여 실시간 유입되는 청크(`chunks`) 데이터를 순차적으로 수집합니다.
  - 응답의 `Content-Length` 헤더 값을 추적하여 현재 누적 바이트(`receivedBytes`)가 전체 크기 대비 몇 퍼센트(`percent%`) 받아졌는지, 현재 수신 용량은 얼마인지(`receivedMB / totalMB`) 실시간으로 상태 배지(`performanceLog`)에 업데이트합니다.
- **다단계 진행 상황 피드백 분할**:
  - **1단계**: 네트워크 요청 송신 (`⚡ 1/4. Sending network request to database...`)
  - **2단계**: 스트리밍 데이터 다운로드 중 (`⏳ 2/4. Downloading: 45% (3.20MB / 7.11MB)`)
  - **3단계**: JSON 역직렬화 진행 (`⚙️ 3/4. Parsing JSON database payload...`)
  - **4단계**: AG-Grid 셀 생성 및 UI 렌더링 (`🎨 4/4. Initializing cells & drawing grid...`)
- **브라우저 렌더링 프레임 보장 (UI 양보)**:
  - 단일 자바스크립트 쓰레드 구조로 인해 헤비한 JSON 파싱 및 렌더링 연산 도중 UI 상태 텍스트가 강제로 업데이트되지 못하고 씹히는 현상을 해결하기 위해, 각 단계 사이에 `setTimeout` 기반 비동기 양보(`await new Promise(...)`)를 삽입하여 상태 변화 텍스트가 정상 노출되도록 보장했습니다.
- **시간 통계 세분화**:
  - 로드 성공 시, 순수 다운로드 소요 시간(`Down`), JSON 파싱 시간(`Parse`), 그리드 로컬 렌더링 시간(`Render`) 및 전체 총합 시간(`Total`)을 밀리초(ms) 단위로 해부하여 최종 피드백으로 출력하도록 고도화했습니다.

## 3. 검증 결과
- **실시간 변화 확인**: 대량 로딩 시작 시, 상단 로그 배지가 1단계(요청)에서 2단계(다운로드 퍼센티지 실시간 상승), 3단계(파싱), 4단계(렌더링)를 거쳐 최종 통계 배지(✅ 완성!)로 단계별로 매끄럽고 정교하게 갱신되는 것을 검증했습니다.
- **네트워크 비정상 조기 종료 대응**: 데이터 수신 중 오류 발생 시 롤백 및 에러 예외 처리가 안정적으로 작동하는 것을 확인 완료했습니다.
