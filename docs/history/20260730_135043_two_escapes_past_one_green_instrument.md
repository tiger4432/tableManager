# 한 라운드에 green 계기를 두 번 통과했다 — 그리고 기제는 하네스의 **구조**였다

> **일자:** 2026-07-30 13:17~13:50 | **관련 커밋:** `77a2c15` · `e14b1d0` · 보드 등재 `850b9d2` | **담당:** Client PM(구현) · QA(검수) · 총괄(확인)
> **대상:** 계기 자체 — `client2/tests/value_suggest_keys_harness.mjs`
> **기능 항목:** `20260730_132426_f3_suggestion_client_one_enter_is_the_commit.md`

## 왜 이걸 따로 남기나

이 라운드의 하네스는 **좋은 하네스다.** 실제 에디터와 실제 훅을 AG-Grid 키보드
파이프라인의 충실한 모형에 걸어 돌리고, 54 assertion과 19 변이가 전부 잡히고, `prebuild`에
배선돼 있다. 이 항목을 쓰며 HEAD에서 다시 돌려도 `54 passed / 19 APPLIED / 19 CAUGHT`다.

**그런데 같은 라운드에서 결함 넷이 그 계기를 그냥 지나갔다.** 그중 둘은 계기가 최종 상태
(54/19)에 도달한 뒤에 QA가 HIGH로 찾았다. 수가 아니라 **왜 볼 수 없었나**가 기록 가치다.

## 지나간 넷

| # | 결함 | 발견 수단 | 착지 |
|---|---|---|---|
| 1 | 좁히기 스냅샷이 셀 편집보다 오래 살아, 방금 커밋한 값을 다음 셀에서 제안하지 않는다 | **브라우저 E2E** | `77a2c15` 안에서 수리 |
| 2 | teardown이 살아 있는 후계자의 공유 싱글턴(리스트·요청)을 놓는다 | **자기 검수** | `e14b1d0` |
| 3 | `Esc`가 in-flight 요청을 취소하지도, 기각을 기록하지도 않는다 → 늦은 답이 리스트를 되열고 다음 Enter가 **운영자가 치지 않은 값**을 쓴다 | **QA (HIGH)** | 미수리 (`850b9d2` 등재) |
| 4 | 리스트가 아직 열리지 않았으면 같은 `Esc`가 AG-Grid의 cancel로 떨어져 **친 텍스트가 사라진다** | **QA (HIGH)** | 미수리 (`850b9d2` 등재) |

3과 4는 **같은 키다.** 어느 갈래가 나오는지는 90 ms 디바운스 + 네트워크 지연이 결정하고,
**화면에는 두 상태를 구별하는 것이 아무것도 없다** — 9 ms 요청에 스피너를 붙이지 않기로 한
의도적 결정의 귀결이다.

그리고 이것이 HIGH인 이유는 위치다. 그 갈래 위의 주석이 스스로 이렇게 적어 놓았다.

```js
if (key === 'Escape') {
  if (this.listOpen) {
    // Dismiss the LIST only. The typed text stays in the input, so the next Enter
    // commits what the operator actually typed. This is the escape hatch that makes
    // first-match-highlighted safe: ...
```

**설계가 스스로 load-bearing이라고 지명한 경로**가 깨진 자리다.

## 🔴 기제 — 계기가 편한 순간에만 답을 배달할 수 있으면 기각을 시험할 수 없다

QA가 지적한 것은 누락된 케이스가 아니라 **하네스의 구조**다.

```js
async function flush() {
  for (let round = 0; round < 6; round++) {
    const q = timers; timers = [];
    for (const t of q) t.fn();
    for (let i = 0; i < 12; i++) await new Promise(r => setImmediate(r));
  }
}

async function typeInto(g, text) {
  for (const ch of text) { g.key(ch); await flush(); }
}
```

**모든 키 입력 뒤에 `flush()`가 온다.** `flush()`는 남은 타이머를 전부 흘리고 마이크로태스크를
비운다. 따라서 **어떤 응답도 다음 운영자 조작보다 늦게 도착할 수 없다.**

그래서 하네스의 Esc 케이스 둘은 필연적으로 정적(quiescent) 상태만 시험한다.

```js
await typeInto(g, 'TFBGA');   // 여기서 요청이 이미 끝나 있다
g.key('Escape');
...
check('Escape closed the list', results.escListOpen, false);
```

리스트가 **열려 있는 상태**에서 Esc를 누르는 것만 채점된다. 3번(요청이 떠 있는 상태)과
4번(리스트가 아직 안 열린 상태)은 **이 하네스에서 표현 자체가 불가능하다.**

그리고 제품 쪽 가드가 그 사실을 그대로 반사한다.

```js
if (this.destroyed || active !== this) return;
if (result.seq !== requestSeq) return;
if (this.eInput.value !== prefix) return;
```

세 갈래는 각각 **에디터가 사라졌다 · 더 새 요청이 있다 · 그 뒤로 타이핑이 있었다**를 막는다.
Escape는 셋 중 아무것도 바꾸지 않는다. `closeList()`는 DOM만 접고 취소도 기록도 하지 않는다.
**"운영자가 기각했다"는 상태가 애초에 존재하지 않는다** — 그리고 정적 하네스는 그 부재를
관측할 수 없다.

> ⚠️ 이 라운드의 계기는 **한 번의 조작에 하나의 답**이라는 세계를 시험했다. 결함 넷 중 셋이
> 그 세계 밖에 있었다 — 1번은 **셀 경계를 넘는 수명**, 2번은 **두 에디터의 겹침**, 3·4번은
> **답이 늦게 오는 것**이다.

## 같은 스윕이 자기 눈먼 자리를 두 번 보여 줬다 (`e14b1d0`)

역설적으로, **눈먼 곳을 드러낸 것도 같은 스윕이었다.**

- 가드 조건의 이름을 바꾸자 M13의 검색 문자열이 매칭을 멈추고 실행이 `18 of 19 APPLIED`를
  보고했다. **적용되지 않은 변이는 잡힌 변이와 구별되지 않는다** — APPLIED/CAUGHT 분리
  (`cb8f01a`)가 존재하는 이유다.
- M19의 첫 판은 **ESCAPED**했다. 선행자가 건드리지도 않는 인스턴스 플래그 `second.listOpen`에
  단언을 걸었기 때문이다. 손상은 **공유 DOM**에 나므로, 단언이 샌드박스 document에서 리스트
  요소를 읽도록 고친 뒤에 red가 됐다. **엉뚱한 관측 대상을 겨눈 단언은 통과한 단언과 구별되지
  않는다.**

두 사례의 공통점이 이 항목의 결론과 같다 — **계기가 자기가 무엇을 못 보는지는 말해 주지
않는다.** APPLIED/CAUGHT 분리는 "변이가 실제로 코드를 바꿨나"를 물어서 그 침묵 하나를 깼고,
`flush()` 구조가 만든 침묵은 아직 깨지지 않았다.

## 이 라운드가 남긴 판정 순서

```
① 하네스 green (52/18)  → ② 브라우저 E2E가 결함 하나 (셀 경계를 넘는 수명)
③ 하네스 green (54/19)  → ④ 자기 검수가 결함 하나 (두 에디터의 겹침)
⑤ 하네스 여전히 green   → ⑥ QA가 HIGH 둘 (답이 늦게 오는 상태)
```

**green이 세 번 인용되는 동안 결함 넷이 그 아래에 있었다.** 계기는 매번 자기가 시험하는 것에
대해 참을 말했다.

## 그때 남아 있던 것

- **HIGH 둘은 이 시점에 미수리다.** `850b9d2`가 보드에 등재했고, 총괄은 보고서를 믿지 않고
  소스를 직접 읽어 둘 다 확인했다.
- **손상을 막고 있는 것은 `client2/dist`가 커밋되지 않은 상태다.** 그 결정은 **무관한 이유**로
  내려졌다 — 공유 트리에 다른 도메인 둘의 미검수 작업이 있어 번들이 오염됐기 때문이다
  (`77a2c15`). 결과적으로 그것이 이 결함을 운영자 손에서 막고 있고, `850b9d2`는 수리가 착지할
  때까지 `dist`를 미커밋으로 유지한다고 적었다.
- **`REQUEST_LIMIT = 12`가 같은 방향으로 당긴다.** 12는 중간 답을 더 자주 `truncated`로 만들고,
  truncated 답은 캐시되지 않으므로 **대부분의 타이핑에서 요청이 떠 있다.** 그 한계값은
  지연 예산으로 골랐고 두 번째 효과는 인지되지 않았다 — 즉 3번 갈래의 모집단이 설계자가
  생각한 것보다 넓다.
- 하네스는 이 커밋 시점에 `flush()` 구조를 그대로 유지하고 있다. 변이 M4가
  "Escape가 리스트 기각 대신 편집을 취소한다"를 잡지만, 그것도 **정적 상태의** Escape다.
