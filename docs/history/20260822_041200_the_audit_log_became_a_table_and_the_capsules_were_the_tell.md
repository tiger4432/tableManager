## Global 탭이 표가 됐다 — 그런데 «배선은 손대지 않았다»

수백 개 주제에 대한 수백 개 항목을 **하나에 카드 하나씩** 두면 훑기가 스크롤이 된다.
Row 탭은 카드를 유지한다(항목이 적고 주제가 하나이고 읽을 자리가 있다). 그래서 범위는
**`loadHistory`가 Global 탭 컨테이너에만 붙이는 `.audit-table` 클래스** — 탭 핸들러 넷이
아니라 **한 자리가 결정한다.**

🔴 **클릭·펼침·Tx 필터 핸들러가 쓰는 `.timeline-card` · `.tx-tag` · `.filter-tx-btn` ·
`.expand-indicator` 넷의 클래스 이름과 중첩 역할이 전부 살아남았다.** 레이아웃만 바뀌었다.

**목업이 이름 댄 것을 발명하지 않은 자리** 둘이 함께 기록됐다.

```
목업의 종류 7 (MANUAL/PASTE/INGEST/OVERWRITE/BATCH/DELETE/SYNC)
  -> 감사 행은 column_name · source_name · total_count 를 나른다 = 이 파일이 늘 그려 온 6갈래
     나머지 일곱은 «아무것도 계산하지 않는 분류»가 됐을 것
목업의 필터 스트립과 「더 보기」
  -> 감사 필터링이 «없고», historyUrl 이 cell/row URL 만 지어서 전역 라우트에 페이징 경로가 없다
     보고했지 발명하지 않았다
```

걸으면서 자기 결함 둘을 잡았다 — `toLocaleTimeString()`이 이 로케일에서 「오후 11:31:31」을
써서 58px 를 넘겨 **모든 행을 두 줄로** 만들었다. 부품에서 조립해 `23:31:31`로, **어느 기계에서나
같은 폭.** 그리고 앞서 적은 `▶` 클립 결함.

## 종류와 필터는 «있는 데이터»에서 읽는다

`d21fd821`이 필터 스트립을 만들 때 **라이브 분포를 먼저 쟀다** — `source_name`이
`custom_script` 94 · `user` 3 · `web_smart_paste_*.txt` 2 · `system` 1. 그래서 목업이 이름 댄
종류가 **전부 도출 가능**하고 **하나도 발명할 필요가 없었다.**

`OVERWRITE`가 MANUAL/PASTE 를 이기되 **사람 출처일 때만** — 누군가 이미 갖고 있던 값을
바꾸는 것은 **빈 칸을 채우는 것과 다른 행위**다. 옛값이 없던 셀은 MANUAL/PASTE 로 남고,
그래서 **그리드가 「미상」으로 칠하는 행들이 overwrite 가 되지 않는다.**

필터는 **이미 로드된 것 위에서** 돌고, **개수가 정확히 그렇게 말한다** — 「100건 중 98」은
테이블이 아니라 **손에 든 그룹**을 센다. 옵션은 로드된 그룹에서 지어져서, **이 화면이 본 적
없는 출처도 나타나는 날 항목을 얻는다.** 데이터에서 사라진 선택은 **조용히 계속 필터하지 않고
해제**된다.

🔴 **폭 140px 이 첫 값이었고 «측정으로» 틀렸다.** 640px 사이드바에서 옛 `1fr` 대상 열은
**117px 뿐**이라, 140 으로 고정하면 **대상을 키우고 변경 내용을 줄인다** — 지시의 정반대를,
그것이 중요한 폭에서. 110 은 양쪽 폭에서 다 옳다(640: 117→110, 150→157 / 890: 250→110,
150→407). 11px 모노에서 키 폭 중앙값 86 · p90 119 · 최장 165 이므로 110px 는 100개 중
15개를 생략부호로 만든다 — **툴팁 있는 «값»에는 허용, 헤더에는 아님**이 §3.7 폭 규칙이
긋는 구분이다.

## 🔴 알약이 표지였다

> 이 화면의 모든 배지가 `border-radius: 999px` — **캡슐**이었다. 목업에는 **하나도 없다**:
> `.pill` 5px, `.tbtn` 6px(높이 32px), `.kbd` 4px에 2px 아랫변. **캡슐은 상태 점으로 읽히고,
> 5px 사각은 «가장자리 있는 컨트롤»로 읽힌다.**

눈대중이 아니라 **목업 자신의 클래스 정의**에서 읽었고, 헤더 컨트롤이 38/35/33 에서 **일률
32** 로 내려왔다. 범위는 이 화면의 chrome — `.glass-*`는 어드민·맵 화면과 공유라 건드리지
않았다.

## 범위 표시기는 «맵»이 아니라 «사각형»이 몬다

🔴 첫 시도는 `commitDragSelection`에 넣었고 **모든 키보드 선택에서 침묵**했다 —
`extendRangeByKeyboard`는 **일부러 그 맵으로 실체화하지 않는다**(Shift+클릭도 마찬가지이고
주석이 이유를 적고 있다). 두 입력 경로가 공유하는 것은 `dragStartCell`/`dragEndCell`이고
**그건 두 페인터가 이미 받는 것**이라, 작성자 하나가 거기 앉으면 **하이라이트와 어긋날 수
없다.** 키보드 Shift+방향 · 마우스 드래그 · 단일 클릭 해제 셋 다 걸었다.

## 툴바 순서는 CSS `order`가 아니라 «DOM 재배열»

🔴 시각 순서만 바꾸면 **탭 포커스가 옛 순서를 걸어서 키보드가 화면과 어긋난다.**
**순수 치환인지 확인했다** — 전후 616줄, **정렬된 줄 다중집합이 동일**. 이동에서 아무것도
떨어지지 않았다.

거기서 레이아웃 사실 셋이 따라 나왔다 — `.controls-area`가 이제 자란다(전에는 못 자랐고
`space-between`이 그것을 가리고 있었다), `.log-indicator-area`가 `flex: 1`을 그만둔다
(**자라는 형제 둘이 여유 공간을 나눠서, 할 말이 있든 없든 상태 메시지가 절반을 가져가고
칩은 절반만 받았다**), 로고가 14px 이음매와 구분선을 얻는다.

## 미저장 클러스터 — «새로 지은 것이 하나도 없다»

`#tx-pending-badge` · `#tx-apply-btn` · `#tx-discard-btn`이 **이미 있었고** 각자 테두리와
색을 갖고 있었다. 목업이 그것을 **하나의 컨트롤**로 그리므로 변경은 **래퍼 하나, 간격 0,
공유된 바깥 모서리 한 쌍**이다. 새 색 0, 새 버튼 0, 새 핸들러 0.

인라인 `border-radius: 6px` 둘은 `!important`로 싸우지 않고 **버튼에서 떼어 냈다** —
**CSS 가 소리쳐 이겨야 하는 인라인 스타일은 모양을 결정하는 «두 번째 자리»**다.

그룹 자신은 테두리가 없다. 그래서 세 자식이 전부 `display: none`일 때 **완전히 사라진다**
(실측: 대기 편집 0에서 폭 0). 그리고 변경 후 **인벤토리를 실측으로 적었다** — 헤더·⚙️·🧭에
무엇이 남았고 무엇이 조건부로 숨는지. **잃은 것 0.**

⚠️ **시험 위생:** 이 확인에는 Tx Mode 를 켜야 했는데 **그건 소유자의 설정이고 리로드를
넘어 살아남는다.** 다시 끄고, 꺼짐·배지 숨김·대기 편집 0을 확인했다.

## 아키텍처 영향

- 감사 이력의 종류 분류가 **라이브 분포에서 도출**된다 — 목업의 이름표를 그대로 받지 않는다.
- 범위 표시기의 단일 작성자가 **선택 사각형**에 앉았다. 실체화된 셀 맵에 의존하지 않는다.
- 헤더 툴바 순서가 **DOM 순서**로 고정됐다(포커스 순서 = 시각 순서).
