## 배경 — 정적 목업에 맞춰진 원이 실데이터 위에 남아 있었다

지워진 줄 하나가 전부다.

```html
<circle class="me2-wafer-edge" id="me2-wafer-edge" cx="100" cy="100" r="86" />
```

**어떤 JavaScript도 그것을 읽거나 쓴 적이 없다** — 그 id는 트리 전체에서
**마크업 안 한 번**만 나온다. 그것은 몇 줄 위에 있던 **정적 플레이스홀더 목업의
셀 좌표에 맞춰 크기가 정해진** 것이었다.

실데이터는 `layoutFor`가 배치하고 **스테이지를 채운다.** 그래서 격자의 반폭은
**약 99**이고 원은 **86**이다 — **모든 맵이, 언제나, 구조적으로 그 원을
넘친다.** 제품 소유자는 그것을 **유효 다이 맵이 웨이퍼 밖으로 흘러넘치는
것**으로 읽었다.

(`fillRatio 0.87`은 도움이 안 된다 — 그것은 **다이가 자기 셀 안에서 차지하는
비율**이지 격자가 스테이지를 채우는 비율이 아니다.)

## 왜 크기를 다시 맞추지 않고 없앴는가

> **웨이퍼 가장자리처럼 생겼으면서 웨이퍼에 대해 아무것도 모르는 도형은 도형이
> 없는 것보다 나쁘다.** 그것은 운영자에게 **안/밖을 그것에서 읽으라고 초대**하는데,
> 그 판단이 정확히 **마스크가 하려고 존재하는 판단**이다.

지어낸 원에 맞춰 격자를 축소하는 것은 **거짓 주장을 더 설득력 있게 만들 뿐**이다.

마스크 자체는 가질 값어치가 있고 **버려진 게 아니라 보드에 올라갔다** —
`seating.insideMask`가 이미 **진짜 밀리미터**로 그것을 판단한다. phys가 그 맵
**자신의 선언**일 때 원을 격자의 축척으로 그릴 수 있고, 그때 화면은 코드가
뜻하는 것을 뜻하게 된다. **선언된 근거가 없으면 아무것도 그리지 않는다.**

## ⚠️ 이 커밋이 남긴 것 — 생산자 없는 CSS 둘

`client2/src/map_editor2.css`에 규칙 둘이 **생산자 없이** 남았다.

```
.me2-wafer-edge { fill:none; stroke: var(--canvas-wafer-edge); ... }
[data-me2-state="unscorable"] .me2-wafer-edge { stroke-dasharray: 3 4; }
```

커밋 메시지는 둘 중 어느 것도 언급하지 않고, 이 시점 **어느 쪽에도 휴면
표시가 없다.** `--canvas-wafer-edge` 변수도 남아 있다. 17분 뒤 `6f0a328`이
그 상황을 **부분적으로** 이름 붙인다.

## 그때 남아 있던 것

- 화면에는 이제 **웨이퍼 경계가 없다.** 마스크가 생기기 전까지 안/밖은 화면에서
  판단되지 않는다.
- 지워진 자리에 **왜 지웠는지를 적은 7줄 한국어 주석**이 들어갔다 — `r="86"`,
  `layoutFor`, `반폭 ≈99 > 86`, `seating.js`의 `insideMask`를 이름으로 댄다.
