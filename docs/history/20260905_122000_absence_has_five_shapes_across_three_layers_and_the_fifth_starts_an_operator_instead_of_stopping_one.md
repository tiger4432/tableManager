## 🔴 ② 다섯이 «한 축»이 아니다 — 무엇이 거짓말하는지가 다르고, 그래서 고치는 «층»이 다르다

이것이 이 부류에서 나온 가장 값비싼 문장이다. 넷을 세었을 때는 「같은 병의 네 철자」로
읽혔는데, 다섯째를 붙이자 **한 축이 아니라는 것**이 드러났다.

```
①②③  «읽은 값»이 거짓말한다          ->  고치는 자리는 «그리는 쪽»
④     «쓴 값»이 거짓말한다            ->  고치는 자리는 «만드는 쪽»
                                       (빈 칸을 못 만들어서 이름을 «지어냈다»)
⑤     «값은 맞는데» 읽는 사람이 틀린다  ->  고치는 자리는 «옆에 한 칸 더»
```

`c9fabb62` 는 그것을 「세 개는 사실을 «들고 있으면서» 안 내놓고, 넷째는 «지어낸다» —
그래서 수리가 «반대 방향»으로 간다」고 적었다. 접힌 사실 셋을 「하나로 묶어서」
처리하려던 계획이 **둘 + 하나**로 갈라진 것이 그 자리다.

## 🔴 ④ 다섯째는 «다른 질문»에 답한다 — 그래서 앞의 넷에 못 합친다

```
①~④ 의 판별식   「이 0 이 «어디서» 왔나」   (출처)
⑤   의 판별식   「이 0 을 «채울 수» 있나」  (가능성)
                 ✅ 채울 수 있다 -> ①~④ 중 하나. 「없다」와 「못 읽었다」를 가르면 된다

```

⚠️ **다섯째는 이날 «명세»로만 존재했고 코드로 착지하지 않았다.** 격차 탐지기의 화면은
`29f97e0e`(14:21)에서 클라 레인에 넘어갔고, 그 화면이 그려졌다는 기록은 이 시점에 없다.

## 착지한 것 — 부류가 이름을 얻기 «전»에 고쳐진 것들

### 갈래를 «세어서» 늘렸다 (모양 ①)

`917ef469` 가 두 갈래를 셋으로, `7673ebd0` 가 셋을 넷으로 늘렸다. 넷째가 필요했던 이유가
기록되어 있다 — **「세어서 0」과 「한 번도 안 세어짐」이 같은 픽셀이었다.**

```
① 계기가 보고되지 않았다      ② 집계가 실패했고 «사유»를 말한다
③ 수 자체가 «도착하지 않았다»  ④ 수가 «도착했고 0» 이었다
```
`7673ebd0` 의 문장: `measured_cells` 없이 도착한 통계가 「사람이 고친 셀 없음」이라고
말하고 있었다 — **아무도 보내지 않은 수에 대한 주장.**

### 길이를 «그리지 않는 것»으로 답했다 (모양 ①)

`d594c2aa`. 재실행에는 `retroactive_runs.total_rows` 가 NULL 인 행이 «실재»한다.
0% 막대는 「거의 끝난 것」에 대해 「아무것도 안 일어났다」고 말한다.

```
막대는 «길이»다  ->  수가 없으면 그릴 것이 없다  ->  컨테이너를 «안 그린다»
퍼센트 칸       ->  «대시»
완료 판정도 «안 한다» — 지어낸 0 을 100 에 견주는 것은 «반대 방향의 같은 거짓말»이다
```

### 색은 «진술»이 아니다 (모양 ②)

`500c276d`. `restartable` 플래그는 내내 도착하고 있었고 독자가 «하나»뿐이었는데,
그 독자가 그것을 **테두리 색**으로 바꿨다. 운영자가 두 번째로 누르기 전에 알아야 할 것
— 재실행이 중복을 만들지 않는다 — 이 **어디에도 말해지지 않았다.**

세 상태다. 플래그가 «없으면 아무것도 안 그린다» — 아무도 안 보낸 불리언에 대해 어느 쪽
낱말을 써도 그건 «지어내는 것»이기 때문이다.

### 닫힌 목록의 멤버가 «하나»면 그건 값이지 고르는 것이 아니다 (모양 ⑤의 사촌)

`a1eaee50`. `occurred_at_basis` 는 멤버가 «정확히 하나»로 출하된다
(`setup_bundle._OCCURRED_AT_BASES`, 표의 CHECK 제약도 같은 말). 그 드롭다운은
**아무것도 할 수 없다** — 그리고 화면에서 그것은 «고장 난 드롭다운»과 구별되지 않는다.
둘은 **반대 수리**를 원한다.

🔴 고침이 «한 경로»가 아니었던 것이 요점이다 — 닫힌 목록을 그리는 자리가 «둘»이었고
(후보가 게시 목록과 정확히 일치하는 계획 행, `schema[node.list]` 를 읽는 스켈레톤 잎),
**한쪽만 고치면 나머지가 «이미 고쳐진 것»처럼 보인다.** 판단이 `closed_list.js` 로
옮겨가고 두 자리가 그것의 «선언»이 됐다 — 쓰기 주소만 다르다.

```
네 상태다. 「도착 안 함」과 「비었음」은 «다른 것»이다:
   schema 는 fetch 가 오기 전까지 {} 이고, 그것을 「멤버 없음」으로 읽으면
   fetch 가 걸리는 «내내 모든 목록이 비어» 보인다
```

⚠️ 그리고 «조임»이 하나 보고됐다 — 멤버 하나가 «값»인 것은 «문서가 이미 그 값을 들고
있을 때뿐»이다. 빈 문서에서는 그 picker 가 값을 쓸 수 있는 «유일한 길»이라, 없애면
새 소스가 `occurred_at_basis` 를 선언할 수 없다.

### 거절이 «선택 뒤»에 오고 있었다 (모양 ⑤에 가장 가까운 착지)

`e1e67c13`. `missing_relations` 는 내내 돌아오고 있었고 클라가 그 라우트를 «0회» 불렀다.

## 🔴 총괄이 자기 종결을 «되돌린» 자리 — 레인이 «스스로 말한 맹점»으로 항목을 닫았다

`89022847`. 클라 레인이 「네 탭 밖에 거짓말하는 0 은 0건」이라 보고하면서 **같은 보고서에
자기 방법의 한계**를 적었다 — 렌더에서 «멀리» 있는 가드는 자기가 훑은 코드 모양과
일치하지 않는다. 총괄이 그 한계를 «경계»로 기록하고 항목을 닫았다. 그러자 **응용 레인이
탭을 열어 그 자리를 찾았다.**

```
🔴 레인이 「내 방법은 이걸 못 본다」고 적으면
   그건 «판정»을 요청하는 문장이 아니라 «다른 계기»를 요청하는 문장이다
   — 그리고 그때 다른 레인이 그 계기를 들고 있었다
```

그리고 같은 정정에서 **상관관계 하나가 죽었다.** 응용 레인은 「부재 부품을 임포트하는
파일 여섯」이라 보고했는데 실제는 «둘»이었고 `ABSENCE_WORDS` 는 소비자가 «아예 없었다».
더 결정적인 것 — 이것을 **맞게** 하는 함수 `renderEffort` 는 **그 부품을 안 쓴다.**
맞는 이유는 «네 갈래로 갈리기» 때문이다.

```
=> 결함은 «부품 소속»이 아니라 «갈래 수»였다
   그리고 결함 있는 함수는 맞는 함수에서 «서른 줄» 떨어진 같은 파일에 있었다:
   renderRecorrection 은 「응답이 이 필드 없이 왔다」 갈래가 없어서
   부재 문장을 찍었고, «읽지도 않은» 7일 창을 리터럴로 달고 있었다
```

## 아키텍처 영향

- 부재 표기의 판단이 **갈래 수**로 잡힌다 — 「부품을 쓰나」가 아니라 「몇 갈래로 갈리나」.
  이날 넷으로 늘어난 자리가 둘(`917ef469`·`7673ebd0`), 셋으로 선 자리가 하나(`500c276d`).
- 닫힌 목록의 규칙이 **`client2/src/closed_list.js`** 한 곳에 산다. 그리는 두 자리가
  그것의 «선언»이고, 이 커밋 시점에 `oe-field-select` 가 뷰 모듈에서 **0회** 나온다
  (하니스가 그 수를 붙들고 있다).
- 진행률 부품이 **길이 없음 = 안 그림**을 답한다. 파일 적재는 항상 수를 보내므로 렌더가
  그대로다.
- `missing_relations` 라우트에 **부르는 화면이 생겼다** — 이 커밋 시점 기준.
