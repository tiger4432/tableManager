## 무엇이 일어났나

`dt_map_derivation.join_rule(db, name)` 이 규칙 이름 «둘»을
`virtual_join.config.load_verified_rules` 에 물어 풀고 있었다. 1단계가 읽기 시점 조인을
은퇴시켰고 4단계가 그 패키지를 지우므로, 이제 **통합 체인 선언**에 묻는다.

```
읽는 법   ingestion_worker.read_rules_document()  +  rule_shape.expand_declaration
          = 로더가 쓰는 «그 판사»(S-244). 둘째 읽기를 만들지 않는다
유일성    chain.join_key_index.unique_index_covering  (:254)
          오른쪽 키·접기는 join_into.right_key (:243) 가 계산한 것 «그대로»
          -> 선언마다 한 번이 아니라 «카탈로그 질의 한 번». 어느 쪽도 캐시가 아니다
안 바뀐 것 `mapper_sdk.MAPPER_SURFACE` 의 «모든 이름», 그리고 돌려주는 dict 의 «키»
```

**새 어휘가 필요 없었다.** `join_key` 와 통합 선언의 `on` 은 같은 모양이고 `right_table` 은
같은 이름이다. 판단이 필요한 칸은 `expose` 하나였고, 그것은 `take` 의 **`from`** 쪽이다 —
`expose` 는 «오른쪽 표에서 SELECT 되는» 컬럼 이름이고, `into` 는 그 값이 왼쪽에서 «앉는» 이름이다.

## 🔴 이 라운드가 «자기 오류 둘»을 찾아냈다

```
① 계수가 «한 칸» 짧았다
   이 모듈이 읽는 칸 넷을 셌는데, MAPPER_SURFACE 가 같은 dict 를 «소유자 맵퍼»에게 넘기고
   거기서 `_matching_join_rule` 이 `left_table` «도» 견준다.
   빼먹어도 «아무것도 안 났다» — 비교가 그냥 안 맞고 재방문이 «0 행»을 유도했다.
   기존 시험 둘이 빨개져 잡았고 `left_table`·`left_columns` 가 dict 로 돌아왔다
② 내가 쓴 갈래 하나가 «도달 불가»였다
   `enabled: false` 를 따로 거절했는데, `expand_declaration` 은 꺼진 선언에 «아무것도 세우지 않는다».
   그 갈래로 갈 수 있는 입력이 없다. 지웠다
```

## 변이 여섯 — 다섯은 잡히고 «하나가 살아남아» 게이트를 강화했다

```
잡힘   take.into 를 읽기 · left_table 빼기 · 유일성 질문 빼기 · virtual_join 으로 되돌아가기
🔴 살아남음   조회를 `startswith` 로 느슨하게 해도 «초록»
              이유: 정확히 그 이름의 규칙이 «먼저 오기» 때문 — 순서가 비교의 일을 하고 있었다
              한 선언이 규칙 «둘»(`<name>` · `<name>:reference`)을 세우고 params 가 «같으므로»,
              접두 일치는 «틀린 쪽»에서 관문을 조용히 풀 수 있었다
✅ 새 시험: 이름이 «더 긴» 규칙만 선언해 두고, 짧은 이름이 «거절»되기를 요구한다
```
📌 **운(「그 규칙이 먼저 온다」)을 문서로 적지 않고 게이트를 세웠다.** 그게 이 항목의 모범이다.

## 시험 픽스처가 «둘째 저자»를 그만뒀다

종전 픽스처는 로더 대신 서서 정규화된 산출물을 «손으로» 지었다 — 진짜 로더라면 «거절했을»
모양을 만들 수 있는 자리였다. 이제 `read_rules_document` 로 **파일 항목**을 주고
`expand_declaration` 이 세운다.
