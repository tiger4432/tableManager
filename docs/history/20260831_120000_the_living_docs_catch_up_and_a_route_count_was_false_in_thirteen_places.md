## 🔴 ② 한 수가 열세 자리에서 거짓이었고, 새 라우트 하나가 «한꺼번에» 반증했다

원장 «읽기» 라우트가 **둘**이라고 문서 **열세 자리**에 적혀 있었다.
결측 라우트(`5cf5197f`)가 착지하면서 그 열셋이 **동시에** 거짓이 됐다.

```
권위 있는 자리   수를 «정정»했다
사본들          수를 «지웠다»  <- 다시 적지 않았다
이유            방금 «열세 자리»에서 낡은 수는 «또» 낡는다
```

`BACKFILL_GUIDE` 가 가장 많은 거짓을 이고 있었다 — **「그 화면은 아직 없다」는 절과
「없음」으로 나열된 항목 둘**, 그런데 **셋 다 이미 착지해 있었다.**

그래프 서사는 **「사라졌다」가 아니라 «되돌릴 수 있는 선» 둘레로** 쓰였다 —
기존 표는 컬럼을 유지하고, 1단은 아직 안 만들어진 표만 바꾸며, 44개 표 삭제는 판정 전이다.
**그 문장은 그 레인이 어느 쪽으로 가든 참으로 남는다.**

지나가다 발견해 고친 것: `auto_register_map_meta` 가 소유자 판정으로 true → false 로 뒤집혔는데
(→ `20260830_143900_...`) **네 자리가 옛 기본값을 가르치고 있었고, 그중 하나는 QA 절차에서
«반대 결과»를 단언**하고 있었다.

## ④ 런타임 계약이 «대화 채널»에 살고 있었다

`a004bd00` → `b456a52b`. `APPLICATION_GAP_SPEC` 은 **결측 라우트가 그것과 어긋나면 거절하는**
파일이다 — 즉 **런타임 계약**이다. 그런데 **레인 채널**(`task/`) 에 살고 있었고,
채널 파일은 **자라고 잘리는 대화 기록**이다.

```
docs/spec/ 로 «옮겼다» — 소유권은 그대로
내용은 «바이트 동일» (길이 · 다이제스트 같음)
task/ 에는 «포인터»를 남겼다 — 코드와 지시서에 이미 적힌 경로가 «여전히 풀리도록»
```
🔴 **`server/` 밑 네 파일이 여전히 옛 경로를 적고 있다.** 그것은 구현자 소관이고,
포인터가 그때까지 매달림(dangling)을 막는다.
