# 한 로트, 두 철자 — 그리고 꺼진 채로 출하된 접기

> **일자:** 2026-08-04 오후 | **관련 커밋:** `92b8d6f`(1단계 구현) · `75a61cf`(센서스 질의 추적) · `090c74a`(운영자 가이드) · `7cea7fe`(선언이 판정을 아직 못 따라왔음을 기록) · 보드 `b069a25`
> **담당:** 사용자(요청 8 「WF 표기 정규화 + `slot`은 항상 int」) · 총괄(판정 순서 변경) · server 구현
> **대상:** 신규 `server/notation_norm.py` · `server/config/notation_rules.json.sample` · `server/database/crud.py` · `server/main.py` · `server/config_resolve_report.py` · `server/scripts/rederive_notation_norm.py` · `server/scripts/wf_spelling_census.sql`
> **⚠️ 이 항목은 `92b8d6f` 시점의 사실이다.** 아래에 서술된 「파생 컬럼에 저장한다」는 모델은 **1단계이고, 이 커밋 시점에 이미 그 일부가 다른 기제로 은퇴하고 있었다**(아래 「7b가 규칙 하나를 재사용으로 은퇴시켰다」 절). 현재 상태로 읽지 말 것.

## 배경 — 조인이 알 방법이 없었다

WF/로트 표기가 섞인 철자로 들어왔다(`CL-2601-001` vs `CL_2601_001`). 필터와 조인이
**한 로트를 조용히 둘로 쪼갰다.** 아무도 에러를 보지 못한다 — 결과가 적게 나올 뿐이다.

여기에 앞선 판정 하나가 순서를 바꿔 놨다. 요청 7의 답이 「`_`는 `lot_*` 접두 스캔이
목적」이었으므로, **0패딩보다 `_` 제거가 접두 스캔을 살리는가**가 먼저다.

> 표기 정규화는 규약을 **바꾸는** 일이 아니라 **규약이 성립하게 만드는** 일이다.

## 수리 — 접기는 쓰기 경계에서 돌고, 결과는 파생 컬럼에 남는다

`notation_norm.fold_notation`이 쓰기 경계에서 실행되고 결과가 **파생 컬럼**에 앉는다.
**원본은 다시 쓰이지 않는다.** 그리고 그것은 단언이 아니라 **거절 셋**으로 강제된다.

| 로더가 거절하는 것 | 그것이 막는 것 |
|---|---|
| `derived == raw` | 파생이 원본을 덮어쓰는 선언 |
| 파생 컬럼이 **업무 키 안에** 들어가는 선언 | 정체성이 접기 규칙에 종속되는 것 |
| `zero_pad`를 **이름으로** | 아래 절의 이유 — 이미 다른 층이 한다 |

그리고 **`"columns": {}`로 불활성 출하**한다. 어떤 컬럼을 접을지는 **운영자의 판정**이다.

7b 위에 얹는다 — `fold_notation(canonical_key_value(raw, type), rules)`.
**한 어휘, 두 층.** `canonical_key_value`를 다시 서술하지 않는다.

## 못 돌리던 센서스가 돌았고, 결과가 깨끗했다

이것이 이 라운드에서 가장 값진 부분이다. **접기가 존재하자 확인 비용이 읽기 전용
스크립트 하나로 떨어졌다.**

| 컬럼 | 병합군 |
|---|---|
| `dt_log.core_lot` | 철자 **30 → 15**, 15개 군 **전부** 같은 로트의 구분자 쌍(`CL-2601-00x` / `CL_2601_00x`) |
| `dt_lot` · `core_slot` · `core_wafer_map.core_lot` · `bonding_log.*` · `lot_event.lot` | **0** |

즉 규칙은 **신고된 그 컬럼 말고는 전부 no-op**이고, 두려워하던 false merge는
**실측상 없다.** 규칙을 정하기 전에 실측한다는 규율이 여기서 값을 냈다.

`75a61cf`가 그 센서스 질의를 추적 대상으로 넣는다 — 보드가 사용자에게 그 파일을
가리키고 있었는데 **파일이 저장소에 없었다.** 그 스크립트는 구성상 읽기 전용이다:
모든 문장이 단일 `SELECT`, 임시 테이블 없음, 단계 간 트랜잭션 상태 없음 — 그래서
각 단계를 **따로 붙여넣을 수 있다.** 앞선 정리 스크립트가 임시 테이블을 써서
**클라이언트가 첫 에러에서 멈추자 나머지가 통째로 안 돌았던** 전례가 있다.

## 7b가 규칙 하나를 재사용으로 은퇴시켰다 — 그리고 선언이 아직 안 따라왔다

「`slot`은 항상 int」는 접기 규칙을 하나 더 만드는 문제가 **아니었다.**
7b의 `canonical_key_value`가 `number` 컬럼에 대해 **이미 0패딩을 제거한다**
(`'01'`/`' 1 '`/`1.0` → `'1'`). 그래서 답은 **타입 선언 하나**다.
`zero_pad`를 이름으로 거절하는 세 번째 거절이 그 판정의 코드판이다.

그런데 `7cea7fe`가 그 문장을 실측에 대 봤고, **문서 쪽이 앞서 있었다.**

> 샘플과 모듈 docstring은 「slot은 항상 int이므로 0패딩 문제는 은퇴했다」고 적혀
> 있었다. 라이브 `table_config` 실측: `dt_log.core_slot` · `dt_log.dt_slot` ·
> `core_wafer_map.core_slot` · `bonding_log.bond_slot`이 **전부 오늘 `string`으로
> 선언돼 있다.** 그러므로 `'01'`과 `'1'`은 **합쳐지지 않고**, 은퇴는 아직 효력이 없다.
> **판정은 실재한다 — 뒤처진 것은 선언된 타입이다.** 두 텍스트가 그렇게 고쳐졌고,
> 고칠 것은 타입이지 `zero_pad`의 구현이 아니라고 명시했다.

같은 커밋이 docstring의 다른 실수도 고쳤다 — 수식에 **호출 대상(callee)의 이름**을
적어 놔서, 실제로 임포트되는 심볼(`canonical_bind_value`)로 grep하면 호출부가
**하나도 안 나왔다.**

## 가이드가 예시의 실제 반환값을 싣는다

`090c74a`가 운영자 가이드를 낸다. 접기가 **꺼진 채로** 출하됐는데 **켜는 법을 적어
둔 곳이 없었다**는 것이 그 커밋의 이유다.

모든 JSON 예시를 `notation_norm.validate_notation_rules`에 **실제로 먹여 반환값을
싣는다.** 그렇게 해서 샘플이 말하지 않던 것 둘이 드러났다 — `zero_pad: true`와
알 수 없는 규칙 이름은 **주변 선언을 버리지 않는다.**

켜는 것은 **두 층이 아니라 세 층**이다: `table_config`가 물리 컬럼을 선언 →
이 파일이 쌍을 선언 → `display_columns`가 그릴지 말지를 결정.
설정된 14개 테이블 전부가 `display_columns`를 선언하므로 **기본은 안 보임**이고,
CSV 추출은 `column_types`에서 만들어지므로 **그리드를 넓히지 않고도 접기를 검사할 수
있다.**

## 그때 남아 있던 것

- **파생 값을 읽는 것은 아직 아무것도 없다.** `.sample`이 `"columns": {}`이므로
  선언 없이는 아무 일도 일어나지 않는다.
- **2단계는 config 플립이 아니라 데이터 마이그레이션이다.** `wafer_map_metadata`
  행들이 **원본 철자로 등록돼 있어서**, `canonical_map_key`가 정규화 값을 읽기
  시작하는 순간 기존 `map_id`가 전부 자기 meta 행과 어긋난다.
- **접기가 조인 양쪽에 대칭이 아니다** — `dt_log.core_lot`은 병합군 15인데
  `core_wafer_map.core_lot`은 **0**이다. 한쪽만 정규화하면 매칭이 조용히 사라진다.
- 이것은 체인 규칙으로 만들지 않았다. 매퍼는 `.py.sample`로 gitignore된 디렉터리에
  출하돼 **도착 즉시 죽고**, `trigger == target`은 `dt_log`의 모든 쓰기를 두 배로 만든다.
- 테스트 23건. 결함 주입 3회 실행 — 항등 접기 → 9 적색, 무동작 파생 → 5 적색,
  `derived == raw` 거절 제거 → 1 적색.
- `7cea7fe`가 가이드를 쓰다 발견한 것 둘을 보드에 남겼다: `/schema` 호출 한 번이
  **표준 파서가 적재 필터로 쓰는 라이브 `display_columns` 목록에 시스템 컬럼을 영구히
  덧붙인다**(N18), 그리고 **「선언했는데 물리 컬럼이 아직 없다」를 말해 주는 곳이
  아무 데도 없다** — 쓰기가 예외도 로그도 없이 조용히 아무 일도 안 한다(N19).
