# 「무엇이 «부르나»」는 「무엇이 «닿나»」와 다른 술어다 — 직접 매칭은 한 홉 모자랐고 고정점은 아니다

## 배경 — 소유자가 「지우지 말고 안 보이게」를 요구했다

`8fc0a996`. 고아 모듈 여섯이 `server/_archive`로 갔다 — 자기 자신만 임포트하던 chain_mapper
무리, examples 패키지, `audit_changeset`, `enrichment_actions`.

**호출 자리가 아니라 «임포트 자리»로 세고 나서 옮겼다** — 그날 아침 개명이 walk 을 깰 뻔한
자리에서 갈렸던 바로 그 구분이다. 전부 0. 그리고 **서버가 다시 뜨고 walk 이 같은 노드·엣지·
자재 아홉을 답하는 것**이 이동의 유일한 증명이다.

## 🔴 수집이 «세 에러»로 멈춰서 4,268이 하나도 안 돌고 있었다

`05a0f10a`. `pytest tests/`가 수집 단계에서 끊겨서 **아무것도 안 돌았다.** 모듈이 옮겨간
시험 파일 셋을 함께 옮겼다(23 + 3 + 21 = 47).

🔴 **그리고 게이트 ②가 안 맞았고, 판정이 「진행하지 말고 보고하라」였다:**

```
기대   4,268 - 47 = 4,221
실측   4,268   — 이동으로 안 바뀜
```

**그 47은 애초에 4,268 «안»에 없었다.** 앞선 줄이 「4268 collected, 3 errors」였는데,
**수집 중 던지는 파일은 collected 에 0을 기여한다.** 그러니 그 셋은 이동 전에도 0이고
이동 후에도 0이다. 47은 실재하지만 **빼려던 총계 안에 있던 적이 없다.**
정직한 기대는 **4,268 그대로**이고 스위트가 보고하는 수가 맞다.

## PG 스킵 — 그리고 「6 skipped 를 이 상자에서는 «볼 수 없다»」

`4609b886`. 아카이브된 모듈을 **본문 안에서** 임포트하는 시험 여섯에 `pytest.mark.skip`을
달았다(이유 문자열에 아카이브 경로를 넣어 되살릴 주소를 남겼다). 헬퍼는 안 건드렸다 —
스킵된 시험은 헬퍼를 안 부르고, 지우면 되살리기가 두 단계 작업이 된다.

```
실측   1 passed, 37 skipped, 0 failed, 0 errors, in 0.25s
기대   skipped 6
```

파일에 시험이 32인데 **먼저 발화하는 두 번째 스킵 조건**이 있다 —
`ASSY_PG_TEST_DATABASE_URL`이 이 상자에 없으니 PostgreSQL 이 필요한 시험은 전부 스킵된다.
32개 시험에 37 스킵이면 파라미터화된 케이스다. **내 여섯은 그 안에 있고 세어서는 분리할 수 없다.**
그래서 **정적으로** 확인했다 — 내가 쓴 이유 문자열이 정확히 여섯 번 나타난다.

## 🔴 그런데 «일곱 번째»가 있었다 — 내 방법이 결함이었지 내 주의가 아니었다

`34b0f5d6`. `test_chain_mapper_schema_failure_writes_no_atom_and_does_not_move_cursor`는
`chain_mapper`를 **한 번도 이름 대지 않는다.** `_rebuilt_mapper_registry()`로 들어가고
임포트는 **그 안에** 있다.

> **내 방법이 결함이었다.** 모든 `chain_mapper` 언급을 감싸는 함수에 대응시켰다 —
> 그건 **직접 사용**에는 정확하고 **한 홉 모자란 질문에 답한다.**
> 도달은 **이행적**이고, 「부른다」는 「거기 간다」와 **같은 술어가 아니다.**

계측기를 교체했다:

```
파일을 최상위 함수 본문으로 파싱한다
씨앗: 자기 본문이 chain_mapper 를 임포트/속성으로 이름 대는 함수 전부
반복: 오염된 함수를 «부르는» 함수를 더한다 — 변화가 없을 때까지
끝: 이름이 test_ 로 시작하는 오염된 함수를 보고한다
```

```
chain_mapper 를 만지는 헬퍼   ['_rebuilt_mapper_registry']  — 판정대로 «하나»
그것에 «닿는» 시험            7
그중 표시된 것                7
게이트 ③ 닿는데 표시 안 된 것   0
```

**고정점은 한 홉 모자랄 수 없다. 직접 매칭은 그럴 수 있고, 그랬다.**

## 아키텍처 영향

- 고아 모듈 여섯이 `server/_archive`로 갔다. **`_archive/`는 수집 경로 밖**이고, 직접 겨누면
  여전히 에러가 난다 — 그게 맞다(그것이 재는 모듈이 sys.path 가 아니라 그 옆에 있다).
- 시험 수집이 다시 돈다. `pytest tests/ --collect-only` 에 Interrupted 도 에러도 없다.
- 되살릴 주소가 **스킵 이유 문자열 안에** 있다.

## 그때 남아 있던 것

- 이 상자에는 `ASSY_PG_TEST_DATABASE_URL`이 **없다.** PG 스킵과 내 스킵이 **한 수 안에 섞여
  있고 세어서 못 가른다.** 정적 확인이 그 자리를 대신한다.
- 「4,268 − 47」이라는 게이트 수치는 **재 보지 않은 수였고**, 그 때문에 레인이 맞는 결과를
  보고 멈출 뻔했다.
