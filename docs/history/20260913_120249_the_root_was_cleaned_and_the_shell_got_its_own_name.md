## ① 규칙을 골라도 폼이 «항상 비어» 있었다 (S-212 `3bdab11c`, 11:09)

```
화면이 보내는 것   GET /admin/chain/rules/raw?name=<규칙>     client2/src/admin.js :1120
                 패널 선언 `nameKey: 'name'` · POST 페이로드 키도 `name`
뷰의 인자         chain_rule_raw_view(name)
GET 라우트만      `rule` 을 선언                              <- 여기가 어긋난 «한 낱말»
```
🔴 **FastAPI 는 «모르는 쿼리»를 떨굽니다.** 그래서 뷰가 `chain_rule_raw_view(None)` 을 받았고,
체인 탭에서 고른 규칙이 폼을 **항상 빈 채**로 남겼습니다 — **아무것도 던지지 않았습니다**.
표 절반이 돌던 것은 양쪽이 둘 다 `table` 을 말했기 때문입니다.
🔵 수리는 «둘째 받는 키»를 더하는 것이 아니라 **라우트 개명**이었습니다 — 한 낱말, 한 철자.
⚠️ **종전 라우트 시험이 이걸 못 본 이유가 이 항목의 값이다** — 그 시험들이 라우트를 태우되
«서버의 낱말»(`params={"rule": …}`)로 불렀습니다. 📌 부류:
**핸들러가 치는 것을 그대로 치는 시험은 «이음새»를 못 찾는다.** 새 시험은 «클라 쪽 철자»로만
채점합니다(`?name=X` 가 X 를 채우고, `?rule=` 은 이제 아무것도 안 채웁니다).

## ② Qt 셸의 폴더가 «감싸는 창»의 이름을 얻었다 (S-211 ③ `e3a21b31`, 11:51)

```
종전   client/   <- 웹 앱은 `client2/` 인데, 그 앱을 «감싸는» 창이 `client/` 였다
오늘   desktop/
```
🔴 **이 폴더의 소비자는 import grep 에 «하나도 안 보입니다».** 그래서 이름 옮기기가
「작은 일」이 아니라 게이트가 필요한 일이었습니다:
```
런처      run_decoupled_app.py 가 셸을 «자식 프로세스»로 띄우는 «경로»
라우트    /api/download/client :642 · /api/desktop/download :664 — 거기서 «빌드된 것»을 내려준다
.gitignore  네 줄(추적 `.spec` 을 다시 들이는 `!` 예외 포함)
산문      그 폴더의 package_client.py + 살아 있는 문서 여덟
```
⚠️ **그래서 import 검사 전건이 초록인 채로 데스크톱 창이 «조용히 안 열릴» 수 있었습니다** —
그 자식은 `restartable=False` 이고, 그것이 프로세스가 죽는 «가장 조용한» 모양입니다.
🔵 오늘 철자는 **프로세스당 하나**입니다 — `run_decoupled_app.DESKTOP_DIR` :36 ·
`main.DESKTOP_DIR` :639. 런처의 경로는 `desktop_shell_path(root_dir)` :39 가 만듭니다(:351 이 부른다).
🔵 **그 헬퍼가 있는 이유는 «물어볼 수» 있게 하기 위해서입니다** — `main()` 은 포트를 거절하고
스키마 드리프트를 보고한 «뒤에야» 명부를 짓기 때문에 시험에서 부를 수 없고, 소스 텍스트에
단언하면 «없는 폴더를 가리키는 런처»에 대해서도 참이 됩니다.
