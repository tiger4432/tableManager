## ① 이미 재고 있던 사실이 «로그 문장 안»에 갇혀 있었다 (`f8bbdf47`)

`QueueHeadWatch` 는 `SYSTEM_RELOAD` 가 맵퍼 모듈을 다시 import 한 시각을 **정체 감시가
착지한 이래로 계속 기록해 왔다.** 그런데 그것이 나가는 방식이 문제였다:

```
나가던 모양   한 문장 «안»의 «텍스트» — 「last mapper reload 42s」
나가던 시점   큐 머리가 «이미 1분 이상 막힌 뒤»
=> 그것이 답하는 질문(「상태가 «데이터»가 아니라 «이 프로세스의 모듈 캐시»에 있나」)을
   «이미 선 시스템의 로그를 읽고 있는 사람»만 물을 수 있었다
```

**새로 재는 것은 없다.** 큐 화면이 **이미 읽는** 레지스트리가 같은 호출 자리에서 같은 시각을
받아 가고, `GET /admin/chain/queue` 가 그것을 큐 깊이 «옆»에 발행한다.

### ⚠️ 값이 «둘»이고, 한 번도 재적재 안 했으면 `null` 이다

```
한 시간 떠 있으면서 «한 번도» 재적재 안 한 루프  ≠  «한 시간 전»에 재적재한 루프
그리고 `0` 은 「방금」으로 읽힌다 — «정반대» 사실이다
=> 가동 시간과 재적재 나이는 «짝»으로만 「재시작이 이걸 지우나」에 답한다
```

`QueueHeadWatch` 는 자기 사본을 **일부러 유지한다** — 결함은 그것이 «유일한» 사본이었다는
것이다. 시험이 **두 호출이 «같은 재적재 자리»에 앉는지**를 단언한다.
**라우트가 못 읽는 곳에 값을 착지시키는 것은 커밋 메시지만 길어진 같은 결함**이기 때문이다.

## ② 없는 표 이름이 «있는 이름»으로 말해지고 있었다 (`de5b51e3`)

```
`database_outbox.table_name` 은 «관례상» 비지 않는다
그래서 소급 실행(단일 표가 «없는» 행)이 자리를 채우려고 `__retroactive__` 를 싣는다
큐 화면이 그것을 «대기 중인 트랜잭션이 건드리는 표» 목록에 «올려서» 그렸다
=> 운영자가 «아무도 만든 적 없는 표»를 찾으러 간다.  그 헛걸음이 이 결함의 «비용»이다
```

🔴 **이건 「사실이 없다」가 아니라 「없음을 «이름»으로 말한 것」이다.**

고침은 **읽는 쪽**에 있다 — 행은 이미 자기가 무엇인지 말한다(`event_type` 이
`RETROACTIVE_RUN` 이고, 같은 묶기가 `event_types` 를 이미 모은다).
새로 만드는 것이 하나도 없고, **읽는 쪽이 자리표시자를 «이미 다른 이름으로 들고 있는 신원»으로
착각하는 것을 멈춘다.**

## 🔴 ③ 그런데 «부류»가 한 멤버 넓었다 — 7분 만에 뒤집혔다 (`2742446f`)

`de5b51e3` 은 **「이것이 통제 이벤트인가」**로 걸렀다. 낱개(`__retroactive__`)로 맞추지 않고
부류로 판정한 것은 옳았는데, **그 부류가 틀렸다.**

```
SCHEDULER_RUN_NOW 는 «통제 이벤트»이면서 «호출자가 준 진짜 표»를 싣는다
=> 필터가 «참인 이름»을 지웠다
=> 운영자가 막힌 트랜잭션을 보면서 「어느 표에 대한 온디맨드 실행인지」를 «잃는다»
   그리고 `event_types` 는 그 답을 «들고 있지 않다»
```

**총괄이 요구한 단언으로 잰 것이 그대로 커밋에 남았다:**

```
    assert group["tables"] == ["dt_map"]
    E  assert [] == ['dt_map']
```

### 부류가 «결함 그 자체»로 옮겨갔다

```python
#: 🔴 EVERY NAME IN THAT COLUMN THAT IS NOT A TABLE, and this declaration IS the
#: statement "these are not tables".
PLACEHOLDER_TABLE_NAMES = frozenset({RETROACTIVE_RUN_TABLE})
```

```
쓰는 쪽   `retroactive.RUN_EVENT_TABLE` 이 «그 선언에서» 읽는다
읽는 쪽   `main.py` 가 «그 선언을» 묻는다
=> 쓰는 쪽과 읽는 쪽이 «써졌지만 인식되지 않는 자리표시자»로 «어긋날 수 없다»
⛔ 읽는 쪽에 리터럴은 여전히 «없다». 다음 자리표시자는 «선언 한 줄»이고 이 자리는 안 고친다
   — 하나 «더해서 사라지는지» 보는 시험이 그것을 못 박는다
```

앞 커밋의 단언 넷은 «유지»됐고 둘이 더해졌다(진짜 표를 든 통제 이벤트 · 살아 있는 부류).
그리고 **이벤트 타입 파라미터화는 «버려졌다» — 틀린 부류를 단언하고 있었기 때문이다.**

## 아키텍처 영향

- 재적재 시각이 **큐 응답의 값**으로 산다. 가동 시간과 «짝»이고, 한 번도 없으면 `null` 이다.
- 「표가 아닌 이름」이 **한 곳에 선언**돼 있고, 그 선언 자체가 문서다.
  `retroactive.RUN_EVENT_TABLE` 이 그 선언에서 읽는다.
- 🔴 **「부류로 판정한다」가 «옳은 부류인가»를 보장하지 않는다**는 사례가 이 저장소에 남았다.
  `de5b51e3` 은 규칙으로는 맞았고(낱개 아님) **외연이 틀렸다.**
