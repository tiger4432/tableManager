## 배경 / 왜

사용자(제품 오너)와의 협의에서 제품 정체가 재정의됨. 기존 SSOT는 그리드/테이블을 **최종 산출물**로, 핵심 가치를 기술 메커니즘(레이어링·이력·실시간)으로 서술했다. 그러나 실제 목적은:

- **전산 인프라가 취약한 R&D 현장**의 데이터 관리.
- 그리드는 목적이 아니라 **불완전한 현장 데이터를 사람이 최소 공수로 교정하는 표면(Correction Surface)**.
- 궁극 목적지는 **온톨로지/지식 그래프** — 교정된 진실이 그래프에 반영되어 객체(예: 불량 WF) 선택 시 연관 공정 이력이 전부 추적되는 것.
- 로그 형태가 다양 → **파서 관리**, 데이터 종류가 방대 → **체인 관리**가 시스템 수명·품질을 좌우.
