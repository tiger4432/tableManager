# A defect's class is a claim

**Date:** 2026-08-14 09:47 · **Domain:** 아키텍처(분류) · **Status:** 기록만 — `51f3119`

---

void와 defect가 분류를 얻었고, 소유자의 표현이 곧 설계다: **class 컬럼이 아니라
class에 대한 주장.**

- 도구가 스캔 시각에 분류한다 — 같은 `observed` 발화에 페이로드 필드로 실리고,
  값 집합은 kind별 닫힌 집합.
- 사람이 나중에 이미지를 보고 반대한다 — 원 관측에 **이벤트 참조로 핀된** 별도
  `classified_as` 주장. 관측에는 런 간 정체성이 없으므로 원자 참조가 「어느 것을
  말하는지」의 정직한 표현이다.
- 해소는 레이어링 값의 적용: 등록 우선순위로 사람의 말이 도구의 말을 이기고, 분쟁은
  contested로 렌더되며, **분류 이력 전체가 살아남는다.**

경계는 유지된다: 무엇인가(what-it-is)는 주장이고, 통과 여부(whether-it-passes)는
여전히 절대 저장되지 않는다.

## 그때 남아 있던 것

- 문서만이다 — 이 시점에 어휘 등록도 코드도 없다. `classified_as`는 선언 상태로
  남았고, 당일 `1ddb937`이 등록기(registry)의 `classes` 선언 수용·검증을 먼저
  착지시키며 «양쪽 관측 표 모두 class 컬럼이 없다»를 측정해 `classes: []`가 스텁이
  아닌 측정값임을 기록했다.
