## 배경

참조 뷰와 작업 목록에 **정렬도 필터도 없었다.** 둘 다 이제 AG-Grid이고,
**옵션 객체 하나를 공유하되 닮음이 아니라 *객체 동일성*으로 단언**한다 —
**한 화면의 두 그리드가 *거의* 같게 동작하는 것은 그 자체로 함정**이기 때문이다.

## 클라이언트 측이라는 전제를 **믿지 않고 쟀다**

| | |
|---|---|
| 서버 페이지네이션 | **작업 목록만**, 버퍼 1,000 |
| 라이브 큐 | **120행 · 4행** |
| 참조 뷰 최대 | **72행** |

**부분적으로 도착하는 것이 없으므로 서버를 거칠 필요가 없었고, 정렬 키도 라우트도
하나도 안 건드렸다.**

## 🔴 출하될 뻔한 결함 하나

> **표시(displayed) 위치에서 계산한 삽입 인덱스를 행 *데이터*를 인덱싱하는 API에
> 먹이고 있었다.**
>
> **아무것도 정렬할 수 없는 동안에는 동일했고, 정렬이 존재하는 순간 틀렸다** —
> **그 기능이 첫 사용에서 자기 버그를 만들었을 것이다.**

## 잘림 표시는 잘림이 **실재할 때만** 뜬다

작업 목록 메타가 **몇 행이 버퍼됐는지** 말하고, **버퍼가 진짜로 서버 총계에 못 미칠
때만** 서버 총계를 이름 댄다.

⚠️ **내 지시서에 대한 정정 하나: 참조 뷰에는 잘림 플래그가 *없고 오늘 가질 수도
없다*.** 감싸기가 **plus-one 없는 맨 LIMIT**이라 **서버 자신이 「정확히 상한」과
「잘림」을 구별하지 못한다.** **그래서 그 패널은 추측하는 대신 잘림에 대해 아무 말도
하지 않는다.**

**모든 행을 숨기는 필터**는 예전에 **축하 오버레이 옆에** 떨어졌다. 이제 그렇다고 말하고,
**개수가 필터가 몇 개를 숨기고 있는지** 말한다.

## 기본값이 아니라 **일부러** 내린 판단 둘

- **메인 그리드의 관례를 재사용하되 그 모듈을 임포트하지 않는다** — 임포트하면
  **기본값 하나 때문에 메인 앱 그래프 전체를 이 페이지로 끌고 온다.**
- **두 패널 다 컬럼 타입으로 갈리지 않고 숫자 인식 비교기를 단 텍스트로 필터한다** —
  **어느 패널에도 타입 출처가 *없다*.** 작업 목록의 컬럼은 규칙 메타데이터에서 오고,
  참조 뷰의 SQL은 **조작자가 작성**한다. **마침 도착한 행들에서 타입을 짐작하는 것이
  두 그리드를 어긋나게 만드는 바로 그것이다.**
