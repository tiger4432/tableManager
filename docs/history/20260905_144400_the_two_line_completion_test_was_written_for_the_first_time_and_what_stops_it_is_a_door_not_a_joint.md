## 배경 — 완성의 정의가 «총괄만 판정할 수 있는» 정의였다

`CLAUDE.md` 의 완성 조건은 2026-08-30 에 소유자가 정했다:

```
「운영에서는 <이 표>에 <이 칸> 을 적으면 됩니다」   <- 두 줄 안. 스키마 이름은 «빈칸»
```

이날까지 그 두 줄이 **한 번도 실제로 쓰인 적이 없었다.** 판정은 매번 총괄이
「됐다/안 됐다」로 했다. `e82c3a6f` 가 그 자리를 이렇게 적었다 —
**총괄만 평가할 수 있는 완성의 정의는 정의가 아니다.**

그래서 지시는 「마디를 더 닫아라」가 아니라 **「세 마디가 닫혔다고 «치고» 두 줄이 어떻게
읽히는지 실제 문장으로 써라」**였다. 낙관 금지, 이 상자의 컬럼 이름이 들어가면 «실패»로
보고하라는 조건이 붙었다.

## 마디 셋 — 두 개가 이날 착지했다

### 마디 1 — 「적어 둔 값」이 아니라 «세어서 낸 값» (`113752bc`, 12:44)

`prepare.implementation_id` 와 `map.implementation_id` 는 **목록도 기본값도 없는 필수
자유 텍스트**였다. 소스를 하나 작성하려면 `declarative-role` 을 **아무 데도 없는 곳에서
타이핑**해야 했다.

```
이건 «도메인 질문»이 아니다 — 운영자가 «답할 수 없는» 질문이다
그리고 이 프로젝트의 완성 시험이 «멈춰 있던 자리»가 정확히 여기다
```

🔴 요점은 기본값이 «있다»가 아니라 **«세어서» 나온다**는 것이다.

```
목록    레지스트리에서 온다 — 이 서버가 «선언한» 준비기 둘 · 맵퍼 셋
기본값  «건네받은 소스들에서 세어» 낸다. 어디에도 «적혀» 있지 않다
        -> 다른 배치의 소스를 건네면 «다른 답»이 나온다.  리터럴은 가질 수 없는 성질이다
counts  기본값 옆에 «무엇을 세어서 나온 값인지»가 같이 나간다
        -> 「기본값」이라는 낱말을 «믿지» 않아도 된다
```

거절 «둘»이 의도적이다 — **동률이면 기본값이 없다**(깨면 증거가 아닌 축이 답을 정한다),
**빈 선언에도 없다**(「목록에서 고르십시오」가 정직한 결과다). 그리고 등록된 구현은
전부 고를 수 있게 남는다 — 출하 소스 «둘»이 다수파가 아닌 것을 쓰고 있고,
**그 둘이 이 필드가 존재하는 이유**다.

### 마디 3 — 문장이 «요구»하는 대신 화면이 «잰다» (`9983f5c8`, 14:14)

`/columns` 는 부르는 곳이 **0** 이었다. 탐색기는 라우트 셋을 읽었고 그중
「정렬 기본값이 참인가」에 답하는 것은 없었다.

```
read.order_by 는 table_config.json 이 «유일하다고 선언한» 최단 키를 받는다
   -> 선언은 «틀릴 수» 있다.  출하된 복합 키 «하나»는 «빈 컬럼 셋»이었고
      아무도 재 보지 않은 채로 그것이 «추천»이 됐다
column_stats 는 그것을 «내내» 재고 있었다
```

🔴 그리고 **다섯 상태**가 됐다 — 지시서는 넷이라고 했다. 다섯째가 서버의 산술에서 나왔다:

```
unique  =  rows == combinations and rows > 0
=> «빈 표»는  unique: false 에 중복 0 을 돌려준다
   그대로 그리면 운영자 앞에 「아무것도 충돌 안 하는데, 유일하지 않다」가 뜬다
   그리고 그 둘은 «반대 행동»을 원한다 — 컬럼을 바꾸기 vs 데이터를 «먼저 넣기»
```

주석이 붙는 자리를 **경로 접미사가 아니라 «서버가 찍는 근거»**(`ordering_default_from_catalog_key`)에
매달았다 — 기본값이 옮겨 가면 주석이 «같이» 옮겨 간다. 화면이 「어느 경로가 무슨 뜻인가」의
두 번째 지도를 «갖지 않는다».

⚠️ 그리고 이것이 **첫째 줄에서 한 마디를 «지웠다»** — 「주어를 가리키는 칸은 유일해야
한다」를 문장이 «요구»하지 않아도 된다. **화면이 그 자리에서 «재서» 답하기 때문이다.**

### 마디 2 — «조건부»로 남았다

두 필드를 선언에서 «빼는» 일이 측정 대기 상태였다. `3588fa02` 가 그것을 **낙관하지 않고**
적었다 — 나가면 두 줄이 그대로이고, 안 나가면 둘째 줄에 마디가 하나 는다:
「…그리고 준비기가 «무엇을 내놓는지» 정확히 옮겨 적으십시오」.

「그다음 선언에서 <그 표>를 고르고 술어 하나를 골라, 그 셋을 «주어 · 시각 · 목적어»에 짝지으십시오」

## 🔴🔴 그런데 «한 자리»에서 막혔다 — 그리고 그것은 마디가 아니었다

```
막히는 자리   둘째 줄의 「선언에서 <그 표>를 «고르고»」
왜          🔴 «새» 소스는 폼에서 «시작이 안 된다»
            작성 계획이 「문서가 «이미 가진» 것」을 걷기 때문에,
            빈 선언에는 «그릴 줄이 없다»
소유자가 하실 물음   「그래서 «어디서» 고르나」
```

🔴 **마디와 문은 다른 것이다.**

```
마디  「무엇을 «적나»」의 문제        -> 셋 다 닫아도
문   「적을 «칸이 나타나나»」의 문제   -> 이 문은 «안 열린다»
```

`e8598abc` 가 그것을 이렇게 판정했다 — 넷째 마디가 «아니다». 그리고 운영자 여정이
**반대편에서 같은 말**을 한다: 그 여덟 걸음이 **전부 「선언이 이미 있다」를 전제한다.**
3단계 «앞»의 걸음이 목록에 없다.

### 이것이 안 보였던 이유가 기록됐다

```
🔴 재던 사람이 «전부 이미 선언을 갖고 있었다». «빈 선언에서» 시작한 사람이 아무도 없었다
```

## 아키텍처 영향

- 구현 선택지의 목록이 **레지스트리**에서 오고, 기본값이 **건네받은 소스에서 세어져** 나온다
  (`server/ledger/implementations.py`). 순수 함수다 — 이 커밋 시점에 **읽는 것이 없다**.
- 탐색기가 **`/columns`(`column_stats`)** 를 부른다. 관계마다 «한 번» 묻고 캐시하며,
  실패도 캐시한다. **전체 표 스캔 비용**이라 키 입력이나 재렌더에 절대 안 실린다;
  실패는 그 행을 «사유와 함께 모름»으로 표시하지 재시도하거나 비우지 않는다.
- 조인 선언의 «승인 여부»가 화면에 나온다(`432c77ce`) — `/admin/config/resolve` 가
  답하던 「유효한가」와 **다른 질문**이고, 그 답과 **DDL** 을 들고 있던 둘째 라우트는
  **부르는 곳이 0** 이었다.
- 완성 판정의 «주체»가 총괄에서 소유자로 옮겨갈 수 있는 문장이 **처음 존재한다.**
