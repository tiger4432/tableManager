# 변경 이력: Delete 키 입력 시 행 삭제 대신 범위 선택 영역 셀 내용 비우기 구현

- **작성일**: 2026년 6월 1일
- **작성자**: Antigravity
- **상태**: 완료

## 1. 개요 및 목적
- 기존 웹 클라이언트(`client2`) 그리드에서 `Delete` 키를 입력했을 때 선택된 행 자체가 영구 삭제되는 거동은 데이터 유실 우려가 컸으며 일반적인 스프레드시트 사용 경험과 상충되었습니다.
- 이를 일반적인 엑셀(Excel)과 유사한 거동인 **"선택 범위 영역 내의 셀 내용 비우기"**로 대체합니다.
- 단일 셀 뿐만 아니라 마우스 드래그를 통한 다중 범위 영역(Range Selection) 내의 셀들을 효율적인 단일 배치 API 호출로 일괄 제거하여 사용자 편의성과 데이터 무결성을 보장합니다.

## 2. 세부 구현 사항

### 프론트엔드 (`client2/src/main.js`)
- **키보드 단축키 바인딩 변경**:
  - `keydown` 이벤트 리스너 내 `Delete` 키 트리거 동작에서 기존의 `deleteSelectedRows()` 호출 대신 새로 추가된 `clearSelectedCells()` 함수를 호출하도록 수정했습니다.
  - 텍스트 박스 또는 텍스트 에어리어 등 실제 텍스트 편집기 안에서 `Delete` 키를 입력하는 편집 중 상태(`isEditing === true`)일 때는 문자 삭제 거동이 보존되도록 예외 처리했습니다.
- **셀 비우기 비동기 함수 구현 (`clearSelectedCells` 신설)**:
  - **선택 영역 감지**: 드래그 범위 정보(`dragStartCell`, `dragEndCell`)가 존재할 경우 전체 범위 인덱스를 추출하고, 범위가 없는 경우 포커스된 단일 셀을 갱신 타겟으로 자동 폴백 처리합니다.
  - **읽기 전용 컬럼 보호 가드**: `created_at`, `updated_at`, `row_id`, `id` 등 테이블 메타데이터 및 행 번호 컬럼(`#`)은 지우기 처리 대상에서 안전하게 제외했습니다.
  - **타입 기반 초기값 설정**: 각 컬럼의 스키마 타입에 따라 수치형(`number`) 데이터는 `null` 값으로 변환하고, 그 외의 문자열(String) 타입 등은 `""` 빈 문자열로 매핑하여 저장 유형 불일치를 미연에 방지합니다.
  - **배치 업데이트 API 연동**: 전송 효율 극대화를 위해 각 행 단위의 업데이트 목록을 모아 단 한 번의 `/tables/{table_name}/data/updates` (PUT) 배치 엔드포인트 요청으로 전송합니다.
  - **로컬 그리드 즉시 동기화**: API 성공 응답을 수신하면 클라이언트 페이지 캐시(`pageCache`)를 클리어한 뒤 AG-Grid의 로컬 로우 데이터를 `applyTransaction({ update: rowsToUpdate })` 형태로 즉시 변경하여 새로고침 지연 없이 화면에 반영되도록 최적화했습니다.

## 3. 검증 결과
- **단일 셀 지우기**: 그리드 포커스 상태에서 `Delete` 키를 누르면 해당 셀의 내용만 깔끔하게 제거되고 로컬 수정 마크(오렌지색 하이라이트)가 즉시 표기됨을 확인.
- **다중 드래그 범위 셀 지우기**: 2x4 형태 등 복수의 셀 범위를 드래그하고 `Delete` 키를 입력 시 대상 영역 내 모든 일반 비즈니스 셀의 정보가 일괄 비워짐을 확인.
- **시스템 필드 보호 검증**: 행 ID나 날짜 컬럼 등 읽기 전용 필드는 `Delete` 키를 입력해도 데이터가 변형되지 않고 안전하게 유지됨을 검증.
- **배치 전송 검증**: 여러 행에 결친 다량의 셀 값 일괄 삭제 시 하나의 트랜잭션 호출(GeneralUpdateBatch) 형태로 정합성 있게 동작하고 변경 이력이 Audit Log에 정상 적재됨을 확인 완료.
