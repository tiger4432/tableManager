# 뿌리에 전용 트랙이 생겼고, 쓰기 경로 레인은 단위 테스트로 통과하지 못하게 됐다

**날짜:** 2026-08-11 17:41~17:48 · **커밋:** `920c343` `d311694` · **레인:** 문서(총괄 소관)
**측정 상자:** 새 문서에 실린 수치는 전부 이 워크스테이션의 격리 스택 것이다.
**운영이 아니다.**

## 배경

하루 동안 성능 조사 넷과 감사 둘이 착지하며 **수십 개의 결함**을 냈다. 그것들은 수십 개의
사고가 아니었다 — **소수의 설계 결정이 드리운 그림자**였다. 증상을 하나씩 고치면 같은
계급이 다음 주에 다른 이름을 달고 돌아온다.

`docs/architecture/ROOT_DEFECTS.md`가 그래서 열렸다. **이 파일은 `PROJECT_STATUS.md`와
같은 이유로 총괄 전담이다 — 여기 들어가는 것은 서술이 아니라 판정이다.** 이 히스토리
항목은 그 파일을 서술만 하고 건드리지 않는다.

## 네 개의 뿌리 (이 커밋 시점의 이름: `R1`~`R4`)

```
R1  쓰기 경로에 거절 어휘가 없다
R2  선언이 실재와 대조되지 않는다
R3  파생 상태가 무효화 프로토콜 없이 박제된다
R4  소비자의 배치 키가 생산자의 표식이다
```

**R1** — `apply_batch_updates`는 「성공」을 말하거나 raise할 수 있고,
「당신의 키 1,000개 중 900개를 받았고 버린 것은 이것들이다」를 담을 **타입이 없다.**
그래서 모든 부분 실패가 **터지거나 거짓말하거나**를 골라야 하고 일관되게 거짓말을
골랐다. 이것이 제품의 **첫 번째 가치를 정면으로 친다** — 조용히 일어나지 않은 교정은
최소공수교정의 반대다. 오늘 인시던트의 처음부터 끝까지가 이것이다.

**R2** — 컬럼 이름이 config·매퍼·자유 SQL·DDL·클라에 선언되고 **아무것도 그것들을 서로
또는 DB와 대조하지 않는다.** 총괄이 오전에 이것을 R1에 접었고 **그게 틀렸다**:
R1은 깨졌을 때 **말하는가**이고 R2는 행이 하나라도 쓰이기 **전에 대조하는가**다.
**R2 하나만으로 `dt_job` 대 `dt_job_id`를 한 행도 쓰기 전에 잡았을 것이다.**
가장 싼 수리이자 예방 가치가 가장 높다.

**R3** — 표시값을 `cell_sources`에서 계산해 행에 `setattr`한다. **낡았다고 말할 방법이
없는 캐시**다. 존재하는 유일한 계측기가 전체 재계산이고, 그 재계산이 아웃박스를
재스테이징하며 체인을 다시 깨운다(10,000행 ≈ 72분으로 측정).

**R4** — `transaction_id`가 「이건 저 파일에서 왔다」는 뜻으로 붙고 「이만큼을 한 그룹으로
처리하라」는 뜻으로 읽히는데, **두 읽기 사이의 계약을 아무도 소유하지 않는다.**
2차 체인 드레인, R3의 직렬화된 N그룹, 한 번도 세팅되지 않은 collapsed 모드가 전부
이것이다.

## 문서를 살려 두는 절

§5는 **뿌리가 아닌 것**을 나열한다 — upsert 회귀, 중복 인덱스, 검색 와일드카드,
아웃박스 힙, WAL 투영, 16배 승수. **모든 것을 뿌리로 받아들이는 근본원인 문서는 태어나는
순간 죽는다.**

16배는 특히 낭비가 아니다. 실측하면 **컬럼 수와 정확히 같고**, 레이어링은 네 번째 제품
가치다. 결함이 아니라 **후보로** §6에 앉는다.

§6은 정직한 공백도 적는다: **조사 넷은 전부 SQL과 CPU만 쟀다.** Python·pydantic·직렬화는
제외됐고, 코드 주석 하나가 직렬화를 그리드 요청 하나의 **72%**로 놓는다.
**아무도 재지 않은 층에 다섯 번째 뿌리가 있을 수 있다.**

그리고 §0의 운영 규칙 — **증상의 상태는 측정이 바꿀 때만 바뀐다. 산문이 바꾸지 않는다.**

## 인수 기준이 올라갔다 (`d311694`)

사용자가 기준을 올렸다. **쓰기 경로·인덱스·공유 함수를 건드리는 것은 세 라이브 경로를
실제로 돌려서 검증한다.**

```
① 격리 환경 브라우저에서의 실제 셀 편집
② 체인 매퍼를 실제로 돌게 만드는 쓰기
③ 인제션 워처를 통과하는 파일 한 개
```

이유가 이 프로젝트가 반복해서 값을 치른 결함 계급이다. **실패 모드가 「부분 실패가 200을
반환」일 때, 수리한 사람이 직접 쓴 단위 테스트는 가장 약한 증인이다** — 그것은 저자의
시스템 모델을 단언하는데, **틀린 것이 바로 그 모델**이었다. 셋은 더 넓은 스모크 테스트가
아니라 **오늘의 인시던트를 만들어 낸 바로 그 셋**이다.

같은 논지가 인덱스 은퇴 레인에는 **반대쪽에서** 적용된다. 스캔 카운트는 **표본 창 동안
실제로 돈 쿼리에 대한 진술**이다. 이 세 경로는 매일 돈다. 그중 하나가 「죽었다」고 판정된
인덱스를 조용히 쓰고 있는 것이 정확히 그 판정이 틀어지는 방식이고, **회복 비용이
비대칭**이다 — 드롭은 빠르고 큰 운영 테이블에서의 재구축은 그렇지 않다.

지금(리뷰 게이트로 나중에 들지 않고) 네 레인에 전달한 이유: **설계를 다 마친 뒤에 인수
기준을 배운 레인은 그 기준을 위해 만들지 않고 증거를 소급 조립한다.**

기준의 마지막 문장이 이 라운드에서 가장 이식성이 높다 —
**「연습되지 않은 경로는 말하면 허용된다. 보고서에서 그냥 빠져 있는 것은 아니다.」**
