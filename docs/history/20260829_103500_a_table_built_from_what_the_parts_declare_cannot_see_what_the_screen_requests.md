# 부품이 «선언한 것»으로 만든 표는 화면이 «요청하는 것»을 못 본다 — 그리고 옮겼다가 되돌린 좌석 하나

> **커밋:** `ffd12e59` (10:16) · `0ebed31e` (10:25) · `397bc3e5` (10:35)
> | **일자:** 2026-08-29 오전
> **레인:** 클라(R&D 보드)
> **측정 상자:** 이 워크스테이션. **운영이 아니다.**

## 배경 — 자재 예산을 «부품이 켜는» 라운드였다

전날 밤 `continues`가 선언이 되면서(→ `20260829_045900_...`), 자재를 따라 걷는 걸음에
**별도 예산**을 주는 배관이 서버에 생겼다. 남은 것은 **어느 부품이 그 예산을 얼마나 쓰나**를
선언하는 일이었다.

## ① 예산은 «부품마다» 선언됐고, 곁다리 호출 하나가 좌석 예산을 «물려받고» 있었다

`ffd12e59`. 자재를 따라가는 부품 넷이 예산을 선언했다 — 구성은 **2홉**(코어 위에 코어가
쌓이면 한 층이 보인다), 칩 확대는 **1홉**(관측의 주어에 닿으려고 `bonded_from` 만 쓴다).
맵과 트렌드는 관측만 따라가므로 **아무것도 선언하지 않는다.**

```
머리 요약의 종류별 웨이퍼 사실   continues_hops=2 로 «나가고 있었다»
그런데 그 호출이 따라가는 술어   inspected · observed · of_kind  = 관측 전용
=> 좌석이 선언한 예산을 «곁다리 호출»이 물려받았다. 명시적으로 껐다
```

**부품 단위로 선언한다는 말은 「좌석에 적으면 그 좌석 것 전부에 걸린다」가 아니다.**
같은 좌석 안에서도 걷는 술어가 다르면 예산도 달라야 한다.

## 🔴 그리고 게이트 하나가 «닫히지 않았다» — 200 은 아무것도 증명하지 않았다

같은 커밋의 정직한 기록. 파라미터가 실제로 살아 있는지는 확인했지만, **효과는 못 보였다.**

```
파라미터가 «파싱되나»   -1 · 99 · abc  ->  «422»  (ge=0 le=40 에 걸린다)
파라미터가 «먹히나»     라이브 선언의 술어 «13» 중 continues 표시된 것 «0»
                      -> 쓸 데가 없으니 노드 수는 어느 쪽이든 «3»
```
🔴 **「200 이 왔으니 읽혔다」가 아니다.** 이 라우트는 **모르는 파라미터를 조용히 무시**하므로
200 은 「받았다」와 「파싱했다」를 구별하지 못한다. 그래서 **범위 밖 값**으로 둘을 갈랐다.
샘플 선언은 그날 여섯을 얻었고(`1162d002`), 라이브 선언은 소유자 파일이라 건드리지 않았다.

## 🔴 ② 실측 표를 «좌석 선언»으로 만들었더니, 선언이 없는 좌석이 통째로 빠졌다

`0ebed31e`. 라운드 ⓪ 이 스스로 적은 문장이 틀렸다 — **「걷기 요청 셋이 전부 방향을 나른다」고
썼는데 실제로는 넷이었고 하나가 안 날랐다.** 더 나쁜 것은, 그 뒤에 **「방향 없음: 1」을 직접
재고도** 쫓지 않고 다음 라운드로 넘어간 것이다.

그리고 그 자리는 **지시서가 지목한 둘 중 어느 것도 아니었다.**

```
loadWaferFacts   머리 요약 소속인데, 라운드 ⓪ 이 이미 방향을 준 좌석이다
optionsFor       control-bar 가 아니라 «트렌드 선언» 좌석에 묶여 있다
=> 이 둘은 선언이 «아무것도 없어서» walkHere 가 «맨 걷기»다
   그래서 좌석 «선언»으로 만든 표에는 «한 번도 안 나타났다»
```

🔴 **원인은 「경로를 좁게 훑었다」가 아니라 「표의 재료를 잘못 골랐다」다.**
부품이 **선언한 것**으로 표를 만들면, 선언이 비어 있는 자리는 **표에서 사라진다.**
표는 **화면이 «요청하는» 것**으로 만들어야 했다.

코드를 읽어 추론하는 것이 **세 번 틀려서**, 디스패처에 임시 프로브를 넣어 좌석 이름과
실제 스펙을 한 번 읽고 **되돌렸다.**

같은 커밋에서 control-bar 가 방향을 선언했다. 주석이 «왜»를 들고 있다:

```js
// 🔴 방향을 «선언»합니다 (라운드 ⓪ 보완, 2026-08-29). 이 좌석의 걷기는 선언 목록이
//    아니라 «부품 배선» 안(`optionsFor('y')`)에 있어서 1차에서 안 잡혔습니다 --
//    실측 표를 좌석 «선언»으로만 만들었고, 화면 요청으로 대조하지 않은 제 잘못입니다.
//    실측: both 400노드·절단 nodes,claims  ->  outgoing 251노드·절단 «없음».
//    Y축 «종류 목록»을 만드는 자리라, 잘린 표본에서 고르면 「그런 종류가 없다」로
//    보입니다. 오늘은 종류가 하나뿐이라 목록이 같지만, 둘째가 오는 날 갈립니다.
direction: 'outgoing',
```

수: 로드 시점의 맨 걷기 **1 → 0**, 요청 수는 **8 로 불변**. 마킹 아래에서는 맨 걷기 하나가
남는데 그것은 `reach` 이고, **일부러** 선언하지 않은 것이다 — 어느 쪽이든 한 홉이 그 부품이
묻는 질문 자체이기 때문이다.

🔴 **종류 목록은 오늘 «1 로 같다»** — 원장에 종류가 하나뿐이라 절단이 아직 물지 않는다.
고칠 이유는 **둘째 종류가 오는 날 조용히 사라지기 때문**이지 오늘 목록이 틀려서가 아니다.

## ③ 좌석 셋을 걷기로 옮겼고, 돌았는데, «되돌렸다»

`397bc3e5`. 멈춤 조건대로 **먼저 걸어 봤다.**

```
보드의 씨앗   엣지 «0», 절단 «없음»  -> 깨끗한 부재이고 원장도 같은 말을 한다
엣지가 있는 씨앗   엣지 «17», 값이 숫자 «16» · 텍스트 «1»
```

그다음 `trend_y` 를 걷기로 옮겼다. **돌았다** — 보드 요청이 **8 → 7**, 전부 200, 404 도
422 도 없다. 그런데 **컨트롤 바의 비율 축이 같이 사라졌다.**

```
그 좌석은 마킹을 «안 읽는다»  ->  씨앗이 «없다»
씨앗 없는 걷기는 «거절»       ->  kinds 가 «빈 배열»
=> 404 하나가 사라지는 대신 «화면이 말을 덜 하게» 됐다
```

**404 를 지우려고 화면이 말을 덜 하게 만드는 거래**는 그 좌석에 대해 이미 판정으로 막혀
있었다. 그래서 **되돌렸다.** 순서가 반대였다 — Y축이 «종류»가 아니라 «집계»를 고르게 되는
것이 먼저이고, 그 뒤에야 이 좌석이 걸을 수 있다.

🔴 **시도에서 하나는 남겼다** — 씨앗 없는 걷기가 **경계에서** 거절한다.

```js
// 🔴 씨앗이 «없으면» 묻지 않습니다 (라운드 ①, 2026-08-29). 없는 씨앗을 그대로 보내면
//    `id=undefined` 가 나가 «422» 이고, 화면에는 「서버가 거절했습니다」가 뜹니다 --
//    그건 「아직 안 골랐다」를 «고장»으로 그리는 것이고, 오늘 밤 같은 자리를 세 번 고쳤습니다.
if (!nodeId) {
  return { ok: false, status: null, body: null,
           detail: { detail: { reason: 'no_seed_chosen' } } };
}
```
같은 부류를 **부품 셋에 각각** 붙이던 것을 **층 하나에서** 막았다.

## 아키텍처 영향

- **자재 예산이 부품 선언**이다. 좌석이 아니라 **걷는 술어**가 단위이고, 곁다리 호출은
  좌석 예산을 물려받지 않는다.
- **씨앗 없는 걷기가 경계에서 거절**한다 — 「아직 안 골랐다」가 422 로 나가지 않는다.
- `trend_y` 는 **아직 걷기가 아니다.** 되돌린 자리에 «무엇을 기다리는지 이름이 붙은» 404
  하나가 남았다.

## 그때 남아 있던 것

- **라이브 선언의 술어 13 중 `continues` 표시가 0 이라, 자재 예산의 효과를 이 상자에서
  못 잰다.** 파라미터가 파싱된다는 것만 확인됐다(범위 밖 값이 422).
- 라이브 선언은 소유자 파일이고 **이 라운드가 건드리지 않았다.** 샘플에만 여섯이 있다.
- 마킹 아래 맨 걷기 «1»(`reach`)은 **일부러 남긴 것**이다.
- 종류 목록이 **1 인 것은 원장에 종류가 하나이기 때문**이지 절단이 없어서가 아니다.
- 이 항목의 수는 전부 **이 상자의 씨앗과 이 상자의 선언 위에서 잰 것**이다.
