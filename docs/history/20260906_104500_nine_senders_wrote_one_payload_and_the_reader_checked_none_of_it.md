# 한 페이로드를 «아홉»이 손으로 썼고, 읽는 쪽은 그중 «아무 칸도» 안 봤다

> **레인:** 구현자(서버)

## 무엇이 일어났나

`batch_refresh_required` 를 보내는 자리가 «아홉»이었고 «각자» dict 를 철자했다 —
일곱은 `{event, table_name, change_count}`, 하나는 `deleted_row_ids_omitted` 를 더하고,
하나는 감사 삼종을 더했다.

🔴 **그리고 이 페이로드는 «조용히» 갈라진다.** 읽는 쪽(`websocket.js`)은 `msg.table_name`
하나만 보고 나머지 «본문을 안 읽는다» — 캐시를 비우고 돌아간다. 그래서 보내는 쪽이 키를
**빠뜨리거나 틀리게 적어도** 오류도 경고도 «화면 변화»도 없다.

```
소유자 기준 ④   「한 능력에 길이 둘이면 안 된다」 -> 이건 «아홉»이었다
```

## 무엇을 «안» 했나 — 이게 이 커밋의 절반이다

```
⛔ 페이로드를 «안 바꿨다». 키 하나도 더하거나 빼지 않았다 —
   선택 넷은 «안 주면 빠지므로» 모든 발신자가 «전과 정확히 같은 객체»를 만든다
=> «모양»을 통일하는 것은 «경계 계약» 판정이라 «일부러» 이 변경이 아니다
```

## ⚠️ 그리고 `is not None` 이지 «참/거짓»이 아니다

빈 `created_logs` 와 `0` 인 `total_log_count` 는 발신자가 **뜻해서 넣은 것**이다.
참/거짓으로 거르면 「아무것도 안 빠졌다」가 「이 발신자는 누락을 보고 안 한다」처럼 보인다 —
이 저장소가 계속 닫고 있는 «부재 대 0» 혼동이 바로 그 모양이다.
`change_count: 0` 도 같다(복구 스윕이 «일부러» 보낸다).
