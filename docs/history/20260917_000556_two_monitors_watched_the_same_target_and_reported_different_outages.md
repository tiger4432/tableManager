## 배경

감시 아홉을 «전부 열어» 감사했다. TaskList 에는 안 뜨므로 세야만 알 수 있는 것들이다.

## 🔴 진짜 발견 — 같은 대상, 같은 주기, 같은 뜻, «다른 답»

```
감시자 둘이 «박스 생존»을 본다 — 같은 대상 · 같은 5분 주기 · 같은 의미론
그런데 «서로 다른 정전»을 보고했다:
   한쪽은 20:29 을 봤고, 다른 쪽은 22:36 을 봤다
각자가 «상대가 잡은 것»을 놓쳤고, 둘을 맞춰 보는 것이 «아무것도 없었다»
```

🔴 **이것이 내가 밤새 판정하고 있던 바로 그 결함이다 — 「같은 기능에 두 경로」·
「문 가르기 금지」 — 그리고 «내 자신의 계기»에 앉아 있었다.** 하나로 접었다.

## ⚠️ 둘 다 내 재기동을 «못 봤다» — 그건 «고장이 아니다»

```
정전       약 30초
폴링 주기   5분
=> 5분 폴링은 30초 정전을 «구조적으로» 볼 수 없다
```

**그래서 적어 둔다 — 나중에 누가 「안 울렸다」를 「안 일어났다」로 읽지 않도록.**
(이 저장소의 「기제가 있다 ≠ 돈다」의 반대 방향이다.)

## 열째 계기 오독, 그리고 «재서» 잡은 열째

하트비트를 「49분 낡았다」고 의심하고 있었다. 열어 보니 **시간 단위**였고
18:06 부터 23:06 까지 «깨끗이» 돌았으며 다음 예정은 00:06 이었다.

## 기록만 하고 «다시 짓지는 않은» 것

```
레인 정체 감시가 오늘 밤 «두 번» 울렸고 «두 번 다 틀렸다»
이유: 그 술어가 «각 레인의 보고 파일»만 읽는다
      -> 긴 스위트를 돌고 있거나 orders 채널에 쓰고 있는 레인이 «조용해 보인다»
구현자 정체 감시는 술어가 «더 낫다» — 커밋 «또는» 트리
이 시각에 다시 짓지 않는다. 드물게 울리고, 「믿기 전에 재기」가 이미 «두 번» 값을 했다
```

## 그때 남아 있던 것

- 살아 있고 자기 일을 하던 것: 착지 감시 · 클라 레인 감시 · orders 낡음 감시 ·
  라이브 config 감시. 마지막 것은 «조용했고 그것이 옳은 침묵»이다 — 소유자가 config 를
  안 건드렸다.
- 중복 하나를 «멈췄다». 레인 정체 감시의 나쁜 술어는 **고치지 않은 채로 남았다.**
