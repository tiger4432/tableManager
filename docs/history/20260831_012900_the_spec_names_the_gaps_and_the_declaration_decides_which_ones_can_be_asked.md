## 무엇이 필요했나

어휘는 **무엇이 «있을 수» 있는지**만 말한다. 「이 웨이퍼에 검사 기록이 없다」 같은 문장은
**어휘가 만들 수 있지만 이름이 없다.** 그래서 결측을 «찾는 것»과 «부르는 것»을 갈랐다.

## ① 두 권위가 «서로를 양방향으로» 검사한다

`b18b22a6`. `gap_names.json` 은 명세의 표 셋을 기계가 읽는 형태로 담고, `gaps.py` 는 이름을
**찾아본다**. **코드에 라벨이 하나도 안 적힌다** — 명세 개정이 데이터 변경이다.
모듈이 이름 대는 술어는 `observed@1` 하나이고, 그것도 **명세의 배제 ③으로 «인용»**된 것이지
여기서 판정한 것이 아니다.

```
표에 있는데 선언이 «은퇴시킨» 술어  ->  «절대 답할 수 없는» 질문
선언은 물을 수 있는데 «아무도 이름 안 붙인» 것 ->  🔴 «이웃의 이름으로» 답해진다
```
🔴 **둘째는 «출력을 봐서는 알 수 없다»** — 화면은 결측의 한 종류가 통째로 빠진 채로도
«완전해 보인다». 그래서 거절이다.

## ② 「해당 없음」은 0 이 아니다 — 그리고 그 규칙은 «한 줄»이다

```
술어가 어떤 타입의 «어휘 안 유일한 등장»이면
   그 타입의 노드가 그 엣지 «없이» 존재할 수 없다
   -> 노드는 «저장»되는 게 아니라 원자 «키에서 도출»되기 때문
=> 그것은 「해당 없음」이지 0 이 아니다
   0 은 「찾아봤는데 없었다」라고 말하고, 사람을 «놓친 것을 찾으러» 보낸다
```
라이브 선언에 대고 재니 정확히 `processed_with@1`/`recipe@1` 짝을 고른다 —
**명세가 «독립적으로» 해당 없음이라고 판정한 그 짝이다.**

`b18b22a6` 시점에 라이브 검사는 **정직하게 SKIP** 했다: 표와 선언이 **네 조합**에서 불일치했고,
그것을 덮지 않고 채널에 보고했다. `73f9eeea` 가 **JSON 네 줄, 코드 0줄**로 닫았고
그 시점에 검출기는 명세의 **열아홉 질문**을 만들었다.

`register` 는 **주어 타입 셋에 이름 하나**를 쓴다 — 운영자가 셋 다에 대해 같은 일을 하므로
**네 번째 주어가 와도 새 이름이 필요 없다**(타입만 갈아 끼운다).

## ③ 노드는 «양쪽»에서 열거된다 — 그것이 나이 규칙이다

`67c34a50`. 노드는 저장되지 않고 원자의 키에서 도출되므로 **어떤 원자든 그것을 이름 부르는
순간 존재하기 시작한다.** 그래서 주어 쪽만 열거하면 안 된다.

```
이 상자에서: defect_kind 와 recipe 는 «자기 원자가 0» 이고 «목적어로만» 나타난다
주어만 열거했으면 -> 「멤버가 아예 없다」로 보고됐을 것이다 (실제는 「나이가 없다」가 아니라)
양쪽 열거 후    -> 노드 2 · 13 과 «진짜 최초 관측 시각»이 돌아온다
```

「이 노드가 그 술어를 갖는다」는 **양방향에 «한 표현»**이다. 주어 쪽은 나갔어야 할 엣지를,
쌍은 들어왔어야 할 엣지를 묻지만 **질문은 같다** — 그 술어의 원자가 이 노드를 이름 부르는가.
표현이 둘이면 **선언의 «모양»에 대한 분기**이고 서로 어긋날 자리가 된다.

🔴 **표본은 스스로 「가장 오래된 것이 아니다」라고 말한다.** 나이로 고르려면 그 타입의 노드를
전부 정렬해야 하고, 그것이 예산이 피하려는 전수 스캔이다. 행들은 자기 나이를 달고
**자기들끼리 오래된 순**으로 보이지만, **집합 자체는 스캔이 먼저 만난 것**이다.
「먼저 찾은 것」이 「가장 오래된 것」으로 읽히면 **운영자를 엉뚱한 일로 보낸다.**
시험이 양방향을 다 못 박는다 — **모든 것에 붙는 단서는 아무 말도 안 하기 때문이다.**

술어 없이는 존재할 수 없는 타입의 질문은 **0 도 안 받고 질의도 안 쓴다.**
시험이 그것을 **«무엇이 실행됐나»를 보고** 단언한다.

G5 를 질문 넷에 대고 쟀다: **검출기가 「이 술어가 없다」고 부른 노드 중 실제로 그것을 가진
수는 0.**

## ④ 🔴 28.9초는 «3초 안에 판단하는 화면»을 못 만난다

`67c34a50` 은 스무 질문이 이 상자에서 **28.9초**에 답한다고 채널에 적었다 — 숨기지 않고.
`5cf5197f` 가 그것을 닫았고, **고칠 것이 이미 코드의 «모양»에 있었다**:

```

measure()    이제 그중 «하나»를 받는다  -> 펼친 하나만 센다        (0.55~1.08s)
```
라우트는 **하나이고 인자가 하나**다. 스무 개를 한 번에 원하는 호출자를 위해 배치 경로는 남는다.

```
표에 없는 이름   -> 404.  빈 목록은 「이 결측엔 멤버가 없다」로 읽힌다 —
                        운영자가 «넘어가는» 좋은 소식이라, 오타가 그걸 만들면 안 된다
표/선언 불일치   -> 503.  두 권위가 어긋나는 것은 «누군가 한쪽을 고칠 배포 사실»이지
                        요청의 실패가 아니다
```
`test_ledger_subgraph` 의 라우트 집합 단언이 **멤버를 못 박으면서**, 이것이 은퇴한 데이터
라우트를 다시 여는 것이 아닌 이유를 옆에 적었다 — **그것들은 «키»를 받아 키마다 답했고
그래서 증식했다. 이것은 선언에서 답한다.**

## ⑤ 배제 ①은 «부재»가 아니라 「질문이 성립하지 않는다」로 도착한다

`9a6cd51a`. `has_netdie` 와 `register` 의 목적어 쪽이 **조용히 빠져 있었다.**
명세가 recipe 행을 남겨 두는 것과 같은 이유로 내보낸다 — **빼면 다음 사람이 왜 없는지
물으러 온다.**

이름은 지어내지 않는다. 타입과 술어는 선언에서 오고 라벨은 **응용 어휘 자신의 값**이다 —
그것은 도메인이 아니라 **«질문»에 대한 진술**이라, 파일은 여전히 도메인 낱말을 **정확히
하나**(인용된 배제 ③) 들고 있다.
