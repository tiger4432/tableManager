## 배경 — 모집단을 «결함»으로 정의하면 결함이 자기를 숨긴다

실패 문구 하니스가 모집단을 **「이 결함을 가진 문자열」**로 정의하고 있었다.

```
명령형   «문장 모양»으로 걸렀다  ->  문장 모양이 아닌 명령형은 «모집단 밖»
대시     «고정 문자열»로 걸렀다  ->  구분자가 하나 붙으면 «떨어져 나갔다»
```

🔴 **즉 고쳐야 할 것이 «세는 그물»을 통과해 버렸다.** 그리고 그것이 이날 오후 모양 D 의
크기를 «오십팔»로 보이게 만든 그 그물이다.

## 변경 내용 — 모집단을 «주제»로 다시 정의했다 (`c9440957`)

```
바꾼 뒤 «즉시» 돌리니   두 죽은 단언이 «되살아나 실패»했다 — 명령형 1 · 대시 조인트 15
적용한 뒤 돌리니        통과
=> 열여섯이 «전부» map_editor.js 에 있었고, 옛 모집단이 그것을 «숨기고» 있었다
```

**좁히기가 값을 했다** — 열여섯 «전부»가 진짜 실패 줄이다(프리셋 저장·삭제, 스키마·셀 fetch,
맵 로드). 넓은 그물이 끌어들이던 라벨·툴팁·성공 메시지는 **하나도 안 들어왔다.**

### 🔴 결과를 «바닥»이라고 «말한다»

```
하니스가 «찍는» 것   넓은 그물 137 · 좁힌 것 49 · «안 본 것 88»
그리고 한 줄         「천장을 알려면 호출부 스캔이 필요하다」
=> 88 은 «안 읽었다». 그것이 판정에서 «배제된 선택지»였다
```

가드가 이제 **반대 방향을 가리킨다** — 모집단을 **40 «위»로** 붙든다.
「실패」는 모양이 고쳐진 «뒤»에도 문자열에 남기 때문이다.
**첫 판이 틀렸던 지점이 정확히 그것이다.**

⚠️ 그리고 **숨기지 않고 적었다** — 열여섯 중 셋은 사용자 문구가 아니라 `console.warn` 이다.
모집단이 아직 **개발자 로그를 포함한다.**

- 실패 문구 하니스의 모집단이 **「고칠 것의 모양」이 아니라 「무엇에 대한 문자열인가」**로

  천장을 주장하지 않는다.
