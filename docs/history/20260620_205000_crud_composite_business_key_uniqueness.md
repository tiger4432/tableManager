# 2026-06-20 CRUD/DB 레이어 복합 비즈니스 키 자동 조립 및 조건부 유일성 검사 구현

비즈니스 키의 가공 및 검증 책임을 CRUD 단으로 내재화하여, 인제션뿐만 아니라 사용자 UI 수정을 통한 개별 셀 업데이트 시에도 비즈니스 키가 실시간으로 안전하게 동기화 및 검증되도록 핵심 데이터 파이프라인을 개선했습니다. 또한, 신규 행 생성(Draft) 상태를 배려하는 조건부 유일성 검사 기법을 도입했습니다.

## 주요 변경 사항

### 1. CRUD 코어 단 (`apply_row_update_internal`) 복합 키 조립 및 동기화 내재화
- **대상 파일**: `server/database/crud.py`
- **구현 방식**:
  - **인제션 선제 매칭 지원**: 업데이트 요청 시 `business_key_val`이 비어있더라도 `updates` 데이터에 `composite_key_source` 구성 컬럼들(예: `base`, `x`, `y`)이 존재하면 선제적으로 키를 가공하여 기존 레코드 조회를 보장하도록 처리했습니다.
  - **동적 동기화 및 검증**: 행 수정 혹은 신규 생성 완료 시점에 구성 컬럼들의 값을 조회하여 비즈니스 키를 재조립합니다. 키가 기존 값과 다르게 갱신되는 경우, 해당 키가 다른 행에 이미 존재하는지 DB를 실시간으로 조회하여 충돌을 감지합니다.
  - **수정 차단 (롤백)**: 다른 행과 비즈니스 키가 중복될 경우 `ValueError` 예외를 발생시키고 해당 데이터베이스 트랜잭션을 전체 롤백하여 데이터 무결성을 보호합니다.

### 2. 드래프트 상태(Draft State) 지원을 통한 신규 빈 행 생성 충돌 해소
- **대상 파일**: `server/database/crud.py`
- **구현 방식**:
  - `composite_key_source` 컬럼들 중 하나라도 비어있거나(`None` / `""`) 누락된 경우에는 비즈니스 키 조립을 보류하여 `business_key_val`과 물리 키 컬럼(예: `pkg_id`)을 `None` 상태로 유지합니다.
  - 이 드래프트 상태에서는 유일성 검사를 우회하므로, **사용자가 값 입력 없이 여러 개의 빈 신규 행들을 동시에 생성하더라도 아무런 키 충돌 없이 안전하게 등록**할 수 있습니다.
  - 사용자가 마지막 원천 컬럼 값을 채워 비즈니스 키가 완성되는 최종 시점에만 유일성 검증이 유효하게 동작합니다.

### 3. 디렉토리 와처 (`DirectoryWatcher`) 로직 간소화
- **대상 파일**: `server/parsers/directory_watcher.py`
- **구현 방식**:
  - 와처 단에 중복으로 존재하던 복합 키 조립 코드를 전면 제거했습니다.
  - 파일 인제션 발생 시, 와처는 파싱된 순수 원천 데이터 행만 구성하여 `apply_batch_updates`로 전달하고, 모든 키 조립과 검증은 단일 창구인 CRUD 단에서만 수행하도록 일원화했습니다.

### 4. 캐시 미스(Cache Miss) 시 DB 폴백 및 캐시 동기화 보완
- **대상 파일**: `server/database/crud.py` 의 `_get_or_create_row`
- **구현 방식**:
  - 배치 업데이트 동작 시, 선제적으로 조립된 복합 키가 초기 `row_cache`에 존재하지 않을 경우(캐시 미스), 데이터베이스 조회를 안전하게 폴백 수행하고 획득한 레코드를 `row_cache`에 즉각 재등록하여 중복 행 생성을 완벽하게 예방했습니다.
