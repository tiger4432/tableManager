## 무엇이 일어났나

새벽의 문장은 하나다: **「화면이 «권하는 것»과 제품이 «받아 주는 것»이 같아야 한다」.**
맵퍼 드롭다운 · 뷰의 편집 진입 · 걸음 순서 · 규칙 추가 폼 — 넷 다 같은 병의 다른 자리였고,
넷 다 **「화면이 계산하지 말고 «값을 받는다»」**로 고쳐졌다. 착지 커밋 단위로 적는다.

## ① 맵퍼 목록 — AST 를 «대체»한 게 아니라 «더했다» (S-207 `2ec11afc` · C-85 `95862c18`)

```
`data`        «그대로» AST — 파일 안의 함수 «전부», 등록 안 된 것도
`registered`  `sorted(mapper_sdk.MAPPER_REGISTRY)` — **저장이 «받아 줄» 이름**
```
🔴 **두 목록인 것이 «의도»이고, 둘이 갈리는 것이 발견이다.** `@mapper` 가 안 붙은 함수는 저장에서
거절되는데 **종전 화면은 그것을 «고를 수 있게» 내놓고 있었다** — 운영자는 고른 «뒤»에 배웠다.
🔵 그래서 클라(C-85)가 `registered` 로 드롭다운을 채운다. 커밋 제목이 그 규칙이다:
「the names the SAVE accepts, not the file's functions」.
⚠️ 그리고 이 순서가 아니면 안 됐다 — 판정 326(API 프로세스가 `discover()` 로 등록부를 채운다)이
«먼저» 서지 않으면, 이 프로세스의 등록부가 비어 있어 드롭다운이 «아무것도» 못 내놓는다.

## ② 판정자를 접는 것과 «한 세계»를 보게 하는 것은 «별개»였다 (S-204 `5422b308`·`45f0da47`)

```

                등록부가 «워커 프로세스에만» 차 있어서 API 는 «모든» 매퍼를 「못 푼다」로 읽었다
수리            API 기동·리로드 뒤 `mapper_sdk.discover()`(판정 326)
```
🔴 **「자리를 하나로」와 「같은 것을 보게」가 두 걸음이라는 것이 이 밤의 구조적 교훈이다.**
📌 그리고 규칙 저장이 «로더 자신의 판정자»에게 묻는다 — 화면이 좋다고 부른 규칙을 로더가 곧이어
거절하는 일이 있을 수 없다. 🔵 폼의 «모양»도 서버가 준다(`skeleton` = `chain_bindings.skeleton()`) —
**폼이 규칙의 모양을 «알 필요가 없다»**.

## ③ 비용은 «계산됐는데 떨어뜨려지고» 있었다 (S-143 `3238bff6`, 판정 319·320·323)

커밋 제목이 결함을 이름 댄다 — 「the activation cost reaches the wire, instead of being
**computed and dropped**」.
🔴 **비용을 «계산하는» 자리는 이미 있었다. 전선에 «안 실려» 있었다** — 그래서 초안 검토 응답이
`redo` 칸을 든다(`DraftPreview.redo` · `_redo_for`), 그리고 «두 문서 어댑터가 공유»한다.
📌 부류는 「착지는 배선이 아니다」이고, **정정이 «계산»이 아니라 «배선»이었다** — 기제가 있다 ≠ 닿는다.
⚠️ **`redo` 가 `None` 이면 「그 질문을 «안 물었다»」이지 「비용이 0」이 아니다**(소스가 그렇게 적는다).
0 으로 접으면 운영자가 «안전하다»로 읽는다 — 「미상은 0이 아니다」 그대로.
🔵 그리고 판정 322·323 이 그 칸의 «말투»를 정했다: 세지 못했으면 **「세지 못했다」를 이름 대고**,
카운터의 응답을 «그대로» 나른다(지어낸 칸 이름이 둘째 어휘가 되지 않게).

## ④ 걷기가 «자기 모집단»을 접는다 — 그래서 수가 예산을 살아남는다 (S-146 `a4d80302`, 판정 331)

```
AGGREGATE_MEASURES  count · distinct · sum · mean · min · max · median   — «일곱, 그 밖은 없다»
group_by            노드의 «타입» 또는 그 값 중 하나
봉투                `groups` · 절단은 «같은 봉투»가 이름 댄다

```
🔴 **요점은 「어디서 세나」다.** 클라가 세려면 걷기가 «전부» 실어 와야 하고, 큰 규모에서 그것은
**「세려다 잘린다」**가 된다. 접는 자리를 옮기면 «잘린 표»가 아니라 «옳은 수»가 온다.
🔴 **목록이 닫혀 있는 것도 설계다** — 열린 측정자면 화면마다 «다른 것»을 세기 시작한다.
⛔ 못 받는 이름은 «이름 대어» 거절한다(철자 틀린 measure 가 조용히 떨어지면 그 수는 «다른 수»이고
아무도 모른다). 숫자를 접는 측정자에 숫자 아닌 값이 오면 `measure_needs_numbers`.
⚠️ **예산은 «하나»다** — 둘이면 「잘렸나」의 답이 둘이 된다.

## ⑤ 선언 칸 둘 — 「복수인가」와 「침묵이 무슨 뜻인가」

```
86fff683  S-144  `attribute_cardinality` — 속성이 «여럿을 담는다»고 «선언»할 수 있다 (판정 327)
05255959  S-147-a `vocabulary.<p>.absence_confirmed_by` — 술어가 «자기 부재의 뜻»을 말한다
```
🔵 **S-147-a 는 「칸이 빠진 것」이 아니라 「«하위 축»이 빠진 것」이었다.** 표 A 의 A1(노드 키)은
「부재의 뜻」을 `allow_null` 로 들고 있었는데 A2(술어)에는 «짝이 아예 없었다» — 술어가 status ·
subjects · object · cardinality 를 적고 **자기 침묵에 대해선 아무것도** 적지 않았다.
🔴 **그리고 값이 «다른 술어의 이름»인 것은 «고른 것이 아니라 강제된 것»이다** —
「안 봤다」와 「보았고 없었다」는 **«다른 원자»의 존재로만** 갈리고, `absence: none|unknown` 같은
플래그로는 표현할 수 없다. ⚠️ 어느 술어가 «검사»인가는 «도메인 사실»이라 «선언»한다 —
코드가 `inspected` 를 이름으로 알면 그것이 «코드에 박힌 도메인 낱말»이다(상설 그대로).
