## 배경

소유자가 토스트 더미를 보셨다. 총괄이 레인에 물은 것은 판정 «셋»이었다 —
**자리 · 실패를 접어도 되나 · 가운데 띠 안의 정렬.** 셋 다 소스를 읽지 말고 «브라우저에서 재라»고 했다.

## 무엇을 바꿨나

### ① 자리는 답이 아니다 — 그리고 그것이 «측정»이다

640×280 상자를 두 화면의 앵커 여섯 위로 밀어 보니 **여섯 다 무언가를 덮었다.**
어드민 1440: 하단 가운데/오른쪽/왼쪽이 각각 「탭 열기 →」와 텍스트 노드 10~15 를,
상단 셋이 컨트롤 4~6 을 덮는다. 메인 그리드 1440: 하단 가운데·오른쪽은 컨트롤을 안 덮지만
그리드 데이터 텍스트 노드 73·95 를 덮고, 나머지 앵커는 전부 컨트롤 13~20 을 덮는다.

**옮기면 «피해자만» 바뀐다.** 직전 이동(맵 에디터 자재 목록 → 오버뷰 카드)이 정확히 그것이었다.
그래서 띠는 그대로 두고 «규칙»을 바꿨다.

### ② 실패는 접힌다 — 다만 «같은 문장»끼리만

`utils.js` 는 실패를 집계에서 «일부러» 뺐고(「개별 사유가 중요하므로」), 그 판단은 유지됐다.
다만 그 판단이 지키는 것은 «사유»이고, 사유는 «문장»이다 — 글자가 같은 두 실패는 두 사유가 아니다.

```js
const foldKey = type === 'error' ? `msg:${text}` : (opts.dedupeKey || null);
if (foldKey) {
  const hit = toastItems.find(it => it.foldKey === foldKey && it.type === type);
```

🔴 **호출자가 준 `dedupeKey` 로는 실패를 접지 «않는다»** — 그 키는 서로 «다른 문장»을 한 덩이로
묶을 수 있고, 그러면 운영자가 둘째 사유를 영영 못 보면서 오류는 아무 데도 안 난다.
`dedupeKey` 는 별도로 보관한다 — `dismissToasts(key)` 가 그것으로 거둔다.

### ③ 상자가 «자기 문장만큼» 커진다

`width: 100%` 였다. 「짧음」 한마디도 640px 을 차지했고, **덮는 면적이 내용이 아니라 «상수»**였다.

```css
-  width: 100%;
+  width: auto;
+  max-width: 100%;
```
수리 뒤 네 메시지가 640 / 429 / 388 / 131 px. 정렬 물음의 답도 여기서 나왔다 — 상자가 왼쪽에
붙어 보였던 것은 «의도»가 아니라 «전폭 + 왼쪽 정렬 텍스트»였다.

### ④ 클릭은 사용자의 것이다

띠와 토스트가 둘 다 `pointer-events: auto` 였다. 어드민 오버뷰에서 「탭 열기 →」를 누르면
`elementFromPoint` 가 토스트를 돌려주어, **탭이 열리는 대신 토스트만 사라졌다** — 조용히,
운영자의 의도를 버리면서. 토스트 «사이의 빈 여백»조차 클릭을 먹었다.

```js
-  el.addEventListener('click', () => { … removeToast(it); });
+  const closeEl = document.createElement('button');
+  closeEl.className = 'toast-close';
+  closeEl.setAttribute('aria-label', '닫기');
+  closeEl.textContent = '×';
```
띠와 본체는 `pointer-events: none`, `.toast-close` 만 `auto`. 닫기가 **보이는 기능**이 됐다 —
전체 클릭으로 닫는 것은 숨은 기능이었다.

## 🔴 공유 DOM 스텁의 구멍 둘 — 둘 다 「초록인 채로 아무것도 안 재는」 모양이었다

```js
+ remove() { if (this.parentNode) this.parentNode.removeChild(this); },
+ get id() { return this.getAttribute('id') || ''; },
+ set id(v) { this.setAttribute('id', v); },
```
- `el.id = 'x'` 가 `attrs.id` 에 안 들어가서 `getElementById` 가 컨테이너를 영영 못 찾았다.
  `toastContainer()` 는 못 찾으면 «새로 만들므로» 하니스가 본 토스트는 매번 «새 컨테이너에 하나»였다 —
  **쌓임도 접힘도 한 번도 안 재졌다.**
- 노드에 `remove()` 가 없어서 `removeToast` 의 지연 제거가 400ms 뒤 «비동기로» 던졌다.
  단언 하나도 안 빨개진다.

## 아키텍처 영향

- **한 사실에 두 글자를 두지 않는 규율이 `pointer-events` 에도 적용됐다** — 「덮는다」와 「클릭을 가져간다」를
  자식 단위로 갈랐다. 총괄 평: 「내준 것이 «없다»」 — 접기를 얻으며 「사유가 중요하다」를 안 버렸고,
  클릭을 페이지에 주며 닫기를 안 버렸다.
- 판정의 «모양»이 바뀌었다: 물음이 「어디로 옮기나」가 아니라 **「덮지 않는 자리가 «있나»」**였고,
  답이 「자유로운 앵커가 없다 → 그러면 위치가 아니라 «면적과 클릭»이다」였다.
