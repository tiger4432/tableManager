# 읽기에 실패한 것은 「선언이 없다」가 아니다 — 그리고 그 강등이 좌표를 영구히 옮긴다

> **일자:** 2026-08-02 오후 | **관련 커밋:** `aee05b1`(소스 수리) · `69c3604`(번들 출하 + 남긴 것 보드에) · 보드 `6b150d3`
> **담당:** 사용자(운영 신고) · map 구현 · 총괄(자기 오라클 선택이 구조적으로 눈이 멀었음을 기록)
> **대상:** `client2/src/map_editor.js`(`fetchGridMetaFor` catch · 표준 버튼 문구) + dist

## 배경 — catch 하나가 두 상태를 하나로 접었다

맵을 적재하면 `fetchGridMetaFor`를 부르고, 그 함수는 **진짜 에러에서 올바르게
throw한다.** 그런데 catch가 그것을 `loadedGridMeta = null`로 **평평하게** 만들었다.

> **한 번의 읽기 실패가 존재하는 서버 선언을 「선언이 없다」로 강등시켰고**,
> 표준/현재 선택 대화상자를 열었으며, **표준 분기가 START를 데이터 바운딩 박스로
> 다시 선언했다 — 토스트 하나 없이.**

## 이것은 표시가 아니라 손상이다

`pushMapData`가 그 컨트롤을 다시 읽어 `grid_start_x`를 **영속화**하고,
`map_overlay`가 맵 간 정렬에 그것을 읽는다. **그래서 강제된 원점이 그 맵의 모든
오버레이로 전파된다.**

실측: 21×21, start `(1,-6)`으로 **선언된** 프레임인데 셀이 `(5,-1)..(12,5)`에만
걸쳐 있는 경우 — **bbox로 강제된 원점이 46개 셀 중 41개를 다른 물리 다이 위로 옮긴다.**

## 같은 경로를 타던 두 번째 입구

`grid_start_x`가 없는 메타 행이 **`Number(null) === 0`**을 통해 같은 경로를 탔다.
그것이 **부재한 원점을 선언된 원점으로 바꾸고 46개 셀 전부를 단일 `NaN` 키로
붕괴시켰다.**

> 회전과 면(side)에는 **정직한 기본값**이 있다. **START에는 없다** —
> **「모르니까 0」이라는 것 자체가 좌표계를 옮기는 행위이기 때문이다.**

## 수리와, 컨트롤 수지

표준 버튼이 이제 **START를 다시 선언한다고 말한다.**
**순 신규 컨트롤 0, 그리고 대화상자 하나가 사라졌다** — 실패 경로에서는 더 이상
나타나지 않는다.

이번 주 세 번의 맵 라운드에서 온 회귀가 **아니다.** 이 동작은 선택 대화상자보다
앞서고, `019140c`는 **무엇을 강제하는지만** 바꿨다.

## 그리고 총괄의 오라클 선택이 구조적으로 눈이 멀어 있었다

`69c3604`가 그것을 기록한다.

> 총괄이 **저장 좌표 왕복(round trip)**을 이것의 오라클로 지시서에 썼다.
> **여기서는 구조적으로 눈이 멀어 있다** — **`start`가 배치하는 쪽이자 읽는 쪽이라,
> 깨진 빌드에 대고도 0을 읽는다.**

## 그때 남아 있던 것

- 소스는 `aee05b1`에 착지했지만 **`69c3604`의 번들이 나오기 전까지 아무것도 사용자에게
  도달하지 않았다** — 이번 주에 선언되지 않은 전역이 출하된 맵 에디터에 올라탄 것과
  **같은 간극**이다.
- **이 수리를 채점한 하네스(단언 28, 변이 5/5 적색)는 아직 스크래치패드에 있다.**
  인자를 받는 형태라 러너가 거짓 적색으로 보고하기 때문이다.
  **그래서 저장소는 방금 고친 바로 그 결함에 대해 보호되지 않은 상태다.**
- **등록기는 선언된 적 없는 맵에 대해 배치 바운딩 박스를 `start`로 쓴다** —
  대화상자가 **아예 안 뜨는** 경로이고 신고 문구에 가장 가깝다.
- `6b150d3`(같은 날 저녁)이 별개의 것을 보드에 열었다 — **가상 조인이 숫자 컬럼에서
  죽는다.** 출하될 수 있었던 이유는 **그때의 측정이 정직하고 비어 있었기** 때문이다:
  숫자 `expose` 컬럼이 0개라 축이 발화한 적이 없다.
