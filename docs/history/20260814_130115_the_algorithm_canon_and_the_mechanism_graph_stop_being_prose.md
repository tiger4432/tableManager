## 알고리즘 정본 — 모든 순위가 손으로 검산 가능

설계 의도 한 줄이 전부를 통치한다: **블랙박스 점수 금지, 합산 가중치 금지.**

- 놀라움: 기저 = 열 «중앙값»(이상치가 자기 잣대를 오염 못 하게), 칠하기 전
  이항 신뢰 하한 가드. 유계 지표는 「채점 불가」를 화면에 문장으로(R-G).
- 대조: 범주 = 농축비 + Katz 하한 · 수치 = 순위합 + 효과 크기 · 경로 = 선언된
  추출기로 특징화 후 환원 · ⑤ 혈통 공통점 = 상류 걷기(`2fcbc2c`).
- 세 관문: 실재(하한) · 상류(occurred_at 선후, boolean) · 기전(BFS 도달 가능성).
  순위 = 관문 통과 **사전식**, 동률만 효과 크기 — 조율된 가중치가 아니라.
- 액션 정렬: 완전 베이지안 정보 이득은 과설계로 배제, v1 근사 3항이 각각 화면에
  보여 사람이 산수를 다시 할 수 있다. 발급은 사람(상설).

## 기전 그래프 v0 — 산문에서 파일로

`server/config/mechanism_models.json.sample` 신설: 모델 3, 방향만 있는 엣지 22
(보이드 형성 18 · 박리 형성 3 · 관측 편향 1), 소유자 감수 통과.

```json
"void_observation_bias": {
  "validity": "NOT a formation path. A factor arriving only here explains
               APPEARANCE, not occurrence - ... never as a cause.",
  "edges": [{"from": "post_bond_queue_h", "to": "void_observed", "dir": "u"}]
}
```

관측 편향이 **별도 모델**인 것이 구조다 — 겉보기만 설명하는 요인이 원인으로
보고될 수 없게 분리가 파일 수준에 있다. `signatures` 블록은 사람용 주석이고
로더는 무시한다(각 원인이 남기는 공간 패턴, 세 맵 프레임 기준).

아침에 지어 둔 이음새가 실증됐다: 파일이 착지하자 구조 뷰가 **코드 수정 0으로**
declared/22엣지를 렌더했다.

## 그때 남아 있던 것

- 기전 관문의 소비자는 이 시점 0 — BFS를 실제로 도는 코드는 미착지(브리프 R3).
- 상시 감시(CUSUM류)는 미도입으로 명시 — 다음 단계 안건.
