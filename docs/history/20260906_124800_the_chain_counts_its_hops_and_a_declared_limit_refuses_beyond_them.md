# 체인이 «자기 홉을 센다» — 그리고 «선언된» 한계가 그 너머를 거절한다

> **커밋:** `639655d7` (12:48)
> | **일자:** 2026-09-06
> **레인:** 구현자(서버)
> **측정 상자:** 이 워크스테이션. **운영이 아니다.**

## 배경 — 소유자 문장이 이 라운드를 열었다

> 「원래는 체인이 체인 유발 아예 막았는데 너무 빡빡해서 풀었더니 이래 된 거네, 깊이 넣으면 될 듯」

```
「체인은 체인을 «절대» 못 깨운다」  와  `allow_chain_trigger`(옵트인하면 «무제한»)
그 «사이»에 아무것도 없었다
```
`source_name == "chain_ingestion"` 은 **체인이 썼나**에만 답하고 **몇 홉이 만들었나**에는
답할 수 없다. 2026-09-06 실측: 서버에서 홉을 세는 것이 «하나도» 없었다.
유일한 제동은 로더의 **정적** 고리 검사인데, 그것은 워커가 뜨기 «전»에 돌고
**«도는» 것이 아니라 «긴» 폭포는 못 본다.**

## 네 조각

```
㉮ 나른다   아웃박스 페이로드가 수 «하나»를 얻는다 — `chain_depth`
㉯ 읽는다   `chain_depth_of` 가 «세 상태»를 가른다 — 없음(체인 밖) · 0 · N
           ⚠️ «없음»은 0이 아니다. 체인 «밖»의 이벤트가 깊이로 거절되면 안 되고,
              0 은 「체인이 썼는데 세는 것을 잊은」 것이다
㉰ 찍는다   «한 자리»에서. 🔴 맵퍼 «열»이 자기가 돌려주는 «행»에 `source_name` 을 철자하지만
           그건 «행»의 컬럼이다. 아웃박스 «봉투»는 `database._outbox_envelope` «한 곳»에서
           지어지고(그 독스트링이 「per-row 와 접힌 이벤트가 갈라지지 않게」 있다고 적는다),
           워커가 컨텍스트 변수를 «한 줄»에서 세우면 스테이저 «둘»이 그것을 읽는다.
           시험이 «찍는 자리의 수»를 센다
㉱ 거절한다  한계를 넘으면 «이름을 대고», 루프의 정규화 단계에서.
           ⛔ `_rule_accepts_event` «안»이 아니다 — 그 술어는 이벤트당 다섯 번 불려서
              거기서 거절하면 «다섯 번 말하거나 아무 말도 안 하게» 된다
```

## 🔴 그리고 거절된 행을 «끝낸다»

안 끝내면 매 틱 다시 읽혀 **뒤를 영원히 막는다** — 같은 날 아침에 닫은 「독 든 행」 결함을
새 기능이 다시 들여오는 모양이다.

## ⛔ 정적 고리 검사는 «안 풀었다»

깊이는 «긴» 폭포를, 고리 검사는 «도는» 폭포를 막는다. 깊이가 무는 것을 보이기 «전»에
두 번째를 풀면 진짜 무한 루프가 열린다.

## 한계는 «상수가 아니라 선언»이다

`chain_rules.json` 의 `max_chain_depth`. 양의 정수가 아니면 기본값으로 떨어진다 —
이 키가 생기기 «전»에 쓰인 config 가 그 자리다.
