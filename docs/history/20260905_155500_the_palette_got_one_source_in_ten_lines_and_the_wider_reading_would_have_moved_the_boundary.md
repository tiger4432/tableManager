# 팔레트가 «열 줄»로 한 출처가 됐다 — 넓게 읽었으면 경계를 «옮기기»만 했다

## 배경 — 부품을 옮기면 색이 «아무도 선언하지 않은 이유»로 바뀌었다

온톨로지 탐색기가 색 역할 **열 개**를 자기 CSS 에 정의하고 있었다. 앱의 `tokens.css` 가
**몇 RGB 옆에서** 같은 역할을 이미 정의한다.

```
결과   이 화면에서 만든 부품을 다른 화면으로 옮기면 «색이 바뀐다»
       그 변화를 «선언한» 사람은 아무도 없다
```

조립식 규율(「모든 UI 는 조립식」, 소유자 2026-08-23)에서 이건 부품이 자기 화면 밖으로
못 나간다는 뜻이다.

## 변경 내용 — 🔴 «두 번째 팔레트»를 지운 것이지, 호출부를 바꾼 것이 아니다

처음 건네받은 읽기는 **`admin.html` 의 `var(--border)` 를 전부 `var(--oe-line)` 으로 고쳐라**
였다. 레인이 그것을 **거절하고 이유를 수로 적었다**:

```
❌ 호출부를 고친다        약 200줄. 그런데 «경계가 옮겨질» 뿐이다 —
                       다른 파일 «열 개»가 앱 팔레트를 그대로 쓰므로 팔레트는 «둘로 남는다»
                       그리고 `rnd_board` 로 옮긴 부품은 «여전히» 색이 바뀐다
✅ 정의를 겨눈다          열 개의 «정의»가 앱 토큰을 가리키게 한다
                       호출부 «0곳» · 선택자 «0개» 변경 · 탐색기에 색 리터럴 «0»
```

🔴 **같은 규칙을 만족시키는데 한쪽은 200줄이고 한쪽은 10줄이다.** 갈린 자리는
「무엇을 고치나」가 아니라 **「두 번째 저자가 어디 있나」**였다.

부수로 얻은 것이 하나 있다 — `light-dark()` 가 정의와 «같이» 갔다. 앱 토큰은 테마마다
자기를 다시 정의하므로, 다크가 이제 **선언 «하나»**를 따른다(둘이 아니라).
열 개 «전부» 양쪽 반쪽이 `tokens.css` 에 있는지 확인한 뒤에 착지했고, 파생 혼합 아홉과
폰트 셋은 **안 건드렸다** — 그것들은 이 열 개의 «퍼센트»라서, 이 라운드가 19줄이 아니라
10줄인 이유가 그것이다.

## 같은 분(minute)에 착지한 형제 — 「없음」을 «두 목소리»로 말하던 개요 (`3e775d31`)

같은 개요 화면의 부재 줄 «둘»이 서로 다른 말투였다. 이날의 명사형 문구 교정이
`renderRecorrection` 에는 닿고 `renderEffort` 에는 **안 닿았다.**

```
세어 보니   그 함수의 네 갈래 중 «셋»이 옛 문장형
           넷째는 이웃이 구분자를 쓰는 자리에 «콜론»을 썼다
=> 넷 다 이웃이 이미 쓰는 낱말로. 갈래 «자체»는 안 건드렸다 — 맞고, 주제가 아니었다
```

🔴 그중 **하나는 판정을 «잃었다»**. 「수집이 끊겼는지 확인」은 **이 파일이 세울 수 없는
원인**을 단언한다. 이제 두 수를 나란히 놓고 운영자가 읽게 둔다 — 큐 패널이 「멈춤」을
거부한 것과 **같은 이유**다. 경고 표시는 남았다: 「이건 이상하다」는 사실이고,
지워진 것은 **진단**뿐이다.

## 아키텍처 영향

- `ontology_explorer.css` 에 **색 리터럴이 0개**다. 열 역할이 전부 앱 토큰을 가리킨다.
  탐색기에서 만든 부품이 다른 화면으로 가도 색이 «선언되지 않은 이유»로 바뀌지 않는다.
- 문구 규율(「상태는 명사, 다음 행동은 옆에」)이 이제 개요의 **두 부재 줄에 같이** 적용된다.
- 화면이 «단언할 수 없는 원인»을 말하지 않는 규율이 이 날 **둘째 자리**에도 적용됐다
  (큐 패널의 「멈춤」 거부 · 여기의 「수집이 끊겼는지 확인」 삭제).
