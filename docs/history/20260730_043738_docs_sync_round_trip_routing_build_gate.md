`5a14e77`·`50bddda`·`c9bf2c7`이 연달아 들어왔다. 코드 라운드가 각자 자기 문서를 조금씩
건드렸지만, **셋을 가로지르는 서술**은 어디에도 없었다. 이 커밋은 코드를 한 줄도 만지지 않고

## ① 함수 항목 한 줄이 아니라 **절(節)**을 만들었다 — §4-ter

종전 `#47 copyGridToExcel`은 **한 줄**이었다. 평문 TSV 내보내기 하나를 서술하는 줄이었고,
그때는 그게 사실이었다.

```
- 용도: … 탭 분리 문자열(TSV) 구조로 클립보드에 가공 기입하여, 사용자가 엑셀에 …
+ 용도: … 클립보드에 기입합니다. `text/plain`(TSV)과 `text/html`을 둘 다 싣습니다 …
```

그런데 왕복은 **일곱 조항**이다. 일곱 조항을 한 줄 함수 항목 안에 밀어 넣으면 **아무도 읽지
않는 절**이 된다. 그래서 `§4-ter 회사 양식 왕복 계약`을 새로 만들고, 함수 항목(#47·신규 #48)은
거기를 가리키게 했다. 스펙 맺음말의 함수 수도 **47 → 48**로 따라갔다.

절이 적어야 했던 것들:

| 조항 | 기록한 것 |
|---|---|
| 4-ter.1 | 읽는 쪽이 왜 **평문**인가(리더가 하나뿐 · 엑셀을 거친 HTML은 우리 colspan과 같다는 보장이 없다) **+ 그 대가** |
| INV-F1ⓑ-3 | **병합 관례를 계약으로 승격** — 압축해 읽으면 DESC가 STACK 자리로 들어간다 |
| 4-ter.2 | 그룹 띠를 **의도적으로 읽지 않는다**, 그리고 그것이 **순환**이라는 것 |
| 4-ter.3 | 격자 폭을 `HDR_GAP_COLS` 하나에서 되찾는다 |
| 4-ter.4 | 노치 `D`의 **세 역할**(그림 · 프레임 지문 · 적용 시 폐기) + 데이터로 되쓰는 비용 = **영구 Push 거절** |
| 4-ter.5 | **거부 네 갈래**, 그리고 최선 노력 배치를 하지 않는다 |
| 4-ter.6 | 적용 규율 — **붙여넣기는 값을 지우지 않는다** |

## ② 라우팅 우선순위를 **찾을 수 있는 자리**에 적었다 — §5.8

`50bddda`(서버 절반)는 자기 히스토리 항목과 운영 절차 문서를 남겼지만, 맵 에디터 계약 정본에는
없었다. 이번에 §5.8이 그것을 받았다: **`wafer_map_metadata` > 라우팅 > 패널**, 서버가 강제,
**조회 miss는 경고가 아니라 정상 경로**.

🔴 **그리고 세 문장을 `c9bf2c7`에 못 박았다** — 클라 절반이 아직 착지하지 않았기 때문이다.
§5.8은 "클라 절반이 들어오면 무엇을 대조해야 하는지"를 함께 적었다. 체크리스트도 같은 규율을
따라 *"HEAD `c9bf2c7` 기준 에디터 동작은 변하지 않는다 — 맵을 열었을 때 규격이 자동으로 바뀌면
그건 클라 절반이 이미 들어온 것이므로 이 항목 대신 그 라운드의 점검 항목을 쓰십시오"*라고
적었다.

## ③ "초록"의 뜻이 바뀌었으므로 **네 곳**에 적었다

`npm run build`가 계약 하네스 4종을 돌리게 됐고, **이번 주까지 아무것도 그것을 돌리지
않았다.** 이건 한 문서의 한 절로 끝날 변경이 아니다 — 이 저장소에서 "검증됐다"가 뜻하는 바가
바뀌었기 때문이다.

| 문서 | 왜 거기에 |
|---|---|
| `CONTRIBUTING §2-bis` 신설 | 「이 저장소가 자기를 검증하는 자리」 — **채점은 두 갈래이고 둘 다 돌려야 한다**(pytest = 서버 절반 / `npm run build` = 클라 절반) |
| `FEATURE_CHECKLIST §2.0` 신설 | **자동 게이트가 초록일 때만 수동 점검이 의미가 있다.** 「0개, 전부 초록」은 통과가 아니므로 **계약 개수를 눈으로 확인**하라(현재 4) |
| `frontend §2.1` | 프론트엔드 아키텍처 쪽 배선 서술 |
| `DEPLOY_SETUP` | **빌드가 실패하면 번들도 갱신되지 않았다** — *"빌드했는데 왜 `grep`이 그대로 0이냐"*의 첫 번째 원인이 이것이다 |

`DEPLOY_SETUP`에 들어간 이유가 이 커밋의 판단 중 가장 실무적이다. 게이트가 생기면 **실패한
빌드가 조용히 옛 번들을 남긴다.** 배포 문서를 보는 사람은 계약을 모르고 번들만 본다.

## ④ PRIMITIVES에 프리미티브 둘이 등재됐다

**「산출물 하나에 읽기 하나·쓰기 하나, 그리고 둘이 공유하는 상수」**. 이건 이론이 아니라
**값을 치르고 배운 것**이다 — 쓰기가 리터럴 한 칸을 찍고 폭 계산만 상수를 쓰는 상태였고, 둘이
갈리는 순간 붙여넣은 격자가 통째로 한 칸 밀린다. 항목의 함정 절은 그 실측을 첫 줄에 놓았고,
재사용 조건에 이 한 줄을 달았다:

> 읽기 쪽을 나중에 붙일 계획이라면 **쓰기를 만들 때 이미 상수를 밖으로 빼 둬라**(그때가 가장 싸다).

**「선언된 라우팅 — 순서가 계약이고 조회 miss는 정상 경로다」**도 같이 등재됐다. 함정 다섯 중
둘이 이 시스템 특유의 것이다: *환경 분기로 답하지 마라(코드는 하나, 선언만 다르다)* ·
*정규화가 다른 인덱스 지름길을 쓰지 마라(없는 miss를 만들어내는데, 이 설계는 miss를 의도적으로
조용하게 두므로 그 오답이 절대 표면화되지 않는다)*.

그리고 **「아무도 돌리지 않는 하네스는 주석이다 — 게이트에 물려라」**가 형식 셋(발견식 스캔 ·
빈 스캔은 실패 · 판정은 종료 코드 하나)과 함께 들어갔다.

## 아무도 시키지 않았는데 발견한 낡은 기록 둘

이것이 이 라운드에서 **히스토리에 남길 값이 가장 큰 부분**이다. 문서 동기화의 부산물이 아니라,
동기화가 존재하는 이유다.

**① `DOE_BAND_MODEL §8`이 하네스 단언 수를 `233`으로 적고 있었다.** 실제로 하네스가 보고하는
값은 **396**이다.

```
- node contracts/doe_band_rules/client_harness.mjs      # 233 assertions
+ node contracts/doe_band_rules/client_harness.mjs      # 396 assertions (실측 2026-07-30)
```

163개 차이가 v3(marker 축)과 `ignored_headers` 집합 단언 도입으로 누적된 것인데, **문서는 그
사이 한 번도 안 따라왔다.** 같은 자리에 「`5a14e77`부터 `prebuild`가 이 하네스를 자동 실행하므로
수동 호출은 디버깅용」임도 명기됐다.

**② `docs/map_editor/README.md`에 Status 배지가 아예 없었다.** 이 저장소의 문서 규율은 배지로
「살아 있는 문서인가 · 마지막으로 언제 코드와 대조했나」를 표시하는데, 그 파일은 **그 표시 자체가
없어서 낡았는지 판정할 방법이 없었다.** 이번에 신설됐다.

둘 다 **찾으라고 지시받은 것이 아니다.** 낡은 수치와 배지 부재는 리빙 문서가 조용히 늙는 두
가지 형태이고, 아무도 안 보면 다음 사람이 `233`을 인용한다.
