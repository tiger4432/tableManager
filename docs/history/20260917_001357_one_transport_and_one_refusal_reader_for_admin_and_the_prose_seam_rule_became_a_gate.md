## 배경 — 「무엇이 잘못됐나」에 철자가 «둘»이었다

같은 물음을 두 페이지가 다르게 물었다.

```
admin.js   adminFetch 로 보내고  ->  failureFactOf -> retroFailureLine 으로 읽는다
           («이름 붙은 상수»를 가진 공용 분류기)
main.js    «맨» fetch 로 보내고  ->  문장을 «손으로» 짓는다: why = `${res.status}` (+ detail)
```

오늘 대개 두 답이 같았다는 것은 근거가 아니다. 상설 「깔끔」④ 의 판별식은
「둘이 «갈라질 수» 있나」이고, 이 쌍은 **이미 갈라져 있었다.**

🔴 그리고 수를 «인용하지 않고 쟀다.** 총괄이 앞서 말한 「55 대 4」는 아무도 센 적 없는
수였고, 실제로 세니 클라 전체에서 `/admin/**` 에 «맨» fetch 로 닿는 자리는 **정확히 하나**
(`main.js` 의 소급 실행)였다. 그 한 자리가 전송이 하는 «넷»을 전부 빠뜨리고 있었다 —
토큰 헤더 · 503 본문 · 비행 중 토큰이 바뀌었을 때의 조용한 재시도 · 단 한 번의 재요청.

## 무엇을 했나 — «옮겼고», 다시 쓰지 않았다

```
admin_token.js 로   adminFetch · withAdminToken · isGateRejection   (:88 · :57 · :49)
                    + «세대 카운터»(:71 tokenGeneration)
                    이 파일은 이미 «키와 헤더 이름»을 소유하고 있었다
config_resolve_view.js 로   failureFactOf (:150) — 이미 부르던 분류기 fetchFailureLine(:137)
                            · retroFailureLine(:166) 옆자리
두 호출 자리          이제 «import» 한다
```

세대 카운터가 전송과 «같이» 옮겨간 것이 요점이다. 사본을 두면
「토큰이 바뀌었나」에 답이 둘이 된다.

**페이지마다 다른 둘은 «주입»한다** — 그 둘은 진짜로 다르기 때문이다:

```
어떻게 묻나   어드민은 모달이 있고, 그리드 페이지는 «없다».
             아무것도 안 넘기면 «안 묻는다»
503 문장이 어디 서나  어드민은 토스트를 넘기고 자기 것을 503 에서 «누른다»
                    그리드는 «아무것도 안 넘긴다» — 거기서는 배너 «행»이 문장을 실으므로
                    토스트를 넘기면 이중이 다시 생긴다
```

## 이 커밋이 «스스로 밝힌» 것 둘

```
⚠️ 적힌 결정을 «넓혔고 그렇게 적었다»
   admin_token.js 의 머리글은 「읽기와 이름만 안다 — 묻지 않고 쓰지 않는다」고 선언돼 있었다.
   묻기·쓰기는 여전히 밖이고, «보내기»가 안으로 들어왔다.
   사유: 그러지 않으면 전송이 «둘»로 남는다
🔵 중복 하나가 «저절로» 죽었다
   admin.js 의 getAdminToken 은 admin_token.readAdminToken 과 «글자까지» 같았다.
   전송이 옮겨가자 소비자가 0 이 됐다
```

## 🔴 이음매 규칙은 «이미 쓰여 있었다 — 산문으로». 그리고 쓰인 순간부터 거짓이었다

`admin.js:91` 은 오래전부터 「`/admin/` 으로 가는 맨 fetch 를 grep 하면 아무것도 안 나와야
한다, 안 그러면 그 호출 자리는 «비인증»이고 운영에서 401 이 난다」고 적어 두었다.

```
산문은 아무것도 «막지 않는다». 그리고 그 문장은 «쓰일 때 이미 거짓»이었다 —
한 호출 자리가 그 옆으로 돌아가고 있었다
=> 이제 «단언»이다. 맨 fetch 를 되돌려 놓는 변이가 그 단언을 빨갛게 만든다
```

📌 이 부류는 이 저장소의 「가드는 도달 가능해지는 날 틀린다」가 아니라, 그 반대다 —
**규칙이 «강제되는 자리»에 없으면 거짓인 채로 살아 있다.** (CLAUDE.md 공통 원칙 ④)
