## 배경 — 무장(arming)이 무엇이었나

확정 버튼은 **두 단계**였다. 한 번 누르면 무장되고(`session.armed`), 다시 누르면 쓴다.
라벨이 「**다시 Enter로 확정**」으로 바뀌고 Esc가 무장을 푼다.

제품 소유자의 판정: **클릭이든 Enter든 즉시 확정.** 무장 단계 삭제.

| | 이전 | 이후 |
|---|---|---|
| 확정 제스처 | 2클릭 | **1** |
| 루프 전체 | 5액션 | **4** |

새 단언은 **정확히 못 박는다.** 옛 단언은 `actions <= 6`이었고, 그것은 **무장이
떠나는 것도 다시 돌아오는 것도 알아차릴 수 없었다.**

## 🔴 ① 같은 가드의 폭발 반경이 이 날 두 배가 됐다

`takesEnter()`는 유지됐다. **의미가 바뀌었다.**

이전에는 **둘 중 첫 번째** 가드였다 — 드롭다운 안의 어긋난 Enter는 **무장 하나**를
비용으로 냈고, 그건 **살아남을 수 있고 눈에 안 띄는** 비용이었다.

> 이제 그 어긋난 Enter는 **쓰기 하나**를 비용으로 낸다.
> 호출 지점에 그렇게 적었다.

`takesEnter`의 허용목록 가드는 원래 **가드 없는 판이 드롭다운 안에서 사슬의 유일한
쓰기를 도달 가능하게 만들어서** 들어간 것이다. 그 주석이 같은 날 Enter 신고를 철회하는
근거의 일부이기도 했다.

## 🔴 ② 이중 발사 변이가 레인 자신의 주장을 뒤집었다

레인은 `preventDefault`와 in-flight 플래그가 **독립적으로 실패한다**고 주장했다.
**변이가 아니라고 답했다.**

**`preventDefault`만 지웠는데 쓰기 횟수가 1로 남았다** — 남은 가드 **어느 쪽이든**
네이티브 클릭을 삼키기 때문이다.

가드는 **셋이고 겹친다**: `preventDefault` · `confirmInFlight` 플래그 ·
`renderConfirm`의 다시그리기-시-비활성화. 그런데 **「정확히 한 번 쓴다」는 단언 하나가
그 스택 전체를 채점**하고 있었다.

> **셋 중 둘이 썩어도 그 단언은 계속 통과했을 것이다.**
> 이제 **가드마다 혼자 죽는 단언이 하나씩** 있다.

## ③ 두 DOM 스텁 모두 네이티브 활성화를 모델링하지 않았다

`<button>` 위의 Enter가 **실제 브라우저가 만드는 클릭을 한 번도 만들지 않았다.**
**그래서 이중 확정이 하네스에서 보이지 않았다.**

두 스텁 다 이제 모델링한다 — **비활성화된 버튼은 활성화되지 않는다**는 것과
`dispatchEvent`가 `!defaultPrevented`를 반환한다는 것까지.

## ④ 요청이 나가는 순간 버튼이 죽는데, 그것을 위해 명시적 `render()`가 필요했다

```js
    btn.disabled = !vm.confirm.enabled || confirmInFlight;
```

명시 호출이 없으면 **다음 다시그리기는 응답 이후의 그것**이다 — 즉 **쓰기가 진행되는
내내 컨트롤이 살아 있고 클릭 가능하다.** 그리고 그것은 **모든 종료 상태 단언에
보이지 않는다.**

## 🔴 ⑤ `armed`를 지우지 않고 `confirmed`로 **바꿨다**

```js
-  return next(session, { armed: false, confirmedCount: session.confirmedCount + 1 });
+  return next(session, { confirmed: true, confirmedCount: session.confirmedCount + 1 });
```

**라벨이 되돌아오는 것이 확정이 착지했을 때 바뀌는 유일한 픽셀이었다.** 그것을 그냥
지우면 남는 것은 **눌러도 아무 답도 안 하는 쓰기 버튼**이고, 그것은 **이 화면이
반복해서 대가를 치러 온 결함 부류**다.

그리고 **소스 행을 여는 것으로는 지워지지 않는다** — 이것이 적어 둘 값어치가 있는
비대칭이다. 무장은 **반쯤 끝난 행위**라 다른 데를 보면 취소하는 것이 맞았다.
**착지한 쓰기는 반쯤 끝난 행위가 아니다.** 조작자가 자기가 방금 한 일을 확인하러 갈 때
그 확인 표시를 지우면, **「그거 들어갔나?」에 침묵으로 답하는 것**이다.

같은 교체가 **더 나쁜 대리지표 하나**도 없앴다.

```js
-  return session.armed !== true;
+  return session.confirmedCount === 0;
```

`armed`는 **양방향으로 나쁜 대리지표**였다 — 무장은 아직 아무것도 안 쓴 상태이고,
`withConfirmed`가 나가는 길에 다시 지워서 **정말로 쓴 세션이 탐색 전용으로 읽혔다.**
