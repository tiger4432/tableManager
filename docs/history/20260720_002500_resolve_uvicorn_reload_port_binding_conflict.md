# 2026-07-20 00:25:00 - Uvicorn 핫 리로드 시 포트 바인딩 충돌로 인한 서버 꺼짐 현상 수정

## 1. 개요 및 현상
* **발생 현상**: 어드민 페이지(Admin Page)에서 코드 편집 후 저장(`POST /admin/scripts/code`)하거나, `⚙️ Reload Configs & Code` 버튼을 클릭하여 시스템 핫 리로드를 유발할 때 백엔드 Uvicorn 웹 서버 프로세스가 비정상 종료(또는 다운된 상태에서 복구되지 않음)하는 현상이 있었습니다.
* **원인**:
  * FastAPI 앱 기동 시 백그라운드로 스폰되는 **`Chained Ingestion Worker`**가 PostgreSQL의 실시간 이벤트 알림을 받기 위해 `wait_for_notification` 함수를 실행합니다.
  * 내부적으로 raw connection에 대해 `select.select()`를 호출하여 타임아웃을 `30.0`초로 할당한 채 소켓 대기를 수행하고 있었습니다.
  * Uvicorn 모니터 프로세스가 코드 편집 감지 등으로 서버 프로세스를 재기동하려 할 때, 기존 프로세스는 이 30초 소켓 대기 스레드(`asyncio.to_thread`) 때문에 즉시 종료되지 못하고 메모리에 잔존하게 됩니다.
  * 이때 새로 스폰된 Uvicorn 자식 프로세스가 동일한 `8080` 포트로 바인딩을 시도하다가 `Address already in use (OSError)`를 일으키며 크래시 나고, 기존 프로세스는 뒤늦게 종료되면서 결과적으로 서버 전체가 다운되는 포트 경합 상태가 발생했던 것이었습니다.

---

## 2. 해결 방안
* **대기 타임아웃 단축 (30.0초 ➡️ 2.0초)**:
  * `server/chain_ingestion_worker.py` 내의 `wait_for_notification` 대기 타임아웃 파라미터를 `30.0`초에서 `2.0`초로 변경했습니다.
  * 이로 인해 Uvicorn이 재기동 신호를 보낼 때, 백그라운드 소켓 대기 스레드가 최대 2.0초 이내에 자원을 반납하고 안전하게 탈출(Exit)하여 이전 프로세스가 신속히 종료됩니다.
  * 새로 뜬 Uvicorn 프로세스가 포트 충돌 없이 깔끔하게 바인딩을 성공하여, 무중단/핫 리로드 기능이 의도한 대로 완벽하게 작동하게 되었습니다.
  * 2.0초의 타임아웃은 데이터베이스 부하에 영향이 전혀 없는 가벼운 빈도이며, 안정성을 극대화합니다.
