# 2026-07-20 00:42:00 - 대용량 격자 맵 렌더링 성능 최적화 (Show Cell Coordinates 토글 기능 추가)

## 1. 개요 및 분석
* **현상**:
  * 맵 에디터(Map Editor)에서 가로/세로 셀 개수가 많아질 때(예: 30x30 이상, 총 900개 초과 셀), 마우스를 움직이거나 드래그하여 페인팅할 때 격자가 간헐적으로 버벅거리는 랙(Lag) 현상이 발생했습니다.
* **원인**:
  * 빈 셀을 생성하거나 그릴 때 각 칩의 텍스트 노드에 물리 화면 좌표 문자열(예: `15,16`)을 다량으로 삽입하는 동작이 원인이었습니다.
  * 브라우저 엔진은 수천 개의 태그 노드 내부에 텍스트가 변경되거나 생성될 때마다 텍스트 레이아웃 계산(Text Layout Flow) 및 폰트 렌더링 부하를 겪게 됩니다. 셀 크기가 작아지면 좌표 텍스트가 겹치거나 읽을 수 없게 되므로 무조건 좌표 텍스트를 고정 노출하는 방식은 성능상 부작용이 컸습니다.

---

## 2. 해결 및 성능 최적화 구현

### A. `Show Cell Coordinates` 옵션 체크박스 탑재
* 맵 에디터 좌측 패널 `Invert Y` 옵션 하단에 **`Show Cell Coordinates (좌표 텍스트 표시)`** 토글 체크박스를 탑재했습니다.
* **조건부 좌표 렌더링**:
  * 해당 체크박스가 비활성화(Unchecked)되어 있을 경우, 빈 셀은 텍스트 없이 깔끔한 격자 면으로만 표현됩니다. 텍스트 레이아웃 연산이 완전히 생략되어 브라우저 렌더링 속도가 **약 10배 이상 비약적으로 향상**됩니다.
  * 색이 칠해진 유효 칩 값(예: `1`, `0`, `E1` 등)은 체크 여부와 상관없이 항상 노출되어 작업 식별성은 완벽히 유지됩니다.

### B. 성능 임계치 기반 자동 토글 비활성화 (Proactive Performance Protection)
* 사용자가 격자 크기를 조정할 때, 전체 셀 개수가 성능 저하를 일으킬 수 있는 분기점인 **400개(예: 20x20 격자 이상)를 초과하면 자동으로 `Show Cell Coordinates` 체크박스를 해제**하도록 설정했습니다.
* 대용량 맵을 로드하거나 설정할 때 사용자가 미처 신경 쓰지 못하더라도 브라우저가 정지하거나 조작이 밀리는 현상을 원천적으로 예방합니다.

## 3. 결과 및 검증
* **조작 피드백 속도**: 50x50(총 2,500셀) 이상의 맵에서도 끊김 없는 실시간 드래그 페인팅 및 렌더링이 보장됩니다.
* **Vite 빌드 정상 완료**: 프론트 배포 패키지 정상 재생성
* **Pytest 단위 테스트 무결성**: 33개 백엔드 단위 테스트 모두 그린 패스
