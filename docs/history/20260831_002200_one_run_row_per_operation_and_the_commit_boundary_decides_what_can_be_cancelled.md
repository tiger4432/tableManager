## 소유자의 문장 하나가 이 라운드의 전부다

> 「백필 돌리다 서버 렉먹는데 백필만 못꺼서 서버 재기동」

**서버를 재기동한다는 것은 다른 모든 작업을 같이 죽인다는 뜻이다.** 그래서 필요한 것은
「죽이기」가 아니라 **「멈춰 달라고 «부탁»하기」**였다.

## ① 등록부는 «두 번째 기제»가 아니었다 — 빠진 칸을 채운 것이다

`fefe2905`. 레지스트리는 이미 일반적이었다 — `chain_replay` · `withdraw` · 인리치먼트 조작
둘이 전부 `restartable` 을 선언하고 자기 드라이런을 들고 있었다. 여기서 더한 것은
**`retroactive_runs` 표 하나**이고, `publish` 가 **아웃박스 이벤트와 «같은 커밋»에** 쓴다.

```
큐 이벤트만 있고 실행 행이 없다   -> 아무도 «볼 수도 멈출 수도» 없는 작업
실행 행만 있고 이벤트가 없다      -> 영원히 queued 에 앉아 있는 행
=> 반쪽은 «둘 다 없는 것»보다 나쁘다. 그래서 한 커밋이다
```

## ② 🔴 취소는 «값을 세우고» 아무것도 죽이지 않는다 — 그리고 세션이 따로인 것이 «기제»다

```python
# server/retroactive.py — class RunControl
# 🔴 IT USES ITS OWN SESSION, DELIBERATELY, and that is the whole mechanism rather than a
# tidiness choice. The cancel flag is set by a WEB REQUEST in another process, and the
# operation is inside a long transaction of its own; reading the flag on the operation's
# session would read that transaction's snapshot and never see the flag at all. Writing
# progress on the operation's session is the mirror failure - a rollback of the batch
# would erase the record of how far the run had got, exactly when a reader needs it most.
```

**깃발을 «읽지 못하면» False 를 돌려준다** — 고장 난 질의가 지어낸 중단은 운영자에게
**요청한 적 없는 취소**로 보인다.

조작은 배치 경계에서 **훅 하나**만 받는다 — `checkpoint(processed) -> stop?` —
두 사실이 같은 순간에 속하기 때문이다: **거기가 멈춤이 안전한 유일한 자리**이고(직전 배치는
커밋됐고 다음은 안 시작했다) **진행 수가 온전한 수인 유일한 자리**다.

## ③ 🔴 다섯 중 «둘»은 못 멈춘다 — 그래서 죽은 버튼 대신 «그렇게 선언»한다

```
enrichment_confirm   큐 «전체»를 모아 confirm_keys 에 «한 번»에 넘긴다
                     -> 그 층의 훅은 «쓰기가 시작되기 전»에만 멈출 수 있다.
                        첫 순간에만 되는 취소는 «없는 것보다 나쁘다»
ledger_rescope       회수-후-재생성. 페이지 루프가 «아예 없다»
둘 다   cancellable: False
```

시험이 **모든 어댑터를 진짜 control 로 순회**하며 **선언과 배선이 «양방향» 일치**함을 단언한다 —
`False` 인데 조용히 훅을 넘기기 시작하는 것도 잡힌다. 양쪽에서 깨웠다: 깃발을 뒤집는 것과
넘김을 빼는 것이 각각 **조작 이름을 대며** 빨개진다.

`total_rows` 는 모르면 **NULL** 로 둔다. 행이 떨어질 때까지 페이징하는 조작은 시작 시점에
총수를 모르고, **0 은 「할 일 없음」으로도 「0%」로도 렌더된다.**

⚠️ 배선상의 함정 하나가 기록됐다 — **새 인자는 시그니처의 «끝»에 붙인다.**
`checkpoint` 를 중간에 끼우니 `withdraw_source` 의 `apply` 가 밀렸고,
그것을 **위치 인자로 부르는 시험이 열둘**이었다.

## ⑤ 0 이 여덟 가지 뜻이었고, 그중 하나가 «열넷이 사라진 상태»였다

`06baed9e`. 조작이 자기가 보고하는 수에 대해 **닫힌 목록에서 하나를 고르고** 화면이 그것을

지어낼 수 없다.**

```
absence   «항상» 실린다
None      「이 수는 말 그대로다」라는 «답»이지, 고르기를 잊은 것이 아니다

```

```

갈라 주는 것은     «되돌려 놓을 것이 있는가»
already_missing   두 커밋 사이에서 죽은 실행이 남긴 상태  <- 전날 밤 실제로 일어났다
```
그것을 「할 일 없음」으로 읽는 것이, **매 드라이런이 0 을 보고하는 동안 원자 열넷이 밤새

네 귀퉁이는 **단위 시험**으로 못 박았다 — 아무것도 사라진 적 없는 상자는 `already_missing`

`upper_bound` 는 반대 방향으로 거짓말한다.**

## ⑦ 한 배치로 끝나는 실행은 «시작도 안 한 것»처럼 보였다

`efaf88c1`. 배치 «하나»로 끝나는 실행은 **보고할 배치 경계가 없어서** 진행이 0 에 머물렀고,
결과는 80행이라고 말했다 — **「시작 안 함」과 「완전히 끝남」이 같은 수로 렌더**됐다.

최종 수는 **어댑터**에서 온다. 어댑터는 자기 조작의 통계 중 어느 것이 행 수인지 이미 안다.
화면이 `result` 를 파싱하게 두면 그 조작별 지식이 클라로 가고, **새 조작마다 다시 필요해진다.**

그리고 취소가 **끝에서 끝까지** 못 박혔다. 네 반쪽이 «한 시험»에 들어간 이유가 적혀 있다 —
**넷 중 셋만으로는 다른 기능이기 때문이다.**

```
① 배치 «경계»에서 멈춘다
② 멈추기 «전에» 커밋된 것을 지킨다
③ 다시 돌리면 «나머지부터» 재개한다
④ 🔴 호출이 «반환»된다 — 프로세스가 살아 있다. 죽이기로는 절대 못 얻는 것
```
배치는 `chunk_size=1` 로 «강제»했다 — 이 상자에서 가장 긴 원장 작업도 한 배치에 끝나서
**취소가 착지할 경계가 없다.** 루프가 요청을 무시하게 만들면 시험이 빨개진다.

## 아키텍처 영향

- `retroactive_runs` 표가 생겼다. 요청형 조작 하나에 실행 행 하나이고,
  **아웃박스 이벤트와 같은 커밋**에 쓰인다.
- 취소는 **협조적**이다: 값을 세우고, 조작이 배치 경계에서 읽고 스스로 멈춘다.
  `RunControl` 은 **자기 세션**을 쓴다.
- **`cancellable` 은 커밋 단위가 정한다.** 페이지 루프가 없거나 한 번에 넘기는 조작 둘은
  `False` 로 «선언»되고, 시험이 선언과 배선의 양방향 일치를 잰다.
- 전진 스캔(백필)이 레지스트리 조작이 됐다 — 소유자가 말한 바로 그 조작이다.
- 「없음」을 말하는 어휘가 **여섯으로 닫혔고**, 조작은 그 목록을 «가리킨다».
- `chain_replay` 가 `business_keys` 로 좁혀지고, `cli` 문자열과 파라미터의 일치가
  **부류 단위 시험**으로 강제된다.

## 그때 남아 있던 것

- `enrichment_confirm` 과 `ledger_rescope` 는 **멈출 수 없다.** 죽은 버튼이 아니라
  `cancellable: False` 로 선언돼 있다.
- 체크포인트가 `False` 를 돌려줄 때 실행이 계속되는 방향은 **직접 안 쟀다.**
  `checkpoint=None` 과 같은 갈래라는 것이 근거로 적혔다.
- `ledger_rescope` 의 회수/재생성은 여전히 **커밋이 둘**이다. `already_missing` 은 그 사이에서
  죽은 실행을 «말하는» 낱말이지, 그 창을 없애지 않는다.
- 이 항목 작성 시 재측정: `tests/test_ledger_gaps.py` + `tests/test_retroactive_admin.py`
