# 맵퍼를 «부르는 자리»가 자기 집을 얻었다

> **커밋:** `236b24e9` (09-13 15:58)
> **일자:** 2026-09-13 (오후, 셋째 묶음)
> **레인:** 구현자(서버) · 응용(문서)
> **측정 상자:** 이 워크스테이션. **운영이 아니다.**

## 무엇이 일어났나

**실행기는 «하나»였고, 집이 틀렸다.** `execute_custom_mapper` 는 저장소에 한 벌이고 그
docstring 이 스스로 「모든 커스텀 맵퍼가 지나는 유일한 자리」라 적는데, 그 자리가 **워커의 집**에
살아서 **재생이 맵퍼를 돌리려면 워커를 import 해야 했다**.

```
새 집    server/chain/mapper_call.py   253줄   (S-214 `236b24e9`, 판정 370)
옮긴 것  execute_custom_mapper :88 + 그것만 쓰는 여섯 + MAPPER_LOG_TAG :46
워커     3,366 -> 3,166줄.  재구현 «0» · 재수출 «0»
남은 엣지 재생 -> 워커는 `load_chain_rules` «하나»뿐 (판정 358)
```

## 🔴 전제가 바뀐 것이 이 라운드의 값이다

처음 적힌 문장은 「한 실행기가 «둘»로 쪼개졌다」였다. 실측은 그게 아니었다 —
**«공용 프리미티브가 한 호출자의 집에 살았다»**. 고칠 것이 「합치기」가 아니라 「내리기」이고,
그 둘은 다른 일이다.
🔵 **S-211 ① 의 `withdraw_source` 와 같은 기제, 반대 방향**이다 — 그때는 철회가 재생의 집에
살면서 실행기가 그것을 썼다. **처방은 둘 다 「두 호출자보다 «아래»로」**다.

## ⚠️ 옮기지 «않은» 것을 이름 대는 것이 이동의 절반이다

```
트랜잭션   재생의 «청크 커밋» · 워커의 «그룹 트랜잭션» — 그 «호출자»의 성질이라 안 옮겼다
로그 파일  `LOG_FILENAME = "chain_worker.log"` :34 — 여기서 둘로 나누면 한 런의 줄이
          두 파일로 쪼개진다. 옮긴 것은 「맵퍼를 «어떻게» 부르나」 하나다
```

## 🔴 그리고 이동이 «두 계기»를 고장 냈다 — 둘 다 모집단 문제였다

```
① 새 게이트가 «자기를 못 봤다»
   「실행기 정의가 저장소에 하나」를 `git grep` 으로 셌더니 «0» — 새 모듈이 아직 «미추적»이라
   `git grep` 이 그것을 못 본다. 같은 게이트가 커밋 «전» 0, «후» 1 이다
② 기존 가드가 «한 파일만» 훑었다
   `test_finish_still_has_exactly_one_caller` 가 `chain/ingestion_worker.py` 하나만 봐서,
   `registry.finish` 호출이 그 파일 «밖»으로 나가자 못 봤다
```
🔴 **둘 다 「게이트가 틀렸다」가 아니라 「게이트가 다른 집합을 재고 있다」**이고, 둘 다
**«초록으로» 나타난다** — 0 은 「중복 없음」으로 읽히고, 한 파일 스윕은 「호출자 하나」로 읽힌다.
📌 부류: **모집단을 «색인»이나 «파일 하나»로 잡은 게이트는, 이사 가는 날 조용해진다.**
🔵 이 부류를 `HARNESS_DISCIPLINE_GUIDE.md` §5-septies 에 적어 뒀다.

## ⚠️ 구현자가 자기 실수 하나를 «부류로» 적었다

첫 이동이 **부분 측정**이었다 — 실행기가 «자기 모듈에서» 쓰는 이름만 재고 **그 헬퍼들이 쓰는
이름을 안 쟀다**. `_missing_as_none` 에서 깨지고, 고치니 `_is_missing_scalar` 에서 또 깨졌다.
고침은 **전이 폐포를 한 번에 계산**하는 것이었다 —
🔴 **「실패를 하나씩 쫓는 것은 «계기»가 아니다」.**
