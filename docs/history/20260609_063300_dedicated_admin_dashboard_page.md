# 변경 이력: 독립형 어드민 대시보드 웹페이지(admin.html) 및 관리용 API 구축

- **작성일**: 2026년 6월 9일
- **작성자**: Antigravity
- **상태**: 완료

## 1. 개요 및 목적
- **현상**: 앞서 Outbox 체인 처리 장애 극복을 위해 3회 리트라이 후 `FAILED` 상태로 이벤트를 격리하고, 이를 재처리(Replay)할 수 있는 API를 개설하였습니다. 그러나 백엔드 API만으로는 관리자가 어떤 이벤트가 왜 실패했는지 에러 트레이스백을 한눈에 식별하기 곤란했으며 재처리 트리거 실행이 어려웠습니다.
- **해결 방안**:
  1. **독립 어드민 웹페이지 구축 (Option B)**: 메인 서비스와 분리된 `/admin` 경로로 접근할 수 있는 전용 어드민 웹페이지 `admin.html` 및 클라이언트 로직 `admin.js`를 개발했습니다.
  2. **에러 원인 분석 뷰 탑재**: 실패한 Outbox의 UUID, 테이블명, 타입, 리트라이 횟수를 표기하고 선택된 행의 원본 Payload와 Stack Traceback을 우측 Diagnostics 영역에 깔끔한 코드 포맷으로 노출하여 장애 원인 분석 편의를 더했습니다.
  3. **원클릭 단건 및 일괄 재처리**: 개별 실패 레코드에 대한 단일 리트라이 버튼과 대기열 전체를 원복시키는 "Retry All" 버튼을 탑재하여 운영 편의성을 높였습니다.
  4. **메인 앱 연동**: 메인 UI의 툴바 우측 상단에 "⚙️ Admin" 바로가기 버튼 링크를 추가해 유기적인 화면 전환을 제공합니다.

## 2. 세부 변경 사항

### 백엔드 (`server/main.py`)
- `GET /admin/outbox/failed` API 신설: 격리된 실패 레코드들의 메타데이터와 payload 에러 로그 정보를 통합 조회 및 페이징 반환합니다.
- `POST /admin/outbox/retry-failed` 수정: `event_id` 선택적 파라미터를 수용해 전체 리플레이뿐만 아니라 단건 이벤트의 핀포인트 복원도 지원합니다.
- `@app.get("/admin")` 및 `@app.get("/admin.html")` 정적 파일 라우트 추가: 어드민 페이지 요청 시 프론트 빌드 경로의 `admin.html`을 파일 응답합니다.
- SPA Fallback 정적 라우트 예외 가드에 `/admin`을 추가해 브라우저 404 라우팅 충돌을 차단했습니다.

### 빌드 설정 (`client2/vite.config.js`)
- `build.rollupOptions.input` 옵션을 추가하여 빌드 번들러가 `index.html`과 `admin.html` 두 개의 멀티 진입점을 함께 컴포넌트 빌드하도록 수정했습니다.

### 프론트엔드 UI (`client2/admin.html`, `client2/src/admin.js`)
- **`admin.html`**: 메인 페이지 스타일을 계승하여 반투명 Glassmorphism과 다크 모드 테마를 구현한 레이아웃을 작성했습니다. 좌측은 테이블 리스트, 우측은 진단 영역(Traceback + JSON)으로 화면을 분할했습니다.
- **`admin.js`**: 실패 이벤트 비동기 조회, 단건/전체 재처리 API 비동기 통신, JSON 클립보드 복사 기능 및 깔끔한 Toast 피드백 애니메이션을 구축했습니다.
- **`index.html`**: 메인 툴바 우측에 어드민 페이지 이동용 `⚙️ Admin` 글래스 링크 버튼을 추가했습니다.

## 3. 검증 결과
- **컴파일/구문 검증**: Python 백엔드 및 Vite 빌드 빌더가 컴파일 에러 없이 `dist/admin.html` 및 번들 리소스를 올바르게 산출함을 검증 완료했습니다.
- **동작 안정성**: 메인 페이지에서 Admin 바로가기를 눌러 어드민 페이지로 이동하고, 실패 레코드의 에러 로그를 확인한 뒤 원클릭 리플레이를 수행해 데이터가 `PENDING` 상태로 정상 원복되는 런타임 신뢰성을 논리적으로 보증합니다.
