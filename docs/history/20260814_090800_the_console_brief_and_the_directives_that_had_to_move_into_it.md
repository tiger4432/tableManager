## 지시서 (`9e11bac`) — 사용자가 시나리오를 직접 돌린다

소유자 지시: 세 시나리오를 사용자가 직접 구동하게, 온톨로지는 효율적으로 세팅되고
분석이 액션으로 흐르게, 사람이 쓸 수 있게. 착지 순서의 목표 넷: 질문 API 셋(기저율
있는 형제 / 검사 런 분모의 레시피 비교 / 모델 워크리스트)을 심은 답안지에 검증;
기존 추적 페이지의 «성장»으로서의 조사 콘솔; 액션 축 — **웹 프로세스의 첫 원장
쓰기**로서 결정답게 취급(같은 게이트·같은 스토어·request-id 멱등·가역 액션 종류만);
비교·워크리스트 뷰는 같은 콘솔의 질문 유형. 상설 규칙 셋: **한 질문은 한 URL**(답이
링크다); **분모·basis·asserter 없는 수는 싣지 않는다**; 셋업 대시보드는 config 쓰기
판정에 따라 읽기 전용.

## 일반화 (`9cbc413`) — void는 예시였다

케이스-컨트롤 콘솔은 **finding kind로 파라미터화**되고 void는 특례가 아니라 기본
뷰다 — 통합 `observed` 어휘가 정확히 이것을 위해 지어졌으므로. 조심할 자리는 분모:
「clean」은 그 kind를 볼 «수 있었던» 방법에 상대적으로만 정의되므로, kind별
시그니처가 어느 방법의 검사 런이 스캔 모집단을 정의하는지 선언하고, 런 분모가 없는
kind는 조작된 clean 대신 「분모 없음 — 대조 불가」 패널을 받는다. 답안지는 자기
인자를 가진 둘째 심은 kind를 얻는다 — kind 전환이 각자의 진실을 찾는 것이 단언이
되도록.

## 이동 (`8a1d339`) — 메시지에만 사는 지시는 내려진 것이 아니다

구현 세션은 얼어 있지 않았다 — **긴 턴 중간**이었고, 큐된 메시지는 턴 경계에서만
배달되므로 당일 지시 넷(분석 목표·완료 목록 딸린 기한·케이스-컨트롤 콘솔·일반화)이
어제의 큐를 계속 실행하는 세션에게 보이지 않았다. 판정 파일 교훈이 지시에도 적용됐다:
0-bis 섹션이 오늘의 정본이 되고, 읽었음을 보드에 마킹하라고 요구해 메시지가 못 닫는
루프를 닫았다.
