## 배경 — 목적지를 고르면 follow 집합이 «떨어져 나온다»

`2372ed0a`가 선언만 읽는 타입 그래프를 세웠다 — **타입 8 · 엣지 12**, 한 질의, 모든 쌍의 모든
경로를 약 3밀리초. 무방향인 이유는 **walk 이 무방향이기 때문**이고, 길이 상한이 「타입 수 −1」인
이유는 **단순 경로가 그보다 길 수 없기 때문**이지 목록을 짧게 하려고 고른 수가 아니다.

그것을 짓다가 **살아 있는 결함**이 드러났다:

```
follow 체크박스가 «버전 붙은» 술어 이름을 보내고 있었다
   inspected    -> 200
   inspected@1  -> 422
=> 상자를 «체크한 사람은 전부 거절»을 받았다
```

라벨은 선언의 철자를 유지하고 **전선에서만 벗긴다.**

## 🔴 자기 루프를 뺀 것이 잘못이었다 — 그리고 그것이 원장에서 «가장 큰» 술어였다

첫 판에서 경로 그래프가 `a != b`로 자기 루프를 뺐다. 그런데 타입 수준에서 자기 루프인 술어
다섯이 **정확히 계보 술어들**이었다:

```
transfer  401,206 원자   ← 원장에서 가장 큰 술어
bonded_from · slot_map · leads_to · derived_from
```

반복이 그것들의 **뜻 자체**이므로 되돌아왔다. 그 결과 die → defect_kind 경로가 **2에서 15로**
늘었고, 새로 생긴 것 대부분은 **follow 집합이 같고 홉 수만 다른** 것들이었다 — 즉 **사용자 축이
경로의 옷을 입은 것**. follow 집합으로 접고 최단 홉을 「이 경로가 요구하는 것」으로 남겨
**쌍 전체 221 · 한 쌍 최대 10**이 됐다.

`0425113b`가 함께 기록한 것: **홉 상한은 답을 다듬지 않고 «지운다».** 웨이퍼에서
`inspected·observed·of_kind`를 따라가면 `defect_kind`는 **홉 3에서만** 나타난다. hops=2로
「이 웨이퍼에 어떤 결함 종류가 있나」를 물으면 0이 돌아오고, 그 0은 **「거기까지 못 갔다」**인데
**「없다」와 똑같이 그려진다.** 그래서 hops 는 고른 «상한»이 아니라 **고른 «경로»가 요구하는
값**이 되어 경로와 함께 실려 간다 — `42a56184`이 「hops 가 아예 안 실리고 있었다」를 고쳤다.

같은 커밋이 **순위는 거리가 아니다**를 기록해 뒀다: 실측상 깊이 2 후보가 깊이 1과 reach 1.0으로
동률이고, `_reach` 자신의 주석이 **전차수로 나누는 것은 이름만 바꾼 길이 감쇠**라고 적고 있었다.

## 🔴 그리고 소유자가 내 측정을 «증거가 아니다»라고 판정했다

`1afeaf47`이 옮긴 소유자 지적: **홉 수는 원장에 달렸다** — 여러 번 split 한 웨이퍼는 `slot_map`
이력이 길고, 그것을 걷는 데 홉을 쓰는데 **그 이력이야말로 보려던 것**이다.

여기서 잰 체인이 1~2홉인 것은 **씨앗 픽스처의 성질**이지 제품의 성질이 아니다. 게다가 첫 시도가
「전부 1홉」이라고 보고한 이유는 **계측기가 서로 다른 JSON 직렬화 둘을 비교**했기 때문이었다.

설계 결론은 그와 무관하게 선다:

```
다른 것으로 «옮기는» 술어   wafer -> die · wafer -> quantity   = 거리
같은 것을 «잇는» 술어       slot_map · derived_from · transfer · bonded_from  (전부 X -> X)
                          = 그 자재 자신의 이력
```

그 자리에서 **서버가 오늘 이 구분을 하지 않는다(hops 가 엣지를 센다)**는 것을 명시하고,
**화면에서 흉내 내지 말고 줄을 보고하라**고 레인에 내렸다.

## 선언이 말한다 — 도출 둘을 «먼저 재고» 버렸다

`4cbcb086`. 소유자 판정은 「술어지」였고, 그 전에 필드를 안 만들어도 되는 도출 둘을 실측했다:

```
subject/object 타입 동일         8 / 11   (leads_to · quantity->quantity 를 «자재 걸음»이라 부른다)
양끝이 «자재 엔터티»             11 / 11   — 단, «오늘의» 어휘에 대해서만
```

11/11 쪽을 안 고른 이유가 기록됐다: **계보가 아닌 미래의 die→die 술어를 막는 것이 아무것도 없다.**
**우연히 맞는 규칙은 도달 가능해지는 날 틀린다.** 그래서 선언이 말한다.

```python
# server/ledger/setup_bundle.py — _validate_vocabulary
if not problems.exact(
        item, path, required=("status", "subjects", "object"),
        optional=("continues",)):
    continue
if "continues" in item and not isinstance(item["continues"], bool):
    problems.add("invalid_predicate", f"{path}.continues", "must be true or false")
```

**선택이고, 부재는 false 이며, 안 쓰는 config 에는 안 적힌다** — 「선언해서 껐다」와 「고려한 적
없다」가 갈라져 있어야 하기 때문이다.

파일 셋이 **같이** 움직여야 했다: 검증기가 모르는 필드를 거절하므로 라이브 선언이 플래그를 실을 수
없다. 검증기 · 골격 문서 · 라이브 config(추적 안 됨). 라이브가 표시한 여섯 —
**derived_from · slot_map · has_wafer · inspected · transfer · bonded_from.**

**온톨로지 탐색기는 클라 변경이 0이었다** — 폼이 `/authoring/schema`가 내주는 골격에서 생성되므로
문서에 잎을 더한 것만으로 컨트롤이 생겼다.

## walk — `depths`는 그대로 두고 «출발»을 따로 센다

```python
# server/ledger_api/ledger_subgraph.py
_charge = 0 if _bare_predicate(atom.predicate) in continuing else 1
if subject_near and not target_near and target is not None:
    _spend(subject_id, target["id"], _charge)
elif target_near and not subject_near:
    _spend(target["id"], subject_id, _charge)
```

`dep_cost`는 **두 번째 깊이가 아니라 두 번째 예산**이다. `depths`는 뜻이 안 바뀌므로 절단 시험 ·
`hops_reached` · 증거 자취 · 클라가 **전부 그대로** 돈다. 최솟값을 유지하는 이유는 `add_node`가
최소 깊이를 유지하는 이유와 같다 — 비싼 경로가 싼 경로가 이미 낸 노드를 은퇴시키면 안 된다.

`DEFAULT_CONTINUES_HOPS = 0`이 **일부러**인 이유: 그날 선언이 이미 여섯을 표시했으므로 다른
기본값은 **축을 도입한 바로 그 커밋에서 기존 모든 답을 바꿨을 것**이다.

## 🔴 게이트가 기대한 자리에서 축이 «안 보였고», 그 이유를 재서 적었다

```
씨앗 SYN-BW-101-16 · direction=both · node_limit=1000
hops=6, 파라미터 없음 / =0 / =12   -> 노드 754 · 엣지 1200 · hops_reached 2 · 절단 claims+edges
                                    셋 다 이전 줄과 «동일»
```

논증이 아니라 측정으로 이유를 남겼다: **그 파라미터에서 walk 은 깊이 2에서 엣지·claim 에 묶여
있고 홉 예산을 아예 안 쓴다.** 홉에 묶이게 만들어서 축이 도는 것을 보였다:

```
hops=1 continues_hops=0   노드  40 · hops_reached 1 · 절단 depth
hops=1 continues_hops=4   노드 157 · hops_reached 3 · 절단 없음
```

## 아키텍처 영향

- **술어에 `continues`라는 선택 불리언이 생겼다.** 걸음이 같은 자재 위에 머무는지를 **선언이**
  말하고, 코드 어디에도 술어 이름이 안 적힌다. 읽을 수 없는 선언은 **빈 집합**을 돌려주므로
  그때의 walk 는 «추측»이 아니라 **그 전과 같은 walk**다.
- walk 에 **두 번째 예산 축** `continues_hops`가 생겼다. 루프는 `hops + continues_hops`까지 돌고
  절단 시험 둘이 그 천장으로 옮겼다.
- 타입 그래프와 경로 열거가 **선언만** 읽는다. 목적지를 고르면 follow 집합과 홉 수가 따라온다.
