# One worklist API, and the triangle that defines missing

**Date:** 2026-08-14 13:13 ~ 13:25 · **Domain:** 프로세스(본질 정본 — 결측·워크리스트) · **Status:** 기록만 — `92d081b`, `687c31c`, `663abef`, `9d76332`

---

12분짜리 소유자 문답 하나가 네 커밋으로 정본화됐다 — 결측 워크리스트의 통일과,
그 통일이 즉시 불러온 세 질문.

## 단일화 (`92d081b`) — 결측은 탐지되지 않는다, 이미 배출되고 있다

소유자 지시 「모든 기능이 하나의 API를 경유하게」에 대해, 설계는 결측의 정의를
새로 만들기를 거부한다 — 엔진이 이미 세 곳에서 구조적으로 뱉는다: 걷기의 미해소
홉 · 3분할의 미검사 · 대조의 결측 부류. **워크리스트 = 세 공급원의 합집합을
액션 점수로 정렬한 것, API 하나** — enrich 화면·fill_missing 액션·질문 현황판이
같은 응답을 소비하고, 새 술어·kind가 선언되면 워크리스트는 코드 0줄로 자란다.
경계 하나가 지켜졌다: 통합은 읽기 축이다 — enrich의 확정 쓰기는 소스 레이어
경로 유지, 원장은 발화의 기록이지 소스 상태의 주인이 아니다.

## 분업 (`687c31c`) — 질문의 문법은 원장, 쓰기의 문법은 소스

추적 타입은 enrich config를 따르지 않는다: 홉이 무엇인지는 원장 어휘가 정본이고
enrich config는 확정이 앉을 소스 자리 선언으로 축소된다. 다리는 새 매핑이 아니라
**번역 선언의 양방향 읽기** — 소스 행을 주장으로 만든 선언을 거꾸로 읽으면
확정의 착지 자리가 나오고, 사본이 없으니 어긋날 수 없다. 걷기 스코프도 질문마다
지정하지 않는다 — 어휘·술어 선언·질문별 유도의 3겹 선언이 만들고, **기능 코드가
「무엇을 걸을지」를 쓰면 그게 위반 신호다.** (실측 동반: 관측 102,177원자 유입
0건, 5.2ms.)

## 삼각형 (`663abef`) — 좁은 걷기가 유니버셜한 이유

소유자가 「혈통만 걷는 건 MI 채움엔 너무 좁지 않냐」고 눌렀고, 답은 삼각형이다:
**골격**(걷기 — 신원 변화만, 일부러 좁게) · **주석**(무슨 일이 있었나) ·
**기대**(선언 — 무엇이 있어야 했나). 결측 = 기대 − 실재 주석. 미해소 홉은 신원
결측, MI 결측은 주석 결측 — 공급원이 다를 뿐 같은 워크리스트다. 측정 계획
선언(MI 묶음, 소유자 「나중에」)이 착지하는 날 워크리스트가 코드 추가 없이 MI
결측을 뱉기 시작한다.

## 증식 규율 (`9d76332`) — 선언은 늘어도 파일은 늘지 않는다

측정 계획이 config 디렉터리를 익사시킬 것이라는 소유자 우려에, 같이 자라던 두
수를 분리했다: ① 새 파일 금지 — 새 선언은 자기가 서술하는 선언의 **필드**로
② 구조 뷰의 선언 지도가 관리 화면 — 안 물리는 미끼 선언이 드러나 가지치기
③ 선언 신설 3문 게이트(기존 필드로 못 들어가는가 / 소비자가 있는가 / 구조 뷰에
뜨는가). 기존 config 간 중복 통폐합은 MI 묶음의 선행 빚으로 대기열 등재.

## 그때 남아 있던 것

- 네 커밋 전부 문서다. 단일 워크리스트 API는 이 시점 미구현(브리프 R5로 오후에
  빌드 단위화), 측정 계획 선언·MI 번역 묶음은 소유자 연기 상태.
