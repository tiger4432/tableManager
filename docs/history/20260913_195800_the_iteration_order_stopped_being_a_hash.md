## ① 트리거 표 순회가 «말해진 순서»가 됐다 (S-228 `2df0b798`, 판정 385 ㉡)

```
종전   집합의 순서 — 문자열 집합은 «파이썬이 프로세스마다 섞는» 해시가 정한다
실측   이 상자, PYTHONHASHSEED 미설정: 표 이름 «여섯» · 다섯 프로세스 -> 순서 «다섯 가지»
결과   트리거 표 «둘»을 든 그룹은 재기동마다 «달라질 수 있는» 순서로 규칙을 돌았다
       — 그리고 아무것도 그 사실을 말하지 않았다
오늘   trigger_tables_in_order(events) :987 — 정렬
```
🔴 **이 항목에서 제일 값진 것은 측정을 «두 번» 한 것이다.** 이름 «넷»을 세 프로세스에서
돌렸을 때는 **전부 같았다.** 거기서 멈췄으면 「결정적이다」가 나왔을 것이고, 그것은
**표본이 답을 정한 결론**이다. 여섯 이름짜리 실행이 참인 쪽이다.
📌 부류: **「같은 답이 나왔다」는 「같은 답이 나온다」가 아니다** — 표본이 작으면 비결정이
«결정처럼» 보인다.
⚠️ 정렬이 «임의»라는 것도 적혀 있다 — 「도착 순서」는 아웃박스 id 순이라 **둘째 축**이 되고,
그러면 답이 「쓴 쪽이 커밋을 어떻게 쪼갰나」에 의존한다. 여기서 필요한 것은
«모든 프로세스가 같은 답»뿐이고, 그래야 규칙 순서(S-156)가 «설 자리»가 생긴다.

## ② 합친 단위의 시도 수 = «구성원의 최대» (S-227 `36ed2500`)

```
종전   격리된 절반(retry_count 2)과 처음인 절반(1)이 한 그룹
       -> 한쪽 FAILED · 다른 쪽 RETRYING · 로그는 「(2/2)」
       = 한 «단위»가 «두 상태»를 가졌다
오늘   max_retry_num = max(max_retry_num, event.retry_count)   :2008
```
🔵 S-153 이 「합친 단위는 실패도 하나」라고 적었는데, **시도 수가 그 문장을 아직 안 지키고
있었다** — 같은 라운드의 다른 절반이다.

## ③ 클라 셋 — 대조만 했다

`frontend.md` 는 클라 레인이 이미 썼고, 이 라운드는 CODE_MAP §7 을 «대조»했다:
세 라운드가 건드린 `client2/src` 파일 **여덟이 전부 행을 가진다.**

### ⚠️ 대조하다 만난 함정 — 지시가 준 해시가 «병합 커밋»이었다
```
d3c97b75  = Merge remote-tracking branch 'origin/design'   (부모 둘)
git show --name-only d3c97b75   ->  «빈 결과»
```
🔴 **그대로 읽으면 「C-101 은 소스를 안 건드렸다」가 되고, 그것은 거짓이다.**
`-m` 을 붙이거나 착지 쪽 부모(`70a4c115`)를 봐야 파일이 보인다.
📌 부류: 제 기억 파일에 이미 있는 줄이다 — **「빈 결과는 «없다»가 아니라 «이 질의가 아무것도
못 짚었다»일 수 있다」.** 오늘은 그것이 «해시의 모양»으로 나타났다.

## ④ 그리고 체인 기저 라운드가 닫혔다

```
착지한 규칙 칸 «넷»   max_group_rows(S-153) · group_by(S-154) · idempotent(S-155) ·
                    max_group_attempts 가 «규칙에서 읽히게»(S-221)
순회 순서            유도된다(S-228) — 다만 «워커가 규칙 순서를 읽는 것»은 S-156, 미착지
```

그 본문은 gitignore 라 제품이 못 보고, 그래서 **제품이 자기 동작을 말할 수 없었다.**
