## 🔴 잘라쓰기를 정당화하던 머리글이 «거짓»이었다

그 파일의 머리글은 이렇게 적혀 있었다 — `admin.js` 는 「import 할 수 없다(CSS 를 끌고 오고
모듈 최상단에서 document 를 건드린다)」.

```
그런데 probe_hooks.mjs 가 `.css` 를 «빈 모듈»로 풀기 시작한 이래
chain_rule_user_path_harness 는 «그 파일을 통째로 import 하고 있었다»
그리고 C-121 에서 나 자신이 또 그렇게 했다
=> 낡은 문장 하나가 «금지된 기법을 살려 두고» 있었다
```

📌 이 저장소가 이미 겪은 부류다 — 2026-09-07 에 `map_editor.js` 의 CSS import 가 사라졌는데
「그래서 import 안 된다」는 문장이 사흘 낡은 채 지시를 만들고 있었다. **같은 병이 하니스
머리글에서 났다.**

## 🔴 그리고 그 비용은 «주장이 아니라 실측»이다

옛 술어 넷을 복원해, `errorText(r)` 을 부르고 답을 «버리는» 변이
(`if (autoFailure && false)`)에 돌렸다.

```
옛 검사 넷이 «전부 true» 를 돌려준다
  텍스트에 여전히 errorText( 가 있다 · absentPath( 가 있다 ·
  failedTotal !== null 이 있다 · warn 갈래가 있다
🔴 그 변이가 «이 파일이 존재하는 이유인 바로 그 결함»이고, 잘라쓰기 판은 그것을 초록으로 찍었다
=> 새 파일에서 M2 이고, «잡힌다»
```

## ⚠️ 남은 잘라쓰기의 «수»는 «내지 않았다»

```
기계적 화면 둘이 «서로 어긋났다» — 하나는 31 파일, 다른 하나는 3 파일
그리고 둘째는 redo_banner_harness 를 «잘못 분류»했다 (내 import 가 그것을 죽여서 잘라쓰기임을 안다)
=> 이 모집단을 가르려면 «읽어야» 한다. 내가 못 서 있는 수는 없느니만 못하다
```
