> | **일자:** 2026-09-05
> **레인:** 구현자(서버) · 클라

## 배경 — 자기가 만든 결함이고, 하필 «가장 비싼» 부류였다

이 레인이 앞서 `retroactive` 실행 표에 `runner` 컬럼을 더했다. 마이그레이션이 아직 안 돈
배포에서는 `_mark_run` 의 UPDATE 가 매번 `UndefinedColumn` 을 던진다. 그런데 그 자리의
`except` 가 그것을 **debug 수준으로 삼켰다.**

```
결과   실행 행은 `queued` 에 머물고 `started_at` 이 안 찍힌다
사실   작업은 «그동안 내내 돈다»
화면   「대기 중」
```

🔴 **이 날 하루가 지우고 있던 바로 그 부류이고, 그중 가장 비싼 모양이다** — 틀린 수가
하필 **운영자가 「한 번 더 누를까」를 정할 때 보는 수**다.

## 변경 내용

### ① 실패가 «시끄러워지고», 값으로도 나간다 (`2a082d11`)

```
로그   ERROR 로 올라가고, 어느 실행인지와 「마이그레이션이 원인일 것」을 같이 말한다
      ⛔ 그래도 «던지지는 않는다» — 장부 기록 실패가 실행을 죽이는 것이 더 나쁘다
값     `queue_view` 가 `record_failures` 를 «발행»한다. `gate_blocked` 와 같은 모양
      이유: 아무도 안 보고 있는 로그 줄은 «자리만 바뀐 침묵»이고,
           이 실패는 그 응답의 «다른 모든 수»를 낡게 만드는데 그걸 감지할 것이 없다
경계   목록은 «상한»이 있다 — 깨진 배포에서 영원히 자라기 때문
```

시험 다섯: 수준 · 실행이 살아남는가 · 사실이 «전달»되는가 · 빈 값이 정상 답인가 · 상한.

### ② 큐 패널의 «첫 줄»이 「집어 가는 것이 있나」가 됐다 (`7ac66098`)

재료는 **이미 이 패널이 받는 응답 안**에 있었다. `last_pickup` 의 클라 참조가 **0** 이었다.

첫 줄이 된 근거는 서버가 «잰» 것이다:

```
대기 시간은 «두 봉우리»다 — 한 틱이거나, 무한. 그 사이가 «없다»
=> 「큐가 얼마나 긴가」로는 «곧 돈다»와 «아무도 안 집어 간다»가 안 갈린다
   마지막 집어 간 시각의 «나이»는 그것을 가른다
   짧은 큐 + 오래된 pickup 이 «빈 큐처럼 보이던» 그 상태다
```

세 상태다 — **한 번도 안 집어 간 것은 「0초 전」이 아니다.** 그렇게 그리면 운영자가 필요한
것의 **정확히 반대**를 단언한다. 대기 개수는 «서버의 수»를 쓴다(목록이 최신순으로 잘려서,
배열을 세는 화면은 «더 적게» 보고하면서 멀쩡해 보인다). 고아 실행의 `unknown` 은
**판정 불가로 그대로 나른다** — 다른 기계의 pid 를 여기서 죽었다고 부를 수 없다.

🔴 **일부러 «없는» 것 셋** — 예상 시작 시각 없음(두 봉우리의 간격이 백 배다) · 지어낸 진행률
없음 · **판정 낱말 없음.** 「멈춤」이라고 부르려면 문턱이 필요한데 **아무도 선언한 적이 없다.**
그리고 그 금지를 주석이 아니라 **하니스 단언**이 붙들었다(도는 큐와 선 큐 양쪽으로).

### ③ 그 문턱이 «선언에서» 나와 같이 실렸다 (`d69412a9`)

```python
def _hb_stale_after():
    """The existing "silence has lasted long enough" constant. Read, never redefined."""
    from utils import heartbeat as _hb
    return _hb.DEFAULT_STALE_AFTER_SEC
```

새 문턱을 만들지 않았다 — **이 시스템이 이미 가진** 「침묵이 충분히 길다」의 답을 읽는다.
그리고 «오해될 자리»가 코드에 적혔다:

```
문턱은 나이 «혼자»에 대고 읽으면 아무 뜻이 없다
쉬는 큐는 «가장 평범한 이유»로 오래된 pickup 을 갖는다
=> 짝이다:  waiting_count > 0  AND  last_pickup_age_seconds > stall_after_seconds
값은 나가고 «읽기는 화면의 것»으로 남는다. 쉬는 경우를 시험이 못 박아,
   나중에 누가 이것을 «경보로 고치는» 것을 막는다
```

## 아키텍처 영향

- `/admin/chain/queue` 의 `queue_view` 가 이제 **네 값을 같이 낸다** — 마지막 pickup 시각·나이,
  picker 주기, 대기 수, 그리고 이 커밋에서 더해진 `stall_after_seconds`.
  판정 낱말은 **서버에도 화면에도 없다.**
- 장부 기록 실패가 **로그와 응답 양쪽**에 산다. 응답 쪽이 정본인 이유는 위에 적힌 그대로다 —
  이 실패는 같은 응답의 다른 수들을 조용히 낡게 만든다.
- ⚠️ `7ac66098` 커밋 본문은 그 상수를 `heartbeat.DEFAULT_STALL_AFTER_SEC` 로 적었다.
  실제 이름은 `utils.heartbeat.DEFAULT_STALE_AFTER_SEC` 이고, 26분 뒤 `d69412a9` 가
  그 이름으로 읽어 갔다.

- 🔴 **「멈춤」이라는 낱말은 이 시점에 «아무 데도 없다».** 문턱은 이제 응답에 실려 있고,

  조용히 실패하는 곳이 또 어디인가」는 **따로 재고 여기 접지 않았다.**
- `record_failures` 목록은 상한이 있다. 상한에 닿았을 때 **몇 건이 잘렸는지 말하는 값은
  이 커밋 시점에 없다.**
