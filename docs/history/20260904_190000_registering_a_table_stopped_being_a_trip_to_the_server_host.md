## 배경 — 「어드민 라우트가 `table_config.json` 을 쓴다」가 «0» 이었다

표를 하나 더하려면 **서버 호스트의 파일을 편집**해야 했다.

```
🔴 그러면 완성 규칙의 «두 줄»이 «세 줄»이 되고,
   그 셋째 줄이 「앱을 나가십시오」다
```

## 🔴 ① 되살리면 «안 되는» 함수가 하나 있었다

`crud.update_table_config` 는 **호출자가 아예 없었고**, 평범한 `open(w)` 로 쓰고,
**실패를 `print` 로 삼켰다.**

```
=> 예외가 나면 «0 바이트 등록»이 «다섯 프로세스가 읽을» 자리에 남는다
   그리고 config_watcher 자기 주석이 «바로 그 writer 로부터 반쯤 써진 파일을 읽은 적이
   있다»고 기록하고 있다
```

## ② 가드 «셋» — 각각이 판정이다 (`e627d6e5`)

`server/ledger_admin.py` 의 `save_table_config_raw()`:

```python
current_base = file_fingerprint(path)
if base != current_base:
    raise _table_config_refusal(
        "stale_base", "base",
        "이 파일이 열어 본 뒤에 바뀌었습니다. 다시 열어 확인한 뒤 저장하십시오")
...
merged = dict(document); merged[table] = declaration
# The whole result, through the product's OWN parse rules, before anything is written.
try:
    json.loads(json.dumps(merged, ensure_ascii=False))
except Exception as exc:
    raise _table_config_refusal("declaration_not_serialisable", f"tables.{table}", ...)
backup = _atomic_write(path, merged)
```

```
① 기준 지문   원장 편집기와 «같은 거절 이름». 없으면 둘째가 첫째를 «조용히 지운다»
② 병합된 «전체»의 검증을 «착지 전»에 — 쓰고 나서 검증하면 config_watcher 가 이미 읽었다
③ «같은 디렉터리»의 임시 파일 -> 원자적 교체 — 워처가 «삭제+생성»이 아니라 «교체»를 본다
```

🔴 「**거절은 코드와 주소를 나르지 산문을 나르지 않는다 — 안 일어난 저장이 «일어난 것처럼»
보이면 안 된다.**」

**쓰기 단위는 «표 하나»**다 — `/admin/ledger/config/raw` 와 같은 모양이고, 그 라우트가
이미 기록한 사유가 있다: **파일 전체 편집은 매 저장을 «남의 등록을 다시 쓰는 일»로
만든다.** 전체 문서는 «맥락»으로 읽히지, 쓰기의 단위가 아니다.

⚠️ 범위 밖도 명시됐다 — 삭제 «없음»(얕은 병합으로 표현이 안 되고 파급 반경이 다르다),
컬럼 타입 추론 «없음», 화면 «없음». 그리고 **`init_dynamic_models` 를 여기서 «안 부른다»**
— `config_watcher` 가 그 일을 하고, **두 번째 문이 있으면 그 둘이 «다른 순간에 다른 것»을
보게 된다.**

⚠️ 마지막 변이는 **백업에 대한 단언이 있어야만** 잡혔다 — 평범한 `open(w)` 도 임시 파일을
안 남기므로, **둘을 가르는 것은 «되돌릴 사본»뿐**이다.

## ③ 화면 반쪽 (`ad9d0299`) — 왕복을 «필드 유무»가 아니라 «왕복»으로 채점

기준 지문이 «루트 요소»에 걸리고 저장 때 같이 돌아간다 — 같은 파일을 편집하던 둘이
`stale_base` 를 받지, 한쪽이 다른 쪽을 조용히 지우지 않는다.
**하니스가 그것을 «필드가 있나»가 아니라 «왕복»으로 채점한다.**

🔴 **클라 쪽 파싱 검사는 «빈 코드»를 «일부러» 보낸다** — `declaration_not_serialisable`
은 서버가 «직렬화 못 하는 값»에 붙인 이름이고, **애초에 JSON 이 아닌 텍스트는 다른 조건**이다.

```
여기에 그 코드를 찍으면 «코드와 메시지가 서로 다른 말»을 하게 되고,
운영자가 «찾아보는 것»은 코드다
```
못 읽는 설정은 **표를 «아예 안 그린다»** — 「못 읽었다」와 「등록된 게 없다」를 가르려고.

```
   다만 파일 이름은 섹션 머리에 남는다. «거절이 가리키는 것»이 그것이라서
```

## 🔴 ⑤ 둘째가 필요해졌을 때 «첫째를 템플릿으로 올렸다» (`7406e36b`)

표에 변환 코드를 거는 규칙은 **읽기 라우트가 있고 화면이 없었다.** 코드 자체는
목록·읽기·쓰기·편집기가 있었는데. 「그게 «체인이 표를 만든다»의 마지막 걸음이
앱 «밖»에 살던 자리였다.」

이 모양의 **두 번째 등록부**라서, 첫째를 **손으로 그리지 않고 «올렸다»**
(2026-08-24 소유자 상설).

`client2/src/raw_registry_panel.js` (206줄) 가 폼 전체를 들고 있고 —
고르기·원문 편집·저장·기준 지문·서버 말로 된 거절 — **도메인 낱말을 «하나도» 안 나른다.**

```js
/**
 * @typedef {object} RegistrySpec
 * @property {string} listKey   ... (예: 'tables' · 'rules')
 * @property {string} nameKey   ... (예: 'table' · 'name')
 * @property {string} cls       ... (예: 'table-config' · 'chain-rule')
 * @property {(payload:object)=>object|null} [extra]  이 등록부에만 있는 값 (예: enabled)
 */
```
`table_config_panel.js` 가 약 180줄에서 **자기 것 10줄 남짓**으로 줄었고,
`chain_rule_panel.js`(59줄)가 «새 선언»이다.
**추출이 동작 중립임의 증거: 표 하니스가 추출 전후 35/0 «변화 없음».**

### 🔴 그리고 규칙 등록부만 «선언하는» 것 하나 — `enabled`

```
저장된 «표»는 등록만 하고 «아무것도 안 돈다»
저장된 «규칙»은 다음 재적재에 다시 읽히고 «돈다»
   -> 서버가 새 규칙을 «enabled false» 로 쓴다
   -> 화면이 그 값을 «안 보여 주면» 운영자가 「저장됨」을 「도는 중」으로 읽고
      «없는 결함»을 찾으러 간다
```
서버 자기 «낱말과 값»으로 그린다 — `enabled false`. **문장이 아니다.** 그리고
켜는 «두 번째 컨트롤»을 «안 만든다» — 원문 편집기에 이미 그 필드가 있다.
**세 상태다**: `true` · `false` · **키가 아예 없음**(목록 응답은 `enabled` 를 안 나르고,
그것을 false 로 그리면 «아무도 안 한 질문»에 답하는 것이다).

## 🔴 ⑥ 「묘하게 다르다」의 정체 — 토큰이 «한 뿌리»에 갇혀 있었다

`c62a8ff3`. 토큰 **스물둘**이 `#ontology-explorer-root` 에 선언돼 있어서

**값을 «복사»해서** 통일돼 있었다.

```
🔴 복사된 축은 «복사한 날» 일치하고 «그 뒤로는 영영» 아니다.  그게 「묘하게 다르다」였다
```

⚠️ **`color-scheme` 이 «같이» 움직여야 했고, 그게 하중이다:**

```
light-dark() 는 «값을 «쓰는» 요소»의 color-scheme 에 대고 푼다
문서 루트의 그것은 «normal» 이었다 — 실측
=> 토큰만 옮겼으면 다크 모드에서 «모든 섹션에 밝은 쪽 절반»을 «조용히» 건넸을 것이다.
   고치려던 결함보다 «나쁜» 결함
```
**시키지 않은 부수효과가 «보고됐다»** — 어드민 페이지의 네이티브 위젯(스크롤바, select

«없다»고 보고됐다.**

`cc610af2` 가 같은 수리를 «한 층 아래»에서 했다 — `.oe-field-select` 도
`#ontology-explorer-root` 뒤에 살아서, 그 클래스를 어드민 요소에 붙여도 «아무 일도

고침은 **«같은 규칙 블록»에 맨 셀렉터를 «더하는» 것**이다 — 다른 데서 다시 쓰지 않는다.
탐색기 자기 셀렉터는 안 건드려서 **특이도와 출력이 못 움직인다.**

## ⑦ 마지막 두 탭 — «있는 부품의 선언»으로 (`58042a18`)

```
Auto Update 의 연결된 실패는 «교집합»이다 — 수집기의 표들 ∩ 최근 실패 로그
   수집기가 없으면 그 교집합은 «필연적으로 0»
   그건 「아무것도 실패 안 했다」가 아니라 «그 수가 적용되지 않는다»이고,
   닫힌 목록에 «그 낱말이 이미 있었다»
인리치먼트의 총계는 더 나쁘다 — «잰 규칙만» 더한다
   큐 술어를 못 만든 규칙, 개수 요청이 실패한 규칙은 «0 이 아니라 아무것도» 기여 안 한다
   -> 총계 0 이 「모든 규칙이 안 재졌다」일 수 있고, 그것이 「채울 게 없다」와 «똑같이» 읽혔다
=> 전부 안 재졌으면 «수를 안 그린다» · 일부면 「전수 아님」 · 진짜 0 이면 그렇게 말한다
```
⚠️ Auto Update 의 부제 「수집기 SUCCESS 는 데이터 도착이 아니다」는 **남는다** —
그건 섹션이 «무엇을 세는지»를 말하지 그 «0 이 무슨 뜻인지»를 말하지 않는다.
그래서 부품이 그걸 안 나르고, 둘이 «같은 말»을 하지 않는다.
