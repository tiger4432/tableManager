# 성능 조사 넷이 돌아왔다 — 그리고 출하된 수리 하나가 거꾸로 돌고 있었다

**날짜:** 2026-08-11 16:42~16:52 · **커밋:** `73c50fe` `5fa4a83` · **레인:** 문서(보드) +
성능 조사 4건(전부 읽기 전용, 자기 커밋 없음)
**측정 상자:** 이 워크스테이션의 격리 스택. **운영이 아니다.** 절대 수치는 이 상자에
남기고, 옮기는 것은 **비율과 기제**다.

---

## 배경

네 건의 성능 조사가 코드를 한 줄도 바꾸지 않고 착지했다. 통합본이 보고서 넷이 아니라
보드로 갔다.

**한 문장 결과: 수리 목록 대부분은 「만들어라」가 아니라 「이미 있는 걸 불러라」다.**
`_load_metas`는 `/view`가 행 단위로 훑는 바로 그 파일 안에 있다. `outbox_mode(COLLAPSED)`는
존재하고 push 경로가 **한 번도 세팅하지 않는다**. 벌크 프리미티브가 그것을 필요로 하는
N+1에서 300줄 떨어져 앉아 있다. **「착지는 배선이 아니다」가 이번엔 성능 축에서** 반복됐다.

## 「고쳤다(미검증)」로 채점된 수리가 회귀였다

`cell_sources` 업서트의 fast path가 **자기가 대체한 `.values()` 경로보다 16% 느리다.**
A/B/A/B 인터리브, 3라운드, 세 라운드 전부.

| | 옛 경로 | fast path |
|---|---|---|
| Python | 17.70 s | **1.44 s** (설계대로 붕괴) |
| 드라이버 | 8.54 s | **29.25 s** (반대로 갔다) |

세는 커서 팩토리가 이유를 말했다 — fast path는 psycopg2에 **파라미터 세트 2만 개**를
`executemany`로 건네고, 옛 경로는 `execute` **20회**를 냈다. psycopg2의 `executemany`는
**행마다 왕복**이다. 그리고 `insertmanyvalues`는 `ON CONFLICT DO UPDATE`에 **개입하지
않는다** — 그게 재작성의 전제 전부였다.

이 커밋 시점의 `server/database/crud.py`에서 그 전제는 **주석으로 단언돼 있다.**

```python
    if _is_executemany_safe(deduped_mappings):
        # One compiled statement, one parameter set per row. psycopg2's `values_only`
        # executemany rewrites each call into a multi-row INSERT with the values
        # rendered as literals, so the per-chunk VALUES construction disappears.
        stmt = upsert_insert(models.CellSource)
```

**배선된 대로는 거짓이다.** 옮겨지는 것은 절대 초가 아니라 **왕복 2만 대 20**이라는 모양이다.

네 조사를 투입할 때 「고쳤다」를 **검증됨 / 미검증**으로 쪼갠 판정이 있었다. 그 분류가
**첫 사용에서 값을 했다.**

## 조사 둘이 어긋났고 트리가 판정했다

체인 조사는 **「한 파일은 한 트랜잭션」** 위에 결론을 세웠다. 인제션 조사가 그것을
잡았고, 트리를 보면 인제션 조사가 옳다 — 내가 직접 확인했다.

```python
        file_tx_id = str(uuid.uuid4())          # 파일당 한 번 (parsers/directory_watcher.py)
        ...
                # 1,000건 청크 단위로 DB 세션을 격리하여 트랜잭션 처리
                db = SessionLocal()             # 청크마다
                ...
                    db.commit()                 # 청크마다
```

`file_tx_id`는 **표식이지 트랜잭션 경계가 아니다.** 긴 트랜잭션이라는 실패 계급은 여기
존재하지 않는다.

**그런데 체인 조사의 결론은 자기 틀린 전제에서 살아남는다** — 이것이 기록할 모양이다.
2차 비용은 트랜잭션이 길어서가 아니라 **워커가 그 표식으로 묶기 때문**에 생긴다. 두 조사가
같은 비용을 서로 모른 채 **반대쪽 끝에서** 쟀고, 전제를 바꾸면 결함 진술이 더 약해지는 게
아니라 **더 정확해진다.**

### 두 번째로 트리를 못 견딘 주장

통합본은 「`cache=`가 형제 호출 세 곳에는 실리고 **넷째에서 빠졌다**」고 적었다. 총괄이
트리와 대조해 기각했다 — **그 자리의 함수는 그 인자를 받지 않는다.** 내가 확인한 사실:
이 시점의 `server/map_alignment.py`에서 `cache=`를 키워드로 받는 것은
`_resolve_reference`와 `_load_reference` 둘뿐이고, 같은 문단이 이름 댄 벌크 프리미티브
`_load_metas(db, map_table, map_ids)`에는 **캐시 매개변수가 없다.**

## 오늘의 수리가 폭탄을 장전한다 (`73c50fe`)

체인 조사가 다른 셋보다 앞에 놓인 이유다. **오늘 출하한 「조용한 성공」 수리가 poison
amplification을 장전한다.** RAISE하는 매퍼는 행 단위 이벤트로 재확장된다 — 천만 건,
19.6 GiB, 7일간 purge 불가. `ColumnBindingRefused`가 정확히 그런 raise다.

**침묵을 소음으로 바꾼 것은 옳았다. 회로 차단기가 없으면 그 소음은 폭발이다.**

## 아웃박스 힙 화해 — 그리고 결론만큼 크게 적힌 단서

운영이 오후에 낸 질문(아웃박스 `count(*)`가 5초를 넘는다)에 대한 답:
**`count(*)`는 행이 아니라 페이지로 청구된다.** 힙이 살아 있는 약 1,000행에 대해
**8,668 페이지**를 들고 있다 — 페이지당 0.12행, 이 상자의 다른 모든 곳은 18~72다.
plain VACUUM이 돌려주지 않는 **8만 1천 구의 purge된 시체**다. 운영 자신의 기록된
최고수위로 스케일하면 「5초 초과」가 산술적으로 재현된다.

**단서를 결론만큼 크게 적었다 — 빼먹었으면 오늘의 네 번째 오진이었다:**
도는 소비자 중 **그 테이블을 세는 것은 없다.** 공간 회수는 디스크·백업 시간·진단
가능성을 사지 **응답 지연을 사지 않는다.**

그리고 조사가 **자기 결론에 대해 스스로** 물었다 — 보드가 오후 내내 `data_outbox`라고
적고 있었는데 테이블 이름은 `database_outbox`다. 그 5초짜리 카운트가 존재하지 않는
이름에 대해 돈 것이라면 **첫 발견을 처음부터 다시 세워야 한다.**

## 10M에서 깨지는 것은 아웃박스 부피가 아니다

체인 드레인이고, **2차(quadratic)**다. 그룹이 쪼개지지 않도록 같은 transaction id의
20,000행을 더 가져오는 가드가 있고, 트림이 **즉시 그것을 쪼갠다** — 250배 증폭,
약 37분 안에 유용한 작업 8.8초. 라이브 로그에 이미 **연속 7줄의 지연 라인이 한
transaction id**를 달고 있다. 산술만이 아니라 관측된 모양이다.

## 그런데 **먼저** 깨지는 것은 아무도 예상하지 않은 쪽이다

`cell_sources` 크기도 아니고 10M도 아니다.

- **맵 에디터 push가 수천 행에서 깨진다.** push는 `source_name='user'`를 선언하고, 그것은
  데이터 행당 메타데이터 **49행**을 뜻한다(기계 소스는 16). `batch.updates`에 상한이 없다.
  **2026-07-25의 freeze 페이로드가 다른 문으로 도착한 것**이다.
- 그다음 `?q=` 검색이 **880,000**에서 — 목표의 10분의 1.
- **WAL 고갈은 아무도 잰 적이 없고**, 실패 모드가 PANIC이라 **모든 writer가 멈춘다.**

## 검증

두 커밋 모두 **보드 문서 1파일**이고 코드 0줄이다 — 스위트 게이트가 없다. 이 라운드의
게이트는 다른 것이었다: 네 조사가 **전부 읽기 전용으로** 돌았고, 서로의 전제를 깨뜨렸고,
총괄이 그중 둘을 트리와 대조해 기각했다. 나는 이 수치들을 재현하지 않았다.

## 그때 남아 있던 것

- **upsert 회귀는 이 시점에 되돌려지지 않았다.** 보드에 기록만 됐다.
- `crud.py`의 그 주석은 이 시점에도 **거짓 문장을 담고 있다.**
- **회로 차단기는 없다.** `ColumnBindingRefused`는 오늘 착지했고 증폭 경로는 열려 있다.
- **WAL은 여전히 미측정**이며, 이 항목이 그것을 재라고 말하지 않는다 — 잰 적이 없다는
  것이 이 시점의 사실이다.
- 절대 초·바이트·페이지 수는 전부 **이 워크스테이션의 격리 스택**에서 나온 것이고
  운영 증거가 아니다.
