## 소유자 요청: 「서버 근본적으로 안무겁게」 — 그리고 제안은 «프로세스 분리»였다

`4ddb70fa`. 먼저 그 지렛대부터 쟀다. **이미 분리돼 있다** — 웹 라우트는 publish 만 하고
실행은 `run_auto_update` 가 한다. 그리고 느려지는 것이 일반 DB 질의와 API «둘 다»로
보고됐으므로 **경합 지점은 PostgreSQL** 이고, **프로세스를 하나 더 띄운다고 풀리지 않는다.**

그래서 네 서브시스템을 **한 잣대로** 감사했다.

```
체인       주기로 sweep · 청크 1,000 · «사이클당 청크 상한» · 남은 것은 다음으로 이월
자동갱신    루프가 sleep 한다
파일 인제션 500행 배치 (짐작이 아니라 측정된 값)
🔴 원장 백필  페이지 2,000행 · sleep 없음 · 사이클 상한 없음 · 이월 없음 · 끝날 때까지 돈다
             max_batches 는 «멈추게» 하지 «느리게» 하지 않는다
```
결론은 새 설계가 아니었다 — **체인이 이미 그 모양을 풀었고, 원장이 같은 모양을 받되
하드코딩이 아니라 «선언»으로 받는다.** 취소 버튼과 같은 가족이다: 하나는 멈추는 손잡이,
이것은 **느리게 하는** 손잡이이고, 대개는 느리게 하는 것으로 충분해서 멈출 일이 없다.

## 🔴 30분 뒤 자기 측정을 정정했다 — 「청크 500」은 페이싱이 아니었다

`c5b672a9`. 소유자가 **파일 인제션도 느려진다**고 보고했고, 그것이 30분 전 측정으로
되돌려 보냈다.

```
내가 「인제션의 페이싱」이라고 부른 것  =  500행 청크
그 주석이 그 수의 이유를 «명시»하고 있다:
   바인드 파라미터와, 50~500 에서 «평평하고» 그 뒤로 악화되는 질의 플랜
그리고 그 경로 어디에도 배치 «사이의 멈춤»이 없다
```
**정확한 그림은 이랬다** — 단위 시간당 작업량을 제한하는 것은 **체인 «하나뿐»**이고,
원장 백필과 파일 인제션은 **둘 다 전속력**으로 돈다. 그리고 인제션은
**피해자이면서 원인**이다: 남 뒤에서 기다리면서 도는 동안 남을 민다.

라운드는 둘로 «넓혔지만» 한 번에 하나씩, 원장 먼저로 갔다 —
**일반화하는 순간은 두 번째가 «올 때»이지 그 전이 아니다.**

## ① 값은 코드 밖에 산다 — 이 라운드가 «지우려는 것»이 바로 재기동이기 때문

`3dbef780`. 지시서는 체인의 «모양»을 베끼되 **그 하드코딩은 베끼지 말라**였다.
체인의 페이싱 수(`OUTBOX_PURGE_MAX_CHUNKS` · `SWEEP_INTERVAL`)는
`chain_ingestion_worker.py` 의 **상수**다.

```json
// server/pacing.json (초판은 server/ledger/pacing.json)
"_why_this_is_a_file_and_not_constants":
  "... An operator who needs a backfill to stop crowding the database at 2am cannot edit
   a constant and restart the server - that is the very restart this round exists to remove."
```

모양은 체인의 것이다 — **사이클당 상한, 그다음 양보.** 그리고 **양보하는 자리가 취소가 쓰는
경계와 정확히 같고, 그것은 우연이 아니다**: 페이지 사이는 직전 페이지의 원자와 커서가 함께
커밋됐고 다음은 안 읽힌 자리라 **멈춤이 공짜이고 재개가 정확하다.**

🔴 **`fast` 는 «이전과 똑같은 동작»이다** — 상한도 없고 쉼도 없다. 기본값을 바꾸는 것은
소유자의 결정이기 때문이다. 시험은 기본값이 `fast` 를 **닮은 것이 아니라 «정확히»** 그것으로
풀리는지, **적어도 한 페이스는 진짜로 느린지**(모든 항목이 같은 뜻인 표는 «거짓말하는 대조군»이다),
그리고 **두 페이스가 한 손잡이의 두 이름이 아닌지**를 단언한다.

오타 난 페이스는 **이름으로 거절**한다. `fast` 로 폴백하면, 서비스가 이미 힘들어서 `slow` 를
집은 사람이 **막으려던 바로 그것을 보게 되고**, 「안 듣는다」와 「도움이 안 됐다」를 구별할 수 없다.

이 상자에서 잰 것 — 같은 배치 3, 같은 12행:

```
fast     1.22s
trickle  9.22s
옆에서 같이 돌린 «구경꾼 질의»   중앙값 0.344s (fast) -> 0.266s (trickle)
                              통과한 프로브    3 -> 28
```
두 실행 다 체크포인트가 물었을 때 경계에서 멈췄다. 그 측정은 `lot_slot_wafer` 의 대기 28행을
번역했는데 — **그 소스가 어차피 해야 할 전진 작업**이라 되돌릴 것이 없었다.

## ② 두 번째 호출자가 «올 때» 표를 들어올렸다

`49988247`. **두 번째 호출자가 이 저장소가 무언가를 템플릿으로 올리는 순간이다** —
그 전이면 층에 소비자가 하나이고, 그 뒤면 두 번째 호출자가 **자기 사본**을 써서 둘이 갈라진다.

```
server/ledger/pacing.json  ->  server/pacing.json  +  server/pacing.py  (둘이 읽는다)
pages_per_cycle            ->  units_per_cycle
   단위(unit)는 원장에겐 «페이지», 인제션에겐 «청크» — 표는 어느 쪽인지 «알 필요가 없다»
```

인제션은 **청크를 내구화하고 그 오프셋을 함께 쓴 커밋 «직후»** 양보한다 — 원장이 쓰는 것과
같은 경계, 같은 이유다. 거기서 재개하는 것은 정확하므로, 멈춤의 비용은 **운영자가 쓰기로 한
벽시계뿐**이다.

손잡이는 `ingestion_settings.json` 의 `ingestion_pace` 이고 샘플에 문서화됐다.
**없으면 `fast`** — 이전과 정확히 같아서, 아무것도 설정 안 한 상자는 무변화다.
라이브 설정 파일은 **소유자의 것이라 안 건드렸다.**

🔴 **두 호출자가 오타를 «일부러» 다르게 거절한다.**

```
원장     «실행»을 거절한다     운영자가 거기 서 있고 다시 칠 수 있다
인제션   경고하고 «전속력»으로 돈다
        -> 설정 오타 때문에 파일 적재를 거부하는 것은, 막으려는 것보다 «큰 장애»다
        그래서 «경고»가 찾을 수 있게 만드는 장치다
```

## 아키텍처 영향

- `server/pacing.json` + `server/pacing.py` 가 생겼다. **원장 백필과 파일 인제션이 같은 표를
  읽는다.** 단위의 뜻은 소비자마다 다르고, 표는 그것을 모른다.
- 페이스는 **선언**이다 — `fast`/`slow`/`trickle` 의 라벨과 「언제 쓰나」가 전부 그 파일에 있다.
- 양보 지점이 **취소의 멈춤 지점과 같다.**
- 인제션 손잡이는 `ingestion_settings.json` 의 `ingestion_pace` 이고, **없으면 이전 동작**이다.

## 그때 남아 있던 것

- **기본값은 여전히 `fast`** 다. 바꾸는 것은 소유자의 결정으로 남겨졌다.
- 체인의 페이싱 수는 **여전히 `chain_ingestion_worker.py` 의 상수**다. 이 라운드는 원장과
  인제션 둘만 표로 옮겼다.
- 인제션의 500행 청크는 **페이싱이 아니라 질의 플랜의 수**다 — 그 구분이 이 라운드에서
  정정된 것이고, 그 수 자체는 안 건드렸다.
- 이 항목의 측정은 **전부 이 상자의 씨앗 위**에서 잰 것이다. 운영 수치가 아니다.
