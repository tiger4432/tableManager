# 작성 폼이 «두 칸»을 그만 내놨다 — 하나는 읽는 쪽이 없고, 하나는 검증기가 «거절»한다

## 배경 — 「무엇을 «추천»하는가」와 「무엇을 «받는가»」는 다른 문서다

작성 폼이 그리는 칸 둘이 각각 다른 이유로 **거짓 문서**였다.

```
references     문법은 «받는다». 그런데 «읽는 쪽»이 없다 (CODE_MAP 이 다섯 층에 걸쳐 적어 뒀다)
               -> 운영자에게 「아무것도 안 바뀌는 칸」을 채우라고 시킨다
entity 바인딩   폼이 신원 키 자리에 «entity» 를 내놓는다
               그런데 `_validate_binding` 은 «착지 이래로 계속» 그 모양에 invalid_binding 을 답한다
               (「entity identity keys allow only column or constant bindings」)
```

## 변경 내용

### ① `references` 는 «폼»에서만 나갔다 — 문법은 그대로 (`b143e162`)

🔴 **이 갈라짐이 이 커밋의 전부다.**

```
바뀐 파일   `ledger_skeleton.json` «하나». 79줄
파이썬     «0줄» -> 그러므로 문법이 움직였을 «수 없다»
           `references` 는 엔티티 검증에서 여전히 받아들여지고
           `_validate_references` 도 여전히 불린다
```

문법에서 은퇴시키면 **references 블록을 이미 든 모든 선언이 깨진다.** 그건 더 크고
**별개의** 결정이다. 시험 넷이 두 반쪽을 갈라 붙든다 — 폼이 안 내놓는다 · 옆의 `class`
필드는 절제에서 살아남았다 · 스켈레톤이 여전히 파싱되고 나머지 필드를 든다 ·
**검증기는 여전히 그 낱말을 안다.**

### 🔴 그런데 이 커밋이 «게이트 하나를 빨갛게» 남겼고, 57분 뒤에 발견됐다

```
b143e162 이 스켈레톤에서 references 를 뺐다 -> 문법은 그 이름들을 «계속» 안다
=> 검증기 쪽에 «짝 없는 필드 이름 7개»가 생겼다
   `test_skeleton_and_validator_name_the_same_fields` 가 «그 커밋 이래로 빨갰다»
   커밋 본문의 자백: 「and I did not run it」
```

`b72843cc` 가 그것을 수리했다 — **면제를 «이름 붙여» 닫는 방식**으로. 정확히 그 7개 경로가
면제되고, **다른 필드를 하나라도 빼면 여전히 빨개진다**(양방향으로 찔러 확인).

### ② 신원 키 자리는 «검증기에 대고 재서» 좁혔다 (`06bd33a9`)

```
스켈레톤이   바깥 칸이 쓰는 «같은 binding def» 를 신원 키 자리에도 겨누고 있었다
그래서      폼이 거기에 `entity` 를 내놓았고, 검증기는 «항상» 그것을 거절했다
=> 능력이 «하나도» 안 사라진다. 문서가 «참»이 되는 것이다
```

🔴 **좁힌 목록을 «믿지 않고 재서» 만들었다:**

```
시험이 `binding_kinds` 의 «모든 kind» 를 신원 키 자리에 먹이고,
제안 목록이 «깨끗하게 돌아오는 것들과 정확히 같은지»를 단언한다
=> 나중에 네 번째 kind 가 오면 «배우거나 거절되거나»이지, «조용히 제안»되지 않는다
```

출하 샘플 실측 — 신원 키 자리의 바인딩: `column 64 · constant 13 · entity 0`.
**좁혀도 깨지는 선언이 없다.**

그리고 스켈레톤 검사기가 낱말 하나를 배웠다 — **한 노드가 다른 노드를 «좁힐» 수 있다**
(필드가 더 적을 수는 있어도 더 많을 수는 없다). 검증 함수가 «하나»라서 역방향 앵커 지도가
둘째 이름을 부를 수 없고, 좁힌 노드는 `invented` 는 검사하되 `missing` 은 면제한다 —
거기서 전부를 요구하면 **검증기가 거절하는 바로 그 필드를 요구하는 것**이 된다.

⛔ 여전히 «바인딩 레코드»이고 «한 층»이다: `kind` + `column` 또는 `value`. 옛 주석이 지키려던
재귀는 **애초에 한 층보다 깊었던 적이 없다** — `column` 과 `constant` 에는 내려갈 `keys` 가 없다.

## 아키텍처 영향

- 작성 폼과 문법이 **다른 문서**임이 시험으로 못 박혔다. 폼에서 은퇴시키는 것과 문법에서
  은퇴시키는 것이 각각 다른 결정이라는 것이 코드에 남았다.
- 스켈레톤 ↔ 검증기 대조 게이트에 **이름 붙은 면제 목록**이 생겼다. 면제는 7개 경로로
  «열거»돼 있고 그 밖은 여전히 빨개진다.
- 스켈레톤 문법에 **「좁힘(narrow)」** 개념이 생겼다.
