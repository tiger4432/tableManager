# 조인 규칙 «하나»가 깨지면 그 표의 «모든» 규칙의 컬럼이 같이 사라졌다

> **커밋:** `390f0ec4` (09:14) · `dd6c9516` (09:30) · `91e7aa29` (09:45) · `6952f788` (10:31) · `4b728132` (11:33)
> | **일자:** 2026-09-03 오전
> **레인:** 구현자(서버)
> **측정 상자:** 이 워크스테이션. **운영이 아니다.**

## 배경 — 결손이 «누구 탓인지» 말해 주는 것이 아무 데도 없었다

`main.py` 의 바깥 핸들러가 `attach()` **호출 전체**를 감싸고 있었다. 그래서 컬럼 하나를
못 만들면 결정 단계까지 건너뛰고, **그 표의 «노출된 모든 컬럼»** — 멀쩡한 규칙에 속한
것까지 — 이 그냥 «없었다». 로그는 «표 이름»만 말했다.

```
🔴 남 때문에 «없는» 컬럼은  «비어 있는» 컬럼과  «정확히 똑같이» 그려진다
```

## ① 가드가 «규칙마다»로 내려왔다 — 그리고 «어디에» 놓느냐가 논증이다

`server/virtual_join_executor.py`:

```python
    for rule in rules:
        try:
            joined = execute_rule(db, rule, row_ids)
        except Exception as exc:                                        # noqa: BLE001
            logger.error(
                "[VirtualJoin] rule '%s' could not be built on '%s'; its columns %s are "
                "omitted and every OTHER rule's columns are unaffected: %s",
                rule.get("name") or rule.get("rule_name") or "<unnamed>", table_name,
                list(rule.get("expose") or ()), exc)
            continue
```

🔴 **collect 를 감싸지 decide 를 감싸지 않는다.** 「전부 모으고, 셀마다 «한 번» 결정한다」는
구조가 있는 이유가 있다 — 규칙별로 결정하면 **뒤 규칙이 앞 규칙의 미상을 LEFT 값으로
읽어**서 **규칙 «순서»가 답을 바꾼다.**

「제안 0」이 근사가 아니라 정확한 이유도 확인됐다 — collect 본문에서 실제로 던지는
문장은 `execute_rule` «하나»뿐이고, 그것은 SELECT 를 조립하다 `getattr(right, c)` 에서
던진다. **아무것도 병합되기 «전»이다.**

⚠️ **그리고 그 커밋은 자기 게이트를 못 맞췄다고 «보고했다».** 지시서의 전제가 틀렸다 —
«출하» 픽스처는 컬럼 다섯을 전부 노출하는 규칙을 «하나»만 선언해서, 부수 빨강 셋이
깨진 컬럼과 «같은 규칙»을 공유한다. 규칙별 격리로는 그것을 못 가른다.

## ② 그래서 «출하 픽스처에 닿는» 좁히기가 따로 왔다 (`dd6c9516`)

```python
    declared = list(rule["expose"])
    expose = [c for c in declared if hasattr(right, c)]
```

컬럼마다 try 가 «아니라» 목록 검사다. 이유는 «비용» — 컬럼마다 try 면 어느 것이 던지는지
알려고 SELECT 를 컬럼 수만큼 «만들고 돌린다».

🔴 근본 원인이 기록됐고, **양쪽 다 틀리지 않았다**:

```
virtual_join_config  expose 를 오른쪽 표의 column_types 키에 대고 «검증»한다
모델 빌더            graph-sync 메타데이터 이름을 «건너뛴다»
                     -> 2026-08-31 «뒤»에 만들어진 표는 그 컬럼을 «안 받는다»
=> 선언은 «유효»하고 컬럼은 «없다»
```

## 🔴 ③ 불리언 단언 넷을 은퇴시켰다 — 그리고 «둘이 조인과 무관»했다

`91e7aa29`. 근거는 총괄 자기 `/health` 규칙이다 — **영영 초록이 될 수 없는 빨강은
기록이 아니라 «빨강을 무시하게 가르치는 잡음»이다.** 불리언 컬럼이 조인 이음매에
닿을 수 없는 근거가 «둘»이고 서로 독립이다(위의 메타데이터 컬럼 + 소유자 판정
「불리언 필요 없음」).

```
비용: 없다.  파일 안 8 실패 -> 2, 남은 둘은 지시서가 「반드시 살아야 한다」고 한 «그 둘»
```

🔴 **그런데 은퇴 대상 셋 중 «둘»이 조인 이음매와 «무관한» 단언을 나르고 있었다** —
`boolean_text_value`·`comparison_text_value`. **스위트 전체에서 그것을 덮는 유일한 곳**이
그 줄들이었다.

```
불리언 «컬럼»은 갔다.  불리언 «값»은 안 갔다 —
   AG-Grid 가 불리언으로 취급하는 컬럼에 JSON true 를 «필터 값»으로 보내고,
   column_filter 는 여전히 그것을 텍스트에 견주기 «전»에 그려야 한다
=> 네 줄이 «픽스처 없는» 시험으로 옮겨갔다
```

그리고 타입 우주 시험이 자리를 지키며 **뒤집혔다** — 이제 「불리언은 «도달 불가»」를
단언한다. **원인의 어느 반쪽이든 되돌리는 날 실패하면서 돌아와야 할 단언들의 이름을
말한다.** 주석이 아니라 «부재 검사»인 이유는 — **주석은 알아챌 수 없어서**다.

## ④ 가드가 «시험 없이» 출하돼 있었다 (`6952f788`)

누가 `try` 를 지워도 스위트에서 빨개지는 것이 «없었다». 그리고 **실패를 «주입»해야
한다** — 자연스러운 방아쇠는 `dd6c9516` 이 «상류에서 걸러 버렸기» 때문이다.

```
🔴 상류에서 방아쇠가 제거된 가드가 «바로 그, 돌아오는 날 틀리는» 부류다
```

⚠️ **지시서의 기대가 정정됐다** — 가드를 «결정» 위로 옮기는 것은 잡히지만 **셋이 다
잡지 배치 시험 «혼자»가 잡는 게 아니다.** 배치 시험이 «혼자» 잡는 것은
**부분 제안 위에서 결정이 도는 것**이다. 「제 자리를 벌긴 하는데, 지시서가 준 이유에서
«한 걸음 옆»의 이유로.」

## 🔴 ⑤ 세는 방식을 바꾸니 «넷»이었고 «그 셋»도 아니었다 (`4b728132`)

기대한 모양이 아니라 «이름»으로 세었다.

```
execute_rule                행 페이로드 SELECT
resolved_expression         필터 — ?q= 검색 «그리고» 내보내기
announced_columns           스키마 + CSV 머리글
ledger/source_preparation   자기 SELECT      <- 지시서가 «몰랐던» 자리
main.py 의 바깥 try         SQL 을 안 만든다 — 마지막 그물로 «남는다»
```

```python
def usable_expose(descriptor, right_model, where: str):
    declared = list(descriptor["expose"])
    usable = [name for name in declared if hasattr(right_model, name)]
    missing = [name for name in declared if name not in usable]
```

🔴 **내보내기가 아직 깨져 있었고, 그 실패는 SQL 보다 «한 걸음 뒤»에 있었다**:

```
announced_columns 가 «모델이 답할 수 없는 이름»을 알린다
   -> 내보내기가 알려진 이름마다 머리글 «칸»을 만든다
   -> 라우트는 못 채우는 칸을 «옳게 거절한다» (밀린 컬럼은 «완성돼 보이는» CSV 를 만든다)
=> 답할 수 없는 «이름 하나»가  ->  «파일이 아예 안 나온다».  멀쩡한 컬럼들에 대해서
```

좁히지 «않은» 자리 둘이 의도적이다 — `virtual_only_columns` 는 계속 전부 알린다
(쓰기 거절에서는 안전한 방향이 «반대»다). 그리고 `source_preparation` 에서는
좁힌 목록을 **언패킹에도** 쓴다 — 좁혀서 SELECT 하고 선언대로 언패킹하면
**모든 값이 한 칸씩 왼쪽으로 밀린다.** 조용한 오답이 예외보다 나쁘다.

⚠️ 새 시험이 살아남은 머리글을 **«이름»으로** 단언한다 — **길이가 맞고 멤버가 틀린
머리글은 개수 검사를 통과한다.** 그리고 주석 둘이 정정됐다 — 내보내기의 500 갈래가
「이런 일은 있을 수 없다」고 적혀 있었는데 **일어나고 있었다.**

## 아키텍처 영향

- 가상 조인의 실패 단위가 **규칙**이다. 가드는 collect 를 감싸고 decide 는 안 감싼다.
- 노출 이름을 모델이 답할 수 있는지 판정하는 자리가 **`server/verified_join_contract.py`
  의 `usable_expose` 하나**이고, **네 곳**이 그것을 부른다.
- 타입 우주 시험이 **불리언의 «도달 불가»를 단언한다** — 원인이 되돌려지면 빨개진다.
