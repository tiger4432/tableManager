# 입문서 — 한 행의 여행, 그리고 읽기 = 서브그래프 추출

> 2026-08-17 12:28/12:33/12:36 · Docs / Plan · 커밋 `3d47b12`, `b3cf541`, `f5a40c1`

## 배경

소유자가 구성요소들의 정체를 반복해서 물었다 — 기존 문서들이 층의 이름만
나열했지, **사실 하나가 층들을 통과하는 모습**을 보여 준 적이 없다는 뜻이다.
그래서 라이브 `lot_event`의 스플릿 행 하나를 뜻 없는 문자열에서 게이트를 통과한
원자 20개까지 걷게 하는 입문서를 만들었다. 03 사전 화면의 원고를 겸한다.

## 변경 내용

`PRIMER.md` 신설 + 2회 증축, 계 205줄.

**`3d47b12` — 쓰기측 여행.** 요소 11개(소스 테이블→table_config→Profile→엔진
group→Mapper 훅→Pack→vocabulary→게이트→봉투→원장→읽기측)가 각각 언제 등장해
무엇을 하는지 실물로. `vocabulary.py`에 별도 절 — 「국어사전 + 문법책」으로,
낱말 목록(닫힌 11개), 낱말마다 문형(서명), 걷기 규칙(traversable 3상태:
True 재귀 통과 / False 도달만 / None 아예 미수집)을 담고, 이 서명이 곧 게이트의
검사 기준이라 Pack이 틀려도 원장이 오염되지 않는 권위 구조를 설명했다. 도착
지점은 라이브 원장에서 인용한 실물 원자다:

```json
{"predicate": "derived_from", "subject_type": "Lot",
 "subject_keys": {"lot": "CL-2601-006-A1"},
 "object_payload": {"type": "Lot", "keys": {"lot": "CL-2601-006"}},
 "occurred_at": "2026-05-03T02:17:00+09:00", "source_who": "lot_event"}
```

**`b3cf541` — 읽기측 상세.** 구성은 «재판관 하나 + 해석기 다섯 + 선언 셋».
해소기의 5단 사전식 순위 `(계급 0핀>1확정>2관측>3추론) → 출처 → 날짜 → 최신 →
id`에서 계급이 최외곽이라 사람 확정을 나중 추론이 못 이기는 이유가 코드가
아니라 **튜플 모양**임을 명시했다. 해석기 다섯(걷기·대조·여정·표/맵·구조 뷰)과
읽기측 선언 셋(`siblings_axes`·`mechanism_models`·`ledger_journey`), 그리고
결정적 비대칭: **쓰기측 선언이 틀리면 게이트가 시끄럽게 거절하지만, 읽기측
선언이 틀리면 그냥 안 보인다** — 오류가 아니라 침묵. 러너북 여덟째 함정의
뿌리가 여기고, 합의 검사기(06)·현황판(05)의 존재 이유다.

**`f5a40c1` — 선언 셋의 실물 예시 + 소유자 정식화.** 세 선언 파일의 라이브/샘플
스니펫을 인용하고(셋 다 원장 잎의 철자를 인용하므로 오타 = 침묵), 소유자의
정식화를 정본화했다: **읽기 = 서브그래프 추출** — 다섯 해석기는 한 기계
(추출→재판→렌더)의 다섯 얼굴이고, 추출 기준만 다르며, 보류 중인 «서브그래프
탐색기»는 사용자가 추출 기준을 직접 쥐는 여섯째 얼굴이다.

## 아키텍처 영향

문서 전용. 코드 동작은 그대로이나, 「원장은 한 글자도 안 바뀌고 답이 바뀐다 —
재판 규칙만 바뀌었으므로」라는 이 구조의 목적 서술과, 쓰기/읽기 선언의 실패
양상 비대칭이 처음으로 한 문서에 명문화됐다.
