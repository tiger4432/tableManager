# 행은 «갱신돼서» 큐를 떠난다 — 그래서 갱신도 알려야 했다

> **커밋:** `7e037e64a` — 구현자
> **일자:** 2026-09-23 (07:10)
> **레인:** 구현자 · 문서 정비는 응용
> **측정 상자:** 이 워크스테이션. **운영이 아니다.**

## 무엇이 일어났나

대기열 화면의 «멤버십»은 아웃박스 행의 «칸»이 정한다. 그러면 행이 떠나는 모든 길은
그 행에 대한 «갱신»이다. 그런데 알리는 좌석이 «새로 난 행»만 보고 있었다 —
행을 비운 트랜잭션이 아무도 안 깨웠고 화면은 그 줄을 그대로 들고 있었다.

```
금방 처리되는 행   이 결함을 «가린다»
기다리던 행       안 가린다   <- 소유자가 본 것이 이쪽이다
```

## 고친 모양

좌석이 아웃박스 행의 «변화»를 깨울 이유로 센다 — 생성이든 수정이든 삭제든.
이름도 같이 옮겼다(«탄생»을 알리다가 «변화»를 알리게 됐으므로), 그 낱말을 인용하던
부팅 로그 줄도 같이 옮겼다.

## 넓힌 것은 «이유»이지 «양»이 아니다

```
깨움은 아무것도 안 나른다 — 듣는 쪽은 어떤 깨움이든 「다시 폴링」으로 다룬다
통지는 트랜잭션당 «한 번»으로 래치돼 있다. 그 상한은 «그대로»다
넓어진 것은 「어떤 트랜잭션이 자격이 있나」다
박스 수(박스라고 밝힌다): 하루 아웃박스 행 148, 지금 기다리는 것 0
```

## 일부러 «안» 한 것

`session.dirty` 를 「칸이 진짜 바뀐 행」으로 좁히지 않았다. 너무 자주 깨우는 것은 래치가 흡수하고,
너무 드물게 깨우는 것이 지금 고치는 «그» 결함이다. 그리고 정밀한 판은 큐 멤버십을 정하는
술어 «옆»에 둘째 술어를 세우는 일이다 — 그 갈라짐이 이 라운드가 피하려는 모양이다.

## 되돌리면 «먼저 우는» 곳

게이트 둘(표시할 때 · 지울 때)이 커서에서 «문장 수»로 채점되고, 탄생은 측정 블록 «밖»에서
끝내 둔다 — 세는 것이 «비우는» 트랜잭션이지 «만든» 트랜잭션이 아니게. 좌석을 탄생만으로
되돌리면 둘 다 빨개지고 다른 것은 안 빨개진다.
