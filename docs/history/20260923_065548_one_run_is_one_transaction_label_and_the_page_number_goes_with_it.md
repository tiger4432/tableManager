# 한 실행은 «한 트랜잭션 라벨»이다 — 접미사일 뿐이던 쪽 번호가 같이 갔다

## 무엇이 일어났나

백필이 감사 로그에 «쪽마다 한 그룹»으로 도착했고, 실행 맨 위에서 연 봉투가
자기 쓰기와 «다른 이름»을 들고 있었다. 한 실행의 두 반쪽이 이제 같은 문자열을 말한다.
인리치 백필도 같은 이유로 청크 번호를 뗐다.

## 잰 것 (구현자 실측, 고치기 «전»)

```
소급 실행 21 개가 이 상자에서 라벨 «30» 개를 나르고 있었다
여럿을 가진 것이 정확히 «여러 쪽»짜리였다
```

## 새 모양이 아니다

같은 파일의 표시 재계산이 «이미» 실행당 라벨 하나를 쓰고 그렇게 적고 있었고,
withdraw 경로의 라벨은 «한 번도» 쪽을 안 달았다. 어긋나던 것은 그 한 자리였다.

## 죽은 것과 «안» 죽은 것

```
죽었다   이름의 «일부»였던 쪽 번호 · 다른 독자가 없던 인자 · 그것을 먹이던 호출 자리들
안 죽었다 진척을 뜻하는 쪽 번호 — 카운터는 그대로 오르고, 실패한 쪽은 «몇 번째»인지 계속 말한다
```

## 되돌리면 «먼저 우는» 곳

게이트가 소스가 아니라 «감사 로그»에서 채점된다 — 여러 쪽짜리 실행은 새 라벨을 «정확히 하나»
남겨야 하고 그 라벨에 쪽 접미사가 없어야 한다. 접미사를 되살리면 빨개지고 «두 라벨»을 다 이름 댄다.

⚠️ 그 게이트는 «실행이 더한» 라벨을 센다. 총계를 세던 첫 판은 픽스처 씨앗의 생성된 id 때문에
하나 쓴 실행을 둘로 보고했다.

## 조용했을 뻔한 자리

시험 호출 셋이 쓰기 쪽에 쪽 번호를 «위치 인자»로 넘기고 있었다. 하나만 요란하게 실패했고
나머지 둘은 그 인자가 `replace_map` 에 «조용히» 묶인 채 통과했을 것이다 — 그래서 셋 다 고쳤다.
