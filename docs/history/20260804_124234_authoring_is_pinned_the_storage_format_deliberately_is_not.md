# 작성만 고정하고 저장 형식은 일부러 고정하지 않았다 — 실측 「8건 중 고아 0건」이 그 설계를 정했다

> **일자:** 2026-08-04 오후 | **관련 커밋:** `6420ad0`(구현) · 보드 `b07b39d`
> **담당:** 사용자(「유효다이 맵은 항상 `valid_die_ref`에 둔다」 판정) · 총괄(설계 판정, 자기 전제 하나가 틀렸음을 기록) · map 구현
> **대상:** `client2/src/map_editor.js` · `client2/map_editor.html` · `server/product_tables.py` · `server/config/table_config.json.sample` · `contracts/map_seam` · `client2/tests/valid_die_authoring_harness.mjs` 외 하네스 3종

## 배경 — 키 옆의 테이블 선택기를 없애면 무엇이 깨지는가

유효다이 키 옆에 테이블을 고르는 컨트롤이 있었다. 사용자 판정으로 그것이 사라지고
**유효다이 맵은 항상 `valid_die_ref`에 저장된다.** 그 자리에 버튼 두 개가 들어간다 —
**APPLY**(지정을 화면에 올린다)와 **SAVE**(그 지정을 기록한다). 그래서 키를 고르는
행위가 더는 에디터를 재배열하지 않고, 지정을 기록하는 데 **맵 전체 Push가 필요 없다.**

문제는 「항상 `valid_die_ref`」를 **어디에 적용하느냐**였다.

## 설계를 정한 것은 문장이 아니라 측정이었다

라이브 선언 **8건**을 셌다.

| | |
|---|---|
| 라이브 유효다이 선언 | **8건** |
| `bonding_map`을 가리키는 것 | 7 |
| `dt_map`을 가리키는 것 | 1 |
| **`valid_die_ref`를 가리키는 것** | **0** |
| 그중 「**내 테이블의 맵**」을 뜻하는 맨 문자열 | **7** |

`parseValidDieRef`는 맨 문자열을 「내 테이블의 맵」으로 읽는다. 그것은 **저장 형식의
뜻**이고 **이음새 양쪽이 같은 것을 돌린다.** 고정된 테이블 기준으로 다시 읽으면
**여덟 개 전부가 아무도 선언하지 않은 맵을 가리키게 되고, 화면에는 그것을 말해 줄
것이 없다.**

> 그래서 **작성만 고정하고 저장 형식은 건드리지 않았다.**
> 사용자가 실제로 바꾼 키는 명시적인 `{table: valid_die_ref, map_id}`로 쓰이고,
> 손대지 않은 키는 **저장된 선언이 지명한 테이블을 그대로 유지**한다.
> 실측: **무변경 저장에서 8건 중 0건이 다르게 풀린다.**

만들어질 고아가 애초에 없었다는 것이 이 라운드의 결론이다. 고아를 만들지 않으려고
설계를 조인 것이 아니라, **고아가 0이라는 측정이 「형식을 건드리지 말라」로 이어졌다.**

## APPLY가 규칙을 지키는 방식 — 새 코드가 아니라 같은 코드

APPLY는 키 상자의 `change` 리스너가 부르던 것과 **바이트 동일**하다. 그래서 보드
규칙 1(참조의 기하 메타가 이 맵의 것을 대체한다)과 규칙 4(저장 좌표는 움직이지
않는다)가 **구성상** 성립한다 — 둘 다 `resolveValidDie` 안에 있고, 이 변경은
그것을 건드리지 않는다.

라이브 확인: 칩 2.5×2.5 → 7×8, 격자 10×10 → 45×39로 바뀌는 동안
`grid_start_x/y`는 **1,1 그대로**였다.

## SAVE가 거절하는 두 자리

SAVE는 `wafer_map_metadata` 한 행의 한 필드에 대한 read-modify-write다. 두 경우
거절한다 — **적재된 정체가 없을 때**, 그리고 **저장된 규격을 읽을 수 없을 때.**

> 읽히지 않은 `{}` 위에 지정을 쓰면 **클릭 한 번으로 격자 규격 전체가 지워진다.**

무엇을 쓸지는 `validDieRefForPush`가 정하고 `applyValidDieRef`가 쓴다 — **Push가
쓰는 바로 그 채점된 두 함수**이지 두 번째 구현이 아니다.

## 계약이 축을 갈아탄 자리

`valid_die_push_decision_cases`는 **더는 존재하지 않는 컨트롤을 서술하던 케이스
두 개를 잃고**, 그 자리를 대체한 축을 얻었다 —
**레거시 선언이 무변경 저장을 살아남아야 하고, 재키잉은 고정 테이블에 앉아야 한다.**
양방향 전부 결함으로 되돌려 넣어 적색을 확인했다.

`valid_die_ref`는 `server/product_tables.py`에서 **제품 소유(product-owned)**로
승격됐다(단일 정의, `.sample`은 자기 설치기가 재생성). 라이브 사이트의 선언은
이미 정확히 일치했다 — **드리프트 0, 어느 사이트 config에도 아무것도 쓰지 않았다.**

## 총괄이 남긴 자기 정정 둘

`b07b39d`가 지시서의 전제 하나와, 지나가다 발견한 운영 사실 하나를 기록한다.

## 그때 남아 있던 것

- 이 라운드에서 나온 미분류 known-red는 **하네스 결함으로 귀속**됐다 — 슬라이서가
  진짜 호출부보다 **먼저 나오는 주석 안의 `projectCellsToPhys`**에 매칭했다.
  오버레이 레인이 걸렸던 것과 같은 first-match 함정이고, **코드 순서는 처음부터
  옳았다.**
- `parseValidDieRef`는 이 커밋 시점에 **바뀌지 않았다.** 맨 문자열은 여전히
  「내 테이블의 맵」이다.
- 라이브 선언 8건은 이 커밋 뒤에도 **여전히 `bonding_map`(7)·`dt_map`(1)을 가리킨다.**
  키를 실제로 바꾸는 저장이 일어나기 전까지는 그대로다.
