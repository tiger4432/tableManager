## 배경 — 이번 라운드에 모델 컬럼 변경이 운영 테이블을 두 번 내려앉혔다

SQLAlchemy는 매핑된 컬럼을 **전부** 방출하므로 **SELECT도 INSERT도 같이 실패**한다.
그리고 **누구든 처음 배우는 것이 화면의 500**이었다.

> **질문은 싸고, 아무도 묻고 있지 않았다.**

## 두 부팅 경로에 건다

```python
    ports_clear = refuse_if_ports_are_taken(api_host, api_port, graph_port)
    if ports_clear:
        report_schema_drift()
```

웹 서버 쪽은 **자기 아웃박스 마이그레이션 뒤**(**교정되려는 참인 DB는 깨진 것으로
읽힌다**), 그리고 **`DECOUPLED` 반환 앞**(그보다 뒤면 운영은 절대 돌지 않는다)이다.

## 아무것도 막지 않는다 — 총괄의 성향이 실측에 뒤집혔다

내 초기 성향은 「막자」였고, 레인이 **측정으로** 논파했다.

- **잡힌 포트는 아예 일할 수 없다.** 드리프트는 **드리프트된 테이블만 빼고 제품이
  돈다**는 뜻이다.
- **거절하면 무인 재기동에 컬럼 하나로 전체를 계속 내려 둘 권한을 준다** —
  그리고 재기동은 **정확히 아무도 안 보고 있을 때**다.

사실 둘이 그것을 날카롭게 했다: 점검이 **config 기반 동적 테이블까지 보게 됐으므로**
config 워처의 ALTER 지연이 **전면 장애**가 될 수 있다. 그리고 **컬럼 둘이 웹 서버
부팅 시점에 교정되는 것으로 기록돼 있어서**, 마이그레이션을 적용하는 그 프로세스
안에서 막으면 **교착**이 된다.

**게이트는 게이트가 안전한 자리에만 있다** — `--preflight-only`가 아무것도 안 띄운
채 묻고, **그 종료 코드는 바뀌지 않았다.**

```python
    sys.exit(0 if ports_clear else 1)
```

**드리프트는 재기동을 거절로 바꿀 수 없다.** `run_at_startup`은 `check()`를
`try/except Exception`으로 감싸 오류 한 줄만 내고 `None`을 돌려주고,
`report_schema_drift`에는 `sys.exit`도 `raise`도 없다 — 그리고 **그 부재를
소스에 대고 단언하는 테스트**가 있다.

## 배너가 마이그레이션 이름을 대려면 결함 셋을 먼저 고쳐야 했다

| 결함 | 수리 |
|---|---|
| **연결 URL이 DB 비밀번호를 인쇄하고 있었다** | 세 자리 전부 `paths.mask_db_password(...)` |
| `MIGRATION_OWNER`가 **손으로 유지돼 낡아 있었다** — 마이그레이션이 트리에 있는 컬럼 둘에 대해 「기록된 마이그레이션 없음」을 인쇄 | 소유자를 **마이그레이션 디렉터리 스캔으로 유도**(`server/migrations/*.py` 등에서 `ADD COLUMN` + 컬럼 + 테이블 동시 매칭). 손표는 **파일이 아닌 교정 둘**만 남음 |
| **선언 테이블 읽기가 26개 중 12개만 봤다** — 모든 운영자 화면이 앉아 있는 **14개 테이블을 건강하다고** 부르고 있었다 | `_declared()`가 `_register_dynamic_models(...)`를 부른다 |

> 12/26과 14라는 숫자는 **산문에만 있다**(모듈 docstring과 `backend.md`).
> diff 안에서 그것을 재는 코드는 없다.

## 가는 길에 닫힌 지뢰 — 그리고 닫히지 않은 것

- **`TESTING=True`를 세팅하고 안 지웠다** → **코드로 닫혔다.** `prior_testing`을
  보관하고 `finally`에서 복원한다(테스트가 `TESTING=None`을 단언한다).
- **런처가 `os.environ.copy()`를 자식 다섯에게 넘긴다** → **이 diff에서 바뀌지
  않았다.** 근거 주석과 테스트 docstring에만 나온다. **「지뢰 둘을 닫았다」 중
  코드 변경이 있는 것은 하나다.**

## ⚠️ diff가 커밋 메시지와 어긋난 자리 하나 더

**`server/main.py`의 +57 중 절반가량이 드리프트 점검이 아니다.** 같은 커밋에
`get_map_alignment_view`의 새 쿼리 파라미터 `assume_reference_geometry: bool = False`와
스펙 §9ⓐ 빌린 웨이퍼 기하에 대한 한국어 docstring 약 20줄, 그리고
`map_alignment.build_alignment_view(...)`로의 전달이 들어 있다. **커밋 메시지는
이것을 한 번도 언급하지 않는다.**

## 세 가지로 시험했다 — 어느 하나도 충분하지 않아서

좁혀 놓은 DB에 대고 점검을 직접 실행(**증상이 아니라 기제**), 호출 순서를
**소스에 대고** 단언, 그리고 `--preflight-only` — **진짜 런처가 진짜 프로세스로
진짜 DB에 대고, 아무것도 안 띄우고** 묻는다.

  질문이 통째로 억제된다.

  관측되지 않는다.**
