## 배경 — 벽은 «만 줄»이 아니라 «한 줄»이었다. 그리고 그 뒤에 셋이 더 있었다

`map_editor.js` 가 import 안 되는 이유는 줄 수가 아니라 1행의 `import './tokens.css'`
였다. **node 가 CSS 를 못 읽어 import 문 «자체»가 죽는다.**

🔴 그런데 `49725ea3` 이 그것을 치우자 **벽이 «넷»이었다** — 각각 «위의 것이 무너진
뒤에만» 보였다.

```

2. transfer_plan.js:53  import './transfer_plan.css'
                        (map_editor 가 그것을 import 하므로, 1만 치우면 던지는 자리가
                         «한 모듈 더 깊이» 옮겨갈 뿐이다)
3. config.js:1,13       window.location · import.meta.env 를 «모듈 최상단»에서
   utils.js:347         window.showToast = showToast
4. map_editor.js        document.addEventListener 두 줄 (페이지 배선)
```

스타일시트는 `map_editor.html` 의 `<link>` 로 나갔고(이미 `map_editor2.html` 이 쓰던
모양), 나머지는 `typeof` 가드가 됐다:

```js
const loc = typeof window !== 'undefined' && window.location
  ? window.location
  : { port: '', origin: '', protocol: '', host: '' };
let viteUser;
try { viteUser = import.meta.env.VITE_USER; } catch (e) { viteUser = undefined; }
export const CURRENT_USER = viteUser || 'web_client';
```

⚠️ `import.meta.env.VITE_USER` 가 **일부러 통째로 철자돼 있다** — `vite.config.js` 의
`define` 이 «정확히 그 표현»을 치환하므로, 줄여 쓰면 치환이 **조용히 안 일어나고**
모든 사용자가 `web_client` 가 된다. 오류 없음, 화면 멀쩡.

**한 줄이 네 모듈을 열었다**(`da397d32`) — `state.js` 가 모듈 스코프에서
`new URLSearchParams(window.location.search)` 로 `isDesktop` 을 만들고 있었고,
`api.js`·`grid.js`·`clipboard.js`·`timeline.js` 가 전부 그것을 import 한다.

## 🔴 ① 가드는 «도달 가능해지는 날» 틀렸다 (`833a9feb`)

`utils.js` 가 리스너 «둘»을 `typeof document !== 'undefined'` 검사 «하나» 뒤에 걸었고,
**둘째는 `window` 에 걸려 있었다.**

```
브라우저에서는 무해 — document 가 있으면 window 도 있다
DOM 을 «부분적으로» 스텁하는 곳에서는 «치명적»
   -> document 만 스텁하면 map_editor.js 가 «세 모듈 건너» utils.js:115 에서 던진다
```
**이 가드가 도달 가능해진 것은 «오늘» 모듈이 import 되기 시작해서**다.

## 🔴 ② 프로브는 «자기 파일이 선언한 것»에만 닿는다 — 그리고 그 수가 «틀렸다가 정정됐다»

`6117dbb8`. 대상 파일에 덧붙인 프로브는 **대상이 «선언한»** 이름을 다시 묶을 수 있다.
**import 로 «받은»** 이름은 못 건드린다 — ESM import 바인딩은 선언 모듈 외에는 읽기 전용이고,
`utils.js` 를 따로 열면 `map_editor` 가 보는 것과 **다른 인스턴스**다.

```

   normalizeLegendItem(3) · getMapIdFromMeta(3) · canonicalMapKey(3) · getLocalTimeString(2) …
```

🔴 **그리고 30초 뒤 `1e6fe77d` 이 자기 수를 정정했다: 12/30 이 아니라 «15/30».**


그 셋은 **다른 레인에 「지금 전환 가능」으로 이미 게시돼 있었다** — 그래서 정정이 즉시
올라가야 했다. **부재를 «부분집합»으로 판정하지 않는다**가 그날 적힌 규칙이다.

해법은 **노드 로더 훅**이다(`46c8f79b`·`e4ec36ac`) — «사본»의 의존을 생성된 스텁 모듈로
돌린다. 고른 이유가 「수를 푸는 양」이 아니라 **「대상의 바이트를 «안 건드리는» 유일한
선택지」**여서다 — `assertAppendOnly` 가 계속 통과하고, **그 통과가 정직함의 증거**다.

```
범위 한정은 «로드»마다이지 «프로세스»마다가 아니다:
   임포터가 «표식 붙은 프로브 사본»일 때 + «맨 형제 지정자»일 때만 발화
   -> ./utils.js 를 다른 데서(하니스 자신 포함) import 하면 «진짜 파일»로 풀린다
⛔ 지정자를 mutation 훅으로 고쳐 쓰는 지름길은 «금지»됐다 —
   그러면 «변이된 대상»과 «스텁된 대상»이 «한 문으로» 들어온다
```
