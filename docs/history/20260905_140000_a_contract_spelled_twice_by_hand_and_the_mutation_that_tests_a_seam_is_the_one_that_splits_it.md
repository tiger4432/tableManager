## 배경 — 사고를 «막으려고 만든 기제»가 같은 사고를 조용히 낼 수 있었다

미배달 알림 표지(undelivered-notification marker)는 **쓰는 쪽**과 **거두는 쪽**이 따로 있다.

```
쓴다   internal_event_client.record_undelivered_notification
거둔다  chain_ingestion_worker.sweep_undelivered_broadcasts
```

두 쪽이 표지의 **세 값을 각자 손으로 철자**하고 있었다. 그래서 이렇게 된다:

```
한쪽만 바꾼다
   -> 쓰는 쪽이 «거두는 쪽이 안 줍는 모양»으로 표지를 쓴다
   -> 오류 «없음» · 예외 «없음»
   -> 행이 DB 에 «영원히» 앉아 있고 화면은 «영영 모른다»
   🔴 그게 이 기제가 «막으려고 존재하는» 바로 그 사고다
```

## 🔴 ① 시험 다섯이 «있었는데» 이걸 못 봤다 — 각자 자기 행을 «손으로 만들어서»

이것이 이 항목의 핵심이다. 커버리지가 없었던 것이 아니다. **다섯이 있었고 전부 초록이었다.**

```
다섯 시험은 전부 «sweep» 을 잰다  ->  각자 행을 손으로 만들어 넣는다
=> 쓰는 쪽이 세 값 중 «무엇을» 바꾸든 다섯은 «그대로 초록»이다
   그 다섯은 틀리지 않았다 — 자기가 재는 것에 대해서는 «맞다»
   없었던 것은 «두 쪽을 지나는» 시험 «하나»다
```

`server/event_constants.py`, 이미 거기 있던 이벤트 타입 옆에:

UNDELIVERED_MARKER_STATUS = "SUCCESS"          # the DATA succeeded; only the notice failed

```
NULL 은 쓰는 쪽이 «설정하는 값»이 아니다 — 거두는 쪽이 «찾는 부재»다
이름을 붙이면 누군가 그것을 «쓰게» 된다
```
`a58df1cc` 가 그 판단을 별도로 남겼다: **부재에 이름을 주면 그것을 쓰라고 초대하는 것.**

## 🔴 ③ 그리고 총괄의 게이트가 «틀린 변이»를 겨냥하고 있었다 — 레인이 돌려 보고 알았다

총괄은 「공유 상수 하나를 변이시켜 새 시험이 빨개지는지 보여라」고 지시했다.
레인이 돌렸더니 **초록이었다.** 그리고 그 초록이 **맞다.**

```
공유 상수를 바꾸면      두 쪽이 «같은 이름»을 읽으므로 «같이» 움직인다  ->  초록
                       (이음매가 «닫혔다»는 뜻이지 시험이 약하다는 뜻이 아니다)
🔴 이음매를 재는 변이   이음매를 «가르는» 변이다 — 한쪽에 리터럴을 «되돌려» 넣는 것
                       -> 그때 이음매 시험이 «빨개진다»
```

`a58df1cc` 가 이것을 이 이음매 하나가 아니라 **여기의 모든 이음매 수리에 적용된다**고
판정하고 기억으로 올렸다. 그리고 커밋 본문이 남긴 문장이 그 자리를 정확히 적는다 —
「변이가 살아남았다」는 **내가 겨냥을 잘못했다고 내 측정이 말해 준 것**이었다.

## ④ 새 시험 하나 — 쓰는 쪽으로 «쓰고», 거두는 쪽의 «자기 필터»로 «고른다»

```python
def marker_row(db):
    """The row THIS test wrote, selected by what makes it a marker."""
    rows = (db.query(models.DatabaseOutbox)
            .filter(models.DatabaseOutbox.event_type
                    == event_constants.EVENT_BROADCAST_RECOVERY)
            .order_by(models.DatabaseOutbox.id.desc()).all())
    assert rows, "the writer produced no marker at all"
    return rows[0]
```

⚠️ 그리고 **자기 시험 안에서 결함 하나를 자기가 잡았다** — 순서 없는 `.first()` 가
«다른 행»을 골라 «남의 데이터»에 단언하고 있었다. 위 조각의 `order_by(...id.desc())` 가
그 수리다.

**기존 다섯은 «손대지 않았다».** 자기가 재는 것에 대해 맞기 때문이다.

## 아키텍처 영향

- 미배달 표지의 «모양»이 **`server/event_constants.py` 한 곳**에 산다. 쓰는 쪽과
  거두는 쪽이 «같은 이름»을 읽는다.
- 이 저장소의 이음매 수리에 **변이 규칙 하나**가 생겼다 — 공유 이름을 바꾸는 변이가
  아니라 **이음매를 가르는 변이**(한쪽에 리터럴 복원)로 채점한다.
- `broadcast_at` 은 공유 상수에 **없다** — 그것이 «값»이 아니라 «부재»라는 판단이
  주석으로 코드 안에 남아 있다.

- 🔴 **이 규칙은 이 이음매 하나에서 «도출»된 것이다.** 같은 저장소의 다른 이음매들이
  같은 방식(양쪽이 손으로 철자)인지는 이 커밋이 세지 않았다.
- 기존 다섯 시험은 여전히 «sweep 만» 잰다. 이음매를 지나는 시험은 이 시점에 **하나**다.
- 이 변경을 읽는 프로세스가 «체인 워커»(거두기)와 «워처·체인 워커»(쓰기)라고 커밋이
