# 변경 이력: 대량 데이터 로드 시 순차 청크 페이징 및 행 개수 기준 실시간 % 진행률 구현

- **작성일**: 2026년 6월 1일
- **작성자**: Antigravity
- **상태**: 완료

## 1. 개요 및 목적
- 단일 대형 요청으로 대량(예: 2만 행 이상) 데이터를 한 번에 로드하는 방식은 서버에 과부하를 가하며 JSON 인코딩 랙을 동반하고, HTTP 헤더의 `Content-Length`가 유실되거나 불안정한 환경에서는 다운로드의 백분율(%) 계산이 누락되는 고질적인 한계가 존재했습니다.
- 이를 해결하기 위해 서버와 클라이언트 모두 부담을 덜도록 **3,000행 단위로 데이터를 조각내어 순차 호출(Sequential Chunk Fetching)**하는 구조로 개편합니다.
- 전체 데이터 대비 현재 로드된 누적 행 수의 실시간 **백분율(%) 진행률**을 상단 상태 바(`performanceLog`)에 정확히 표기하여 사용자에게 안정적이고 상세한 피드백을 전달합니다.

## 2. 세부 구현 사항

### 프론트엔드 (`client2/src/main.js`)
- **청크 단위 순차 페이징 루프 설계**:
  - `Load All` 실행 시 `chunkLimit = 3000` 단위로 분할 로드를 시작합니다.
  - 첫 번째 청크 요청(`skip=0&limit=3000`)을 전송하여 전체 대상 데이터 총량(`total`) 및 1차 적재 데이터를 수신합니다.
  - 만약 총량이 첫 청크 크기보다 큰 경우, 루프(`while`)를 구동하여 수집 데이터 개수가 전체 데이터 크기에 도달할 때까지 `currentSkipOffset`을 청크 크기만큼 누적하여 더하며 API 요청을 반복합니다.
- **행 개수 기반 백분율(%) 계산 및 UI 출력**:
  - 매 청크가 수집될 때마다 `Math.floor((누적수집량 / 전체수량) * 100)`을 계산하여 `⏳ 2/3. Fetching rows: 45% (9000 / 20000)`와 같이 직관적이고 정확한 수치 정보를 상태 창에 출력합니다.
- **UI 양보 가드 및 안전 탈출**:
  - 매 루프 호출 사이에 5ms의 비동기 딜레이(`setTimeout`)를 할당하여 브라우저의 화면 갱신 쓰레드가 멈추지 않고 실시간 퍼센트를 렌더링하도록 흐름을 제어했습니다.
  - 수신된 다음 청크의 개수가 0개이거나 더 이상 가져올 데이터가 없을 경우 루프를 강제로 탈출하도록 예외 안심 가드를 보강했습니다.

## 3. 검증 결과
- **20,000행 데이터 로드 검증**: 2만 행의 데이터를 로드할 때, 3,000개 단위로 청킹되어 로컬 배열에 누적되는 과정이 `15%` -> `30%` -> ... -> `100%` 단계별로 실시간 표기됨을 검증했습니다.
- **프리징 해결 및 안정성**: 단일 대량 로드에 비해 서버 메모리 과부하 현상이 해결되었으며, 클라이언트가 데이터 로딩 중 멈춰 서는 현상 없이 완전히 비동기로 부드럽게 모든 데이터를 순차 적재함을 완료했습니다.
