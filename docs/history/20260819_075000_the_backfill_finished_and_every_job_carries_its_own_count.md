# 백필이 끝났고, 이제 모든 job이 자기 수를 들고 있다

**날짜:** 2026-08-19 07:40~07:55 · **커밋:** 코드 변경 없음(데이터 작업)
**레인:** 서버(원장 · dt_job 완주) · **측정 상자:** 이 워크스테이션. **운영이 아니다.**
**앞 항목:** [커서를 쓰는 키와 읽는 키가 달랐다](20260819_074500_the_cursor_was_written_with_one_key_and_read_with_another.md)

## 목표가 「T17 고치기」가 아니었다

총괄 실측: job 396개 중 **die count를 가진 것이 91개**였다. 백필은 **25% 지점**에 멈춰
서 있었고, T17의 틀린 32는 그 사실 옆에서는 각주다. **끝내는 것이 일이었다.**

## 리셋 전에 잰 것 — 「이미 맞는 것을 다시 돌리면 조용한가」

전진 실행은 커서 뒤의 다섯 job에 닿지 않으므로 커서를 되감아 396개를 통째로 재생하기로
했다. 그것이 안전하려면 **이미 맞는 원자를 다시 만들었을 때 dedupe 튜플이 한 글자도 안
달라져야** 한다. 표본을 뽑는 대신 **91개 전부**를 읽기 전용으로 재생했다(9.6초):

```
동일 튜플 -> 유니크 인덱스가 삼킴 : 90
새 행을 넣게 됨                  :  1   (T17: 32를 들고 있는데 72를 쓴다)
has_netdie 말고 다른 것을 낸 job :  0
```

`occurred_at`도 `source_raw_ref`도 흔들리지 않았다. 걸치지 않는 job은 두 페이지 키 모두에서
한 페이지 안에 있었으니 `min` 접기가 **무연산**이라는 추론이 실측으로 확인됐다.

## 그리고 실행

`has_netdie = 32` 한 행 삭제(레지스터는 존치 — 부분 인용이지만 **참인 문장**이고, 재생이
레지스터를 다시 내지 않는다는 것이 앞의 측정이다), 커서를 되감고, 완주.

```
molecules 396 · refused 0 · incomplete 0
attempted 695 = has_netdie 396 + register 299(미등록분)
inserted  605 · deduped 90(이미 맞던 그 90) · batches 19 · rows 34,939 · 53.2s
```

| | |
|---|---|
| dt_log job | **396** |
| `has_netdie`를 가진 job | **396** |
| `register`를 가진 job | **396** |
| 같은 술어를 둘 이상 가진 job | **0** |
| **실제 행 수와 어긋나는 count** | **0** |

쪼갬 가드는 **한 번도 울지 않았다**(`molecules_refused 0`, 19배치 396그룹). 백필을 세워 뒀던
두 job이 이제 각각 하나씩, 맞는 수로 서 있다 — `T17 = 72`, `T11 = 72`.

## 멱등까지 확인하고 닫는다

`min`을 고른 이유 자체가 「다시 돌려도 같은 원자」였으므로, 그것도 **읽기 전용으로 396개
전부** 재생해 확인했다(57.9초): **이미 있는 튜플 396, 새로 넣을 것 0.** 앞 측정이 못 덮었던
150행짜리 `SYN-DTJ-*`까지 포함해서다.
