## 무엇이 일어났나

소유자 2026-09-16: 「맵퍼 한 문인데 왜 이름이 달라」 · **「문 가르기 금지」.** 체인 문법 하나가
enrich·join·decide 를 선언하는데 **디스패처가 둘**이었다 — 파일 맵퍼는
`mapper_call.execute_custom_mapper(module, function, ...)` 으로, `builtin:` 종류는
`builtins.run_builtin(kind, ...)` 로 갔고, 규칙을 돌릴 수 있는 «모든 호출자»가 그 질문을
**자기 낱말로** 물었다. 판정 419 ① 의 전수 세기가 그 한 판단이 **20 자리에 일곱 철자**로
쓰여 있는 것을 셌다.

`server/chain/rule_run.py` 150줄이 새로 섰다. `run_rule(db, rule, payloads=None, row_ids=None,
done=None)` 이 그 질문을 «한 번» 묻고, 어느 문이 답했든 **같은 모양**으로 돌려준다 —
`{updates, map_metadata_updates, batches, written, refusal}`, 칸이 전부 있다.

## 🔴 그러나 이 커밋은 «아무것도 옮기지 않았다» — 호출자가 «없다»

```
실측 (2026-09-16, 이 항목을 쓰며 다시 잼)
   git grep -n 'rule_run' 3648da7b -- server/   에서 server/tests/ 를 뺀 히트 «0»
   HEAD 에서는 server/chain/replay.py 하나 — 그것은 «다음» 커밋(edecf1a0)이 한 일이다
```
🔴 **그래서 이 항목은 「이제 체인이 한 좌석을 지난다」고 말하지 않는다.** 그렇게 읽히면 거짓이다.
총괄이 ㉡ 을 둘로 잘랐고(채널 19:3x), 파트 1(후속 `follow_up` 여덟 자리)이 총괄 워크트리에서
같은 파일을 만지고 있어 **좌석만 짓고 호출자는 ㉡-2 로 미뤘다.** 커밋 메시지 자신이 그것을
「NEW FILE ONLY」로 «먼저» 적었다 — 함의로 남기지 않고.

📌 **부류: 「착지는 배선이 아니다」.** 좌석이 있다는 것과 제품이 그것을 지난다는 것은 다른 사실이고,
   둘 사이의 시차가 이 라운드에서는 **24분**이었다.

## 좌석이 «실제로» 접은 것 — 그리고 그것이 왜 접혀야 했나

```
질문       builtin_kind(rule)  :112   -> `BUILTIN_KINDS` 와의 비교가 «한 자리»로.
                                        돌리지 «않고» 종류만 알아야 하는 호출자(소급의 통계·
                                        드라이런 관문)가 이 함수를 지난다
답의 모양  _uniform()                  -> 칸 다섯이 «항상» 있다. 호출자가 세 리스트를 무조건
                                        extend 하고 `written` 을 읽는다 — 종류를 모른 채로.
                                        자기가 쓰는 종류는 아무것도 제안하지 않으니 extend 가
                                        no-op 이 되고, 그래서 «호출자에서 갈래가 사라진다»
줄        RULE_LOG_TAG = "ChainRule"   -> 접두가 둘이었다: `[ChainBuiltin] … written=` 대
                                        `[mapper@<logfile>] … rows_out=`. 운영자가 「이 규칙이
                                        돌았나」를 grep 하려면 «종류를 먼저 알아야» 했다
```
🔵 **`written` 은 셋지 않았을 때 `None` 이고 `0` 이 아니다**(:`_uniform`). 「안 셌다」와 「0 이었다」는
다른 사실이고, `chain.builtins` 가 이미 같은 이유로 둘을 갈라 두고 있었다.

   넘어가면 다음 사람이 같은 전제를 다시 읽는다.

## `done=` — 40분 뒤, 가드는 있는데 «단언»이 없었다 (`b5bb399a`)

㉡-1 이 「호출자가 줬을 때만 `done=` 을 넘긴다」를 «짓고» 그것을 재는 것을 안 두었다.

```
실측 (2026-09-16, blob 에서 다시 잼) — 등록된 종류 셋의 시그니처
   server/chain/builtins.py:77   def _run_join(db, rule, row_ids=None, key_values=None)     <- done «없다»
   server/chain/builtins.py:92   def _run_auto_confirm(db, rule, row_ids=None, done=None, **_)
   server/chain/join_into.py:256 def run(db, rule, row_ids=None, done=None, **_)
   등록:  builtins.py:323 `_run_join` · :328 `join_into.run` · :331 `_run_auto_confirm`
```
그래서 `done=` 을 «무조건» 넘기면 `_run_join` 이 `TypeError: got an unexpected keyword argument
'done'` 을 던진다 — **살아 있는 후속 랩이 `92257825`(2026-09-12 15:20) 이래 받아 온 그 던짐**이다.

🔴 **탐침의 시그니처가 «좁은» 것이 이 시험의 전부다.** `(db_, rule_, row_ids=None)` — `done` 도
`**kwargs` 도 없다. `**kwargs` 로 썼으면 **어느 동작이든 받아들여 아무것도 판별하지 않는다**
(「두 규칙이 같은 답을 내는 표본은 판별식이 아니다」).

⚠️ 그리고 이 커밋은 `_run_join` 을 **안 고쳤다.** 그것은 별도 판정이고 채널에 올라가 있다.
이 탐침이 단언하는 것은 「좌석이 그 상황을 «더 나쁘게 만들지 않는다»」 하나뿐이다.

## 🔵 좌석이 «안 하는 것» — 파일이 스스로 적어 두었다

```
안 잡는다        맵퍼가 던지면 그대로 던진다. `refusal` 은 빌트인이 «질서 있게» 물러설 때
                 채우는 칸이고, 던짐은 그것이 아니다
행을 안 고른다    신선도(`followup_already_served`) · 페이징 · 이벤트 매칭은 호출자의 것이고
                 손대지 않았다
문의 줄을 안 뺏는다 `execute_custom_mapper` 는 자기 안에서 START/END 를 말한다. 그것은 «맵퍼»에
                 대한 문장이고, 좌석의 줄은 «규칙»에 대한 문장이다
```
⚠️ **두 문은 «남는다».** 하나는 운영자가 쓴 모듈을 import 하고, 다른 하나는 이 저장소가 소유한
표에서 이름을 찾는다. 틀렸던 것은 문이 둘인 것이 아니라 **그 «선택»이 모든 호출자에 살던 것**이다.
