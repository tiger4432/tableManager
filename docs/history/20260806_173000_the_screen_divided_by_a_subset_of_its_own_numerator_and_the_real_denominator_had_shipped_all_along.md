# 화면이 **자기 분자의 부분집합**으로 나누고 있었고, 진짜 분모는 이미 실려 오고 있었다

## 1. 신고와 무엇이 참이었나

「로그는 만점이 아닌데 화면은 만점」.

**두 수 다 서버의 것이었다** — 클라가 유도한 것은 하나도 없다. 문제는 그 둘이 **한 분수의
분자와 분모가 아니라는 것**이고, 화면이 그렇게 칠했다는 것이다.

```
index_agreement      = count_nonzero(index_member)
index_discriminating = count_nonzero(index_member & index_varies)
```

🔴 **둘째는 모든 축에서 첫째의 부분집합이다.** 구조적으로 `discriminating ≤ agree`가 항상
성립하고, index 축에서는 **여덟 프레임 전부가 맞히는 셀이 없는 한 둘이 같다** — 실제 맵에서는
일어나지 않는 일이다. 그래서 행은 서버가 무엇을 측정했든 **N/N**을 읽었다.

**더 나쁜 것:** 칠해진 분모가 후보마다 달랐다 — 300, 7, 4, 6, 3, 2, 5, 1. 여덟 분수가
**서로 비교조차 불가능**했다. 서버 자신의 주석이 분모는 후보 독립이어야 한다고 적고 있다.

## 2. 진짜 모집단은 계속 실려 오고 있었고 아무도 안 읽었다

한 페이로드 위에 **서로 다른 넷**이 존재했다 — 소스 셀 640, 스코어러에 도달한 600,
index 축에서 쓸 수 있는 **512**, 그리고 화면이 나누던 **300**.

디코더가 축마다 셋째 키를 반환하게 됐다:

```js
return Object.freeze({ agree: 'index_agreement', discriminating: 'index_discriminating',
                       total: 'index_total' });
// values 축:    total: 'agreement'   (값은 셀이 기준에 앉은 자리에서만 비교된다)
// occupancy 축: total: 'placed'      (이 후보가 놓은 셀)
```

🔴 **부재는 0이 아니고, 행을 버릴 이유도 아니다.** 이 필드보다 앞선 서버는 모집단 없이
카운트만 실어 보내고, 그때 정직한 화면은 분모 자리의 `미상`이다 — 거절된 후보(동점 수가
줄어든다)도 아니고 0도 아니다.

`판별` 라벨은 `대상`이 됐다. **라벨이 결함을 정확히 서술하고 있었던 것이다.**
`discriminating`은 그대로 남는다 — `min_discriminating_dies`가 그것으로 게이팅하고,
빼면 어떤 실행이 순위에 오르는지가 조용히 바뀐다. 다만 **분모가 아니고 더는 그렇게 그려지지
않는다.**

## 3. 🔴 하네스가 이걸 볼 수 없던 이유 — 서버가 낼 수 없는 값을 싣고 있었다

페이로드 셋이 **생산 불가능**했다: `agree 400 / discriminating 528`, `200/300`, `312/374`.
`member & varies`가 `member`보다 많을 수는 **없다.** 그런데 그 모양 아래에서는 둘째 수가
**분모처럼 보인다.** 그래서 하네스가 **틀린 읽기를 계약처럼 고정**하고 있었다.

> **픽스처가 표현할 수 없는 결함은 채점될 수 없다** — 이 저장소가 같은 날 세 번째로 밟은 함정.

## 4. 새 그물

- **섹션 Q**가 `bootstrap → adaptPayload → view model → DOM`을 서버가 300/512로 채점한
  실행에 대해 구동한다.
- **Q0/Q0b**는 활성화 대조군 — 렌더된 8행 중 **8행**이 바뀌고 렌더 문자 **46자**가 바뀐다.
- **Q3**은 반대 방향 대조군 — 진짜 만점 실행은 여전히 **512/512**로 읽혀야 한다. 그래야
  Q2가 「두 수를 구조적으로 다르게 만들기」로 만족될 수 없다.
- **MD1–MD4**가 네 곳 각각에서 결함을 복원하고, 각 곳마다 **그것 때문에만 죽는 단언**이 있다
  (MD4 → G9/Q2c 단독).
- 주석만 고친 대조군은 살아남는다.
