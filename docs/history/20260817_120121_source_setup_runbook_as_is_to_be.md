# 소스→원장 셋업 러너북 — as-is 실측과 to-be 사상표

> 2026-08-17 12:01/12:08 · Docs / Plan · 커밋 `3a89003`(as-is), `0889501`(to-be)

## 배경

전환 계획(01~07)은 목적지를 말했지만, **지금 이 순간** 새 소스 하나를 원장에
잇는 사람이 걸어야 하는 길은 어디에도 적혀 있지 않았다. `3a89003`은 그 길을
계획의 약속이 아니라 **코드가 실제로 읽는 것 기준으로 실측**해 적었고,
`0889501`은 같은 문서에 「각 걸음이 어느 단계에서 어떻게 짧아지는가」 사상표를
붙였다.

## 변경 내용

`RUNBOOK_AS_IS.md` 신설(102줄) + TO-BE 절 추가(37줄).

**as-is (`3a89003`)** — 절차 7걸음(표 선언 → 소스 선언 → 변환기 선택 → 낱말 →
드라이런 → 백필 → structure 확인)과 변환기의 두 갈래:

- 갈래 A — 신뢰 Python mapper. 이 커밋 시점에 유일하게 «걸어 본» 길이며 라이브
  실증은 `lot_event` 1건이 전부였다.
- 갈래 B — canonical Profile. **계약은 완비, 실전 0회.** 스키마 정본은 문서가
  아니라 `server/ledger/source_profile.py`이고, 등록 Pack 목록은
  `source_profile_builtins.py`가 정본이라 거기 없는 claim은 쓸 수 없었다.

함정 7개를 실측·실사고 기반으로 적었다. 특히:

```
3. business_key가 시각을 포함하면 같은 순간의 두 사건이 한 행으로 붕괴
   (축 7 실사고 — txn_seq가 있으면 키에 넣어라).
6. 원자가 안 생기는 «정상» — 백필을 돌리기 전엔 원자 0이 맞다.
   structure의 0은 결함이 아니라 미실행.
7. 읽기측 미선언 — 원자가 있어도 siblings_axes에 축·기하가 없으면
   트렌드·대조에 안 보인다(등재 ≠ 소비).
```

**to-be (`0889501`)** — 걸음별 목적지 표(예: 소스 선언 손편집 → 인터뷰 4~5문,
변환기 선택 → 선택 소멸·Profile 기본), 함정 사망 명부(일곱 함정 각각을 어느
단계가 죽이는가), 그리고 as-is 목록이 볼 수 없었던 여덟째 함정을 명시했다:
«영원히 조용»(바인딩·라벨 유령 경로)은 06 합의 검사기 소관. 최종 상태의 정의를
한 문장으로 고정했다 — 인터뷰 → 문장 판정 → 저장 → [백필] → 현황판 완충, 그날
이 러너북 §0~3은 역사 문서가 된다.

## 아키텍처 영향

문서 전용. 다만 「소스→원장 완료」의 정의를 7걸음까지로 좁혀(읽기측 8~9걸음과
분리) 등재≠소비 혼동을 어휘 수준에서 끊었고, 1단계 전환 목록의 입력 문서가
됐다.

## 그때 남아 있던 것

- 갈래 B(Profile)의 라이브 사용 0건 — 첫 사용자가 아직 없었다.
- 함정 1~7은 전부 살아 있는 상태였다(to-be는 사상표일 뿐 아무것도 아직 죽이지
  않았다).
- occurred_at 포맷·타임존 철자는 현행 `lot_event` 선언에서 복사하는 것이
  유일한 안전 경로였다.
