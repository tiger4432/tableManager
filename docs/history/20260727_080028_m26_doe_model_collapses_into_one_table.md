# M2.6 — DOE 모델이 테이블 하나로 접힌다. 단순화의 연쇄가 표를 지웠다

> 커밋 `cdcddee` · 2026-07-27 08:00 · 도메인 Client / 맵 에디터·DOE 패널 (+ `server/product_tables.py` 선언)
> 상위: [SYSTEM_OVERVIEW](../overview/SYSTEM_OVERVIEW.md) · 저장 지도: [DOE_STORAGE_MAP](../spec/DOE_STORAGE_MAP.md) · 프리미티브: [PRIMITIVES](../architecture/PRIMITIVES.md)
> 선행: [DOE 삭제 — 차집합이 아니라 집합 교체](./20260727_064938_doe_delete_via_replace_map.md)

## 배경 — 표가 사라진 이유는 스키마 판단이 아니라 **연쇄**다

이 변경의 *왜*는 한 줄로 요약되지 않는다. **단순화 하나가 다음 단순화의 필요를 지우는 연쇄**였고,
연쇄가 끝났을 때 테이블 둘이 남지 않았다.

1. `stack_band`가 **자유 텍스트**였다. 그래야 현장의 어떤 표기법이든 살아남으니까.
2. 자유 텍스트라서 **층 수를 유도할 수 없었다.** 라벨을 파싱하지 않는 한 `2-15`가 몇 층인지 시스템은 모른다.
3. 유도할 수 없으니 **사용자가 총 소요를 직접 입력해야 했다.** 그리고 그 값은 사용자 머릿속의 곱셈이었다.

사용자의 말이 이 연쇄의 끝을 그대로 가리킨다.

> **"STACK 구간별 총 소요는 뭘 적으란 건지 모르겠음"**

입력란을 만든 쪽이 그 입력란의 의미를 설명하지 못하는 상태였다.

### 정수 둘이 연쇄를 끊었다

`to - from + 1`은 **파싱이 아니라 산술**이다. 여기서 두 가지가 동시에 해결된다.

- **드리프트할 두 번째 구현이 없다.** 라벨 파서가 있으면 클라와 서버가 각자 해석하다 어긋난다. 뺄셈은 어긋날 데가 없다.
- **비(非)숫자 라벨 문제가 사라진다.** 텍스트가 없으니 "이 표기법도 받아줘야 하나"라는 질문 자체가 성립하지 않는다.

그 다음 **인접성(contiguity)**이 한 번 더 줄였다 — 앞 구간이 끝난 다음 층에서 다음 구간이 시작하므로
`from`은 유도값이고, **사용자가 타이핑하는 것은 `to` 하나뿐**이다.

그리고 총 소요와 knob이 구간에서 빠지고 나자, 구간 한 행에 남은 것은 `{seq, to}`뿐이었다.
**그 정도는 더 이상 테이블 값을 하지 못한다.** `map_doe`·`map_doe_source`가 사라진 이유가 이것이다 —
"테이블을 줄이자"가 목표였던 적은 없다.

## 변경 내용

### 모델 전부가 이 네 줄이다

```js
// client2/src/transfer_plan.js
// 앞 구간의 끝 층(없으면 0). **배열 위치**가 순서라는 규칙이 여기 한 줄에 들어 있다.
function prevTo(bands, i) { /* i-1부터 역순으로 to가 정해진 첫 구간 */ }

function bandFrom(bands, i)   { return prevTo(bands, i) + 1; }              // 시작 층 = 앞 끝 + 1
function bandLayers(bands, i) { return Math.max(0, to - prevTo(bands, i)); } // 층 수 = 뺄셈 한 번
function bandTotal(value, bands, i) { return paintedOf(value) * bandLayers(bands, i); }
function bandShare(value, bands, i) { return Math.ceil(bandTotal(...) / n); } // 내림·반올림은 부족분을 숨긴다
```

**유도값은 하나도 저장하지 않는다.** 총 소요를 저장하면 누군가 셀 하나를 더 칠하는 순간 조용히 어긋난다 —
그게 이 변경이 없애려던 원래 불만이다.

### 바뀌지 **않는** 것을 기록해 둔다 — 정체는 여전히 `band_seq`

테이블이 사라졌다고 키 규율까지 사라진 것이 아니다.

- **`seq`가 정체다.** 자재는 `seq`에 소속된다. 순서 변경에도 삭제에도 **재번호를 매기지 않는다.**
- **순서는 `seq`가 아니라 배열 위치다.** `seq`로 정렬하면 층 수가 음수가 된다.

범위(`1–15`)나 라벨을 키로 삼았다면, 누군가 그 범위를 **고치는 순간** 그 구간의 자재가 고아가 된다.
선행 항목에서 `stack_band`를 비키 컬럼으로 둔 이유와 같은 이유이며, 그 판단은 여기서도 유효하다.

`bands` JSON은 `{"seq": int, "to": int|null, "materials": [str, ...]}` 배열이고,
계약 전문은 `server/product_tables.py`의 `map_split_registry.__comment`에 있다.
`to = null`(미정)과 빈 `materials`는 오류가 아니라 정상 상태다.

### 동시성 — 쓰기 경로에 읽기 하나가 붙었다

`replace_map`은 `(ref_table, map_key)` 범위를 통째로 비우므로, 한 계획에 여러 명이 붙으면
**나중에 저장한 쪽이 앞사람 것을 조용히 지운다.** 선행 항목이 "해소되지 않았다"고 남긴 구멍(ⓑ)이 그것이다.

이제 PUT 앞에 GET 하나가 들어가고, 마지막으로 서버를 봤을 때 기록한 지문과 비교한다.

```
읽기 실패 / 절단 ............ 아예 쓰지 않음 (BLOCK)
권한 없음 + 서버에 행 있음 ... 서버본을 채택하고 이번 쓰기는 건너뜀
지문 ≠ 기준선 ............... 거부, 충돌 표시, 다시 불러오기 안내
지문 = 기준선 ............... PUT replace_map:true, 기준선 갱신
```

지문은 **양쪽이 같은 정규화 함수 하나(`canonRegistryRow`)를 통과해서** 만든다.
"같은 행"의 구현이 둘이면 진짜 충돌을 놓치거나 없는 충돌을 만든다 — 그리고 **실제로 만들었다**(아래 검증).

충돌이면 upsert로 **강등하지 않고 쓰기를 통째로 막는다.** 행이 이제 계획을 담고 있으므로
강등은 우리 쪽 낡은 `bands`를 상대 것 위에 덮어쓰는 일이 된다. 이건 의도한 조임이고 대가가 있다 —
registry 읽기가 실패하는 동안 한 legend 설명 수정은 **이제 전송되지 않는다**(종전에는 upsert로 나갔다).

## 아키텍처 영향

- **한 값 = `map_split_registry` 한 행 = DOE 하나.** 기록자가 하나(`map_editor.js`)로 줄었고,
  그래서 가드(권한·절단·동시성)도 **한 벌만** 있으면 된다. 테이블을 합칠 때 먼저 정할 것은
  스키마가 아니라 **기록자가 누구 하나인가**였다.
- `split_desc`와 `knobs`는 **평평한 컬럼으로 남긴다.** 온톨로지/LLM이 소비하는 입력이라
  `bands` 안에 중첩하면 온톨로지의 입력이 blob 속에 묻힌다. 중첩하는 것은 구간 구조뿐이다.
- knob이 **구간별 → 값 단위**로 올라갔다. 구간이 B개면 종전에는 같은 knob을 B번 타이핑해야 했다.
- 컨트롤 수: 2구간·3자재 기준 **28 → 22(−6)**, 3구간·5자재 기준 **40 → 29(−11)**.
  새로 생긴 것은 읽기 전용 텍스트 두 줄(`칠함 43 × 14층 = 소요 602 · 자재 3매 → 매당 201`)뿐이다 —
  **사용자가 머릿속으로 하던 곱셈을 화면이 대신 인쇄한다.**

### 선언은 됐지만 쓸 수 없는 컬럼 — `updated_by`

목표 스키마에서 `updated_by`를 **의도적으로 뺐다.** `crud.py`가 `system_cols`에 `updated_by`를 넣고
컬럼 루프에서 건너뛰므로, 제네릭 테이블 API로는 **선언해도 영원히 NULL이다.**
스냅샷의 `map_doe`·`map_doe_source` 전 행이 NULL인 것으로 실증됐다 — 선언된 날부터 죽어 있었고 아무도 몰랐다.

기록해 둘 것은 그 다음이다. **이 사실은 이전 에이전트가 이미 지적했고, 총괄이 흡수하지 않았다.**
그 결과 이번 사이클에 "updated_by와 eventtime 둘 다 쓰인다"는 틀린 전제가 지시로 내려갔다.
지적이 보고서에 있었는데도 다음 지시에 반영되지 않으면, 같은 결함을 **두 번 발견**하게 된다.

## 검증

### 픽스처를 "틀린 구현이 반드시 드러나도록" 골랐다

`bonding_map` / `AAA`, **칠한 셀 43개**, 구간 `to = 1 / 15 / 16` (사용자 본인의 `1, 2-15, 16` 예시).

| 결함 축 | 이 픽스처에서 드러나는가 |
|---|---|
| 뺄셈 (`layers = to − prevTo`) | 예 — 정답 `[1,14,1]`, 순진한 `layers = to`는 `[1,15,16]` → **3중 2 불일치** |
| 배열 위치 vs `seq` | 예 — 순서 변경 후 `seq`로 유도하면 `[20,−5,1]` vs 정답 `[15,1,4]` → **3중 3 불일치** |
| `ceil` vs 반올림/내림 | 예 — 43/3 = 14.33 → **15**(반올림·내림 모두 14) |

**43은 자재 3매와 서로소**라 `ceil` 축이 숨을 수 없고, `to = 1/15/16`(1/2/3이 아니라)이 뺄셈 축을 살려 둔다.
`to = [1,2,3]`이나 총량을 나누어떨어지게 하는 자재 수였다면 **셋 다 가려졌다.**

### 음성 대조군 — 거부가 장식이 아님을 증명하는 유일한 방법

계획에 우리 값 `F`와 다른 세션의 값 `Z`가 있는 상태에서, **동시성 가드를 뺐다면 클라가 보냈을 그 PUT을 손으로 발사**했다.

```
DB before:  value='F' ... , value='Z' desc='added by SECOND SESSION' bands=[{seq:1,to:9,...}]
DB after :  value='F' ...
```

`Z`가 파괴됐다. **가드가 실제로 무언가를 막고 있다는 증거는 이것뿐이다** —
"거부 토스트가 떴다"는 가드가 옳은 것을 막았다는 증거가 아니다.

### 가드 테스트는 **주입 1건 + 무주입 재시도**로 짝을 이뤘다

절단 가드·C1 가드 모두 실패를 **정확히 하나** 주입하고(잔여 예산 0 단언), 곧바로 주입 없는 반복이 성공해야 했다.
두 번째 단계가 없으면 "막았다"와 "잠갔다"를 구분할 수 없다.

### 정규형이 둘이어서 생긴 거짓 충돌 (수정됨)

페이로드 지문에는 `updated_by='web_client'`가, 읽어온 쪽에는 플랫폼의 셀 단위 값이 들어가
**매 두 번째 저장이 거부됐다.** 필드를 빼자 연속 저장 6회가 통과했다.
지문 로직을 만들면 **연속 저장 2회가 거부되지 않는지**를 반드시 회귀 항목에 넣어야 한다 —
없으면 거짓 양성이 조용히 산다.

### 환경 함정 — 격리 응답을 그대로 믿었다

`devenv status`는 `api dead`인데 **고아 프로세스**가 `:8081`을 잡고 있었다.
그 프로세스의 ORM 모델은 새 컬럼을 몰랐고 config만 핫리로드돼 있어서,
DB에 값이 있는데 API가 `bands: null`을 주는 — **직렬화 버그와 구별되지 않는** 증상이 나왔다.
격리 환경에서 이상한 값을 보면 코드를 의심하기 전에 `netstat` PID와 `devenv status` PID가 같은지 본다.

## 아직 되지 않은 것 — 이 커밋으로 끝난 것이 아니다

여기까지는 **클라이언트와 선언**이다. 현장에는 아직 아무것도 적용되지 않았다.

1. **`bands` 컬럼이 라이브에 물리적으로 존재하지 않는다.** 설치기 실행 + 웹서버 재기동으로
   `ALTER TABLE map_split_registry ADD COLUMN knobs/bands`가 나가야 하고, 확인은
   `GET /tables/{t}/schema`가 아니라 `information_schema.columns`로 해야 한다(전자는 config 싱글턴을 읽는다).
2. **서버 쪽이 아직 옛 테이블을 본다.** `server/transfer_plan.py`가 `plan_store.doe` / `plan_store.doe_source`를
   퇴역한 테이블에 바인딩하고 있어, **`/api/transfer-plan/validate`는 지금 빈 계획을 읽는다.**
   가용량 계산은 위 `bands` 계약에 맞춰 다시 붙여야 한다.
   `server/scripts/setup_transfer_plan_indexes.py`도 여전히 옛 테이블을 인덱싱한다.
3. **행 이동은 사용자 몫이다.** 마이그레이션 코드는 지시대로 쓰지 않았다.
   라벨 → 절단점 번역에 주의: `1, 2-15, 16` → `to = 1, 15, 16`.
4. **`DROP TABLE map_doe, map_doe_source`는 승인 대기.** 그때까지 선언은 DEPRECATED 표시로 남아
   행을 읽을 수 있게 한다. 새 소비자를 붙이지 말 것.
