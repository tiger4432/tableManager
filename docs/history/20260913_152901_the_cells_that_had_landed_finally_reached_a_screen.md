# 착지해 있던 칸들이 «화면에» 닿은 오후

> **커밋:** `09a01798`~`c3015b8a` (09-13 12:54~15:0x)
> **일자:** 2026-09-13 (오후, 둘째 묶음)
> **레인:** 구현자(서버) · 클라 · 응용(문서)
> **측정 상자:** 이 워크스테이션. **운영이 아니다.**

## 무엇이 일어났나

이 묶음의 문장은 **「착지는 배선이 아니다 — 그리고 이번엔 «읽는 쪽»이 없었다」**이다.
서버가 계산해서 전선에 실어 보내던 칸이 «둘», 클라가 그중 하나도 안 읽고 있었다.
그리고 그 반대 방향으로, **작성자가 실제로 import 하는 이름이 «선언»이 됐다.**
착지 커밋 단위로 적는다.

## ① 선언이 「어느 술어가 «검사»인가」를 말한다 (S-216 `09217e2e`, 판정 366)

```
종전   /api/ledger/declaration 의 predicates[] = { name, subjects, object, origin }
오늘   + `absence_confirmed_by`  —  «선언한 술어에만» 실린다
```
🔴 **부재 열의 모집단은 «선언»이지 «데이터»가 아니다.** S-149 가 모든 노드에 `absence` 판정을
접어 주므로, 그 열을 «노드만 보고» 그리면 화면은 **「도착한」 술어들을 모집단으로 쓴다** —
그것이 그 판정 칸이 막으려던 바로 그 오독이다.
⚠️ **없으면 «비우지 않고 생략한다»** — `class`·`attributes` 와 같은 규율이다.
「이 술어는 확인자를 안 적었다」와 「이 설치는 그 축이 생기기 전이다」는 **다른 사실**이고,
빈 문자열은 그 둘을 하나로 접는다.
⚠️ 오늘 출하 선언에는 확인자가 하나도 없어서 **키가 «전혀 안 나온다»** — 그것이
「여긴 그 축을 안 쓴다」를 뜻하지 「못 한다」가 아니다. 🔵 **기제가 있다 ≠ 돈다**의 정직한 표기다.

## ② 작성자가 import 하는 이름이 «표»가 됐다 (S-215 `c3015b8a`, 판정 368·369)

```
MAPPER_SURFACE  server/mapper_sdk.py :422   — 항목 «41» · 원천 모듈 «9» · 사설 «둘»  (제 실측)
__getattr__     :473 — 이름을 «그 모듈의 진짜 객체»로 푼다. 사본이 아니다
```
🔵 **표가 곧 선언이다** — `__getattr__` 에 그 밖의 출처가 «없어서», 「선언된 표면에서만」이
습관이 아니라 **코드의 성질**이다.
🔵 **게으른 풀기인 이유도 적혀 있다** — 그 아홉 모듈이 13,406줄이고 이 파일은 체인 워커의
«부팅 경로»에서 읽힌다. 최상단에서 재수출하면 아무도 안 쓰는 이름 때문에 그 전부가 부팅에 얹힌다.
⛔ **표에 없는 이름은 평범한 `AttributeError` 다** — 이 자리가 «거절문을 짓지 않는다»(판정 369).
지어내면 파이썬이 이미 쓰는 메시지에 «둘째 저자»가 생기고, 오타가 «제품 규칙»처럼 보인다.
🔴 **그리고 이 목록은 «고른 것이 아니라 «잰» 것»이다** — 오늘 라이브 맵퍼가 실제로 import 하는
이름이다. 줄이는 것은 정리가 아니라 **계약 파기**이고, 이 저장소가 볼 수 없는 파일을 깬다.
⚠️ 밑줄로 시작하는 이름 둘(`_cells_of`·`_load_metas`)이 «그 철자 그대로» 들어 있다 —
SDK 에 `_name` 은 이상하고 실제로 이상하지만, **이미 계약**이라 이번 라운드는 계약을 «적었을»
뿐 바꾸지 않았다. 이름을 바꾸면 «운영자의 파일을 고치게» 되고, 그것이 이 표면이 존재하는 이유다.

## ③ 클라 — 착지해 있던 칸 둘을 «읽기» 시작했다

```
69e05ca0 13:13  C-96   저장 «옆»에 「다시 도는 비용」 — 서버의 `redo` 를 처음으로 읽는다

5f10e218 13:57  C-100  붙여넣기 형식 모달이 «부품»이 되고, 프레임을 안 기다린다
09a01798 12:54  C-99 ④ 아무것도 안 꾸미던 클래스 셋이 «입은 것»을 꾸민다
```
🔴 **C-96 과 C-97 은 «같은 문장»이다** — 서버가 전부터 내주던 것을 클라가 «한 줄도» 안 읽었다.
`git grep redo -- client2/src` 는 배너만 냈고, `git grep seed_type -- client2/src` 는 «0» 이었다.
📌 부류: **「착지는 배선이 아니다」의 «읽는 쪽» 판** — 수는 착지했고 운영자는 볼 수 없었다.
⚠️ **그리고 C-96 의 지시서 전제가 낡아 있었다** — 「활성화 버튼 «옆»」이라 했는데 **그 버튼이 없다**.
소유자 판정으로 활성화가 «저장 안»으로 들어갔기 때문이다(`save-draft` 가 PUT 뒤 POST /activate).
🔵 그래서 값은 «저장 옆»에 서고, **저장이 곧 발화라는 점이 그 값을 더 필요하게** 만든다 —
정정이 라운드를 작게 만든 것이 아니라 크게 만들었다.
🔴 **C-97 이 막고 있던 것은 «질문의 모양»이었다** — 타입만 고르고 키를 비우면 **422** 였고
(`entity id must contain [type, structured keys]`), 그런데 「이 타입이 무엇에 닿나」는
**주어를 모를 때 묻는 질문**이다. 물을 수 있어야 할 질문이 끝이 막힌 길이었다.
