## 배경

- **U9**: 사용자 결정(2026-07-28) — legend STACK `0`은 높이 오타가 아니라 **마커 값 선언**(상태 표시 값, 예: BASE FAIL)이다. 이 커밋 시점까지 클라·서버 모두 0을 invalid로 거부했다.
- **U8**: 사용자 관측 "가용 버튼 눌러도 업데이트 안됨". 실측 결과 버튼은 **한 번도 고장난 적이 없었다** — 라이브 stage 둘 다 `bin_map`/`lot_membership` 미선언이라 서버가 BIN 축을 거절했고, 응답은 매번 같은 미상(未詳)이었다. 같은 미상 셀을 같은 미상으로 다시 칠하니 버튼이 죽은 것처럼 **보였을** 뿐이다. 결함이 아니라 **무응답처럼 보이는 정답**이 문제였다.

## 변경 내용 — U9: 계약 벡터가 먼저, 구현이 뒤에

작업 순서 자체가 기록 가치가 있다: `contracts/doe_band_rules/vectors.json`을 **v3**로 먼저 올리고(11케이스 추가, 총 331 어서션), 클라·서버가 각자 그 파일에 착지했다. 양쪽이 같은 채점지를 보므로 "클라는 마커, 서버는 invalid"로 갈라질 길이 계약 수준에서 막혔다.

### 4번째 상태 — blank와 접지 않는다

```js
// doe_bands.js — stackState, 이 커밋 시점
-  if (st.value < 1) return { value: st.value, state: 'invalid' };   // 0 and negatives are not heights
+  if (st.value === 0) return { value: 0, state: 'marker' };
+  if (st.value < 0) return { value: st.value, state: 'invalid' };   // negatives are not heights
```

경계가 셋 다 유지됐다는 것이 핵심이다: **공백은 여전히 blank**(안 친 것 ≠ 0 선언 — `Number('  ')`가 0인 함정은 마커 의미론 아래에서 오히려 더 위험해졌다: 공백을 0으로 읽으면 반쯤 입력한 행이 조용히 마커로 둔갑한다), **음수는 여전히 invalid**, `'0x10'` 같은 판독 불가도 그대로다. 벡터에 `zero_string_is_a_marker_too`(`"0"` 문자열 — 엑셀은 텍스트를 준다)와 `blank_stack_blocks_too`("U9로 안 바뀐 것"을 핀)가 함께 들어가 접힘을 채점한다.

### 마커의 기하 — known-empty이지 unknowable이 아니다

- `midZone`: `{from:null, to:null, size:0, known:true}` — 판독 불가(`known:false`)와 구분. 접으면 V5가 합법 마커 행을 갈구거나, 오타 높이가 조용히 소요 0이 된다(서버 항목과 동일 원리, 같은 벡터로 채점).
- `zoneLayers`: 내용이 적혀 있어도 `[]` — 모순은 기하가 정당화할 것이 아니라 V6가 보고할 것.
- **V6**(클라측): 마커 행에 구역 자재가 있으면 자재명을 메시지에 명기해 보고 — 구역 칸이 「해당 없음」으로 비활성 렌더되므로 명기하지 않으면 문제의 내용이 화면에서 보이지 않는다. 마커 행은 **V6에만 답한다**: V4를 같이 발화시키면 한 행에 "토큰을 고쳐라 vs 자재를 지워라"라는 모순 지시 둘이 놓인다(V5가 V1을 억제하는 것과 같은 패턴). V3 풀 스캔에서도 제외 — 소요 없는 토큰을 실제 행과 짝지어 이중 계산으로 막으면, 아무도 요구하지 않은 웨이퍼 때문에 올바른 계획이 막힌다.
- 롤업: 마커 행은 **부재**(0으로 존재가 아니라) — "계획됨·비용 0" 행은 가용 조회를 유발한다. 벡터는 마커의 칠한 셀 수(50)를 실제 행(6)보다 일부러 크게 두어, 마커를 세는 롤업이 숨을 수 없게 했다.
- 왕복: `planRowToRecord`가 마커를 **읽을 수 있는 값**으로 취급해 정본 `'0'`을 내보낸다 — 엑셀에서 친 `0`은 `0`으로 돌아온다(비워지지도, 거부되지도, "수리"되지도 않는다).

### UI — 마커는 오류 스타일을 받지 않는다

`transfer_plan.js`에서 STACK 입력의 `bad` 클래스 판정·구역 렌더(`해당 없음` + "STACK 0 = 상태 표시 값 (층 없음)")·푸터 도움말이 마커를 정상 상태로 취급하게 됐다. 파일 헤더의 모델 서술도 이 커밋에서 구간(band) 모델 서술을 걷어내고 zone 모델(+마커)로 다시 썼다 — `prevTo`/`bandsToZones`는 퇴역 모델이 **쓴 것을 읽기만** 하는 코드로 명시됐다.

### 하네스의 자기 방어

`client_harness.mjs`에 fixture-비활성 가드가 추가됐다: 마커 축은 **침묵 케이스와 V6 케이스가 쌍으로** 있어야 한다 — 한쪽만 있으면 "0은 여전히 invalid" 구현이나 "V6가 영원히 안 뜨는" 구현이 나머지 케이스를 전부 통과한다.

## 변경 내용 — U8: 계산을 더하지 않고 **이유를 소리내게** 했다

수정은 클라 폴백 계산이 아니다(가용의 권위는 서버 한 곳 유지). `[↻ 가용]` 버튼 경로(`force=true`)에서만, 갱신 후 미상으로 남은 풀들의 사유를 집계해 **최빈 사유 한 줄 토스트**를 띄운다. 셀별 사유는 기존 미상 툴팁에 이미 있었으므로 새 영역·모달 없이 기존 채널 둘로 끝났다. "서버가 BIN 단위 가용을 거절했다"는 대답이 화면 무변화로 표현되던 것이, 이제 대답으로 표현된다.
