## 🔴 ① 심장이 «수집기가 도는 동안» 멈췄다 (`af744fe3`)

`run()` 이 `heartbeat.beat("scheduler")` 를 **틱 스레드에서** 낸다. 그리고
`check_and_run_schedules` 가 `execute_collector` 를 **같은 스레드에서 인라인**으로 불렀다.

```
=> cron 수집기의 «사용자 스크립트가 도는 내내»
      박동이 «없고»  ->  /health 가 그 데몬을 「진척 없음」으로 보고
      같은 루프의 «아웃박스 폴링»도 «안 돈다»
   그러면 큐에 든 RETROACTIVE_RUN 행이 «제자리에서 늙으며 범인처럼 보이고»,
   체인 워커는 — «다른 프로세스에서» — 멀쩡하다
🔴 감시 표면이 «수집기가 자기 일을 한 직접적 결과로» 내려갔다
```

**옮기기 전에 셋을 «쟀고», 셋 중 «하나»만 진짜였다:**

```
run_collector_on_demand   execute_collector 를 «이미 스레드로» 돈다
                          「호출은 인라인인데 «일»은 한 번도 인라인이 아니었다」
                          -> start_retroactive_run 의 독스트링이 «이 자리»를 인라인이라 지목했고
                             «그건 이제 그 함수에 대해 참이 아니다»
check_and_run_schedules   «인라인으로 돈다» — 이것이 막는 자리
maybe_backup_configs      CHECK_INTERVAL_SEC(1800초)로 throttle 되고 로컬 스냅숏에 한정
                          -> «그대로 둔다»
```

두 질문에 답해야 했다:

```
보장   cron 실행에는 «표시할 아웃박스 행이 없다».
       execute_collector 가 «자기 시작에서» next_run 을 밀어 두는데, 그것이 이제 «스레드 안»이다
       -> 틱이 옛 next_run 을 보고 «같은 수집기를 또» 쏠 수 있다
       => 그래서 «스레드가 생기기 전에, 동기적으로» 선점한다
동시성 「문이 «없었다» — 인라인 호출이 «문 그 자체»였고, 일을 틱에서 떼면 그 문이 사라진다」
```

```python
key = self._collector_key(collector)
with self._lock:
    if key in self._collectors_running:
        logger.warning("[Collector] '%s' is already running; this trigger is refused "
                       "rather than started a second time", key)
        return False
    self._collectors_running.add(key)

def _worker():
    try:
        self.execute_collector(collector)
    finally:
        # a claim left behind by a raising collector would refuse that collector
        # forever, which looks exactly like a schedule that stopped working.
        with self._lock:
            self._collectors_running.discard(key)
```
`run_collector_on_demand` 도 **같은 문**으로 간다 — 스레드는 필요 없었지만 **문도 없었다.**

⚠️ 변이 여섯 중 **하나가 처음에 살아남았다** — 모든 케이스가 `start_collector` 를
직접 몰아서, **인라인 호출을 호출자에 되돌려 놔도 전부 초록**이었다. 핀 박는 시험은
**진짜 스케줄링 패스**를 몬다.

## 🔴 ② 나쁜 행 하나가 큐를 «영원히» 붙들었다 (`d4483b6e`)

```
스케줄러는 매 틱 «가장 오래된 미처리 RETROACTIVE_RUN 행»을 집는다 (order_by id.asc())
그리고 행은 실행이 «시작될 때»만 표시된다
=> 페이로드를 못 다루는 행은 «던지고, 로깅되고, 영원히 맨 앞에 남는다»
   뒤의 모든 요청이 그 뒤에 앉는다 · retry_count 는 «안 움직인다»
   🔴 재기동해도 소용없다 — 결함이 «프로세스»가 아니라 «행»에 있다
   그리고 «두 워커 다 내내 건강해 보인다»
```

```python
except Exception as retro_err:
    logger.error("Failed to handle RETROACTIVE_RUN trigger "
                 "(outbox#%s, run_id=%s, op=%s); marking it FAILED so "
                 "the requests behind it can run: %s", ...)
    try:
        db.rollback()
        retro_trigger.status = "FAILED"
        retro_trigger.processed_chain = True
        db.commit()
    except Exception as mark_err:
        logger.error("Could not mark the failed RETROACTIVE_RUN (outbox#%s) as "
                     "finished; the queue is still blocked behind it: %s", ...)
```
**새 정책이 아니다** — 열 줄 위에서 같은 경로가 이미 «최대 한 번»을 골랐다
(「조용히 반복되는 실행이 운영자가 두 번 눌러야 하는 것보다 나쁘다」). 파싱 안 되는
요청을 영원히 재시도하는 것은 **그 결정의 정반대**다. `retry_count` 는 안 건드린다 —
**파싱 안 되는 페이로드는 다음에도 안 된다.** 페이로드 «본문»은 로깅 안 한다.

⛔ **거절된 대안: «다음 행으로 건너뛰기»** — 그 행이 «영원히 기다리고» 큐가
«아무도 안 집을 것 하나»를 계속 센다.

⚠️ 방법 기록 — 이 블록을 **200줄짜리 `while` 루프에서 «빼내» `handle_retroactive_trigger`**
로 만들어야 시험이 닿았다. **그리고 시험의 첫 판은 블록을 «다시 구현»해서, 고침을
되돌려도 초록이었을 것이다** — 「이 저장소가 오늘만 «두 번» 맞은 같은 실패」.

## ③ 계기이고 «고침이 아니다» — 그렇게 적혀 있다 (`bacbddd7`)

```
🔴 「밖에서 보면 «아무것도 안 빼는» 루프는 «바쁜» 루프와 «정확히 똑같아» 보인다 —

**임계는 새 수가 아니다** — `heartbeat.DEFAULT_STALE_AFTER_SEC`, 이 시스템이 이미
「진척 없는 워커」로 뜻하는 값이다.

⛔ **두 후보 중 «아무것도 안 고쳤다»** — 「지금 하나를 고치면 «어느 쪽이었는지 아무도
못 배운 채» 증상만 사라진다.」

## ④ 두 침묵이 겹쳤다 (`c0dea994` · `d886307b`)

```
① 큐 계기가 processed_chain=false 를 세고 그것을 «체인 큐»라 불렀다
   — 그런데 «두 데몬»이 그 표를 비운다
② retroactive_busy 는 «살아 있다»만 답했다
```
깊이와 나이가 **행을 비우는 데몬별로** 갈렸다 — `event_constants` 의 **공유 집합
하나**에서. 「스케줄러 자기 필터가 둘 중 하나를 «리터럴»로 철자하고 있었는데,
그게 그런 사본이 «쓸 때는 아무도 안 틀린 채로» 표류하는 방식이다.」

🔴 **추적 안 되는 `event_type` 은 «unknown» 이고, 절대 chain 으로 접히지 않는다** —
「chain 이라고 가정하는 것이 «이것이 끝내려는 바로 그 오독»이고, 그것은 «안 보인다».」
`SYSTEM_RELOAD` 는 **일부러 unknown** 이다 — 체인 워커가 «가장 최근» 것만 표시하므로
운명이 «타입»이 아니라 «어느 행인가»에 달렸고, 타입별 소유자는 그 말을 못 한다.

⛔ **게이트는 «그대로»이고 시험이 그것을 핀으로 박는다.** 「타임아웃으로 여는 것은
«멈춘 실행 하나»를 «두 세션에서 같은 셀을 쓰는 동시 replay 둘»과 바꾸는 것이다.」
바뀐 것은 **무엇을 «말하는가»** 다.

`unreported` 는 `stalled` 가 «아니다» — `_mark_run` 이 시작에 `last_progress_at` 을 찍고,
등록된 여섯 작업 중 **넷만** `_checkpoint` 훅을 준다. `ledger_rescope`·`enrichment_confirm`
은 **도는 중에 한 번도 보고하지 않으므로** 그 침묵이 아무것도 성립시키지 않는다.
둘 다 `cancellable:false` 라 `cancel_reaches` 가 **`never`** 라고 말한다 —
«아무 일도 안 하는 버튼»을 내놓는 대신.

화면 쪽(`d886307b`)은 응답 모양을 **설명이 아니라 «라우트와 코드»에서 읽었다** —
「설명된 모양은 이번 주에 «두 번» 틀렸다」. 그리고 **문구를 지어내지 않았다** —
`progressing/stalled/unreported`·`at_next_batch/unknown/never` 를 **서버 자기 토큰
그대로** 찍는다. 「번역하면 서버가 정확히 구별하는 `stalled` 와 `unreported` 를
«한 낱말»로 접는다.」

⚠️ 배치에 «수»가 붙어 있다 — 소유자는 «일곱째 컬럼»이 아니라 **Event 셀 «안»**에
그려진다. 「직전 라운드가 570px 아래에서 표가 패널을 넘치는 것을 재서 0 으로 만들었고,
새 컬럼은 그것을 도로 쓴다.」 하니스가 머리글이 여전히 **여섯**을 선언하는지 단언한다.

## ⑤ 정렬 없는 `.first()` 와 «속일 수 없는» 신호 (`83627dc5`)

`SCHEDULER_RUN_NOW` 질의가 **`order_by` 없이 `.first()`** 였다 — 여럿이 기다릴 때
«어느» 것이 도는지를 «질의 계획»이 정했고, **정렬 없는 선택은 «더 오래된 것이 무한정
기다리는 동안» 한 행을 계속 고를 수 있다.** 네 줄 아래 형제는 **이미 id 로 정렬**하고
있었다.

미배달 브로드캐스트 쓸기는 체인 워커 루프 «안»에서 돌아서, **밖에서는 그것이 멈춘 줄
알 방법이 없었다** — 워커는 계속 뛰고, 아웃박스는 계속 빠지고, 써졌지만 알려지지 않은
행만 쌓인다.

🔴 **핵심 판단: «마지막 실행 시각»이 아니라 «백로그»를 잰다.**

```
매번 돌고 매번 실패하는 쓸기는 «싱싱한 타임스탬프»와 «커지는 백로그»를 남긴다
=> 백로그가 «속일 수 없는» 신호다
그리고 어느 프로세스에도 «새 상태»가 필요 없다 — 행 집합이 idx_outbox_undelivered 가
   쓸기 자신을 위해 이미 인덱싱하는 «바로 그것»이라, 감시자와 감시 대상이 «한 정의»를 읽는다
```

`c8432558` 이 막는 실행의 창에 셋을 얹었다 — 인자·누가 요청했나·언제 큐에 들어갔나.

```

③ 이미 "admin" 을 든 행은 «안 건드린다» — 「고치면 코드가 아니라 «기록»을 편집하는 것이다」

그 시험은 **주어가 진짜로 텍스트**라(스케줄러가 공유 상수를 부르나, 문자열을 다시
철자하나) **메서드 하나가 아니라 «클래스»를 읽게** 바뀌었다 —
**자리를 고정하는 비용을 적어 두고.**

## 아키텍처 영향

- cron 수집기가 **틱을 떠났다.** 선점은 «스레드 전에 동기적으로». 예약·즉시 실행이
  **한 문**으로 간다.
- 다룰 수 없는 재실행 요청이 **FAILED 로 «끝난다»** — 큐가 그 뒤로 흐른다.
  실패의 실패는 「큐가 아직 막혀 있다」고 «말한다».
- 아웃박스 깊이·나이가 **비우는 데몬별로** 갈리고, 갈래가 `event_constants` 의
  **공유 집합 하나**에서 온다. 추적 안 되는 타입은 **`unknown`** 이고 chain 에 안 접힌다.
- `/health` 가 **미배달 «백로그»** 를 본다 — 마지막 실행 시각이 아니라.
  쓸기가 쓰는 인덱스를 «그대로» 읽는다.
- 로그 파일이 **첫 호출자 = 프로세스**를 따른다. 맵퍼 태그를 **로거에서** 읽는다.
- 「서버는 값을, 화면은 문장을」이 **`null` 을 «없음»으로 유지하는 것**까지 포함한다 —
  그리고 **없는 요청자에게 이름을 «쓰지» 않는다.**
