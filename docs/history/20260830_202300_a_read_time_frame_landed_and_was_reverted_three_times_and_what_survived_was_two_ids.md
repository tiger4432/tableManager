## 무엇이 필요했나

같은 물리적 좌석을 **서로 다른 프레임으로 읽는 로그 둘**이 있고 둘 다 `dt_x/dt_y` 로 쓴다.
walk 이 그 둘을 «한 좌석»으로 보게 하려면 어딘가에서 변환이 일어나야 한다.
`c5274dd8` 이 그 설계를 적었다 — **원장이 프레임을 주장하지 않고, walk 이 «키를 도출»한다.**

답이 바뀌고 회수할 것이 없다.**

## 왜 «남겨 두지» 않고 되돌렸나 — 되돌림 ①의 근거

`4a7eb4f0`. 취소 사유는 **계보가 이미 걷힌다**는 것이었다 — `slot_map@1`(lot_slot → lot_slot,

필요 없었다.

그대로 두지 않은 이유가 적혀 있다: **walk 안의 안 쓰이는 기제는 공짜가 아니다.**
프론티어 확장과 「한 변에 id 둘」 규칙은 놓인 자리에서 **하중을 받고 있고**, 읽는 사람은
「아무것도 프레임을 선언하지 않는다」를 **스스로 알아내야** 그것들이 아무 일도 안 한다는
결론에 닿는다.

되돌림이 안전하다는 근거도 수로 남았다 — 그 사이에 **다섯 파일을 건드린 커밋이 0**이었고,

## 왜 다시 복원했나 — 그리고 «꺼진 채로» 복원한 이유

## 🔴 기제는 죽었고 «발견»은 살아남았다

되돌림 ②·③이 둘 다 이 문장을 명시적으로 보존했다 — 한 번은 코드 옆 주석으로.

```
한 끝점은 id 를 «둘» 들고 있고 둘은 «호환되지 않는다»
  raw id    「이것이 프론티어에 있었나」에 답한다
  datum id  노드 · 엣지 · 깊이 · 출발 카운트를 «키로» 삼는다
🔴 하류에서 raw id 를 쓰면 엣지가 «조용히» 사라진다 —
   add_edge 는 nodes 에 없는 끝점을 거절하기 때문이다
```

그리고 착지 커밋(`70246f87`)이 **재기 아니라 측정으로 잡은 버그**를 하나 적어 두었다 —
프레임은 «순열»이라 **읽으면서 제자리에 쓰면 파괴된다**: x-from-y 다음 y-from-x 가
방금 덮어쓴 값을 집는다.

`_declared_frames` 는 `_declared_key_order` 의 「절대 안 던진다」를 **일부러 안 베꼈다**:
라벨이면 못 읽는 선언의 값이 «못생긴 라벨»이지만, 변환이면 값이
**조용히 아무것도 안 잇는 것**이고 그것은 화면에서 「아직 선언 안 됨」과 똑같이 보인다.

## 같은 창에 낀 것 — `has_wafer` 가 원자 0 이었던 이유

`d306b450` (21:33). 되돌림 ②와 ③ 사이에 착지했다.

선언된 모든 술어에 원자가 있는데 `has_wafer` 와 `derived_from` 만 0 이었고,
`register` 원자 396 이 전부 dtjob 이었다 — **`lot_event` 소스가 재건 이후 아무것도 못 만들었다.**
돌려 보니 **이름으로 거절**했다:

```
RoleFrameError: bundle.sources.lot_event.bind.mappings.in_slot.bind.subject.keys:
a mapper-supplied Entity reference carries one identity key
```

`has_wafer` 의 주어는 `lot_slot@1` 이고 **키가 둘**이다. 즉 `in_slot` 은 커스텀 맵퍼에서
**원자를 만들 수 없었다.** 그런데 소스 자체가 안 돌고 있었으므로 운영자에게는
**거절이 아니라 «부재»로 보였다.**

`in_slot` 은 `lot_event` 의 콜론으로 이어붙인 slotnumbers/waferids 를 **행 단위로 펼치는 뷰**
위의 선언형 역할 소스로 옮겼다. 프레임워크가 컬럼에서 키 둘을 다 만드므로 그 계약이 아예
적용되지 않는다 — 같은 두 키 엔터티를 두고 `lot_slot_move` 가 이미 다니는 길이다.
슬롯은 텍스트 형태를 유지한다(`'01'`, 1 이 아니라) — walk 이 JSONB 동등으로 키를 맞추고
`lot_slot_move` 가 같은 모양으로 저장하기 때문이다.

맵퍼만 알던 문장 둘(`split_slot_carry`·`merge_slot_join`)이 함께 은퇴했다 —
그 술어는 같은 날 먼저 은퇴했고, 한쪽 좌석에서 다른 쪽 좌석으로는 **공유하는 웨이퍼를 거쳐
선언된 엣지로** 닿는다.

```
이 상자에서: has_wafer 0 -> 907 (좌석 238 · 웨이퍼 125) · derived_from 0 -> 40 · register 396 -> 546
```

## 아키텍처 영향

- **읽기 시점 프레임 기제는 트리에 없다.** `frame_keys`·`frame.<type>` 어휘, 프론티어 확장,
  datum 이송은 전부 되돌려졌다. 좌표 보정은 **원천 표준화 + 범위 재번역** 쪽으로 갔다.
- `in_slot` 이 커스텀 맵퍼에서 **선언형 역할 소스 + 뷰**로 옮겼다. 두 키 주어를 커스텀 맵퍼가
  말할 수 없다는 제약이 «이름으로 거절되는» 형태로 확인됐다.
- 「한 끝점에 id 가 둘」은 코드 옆 주석으로 남았다.
