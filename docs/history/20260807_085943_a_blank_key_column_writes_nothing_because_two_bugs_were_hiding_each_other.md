# 빈 키 컬럼은 아무것도 쓰지 않는다 — 결함 둘이 서로를 가리고 있었다

**날짜:** 2026-08-07 08:59 · **커밋:** `818c9c0` · **레인:** 서버(인제션)
**측정 상자:** 이 워크스테이션의 **실제 PostgreSQL**. **운영이 아니다.**

---

## 배경

`528dfcb`가 유니크 업무 키를 넣자 선재 결함이 **선재 결함에서 전제 조건으로 승격**했다.
유니크 인덱스가 살아 있는 상태에서 옛 코드는 키 없는 행을 실은 파일만 거절하는 것이 아니다 —
**변경 없는 아무 맵이든 두 번째 Push가 거절된다.**

```
DETAIL: (business_key_val)=() already exists
```

그래서 「인제션은 키 없는 행을 만들지 않는다」는 제품 소유자의 판정은 **참인데도 이 문제를
치우지 못했다.** 문제는 키 없는 행이 아니라 `''`라는 **값**이었다.

## 두 후보가 다 틀렸고, 하나는 출하 전에 잡혔다

- **후보 A — `''`를 쓴다(옛 동작).** `''`는 값이므로 그 테이블의 키 없는 행 전부가 **같은
  신원**을 갖는다. 한 배치의 다섯 행이 **서로** 충돌하고, `apply_batch_updates`의
  `IntegrityError` 복구는 이것을 고칠 수 없다 — 그 복구는 「롤백하고 DB를 다시 읽어 승자가
  커밋한 행에 붙는다」인데 **충돌한 행 중 커밋된 것이 하나도 없다.** 재생이 같은 충돌을
  재현하고 `BK_CONFLICT_MAX_RETRIES` 뒤에 **배치가 거절된다.** 실측: 키 컬럼이 빈 5행
  페이로드를 세 번 밀어 **매번 0행 기록** — 중복 다섯이 아니라 아무것도 안 들어간다.

- **후보 B — 빈 값이면 NULL로 지운다(첫 초안).** 자연스러운 축소인데 **틀렸고, PostgreSQL
  프로브가 출하 전에 잡았다.** 맵 테이블의 키 컬럼은 **파생값**이다(`map_pk`는
  `map_id`+`die_no`에서 조립된다). 파일이 그 컬럼을 **있는데 빈 값으로** 실어 오면 그것은
  「이 행에 키가 없다」가 아니라 「파일이 주지 않았다」다. 변경 없는 맵을 다시 Push하면
  복합 키 재계산이 건너뛰어지고(행이 신규가 아니고 소스가 안 바뀜) **아무것도 키를 되돌려
  놓지 않는다.** 실측: Push 1 = 4행 4키 → Push 2 = 4행 0키 → Push 3 = **8행.**

🔴 **결함이 결함을 가리고 있었다.** 옛 `''` 코드도 키를 **똑같이 파괴**했는데, `''`가 그 뒤에
충돌해서 배치가 거절되는 바람에 피해가 커밋되지 않았을 뿐이다. **충돌만 없애고 파괴를 남기면**
시끄러운 거절이 **조용한 키 손실 + 복제**로 바뀐다.

## 그래서 분기는 아무것도 쓰지 않는다

```python
def _apply(raw):
    if raw is None:
        return
    str_val = str(raw).strip()
    if str_val == "":
        # Blank -> write nothing. Never `''` (a shared identity that collides), and
        # never a clear (it destroys a map row's key on re-push). See the docstring.
        return
```

빈 값은 **새 행의 NULL을 그대로 두고, 이미 키가 있는 행의 키도 건드리지 않는다.** 표시된 키
셀을 비우면 `business_key_val`은 **낡은 채로 남는다** — 의도한 교환이다. 낡았지만 유일한 핸들은
새 키를 입력해서 복구할 수 있는 반면, 살아 있는 행의 신원을 없애면 그것을 키로 붙잡고 있던
모든 것(`FrameConfirmation.unit_key`, `GraphNode.identity_key`)이 고아가 된다.

NULL이 받아들여지는 모양이라는 근거도 실측이다 — 일반 UNIQUE 인덱스는 NULL을 서로 다르게
취급하고, 라이브 DB가 이미 그런 행을 갖고 있다(2026-08-07 실측: `wafer_map_metadata` 11건,
`production_plan` 10건, 전부 수동 병합에서 나온 것).

## 검증 — 순서가 증거의 일부다

1. **옛 동작을 먼저 재현했다**(3/3 배치 거절, 0행 기록).
2. 그다음 5 → 10 → 15행, 빈 문자열 0개·거절 0건.
3. 변경 없는 맵 4 → 4 → 4, 키 온전.
4. 선재 NULL 행 생존.

경보는 **변이 두 개**로 확인했다 — 옛 `''`와 NULL로 지우는 초안. 그리고 **양쪽에서 다 통과하는
테스트 네 개는 자기 독스트링에 그렇다고 적었다.**
