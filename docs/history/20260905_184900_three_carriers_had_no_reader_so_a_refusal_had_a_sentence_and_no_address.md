## 배경 — 답은 «착지 이래로 계속» 있었다

```
`envelope.check_envelope`   착지 이래 «(code, path, message)» 를 답한다
`screen_molecule`           그 이래 «report["violation_details"]» 에 그것을 실어 왔다
실측
   violation_details   쓰는 쪽 «둘» · 읽는 쪽 «0»
   gate.samples()      호출자 «0»
   gate.captured()     호출자 «0»
=> 나르개 «셋», 읽는 쪽 «0».  운영자는 «문장»을 받고 «주소»를 못 받았다
   「어느 칸을 고치나」에 답이 «없었다»
```

## ① 거절이 자기가 이미 알아낸 주소를 «건넨다» (`75dc3b59`)

**새로 계산하는 것이 없다.** 거절이 주소를 `gate.refuse` 에 건네고, 그것이 표본 목록에
찍히고, 백필 실행이 그 목록을 보고한다.

### ⛔ «개수» 위에 태우지 않았다 — 태우면 불변식이 깨진다

```
`_refusals` 는 «(source, reason) -> count» 이고
그 불변식은 「분해가 거절 «수»로 «합해진다»」이다
=> 원자마다 주소를 붙이면 그 등식이 «깨지는데» 화면은 «전부 그대로 그려진다»
✅ 나르개는 `_samples` 다 — 상한이 있고, 거절당 «한 항목»이며, «어떤 합에도 안 들어간다»
   합에 대한 단언이 그것을 못 박는다
```

### ⚠️ 상한을 «문장»이 아니라 «수»로 말한다

```
`refused_total` 이 `refused_samples` «옆»에 `refused_samples_capped` 와 같이 간다
=> 「400건 거절, 20건 주소 있음」이 「거절 20건」으로 «그려질 수 없다»
   «잘림을 부재로 읽는 것»은 한 층 위의 «같은 실패 부류»다
```

### 📌 판정과 «한 군데 어긋났고», 그 어긋남을 재서 적었다

총괄 판정은 `runtime_v2.py:307` 의 `kept, _report = ...` 를 «진짜 자리»로 지목했다.

```
실측   그 줄은 `gate.building_molecule` «안»에 있고, 거기서 `gate.refuse` 는 «던진다»
=> 그 자리가 묶는 짝은 «언제나 «승인» 답»이다. 소비해 봐야 «어떤 거절에 대해서도 아무것도» 안 나온다
=> 쓰지도 않을 `_report` 의 이름을 바꾸는 것은 «연극»이다.  버리기를 «유지»하고 사유를 그 줄에 적었다
✅ 주소는 «거절 경로»로 나간다 — «존재하는» 경로다
```

## ② 그리고 «이미 주소를 묻고 있던» 읽는 쪽에 닿았다 (`71b0de61`)

`config_explorer_service._test_run_refusal` 은 **줄곧** `getattr(exc, "code")` 와
`getattr(exc, "path")` 를 읽고, 없으면 **클래스 이름으로 물러섰다.**
`MoleculeRefused` 는 `(source, reason, detail)` 을 나르고 **그 둘을 안 날랐다.**

```
before   code = "MoleculeRefused"        path = ""
after    code = "source_raw_ref_empty"   path = "atom.source.raw_ref"
```

🔴 그 화면은 **존재 이유가 「어느 칸을 고치나」라고 «스스로 적어 둔» 화면**이다.

**새 화면도 새 라우트도 없다** — 읽는 쪽도, 그 물러섬도, 경로 매핑도 «이미 쓰여 있었다».
예외가 `check_envelope` 가 «이미 답한 것»을 나르기 시작했을 뿐이다.

### ⚠️ 과장하지 않았다

```
`atom.source.raw_ref` 는 «원자»의 주소이지 «폼의 칸»이 아니다
=> `form_path` 는 «빈 채»로 두고 거절을 «날것»으로 보여 준다
   — `_test_run_refusal` 자신의 규칙이다: «찍어 맞힌 상자»는 «자리 없는 문장»보다 나쁘다
얻은 것은 «참인 주소»이지 «강조된 필드»가 아니고, 시험이 그 구분을 못 박는다
```

첫 주소가 `code`/`path` 가 되고 나머지는 `addresses` 에 남는다.
「아무거나」가 아니라 **「첫째」**인 이유는 `_envelope_reason` 이 **같은 목록에서 이미 첫째를
고르기 때문**이다 — 그래야 코드와 주소가 «둘»이 아니라 **같은 위반**을 서술한다.

## 아키텍처 영향

- 거절의 «주소»가 **표본 목록**으로 나른다. 개수 분해의 합 불변식은 그대로다.
- 상한이 **수로** 나른다(`refused_total` · `refused_samples_capped`).
- 시운전 화면의 거절이 **참인 code/path** 를 받는다. 폼 칸에 매핑되지 «않는» 주소는
  «날것»으로 남고, 그 구분이 시험으로 고정됐다.
