**한 subject type 의 `object_payload`**에서 찾는데 원장은 그것을 **다른 subject type 의

## 🔴 전파의 나눗수가 «자기 문서의 셋째 규칙»을 어기고 있었다

`a3830826`. `_reach`가 **무방향 차수**로 나눴는데 그 차수는 **자기가 들어온 이웃까지 센다.**
순수한 체인에서 1.0 / 0.5 / 0.25 — **기하급수적 감쇠**이고, docstring 의 셋째 규칙이 금지하는 것이다.

```python
# server/ledger_api/ledger_subgraph.py
forward = max(1, len(neighbours) - 1)     # exclude the way it came in
share = carried if node == seed else carried / forward
```

재채점: **9층 → 5층**, `dt_pass_count`·`humidity` 8→4, `pre_bond_queue_h` 9→5
(저장소 안 `task/implementer_pickup_report.md`가 이 수를 함께 들고 있다).

🔴 **그런데 `a3830826`은 「주석이 감쇠 상수를 금지하는데 루프가 차수로 그것을 만들었다」고
적었다.** diff 가 교체하는 원래 docstring 항목은 **「그 뒤 모든 홉은 «내보내는 노드의 차수»로
나눈다」**로, 주석은 코드를 **정확히 서술하고 있었다.** 어긋난 것은 셋째 항목뿐이다.
그리고 `66895f44`은 「나눗수가 forward 차수에서 full 차수로 **드리프트했다**」고 적었는데,
**어느 diff 도 이전에 forward 차수였다는 것을 뒷받침하지 않는다** — `a3830826`의 원본이
full 차수를 문서화하고 있다.

## 아키텍처 영향

- 트렌드의 **grain 이 호출자 선언**이다. 라우트 코드에 fab 의 낱말이 없다.
- 읽기 경로가 **쓰기 검증기를 안 부른다.** 원장에 있는 타입은 seed 가 된다.
- `_reach`가 **들어온 방향을 뺀 차수**로 나눈다. 그 규칙이 두 그래프 한 쌍으로 고정됐다.

## 그때 남아 있던 것

- grain 멤버 **다섯이 울타리 안**에 있다 — 신원 인코더가 축 값을 위치로 받고, keyset 커서가 그
  튜플을 나른다.
- **기본 grain 은 일부러 안 뒤집었다** — 커밋된 씨앗과 이 상자의 원장이 어긋나 있기 때문.
- 전파 규칙 변경의 비용(동률 증가)은 **판정 없이** 남았다.
- `66895f44`의 「드리프트했다」는 문장은 **이 시점에 근거가 없다.**
