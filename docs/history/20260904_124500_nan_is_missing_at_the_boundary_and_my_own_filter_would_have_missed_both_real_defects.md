## 배경 — 소유자 신고: 체인에서 `cannot convert float NaN to integer`

부류가 이것이다:

```
결손 표지로 «모두가 가드하는» 것은 None 이다
그런데 double precision 컬럼은 «NaN» 도 낸다.  그리고  NaN is not None
=> NaN 은  if x is None: continue  를 «그대로 통과»하고 다음 int() 에서 터진다
```

## ① 경계를 «한 곳»에 놨다 (`c5a1e5ab`)

`server/chain_ingestion_worker.py`. `execute_custom_mapper` 가 **모든 커스텀 맵퍼가
지나는 «유일한» 자리**라, 들어가는 페이로드와 **나오는 반환값**을 거기서 정규화한다.

```python
payload = without_missing(payload)
if rule is not None and _mapper_accepts_rule(mapper_func):
    result = mapper_func(db, payload, rule=rule)
else:
    result = mapper_func(db, payload)
# The way out as well: whatever the mapper returns goes on to the write path,
# which has its own integer columns and would hit the same conversion.
return without_missing(result)
```
사유: **「맵퍼 저자가 «기억해야 하는» 규칙은 함정이고, 이 도구는 맵퍼를 «쓰는 사람»을
위해 존재한다.」**

네 가지 설계 판단이 기록됐다:

```
철자를 «지어내지 않고 복사»했다 — parsers/pipeline_base.py:73-75 에서
   pd.isna(None/NaN/NaT) + float 무한을 None 으로
   -> 「값 없음」의 철자가 «둘»이면 한 소스 값이 한 경로에서는 «수», 다른 경로에서는 «공백»이 된다
결손은 None 이 되지 «0» 이 되지 않는다 — 0 은 «값»이다
🔴 안 바뀐 입력은 «같은 객체»로 돌아온다
   _missing_as_none 이 (value, changed) 를 돌려주고 «바뀐 게 있을 때만» 컨테이너를 다시 만든다
   시험이 «동등»이 아니라 «동일성»을 단언한다 — 동등이면 어느 쪽이든 통과한다
   매 페이로드를 다시 만들면 큰 배치가 «자기에게 없는» 결함의 값을 문다
DataFrame/ndarray 는 «건드리지 않는다» — pd.isna 는 컨테이너에 원소별로 답해서
   진리값을 취하면 던진다.  «이런 가드가 보통 실패하는 방식»이다: 시끄럽게, 아무도
   시험 안 한 «그 한 모양»에서
```
⚠️ 단언하지 «않는» 것도 적혔다 — pandas 로 자기 프레임을 만드는 맵퍼는 **자기 안에서**
NaN 을 만들고 반환 «전»에 던질 수 있다. 단언되는 것은 「맵퍼가 NaN 을 «받지 않는다»」뿐이다.

### 시끄러운 쪽 — 좌표 (`99459a31`)

`server/bonding_plan.py` 의 두 자리가 «둘 다» 틀린 가드였다. 그래서 판단이 함수 하나가 됐다:

```python
def _finite_point(px, py):
    if px is None or py is None:
        return False
    return (not (isinstance(px, float) and not math.isfinite(px))
            and not (isinstance(py, float) and not math.isfinite(py)))
```
무한도 같이 간다 — `int(inf)` 도 던지고, 무한 좌표는 좌표가 아니다.

🔴 **도달 가능성이 «가정이 아니라 서술»로 적혔고, 이 테마 내내 되풀이된다**:
평범한 쓰기 경로는 그런 행을 «만들 수 없다» — `crud.cast_value_by_type` 가 nan/inf 를
숫자 컬럼에 넣기를 거절하고 사유를 기록한다. **만들 수 있는 것은 그것을 «안 지난» 쓰기**
— 씨앗 스크립트가 표 행을 직접 쓴다.

⚠️ **변이 6개 중 둘은 시험을 «다시 쓴 뒤»에야 잡혔다.** 첫 다섯 케이스는 헬퍼만
운동시켰고 **어느 호출 자리도 지나지 않아서**, 호출 자리의 가드를 바꿔도 초록이었다.
잡는 케이스는 «진짜 경로»를 몰고 **개수»를 단언한다** — 예외가 바깥 `try` 에 삼켜지는
루프가 먹이는 개수까지. **거기서는 틀린 가드가 진짜 개수를 «0» 으로 만들고
응답까지 «아무것도 안 닿는다».**

### 조용한 쪽 — 정체 (`157b11d6`)

이 상자에서 잰 것:

```
compose_business_key("t", ["A", float("nan"), "C"])  ->  "A_nan_C"
```
`clean_str_value(float("nan"))` 이 **문자열 `"nan"`** 이라, 결손 키 조각이 아무것에도
«비어 보이지» 않는다 — **«값»처럼 보인다.**

```
서로 무관한 이유로 키 조각이 빠진 «두 행»이 «한 정체»에 착지한다
그리고 값이 나중에 도착한 행은 «다른 키»를 받아 «앞의 것을 고아로» 만든다
아무것도 안 던진다
```

```python
def is_blank_key_part(value) -> bool:
    if isinstance(value, float) and not math.isfinite(value):
        return True
    return is_blank_value(value)
```
🔴 **새 거절을 «안 만들었다»** — `unfilled_key_columns` 가 키 조각 결손의 처리를
이미 «정한다». 결함은 그것이 이 하나를 «못 봤다»는 것이다. 두 번째 거절은 그 판단의
«두 번째 집»이 됐을 것이다. 그리고 «조립기»도 같은 헬퍼에 묻기 때문에 `"A_nan_C"` 는
거절되는 게 아니라 **애초에 조립되지 않는다.**

⚠️ `is_blank_value` 는 «일부러» 그대로다 — 그것은 공백이 «무엇이 써지는지»를 정하는
자리들(가상 조인의 빈 칸만 채우기, 인리치먼트 게이트, `blank_to_null`)에서 읽히고,
거기서 NaN 이 공백인지는 **별개의, 아직 안 끝난 측정**이다. 시험이 둘을 «갈라» 핀으로
박아 나중 라운드가 실수로 넓히지 못하게 했다.

- NaN→결손 변환이 **맵퍼 경계 한 곳**(`execute_custom_mapper`)에서 «양방향»으로 일어난다.

- 대시보드 요약의 실패 단위가 **표**다.
