# 2026-05-30 CSV 내보내기 성능 최적화 및 데스크톱 다운로드 웹 통합

## 1. 배경 및 문제점
* **다운로드 100% 부근 감속 현상**: 대용량 CSV 내보내기 시, 이너 루프에서 매 행마다 StringIO 버퍼 읽기(`getvalue()`) 및 버퍼 초기화(`truncate(0)`)가 작동하여 수십만 개의 자잘한 문자열 복사 및 객체 생성 오버헤드가 누적되었습니다. 또한, 데이터 캐시가 비제한적으로 증가하여 Garbage Collector(GC) 병목으로 인해 100%에 가까워질수록 속도가 급격히 저하되었습니다.
* **진행률 게이지 정체(Visual Hang)**: 크기 예측과 실제 바이트 크기의 편차로 인해, 파일 전송이 완전히 끝나기 전에 진행률이 100%에 도달해 멈춘 상태처럼 느껴지던 시각적 오류가 존재했습니다.
* **데스크톱 클라이언트의 UI 지연**: PyQt(`QWebEngineView`) 다운로드 스레드에서 바이트를 수신할 때마다 실시간으로 웹뷰 화면으로 IPC(`runJavaScript`) 호출을 수행해 로그를 갱신함으로써 잦은 컨텍스트 스위칭과 GUI 지연을 유발했습니다.

## 2. 주요 개선 사항

### ① 데이터베이스 서버사이드 커서 및 메모리 바인딩
* `export_query`에 `.execution_options(stream_results=True)` 옵션을 명시적으로 지정하여 PostgreSQL에서 실제 서버사이드 커서 스캔을 작동시켰습니다.
* datetime 포맷 문자열 캐시(`date_cache`)가 10,000개 이상의 유니크 엔트리를 보유하지 않도록 메모리 바운더리를 설계하여 메모리 누수를 방지했습니다.

### ② StringIO 배치 쓰기 최적화 (CPU 연산 5,000배 감소)
* 행 단위로 버퍼 문자열을 빌드하던 구조를 개선하여, `batch_size (5,000행)` 단위로 수집한 후 한번에 StringIO 문자열을 빌드하여 yield하도록 수정했습니다. 이로 인해 StringIO 호출 수가 5,000분의 1로 급감하며 CPU 병목을 해소했습니다.

### ③ 데스크톱 클라이언트 다운로드 웹 통합 및 IPC 제거
* 데스크톱 래퍼(`desktop_wrapper.py`) 상의 실시간 진행률 리스너와 상태 변경 시그널, 그리고 `runJavaScript` 호출을 모두 삭제했습니다.
* 데스크톱 환경도 웹 클라이언트의 JavaScript 비동기 `fetch` 및 `ReadableStream` 수신 엔진을 그대로 활용하도록 단일화하여 다운로드 중 IPC 오버헤드를 0으로 만들었습니다.
* 파일 다운로드가 인메모리 상에 완료된 시점에만 가상 Blob URL 클릭 링크(`link.click()`)를 호출하여, 파이썬 데스크톱 래퍼는 최초 저장 경로 탐색(`QFileDialog`) 및 파일 쓰기 승인(`download.accept()`) 역할만 수행하게 정제했습니다.

### ④ 진행률 계산 보정
* 다운로드 스트리밍 중에는 진행률이 최대 `99%`를 넘지 못하도록 상한선을 씌워 시각적 걸림 현상을 해결하고, 스트리밍 루프가 정상 종료되는 순간 즉시 `100%` 및 최종 완료 알림이 연동되도록 보정했습니다.

### ⑤ 페이징 모드에서 Load All 수행 시 페이지네이션 UI 유지 및 복구 보정
* **페이지 버튼 가시성 보장**: 기존에 `Load All` 완료 시 페이징 영역이 무조건 `display = 'none'`으로 처리되어 페이징 화면으로 다시 돌아갈 수 없던 문제를 해결했습니다. 페이징 모드인 경우 데이터가 전체 로드되더라도 컨트롤 영역을 항상 보이도록 보장합니다.
* **페이지 이동 시 Load All 상태 해제 연동**: 사용자가 페이지 번호를 직접 입력하거나 Next/Prev 버튼을 누르면 즉시 `allDataLoaded = false` 상태로 리셋되며 원래의 500개 단위 페이징 데이터 쿼리로 자연스럽게 복귀합니다.
* **테이블 전환 시 로드 상태 리셋**: 테이블이 전환될 때 (`switchTable`), 이전 테이블의 전체 로드 상태(`allDataLoaded = true`)가 잔존하지 않도록 `allDataLoaded = false`로 강제 리셋해 오작동을 차단했습니다.

### ⑥ 행 번호 (#) 고정 컬럼 너비 상향 (숫자 잘림 방지)
* 행 번호 컬럼(`#`)의 기본 width를 기존 `60px`에서 `100px`로 상향 조정(minWidth: 90px, maxWidth: 150px)하여 대량 데이터 로드 시 5~6자리 이상의 행 번호 숫자가 셀 테두리에 의해 잘려 보이는 현상을 수정했습니다.

## 3. 검증 결과
* uvicorn 서버 및 PySide 데스크톱 클라이언트 구문 무결성 확인 및 빌드 정상 완료.
* 웹과 데스크톱 클라이언트에서 모두 균일한 속도(등속)로 다운로드가 부드럽게 진행되며, 완료 직후 저장 팝업을 통해 로컬 저장소로 안전하게 저장되는 것을 확인했습니다.
* 페이징 모드 상태에서 `Load All`을 수행하더라도 하단 페이지 이동 바가 안정적으로 유지되고, 페이지 이동이나 테이블 전환을 수행하면 페이징 목록으로 정상 복구되는 것을 최종 검증했습니다.
* 행 번호 컬럼의 가로폭이 넓어져 큰 숫자도 완전히 가독성 있게 표현됨을 검증했습니다.
