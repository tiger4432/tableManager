## 배경 — 404 는 «차트»가 아니라 «알약»에 뿌리가 있었다

같은 날 오전, 좌석 셋을 걷기로 옮겼다가 **되돌렸다**(`397bc3e5`). 이유는 Y축 알약이
「종류」를 고르게 돼 있었고, 그 목록이 **은퇴한 `/trends` 라우트의 `selectable_finding_kinds`**
에서 왔기 때문이다.

```
실측(변경 «전»)   /trends  ->  «404»
                 kinds    ->  «빈 배열»
                 => Y축이 «쓸 수 있는 알약을 하나도» 안 내놓고 있었다
```
🔴 **보드에 남아 있던 404 는 차트의 문제가 아니라 «알약»의 문제였다.** 옮길 순서가 반대였고,
그 순서를 바로잡는 것이 이 라운드다.

## ① 축이 «쌍»이 됐고, 세 반쪽이 «일부러» 서로 다른 곳에서 온다

`0308e6b9`. 축 = **집계 × 수식어**.

```
집계     api.js 의 «고정» 목록. 데이터가 필요 없다 -> 마킹이 비어도 «일곱이 전부» 선다
        median·mean·sum·min·max 는 수치 전용 · count·distinct 는 아무거나
수식어   /declaration. 술어 다섯에 걸쳐 «15» 개의 이름. 원장을 한 줄도 «안 읽는다»
        -> 마킹과 무관해서 «첫 그림»부터 통째로 서 있다
수치인가  «걷기». qualifierTypesFromWalk 가 이름마다 {seen, numeric} 을 준다
        -> 참/거짓이 «아니라» 수라서, 화면이 「수치 4/4」라고 «말할 수» 있다
```

```js
// 🔴 셋은 «서로 다른 곳»에서 옵니다. 접으면 화면이 「없어서」와 「아직 안 골라서」를
//    같은 말로 하게 됩니다 -- 이 보드가 존재하는 이유가 그 구분입니다.
//      집계 목록   «여기». 고정이고 데이터가 «필요 없습니다» -- 마킹이 비어도 고를 수 있습니다
//      수식어 목록 «선언»(`/declaration` 의 술어별 qualifiers). 마킹과 무관합니다
//      수치인가    «데이터». 마킹이 있을 때만 알 수 있습니다
```

마킹이 없을 때 알약은 **전부 있고** 줄은 「재려면 마킹이 필요합니다」라고 말한다 —
**「값 없음」도 아니고 빈 목록도 아니다.** 「없어서」와 「아직 안 골라서」는 다른 사실이다.

측정(격리 오리진에서 이 워크트리를 서빙 — 라이브 :8080 은 main 을 서빙하므로 이 레인의
변경이 거기서는 **안 보인다**):
```
count(radius_x) 4  ->  median(radius_x) 9.95  ->  max(radius_x) 11.38   (y축 상단이 따라감)
요청 «8» 전 · «8» 후.  /trends 404 «하나»가 /declaration 200 «하나»로 바뀌었을 뿐
컨트롤 바 좌석은 이제 «어떤 라우트 이름도 대지 않는다»
```

## 🔴 스스로 찾은 결함 하나 — 「안 실었다」가 «거짓»이었다

수치 전용 집계 아래에서 비수치 수식어를 고르면
「이 걷기가 그 수식어를 안 실었습니다」가 찍혔다. **거짓이다** — 걷기는 그 값들을 **실어
왔고** 집계가 전부 **건너뛴** 것이다.

```
모델      건너뛴 수를 «이미 세고 있었다»
그리는 쪽  그 수를 «안 읽었다»
=> 「건너뛴 수를 반드시 말한다」는 규칙이 «바로 그 자리»에서 공허했다
```
같은 0 두 개에 이제 **두 문장**이 붙는다.

## 🔴 ② 「404 가 0」은 «소스»에 대해 참이고 «화면»에 대해 거짓이었다

`b3c00d08`. 총괄이 라이브 페이지에서 **`/trends` 404 가 여전히 있다**고 쟀다. 라운드 ①-a 는
0 이라고 보고했다. **둘 다 정직했고 «서로 다른 코드»를 잰 것이다.**

```
페이지가 로드한 번들   라운드 ①-a 가 «하나도» 안 들어 있다
                    -> 집계 알약 없음 · 「재려면 마킹이 필요합니다」 없음 · axis:agg 없음
이유                0308e6b9 은 src/ «만» 바꾸고 dist 를 «다시 안 빌드했다»
```
🔴 **그 레인의 이전 클라 라운드는 전부 소스 옆에 번들을 같이 실었다. 그 하나만 안 실었다.**
그래서 「404 0」은 **소스에 대해 참**이고 **화면에 대해 거짓**이었다. 이 커밋이 다시 빌드했고,
아래 검증은 **번들에 대한 것**이다.

## 그리고 «기본값»이 죽은 라우트를 되살리고 있었다

같은 커밋의 진짜 수리. 좌석은 이미 `collect` 를 버렸는데 **부품이 `options.collect || 'trend_y'`
를 들고 있었다.**

```
기본값 = «아무도 안 쓴 선언»
좌석의 줄을 지워도 «동작이 살아남는다»
=> 「선언에서 떠났나?」를 묻는 게이트는 «초록»인데 요청은 «여전히 나간다»
```
부품이 이제 `null` 을 받고, collect 도 바인딩된 로드도 없으면 **걷지 않고 그렇게 말한다.**
그 문장은 **거절이 아니다 — 서버에 물어본 적이 없다.**

번들에서 잰 것(캐시 무시 로드, 요청 URL 전부 보고서에 나열):
```
/declaration «2» · /subgraph «4» · /tables «2»  =  «8».   /trends «0»
트렌드 좌석은 「marking:1 이 비었습니다」라고 «문장»으로 말한다 (빈 차트가 아니라)
```

픽스처 셋이 이제 `collect: 'trend_y'` 를 **명시**한다. **기본값에 얹혀 있던 것**이고,
그것이 같은 결함의 축소판이다 — **무엇을 묻는지 말하지 않는 시험도 돌기는 한다.**
새 단언 E2·E3 가 collect 없는 패널의 fetch 수(0)를 세고 거절을 그리지 않고 이유를 말하는지
본다. 변이 M20 이 기본값을 되살리면 **둘 다 빨개진다.**

```
하니스   rnd_board 170/0 · control_trend 36/0 -> 59/0 · walk_box 48/0 · walk 32/0
        composition 40/0 · intersection 24/0 · reach 63/0
변이     ①-a 19/19 잡음 · 수리 라운드 20/20 잡음
```

## 시험 넷이 «자기가 재던 코드와 같이» 죽었다

```
A1   죽은 라우트의 «종류 목록» -> 선언의 «수식어 목록» 으로 «옮김»
B1   «은퇴». 쌍(집계 × 수식어)에서는 「첫 축 자동 선택」이 «불가능»하다
변이 앵커 넷   자기가 앉아 있던 줄을 따라 «이동»
```
새 단언 여섯 + 새 변이 여섯이 이 라운드가 «더한 것»을 덮는다. 「하나라도 수치면 수치」를
가르는 픽스처는 **숫자 셋 사이에 문자열 하나**를 넣었다 — 전수 규칙과 any 규칙이 **거기서
서로 다른 답**을 낸다.

## 아키텍처 영향

- **Y축이 «집계 × 수식어» 쌍**이다. 세 반쪽이 각각 코드 고정값 · 선언 · 걷기에서 오고,
  그 분리가 「없어서」와 「아직 안 골라서」를 갈라 준다.
- **컨트롤 바 좌석이 어떤 라우트 이름도 대지 않는다.** 보드의 `/trends` 요청이 0 이 됐다.
- **부품이 `collect` 기본값을 갖지 않는다.** 안 주면 걷지 않고 그렇게 말한다.
