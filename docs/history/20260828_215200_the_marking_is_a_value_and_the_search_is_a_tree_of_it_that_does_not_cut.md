# 마킹은 «값»이고 탐색은 그 값의 «나무»다 — 자르지 않는 나무, 그리고 쓰는 곳이 «하나»

## 배경 — 복원 중에 구독자가 «아무것도 안 고른 상태»를 본다

`154d9c7c`. 라운드 W 의 유일한 새 기본 단위를, 그것을 필요로 하는 탐색기보다 «먼저» 착지시켰다.
총괄이 준 수를 **받지 않고 다시 쟀다** — 이름이 이미 마크를 들고 있었으면 N+1 emit 이 맞고,
비어 있었으면 N 이다(clear 가 빈 집합에서 emit 을 건너뛴다).

🔴 **문제는 개수가 아니었다.** 노드 셋을 복원하는 동안 구독자가 크기 **0 · 1 · 2 · 3**을 본다.
그 **0이 「아무것도 안 골랐다」로 읽힌다** — 그래서 부품이 빈 상태를 그리고 다시 걷는다.
**이력이 한 칸 뒤로 갈 때마다, 노드마다 한 번씩.**

`replace`는 **집합 전체를 쓰고 한 번 emit** 한다 — 구독자는 `[3]`을 본다. 그리고 `set`의
기존 약속을 지킨다 — **같은 값이면 emit 이 없다.** 이것이 탐색기가 재진입 플래그 없이
「밖에서 뭔가 바뀌었나」를 **값 비교**로 물을 수 있게 하는 전제다.

## 이력은 나무이고 «자르지 않는다»

```js
// client2/src/rnd_board/walk_box_panel.js
/** 이력의 한 칸으로 «이동». 저장소에 쓰는 곳은 여기뿐입니다. */
goto(id) {
  const node = this.nodes.get(id);
  if (!node || !this.markings) return;
  this.current = id;
  this.markings.replace(this.historyName(), node.value);
  this.render();
}

/** 자식 한 칸을 «추가»하고 그리로 이동. 먼저 있던 형제는 그대로 남습니다. */
push(value) { ... this.nodes.set(id, { value: ..., parent: this.current }); this.goto(id); }
```

**쓰는 곳은 `goto` 하나**다. 이동·수집·뒤로·다른 갈래·바깥의 변경이 전부 `push`와 `goto`를
지나므로 **「무엇이 마킹을 바꿨나」의 답이 언제나 한 줄**이다.

🔴 **뒤로 갔다 다른 데로 가도 먼저 갈래가 «남는다»** — 소유자 손그림이 그렇고 파일 탐색기가
그렇다. **브라우저식으로 자르면 「돌아가서 다른 길」이 먼저 길을 지운다.**

🔴 **무한 루프가 플래그로 막히지 않는다.** `goto` 직후에는 저장소 값과
`nodes[current].value`가 같으므로 구독의 「밖에서 바뀌었나」가 **값 비교로 저절로 거짓**이 된다.
`replace`가 같은 값에 emit 을 안 하는 것이 그 성질의 전제다.

클릭과 찍기는 **소유자가 정한 대로 다른 동작**이다 — 이동은 마킹을 그 노드 하나로 교체하고,
수집은 있는 것에 더한다. **밖에서 온 쓰기는 무시되지 않고 «자식»이 된다** — 다른 패널에서
찍은 것도 같은 탐색의 한 걸음이다.

인스턴스 둘로 채점했다: **A 의 이력 3, B 의 이력 1, B 가 `marking:3`을 써도 `marking:1`은
그대로.** `goto`를 두 번 하면 이력이 **0만큼** 자란다.

## 나무가 그려지고, 실제 보드에서 첫 시도가 «0걸음»을 쟀다

`ee9272eb`. 걸음마다 한 행, 깊이만큼 들여쓰고, 현재 것에 표시, **어느 행이든 클릭하면 그리로
간다**(그때 이력은 안 자란다 — `goto`는 노드를 안 만든다). **쓸 이름을 선언 안 한 인스턴스는
빈 상자가 아니라 «이력을 아예 안 그린다».**

🔴 **게이트 일곱을 진짜 보드에서 돌렸더니 첫 시도가 0 걸음을 쟀다** — 본드 맵을 마킹했는데
그건 `marking:1`을 쓰고 **탐색기는 `marking:2`를 쓴다.** 그건 **게이트 하나가 스텁이 아니라
제품에서 성립한 것**이므로 조용히 다시 시도하지 않고 적었다.

코어 맵을 두 번 마킹하니 이력이 **1 → 3**이 되고 **가운데 걸음은 마크 0을 읽는다** —
토글 오프. **나무가 그 «해제»를 걸음으로 유지**하므로 뒤로 가면 그리로 돌아온다.
**그것이 「자르지 않는다」의 뜻이다.**

## 트렌드 좌석 — 마킹이 «모집단»이다

`57ba187e`. 좌석 4·6이 마킹과 따라갈 술어를 선언하고 **창이 센다** — 웨이퍼당 한 점,
`observed` 엣지에서 찾고, 분모는 `inspected`, 시각은 **모든 엣지가 이미 나르는 `occurred_at`**.
종류는 `defect_kind` 노드에서 오므로 **코드에 종류 이름이 없다. 서버 무변경, 새 라우트 없음.**

🔴 **진짜로 마킹해서 채워진 경우를 채점했고, 틀린 문장을 잡았다.** 마킹된 다이에서의 walk 이
노드와 claim 에서 잘려 오고 모델이 그렇게 말하는데, **패널은 그것과 무관하게 「이 창에 점이
없습니다」를 인쇄하고 있었다** — **예산을 부재로 바꾸는 것**이고, 오늘의 미검사 규칙이 막으려고
존재하는 바로 그 자리다. 이제 **모델이 잰 것**을 인쇄한다.

## 아키텍처 영향

- 마킹 저장소에 **`replace`가 있다** — 한 번 쓰고 한 번 emit. 복원 중에 «반쯤 복원된 마킹»이
  구독자에게 안 보인다. 같은 값이면 여전히 조용하다.
- 서브그래프 탐색기가 **마킹 값의 나무**를 들고, **자르지 않으며**, 저장소에 쓰는 자리가
  `goto` **하나**다. 재진입 방지가 플래그가 아니라 **값 비교**다.
- 트렌드 좌석이 **마킹을 모집단**으로 센다. 잘린 walk 은 0점이 아니라 **잘렸다고** 말한다.
