## 왜 이걸 히스토리에 남기나

보드는 리빙 문서라 **다음 편집이 이전 서술을 덮는다.** 이 라운드에서 벌어진 두 가지는 덮이고
나면 흔적이 없고, 흔적이 없으면 **기억에서 다시 주장된다** — 특히 두 번째는 이미 한 번
"측정 없이 확신하고 기록한" 것이 원인이었다.

## ① 보드의 한글이 통째로 깨졌다 — PowerShell 리다이렉션

`27e9faf`(직전 커밋)이 `docs/process/PROJECT_STATUS.md`의 **모든 한글 문자를 파괴**했다.
파일을 PowerShell 리다이렉션으로 썼고 이 시스템의 ANSI 코드페이지가 **CP949**라, UTF-8이
손실 디코드를 한 번 지났다. 남은 것은 이런 상태였다.

```
# ?뱦 PROJECT STATUS ??吏꾪뻾 ?곹솴 & 臾몄젣 ?꾪솴 (Living Board)
```

**복구 불가다.** 변환을 되돌리면 수천 개의 U+FFFD가 남는다 — 커밋 기록은 5,372자, 이 항목을
쓰며 다시 잰 값은 5,489자였다(역변환 방법에 따라 몇십 자가 달라지지만 결론은 같다: 손실
디코드는 정보를 이미 버렸다). 그래서 `20f806a`에서 파일을 복원하고, `27e9faf`가 담고 있던
내용을 다시 썼다.

**복원이 손실 없이 끝났다는 근거**: `20f806a`와 복원본(`8805417`)의 차이는 **20줄 추가 · 1줄
수정**뿐이다(같은 파일 521줄). `27e9faf`가 새로 실었던 F5 설계는 그사이 **구현이 되어 버려**
잃을 것이 없었고(`50bddda`, 운영 선언 절차는 server-pm이 `guide/config/map_overlay_config §2-bis`에
남겼다), 나머지는 인계 블록이라 다시 쓸 수 있었다. HEAD 시점 이 파일의 U+FFFD는 **0자**다.

**이 사고에서 나온 규율은 한 줄이다: 문서는 Write/Edit 도구로 쓴다. 셸 리다이렉션으로 쓰지
않는다.** (에이전트 공통 교훈에 이미 "Windows 콘솔은 cp949라 유니코드 출력에서 인코딩 에러가
난다"가 있었는데, 그것은 **읽는 쪽**의 함정이었고 이번은 **쓰는 쪽**이었다.)

같이 복원·재적용된 것 하나 더 — **Fill All의 저장 불가 셀 비율 정정**. 보드에 `약 21%`로
적혀 있던 수치가 **실측 35~51%**로 바뀌었다(프리셋별 CORE 35 / BASE 41 / TEST 44 / TAPE 51,
프리셋이 없으면 7% — 격자가 100×100에서 잘려 웨이퍼보다 작아지기 때문).

또 하나의 자기정정이 인계 블록에 남았다: **F5 스위트를 처음 돌렸을 때 `1 failed`가 나와
server-pm 보고와 어긋난다고 적었으나, 불안정 실행이었다**(인제션 sweep의 임시 디렉터리·
sqlite 타이밍). 재실행 결과는 **1279 passed**로 보고가 맞았다.

## ② F6이 한 줄로 줄어들었다 — 거절 지점을 실제로 재고

F6은 「유효 다이 맵을 불러올 때 *grid x,y 안 맞다*로 거절되는 것」이다. 설계는 세 갈래
(ⓐ 프레임 없으면 참조 맵 것 채택 · ⓑ 치수 다르면 대상 격자를 넓힘 · ⓒ 회전·면 다르면 변환)로
잡혀 있었는데, **거절 지점을 실제로 열어 보니 조건이 하나뿐이었다.**

```python
# server/map_overlay.py — 프레임이 서로 다르다는 이유로 거절하는 자리는 여기 하나다
if (s_phys["cols"], s_phys["rows"]) != (t_phys["cols"], t_phys["rows"]):
    raise ValueError(
        f"physical grid dims differ: source {s_phys['cols']}x{s_phys['rows']} vs "
        f"target {t_phys['cols']}x{t_phys['rows']} — 같은 웨이퍼 규격이 아니다")
```

**회전·면은 거절 사유가 아니고 이미 변환된다.** 즉 사용자가 원한다고 답한 ⓒ 동작은 **이미
구현돼 있었고**, F6 전체가 ⓑ 하나로 줄었다. 서버 쪽 거절은 그대로 두기로 했다 — 클라가
채택하지 않은 조합·낡은 저장 조합은 계속 소리 나게 실패해야 한다.

⚠️ 보드는 이것을 *"치수 불일치일 때만 raise한다"*고 적었는데, 같은 함수는 **격자 메타 자체가
없을 때**와 **`phys` 규격이 미등록일 때**도 거절한다. 그 둘은 "프레임이 다르다"가 아니라
"프레임을 알 수 없다"이므로 F6의 결론(회전·면 때문에 거절되는 일은 없다)은 그대로 서지만,
서술을 그대로 옮기면 거절 가지가 셋인 함수가 하나로 읽힌다.

## ③ 🔴 그리고 내가 적은 반 칸 편향은 **존재하지 않았다**

`64dea7c`에서 「`:406` 치수 제약을 그냥 지운다」는 안을 기각하며 이렇게 적었다:

> 홀짝이 다르면 `Math.round`가 한 방향으로 몰아 가장자리 한 줄이 통째로 어긋난다
> (`cols=41` → 20은 정수, `cols=40` → 19.5).

**틀렸다.** `ddfffc9`에서 `getPhysicalCoords`의 산술을 소스 그대로 옮겨 돌려 보니
`(cols-1)/2` 항이 **전 조합에서 정확히 상쇄된다.** 41/40/39 × 51을 회전 0·90·180·270로 돌린
전 조합에서 비정수 결과 0건이었다.

이 항목을 쓰며 소스(`c9bf2c7` 기준)로 다시 확인했다 — 회전 0에서 두 식은 이렇다.

```js
const xScreenWafer = colVisual - (visualCols - 1) / 2.0 + shiftX;   // 화면칸 → 물리
const xp = Math.round(xRot + (cols - 1) / 2.0);
```

회전 0에서 `visualCols === cols`, `xRot === xScreenWafer`이므로 두 `(cols-1)/2`가 소거되어
`xp = Math.round(colVisual + shiftX)`가 된다. `shiftX`가 0이면 **물리 좌표는 셀 인덱스 그
자체**이고 홀짝은 아무 영향이 없다. **홀짝 문제가 없으므로 「0.5를 도입해 고친다」는 제안도
고칠 대상이 없었다.**

**제약 자체는 여전히 옳다. 다만 이유가 다르다.** 물리 좌표는 **캔버스 인덱스 상대**이지
웨이퍼 중심 절대가 아니다. 크기가 다른 두 캔버스를 인덱스로 맞추면 좌상단에서 정렬되는데
각 캔버스는 자기 원을 중앙에 두므로 **웨이퍼끼리 어긋난다.** 어긋나는 양은 대략
`(cols 차이)/2`이고 **홀짝과 무관하게 정수 칸 단위**다. 제약을 지우면 거절이 사라지는 대신
`status: ok`인 **틀린 답**이 나오고, 화면은 멀쩡하다.

**측정에서 실제 결함 하나가 떨어졌다.** `Math.round`가 반올림하는 것은 치수가 아니라
**오프셋의 소수부**다.

```js
shiftX = (origOffsetX / chipX) * cellW;   // 연속값 — 반 칸이 표현 가능하다
```

실측 `phys_offset_x = 3mm / chipX = 6` → shift 0.500칸 → `phys.x`가 3에서 4로 **조용히
스냅**된다. 반 칸 오프셋을 선언한 맵은 전 셀이 한 다이씩 밀린 채 저장된다.

## 이 라운드가 남긴 판정 순서

```
① 코드에 그 선이 있다고 가정하고 설계  →  ② 소스를 열어 보니 선이 없었다(F6 ⓒ는 이미 동작)
③ 결함을 산술로 추론해 기록            →  ④ 산술을 실제로 돌려 보니 상쇄됐다(홀짝 편향 부존재)
```

②와 ④는 **같은 라운드 안에서 30분 간격으로** 일어났다. ③을 적을 때 근거로 든 「41→20 vs
40→19.5」는 그 자체로는 참이지만, **그 두 값이 식에서 어떻게 쓰이는지를 안 봤다** — 소거되는
항의 홀짝을 논한 것이었다.

## 그때 남아 있던 것

- **오프셋 반 칸 스냅은 이 시점에서 미등재 결함 후보**다 — 별도 트리아지 대상으로 보드에
  기록만 됐고, 코드는 손대지 않았다.
- **F6은 「설계 확정 — 투입 대기」** 상태이고, 같은 `map_editor.js`를 쓰는 F1ⓑ 뒤로 직렬
  배치돼 있다. `64dea7c`가 「착수 전 필수 측정」으로 걸어 둔 홀짝 항목은 `ddfffc9`의 측정으로
  **해소되어 삭제됐다.**
- **치수 제약이 필요 이상으로 넓다는 사실도 기록만 됐다** — `phys` 규격이 같은 두 맵은 원이
  양쪽 캔버스 중앙에 놓이므로 변환이 잘 정의되는데, 지금은 그 경우까지 싸잡아 거절한다.
- `27e9faf`가 손상된 채로 저장소에 남아 있다. 복원은 새 커밋이며, 히스토리와 마찬가지로
  **되감기가 아니다.**
