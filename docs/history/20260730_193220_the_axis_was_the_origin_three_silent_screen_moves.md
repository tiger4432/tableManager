## 이 라운드가 딛고 선 것 — 사용자가 확정한 좌표 규약

세 커밋을 따로 읽으면 세 개의 작은 버그지만, 같이 읽으면 **같은 문장을 세 번 말한다.**
그 문장의 정본은 사용자가 이날 확정한 네 불변식이다.

> ① **화면이 정본이다** — 저장은 화면을 따라가고, 결함은 화면을 **조용히 움직이는** 것이다
> ② **표시 = 원점 + DB 값**
> ③ **`start_x/y` = 유효 다이 영역의 최소 열/행**
> ④ **원점 = start를 놓았을 때 (0,0)으로 읽히는 지점**

저장 좌표는 **원점 기준 칸수**이지 mm 주소가 아니다. 앞선 라운드가 mm 프레이밍 위에 NO-GO를
세웠다가 사용자 판정으로 기각됐고, 그 오독이 두 라운드를 썼다(선행 항목 `…172000…` 참조).
**칸수에 칩 피치를 곱하는 그 곱셈 자체가 없는 결함을 제조한다.**

①이 취향이 아니라 자기정합인 근거도 측정으로 서 있다 — `c − c_origin ≡ xv`가
**204 프레임 / 315,210 셀에서 불일치 0**으로 항등이다. 표시와 저장은 **한 수량**이다.
그래서 「화면이 움직였다」와 「저장 좌표가 바뀌었다」는 두 사건이 아니라 하나다.

## `019140c` — 표준 로드가 원점을 선언하는 대신 셀의 번호를 다시 매겼다

### 배경

metadata 없는 맵을 📐 표준으로 열면 `loadExistingMap`이 `startX = startY = 0`으로 두고,
셀 루프가 모든 저장 좌표에서 `minX`/`minY`를 뺐다. **아무도 다시 더하지 않았고, 프레임은
뺐다는 기록을 갖지 않았다.** 프레임은 "이 격자의 0열은 DB x=0"이라고 말하는데 셀은
"DB x=minX"인 것처럼 번호를 새로 받은 상태였다.

그 어긋남이 화면에 머물지 않는 이유가 ①이다. `getVisualCoords`(= `cellObj.x`의 출처이고
`pushMapData`가 x/y 컬럼에 쓰는 값)는 `getCellFromVisualCoords`(로드가 셀을 놓는 함수)의
**정확한 역함수**다. 그래서 다시 매긴 번호는 **화면이 진술한 값이자 ⚡ Push가 쓴 값**이었다.

**화면이 그것을 드러낼 수 없었던 이유도 기록해 둔다** — 셀 안 라벨이 바로 그 *다시 계산된*
좌표이고, 빈 셀에만 그려진다. 즉 계기가 자기 자신을 채점하고 있었다.

### 변경

```js
// 종전
startX = 0;
startY = 0;
// … 그리고 셀 루프에서
if (userChoice === 'standard') { xNum = xNum - minX; yNum = yNum - minY; }

// 지금 — 원점을 **프레임이 선언**하고, 셀은 저장 좌표 그대로 놓인다
startX = minX;
startY = minY;
// (셀 루프의 시프트는 삭제. 오프셋은 프레임이 나르고 아래 함수가 적용한다)
const cell = getCellFromVisualCoords(xNum, yNum, cols, rows, rotation, side, invertY, startX, startY);
```

화면이 안 움직인다는 것이 이 형태의 핵심이다 — `c = xv - startX + box.minC`는 `xv`와
`startX`가 **같이** 움직이면 불변이다. 모든 셀이 종전과 같은 캔버스 칸에 앉는다.
바뀌는 것은 **화면이 진술하는 좌표, 따라서 Push가 쓰는 좌표가 이제 저장된 그것**이라는 점뿐이다.
저장 경로는 손대지 않았다 — Push에 보정 없음.

### ⚠️ 커밋 메시지는 손상을 기정사실로 말하지만, 사후 확인은 그렇지 않다

커밋 본문은 "네 맵이 첫 Push 이후 열화를 멈췄다", "원래 좌표는 복구 불가"라고 적었다.
**사후에 `audit_logs` 2,676,510행을 확인한 결과는 다르다** — metadata 없는 맵 4개에 대한
좌표 **INSERT 4,498건, UPDATE 0건.** 수리는 어떤 좌표도 덮어쓰이기 전에 착지했다.

> **노출은 실재했고(1,923개 드로잉 셀 중 451개가 Push에 닿는 경로에 있었다) 실현되지 않았다.
> 이 라운드는 잠재 결함을 닫은 것이지 손상을 복구한 것이 아니다.**

실현됐다면 되돌릴 수 없었을 것이라는 점은 그대로 사실이다 — `replace_map`은 좌표 행을
CellSource/CellOverwrite 이력과 **함께 하드 삭제**한다(`crud.py`, `if batch.replace_map` 아래 purge).
애플리케이션 자기 저장소에 원본이 남지 않는다.

또 하나 측정된 것: **누적이 아니라 1회성이다.** 결함을 그대로 복원한 변이 D0에서 두 번째
Push→리로드 사이클은 두 메타데이터 형태 모두에서 **94개 좌표 중 0개**를 움직였다 — 첫 통과 후
저장 최소값이 0이므로 다음 뺄셈은 0을 빼는 것이다.

### 계기

신규 `standard_frame_origin_harness.mjs`는 **출하된 `loadExistingMap`을 vm 샌드박스에서 실행**하고,
**어떤 좌표 함수도 참여하지 않는 오라클**에 19 단언을 채점한다 — 픽스처의 각 행이 자기 저장
좌표를 **값 안에** 인코딩하고 있어서 키 대 키로 비교된다. 변이 7 선언 / 7 적용 / 7 이름 있는 단언
검출 / 0 미검출.

## `02a72c6` — 기하 프리셋이 기하를 말하는데 방향까지 말하고 있었다

### 배경

`applyPresetObject`가 마지막에 `currentRotation`과 `currentSide`를 프리셋 값으로 썼다.
그리고 `server/config/maps.json`의 저장된 프리셋 **다섯 개 전부가 rot 0 / front를 선언**한다.
회전됐거나 뒷면인 맵에 **아무 프리셋이나 적용하면 방향이 조용히 초기화**됐다.
`getPhysicalCoords`가 회전과 면을 둘 다 읽으므로 **모든 셀의 물리 키가 바뀌고**, 그와 함께
Push가 쓰는 좌표가 바뀐다.

실측 표본 `aa123_a` + 프리셋 `4A` — **물리 규격 바이트 동일, 격자 불변, 바운딩 박스 불변,
187개 다이 중 173개 번호 재부여, 그리고 Push가 진행됐다.** 대조 게이트가 막지 못한 이유는
그것이 **격자나 원을 벗어나는 셀만 세기 때문**이다. 벗어난 셀은 하나도 없었다.

### 변경

두 줄을 삭제했다. 운영자는 회전 버튼과 앞/뒷면 라디오로 **이미 방향을 소유한다.**
프리셋이 그것을 다시 주장하는 것은 **동의 없이 화면이 움직이는 것**이고, ①이 금지하는 바로 그것이다.
호출자 넷(프리셋 드롭다운, metadata 없는 맵의 라우팅된 기본, 자재 프레임 빈 열기, 표준 분기의
마스크 없는 규격)이 전부 이 **한 함수**에 닿으므로 호출자별 규칙이 아니라 하나의 행동이다.

`maps.json`은 운영자 편집 대상이라 프리셋이 여전히 방향을 선언**할 수 있다.** 읽고 **무시하되
조용하지 않게** 처리한다.

```js
const declaredRot = (preset.rotation === undefined || preset.rotation === null)
  ? null : (Number(preset.rotation) || 0);
const declaredSide = (preset.side === 'back' || preset.side === 'front') ? preset.side : null;
const ignoredRot  = (declaredRot  !== null && declaredRot  !== currentRotation) ? declaredRot  : null;
const ignoredSide = (declaredSide !== null && declaredSide !== currentSide)     ? declaredSide : null;
// 둘 중 하나라도 있으면 info 토스트 1회 — 선언된 것과 화면이 지킨 것을 함께 말한다.
```

**사후 통지가 여기서 정당한 이유는 아무것도 움직이지 않았기 때문이다** — 이동 통지가 아니라
화면이 제자리에 있었다는 보고다. 선언한 방향이 화면과 이미 일치하거나 아예 선언이 없으면
아무 말도 하지 않는다. 복잡도: **컨트롤 0 추가 / 0 제거**, 패널·모드·모달·확인창 없음.

### ⚠️ 부수 결과 하나

라우팅된 프리셋 경로(F5c)도 이제 선언된 방향을 적용하지 않는다. 이 커밋 시점의 `maps.json`에
기본값 아닌 방향을 선언한 프리셋은 **0개**라 실질 변화는 없다. 다만 그 동작이 의도된 것이었다면
**프리셋은 그것을 나를 수 있는 자리가 아니게 됐다** — 방향은 `wafer_map_metadata`가 나르고,
그쪽이 라우팅보다 상위다.

### 계기

`valid_die_frame_adoption_harness.mjs`의 `P` 블록이 aa123_a 모양 맵(29x25, rot 90 · 뒷면,
칩 11x13)에 **실제 `4A` 프리셋**을 적용한다 — 물리 규격이 동일해서 방향만 살아 있는 축이다.

## `7a9c2b0` — 정렬 경보가 격자 크기를 보고 있었다

### 배경

유효 다이 참조가 이 맵과 어긋났을 때 알리는 경보는 **치수만** 비교했다.
`MID_01 ← 4MAIN_DT`는 **둘 다 23×23**이고 물리 규격도 같은데 시작 좌표가 **(1,1) 대 (−4,−3)**이다 —
마스크가 5열·4행 밀려 앉는데 **아무 말도 하지 않았다.**

> **크기가 같다는 것은 정렬이 같다는 뜻이 아니다.** 같은 DB 좌표가 같은 다이를 가리키는지
> 정하는 것은 **원점**이다(불변식 ③④).

### 변경

술어를 **새 기하식 없이** 세웠다 — `projectCellsToPhys`는 마스크 키를 만드는 **바로 그 함수**이므로,
셀 하나 DB(0,0)을 두 프레임으로 각각 투영해서 물리 키를 비교하면 "마스크가 겹치는가"를
마스크와 **같은 규칙으로** 묻게 된다(불변식 ①: 변환 구현은 하나, 프레임 창만 갈아끼운다).

```js
const originPhysOf = (frame) => {
  const m = projectCellsToPhys([{ x: 0, y: 0 }], frame);
  const k = [...m.keys()][0];
  const [px, py] = String(k || '0_0').split('_').map(Number);
  return { x: px, y: py };
};
const oHere = originPhysOf(currentFrame());
const oThere = originPhysOf(refFrame);
```

캔버스 열이 아니라 **물리 키**인 것은 의도적이다.

### ⚠️ 구현자가 자기 추론을 실측으로 뒤집었다

처음 단언은 **"회전만 다른 차이는 조용해야 한다"**였고, 근거는 "물리 키는 회전 불변"이었다.
**하네스가 반대했고, 하네스가 옳았다.**

`getCellFromVisualCoords`는 DB 좌표를 `getWaferBoundingBox(rotation, side)`에 앵커하는데
**그 바운딩 박스 자체가 회전 의존**이다. 그래서 **캔버스 → 물리는 회전 불변이어도
DB → 물리는 회전 불변이 아니다.** 90°로 저장된 참조는 DB(0,0)로 정말 다른 다이를 가리키고,
경보가 울리는 것이 옳다. 단언은 이제 특수 사례가 아니라 일반 성질이다 — **참조를 자기 프레임이
아니라 이 맵의 프레임으로 읽었을 때 다른 다이 집합에 앉게 되면, 그때 정확히 경보가 울린다.**

### 치수 축은 대체가 아니라 병존이다

원점과 범위는 **서로 독립인 사실**이다 — 정렬된 참조라도 크기가 다르면 마스크 일부가 이 격자
밖에 앉는다. 치수 축을 지우면 한 맹점을 다른 맹점과 바꾸는 것이고, 변이 O4가 그것을 채점한다.
문구는 **성립한 쪽만** 말하고 어긋남을 **칸수로** 잰다.

범위는 좁다: 이것은 **경보이지 거절이 아니다.** 채택 0 · 이동 0 · 좌표 변경 0.
컨트롤 0 추가 / 0 제거, 읽기 경로의 info 토스트 1회.

### 계기

다른 다이에 앉고 경보가 `5칸·4행`을 지목, Push 좌표 411개 불변), ⓑ 정렬된 참조(조용하고,
그 침묵이 **운이 아니라 옳음**임을 증명), ⓒ 회전만 다른 참조.
베이스라인 228 단언, 변이 26 선언 / 26 적용 / 26 검출 / 0 미검출.

`MUTATION DID NOT APPLY` / `STILL GREEN`이 났다 — **이 파일이 존재하는 이유가 정확히 그 실패 양식**이다.
변이가 조용히 무력해지면 계기는 줄어들지 않고 **거짓으로 초록**이 된다.

## 세 커밋이 같은 답을 세 번 말한다

| 어디를 봤나 | 종전 | 지금 |
|---|---|---|
| 표준 로드 | 오프셋을 **셀에** 넣었다 | 오프셋을 **프레임이 선언**한다 |
| 기하 프리셋 | **방향에** 자기 값을 썼다 | 방향은 **화면의 것**으로 둔다 |
| 정렬 경보 | **격자 크기**를 봤다 | **원점 셀**을 본다 |

②(표시 = 원점 + DB 값)를 놓고 보면 셋 다 ②를 어기고 있었다 — 하나는 **DB 값**을 고쳤고,
하나는 **원점을 유도하는 축**을 고쳤고, 하나는 **둘이 어긋난 것을 못 봤다.**
공통 답은 하나다: **좌표의 정체성을 정하는 것은 원점이다.**
