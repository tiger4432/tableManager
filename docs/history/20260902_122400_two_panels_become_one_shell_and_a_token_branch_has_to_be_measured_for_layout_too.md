## ① 판정 하나가 «소유자 요구»로 뒤집혔고, 뒤집힌 자리에 그 사실을 적었다

`0a888db4`. 2026-08-31 판정은 **「고르는 곳은 그리드, 돌리는 곳은 어드민」**이었다
(→ `20260831_123400_...`). 소유자 요구가 그것을 대체했다 — **그룹 줄을 누르면 «그 자리에서»
돈다.** 그리고 그 줄이 무엇이 일어났는지 말한다 — 큐에 들어갔다, 또는 **안 된 이유**.

🔴 **뒤집힌 판정은 «옛 판정이 적혀 있던 파일»에 적혔다.** 판정을 뒤집으면서 그 기록을
안 고치면, 다음 사람이 **이미 죽은 규칙을 도는 규칙으로 읽는다.**

부품은 여전히 **라우트도 토큰도 fetch 도 모른다.**
```
실행    «주입된 함수» 하나
토큰    «주입된 질문» 하나 — hasToken(), «값이 아니다»
```
🔴 이것은 정돈이 아니다 — **그래야 하니스가 이 기능 «전체»를 가짜로 채점할 수 있다.**
「하니스에 진짜 토큰을 두지 마라」는 게이트가 실제로 요구하는 것이 그것이다.

## 🔴 ② 401 과 «선언이 빈 것»은 다른 사실이다

체인 쪽은 이제 **여기서** 규칙별로 묶는다 — 규칙 목록을 **넘겨받을 수 있기** 때문이다.
규칙은 그 조작이 **요구하는** 것이라, **못 읽은 목록**과 **선언이 비었다고 말한 목록**을
**다르게 그린다.**

```
401(못 읽음)   「chain rules not loaded」   ->  토큰을 고치러 간다
빈 선언        빈 목록                      ->  선언을 고치러 간다
같은 픽셀로 그리면   운영자가 «엉뚱한 것»을 고치러 간다
```
라이브에서 잘못된 토큰은 `/admin/chain/rules` 에서 **401** 을 낸다 — 패널이 규칙을
**지어내지 않고** 그렇게 말한다.

토큰 키는 `admin_token.js` 로 옮겼다. 그리드 페이지도 **같은 키**를 읽어야 하고,
**그 문자열의 사본 둘은 「토큰이 있는데 없다고 말하는 화면」** 이다 —
**오류가 안 붙는 고장**이다.

원장 payload 와 누를 수 있는 줄이 **한 목록**에서 나온다. 전에는 둘이었고,
**범위 값을 공백으로 잇는 변이가 «탈출»했다** — 한쪽 join 을 바꿔도 **다른 쪽이 단언에
읽히도록** 남아 있었기 때문이다.

## 아키텍처 영향

- **드롭다운 껍데기가 «한 벌»** (`dropdown.js`)이다 — 재번역 패널과 필터 펼침이 **닫는 방법을
  공유**하고, 각자 «배치»만 선언한다. 리스너를 **떼는 것까지**가 그 함수다.
- 재번역 패널이 **줄에서 «직접 실행»**한다. 부품은 여전히 라우트·토큰·fetch 를 모르고,
  실행은 **주입된 함수**, 토큰은 **주입된 질문**(`hasToken()`)이다.
- 어드민 토큰 키가 **`admin_token.js` 한 곳**에 산다.
- 「못 읽음(401)」과 「선언이 비었음」이 **다르게 그려진다.**
- 하니스가 **`dropdown.js` 도 읽는다** — 뽑아낸 파일의 변이가 조용해지지 않도록.

## 그때 남아 있던 것

- 라이브 실행 확인은 **비-GET 차단기를 설치한 상태**에서 했다 — 실제로 큐에 들어가는 경로는
  이 라운드에서 관측되지 않았다(차단된 요청의 «메서드와 경로»까지만 확인).
- **동작·서버·선언·원장은 손대지 않았다**(`0e48f79f`). 헤더 배치·flex basis·다른 헤더
  컨트롤·개별 삭제·전부 지우기도 마찬가지다(`0d304005`).
- 통제 «둘»은 **일부러 탈출한다** — 그것이 이 하니스가 판별력을 갖고 있다는 표지다.
