## 배경 — 이 주의 잘못된 길 대부분이 두 이름에서 나왔다

```js
function getVisualCoords(...)     // ← 돌려주는 것은 **DB에 저장되는 좌표**다
function getPhysicalCoords(...)   // ← 돌려주는 것은 **셀 인덱스**다. 밀리미터가 아니다
```

"Visual"은 화면 좌표처럼 읽히지만 실제로는 저장값이고, "Physical"은 물리 치수처럼 읽히지만
실제로는 정수 격자 인덱스다. **이름 두 개가 서로 상대의 뜻을 입고 있었다.**
`xv`/`yv`라는 지역 변수명이 그 오독을 파일 전체로 실어 날랐다.

이 주에 「mm로 재야 한다」는 프레이밍 위에 NO-GO가 섰다가 사용자 판정으로 기각된 적이 있고
(선행 항목의 선행), 저장 좌표를 mm 주소로 읽은 라운드가 있었다. **그 오독의 물리적 근거가
이 두 이름이다.**

## 개명 — 이름이 자기가 말하는 것을 말한다

| 옛 이름 | 새 이름 | 실제로 다루는 공간 |
|---|---|---|
| `getVisualCoords` | `getDbCoords` | **DB 저장 좌표**(원점 기준 칸수) |
| `getCellFromVisualCoords` | `getCanvasCellFromDb` | 그 역함수 — 저장 좌표 → 캔버스 칸 |

| `getCellFromPhysicalCoords` | `getCanvasCellFromDieIndex` | 그 역함수 |
| `xv` / `yv` | `dbX` / `dbY` | — |

**실측(이 항목 작성 시점):** 개명 직전 `map_editor.js`에 옛 이름 4종이 **40회** 등장하고
개명 후 **0회**, 새 이름 4종이 **50회** 등장한다. 하네스 8종의 `SYMBOLS` 목록도 함께 옮겼다.

> **`mm`은 일부러 비워 뒀다.** 규칙 6(서로 다른 메타의 오버레이)과 결함 마킹이 진짜 밀리미터
> 공간을 요구하는데, **이 커밋 시점의 클라에는 그 공간이 없다.** 이름을 미리 점유하면 다음
> 사람이 정수 인덱스를 mm라고 부르는 이 결함을 한 번 더 만든다.

## 다이 인덱스의 원점이 격자 모서리에서 웨이퍼 중심으로 옮겨졌다

종전 식은 `xp = round(xRot + (cols-1)/2)`였다. 입력 `xRot`은 이미 웨이퍼 중심 기준인데
**출력만 이 맵 자신의 격자 중심으로 되기준**됐다. 그래서 물리 키의 뜻이 「웨이퍼 중심에서 몇
칸」이 아니라 「이 격자의 몇 번째 칸」이었고, 23×23과 45×45가 **같은 다이를 11만큼 다른 키로**
불렀다(중심 11 대 22).

⚠️ 그냥 지울 수 없었던 이유가 코드에 남아 있다 — **패리티**다.

```js
// 남기는 것은 격자의 **크기**가 아니라 **패리티**다.
const xp = Math.round(xRot + (Math.abs(Math.round(cols)) % 2 === 0 ? 0.5 : 0));
const yp = Math.round(yRot + (Math.abs(Math.round(rows)) % 2 === 0 ? 0.5 : 0));
```

칸 수가 짝수면 웨이퍼 중심이 칸 경계에 앉고 홀수면 칸 한가운데 앉는다. 그 반 칸은 좌표계의
취향이 아니라 다이 격자의 **물리적 사실**이라, 되기준 항을 통째로 없애면 짝수 격자에서
`Math.round`가 반 칸을 삼켜 역함수와의 왕복이 한 칸 어긋난다. 커밋이 적어 둔 실측 근거:
**운영 데이터 214개 맵 중 163개가 짝수 치수**를 갖는다.

결과적으로 **새 키 == 옛 키 − `floor((cols-1)/2)`**, 정확한 정수 평행이동이다. 왕복 항등은
한 글자도 약해지지 않고 사라지는 것은 격자 **크기** 의존뿐이다.

### 그 이동이 로컬 초안을 무효로 만든다

초안은 `cells`를 **물리 키로** 저장한다. 키 공간이 옮겨졌으므로 v3 초안을 그대로 복원하면
값들이 **다른 칸**에 앉는다. 마이그레이션하지 않고 버린다 — `DRAFT_VERSION` 3 → 4.
**저장 안 된 작업 한 번을 다시 그리는 쪽이, 좌표가 조용히 옮겨간 맵을 복원하는 것보다 낫다.**

## 격자가 유효 다이 기하를 따라간다 — 파생이지 채택이 아니다

사용자 문장은 「격자는 유효 다이 맵 기하에 맞게 변경(유효 다이가 온전히 보이게)」이다.

이것이 `94b9baa`에서 **삭제된** 프레임 채택과 어떻게 다른지가 이 라운드의 핵심 구분이다.

| | 거절당한 채택(`94b9baa`가 지운 것) | 이 라운드 |
|---|---|---|
| 치수의 출처 | 참조가 **선언한** cols/rows를 베낀다 | 갈아끼운 **규격에서 파생**한다(`applyPhysicalGeometry`) |
| 셀 | 캔버스 칸에 그대로 둔다 | 자기 **저장 좌표에서** 다시 앉힌다 |
| 결과 | 273칸 전부의 좌표가 움직였다 | 좌표 이동 0 |

파생과 재배치는 **한 쌍**이고, 한쪽만 하면 그것이 거절당한 그 동작이다. 그래서 둘이 같은
호출 안에 있다. 그리고 파생 격자가 마스크를 못 담을 때만, 담을 때까지만 넓히는 적합 가드가
붙는다 — 담고 있으면 한 칸도 늘리지 않는다.

```js
// 한 번에 한 칸. 키가 덮는 범위는 치수에 대해 **중첩 단조**이므로 위반이 난 축만 늘리면
// 최소 치수에서 멈춘다. 멈추는 이유는 하나여야 한다 ― 편집기의 치수 정의역(frameDimBounds).
for (let step = 0; miss.any > 0 && step < 2 * dimMax; step++) { … }
if (miss.any > 0) {
  console.warn(`[Map Editor][M4] the valid-die mask does not fit the grid: …`
    + 'NOT grown further and NOT clipped ― the cells keep their stored coordinates …');
}
```

⚠️ 상한에 닿으면 **더 넓히지도, 잘라 내지도 않는다.** 조용히 자라거나 잘리는 대신 사유를
남기고, 격자 밖 셀은 Push 관문이 보고한다.

커밋이 적어 둔 실측 — A2가 23×23 → 25×25로, 마스크 키 326개, 격자 밖 0, **좌표 이동 0**.
쌍이 지지대라는 증거로 변이 둘: 재배치 없는 확대는 120/120을 움직이고, 옛 치수를 유지하는
로드는 15/15를 움직인다.

## 개명이 하네스 둘을 적색으로 만들었는데, 소스 잘못이 아니었다

`company_roundtrip`과 `copy_header_count`는 **두 개의 git 리비전을 슬라이스한다.** 고정된
베이스라인은 옛 철자를 영원히 갖고 있으므로 **한 철자로 양쪽을 가리킬 수 없다.**
점수를 면제하는 대신 **슬라이스 경계에서** 허용 철자 목록으로 고쳤다.

> 이것이 이 파일이 도처에 붙여 둔 경고와 같은 부류다 — 개명은 소스만의 사건이 아니라
> **소스를 텍스트로 읽는 도구 전부의 사건**이다.

## QA가 「고장」이라고 본 것이 코드가 아니었다

사용자가 기하 스왑을 고장으로 QA했고, **나는 `valid_die_ref`에 두 가지 모양이 있다는 가설을
그대로 전달했다. 그 가설은 틀렸다** — `parseValidDieRef`가 맨 문자열 형태를 접어 주고
A2의 `"DT_TEST"`는 정상 해석된다. 대조군으로 재면 HEAD의 패널은 14.3 × 15.2, 이 트리는
13.6 × 13.7로 **스왑이 이미 동작하고 있었다.**

유력한 원인은 환경이다 — **개발 서버가 IPv6에만 바인딩해서 `127.0.0.1:5173`은 즉시 거절되고
`localhost:5173`만 응답한다.**
