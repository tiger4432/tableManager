# Pack 성숙 규율 — Pack은 설계물이 아니라 추출물

> 2026-08-17 12:12 · Docs / Plan · 커밋 `a70b871`

## 배경

소유자 판정: 「Pack 부실한 상태에서 (마법사를) 하면 독이 된다 — 초기에는 Pack
설계도 동시에 해야 한다.」 책상에서 설계한 Pack 위에 마법사를 세우면, 마법사는
**틀린 추상으로 사용자를 자신 있게 안내하는 기계**가 된다. `84bd418`의 2단계는
Pack 7종을 선작성 대상처럼 읽힐 수 있었기에 작동 방식 자체를 개정했다.

## 변경 내용

`02_PACK_LIBRARY.md`에 개정 절(24줄), `04_WIZARD_EXTENSIONS.md`에 연동 제약
(5줄) 추가. 핵심 규율:

```
1. Pack 초안은 실제 착지에서 추출한다. 7종 표는 «목표 목록»이지 선작성
   대상이 아니다.
2. v1 승격 기준: 서로 다른 소스 «둘»이 같은 Pack으로 착지. 소스 하나만
   지나간 Pack은 그 소스의 사진이지 추상이 아니다 — draft 표지를 달고 남는다.
3. 따라서 초기 정문은 마법사가 아니라 «원시 모드»다 — Profile 손편집 +
   드라이런 + 문장 미리보기.
4. 소유자의 현재 재구축 작업이 곧 Pack 설계 세션이다.
```

마법사(04) 쪽에는: 인터뷰는 v1 실증 Pack이 있는 영역에만 열리고, draft Pack
영역에서는 초안을 만들지 않고 「아직 이 모양의 Pack 없음 — 원시 모드로」를
정직하게 안내한다는 제약이 붙었다.

## 아키텍처 영향

문서 전용. 2단계의 실행 형태가 「Pack 7종 일괄 작성」에서 「소스 착지 → 추출
회의 → Pack 후보 갱신」 루프로 바뀌었고, 둘째 소스에서 안 맞는 부분이 드러나는
지점을 Pack의 진짜 경계로 삼는 승격 기준이 생겼다.

## 그때 남아 있던 것

  아직 하나도 없었다.
- 원시 모드(Profile 손편집 + 드라이런 + 문장 미리보기)의 화면 자체도 미구현
  이었다.
