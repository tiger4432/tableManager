# 깨진 것은 `COALESCE`였고, `number`는 거기 걸어 들어간 첫 타입일 뿐이었다 (N8)

> **일자:** 2026-08-04 오전 | **관련 커밋:** `9e02e3f`(N8) · 선행 `5be96f5`(N7) · 축이 없었음을 기록한 보드 `6b150d3`
> **담당:** QA(두 번째 사례를 PostgreSQL 18.3에서 재현) · server 구현(열거로 세 번째를 선제 발견) · 총괄(수치 렌더링은 판정 보류)
> **대상:** `crud.column_text_sql`(단일 깔때기) · `contracts/blank_predicate` · `server/virtual_join_*`
> **선행 항목:** `20260804_062339_the_label_is_text_so_the_number_must_speak_text.md`(N7)

## 배경 — 축이 없으면 술어는 채점되지 않는다

가상 조인의 해소 표현식은 `COALESCE(<part>, '<label>')`이다. 오른쪽은 미해결을
뜻하는 **텍스트 라벨**(`미상`)이다. 왼쪽이 텍스트가 아니면 SQL이 죽는다.

이것이 출하될 수 있었던 이유를 `6b150d3`이 정직하게 적어 뒀다:

> **그때의 측정은 정직했고 비어 있었다** — 숫자 타입 `expose` 컬럼이 **0개**여서
> 그 축이 한 번도 발동하지 않았다. 픽스처에도 하나도 없다. 그래서 수리는
> **먼저 하나를 선언해서 적색을 보는 것**으로 시작해야 했다.

페이로드 쪽은 이미 이 문제를 사유해 뒀다 — `announced_columns`가 **값 도메인에
문자열 라벨이 포함된다**고 말하고, 그래서 라벨이 스키마에 실린다. **나중에 붙은
SQL 경로가 그 사유를 물려받지 못했다.**

## N7의 틀 자체가 결함이었다

N7은 「숫자 `expose` 컬럼에는 캐스트가 필요하다」로 출하됐다. **그 틀이 결함이다.**

깨지는 것은 「숫자」가 아니라 **텍스트가 아닌 무엇이든**이다. `number`는 거기
걸어 들어간 **첫 타입**이었을 뿐이다.

| 타입 | 증상 |
|---|---|
| `number` | N7이 잡은 것 |
| `datetime` | QA가 **PostgreSQL 18.3에서 재현** — `InvalidDatetimeFormat` |
| `boolean` | 기다리지 않고 **열거해서** 찾음. PG에서 `InvalidTextRepresentation`. **SQLite에서는 크래시조차 없다** — 모든 UNMATCHED 행이 `True`로 돌아와 **미해결 라벨이 찾을 수 없게 된다** |

## 열거는 단언됐지, 가정되지 않았다

`init_dynamic_models`가 `column_types`를 Float / DateTime(timezone=True) / String으로
매핑하고, 공유 메타데이터 컬럼이 Boolean과 DateTime을 더한다. `virtual_join_config`는
`expose`를 **`column_types`의 키**에 대해 검증하므로, 거기 선언된 메타데이터 **이름**이
평범한 config를 통해 Boolean·DateTime 컬럼에 닿는다.

Numeric / Integer / Enum / JSON / ARRAY / UUID는 오늘 생산되지 않는다 —
**그런데 그 문장이 지난주에 `datetime`에 대해서도 참이었다.** 그래서 전부 처리했다.

## 깔때기는 「이미 텍스트인가」를 묻는다

`crud.column_text_sql` 하나로 모은다. 그리고 그 함수는 **「우리가 문제라고 아는
타입인가」가 아니라 「이것은 **이미** 텍스트인가」를 묻는다.**

> 그래서 **모르는 타입은 500이 아니라 CAST를 받는다.**

각 렌더러에는 **파이썬 쌍둥이**가 있다 — 페이로드와 `WHERE` 절이 한 셀을 다르게
철자할 수 없게.

## 시간 철자는 상속하지 않고 **핀으로 박았다**

PostgreSQL 자신의 `timestamptz` CAST는 **세션 타임존**으로 렌더하고 소수부가 0이면
떨어뜨린다. 그러면 **한 행을 든 두 서버가 서로 다른 텍스트를 비교하게 된다.**

`TEMPORAL_TEXT_FORMAT`은 **UTC · 공백 구분 · 마이크로초 6자리 항상**이다.
이것은 SQLite의 네이티브 DATETIME 저장 텍스트이기도 하고, **고정폭이라 사전순이
곧 시간순**이다. 라이브 PG 18.3에서 검증했다 — SQL 텍스트가 측정한 모든 행에서
파이썬 쌍둥이와 같고, NULL은 여전히 라벨로 접힌다. Boolean은 `'true'`/`'false'` —
**브라우저가 찍는 것**이지 `clean_str_value`의 `'True'`가 아니다.

## 계약이 잘못된 대리지표를 채점하고 있었다 (N9)

`contracts/blank_predicate`는 숫자 이음새를 **SQL vs `clean_str_value`**로 채점하고
자기 docstring에 그렇게 적어 뒀다. **그런데 페이로드는 원시 JSON 숫자를 싣고,
화면까지 가는 길에 그 헬퍼를 부르는 것이 없다 — 브라우저가 문자열화한다.**

그래서 축을 **브라우저가 실제로 찍는 것**으로 다시 겨눴다. JS 엔진이
`client_harness.mjs`에서 측정하고, pytest 반쪽이 방언별로 재유도한다.

`clean_str_value`는 **보수적 대리지표조차 아니다**:

| | `clean_str_value` | Postgres | 브라우저 |
|---|---|---|---|
| `1e19` | 브라우저와 **일치** | **불일치** | ― |
| `1e21` | 브라우저와 **불일치** | **일치** | ― |

그 띠는 양쪽 경계와 함께 기록됐고, 실측 도달 범위도 같이 남았다 —
**라이브 숫자 컬럼 24개, 널이 아닌 값 116,084개, 그 띠 안에 0개.**

닫으려면 숫자 페이로드를 텍스트로 렌더해야 하고, 그것은 **이미 출하된 셀 값의 JSON
타입을 바꾸는 일**이다. 총괄 소관으로 남겼다.

## 그때 남아 있던 것

- **덮지 않고 선언한 것 하나**: 핀으로 박힌 텍스트 타입의 `collide` 컬럼은
  **왼쪽이 소유한 셀에서 여전히 갈린다** — 조인이 **진** 셀은 바이트 동일하게
  남아야 하기 때문이다. 조용히 자라지 못하도록 **이름으로** 핀을 박았다.
  이 커밋 시점에 그런 선언은 **하나도 없다.**
- 숫자 페이로드를 텍스트로 렌더하는 문제(N9의 잔여분)는 **판정 보류 상태**다.
