# 🧪 DOE 설정 가이드 — 맵에 실험 계획 얹는 법

> **Status:** 🟢 Living | **작성:** 2026-07-28 · 총괄 | **Last-verified:** 2026-07-30 (F2 `064550f` 착지 후 코드 대조 — **수량은 「저장되는 셀」만 센다**를 §1·§5·§9에 반영(감소폭 표 포함), §4 계약 밖 칸에 **`COUNT`** 추가, §5에 `Fill All`의 유효 다이 필터·토스트. 직전 2026-07-28: U9 마커·U8 가용 피드백·H2 적재 게이트 착지 후 코드 대조 — §8 적재 누락 행을 실제 게이트 동작에 맞춤) | **대상:** 맵 에디터에서 DOE를 작성하는 **사용자** (개발자용 계약은 [MAP_EDITOR_SPEC §6](../spec/MAP_EDITOR_SPEC.md))
> **한 줄 요약:** **색칠이 곧 계획이다.** 값 하나 = DOE 조건 하나이고, 그 값으로 칠한 셀 중 **저장되는 것**의 수 × 층수가 자재 수요가 된다.

---

## 1. 개념 — 3가지만 알면 된다

1. **값(VALUE) 하나 = DOE 조건 하나.** 범례에 값을 만들고 그 값으로 맵을 칠하면, 칠한 영역이 그 조건의 적용 범위다.
2. **층 구조는 STACK 숫자 하나로 끝난다.** `STACK=16`이면 이 조건은 16층이고, 세 구역이 자동으로 생긴다 — **1H**(1층) · **MID**(사이 전부) · **TOP**(16층). 구간 입력, FROM/TO 같은 건 없다. 겹침·빈 층은 **입력 자체가 불가능**하다.
3. **수량은 저장하지 않고 파생된다.** 사용 = **저장되는 셀 수** × 층수. 셀을 하나 더 칠하면 수요가 바로 바뀐다.

> **"저장되는 셀"이 무슨 뜻인가** — 유효 다이(웨이퍼 원, 또는 그 맵에 지정된 [유효 다이 맵](VALID_DIE_MAP_GUIDE.md)) **안쪽**의 칠해진 셀이다. 그 바깥은 캔버스에 색도 안 나오고 `⚡ Push`로 서버에 올라가지도 않는다 — **저장되지 않는 셀은 수량에도 안 들어간다.** 화면의 숫자와 서버에 들어간 행 수가 항상 같다는 뜻이다(§9 참조).

## 2. 시작하기

1. 맵 에디터에서 **Target Table**(예: `bonding_map`)과 키를 넣고 **Load** — **없는 키도 그냥 열린다**(빈 맵). 키는 ⚡ Push 때 생성된다.
2. 처음 여는 맵은 DOE가 **VALUE 1 하나짜리 빈 조건**으로 시작한다. 그 키에 저장된 DOE 세트가 있으면 그게 로드된다.

## 3. 표① 값 정의 — 칼럼별 입력법

| 칼럼 | 입력 | 예 |
|---|---|---|
| **VALUE** | 조건 이름(자유 문자열) | `A`, `SPLIT-C7`, `F` |
| **STACK** | 총 층수(정수). **`0` = 상태 표시 값**(§3.1) | `16`, `0` |
| **DESC** | 설명(자유) | `EDS FAIL 위치` |
| **1H** | 1층 자재. **비우면 MID가 1층부터** | `LOTA_01` |
| **MID** | 중간 자재 — 여러 개면 줄바꿈 또는 쉼표 | `LOTB` |
| **TOP** | 마지막 층 자재. **비우면 MID가 끝까지** | `LOTC_05:2` |
| **KNOB** | 공정 조건 태그(쌍 아님, 그냥 태그) — 줄바꿈/쉼표 구분. 나중에 공정 추적으로 자동 부착 예정 | `dose_28`, `focus_002` |

### 3.1 STACK 0 — "이 색은 계획이 아니라 표시"

BASE의 FAIL 위치처럼 **층 구조 없이 상태만 표시하려고 칠하는 값**은 STACK에 `0`을 넣는다. 그 값은:
- 구역 입력이 **해당 없음**으로 잠기고, 자재 수요·롤업에서 빠지고, 검수도 잔소리하지 않는다.
- `0`인데 구역에 자재가 적혀 있으면 모순이라고 **알려만** 준다(V6 — 저장은 막지 않음).

> **`0`과 빈칸은 다르다.** `0` = "층이 없다"는 선언. 빈칸 = "아직 안 적었다" — 빈칸은 검수가 계속 지적한다.

### 3.2 자재 토큰 문법 — `lot[_slot][:BIN]`

| 쓰면 | 뜻 |
|---|---|
| `ADFE1H_01` | 그 lot의 slot 01 |
| `ADFE1H_01:3` | 같은 wafer의 **BIN 3만** |
| `ADFE1H` | **lot 전체** (slot 미기입) |
| `ADFE1H:2` | lot 전체에 일괄 BIN 2 |

BIN 생략 시 **1**. 롤업 행의 정체는 `(자재, BIN)` 풀이다 — 한 DT 맵에서 VALUE별로 BIN을 나눠 쓰는 것도 이 문법으로 표현된다.

## 4. 엑셀 호환 — 표를 그대로 붙여넣는다

사람들이 엑셀에 만들어 둔 표와 **직접 왕복**된다. 계약 칼럼은 6개:

```
VALUE  STACK  DESC  1H  MID  TOP
```

- **붙여넣기**: 엑셀에서 범위 복사 → 표①에 붙여넣기. 헤더 행이 있으면 **이름으로** 매칭, 없으면 **왼쪽부터 순서대로**. 색은 무시된다(색은 에디터가 관리).
- **복사**: 표①에서 복사하면 같은 6칼럼 TSV로 나간다. `0`도 적은 그대로 왕복된다.
- **COLOR · 칠함 · COUNT**는 파생값이라 계약 밖 — 붙여넣어도 **알아보되 버린다**. 「칠함」과 `COUNT`는 같은 값의 화면 이름·내보내기 이름이다(맵 화면의 `COPY HEADER MODE`가 우측 보조표를 `VALUE | COUNT | STACK | DESC`로 싣는다). 이 단어들을 무시 목록에 넣어 둔 이유는 **머리줄을 통째로 긁어 붙여도 그 줄이 머리줄로 인식되게** 하기 위해서다 — 모르는 척하면 값 이름이 `VALUE`이고 STACK이 `COUNT`인 데이터 행이 생긴다.
  - 즉 **내보낸 보조표를 그대로 되붙일 수 있다.** 칠한 셀 수는 격자에서 세는 값이지 붙여넣기로 정하는 값이 아니므로, 되붙여도 수량은 격자 기준 그대로다.

## 5. 색칠

1. 표①에서 값 행을 클릭해 **브러시로 선택**
2. 맵에서 **드래그**로 칠하기 · 우클릭 드래그로 지우기 · 전체 채우기/선택 영역 채우기 버튼
3. 칠한 순간 표②의 **사용≈**이 바로 바뀐다 (**저장되는 셀** × 층수)

`F` 등 잠금 값으로 선언된 셀은 보호되어 덮어지지 않는다.

> **`🎨 Fill All`은 유효 다이 안쪽만 칠한다.** 바깥으로 건너뛴 칸이 있으면 토스트가 몇 칸인지 말해 준다(예: *"1,842칸을 'A'로 칠했습니다 (유효 다이 밖 512칸 제외 — 저장되지 않는 셀입니다)"*). 한 칸도 못 칠했으면 그것도 말해 준다 — 그때는 물리 규격(직경·칩 크기)이나 유효 다이 맵 지정을 확인하면 된다.

## 6. 표② 자재 롤업 — 읽는 법

| 칼럼 | 뜻 |
|---|---|
| **MAT** | 자재 토큰 (행 클릭 → 그 자재의 맵으로 이동. **없는 맵도 빈 채로 열린다**) |
| **MAP** | 그 자재의 맵 존재 여부 (`?` = 확인 안 됨) |
| **가용** | 서버가 계산한 쓸 수 있는 수량 |
| **사용≈** | 이 계획의 소요 — **균등 분배 가정값**(어느 wafer를 먼저 쓸지는 기록 안 하므로 ≈) |
| **잔여≈** | 가용 − 사용 |

> 🔴 **「미상」은 0이 아니다.** 미상 = "검사 못 했다"이지 "없다"가 아니다. 가용이 미상이면 잔여도 미상이다. 시스템은 모르는 것을 절대 0으로 보여주지 않는다.

- **↻ 가용** 버튼으로 재조회. 조회 후에도 미상이면 토스트와 셀 툴팁이 **이유**를 말해준다(예: "BIN 축이 선언돼 있지 않습니다").
- BIN별 가용은 관리자가 config에 `bin_map`을 선언해야 켜진다([CONFIG_GUIDE §5.8](CONFIG_GUIDE.md)). 미선언은 고장이 아니라 **아직 배선 안 됨**이다.

## 7. 저장 — 규칙은 하나다

> **⚡ Push Map Data가 유일한 저장이다.** 자동 저장은 없다.

- 편집하면 **이 브라우저에 초안**으로 보관된다 — 탭을 닫거나 새로고침해도 사라지지 않고, 다시 열면 마지막 맵이 자동으로 다시 열린다.
- 계획 헤더의 칩이 상태를 말한다: `● 저장 안 됨 · [⚡ Push]로 저장` / `저장됨 HH:MM` / `변경 없음`.
- Push는 맵과 계획을 **함께** 올린다. 서버에는 Push 전까지 아무것도 쓰지 않는다.
- 다른 PC에서는 초안이 안 보인다(브라우저 보관). 공유하려면 Push.

## 8. 검수 메시지 — 막는 것과 알리는 것

**검수(V1~V6)는 보고만 하고 저장을 막지 않는다.** 불완전한 계획도 Push된다 — 고치라고 말해줄 뿐이다.

저장을 **막는** 것은 데이터가 **파괴될 때**뿐이다:
| 차단 사유 | 뜻 |
|---|---|
| 층 구조 컬럼 없음 | 지금 저장하면 층 구조가 버려진 채 계획이 교체됨 — **계획이 틀려서가 아님** |
| 옛 형식 해석 불가 | 옛 구간 데이터를 뭉개면 정보가 사라짐 |
| 적재 누락 감지 | 값이 들어 있는 셀 중 **이번 적재에 담기지 않는 것**이 있어, 이대로 올리면 그 셀들이 서버에서 **삭제**될 상황. 확인창이 뜨기 전에 막고 **몇 개가 삭제될지 개수로** 말해준다 |

> **적재 누락이 뜨면 두 가지 중 하나다.**
> - **프레임이 맵을 못 덮는다** — 격자 크기·시작 좌표·회전·물리 규격을 맵 전체가 보이도록 맞추면 풀린다.
> - **유효 다이 밖에 값이 남아 있다** — 2026-07-30 이전에 `🎨 Fill All`로 칠해 둔 뒤 저장하지 못하고 이 브라우저에 남은 **초안**이 이 경우다. 지금의 `Fill All`은 유효 다이 밖을 칠하지 않으므로 **새로 칠하는 맵에서는 더 생기지 않는다.** 이미 남아 있는 초안을 정리하는 수정은 **아직 작업 중**이라, 그런 맵은 당분간 계속 거부될 수 있다. 거부 문구가 말하는 개수가 **격자를 아무리 넓혀도 줄지 않으면** 이 경우다.

## 9. 자주 묻는 것

- **"DOE 잘못 입력해도 저장돼요?"** — 된다(의도). 검수 메시지가 뭘 고칠지 알려준다.
- **"반반 실험은?"** — 값 두 개 만들어 반씩 칠하면 된다. 값별로 STACK·자재가 다르면 그게 곧 split이다.
- **"dt_map에도 자재 적고 싶은데"** — `STACK=1`에 MID만 적으면 된다(1H·TOP 비움).
- **"수량이 어제랑 달라요"** — 누가 셀을 칠했거나 dt 맵이 바뀐 것. 수량은 저장된 게 아니라 **매번 계산**된다.
- **"아무것도 안 했는데 2026-07-30에 숫자가 내려갔어요"** — 그날부터 수량이 **저장되는 셀만** 세기 때문이다. 아래 표가 어느 맵에서 얼마나 내려가는지다. **사라진 숫자는 원래 저장될 수 없던 셀이다** — 서버에 올라간 적도, 화면에 색이 나온 적도 없다. 그러니까 **지금 보이는 숫자가 처음으로 맞는 숫자**다.

| 어떤 맵인가 | 얼마나 내려가나 |
|---|---|
| **`⚡ Push`로 저장해 온 맵을 불러온 것** | **0%** — 변화 없음(실측). Push는 유효 다이 밖 셀을 저장한 적이 없다 |
| 새로 만들면서 **`🎨 Fill All`을 쓴 맵** (규격 프리셋 사용) | **약 35~51%** — 프리셋에 따라 다르다(격자 사각형 중 유효 다이 밖의 비율) |
| 새로 만들면서 `Fill All`을 쓴 맵 (**규격 프리셋 없음**) | **약 7%** — 격자가 웨이퍼보다 작게 잘려 있어 밖에 해당하는 셀 자체가 적다 |
| **드래그로만 칠한 맵** | 사실상 **0%** — 유효 다이 밖은 원래 손으로 칠하기 어렵다 |

> ⚠️ **예외 하나 — 파서가 인제션한 맵.** 인제션은 `⚡ Push`를 거치지 않으므로, 이미 저장된 행 중 일부가 **현재 물리 규격(또는 지정된 유효 다이 맵)의 밖**에 놓일 수 있다. 그런 맵은 서버에서 불러왔는데도 수량이 내려가고, 그건 **데이터가 잘못된 것이 아니라 이 맵의 물리 규격·유효 다이 지정이 실제 데이터와 맞지 않는다는 신호**다 — 규격을 맞추면 다시 잡힌다. 🔴 **맞추기 전에는 `⚡ Push`하지 말 것**(적재 누락 게이트가 막아 주지만, 그 거부가 바로 이 신호다).

> 같이 사라진 증상: `Fill All`을 쓴 맵에서 **`⚡ Push`가 계속 거부되던 것**(*"현재 프레임이 맵 전체를 덮지 못합니다"*)도 이 원인이었다. 격자 크기를 아무리 맞춰도 안 풀렸던 이유는 그 셀들이 **격자 밖이 아니라 유효 다이 밖**이었기 때문이다.
