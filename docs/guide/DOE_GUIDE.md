# 🧪 DOE 설정 가이드 — 맵에 실험 계획 얹는 법

> **Status:** 🟢 Living | **작성:** 2026-07-28 · 총괄 | **대상:** 맵 에디터에서 DOE를 작성하는 **사용자** (개발자용 계약은 [MAP_EDITOR_SPEC §6](../spec/MAP_EDITOR_SPEC.md))
> **한 줄 요약:** **색칠이 곧 계획이다.** 값 하나 = DOE 조건 하나이고, 그 값으로 칠한 셀 수 × 층수가 자재 수요가 된다.

---

## 1. 개념 — 3가지만 알면 된다

1. **값(VALUE) 하나 = DOE 조건 하나.** 범례에 값을 만들고 그 값으로 맵을 칠하면, 칠한 영역이 그 조건의 적용 범위다.
2. **층 구조는 STACK 숫자 하나로 끝난다.** `STACK=16`이면 이 조건은 16층이고, 세 구역이 자동으로 생긴다 — **1H**(1층) · **MID**(사이 전부) · **TOP**(16층). 구간 입력, FROM/TO 같은 건 없다. 겹침·빈 층은 **입력 자체가 불가능**하다.
3. **수량은 저장하지 않고 파생된다.** 사용 = 칠한 셀 수 × 층수. 셀을 하나 더 칠하면 수요가 바로 바뀐다.

## 2. 시작하기

1. 맵 에디터에서 **Target Table**(예: `bonding_map`)과 키를 넣고 **Load** — **없는 키도 그냥 열린다**(빈 맵). 키는 ⚡ Push 때 생성된다.
2. 처음 여는 맵은 DOE가 **VALUE 1 하나짜리 빈 조건**으로 시작한다. 그 키에 저장된 DOE 세트가 있으면 그게 로드된다.

## 3. 표① 값 정의 — 칼럼별 입력법

| 칼럼 | 입력 | 예 |
|---|---|---|
| **VALUE** | 조건 이름(자유 문자열) | `A`, `SPLIT-C7`, `F` |
| **STACK** | 총 층수(정수). **`0` = 상태 표시 값**(§3.1) | `16`, `0` |
| **DESC** | 설명(자유) | `EDS FAIL 위치` |
| **1H** | 1층 자재. **비우면 MID가 1층부터** | `LOTA_01` |
| **MID** | 중간 자재 — 여러 개면 줄바꿈 또는 쉼표 | `LOTB` |
| **TOP** | 마지막 층 자재. **비우면 MID가 끝까지** | `LOTC_05:2` |
| **KNOB** | 공정 조건 태그(쌍 아님, 그냥 태그) — 줄바꿈/쉼표 구분. 나중에 공정 추적으로 자동 부착 예정 | `dose_28`, `focus_002` |

### 3.1 STACK 0 — "이 색은 계획이 아니라 표시"

BASE의 FAIL 위치처럼 **층 구조 없이 상태만 표시하려고 칠하는 값**은 STACK에 `0`을 넣는다. 그 값은:
- 구역 입력이 **해당 없음**으로 잠기고, 자재 수요·롤업에서 빠지고, 검수도 잔소리하지 않는다.
- `0`인데 구역에 자재가 적혀 있으면 모순이라고 **알려만** 준다(V6 — 저장은 막지 않음).

> **`0`과 빈칸은 다르다.** `0` = "층이 없다"는 선언. 빈칸 = "아직 안 적었다" — 빈칸은 검수가 계속 지적한다.

### 3.2 자재 토큰 문법 — `lot[_slot][:BIN]`

| 쓰면 | 뜻 |
|---|---|
| `ADFE1H_01` | 그 lot의 slot 01 |
| `ADFE1H_01:3` | 같은 wafer의 **BIN 3만** |
| `ADFE1H` | **lot 전체** (slot 미기입) |
| `ADFE1H:2` | lot 전체에 일괄 BIN 2 |

BIN 생략 시 **1**. 롤업 행의 정체는 `(자재, BIN)` 풀이다 — 한 DT 맵에서 VALUE별로 BIN을 나눠 쓰는 것도 이 문법으로 표현된다.

## 4. 엑셀 호환 — 표를 그대로 붙여넣는다

사람들이 엑셀에 만들어 둔 표와 **직접 왕복**된다. 계약 칼럼은 6개:

```
VALUE  STACK  DESC  1H  MID  TOP
```

- **붙여넣기**: 엑셀에서 범위 복사 → 표①에 붙여넣기. 헤더 행이 있으면 **이름으로** 매칭, 없으면 **왼쪽부터 순서대로**. 색은 무시된다(색은 에디터가 관리).
- **복사**: 표①에서 복사하면 같은 6칼럼 TSV로 나간다. `0`도 적은 그대로 왕복된다.
- COLOR·칠함(칠한 셀 수)은 파생값이라 계약 밖 — 붙여넣어도 무시된다.

## 5. 색칠

1. 표①에서 값 행을 클릭해 **브러시로 선택**
2. 맵에서 **드래그**로 칠하기 · 우클릭 드래그로 지우기 · 전체 채우기/선택 영역 채우기 버튼
3. 칠한 순간 표②의 **사용≈**이 바로 바뀐다 (칠한 셀 × 층수)

`F` 등 잠금 값으로 선언된 셀은 보호되어 덮어지지 않는다.

## 6. 표② 자재 롤업 — 읽는 법

| 칼럼 | 뜻 |
|---|---|
| **MAT** | 자재 토큰 (행 클릭 → 그 자재의 맵으로 이동. **없는 맵도 빈 채로 열린다**) |
| **MAP** | 그 자재의 맵 존재 여부 (`?` = 확인 안 됨) |
| **가용** | 서버가 계산한 쓸 수 있는 수량 |
| **사용≈** | 이 계획의 소요 — **균등 분배 가정값**(어느 wafer를 먼저 쓸지는 기록 안 하므로 ≈) |
| **잔여≈** | 가용 − 사용 |

> 🔴 **「미상」은 0이 아니다.** 미상 = "검사 못 했다"이지 "없다"가 아니다. 가용이 미상이면 잔여도 미상이다. 시스템은 모르는 것을 절대 0으로 보여주지 않는다.

- **↻ 가용** 버튼으로 재조회. 조회 후에도 미상이면 토스트와 셀 툴팁이 **이유**를 말해준다(예: "BIN 축이 선언돼 있지 않습니다").
- BIN별 가용은 관리자가 config에 `bin_map`을 선언해야 켜진다([CONFIG_GUIDE §5.8](CONFIG_GUIDE.md)). 미선언은 고장이 아니라 **아직 배선 안 됨**이다.

## 7. 저장 — 규칙은 하나다

> **⚡ Push Map Data가 유일한 저장이다.** 자동 저장은 없다.

- 편집하면 **이 브라우저에 초안**으로 보관된다 — 탭을 닫거나 새로고침해도 사라지지 않고, 다시 열면 마지막 맵이 자동으로 다시 열린다.
- 계획 헤더의 칩이 상태를 말한다: `● 저장 안 됨 · [⚡ Push]로 저장` / `저장됨 HH:MM` / `변경 없음`.
- Push는 맵과 계획을 **함께** 올린다. 서버에는 Push 전까지 아무것도 쓰지 않는다.
- 다른 PC에서는 초안이 안 보인다(브라우저 보관). 공유하려면 Push.

## 8. 검수 메시지 — 막는 것과 알리는 것

**검수(V1~V6)는 보고만 하고 저장을 막지 않는다.** 불완전한 계획도 Push된다 — 고치라고 말해줄 뿐이다.

저장을 **막는** 것은 데이터가 **파괴될 때**뿐이다:
| 차단 사유 | 뜻 |
|---|---|
| 층 구조 컬럼 없음 | 지금 저장하면 층 구조가 버려진 채 계획이 교체됨 — **계획이 틀려서가 아님** |
| 옛 형식 해석 불가 | 옛 구간 데이터를 뭉개면 정보가 사라짐 |
| 적재 누락 감지 | 화면 프레임이 맵을 다 못 담아 셀이 잘려나갈 상황 |

## 9. 자주 묻는 것

- **"DOE 잘못 입력해도 저장돼요?"** — 된다(의도). 검수 메시지가 뭘 고칠지 알려준다.
- **"반반 실험은?"** — 값 두 개 만들어 반씩 칠하면 된다. 값별로 STACK·자재가 다르면 그게 곧 split이다.
- **"dt_map에도 자재 적고 싶은데"** — `STACK=1`에 MID만 적으면 된다(1H·TOP 비움).
- **"수량이 어제랑 달라요"** — 누가 셀을 칠했거나 dt 맵이 바뀐 것. 수량은 저장된 게 아니라 **매번 계산**된다.
