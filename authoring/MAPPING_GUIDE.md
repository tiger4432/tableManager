# 체인 맵퍼 — 당신이 쓰는 것은 «함수 하나»입니다

> **정본:** `server/mapper_sdk.py` (395줄) @ `9c7d850c` · 등록부 소비자 `server/main.py` :5509 @ `2ec11afc`
> **버전:** ⚰️ 이 줄은 «별도 저장소»였을 때의 것입니다 — 판정 386 이후 이 문서는 제품과 «같은 커밋»에 삽니다. 인용한 줄 번호는 «이 커밋의» 파일에서 잰 것입니다

## 0. 두 줄 요약

```
① `(df, db) -> df` 함수를 하나 씁니다.  들어온 프레임을 보고, 나갈 프레임을 돌려줍니다
② 그 위에 `@mapper()` 를 붙입니다.      나머지는 전부 SDK 가 합니다
```

## 1. 세 걸음 중 «둘»은 당신 것이 아닙니다

`server/mapper_sdk.py` 머리 주석 :4~11 이 그 모양을 적습니다:

```
① payloads        -> DataFrame          SDK — payloads_to_df   :53
② DataFrame + SQL -> DataFrame          🔴 «당신»이 쓰는 유일한 것
③ DataFrame       -> updates 봉투       SDK — df_to_updates    :130
```

🔴 **②만 쓰라는 것은 친절이 아니라 «안전»입니다.** ③이 하는 일 중 하나가
**비즈니스 키를 «선언»에서 읽는 것**인데(`df_to_updates` :130 의 머리 주석), 그것을 작성자가
직접 적으면 **틀려도 오류가 안 납니다** — 행이 들어가고, 다음 실행이 그 행을 못 찾아
또 넣습니다. 그 사고가 실제로 있었고 소스가 그 날짜를 적어 둡니다(:170~:176).

## 2. 최소 맵퍼

```python
from mapper_sdk import mapper

@mapper()
def build_rows(df, db):
    #  df : 이 규칙이 집어 온 행들이 «한 행 = 한 dict» 로 평평해진 프레임
    #  db : 지금 트랜잭션의 세션. 읽기에만 씁니다
    out = df[["<키 컬럼>", "<값 컬럼>"]].copy()
    return out            # DataFrame 을 돌려줍니다. 봉투를 만들지 «않습니다»
```

정본 `server/mapper_sdk.py` :339~ (`mapper(...)` 데코레이터)가 단언하는 것 넷:

| 단언 | 어디 | 왜 |
|---|---|---|
| 워커가 부르는 모양은 «그대로»(`(db, payloads, rule=None)`) | :353~354 산문 | 손으로 쓴 맵퍼가 있던 자리에 그대로 들어갑니다 — SDK 는 «둘째 호출 규약»이 아닙니다 |
| 타깃 표는 «규칙»이 정합니다 | :356~ | 그 사실은 `rule["target_table"]` 에 이미 삽니다. 맵퍼가 다시 적으면 «틀릴 자리»가 둘이 됩니다 |
| `updated_by` 기본값 = 당신 «함수 이름» | :362~ | 손으로 적는 출처는 앞 맵퍼에서 복사돼 «틀린 이름»을 답니다 |
| 빈 DataFrame = «의도한 무동작» | :366~ | `None` 을 돌려줘도 같아 보이지만 그건 «우연»입니다. 빈 프레임이 그 뜻의 철자입니다 |

⛔ **DataFrame 이 아닌 것을 돌려주면 «이름을 대고» 거절합니다**(:381~385) — 봉투를 직접 만들고
싶다면 그건 「이 데코레이터가 당신이 원하는 물건이 아니다」라는 뜻이라고 소스가 그렇게 적습니다.

## 3. 읽기 — `sql(db, ...)` 하나만 쓰십시오

```python
from mapper_sdk import sql

prev = sql(db, "SELECT <컬럼> FROM <표> WHERE <키> = :k", {"k": key})
```

정본 `server/mapper_sdk.py` :100~128. 그 머리 주석이 «성질 둘»을 단언합니다:

```
🔴 «당신의 세션»으로 읽습니다 (새 커넥션이 아닙니다)      :106~113
   체인 맵퍼는 워커의 트랜잭션 «안»에서 돌고 커밋이 금지돼 있습니다. 그래서 이 배치가
   이미 쌓아 둔 행이 당신에게 «보입니다». 자기 커넥션을 여는 헬퍼였다면 이 배치 «전»의
   데이터베이스를 읽고, 당신은 «낡은 상태»에서 파생합니다 — 조용히, 동시성에서만
🔴 파라미터는 «바인딩»입니다. 문자열로 만들지 않습니다               :115~118
   직접 조립한 문자열은 주입까지 한 걸음이고, 더 흔하게는 `None` 하나로
   `WHERE <키> = None` 이 되어 «조용히 아무것도 안 맞습니다»
```
⚠️ **SQL 의 NULL 은 `NaN`(float)으로 도착합니다**(:120~123). 돌아갈 때 `df_to_updates` 가
`None` 으로 되돌립니다 — 그래서 «당신이 그 수리를 적지 않아도» 왕복이 됩니다.
⚠️ **컬럼 이름은 여전히 «선언»에서 옵니다**(:116~119). 질의가 자기 컬럼 이름을 «철자»하는 것은
맵퍼가 그러는 것과 같은 결함이고, 이 헬퍼는 그것을 대신 막아 주지 못합니다.

## 4. 🔴 이름 — 등록부가 «저장의 판정자»입니다

```
@mapper(name="<이 맵퍼의 이름>")      이름을 안 주면 «당신 함수 이름»으로 등록됩니다  :389~392
     |
     v
MAPPER_REGISTRY                    server/mapper_sdk.py :253   name -> 호출 가능한 것
     |
     v
저장이 그 이름을 «판정»합니다        server/main.py :5491 산문이 그렇게 적습니다
     |
     v
chain 탭 규칙 등록의 «드롭다운»      server/main.py :5509  registered = sorted(MAPPER_REGISTRY)
```

⚰️ **[2026-09-13 정정 — S-223 `da4f0111`, 판정 379] 이 절이 「`@mapper` 를 안 붙이면 고를 수
없다」고 적었고, 그것은 «오늘 거짓»입니다.** 그렇게 적을 당시엔 드롭다운이 `registered`(즉
`@mapper` 가 준 이름) «하나»로 채워졌는데, 그러면 **돌고 있는 맵퍼로 가득한 디렉터리를 두고
화면이 「선택지 없음」**이라고 말했습니다 — 오늘 운영에서 도는 맵퍼는 대개 규칙이
`mapper_function` 으로 «이름을 대는» 모듈 수준 함수이기 때문입니다.

오늘 `/admin/mappers/list` 가 내는 칸은 «다섯»이고, 뒤의 «셋»이 서로 «배타»입니다:

| 칸 | 무엇 | 당신에게 |
|---|---|---|
| `data` | 파일을 AST 로 읽은 «모든 최상위 def» | import 안 되는 모듈의 def 도 들어 있습니다 |
| `registered` | `@mapper` 가 준 이름 | 「저장이 이름으로 아는 것」 |
| 🔵 `candidates` | **규칙이 오늘 이름 댈 수 있는 것** | **드롭다운이 여기서 옵니다** |
| `other` | import 는 되는데 «원장 롤 맵퍼» — 체인 규칙이 안 부름 | 다른 계열입니다 |
| `refused` | import 자체가 «안 된» 것 + 사유 | 고칠 것이 있다는 뜻입니다 |

🔴 **셋이 배타인 것이 설계입니다** — 「여기 없다」·「고장났다」·「다른 계열이다」는 **세 답**이고,
둘을 합치면 화면에 «거짓 문장»이 섭니다.
⚠️ **`other` 는 «import 된 모듈 중에서만» 가립니다** — 못 읽은 파일을 보고 계열을 판정하는 것은
「파싱했다 ≠ import 된다」이고, import 실패는 `refused` «하나»입니다(로드되는 날 `other` 로 옮겨갑니다).
🔴 **그리고 «클래스»는 후보가 아닙니다**(판정 379) — 실행기가 `getattr` 뒤에 «부르»므로 클래스는
«구성»됩니다. 인스턴스가 행 수 세는 데까지 흘러가고 **틀린 답이 조용히 나갑니다**.
「호출 가능」과 「돌릴 수 있음」은 다릅니다.
⚠️ **함수는 «이름»이 아니라 «시그니처»로 걸러집니다** — 실행기가 `(db, payload)` 를 넘기므로
「위치 인자 둘 이상」이 그 성질입니다. 이름으로 거르는 것은 이 저장소의 가장 오래된 결함입니다.

**당신이 할 일 한 줄: 규칙이 이름 댈 수 있으려면 «모듈 수준 함수»이고 «(db, payload) 를 받으면»
됩니다. `@mapper` 는 그 위에 「이름을 등록」을 더합니다 — 필수가 아니라 «이름을 당신이 정하는» 길입니다.**

### 한 이름을 둘이 주장하면 — 이름을 대고 던집니다
`MapperNameClaimedTwice` (`server/mapper_sdk.py` :261, 던지는 자리 :301~305).
조용히 덮으면 **어느 맵퍼가 도는지 아무도 모릅니다** — 답이 «import 순서»로 정해지고
그 사실을 아무것도 말해 주지 않습니다.
⚠️ 「같은 이름」은 «모듈»로 가릅니다, 객체 동일성이 아니라(:295~300 · `_origin` :281).
리로드는 같은 소스로 «새 래퍼»를 만들기 때문에, 동일성으로 갈랐으면 리로드가 자기가
새로 고친 맵퍼를 전부 거절했을 것입니다.

다시 묶었고, 그 본문은 제품이 못 보는 파일이라 **제품이 자기 그룹을 말할 수 없었습니다**.

🔴 **「두 번 돌면 안 된다」는 «당신만» 아는 사실입니다** — 제품은 당신 맵퍼 본문을 못 봅니다.
적지 않으면 제품은 「돌려도 된다」로 «가정»합니다.

⚠️ **합쳐진 단위는 «실패도 하나»입니다** — 같이 성공하고 같이 실패합니다.
실패한 병합을 다시 쪼개는 것은 오늘 «안 합니다».
🔵 **당신이 할 일 한 줄: 맵퍼가 «한 번에 더 많은 행»을 보면 빨라지는 종류라면 규칙에 그 수를
적고, 아니면 «적지 마십시오» — 안 적은 것이 오늘의 동작입니다.**

### `params` — 규칙에서 무엇을 읽는지 «당신이» 선언합니다
```python
@mapper(params=("<인자 이름>", "<인자 이름>"))
```
`MAPPER_PARAMS` (`server/mapper_sdk.py` :258). 그 줄의 주석이 이유를 적습니다 —
**맵퍼 파일은 제품에 «배포되지 않으므로»**, 제품이 「이 맵퍼가 무엇을 읽나」를 알아낼 방법이
없습니다. 그래서 맵퍼가 «말해야» 합니다. 로더가 「아무도 선언 안 한 이름」을 경고합니다.

## 5. 왜 SDK 가 «맵퍼 디렉토리 안»에 안 사나 — 당신에게도 중요한 이유

`server/mapper_sdk.py` :12~17 이 그것을 적습니다:

```
`.gitignore` 가 `server/mappers/*` 를 제외하고 `*.sample` 과 `ledger_v2_*.py` 만 다시 들입니다
   (.gitignore :68 · :69 · :75 — 제 실측)
=> 맵퍼 «옆»에 둔 모듈은 그것을 쓴 상자에만 있고 다른 어디에도 없습니다
=> 그래서 SDK 는 «배포되는 자리»에 살고, 작성자는 «이름으로 import» 합니다
```
🔴 **당신에게 이것이 뜻하는 바 한 줄: 당신 맵퍼 파일은 «당신 것»이고 제품과 함께 오지 않습니다.**
그래서 위 §4 의 `params` 선언이 필요하고, 그래서 당신 파일에 헬퍼를 만들어 두면
**다른 상자에서 그 헬퍼가 없습니다.** 공용이 필요하면 SDK 에 들어가야 하고, 그건 제품 쪽 일입니다.
⛔ **상속을 «길»로 쓰지 마십시오** — `BaseMapper`(:77)는 «이미 있는 맵퍼가 import 하는 이름»이라
남아 있는 것이고, 소스가 「새 맵퍼는 함수를 쓰라」고 적습니다(:88~92).

## 5-bis. 🔴 import 해도 되는 이름 — 표가 있습니다

```
정본   server/mapper_sdk.py 의 `MAPPER_SURFACE` :422      (S-215 `c3015b8a`, 판정 368)
쓰는 법  from mapper_sdk import <그 표에 있는 이름>
```
🔵 **이 문서는 그 목록을 «옮겨 적지 않습니다».**
이름이 몇십 개인 목록을 두 곳에 두면 «갈라지고», 갈라진 쪽은
조용합니다. 이름이 필요하면 **그 표를 보십시오** — 제품이 그것을
돌려주고, 이 문서는 «어디»만 말합니다.

🔴 **그 표에 없는 이름은 `AttributeError` 입니다** — 평범한 파이썬
오류이고, 제품이 자기 거절문을 지어내지 않습니다(판정 369) —
오타를 «제품 규칙»처럼 보이게 하지 않기 위해서입니다.
🔵 **돌아오는 것은 «같은 객체»이지 사본이 아닙니다** —
`mapper_sdk.fold_notation is notation_norm.fold_notation` 가 참입니다.

⚠️ **그 표에 밑줄로 시작하는 이름이 «둘» 있습니다.**
SDK 에 `_name` 이 있는 것은 이상해 보이고, 실제로 이상합니다 —
다만 **그것이 이미 계약**이라, 이번 라운드는 계약을 «적었을» 뿐
바꾸지 않았습니다. 이름을 바꾸면 **당신의 파일을 고치게 되고**,
그것이 이 표면이 존재하는 이유 자체입니다.

🔴 **그리고 이 목록은 «고른 것»이 아니라 «잴 것»입니다** —
오늘 라이브 맵퍼가 실제로 import 하는 이름을 읽어서 만들었습니다.
그래서 줄이는 것은 «정리»가 아니라 «계약 파기»입니다.

## 6. 거절 — 전부 «이름이 있습니다»

`MapperContractError` (`server/mapper_sdk.py` :47). 소스의 표현: **이름을 대고 거절하며,
조용히 내보내지 않는다 — 조용히 나간 것은 나중에 «행을 세는 사람»이 찾는다.**

| 그 표가 «정체를 선언 안 했다» | :218~223 | **선언** 사실입니다 — 그 표의 키를 무엇으로 할지 정해 선언합니다 |
| 조합 키의 재료 컬럼이 프레임에 없다 | :205~209 | 그 컬럼을 프레임에 싣습니다 |
| 단일 키 컬럼이 프레임에 없다 | :211~215 | 같음 |
| 어떤 행의 키 값이 «비어 있다» | :237~241 | 그 행을 거르거나 값을 채웁니다 |

🔴 **가운데 둘이 «따로 있는 것»이 설계입니다**(:180~189). 「못 읽었다」와 「키가 없다」를
한 문장으로 합치면 **당신이 한 곳만 보러 갑니다** — 하나는 설정을 고치는 일이고 다른 하나는
선언을 정하는 일이라, 다음 행동이 다릅니다.

```
server/notebooks/mapper_workbench.ipynb      제품 저장소 경로 (사람이 여는 것)
```
### 예제 — 이 디렉토리의 `examples/`
```
examples/production_mapper.py.sample         가장 작은 것부터 — 여기서 시작하십시오

```
🔵 **셋 다 «읽는 파일»입니다** — 그대로 복사해 당신의 맵퍼 디렉토리에 두고 고치십시오.
⚠️ **이것들은 «데코레이터 이전» 모양일 수 있습니다**(저장소에서 온 파일입니다). 오늘의 정본은

### 저장소에 «남은» 일곱 — 여기 사본이 없습니다
`server/mappers/*.py.sample` 일곱은 시험이 그 바이트를 «라이브 맵퍼»와 대조하는 드리프트 게이트가
읽습니다(판정 348). 사람만 읽는 파일이 «아니라서» 남았고, 이 가이드는 사본을 두지 않고
«저장소 경로»로만 가리킵니다. 🔴 같은 파일이 두 곳에 있으면 «갈리고», 갈린 쪽이 조용합니다.
